# 范围交付

## 开始与恢复开发

每轮新开发或恢复开发（包括复用旧 worktree），在修改文件前完成：

1. 执行 `git fetch origin main`，记录本轮取得的 `origin/main` 完整 SHA，以及当前 HEAD、分支和完整暂存/未暂存/未跟踪状态。远端拉取失败时如实报告，只继续不依赖最新基线的只读核对。
2. 明确本批路径及其累计已确认需求。只沿这些路径核对前序未交付修改，优先继续同一页面或文件已有的任务分支，保持一个活跃编辑位置；新 worktree 从本轮记录的 main SHA 创建。
3. 已有 worktree 的 HEAD 尚未包含该 SHA 时，先同步再编码：干净且无独有提交时快进；有独有提交时保留这些提交并合并最新 main；有未提交改动时，先按授权范围保存任务分支检查点或可恢复快照、整理本批范围，再完成同步并复核改动仍在。保持原工作区和并行修改，不以同步为由整体覆盖或整仓自动暂存；语义冲突按仓库冲突处理规则解决。
4. 用 `git merge-base --is-ancestor <本轮取得的main完整SHA> HEAD` 确认当前开发基线包含该提交，检查退出码为 0 后才开始修改文件。只有 fetch 成功不代表工作树已同步，也不能用落后的本地 main 代替远端基线。

独立改动在合适的干净 worktree 中实施，优先复用本任务已有、适合该基线的 worktree。混合工作区的依赖改动若是必要前提，明确纳入范围或先解决基线，不能靠拷贝整个目录带入。阶段结束仍未交付的修改，按任务授权保存在任务分支检查点或可恢复快照中，并标明待交付状态。

普通的“提交并 push”检查本批路径、相关文件的累计修改、当前提交与目标远端；输出范围摘要。用户要求合并其他分支、全仓盘点或范围不明时，才扩展到其他路径的 worktree 和分支历史。

## 验证与提交

1. 从 `package.json` 的项目命令进入验证。指定 TypeScript 测试用 `pnpm test <测试路径>`，保留已有 `svelte-kit sync` 前置步骤；按改动选择 check/build/browser 验证。
2. 验收记录对应 checkout、基线提交、源码及锁文件内容、构建参数和测试命令。同一输入可复用已有结果；换基线、转移了代码或输入发生变化时，重跑受影响的检查。单纯补充交付说明不重复业务回归。
3. 交付前 fetch 目标分支，审阅本批 diff，按 [提交内容与文件体积](../../../AGENTS.md#提交内容与文件体积必选) 排除验证过程文件、evidence 与其他本地产物；验证结果写入答复或 PR。显式暂存文件或属于本批的 hunks。混合文件仅移入本批变更；保留并行修改，不使用全仓暂存。语义冲突交由用户决定。
   同一页面或文件按累计已确认需求验收，保留前序已确认但尚未交付的功能；不能只抽取本轮差异而遗漏这些功能。未确认或超出本任务授权的差异保持独立，并明确列出未包含项。
   暂存后核对实际文件清单和各 blob 字节数；超过 1,000,000 字节或属于过程附件的文件，未获逐文件明确确认就移出本批提交。检查暂存内容，不能用工作区大小代替；生成文件、锁文件、历史夹具及已跟踪的 evidence 都不能自动豁免。收口时报告是否存在例外。
4. commit、push 后读取一次远端 ref，确认包含本次提交。推送被拒时 fetch 后重新核对，不 force push。

## 等待 CI

默认完成标准为推送已确认且 CI 已完成。分别报告提交、远端和 CI 结论，`expected/bypassed` 不代表通过。

从交付 checkout 执行：

```sh
node tools/scripts/wait-ci.mjs <完整提交SHA>
```

工具按该 SHA 定位 CI，用一个 watcher 等待，只输出新增的完成/失败步骤，最后核对提交和完整结论。正常等待复用这个进程；仅在失败、取消、查询错误或状态异常时额外诊断。进度说明聚焦新结果，不重复抄送未变化的阶段。

用户明确要求只完成 push、后台通知或其他完成点时，按其要求执行，清楚报告尚未完成的 CI；未来通知按用户授权使用可用调度工具，不能假称已安排。

## 收口

每次交付按 [分支与工作树清理标准](../../../docs/agents/git-cleanup.md) 清理本任务已合入 `origin/main` 的 GitHub 分支、本地分支和 worktree；全仓清理仅在用户要求时展开。未满足条件的项保留并说明原因。

最终答复给出提交、远端验证、CI 链接及清理结果；真实服务或部署只报告实际运行过的结论。交付文件从已验证的精确提交或冻结候选导出，提供稳定路径、文件 SHA-256 和基线/提交标识，明确本地候选、已提交、已合入 main 或已部署的实际状态；不把待清理工作树中的文件笼统称为“最新版本”。
