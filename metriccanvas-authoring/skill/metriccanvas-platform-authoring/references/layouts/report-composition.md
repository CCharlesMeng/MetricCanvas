# PC Report 章节组合

新建Report、重组章节、选择本章排法，或用户反馈“区域不清、分割不够、卡片不合理”时读取。先确定阅读任务和已有数据，按容器基本原则明确各组卡面归属，再选表达与组合，最后通过实际PC预览修复问题。局部改标题或数据绑定时沿用已有布局。

这是经视觉审核的创作参考，不是固定整页模板或保存准入。每章只采用能回答当前问题的组合；章节数量、对象数、比例和变体随内容调整。缺少数据时说明缺口，用已有事实能支撑的表达，不为丰富度添加业务视角。

## 容器基本原则：先决定谁提供卡面

布局控制排列与占位，卡面提供背景、内边距和可辨认的边界。span分配宽度，不会为组件增加卡面；分区、组合卡和组件自身外观分别承担不同职责。

1. **分区组织阅读，卡片围合信息。** 章节可以包含多个独立对象／分析主题；同一对象的主值、变化与解释保持归属，不按数据源数量拆卡。
2. **逐组明确卡面提供者。** 选择分区card／panel、组件级组合卡、组件自身卡面，或有意露在底色上的标题／短说明。plain是透明组织层，不会给其中图表补白底或边界。
3. **同层信息使用相称的视觉边界。** 并列比较的分析模块应能各自辨认；一个图裸露、另一张表自带白卡时，要明确这是否符合本次层级，而不是让组件默认外观偶然决定。
4. **每组保留一层主要卡面。** 已有外层阅读面时，内部优先用排布、间距和受支持的紧凑变体组织；需要嵌套时说明内部独立信息的用途，遵守子组件准入。
5. **卡面服务内容。** 标题和短说明可直接放在页面底色上，连续正文可共用整章阅读面；独立分析组才围合成卡。根据内容决定宽度与高度，避免逐段套框、卡壳套卡壳或为填满一行制造新主题。
6. **以实际外观验收。** 去掉装饰性内部分隔线后仍能辨认分组；同组内容保持相邻，主辅值不粘连。合法容器声明和无溢出都不能替代此项判断。

新建或重组时，在创作计划中简列“信息组 → 卡面提供者 → 内部内容”；每组都应有明确选择，短说明选择露底色也需有意为之。局部字段修改不要求另造计划文件，这张表也不写成新的Page字段。

| 信息组 | 卡面提供者示例 | 内部内容 |
|---|---|---|
| 独立走势模块 | plain分区内的组合卡 | 一张lineChart，卡标题与图标题避免重复 |
| 独立精确数表 | 普通table自身卡面 | 真实列头与数据行，无需再用不合法的组合卡包表格 |
| 连续阅读的整章证据 | section.container的card／panel | 图、说明与受支持的紧凑表格共同回答本章问题 |
| 章节标题／简短口径 | 有意不设卡面 | 在底色上标识阅读顺序或就近说明 |

例如同排独立走势与精确表可以是`plain → [compositeCard → lineChart] + [普通table]`；若共同使用整章阅读面，也可在card分区内采用受支持的图与紧凑表格。两种选择都成立，关键是卡面归属与信息关系一致。独立饼图同样先判断是否需要组合卡，不能把plain或span:12当成已有外壳。具体子项与变体仍按当前协议核对。

## 选择组合

| 编号 | 组合 | 采用条件与保留关系 |
|---|---|---|
| C1-A | 按对象聚合 | 少量对象各有几个核心指标。同一对象同卡，主值与所属变化同一行，同级对象保持一致列位；数据源不同不自动拆卡 |
| C1-B | 按指标对照 | 逐项比较多个对象。对象身份、指标单位和变化基准明确；本期值保持默认颜色，仅变化值按业务方向使用红绿 |
| C2-A | 双组详细排行并列 | 两组对象需同时比较、解释较短。身份、值、变化及原因留在对应条目；解释长或字段宽时采用C2-B |
| C2-B | 原因随行的明细表 | 逐行核对多个字段或原因需要宽度。组别与对象身份清楚，原因紧邻所属对象，不统一挪到报告末尾 |
| C3-A | 一张分组表头表 | 同一对象的多个业务阶段需横向核对。对象列、总量与各阶段分组有归属；先分配可读列宽，过宽时表内横滚 |
| C4-A | 同排构成卡，饼图／环图与明细 | 输入已有多个需要展示的构成主题，每个主题独立成卡，占部分行宽。图与精确值靠近；明细左右或上下排布以实际可读宽度为准 |
| C4-B | 窄卡构成图与下方明细 | 一个构成摘要适合窄模块，饼图／环图与精确值上下相邻。宽度围绕内容确定，避免小图配大块空白 |
| C4-C | 横向条形图与精确值 | 主要比较类别大小或名称较长；数量及占比明细紧邻图形。数值已能核对时图上标签按可读性取舍 |
| C4-D | 仅分类明细 | 类别少、主要任务是精确核对；图形没有新增阅读价值时省略，保留单位和必要合计 |
| C5-A | 概览与明细页签 | 同主题两种任务按需切换；默认页展示用户首先需要的内容，不将必须同时比较的证据藏到不同页签 |
| C5-B | 趋势与明细连续展开 | 连续报告或需同时核对趋势与精确值。两者同主题相邻；明细有精确核对用途，避免再加文字逐个复述数字 |

C3-B（阶段拆成相邻小表）不在本轮采用集合。阶段核对优先保留C3-A的一张分组表，不自动拆成多张重复对象列的小表。

## 先选表达，再定卡面边界

| 读者要完成的任务 | 优先表达与保留内容 |
|---|---|
| 逐月、逐对象核对多个精确值 | 真实table，保留表头、单位、数值对齐和必要行线；多列文字排版不能替代表格结构 |
| 看变化走势，同时查某月数值 | 趋势图与真实明细表相邻；空间允许时分别成卡并排，否则连续展开 |
| 看整体中各类别的份额 | 分母可靠且类别完整时用饼图／环图，配类别、数量、占比；饼图呈现份额，环图仅在组件支持且有合计用途时考虑中心内容 |
| 精确比较类别大小，或类别较多、名称较长 | 条形图或表格；保留必要的数量、单位和口径 |

用户已要求表格或饼图时先保留其阅读目的，在协议与数据允许范围内实现。构成图偏高时，先调整卡片宽度、图文方向或受支持的变体；只有阅读任务也适合纯明细时才改选C4-D。静态摘要文字适合说明结论与口径，精确对照交给表格。

用户说“分割不够”时，先检查卡片外边界是否缺失、不同主题是否被塞进同一个大白面。独立主题通过卡面和间距分开；同一对象的主值、变化和简短解释继续聚在一起。表格行线用于逐行核对，图表网格用于读数，保留其用途。仅当同卡内容确实需要额外分组时再使用内部dividers或章节连接线，避免用连续横竖线补偿错误的分组。

背景色区分页面底、卡面和强调信息的层级；具体颜色沿用当前主题，不固定照抄案例蓝色。相邻同级卡保持一致卡面与标题层级，间距承担主题边界。每个标题只标识一个层级：章节名概括问题，卡标题标识对象／图表；一张卡只含一个图时合并同义标题。

### 对应现有协议

先核对当前版本与能力入口；以下是完整Page创作路径的实现线索，不是compose_page新增支持面：

- plain分区不提供整章白卡；组件自身的卡面仍可形成并列边界。组合卡是组件，可在同一分区内并排；section.container的card是整个分区的卡面。
- 纯指标组可用compositeCard的metricGrid避免默认最小高度留下空白。子组件准入按当前协议读取，不能为套卡壳任意嵌入table、text或另一张组合卡。
- 表格要独立白卡时，核对普通table自带卡面；reportCompact适合已经有外层阅读面的紧凑表格。高度使用受支持的fit等属性，不以非法组合卡嵌套包表格。
- 构成图可使用原生表格式图例呈现类别、数量和占比；独立categoryBreakdown是另一种可选表达，按当前协议绑定与配色。预览确认窄卡图例是否移到下方，以实际效果描述方向。
- 只使用已支持的容器、变体、span和样式规则。能力不足时说明缺口；本参考不授予任意CSS、嵌套或尺寸字段。

### 已验证案例：服务运营月报

两个团队各有工单数、响应时长及变化；另有半年趋势与月度值、客户变化原因、阶段数据，以及业务类型／办结状态两个构成主题。最终结构为：团队各自成卡；趋势图与月度table各自成卡并排；客户原因随行表和阶段分组表分别通栏；两个构成主题各用独立饼图卡。章节标题置于卡外，共同口径紧邻相应章节。

这次迭代中，整章白面与内部横竖线未能形成用户需要的主题边界；纯文字数表削弱精确核对，省去构成图也偏离阅读意图。改用独立卡面并恢复真实table、饼图后，用户反馈“好多了”。可复用的是表达与信息边界的选择；两个团队、五个主题、具体span、蓝底和卡片数量属于案例，不是模板要求。该页使用inline合成数据，PC预览通过，不证明真实取数或模型创作稳定性。

## 颜色与主辅层级

C1-B本期数值使用默认文本色，不新增蓝色强调；所有需表达变化的对应项设置一致规则，不能只给一半变化值着色。保留正负号和变化基准，颜色不代替文字。

按字段语义决定方向：响应时长越短越好时，下降绿、上升红；数量仅表达增减时，增加绿、减少红，避免称为改善／恶化。业务方向相反时相应调整，未知方向保持默认并说明。

使用当前组件明确支持的数值颜色规则；数值保留数值类型，不通过拼HTML、行号或自定义CSS实现通用业务规则。混合方向矩阵需核对每个变化字段能否独立配置；接口表达不了时说明限制，选择可表达的列组织或替代组合。

对象标题、主值、变化和解释逐级呈现；所属变化不拆成与主值同权的裸数字卡。主值和变化绑定同一对象、期间与口径，多行源通过可信对象选择定位，不将第一行猜作总量。

组件变体带有真实外观语义，不能仅按名称猜用途。静态口径、样本范围等普通说明优先使用plain文字；text的reportInline会自带图标及“AI 总结：”，只在确需这种分析摘要呈现时采用。指标的context位置随变体变化，基期与主值紧贴时选择合适变体或将基期移到所属组的就近说明，保持原值和单位可核对。

## 构成模块的密度

一张构成卡只保留一个主题标题。图与明细共享类别范围、期间和数值口径；有受支持的类别色板时按类别同色对应。中心合计只在组件明确支持、数据可加总时使用。

C4-A只在已有多个构成主题时并排；只有一个主题时改选C4-B或C4-D，不制造第二主题凑行。类别多、需排序分页或很多宽字段时选条形图／表格。高度、图大小和图文距离围绕内容量，单个小环图不独占通栏，避免小图漂在大片空白中。来源span不是固定规则，卡内轨道与内容分区轨道分别按协议解释。

## 先核对实际能力

以上描述信息关系，不赋予新的组件字段、工具枚举或自动装配能力。先读本轮组件协议、实际工具Schema和能力目录，再选择实现路径：

- 页面协议能渲染某组件，不等于compose_page能生成它。组合卡、页签、分组表头、同卡跨源与局部颜色分别核对，不从组件可用推断全部属性可装配。
- 当前自动装配不支持compositeCard／tabContainer时，相关同卡组合及C5-A通过受支持的完整页面创作或已有页编辑路径实现；只能用compose_page的调用方说明缺口，优先选择可表达的C4-C／C4-D或C5-B。合法编译计划不证明未支持组合已实现。
- 审核原型中的中心合计、共享配色和局部尺寸不是新增协议承诺。当前Report主题缺少相应色板时，不声称已实现同色色点；属性不足时保留可读关系并说明呈现限制。

本参考不强制开启ECharts定制；高级配置按调用方已确认的定制范围及当前协议处理。MC提供能力事实和检查结论，Skill决定采用、替换、保存与交付。

## 创作完成核对

1. 每个组合有本次任务和数据依据，未新增无依据的客户、阶段、预测或业务视角。
2. 对象、主值与变化归属清楚，同级对象可比较，原因与证据相邻。
3. PC实际预览中检查独立主题能否凭卡面与间距辨认、同组信息是否仍相邻，以及最长名称、表头、末列、数值颜色、重复标题和容器空白；并排内容可同时核对，小图不独占大空行。用户要求的真实表格／构成图均已呈现，图形、数量与占比对应同一口径。
4. 页签默认内容与切换、表内滚动等按所用组合验证。用户首先需要的内容直接可见。
5. 协议有效、实际视觉和真实取数分别记录。静态校验不证明布局好看；无预览时明确视觉未验，不以组件数量或无溢出替代视觉结论。

## 预览、修复与复验

有目标浏览器环境时，创作者在结构校验后自行预览实际文件，按卡面归属计划逐组核对：背景与边界由谁提供、同层模块是否一致、主值与基期是否粘连、变体是否带来不合语义的前缀或外壳。PC Report至少覆盖常用会议宽度与较窄PC宽度；评测有明确视口时按该视口保存截图。

发现自身页面声明可解决的问题，继续修复并在同一视口复验；每轮完整输出先冻结，再校验与预览。完成依据是相关视觉问题已处理，或已明确记录当前能力／环境无法关闭的缺口，不能以“静态通过”结束仍可修复的呈现问题。缺少浏览器时继续可验证部分，视觉保持未验。

独立评测可以限制旧页面、历史答案和评测方提示，不应因此禁止创作者查看自己的产物。分别保留首版和自助修复后的结果、截图与原因；首版质量、自助修复能力及最终视觉结论分别报告。这是创作与验收流程，不新增MC保存或发布门禁。

本参考来自PC视觉审核，不是新增模型稳定性或真实Relay部署的评测证明。小屏只作附带观察。
