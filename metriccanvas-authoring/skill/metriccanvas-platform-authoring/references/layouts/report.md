# report 创建与修改基线

面向阅读、解释与分析报告。用户明确选择优先；用途不明确先澄清。创建前说明采用 report，并显式传 layout。

## 新建默认

对象概况用已注册的 metric-summary 表达意图，程序映射既有卡面与 rows/changes；可用形态由当前计划版本决定。每卡一个业务对象，辅助变化位于对应主值行内，绑定相同的唯一对象；按需选择双卡或多卡，保留语义宽度。重排或字号间距调整不能代替主辅指标组合。

同组、同层级的指标卡优先工整等宽排布：3 张一排三列，计划中每张显式 `width: "third"`（页面 `span: 4`）；4 张采用两行两列，每张显式 `width: "half"`（页面 `span: 6`）。卡片连续排列，说明文字另起通栏，不计入卡数，也不插进卡片组。不要依赖 pattern 的缺省宽度来表达此选择。用户明确指定的宽度、需要突出主指标的主次层级及已有页面布局优先；窄屏仍由运行时自动转单列，不为凑卡数增删业务内容。

完整报告以[场景与结构](../scenarios.md)组织业务章节：页头在 plain 分区；指标组、带图表章节优先用 panel（外层章节装饰、内层白色内容区）；纯表格或文字小节可用 card（白色内容底）。plain 是透明容器，仅在标题/装饰或已经有完整内容表面的独立组件上使用，不因指标卡内部有白底就省掉整组的白色承载区。有效业务内容落在白底，章节外层装饰可用渐变；不新增任意背景色参数。

新建保留[模块标题与组件标题](../reading-design.md#module-titles)两个阅读层级，按该规则处理真正重复的标题。修改已有页保留用户设置，除非用户明确要求调整容器。同章可组合不同口径内容，重要差异以阅读设计参考中的短业务说明表达。快速 compose_page 保留口径分区，兼容 operations 新建沿用 main。

采用统一运行时的定宽居中（当前最大75rem），较窄集成应用内收缩。组件占位使用既有12轨道/span；数据构造器已有比例装配，不把像素尺寸写入文档。响应式由集成应用容器宽度驱动，当前760px断点转单列；显式columnTracks、connectPrevious、铺底安全区继续按共同协议处理。

## 既有页转换

显式 set_page_layout 只切根形态，保留标题归属、容器、span、数据源、筛选、参数与手工属性，并返回呈现影响。看板工具栏在 report 不呈现，其声明保留；需要其中入口的用户应获知该影响。report + backdrop 合法时继续保留，窄屏铺底按原数组顺序回到内容流。

默认不是硬约束：不将已有 plain/card 改成 panel，不搬标题，不为适配新宽度删组件。整页校验失败时回滚；仅调整形态不能解决的真实冲突需明确目标设置后用受控操作处理。
