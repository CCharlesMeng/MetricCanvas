# 执行检查点

Workflow 指导模型选择与组织任务；权限、引用、版本、预算、页面校验和保存必须由程序执行。步骤没有成功回执就不能推导下一步已完成。以下表格同时是部署验收清单。

| 检查点 | 必要输入 | 可继续的证据 | 失败处理 |
|---|---|---|---|
| 本轮上下文 | 集成程序提供 context_ref、当前身份和完整创作基线；新建为空基线 | read_page_context 返回 pageId、workVersion、ref；已有资源通过 Java 当前读取核对 | 上下文缺失、过期、只读或 Java 读取失败，停止修改 |
| 修改目标 | 明确的章节/组件 ID 与必要配置；分页使用同版本 cursor | 目标唯一且属于本页；删除依赖已完整读取 | 歧义先澄清，缺失不从截图补造 |
| 分析计划 | 业务问题、指标定义、时间、筛选与核心问题 | 集成程序记录与 request 摘要和数据上下文版本匹配的授权 | ANALYSIS_PLAN_NOT_CONFIRMED 不查数；纯配置修改跳过本步骤 |
| 查询证据 | 已确认 request，或本轮 result_ref | 逐项检查 status、实际 scope、fields、rows、coverage；版本一致 | 空值、失败与零值分开；核心缺口阻塞对应结论；首批加最多两轮补查 |
| 页面表达 | resultRef、章节、字段选择与受控操作 | 标题/对象/期间一致；指标与单位相容；引用可追溯；章节顺序符合用户问题 | 不用无证据内容填充版面；未覆盖需求逐项报告 |
| 页面修改 | page_id、expected_version、operations；新建使用 compose 请求 | 目标页匹配、Java 当前基线匹配、工作版本竞争成功，逐操作整页校验 | 过期基线回到集成程序重建轮次；不自动合并或重放 |
| 草稿保存 | 合法且有变化的定义，冻结的 base 与 operationId | saveStatus=saved 且 ref/draftId/artifactRef 完整 | unknown/pending/rejected 停止发送；程序核对原提交 |
| 预览交付 | 保存返回的精确 artifactRef | page_metadata_emit_preview 返回 ready | 只修复预览交付，不再次查数或保存；ready 不证明用户已看到 |
| 最终答复 | 逐项操作与保存/预览回执 | 说明完成项、partial 缺口、保存状态；ready 时保留两个字面标记 | 不把合法 Schema、预览准备好或计划确认说成已发布 |

## 工具强制执行的边界

默认单轮共享预算：24 次调用、3 轮业务查询、2 次页面修改、300 秒；证据每结果最多 20 行、16000 字节，累计 96000 字节。部署可注入其他 Limits；以实际错误为准，不能换 context_ref 绕过预算。相同查询复用已记录结果，包括失败；只修改表达时不重查。

合法的独立成功操作可组成 partial 并保存；失败操作回滚，依赖操作 skipped。全失败、无变化或非法页面不保存。下一次修复必须读新 workVersion，最多一次有依据的定向修复。未知保存属于程序恢复，不能算一次“修复”重发。

程序可以验证字段、单位、组件形状和页面协议，不能仅凭 Schema 证明业务叙述与布局质量。模型必须在提交前检查阅读顺序、指标关系、期间和局限；实际页面呈现需要集成应用的渲染验收。没有渲染证据时如实说明验证范围。

## 部署验收

本发布要求上下文提供方、持久化工作存储、计划授权、数据发现/DQE、Java 当前读取与条件保存、Relay 预览适配器全部接通。仅启动 MCP 或 list_tools 成功不算功能就绪。至少实际跑通：新建、标题修改、新增数据块、partial、外部修订变化、保存结果未知、预览失败后恢复，以及取消后的迟到结果隔离。

Skill 内只引用可随包读取的执行规则。维护者查看 Bundle 的 tool/README.md，按调用链定位实现与测试；生产接通情况以集成回执为准，本地替身通过不能替代它。
