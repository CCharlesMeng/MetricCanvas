# 阅读层级与表达

创建完整页面或重新组织信息时读取；只改标题、列宽时无需加载。先决定读者要完成什么，再选择表达和占位；无需额外模型往返或向用户展示内部推演。

## 根据任务选表达

| 读者任务 | 优先考虑 | 必要条件与取舍 |
| --- | --- | --- |
| 快速了解整体与变化 | 指标摘要 | 主辅关系须有可信证据；整体和子对象可有不同宽度/摘要形态 |
| 比较不同对象大小 | 条形图 | 同量纲，标签较长时可横向；并列比较不等于构成，不默认堆叠 |
| 观察变化过程 | 时间趋势 | 有可信时间维度；几个期间含义不明的金额列不能拼成趋势 |
| 找待关注对象 | 精简列表 | 留下识别对象与判断所需字段；入选名单不等于全量排名或贡献 |
| 精确核对 | 通栏表格 | 保留任务所需列；不为了组件多样性增加无用图表 |

## 安排层级与空间

<a id="module-titles"></a>

### 模块标题与组件标题

业务模块的可见标题写在 `plan.sections[].title`，概括整组回答的问题，例如“流水总览”“目标与推演”；块的 `title` 标识具体对象或图表，例如“整体”“Core”“云通信”。`businessQuestion` 和 `businessObject` 是计划语义，不会自动变成可见标题。

多组件业务模块默认保留非空分区标题，包括多张指标卡、图表与核对表的组合。去重只针对单组件模块且组件标题与模块标题完全同义时，才考虑省略分区标题；页头、纯装饰分区和用户明确要求无标题的模块例外。不能因为每个组件已有标题就删掉模块层级，修改既有页面仍保留用户显式设置。

整体与子对象不是必须同等强调；根据任务确定哪部分先读。并排内容应便于同层比较，宽表和长时间序列通常需要通栏。分区容器表达共同归属，也承载内容表面；report 的具体选型遵循布局参考，不能因为组件有标题就把所有章节改成 plain。

重点对象只需一段短观察时，把它放在相关分析模块的图表或明细附近，并按阅读顺序决定前后；独立章节要有独立业务问题和足够内容。编辑既有页时，用户指出某章过短，应优先把其中内容并入相关章节，保留原有事实范围。

一源可多用，但每次表达要有独立用途：图负责比较、表负责精确核对可以共存。字段重叠提示不授权程序删组件。没有信息增量的块由模型在计划中省略，而不是生成后被隐式清理。

## 面向读者的文案

正文只呈现业务信息。查询粒度、可信关系校验、工具能力以及“本页不计算/不支持什么”属于执行过程，留在交接说明或程序审计，不逐章生成“口径说明”。v3 程序不自动追加查询范围正文。

确实影响理解的边界仍须可见，但用简短的业务语言就近表达：例如标题中的“年度推演”、名单副标题“仅含入选客户”、页头报告月份、趋势标题或横轴的期间。同一事实只出现一次；查询期间不冒充指标统计期间。用户明确要求的口径说明保留，不以关键词自动删除既有正文。

用户明确删去口径说明时，删除对应正文，不换一个标题再次添加。若报告还要求标明样例或非生产来源，用页头等已有可见位置承载最短标识。

## 交接前检查

确认每个业务问题有对应表达或明确缺口；多组件业务模块已声明可见分区标题；显式组件/宽度受到支持；正文没有从元数据推断数值结论；查询期间与指标期间没有混为一谈。检查有理由保留的重复与无意义重复，区分结构校验成功和用户视觉认可。

参考组合可以调整、裁剪；评价的是阅读任务是否完成，不是卡数、图数或固定栅格形状。
