# 知识维护与升级

修改本 Skill 的流程、协议参考或分发内容时读取本说明。普通页面创作按入口路由读取所需知识即可。

## 文件归属

| 内容 | 维护方式 |
|---|---|
| SKILL.md、本地流程、布局指南、短写法、地图说明、本说明 | 作者维护；记录实际问题，再修改对应规则 |
| scripts/snapshot-attempt.mjs | 作者维护；验证原始字节保留、重复目录拒绝和哈希检查 |
| references/page-metadata/ | 从产品协议、字段语义和完整示例统一生成 |
| references/map-regions.json、assets/layouts/overview-map-led.json | 从实际底图和通用布局维护源生成；完整样例生成时必须校验 |
| scripts/validate-page.mjs、scripts/THIRD-PARTY-LICENSES.md | 从产品校验器及锁定依赖生成，运行只依赖 Node 内建模块 |
| references/knowledge.json | 锁定生成文件的版本与SHA256；不包含作者说明文件的哈希 |

安装副本消费生成知识。维护者在产品维护仓库修改真源并生成整套文件，再交付完整目录；生成文件的直接修改会在下次更新被覆盖。流程改动不能改变协议字段语义，业务页面示例不能成为通用业务口径。

## 更新检查

1. 区分协议变化、创作流程问题、模型未遵守已有规则，以及缺少数据或运行环境；只修改有证据支持的维护源。
2. 同一产品版本生成协议参考、地名、完整样例、校验器与知识清单。核对[知识清单](knowledge.json)的 schemaVersion，并执行：

   ```sh
   node "<skill-dir>/scripts/validate-page.mjs" --version
   node "<skill-dir>/scripts/validate-page.mjs" "<skill-dir>/assets/layouts/overview-map-led.json"
   ```

3. 将整个目录复制到无产品源码和依赖的临时位置，检查目录内链接与文件哈希，并运行合法及非法页面校验。所有知识链接和脚本运行依赖均在此目录内闭合。
4. 工作流或例子有实质变化时，用原始需求、设计与独立数据验证。评估模型读取本目录和本次输入；期望值、旧结果、先前反馈由验收方保管。保留实际使用的说明版本和每轮原始快照。
5. 分开记录静态校验、独立计算、浏览器视觉/交互与真实取数的结果。存在失败项时保留其结论；文档追加说明通过静态检查，不等于模型复测通过。

## 安装副本的更新与回退

复制完整 metriccanvas-local-authoring 目录，包含 references、scripts、assets。替换前备份当前完整目录；替换后核对版本并重新校验用户目标页面。回退也恢复整个目录，避免协议、校验器或作者说明混版。

安装副本不需要产品维护仓库、其他 Skill 或在线工具。外部设计、数据和页面是本次工作输入；更新知识不能引入指向安装目录外的知识软链接。页面试验场与数据服务由用户项目提供，并分别验收。
