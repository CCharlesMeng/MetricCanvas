# 布局形态识别与确认

Dashboard（看板）和 Report（报表）是同一个页面的两种布局形态，对应顶层 `layout`；不是两类资产。布局形态决定外框，阅读目的指导内容组织，两者分别判断。页面使用 query 或 inline、是否有图表或日期筛选，都不能单独决定形态。

## 识别依据

先核对本次用户指令，再看设计源的整体阅读与操作方式；已有页面的显式形态用于说明当前状态，示例名称和组件名只作辅助。说明依据来自用户原话、设计源可见结构还是模型推断。

| 观察维度 | 倾向 Dashboard | 倾向 Report |
|---|---|---|
| 使用目的 | 持续查看状态、比较主题、筛选定位对象、下钻办理 | 按顺序阅读结论、趋势、原因和明细，形成周期分析材料 |
| 外框与层次 | 占满集成应用宽度，多列主题卡、地图、清单或对象详情 | 定宽居中、明确报告标题与章节，正文承接图表证据 |
| 操作组织 | 统一工具栏筛选、Tab、列表搜索排序、明细导航 | 报告期间、章节阅读、报告日期工具带与整份报告下载 |
| 常见需求 | 作战地图、运营概览、机会点清单、项目详情 | 经营月报、专项分析、风险简报 |

按证据给出“明确／倾向／不确定”，不编造概率。用户明确指定的形态优先于模型偏好；当需求、设计源或已有页面存在实质冲突时，按下节单独确认冲突处理。没有强信号时给出一个推荐及理由，再让用户选择。

容易误判的输入：

- “分析”“月度”“经营”两种形态都可用；“运营分析”几个字不足以推断 Report。
- 表格密集的筛选清单仍可为 Dashboard；有趋势图或多个 KPI 的月报仍可为 Report。
- `reportHeader` 是可复用内容页头。对象详情可使用它，并隐藏 Dashboard 统一工具栏；组件名不能覆盖页面的显式 `layout`。
- “需要导出 Excel”只表达表格操作；“需要 PDF”可能只是交付方式。若已明确 Dashboard，先核对当前协议支持的交付能力，说明缺口，不能为满足下载而自行改成 Report。
- 地图、多列或深色背景只是辅助证据；截图裁剪导致看不到外框或工具栏时，标记未知，不补造图中行为。

## 确认完成条件

确认摘要列出形态及依据、内容分组与阅读／操作顺序、主要交互位置、候选范式，以及冲突／未知项。此时可根据本节及原始输入描述组织意图，详细范式与协议装配留待确认后读取；不生成完整章节骨架。未确认时，当前轮只给出如下摘要，并等待用户答复：

> 推荐：Dashboard（看板，满宽）。依据：设计源以地图和并列业务卡扫描状态。组织方向：顶部公共筛选，主题指标与地图对比，下方重点对象明细；候选采用地图概览范式。未知：截图未说明是否需要报告导出。请确认按此方向生成，还是采用 Report（定宽、章节阅读）？

高置信度也执行确认；聊天工具可用选择题，无工具时直接提问。用户尚未答复、只确认数据口径、回复“继续”但上下文存在多个未决选择、或等待超时，都不构成形态确认。无人值守时返回待确认状态，不按默认值生成。

以下输入在没有未解决冲突时已构成明确确认，简述组织方向后继续，不再机械多问一轮：

- 本轮指令明确指定“生成 Dashboard”“做成报表（Report）”或给出目标 `layout`。
- 用户直接回答本次形态问题，例如“用看板”或“就按你推荐的 Dashboard”。
- 当前任务此前已经确认同一个目标页面的形态，后续需求没有改变该选择。

记录目标页面、所选形态和用户确认原话／消息依据，放在会话摘要或项目的任务记录中；不往页面 JSON 写确认状态、置信度或新协议字段。明确选定一个形态后，才读取该形态范式并开始章节、组件和数据源装配。

已有页面仅改标题、格式或绑定时沿用原形态；旧文档省略布局按协议默认 Report 解释，不能把它当作新需求的确认。整页重组需重新核对本次确认；明确要求切换为 Dashboard／Report 的新指令本身就是新的确认。

## 冲突必须单独确认

实质冲突包括：用户要求与设计源明确的外框／组织方式不一致；用户要求的形态与同时要求保留的交互或当前协议能力不兼容；原页面形态与本次重组方向相反。仅组件名称、模型偏好或关键词不同，不构成冲突，例如 Dashboard 使用 reportHeader 无需额外确认。

列出冲突证据、保持原样与适配目标形态各会产生什么结果，再给出推荐并等待针对该冲突的明确答复。例如：

> 你指定 Dashboard，但提供的是定宽月报设计，包含封面和连续章节。建议保留指标与分析内容，将封面改为工具栏标题，并按主题重组。请明确选择“按 Dashboard 适配”或“保持设计稿的 Report 组织”；确认后开始生成。

已有“用 Dashboard”只确认当时已知的选择，不自动解决后发现的冲突；用户只回复“继续”且选项仍不清楚时继续等待。如果本轮指令本身已明确处理同一冲突，例如“将这张月报按 Dashboard 重排，保留全部指标”，引用该依据继续，不重复询问。冲突确认解决后更新组织摘要，并记录采用方案与必要偏离；不添加页面协议字段。

## 确认后的核对

新建页面显式写当前协议的 `layout`。历史文档保留合法兼容字段，按本次修改范围决定是否规范化。使用独立校验器的 `--expected-layout dashboard`／`--expected-layout report` 比对本次确认与文件的有效布局；兼容旧文档时省略布局仍按 Report 解释。不一致时修复文档，不能只以 Schema 合法判定满足选择，也不能从待验文件反推命令参数。交付说明列出形态、确认依据、组织方向及采用的范式。该检查不验证会话确认或业务组织质量。结构与布局规则见[页面](page-metadata/page.md)、[分区](page-metadata/sections-and-layout.md)。
