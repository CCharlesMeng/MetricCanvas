# 页面调试

用于页面 JSON 报错、没有数据、数值不对或交互失效。目标是解释并修复已观察到的失败；页面配置、查询执行、运行时渲染和外部服务分别取证。

## 固定复现条件

确认实际打开的页面文件或页面版本、复现操作、预期与实际结果。保留用户提供的错误，以及当前工作文件的原件快照；同名本地文件不能替代浏览器实际加载的文档。已有足够证据就继续定位，只补阻碍判断的输入。

先用独立校验器检查候选快照，保留退出码及原始错误路径。无法解析的 JSON 先恢复语法，再检查协议；多个联合分支错误先找共同的上游声明，不逐条删配置。校验合法仍有现象时，继续检查请求、数据或交互，不把合法性当作修复成功。

## 沿失败链定位

按[场景索引](scenario-index.md)的“debug 按症状进入”表选具体逻辑：

遇到 `DQE_CONFIG_ERROR: 数据网关未配置全表文本搜索能力`，先读[全表文本搜索定位与修复](table-search-gateway-repair.md)，区分请求前编码失败、页面搜索语义和部署版本，再按业务需求选择精确搜索或网关适配。

- 配置与引用问题：对照错误路径、声明和消费位置，只读取受影响对象。未知位置先发现实际组件位置，再使用回执中的 JSON Pointer；字段使用页面契约中的 id。
- 请求与数据问题：核对当前生效筛选/参数、实际查询分支、请求、响应和 queryField。区分请求未发出、请求失败、成功空结果与字段映射丢失。有多源、Tab或条件分支时，检查所有涉及的成员与未激活分支，避免只修复首个报错源。
- 数值与展示问题：从原始响应和字段契约判断是口径、计算、映射还是格式差异；按所涉绑定读取知识。不修改原始数据来迎合显示预期。
- 交互问题：沿“操作 → 状态/参数 → 消费绑定 → 请求 → 显示”找到首次偏离；控件值变化不证明数据变化。

真实请求或运行环境缺失时，保留已验证事实、当前假设及缺少的最小证据。可独立确认的配置错误照常修复；服务能力、权限或运行时源码问题交付精确诊断与复现材料，不伪造已修复结论，也不通过删行、删查询或更换数据掩盖症状。

## 最小修复与复验

先说明哪个证据支持修改及必须保持的行为，再修改原因所在。合法且可解析的原件、明确的局部修改范围，使用入口中的 finish-edit；原件 JSON 无法解析或修复涉及结构重建时保留原始字节，使用候选快照和完整校验，不为套用范围检查而放宽 allow。

完整页面校验通过后，用相同输入与操作复验原现象，并核对共享消费者。查询问题以实际请求与响应为证，呈现或交互问题以目标运行时为证；缺环境时交“配置已修复，原现象待复验”及所需条件。产品缺口不能由 Schema 校验通过抵消。

交付包含原因与依据、修改文件、原问题的复验结果、未解决项。失败候选和原件按[临时产物生命周期](local-workflow.md#临时产物生命周期)保留；明确要求保留评测记录时不自动清理。
