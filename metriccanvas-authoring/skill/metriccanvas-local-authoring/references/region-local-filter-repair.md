# 区域与局部筛选联动

用于新建／调整 IOC Region 与局部筛选联动，以及修复切换或 URL 恢复后图表按钮消失、隐藏条件仍参与查询、返回全球后选择丢失。局部筛选包括组合卡、Tab 内的 `filterGroup`；不要仅检查页头。

## 先还原输入

保留用户提供的完整 URL 参数，从目标页的 Region 声明和授权候选核对实际 `values`、`level` 与 `dimension`。`region-dept=全球` 会恢复为地区部层级、选中值 `全球`；不能仅因 `level !== "geo"` 就认定用户选中了具体地区部，也不能把所有全球输入都当成 `values` 为空。IOC 的规范值 `全球` 表示不限制 Region 查询，与节点所在层级分开判断；其他中文标签或业务编码不自动等价于全球。

相关协议只读本册[Region URL 输入](page-metadata/filters.md#region-level-url)、[IOC 业务筛选](page-metadata/filters.md#business-filters)与[条件绑定](page-metadata/queries-and-bindings.md#filter-binding-when)，或运行 `node "<skill-dir>/scripts/read-knowledge.mjs" show --topic query.bindingWhen`。这些协议已有表达能力时修页面配置，不新增 Schema 字段或修改引擎来补偿页面条件。

## 同时核对显示与执行

1. 找到所有相关筛选控件、父容器条件和数据消费者，包括组合卡、未激活 Tab、共享页面数据源、查询分支和组合查询的成员。逐一列出“筛选 id → 控件 → 查询绑定”，不能只修第一张可见图。
2. 按用户要求区分“全球范围”与“具体组织”。业务要求全球时显示的控件，条件须覆盖规范值 `全球`，不能只比较层级。空选是否算全球、其他 geo 节点是否显示，沿用该页已确认口径；不把某个业务页的选择扩成所有页面的默认规则。
3. 控件的 `visibleWhen` 只控制呈现，不暂停查询。若要求隐藏时暂停该条件，在每个相关维度 `filterBindings` 上以 `when` 声明同一生效范围；不删除筛选、默认值或绑定，也不清空保存的选择。若隐藏时仍应过滤，则保留原执行规则。
4. 保留期间、区域、客户分类、权限及固定查询条件。四组独立按钮仍各自绑定，不将其中一组选择复制到其他组。再次回到全球时应用各自保留的选择和 URL 状态。

例如，某页已确认“geo 层级或规范值全球时显示站点选择”，则控件 `visibleWhen` 和对应绑定 `when` 均使用以下条件；若该页的全球口径不同，先据实际输入调整条件，不直接套用：

```json
{
  "any": [
    { "filter": "region", "part": "level", "op": "eq", "value": "geo" },
    { "filter": "region", "part": "values", "op": "containsAny", "values": ["全球"] }
  ]
}
```

`when` 从 Schema 6.100 起支持；旧页按[旧页面继续开发](page-upgrade.md)升级并核对目标引擎能力，不通过降低版本或只改显隐绕过。

## 按原始链接回归

先以用户完整参数重现，再覆盖以下适用状态。实际组织取值来自授权候选，不虚构业务值。

| 输入或操作 | 检查 |
|---|---|
| 用户原始 URL，特别是 `region-dept=全球` | 所有预期局部筛选可见，默认值/URL 选择正确，实际请求消费各自选择；全球不生成具体组织谓词。 |
| 该页支持的 geo 全球输入与空选 | 按已确认口径显示或隐藏，不只验证默认空参数页面。 |
| 具体地区部及代表处 | 按要求隐藏按钮并暂停对应站点谓词；组织、期间和其他条件保留。 |
| 各组分别改选 → 进入具体组织 → 返回全球 | 每组独立恢复，其他组不串值；刷新仍保留。 |
| 正常、空结果、查询失败及相关 Tab 切换 | 数据状态不误删控件；检查所有共享消费者。 |

完整页面校验只能证明结构及引用合法，不能证明业务显隐和有效查询一致。有目标运行时则查看精确页面、控件和实际 execute 请求；用拦截或合成数据时明确其性质。缺环境时报告未验证的浏览器/真实取数范围，不能把静态通过写成问题已完全验收。
