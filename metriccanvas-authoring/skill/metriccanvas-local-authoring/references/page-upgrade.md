# 旧页面继续开发

入口判定需要协议迁移时读取本页。当前版本内的属性修复和新增已支持能力沿用准确上下文，编辑后完整校验。迁移属于本次本地开发准备，无需另行询问是否启动；已有形态沿用原值。工具只做创作期转换，不修改历史发布修订或目标运行时读取策略。

<a id="新增特性的版本闭环"></a>

## 新增特性的版本闭环

1. 运行 `node "<skill-dir>/scripts/validate-page.mjs" --version`，以返回的 schemaVersion 作为本轮目标，不从记忆、旧示例或特性的最低版本猜测。新建页面使用这个版本。
2. 原件版本等于目标且无已知迁移形状时直接编辑，完整校验放在编辑后。需要升版时，在原件尚未加入新特性前执行下方升级检查；ready 时在项目外的本轮临时目录写出一次备份与迁移结果，再接回工作文件。同轮复用该备份，不为每项特性重复升级。核对目标版本后再加入新声明，用户无需自行修改版本号或管理备份。
3. 若已在旧版本文档中加入新声明而遇到能力下限错误，保留失败尝试，回到本轮原件先迁移，再重放本次局部修改。原件已有的旧语义缺口按下文处理，不用只改版本号掩盖错误，也不删除用户要求的新能力来通过校验。
4. 编辑后再次核对工作文件版本等于本轮目标，运行 validate-page 完整校验，并按需求检查实际字段位置及预览。旧版本原页仍合法但升级受阻的保留路径，只适用于本轮未引入更新版本能力的局部修改；新增能力所需的迁移由 Skill 继续处理，只有明确的业务语义选择才交用户确认。

目标版本是安装包当前支持的版本。若所需能力超出安装包，明确报告需要更新完整 Skill；已知目标运行时更旧时，明确报告实际版本差异及运行时升级需求。没有目标运行时信息时标记运行兼容性未验证，静态校验不能证明部署可用。交付说明本轮原版本、目标版本及校验／预览结果；仅在仍保留恢复材料时报告其位置。

## 检查与写出

```sh
node "<skill-dir>/scripts/upgrade-page.mjs" "<page-file>"
node "<skill-dir>/scripts/upgrade-page.mjs" "<page-file>" --out-dir "<task-temp-directory>/upgrade"
```

第一条只检查，不写文件。`status:unchanged` 表示已是当前写出形状，可继续原任务；`ready` 表示有可执行的迁移。第二条由 Skill 在系统临时位置为本轮新建独立父目录，将 task-temp-directory 替换为该路径，upgrade 子目录须尚不存在；不在项目或页面目录里堆放备份。工具在其中写出：

- `original/<原文件名>`：原始字节；回执的 inputSha256 可复核原件。
- `page/<页面id>.json`：通过完整目标协议校验的新页面。
- `migration.json`：来源/目标版本、规则、变更位置、警告和结果路径。

写出成功后先核对备份与迁移报告，再把升级结果复制回用户指定的工作文件，继续完成用户要求的修改。处理中保留恢复材料；结束时统一按[本地创作与验收](local-workflow.md)的“临时产物生命周期”清理或保留，不默认长期归档。原文件名与页面id不一致时，说明校验器的命名要求并保持页面身份，使用与id一致的工作文件。不要把“已升级”当作业务修改完成。

候选输入为5.0—5.4和6.0至工具当前版本；能否迁移由能力下限、具体规则和完整目标校验共同决定。工具只写当前版本，目标运行时需要支持该版本；已知宿主更旧时先说明版本差异，不生成声称可部署的升级结果。`--target` 可显式声明目标，当前仅接受本工具的当前版本；查看 `--version` 和 `--help`。

当前规则覆盖已知版本的布局规范化、5.x导航兼容转换及旧图表筛选向独立filterGroup的转换。图表筛选保持图表id、外层跨度、筛选器、默认值、选项和查询绑定；组合卡内旧图表筛选需在原卡内显式拆分，避免创建嵌套组合卡。5.x导航转换后的部署URL需预览核对。

用户要求旧 header 换成新版时，升级后继续按[页头迁移](ioc-header-migration.md)处理。`upgrade-page.mjs` 会将旧根级IOC页头转为首section中的组件；普通旧工具栏因Region、返回及导出语义差异返回blocked。正文 `reportHeader` 的业务迁移仍需单独处理；`unchanged` 也不表示页头迁移已完成。

`blocked` 返回退出码1，errors保留type/path/message，不写出页面。先用validate-page校验原件：原页仍有效，且本次需求只用到该版本已支持的能力时，保留原schemaVersion和历史语义继续局部修改，再校验；报告“保留原版本完成开发，整页升级未执行”及升级缺口。不要为改标题、文案等局部需求强制用户先处理整页迁移。

原件无效或本次确实需要新版本能力时，定位报出的字段完成显式迁移。未知/未来版本、能力下限错误、非法配置、6.5/6.6非空数组参数的旧写入语义，以及6.13/6.14页头filterIds触发的自动期间文字不能仅靠改版本号解决；涉及业务语义选择时只澄清该选择，继续可独立完成的工作。保留合法查询、参数、initial、筛选和交互。

文件/参数错误退出码2，修正调用后重试；输出目录已存在时换新目录，保留失败尝试。完整业务修改后仍按主流程保存尝试快照、运行validate-page并验证实际预览。静态迁移不证明真实查询、线上保存或发布成功。
