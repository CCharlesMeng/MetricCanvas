# 概览页面的常见布局

这是通用页面组合方法，不是某个 IOC 页面的答案。先总结输入的阅读目的、业务章节、图形和交互，再选布局；来源截图与用户要求优先，不能从旧结果 JSON 反推。字段、数据与导航依据本次输入。

## 三种布局

| 布局 | 适用目的 | 宽屏结构 | 需要核对 |
|---|---|---|---|
| 地图主导 | 对比地域差异，兼看管理指标与项目明细 | 顶部三张业务卡横排；下部左侧明细约1/3、右侧地图约2/3 | 图例、地图行、地域名称命中；卡片内指标/分类不分离 |
| 趋势主导 | 看当前值与时间变化 | 顶部KPI带；中部趋势约2/3、异常/排行约1/3；底部完整明细 | 横轴时间、单位、排序、趋势与明细口径一致 |
| 管理主导 | 按多个管理主题扫描状态 | 每个主题一张组合卡，宽屏通常三列；每张卡含主指标、分布、明细/说明；下部对比或明细 | 主题不能变成一个巨大的竖排指标清单；图形不代替完整类别和值 |

地图主导的阅读骨架：

```text
标题与必要筛选（由统一工具栏或明确页头承担一次）
┌─────────────┬─────────────┬─────────────┐
│业务卡 A     │业务卡 B     │业务卡 C     │
│主值/变化    │主值/比率    │主值/比率    │
│分布+完整值  │分布+完整值  │分类+完整值  │
├─────────────┼─────────────┴─────────────┤
│切换明细     │地图、图例、地域提示         │
│约 1/3      │约 2/3                       │
└─────────────┴───────────────────────────┘
```

## 映射到当前页面协议

- 分区默认12条等权轨，组件 `layout.span` 是占轨数：三卡各4；表与地图4+8；趋势与排行8+4。非等权只用分区 `columnTracks`，没有 `section.columns`。不同分区不能靠相同 span 自动并排，需并排的内容放在同一分区。
- 三卡用三个 `compositeCard`，每个卡的业务指标、饼图与分类明细放在同一 `props.components`。不要把一组指标放第一分区、对应分类放第二分区，造成业务卡拆散。
- 主指标少量横排先看 `metricCard.variant="compactStrip"`；单个主值看 compactSummary。多行大号 summary 会把卡拉得很高。变化用 `rows[].changes[]`，不是 changeField。
- 分类图与明细并排：卡内 `pieChart` 约5轨、`categoryBreakdown` 约7轨，二者使用同一分类字段。`swatches:true` 需要同页饼图共享分类字段，不允许单独开色点冒充分类色板。
- 容器与子项各自占自己的12轨，顶层卡span4并不意味着卡内子项也只能span4。mapChart 与 tabContainer 放顶层；不要凭直觉把任意组件塞进组合卡。
- dashboard 默认工具栏显示 meta.title。不要再加重复标题的 reportHeader。确有独立内容页头时核对是否应隐藏统一工具栏；dashboard 的 reportHeader 不允许 report 专用 filterIds 工具带。
- 多筛选、长说明与窄屏优先使用`dashboardToolbar: "visible"` 或省略字段的默认工具栏，说明作为独立 text。compact 是单行呈现，不适合作为多控件窄屏默认；readOnly=true 会禁用控件，不能用它绕过业务要求。

可直接校验的[通用地图主导完整示例](../assets/layouts/overview-map-led.json)只演示组合、布局与国家地名，不含 IOC 指标口径或真实查询。其三个市场是演示国家，不代表业务宏观地区。按需看[常用合法写法](component-recipes.md)和[地图核对](map-bindings.md)。

## 验收

宽屏先核对标题是否重复、三张卡的业务归属、图形/分类是否保留、地图与表是否在同一行。再检查组件实际高度，不能只看 span 数字。

窄屏检查实际页面 scrollWidth 与视口；表格横向滚动在表容器内，不等于允许整页溢出。工具栏、长说明、Tab 与字段长文本也分别检查。不能因缺浏览器就声明响应式通过。
