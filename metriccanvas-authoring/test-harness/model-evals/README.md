# Platform Skill 真实模型行为评测

本目录交付可执行环境接入前的用例与判定约定。`platform-authoring.cases.json` 的执行状态为 `not_run`；它不是模型输出记录，不能计入准确率。公开工具与浏览器的确定性证据另见 platform-skills-evidence.md。

## 运行前置

由 Relay 提供方提供评测入口、两个 Skill 的真实注册/路由及旧问数入口隔离；记录实际模型 ID/版本、采样参数、Skill/Bundle/内容工具 SHA。准备隔离身份/工作区、可信基线读取与文件 token 映射、已启用的安全摘要过滤、受治理 Data Context/DQE 接口和需要时的总结服务。明确评测账户及调用预算后再运行；本目录不内置端点、凭据、伪造模型答案或提供方 HTTP API。

每个 baseline 由可信程序根据标记夹具构造并计算 ref/hash，不把整页给模型。模型只收到 prompt、必要页面/组件摘要和可信 token。`test_page_editing.page()` 可生成含手工标题/列宽/布局的代表基线；将 layout 设为用例值。`test_interaction_editing.interaction_page()` 提供已解析 queryField 的查询基线。旧问数入口必须按现有配置独立触发。

## 每例执行与判定

1. 使用用例 context 初始化隔离会话；manualChanges 由可信程序应用，后续轮次读取新精确基线。按 turns 顺序发送真实问题；需要澄清的用例先保留等待状态再发送回答。
2. 记录真实选中的 Skill、工具名/受控参数、调用顺序、模型答复、状态转移、产物 SHA 与程序侧前后 diff。另存完整原始 trace 于受限证据目录，模型上下文及对外报告不得含整页/数据行/凭据。
3. 逐项评估 expected：路由、显式 layout、等待/澄清、目标命中、依赖闭合、未触及内容字节级保持、真实冲突失败，以及答复是否误称保存。布尔判断应来自工具trace/产物diff；语义回答由评审记录理由。缺必要 trace 标为 inconclusive，不计通过。
4. 错路由后重建基线、越过用户意图改整页、泄露程序产物或冒称保存单独列为关键违规。逐例记录 pass/fail/inconclusive/blocked；统计分母、重复次数、创建/修改与两形态分组，不把未运行例当成功。通过阈值及允许重试次数由项目验收方冻结，本目录未自行设定。

创建与修改四组合必须分别跑；切换/缺基线/手工语言多轮及合法跨形态组合增加独立用例。普通问数行为需回归。真实 Relay/模型成绩与确定性工具测试、本地 HTTP 浏览器、外部生产联调分别记录。

## 当前缺口

未获得本轮真实 Relay 评测入口/身份、模型版本与采样参数、双 Skill 注册回执、受控数据服务配置、可导出 trace 的基线/产物通道及授权评测账户/预算。所有 cases 均未运行；本仓没有调用真实模型或实现替代 Relay。
