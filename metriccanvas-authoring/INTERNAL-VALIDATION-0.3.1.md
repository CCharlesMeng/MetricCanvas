# 内部接入验收

执行环境：实际 Relay、Java、DQE 和内部身份；本地 mock 不能替代本清单。操作入口见 [接入说明](RELAY-HANDOFF.md)。版本记录必须包括公共提交、内部提交、Bundle 0.3.1、接口 authoring-adapters/1.0 与构建产物哈希。

## 预检

1. check_bundle.py 通过，证明公共文件一致；它不校验内部实现。
2. check_adapters.py 通过，证明工厂版本和方法已装配；它不证明外部连通。
3. 使用真实 contextRef 运行 check_adapters.py --context-ref，核验真实可信轮次。
4. 内部确认身份按调用隔离、共享存储跨进程可达、程序产物通道可接收。

## 最小主流程

| 场景 | 操作与期望证据 |
|---|---|
| 创建 | 新轮次读取配置→发现→授权查询→compose_page→Java 保存→程序产物接收；保存一次、ref 与文档一致 |
| 编辑 | 新轮次重新打开已保存页面→核对当前修订→edit_page→条件保存→交接；修订前进，未修改字段保留 |
| 跨子进程 | 查询与创建分不同 MCP 子进程，仍能读取同轮状态和结果引用 |
| 拒绝 | 未确认或版本不匹配请求 DQE 调用数为零；过期页面不保存 |
| 并发 | 同一工作版本 CAS 仅一个成功；Java 条件写保护真实当前修订 |
| 保存未知 | 模拟响应丢失，保留冻结提交和核对状态；重复或变更请求都不自动重发 |
| 交接失败 | 已保存后回执不匹配，单独报告交接失败；不再次保存 |
| 公共升级 | 同步前后内部 adapters 文件哈希相同；重新安装及接口检查通过 |

记录每个场景 pass/fail/blocked/not-run、关联 ID、DQE 调用数、Java 保存数、产物接收数。禁止回传凭据、SQL、完整业务数据或原始错误响应。

真实模型与页面可见性是独立证据：有需要时在真实 Relay 上运行相同创建/编辑流程，并确认内部展示入口消费产物；ready 只表示接收。当前本地交付不声称真实模型、内部服务或浏览器验收已完成。
