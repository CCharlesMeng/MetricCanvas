# 页面创作流程交互原型

THROWAWAY PROTOTYPE / 早期交互评审稿。问题：手动编辑与自然语言调整如何共用前端最新工作副本，执行锁如何呈现，管理信息编辑如何走直接接口。

架构设计入口：[本轮主方案](../../../../docs/plan/2026-10-24-agent-authoring-flow.md)。原型代码位于平台应用旁，完全隔离于正式路由、入口和产品行为。

正式 MC 实现已提供：`pnpm --filter platform dev:agent-flow`，完整会话与 URL 场景见 [Platform 验收](../../../../pages/platform/README.md#云宝创作与最新工作副本)。本目录保留离线状态原型，不与生产入口混用。

## 打开与运行

先执行下方构建命令生成本地单文件 prototype.html，再直接打开，无需服务或账号。生成的 HTML 与 evidence 原始产物不随源码提交。该文件内联全部 JavaScript/CSS，包含真实 `@metriccanvas/ui`、MetricCanvas 与 RuntimeView；样例数据、Agent 和接口均在内存中模拟。为复用本仓实际组件，源码通过现有 Svelte/Vite 编译，交付仍为一个可离线打开的 HTML 文件。

在仓库根目录重新生成：

```sh
node apps/platform/prototypes/agent-authoring-flow/build.mjs
```

需要浏览器 HTTP 地址时，在本目录运行 `python3 -m http.server 5186 --bind 127.0.0.1`，打开 [原型](http://127.0.0.1:5186/prototype.html)。该地址仅用于原型本地评审。

## 四条路线

每个页签提供顺序引导按钮，同时可以自由操作实际界面；切换页签或重置路线会重置内存数据。

1. **手改后对话**：按引导修改图表标题、发送自然语言调整、核对本轮输入。前端图表标题和本轮输入一致，模拟服务端的图表标题仍为旧值。
2. **新建与发布**：空画布生成初版、发送发布请求、确认保存访问地址、进入管理。所有工作台操作进入同一个 Chat。
3. **管理信息与路径**：行内修改标题并保存、进入独立表单修改路径并保存。Agent 发送为 0，直接接口调用为 2。
4. **执行失败与锁定**：保留手工图表修改、发起对话、模拟失败、核对内容保留与编辑恢复。

点“查看演示记录”可以看到当前/服务端/本轮输入标题、锁状态与调用计数。记录属于原型观察工具，不是计划新增的产品流程。

图表复用真实画布选择、属性编辑与移动能力。桌面右侧可改所选组件标题，较窄布局在画布工具栏下呈现同一属性输入。管理页没有 Chat，行编辑可取消，独立表单只编辑基本信息与可访问路径。路径缺少当前 pageId 时保留表单并提示。

### 复杂度

口径：仓内 `metriccanvas-ts-ast/1`，TypeScript 5.9.3。对新 TS/MJS 全文件、Svelte script 以及模板内全部箭头/函数表达式分别测量，包含嵌套回调；未将整个 Svelte 文件作为 TS 解析。模板 if/each 属于界面状态展示，不以函数 CC 伪装覆盖。

本轮新增 82 个函数，全部 `selfCC ≤ 8`，无超过 15 的未关闭项；新增前无对应函数，基线为不适用。`model.ts` 30 个函数最高 8，构建脚本 5 个函数最高 2，Svelte script 30 个函数最高 5，模板表达式 17 个函数。逐函数结果见 [complexity.json](evidence/complexity.json)。本轮没有修改产品存量函数。

### 证据限度

原型不调用真实云宝、Java、Relay、DQE 或门户，不证明真实 SDK 的发问方法、结束通知、元数据回显时序、自定义访问路径可达或实际保存成功。处理时长和生成内容为确定性替身，不能作为真实时延/模型质量证据。

源代码与原型均为本轮新增文件，工作区其他修改未纳入本批。未提交、未推送、未部署。待用户审核原型、获得实际交互结论后，按 prototype 工作流保留独立原型快照，再实施产品工作包。
