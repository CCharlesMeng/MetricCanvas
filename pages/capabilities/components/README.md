# 基础组件与共享内联数据

## 六类基础组件

页面 `component-foundations`，独立入口 `/pages/component-foundations`。运行 `pnpm dev:playground`，无需额外服务或 URL 参数。布局明确为 Dashboard，采用主题分析范式，按组件分区对比数据消费方式。

所有数据均为内联合成数据。区域行按签约数量 72、45、30 的给定顺序排列；变化分别为 8、-3、2，不代表真实增长口径。单行来源显式保存华东记录。仪表的示例完成率为 72%，刻度为 0 至 100，不做比例换算。

1. 从组件目录进入仪表、排行卡、详细排行卡、信息面板、分类明细或字段长文本，各自只展示对应的组件分区。
2. 仪表显示 72%；排行卡和详细排行卡按华东、华南、华北展示；详细排行卡附带变化与合成说明。
3. 信息面板显示华东及数量 72；字段长文本读取单行来源中的说明；分类明细列出三地的数量。
4. 从数据与联动的「定义取数」或「数据关联与组合」进入同一场景，可以同时看到六个分区。多行来源被排行和分类组件共享，单行来源供信息与长文本消费；这里不执行关联查询或重新聚合。
5. 点击「在此基础上试改」，修改内联华东数量后，使用该来源的组件更新。制造 JSON 语法错误后应显示错误，修复后恢复；「恢复当前示例」还原运行输入，不改仓库文件。

关键声明：`dataSources`、组件的 `data.main` 和 `props` 字段绑定；完整页面中 `sectionAnchors` 提供分区定位。组件目录的分区投影只服务本场景，实际数据来源不被重新定义。

本例不请求 DQE，不证明真实查询、权限或生产接入。单行来源与多行来源是两份显式内联数据，不宣称两者存在动态派生关系。
