# MetricCanvas 下一阶段产品规划：页面目标 + 指标 + 维度驱动生成

> 文档状态：规划提案
> 规划日期：2026-07-30
> 适用范围：MetricCanvas 下一阶段产品演进
> 关系说明：本文是独立产品规划，不修改、不替代 [`docs/solution.md`](./solution.md)；关键判断来自[《从“前端页面 + 数据”演进到“指标 + 维度驱动看板页面生成”》](./research/data-dimension-driven-page-generation.md)。

## 1. 产品决策

下一阶段采用以下产品定位：

> **由页面目标约束、由数据服务治理的指标与维度供给驱动、由确定性规则和 AI 共同规划、由领域 DSL 承载的看板页面生成。**

这不是把“前端页面 + 数据”替换成另一套动态前端生成技术，而是把看板页面的创作入口从手工编排升级为：

```text
页面目标 / 受众 / 分析问题
            +
数据服务治理的指标、维度、聚合、关系与安全语义
            +
可解释的图形推荐规则
            +
受治理的纯渲染组件目录与领域 DSL
            ↓
       未保存页面文档
            ↓ 静态校验
       用户确认保存
            ↓
          页面修订
            ↓ 真实查询与精确修订预览
       人工确认发布
            ↓
      统一运行时确定性呈现
```

产品承诺不是“只给数据和维度就能得到唯一正确页面”，而是：

- 让用户更快获得一个**口径正确、结构合法、可解释、可继续编辑**的看板页面起点；
- 生成结果不定义指标、不扩张权限、不携带计算脚本；
- 页面结构只在创作期变化，已发布看板页面不会因模型或数据变化而暗中重排；
- 所有结果继续进入既有页面修订、精确修订预览、发布租约和回滚治理。

## 2. 为什么现在做

### 2.1 已具备的产品骨架

当前仓库已具备：

- 以结构化查询引用指标、维度与聚合的领域 DSL；
- 命名页面数据源、组件字段绑定和封闭的纯渲染组件目录；
- 元数据快照、Schema 与语义校验；
- 不可变页面修订、精确修订预览、发布租约与审计；
- 页面模板及其独立模板修订；
- 通过 MCP 进行目录检索、校验、保存、预览和申请发布的 Agent 路径；
- 指标缺口进入指标需求队列，并通过页面搭建蓝图续接页面；
- 统一运行时经数据网关访问数据服务。

因此，本阶段不需要更换看板页面资产格式或重写统一运行时。

### 2.2 当前阻断项

当前同步目录仍可能用“所有维度均可用”和通用聚合集合作为宽松默认。形式上可校验，不等于业务上可组合。若直接开放整页生成，系统会在错误放大的候选空间里工作。

进入生产级生成前，数据服务至少需要真实提供：

- 指标定义、值类型、单位、默认展示建议；
- 允许的聚合、可加性和默认聚合；
- 默认时间维度、合法时间粒度；
- 指标可用的维度及合法关系；
- 维度角色、基数、排序、层级和可筛选性；
- 数据新鲜度、质量状态与权限语义；
- 明确的“未知”，而不是用宽松默认代替未知。

## 3. 目标用户与核心场景

### 3.1 目标用户

| 用户 | 当前任务 | 本阶段价值 |
|---|---|---|
| 开发者 / 数据工程师 | 编写或修改页面文档、排查字段和组件绑定 | 从手工编排转为校验后的候选页面，减少重复结构工作 |
| 数据分析师 | 把业务问题拆成指标、维度和图形 | 系统辅助完成分析任务拆解、组件推荐和页面组织 |
| 业务用户（受控试点） | 描述经营问题并反复沟通页面 | 从页面目标出发获得可解释预览，在关键歧义处确认 |
| 发布者 | 判断页面是否可进入生产 | 获得精确页面修订、生成理由和验真结果 |
| 管理员 | 治理页面模板与异常发布状态 | 把高质量页面沉淀为页面模板，管理发布租约异常 |

### 3.2 首批场景

1. **指标快速探索**：选择一个指标，生成当前值、默认时间趋势、低基数维度对比和明细入口。
2. **经营总览**：根据明确的页面目标，把核心指标、趋势、分类对比、排行和明细组织为一个看板页面。
3. **趋势与分类对比**：围绕指定指标和时间范围，生成趋势、同比/环比所需的既有指标引用及分类对比。
4. **排行与明细核对**：生成带排序、limit 和明细表格的页面结构。
5. **从页面模板开始**：优先复用已发布页面模板，在精确来源页面修订上替换合法的指标、维度和筛选状态。

地图、复杂跨页下钻、多单位共轴、未治理的衍生计算和自由样式不进入首批自动生成范围。

## 4. 产品原则

1. **数据服务是数据语义的唯一事实源。** 指标口径、合法维度、聚合和数据权限不由 AI 或页面定义。
2. **页面目标先于组件选择。** 同一组指标和维度可以回答不同问题；没有目标时只提供候选，不宣称唯一答案。
3. **规则决定合法性，AI 负责规划与组合。** 确定性规则先缩小空间，AI 不在开放组件和查询空间中自由创作。
4. **创作期生成，统一运行时确定性执行。** 生成结果编译为页面文档，保存后形成页面修订；运行时不重新猜页面结构。
5. **先静态校验，用户确认保存，再做真实查询和精确修订预览，最后人工发布。** 未保存页面文档、页面修订和已发布修订是三个不同状态。
6. **解释与结果同行。** 每个组件要能说明其分析任务、所用指标/维度、入选原因和被排除候选。
7. **未知即阻断或降级。** 缺少兼容性事实时不得猜测；指标缺口继续走指标需求队列。
8. **复用现有治理资产。** 领域 DSL、页面模板、页面修订、发布租约、统一运行时和 MCP 均继续有效。

## 5. 目标产品能力

### 5.1 能力地图

| 能力域 | 目标能力 | 当前基础 | 本阶段变化 |
|---|---|---|---|
| 语义供给 | 真实的指标、维度、聚合、关系、安全与展示语义 | 元数据快照、目录同步、目录检索 | 补齐真实元数据；未知能力显式失败 |
| 任务理解 | 从页面目标识别当前值、趋势、对比、构成、排行、明细等分析任务 | Agent 提示与人工拆解 | 增加结构化任务输出与歧义确认 |
| 单组件推荐 | 按字段角色、基数、单位和结果形状排序纯渲染组件 | 组件目录中的自然语言说明 | 增加机器可判定的硬约束与软偏好 |
| 整页规划 | 组织分区、页面数据源、组件字段绑定、筛选状态和有限跨页下钻 | 页面模板、自动网格、Agent + MCP | 新增创作期生成模块，产出未保存页面文档及解释 |
| 结果验真 | 检查空集、单值、过高基数、行数、耗时和单位冲突 | 保存时静态校验、保存后精确修订预览 | 把真实查询与精确修订预览设为人工发布前的必经闸门 |
| 资产治理 | 保存、diff、预览、发布、回滚、模板化 | 页面生命周期与页面模板已具备 | 把生成上下文和元数据版本纳入审查信息 |
| 缺口履约 | 识别、确认、开发、验真并续接缺失指标 | 指标需求队列、页面搭建蓝图、DP 与数据服务验真 | 让生成流程在 `METRIC_GAP` 后可恢复 |
| 效果学习 | 衡量推荐采用、修改和失败原因 | 尚无闭环指标 | 记录匿名化决策结果，不记录业务数据行 |

### 5.2 创作期生成模块的最小接口

这是一个规划新增的深模块，其公开接口应保持小而稳定：

```text
输入：
  页面目标 / 受众 / 分析问题
  + 当前权限范围内的指标、维度、聚合、关系与安全语义
  + 可解释的图形推荐规则
  + 纯渲染组件目录与领域 DSL
  + 可选的页面模板或现有页面修订

输出：
  未保存页面文档
  + 生成解释
  + 仍需用户确认的歧义
  + 被阻断的指标/维度依赖
```

其 Implementation 可以依次演进为“纯规则 → 规则 + 页面模板 → 规则 + AI”，但页面创作工作台只依赖这一个 Interface。模型提供方、提示词或推荐算法的变化不应穿透到页面生命周期和统一运行时。

## 6. 分阶段路线

路线以退出闸门推进，不以自然月强行推进。任何阶段未过闸门，都应停留在可独立产生价值的上一阶段。

### M0：可信元数据

**目标：** 让系统知道什么组合合法，也知道什么尚未确认。

**交付：**

- 数据服务真实供给指标可用维度、可用聚合和值类型；
- 增加默认时间维度/粒度、单位、可加性、维度角色和基数；
- 目录同步不再用宽松默认填补未知能力；
- 元数据快照版本进入生成记录，保存与发布都可追溯；
- 建立目录契约测试和数据漂移告警。

**退出闸门：**

- 试点指标的兼容关系覆盖率为 100%；
- 自动生成路径中不存在“全部维度可用”的占位逻辑；
- 非法指标—维度—聚合组合拦截率为 100%；
- 未知能力能稳定返回可行动错误，不产生候选页面。

**独立价值：** 即使后续不做 AI，也能提高人工搭建、校验和指标履约的可靠性。

### M1：确定性单组件推荐

**目标：** 对一个分析任务稳定给出 1～3 个合法纯渲染组件候选。

**交付：**

- 把组件目录的适用说明扩展为机器可判定约束；
- 覆盖指标卡、折线图、柱状图、排行、表格和有明确地域角色的地图；
- 输出候选分数、入选理由和淘汰理由；
- 建立固定样例集和推荐回归测试；
- 在页面创作工作台中支持“一键采用 / 换一个 / 手工选择”。

**退出闸门：**

- 固定样例集中非法组件候选为 0；
- 专家标注样例的 Top-3 覆盖率不低于 95%；
- 相同输入在相同规则和元数据版本下输出稳定；
- 推荐失败时仍可手工完成页面，不阻塞现有流程。

**止损点：** 单组件推荐本身可作为长期能力，不依赖整页 AI。

### M2：受限场景整页生成

**目标：** 从明确目标或已发布页面模板生成可编辑的未保存页面文档。

**交付：**

- 支持“指标快速探索、经营总览、趋势与分类对比、排行与明细”；
- 用分析任务组织页面数据源、分区、组件字段绑定和筛选状态；
- 先由规则和页面模板组合，不要求模型参与所有场景；
- 展示生成解释与待确认歧义；
- 生成结果先形成未保存页面文档，通过静态校验后由用户明确保存为页面修订；
- 保存后通过统一运行时发起真实查询并预览该精确页面修订，检查空集、基数、行数和耗时。

**退出闸门：**

- 自动生成页面的 Schema、引用和元数据语义校验通过率为 100%；
- 试点场景中，首次生成后无需结构性重做即可进入精确修订预览的比例不低于 80%；
- 相对试点前基线，中位首次可用预览时间下降至少 70%；
- 高基数、空结果、单位冲突和目录漂移均有可验证的降级路径；
- 没有自动保存、自动发布或后台修改已发布看板页面的路径。

### M3：AI 整页规划与对话迭代

**目标：** 让业务用户用自然语言表达目标，由 AI 完成任务拆解和候选组合。

**交付：**

- AI 只消费当前权限范围内的结构化目录候选；
- AI 只能通过 MCP 读写 MetricCanvas，不能旁路页面校验和页面生命周期；
- 对页面目标、时间范围、受众或指标含义的实质歧义发起确认；
- `METRIC_GAP` 进入页面搭建蓝图，指标履约后可从当前最新页面修订继续；
- 建立跨模型、跨目录版本的回归集；
- 模型不可用时降级到页面模板、确定性推荐和手工搭建。

**退出闸门：**

- 100% 工具写入经过身份、权限、幂等与审计检查；
- 100% 指标缺口在用户明确确认后才进入指标需求队列；
- 生成页面的事实错误、越权引用和治理旁路均为 0；
- 试点用户对推荐结果“直接采用或小改后采用”的比例不低于 70%；
- 模型故障不影响已发布看板页面的打开和取数。

### M4：分析与反馈闭环

**目标：** 在不改变事实源的前提下，用真实使用结果改进推荐。

**交付：**

- 记录候选采用、替换、删除和发布前退回原因；
- 按分析任务、组件类型、元数据质量和用户类型衡量效果；
- 只调整软偏好和页面模板推荐，不通过行为数据放宽合法性规则；
- 将高频指标缺口反哺数据服务治理与指标需求清单流程。

**退出闸门：**

- 所有反馈不包含业务数据行；
- 推荐策略变更有版本、离线回归和可回滚能力；
- 没有以点击率覆盖指标口径、权限或兼容关系的路径。

## 7. MVP 定义

MVP 由 M0 + M1 + M2 的受限子集组成，不等待完整 AI 整页规划。

**MVP 输入：**

- 明确的页面目标、受众和分析问题；
- 当前权限范围内 1～5 个已治理指标，以及默认时间维度和最多 3 个普通类别维度；
- 指标对应的聚合、关系与安全语义；
- 版本化的图形推荐规则；
- 纯渲染组件目录与领域 DSL；
- 可选的一个已发布页面模板。

**MVP 输出：**

- 一个未保存页面文档；
- 指标卡、趋势、分类对比、排行或表格中的合法组合；
- 每个组件的分析任务和选择理由；
- 静态校验结果，以及保存后真实查询与精确修订预览结果；
- 明确的指标缺口或需要用户确认的歧义。

**MVP 不做：**

- 在页面中定义新指标或计算表达式；
- 自由 HTML、CSS、脚本或未登记组件；
- 自动创建或发布 DP 指标；
- 自动保存、自动发布或直接改写已发布看板页面；
- 从大量业务数据行反推指标口径；
- 未声明目标页面或目标筛选器的跨页下钻；
- 依赖模型才能打开、取数或渲染已发布页面。

## 8. 产品指标

### 8.1 北极星指标

> **从页面目标提交到“用户认可并保存为页面修订”的中位时间。**

只统计成功通过校验且用户明确保存的结果，不能用“模型返回了 JSON”代替成功。

### 8.2 护栏指标

| 维度 | 指标 |
|---|---|
| 正确性 | 非法指标/维度/聚合组合数；Schema 与语义校验失败率；数据权限越权数 |
| 效率 | 首次可用预览时间；生成后结构性重做率；手工绑定字段数量 |
| 可用性 | 候选采用率；小改后采用率；降级到手工流程的完成率 |
| 治理 | 自动保存/发布旁路数；发布复验失败率；精确页面修订可回滚率 |
| 语义供给 | 指标兼容关系覆盖率；未知能力占比；目录漂移发现时延 |
| 缺口履约 | `METRIC_GAP` 确认率；已履约周期；履约后页面续接成功率 |
| 稳定性 | 相同输入的规则输出稳定率；模型故障下已发布页面可用率 |

## 9. 依赖与协作

| 依赖 | 必须提供的能力 | 主要协作者 | 未满足时的处理 |
|---|---|---|---|
| 数据服务 | 真实指标/维度/聚合目录、结构化查询、权限施加 | 数据服务维护团队 | M0 不通过，不开放自动生成 |
| DP | 指标候选查询、稳定指标 ID 和发布状态 | 数据开发确认人、DP 维护团队 | 仅记录并等待，不在 MetricCanvas 内代建指标 |
| 身份与权限体系 | 用户身份、角色与能力上下文 | 宿主门户 / 平台管理员 | 拒绝生成涉及无权目录或拒绝写入 |
| 模型提供方 | 页面目标理解、分析任务拆解和候选组合 | AI 平台维护团队 | 降级到页面模板、规则与手工搭建 |
| 页面生命周期 | 保存、diff、发布租约、审计、回滚 | 看板页面搭建者、发布者、管理员 | 不允许绕过；失败时保留未保存页面文档 |
| 页面模板 | 受治理的复用起点 | 管理员、领域专家 | 从空白规则生成或手工搭建 |

详细构建过程、Interface、Adapter 和角色责任见[《看板页面构建过程、服务依赖与角色协作》](./dashboard-page-building-process.md)。

## 10. 主要风险与决策闸门

| 风险 | 早期信号 | 决策 |
|---|---|---|
| 目录语义不可信 | 预览期大量查询失败或人工纠正维度 | 停在 M0，不用提示词掩盖元数据缺口 |
| 规则过硬导致推荐单一 | 合法候选少、用户频繁手工改图 | 保持硬约束，调整可版本化软偏好 |
| AI 产生看似合理的业务错误 | 错指标、错聚合、错时间范围 | 结构化候选输入、输出强校验、关键歧义确认 |
| 整页结构可用但叙事不清 | 用户大量移动、删除分区 | 先收窄页面模板与分析任务，不扩组件自由度 |
| 用户把预览当成生产 | 未确认结果被分享或嵌入 | 清晰区分未保存页面文档、页面修订和已发布修订 |
| 模型或外部系统不稳定 | 生成超时、DP/目录不可用 | 每个外部 Seam 有超时、错误语义和非 AI 降级路径 |
| 新模块侵入统一运行时 | 打开同一修订得到不同结构 | 坚持创作期编译，统一运行时只消费已保存页面文档 |

## 11. 实施前需形成的决策

本规划与现有 ADR 方向一致；实施创作期生成模块前，仍需单独决策并记录：

1. 数据服务新增元数据字段及其兼容演进方式；
2. 组件推荐硬约束与软偏好的版本归属；
3. 生成解释是临时审查信息还是需要持久化的治理记录；
4. 真实查询与精确修订预览的配额、超时和权限；
5. 模型调用时允许发送的元数据范围和审计要求。

这些决策不能通过修改已发布看板页面或放宽领域 DSL 来规避。
