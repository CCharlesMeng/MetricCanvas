# 主应用接入调查结论与内网维护边界

日期：2026-09-28。来源：用户提供的 CBCBICloudBIWebsite 只读报告，基线 8e741195b88f3b551acbd0d9134fe3abecf6b5a8，分支 fuxi_release_20260911171436。未直接检查内网仓，报告中的代码结论不是运行验收。

## 已知接入方向

- 主应用 Angular + 带私有 patch 的 qiankun 2.10.16；注册通过服务端 /apps 下发，前缀内 URL 路由由平台负责。
- props 只提供 appList/roleList；当前用户、语言、cftk、重登等来自门户全局对象。
- 不要求主应用为了平台增加 readConfig/subscribeConfig；由独立内网部署 Adapter 转换成平台标准输入。
- 主应用报告称身份变化整页重登，实时通知未证实。核验后可声明 configChanges: reload；若支持原地切换，必须实现真实 subscribeConfig。
- 平台当前已改为普通 Svelte 和客户端 URL 路由。GitHub ADR-0093 与本地 Kit 探针记录了迁移依据；本报告不代表内网环境已验收。

## 需要补证据

1. 主应用 Cookie/cftk 身份与平台 Java/DQE 的 authToken/operatorId/workspaceId 之间没有已证实映射。必须检查网关是否转换身份，或浏览器真实字段来源；不得把 cftk 当 token、把 appId/siteId 当 workspaceId。
2. 主应用盘古 API 报告未证明提供平台当前需要的 instance(id)/renderChat/destroy。主应用 afterMount 才初始化 SDK，平台 mount 不能反向等待它。
3. 缺少 lockfile 中传递依赖版本、私有 qiankun patch 全文、真实子应用的生产入口和构建例子。
4. 应用注册/权限登记与静态目录或 WCM 发布流程需要内网所有者确认。

## 对报告的修正

- 已见同源资源，不足以推出只能同源；WCM 地址仍需核对。
- strictStyleIsolation:false 不是关闭 JS 沙箱；loose 与 patch 需联合验证。
- 内部跳转保持实例取决于激活状态，不仅是 urlRerouteOnly；离开前缀才应卸载。
- 不复制报告中的 base 标签与相对资源路径示例；平台路由 base 和静态资源 base 分开。
- 报告中带 import/export 的 JS 是源码形状，不是已验证的 qiankun 2 生产产物。
- 主应用设置 POWERED_BY 标记不能替代生命周期传入容器的验证。

## 分别维护与交付

GitHub 只维护平台业务、通用微前端入口、版本化部署契约、静态组合工具和合成测试。内网独立仓维护 CBCBI Adapter、门户字段映射、身份/网关转换、SDK、私有补丁、配置与流水线。

内网锁定上游静态归档及摘要，在自己的项目编译为经典脚本（不含未解析 import）并注册 window.MetricCanvasDeploymentAdapter。使用上游归档中的 compose-deployment.mjs 组合，不修改上游 UMD/CSS。独立升级 Adapter 或平台，最终锁定组合摘要并整体回滚。

真实鉴权未核实时保持配置不可用，不填虚假凭据。平台原有请求协议本次未改变；若网关需要新传输方式，只向 GitHub 提交脱离门户名称的通用契约需求，实际内网映射由独立项目维护，不进入通用平台构建。

按用户后续要求，本目录已纳入仓库的 docs/plan/qiankun-platform/portal-handoff/2026-09-28，包含原报告、补充提示词和迁出的旧本地接线，仅作资料，不参与平台构建。legacy-local-config 仅是原文件备份，未经独立构建，不代表可直接运行或发布。
