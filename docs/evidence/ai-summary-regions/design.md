# AI Summary 容器组合与顶部位置

2026-10-23。状态：用户已确认方案，本仓实现及本地验收完成；详见 [验收记录](result.md)。基线：db88ab94（Schema 6.55，包含 body 直显和 relatedDataSources）。

## 已确认设计

- AI Summary 保留同一组件，既能独立放在页面正文顶部，也能作为现有内容分区、组合卡、Tab 页签内的普通子组件。
- 内容分区和组合卡分别支持纵向区域与横向并排区域。容器嵌套、原有布局、筛选、显隐、Tab 激活规则保持现状；本次仅给组合卡增加 aiSummary 准入，不借此改变其他组件准入。
- 显式 `props.scope: "container"` 表示总结直接拥有当前摘要的内容集合：组合卡子项、当前 Tab 页签子项或所属内容分区。没有配置该字段时绝不根据摆放位置隐式改变既有分析范围。
- 动态生成时 scope 与 relatedDataSources/relatedSections 及旧范围声明互斥；非空 body 仍优先直显，不启动生成，不解析无效分析引用。
- 只收集区域中当前可见组件的数据槽；嵌套 Tab 仅活动页签，数据源去重，采用全部非明细字段。文字、标题、其他 AI 总结正文和查询上游不进入总结输入，不新增取数。
- 页头、日期筛选和区域标题仍在摘要之前；正文组件序列中的摘要必须连续排在最前，且 span 占满当前列轨，避免内容与摘要同一行。
- 独立页面摘要使用正文首个内容分区，放在 Report 页头之后。区域摘要放在所属内容分区/组合卡/页签的内容序列开头。一个容器中多个摘要可以连续置顶，不新增数量限制。
- 新增能力登记 Schema 6.58；新版本对顶部位置进行结构校验，旧版本保留读取与原序，示例迁到新规则。运行时不偷偷重排页面树。
- 生成、后台任务、缓存、错误、纯文字降级与导出复用现有链路；输入附加可选区域身份，确保同数据源但区域归属变化仍有准确输入身份。Adapter 仍是 generate(question, contextInfo)。

## 实施职责与复杂度

1. page：组合卡准入、scope Schema、区域归属及数据源解析、顶部校验、版本能力和契约向量。复用组件树与活动 Tab 遍历；位置校验独立于生成校验。
2. data-execution：现有依赖收集调用统一解析器时传入摘要身份，避免自动查询分页遗漏共享消费者。
3. runtime-ui：冻结输入附带区域身份；不复制任务或 UI 实现，继续使用现有 ReportSummary/reportInline。
4. Playground：新增 Report 场景，包含页面顶部摘要、整行区域、并排组合卡、Tab 区域、独立显式范围与文字排除。复用现有样式，不新造摘要外观。
5. 文档/分发：PAGE-METADATA、组件说明、示例 README、生成契约与 local-authoring 仓外安装校验。

编码前用 metriccanvas-ts-ast/1 测量范围解析、生成输入、依赖编排等修改函数；编码后扫描全部修改/新增函数及测试闭包，新增 selfCC ≤ 15。存量超限不增长并记录原因与入口。
