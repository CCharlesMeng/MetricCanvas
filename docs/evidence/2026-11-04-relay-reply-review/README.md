# Relay R01–R05 回复审核与 MC 答复

日期：2026-11-04。依据：[Relay 原始回复](relay-reply.md)、同摘要0.2.2产物、现行四项交付契约及[本次CLI探针](local-probes.json)。Relay提供的代码位置和运行描述作为现场自报，尚未取得其源码、完整注册快照或会话原始回执；下文分别记录自报与本地验证。

## 1. 接收结论与上下文判断修正

Relay自报当前仍使用6.77旧Content和import包装，新四项尚未采用，实验已回滚。模型不递归加载references，不注入完整Interface；完整页面及查询结果留在程序侧，模型接收摘要/有界证据。这些信息可用于确定后续适配方向，实际接线仍需原始材料验收。

因此，之前对749KB Interface的担忧应定位为**新接入时的暴露风险**，不能据此认定现在线上模型每轮已承担这部分成本。当前能继续跟进的是Relay自报的约18项工具定义、旧读取默认256KB、单次知识2–50KB和摘要5–20KB；这些数字均为估算，尚无逐请求装载或usage证据。

同意Relay保留简明MCP包装、按任务暴露所需工具、完整机器契约供程序校验。Interface是公开的版本化机器契约；模型可见MCP定义由Relay装配。包装负责可信材料注入和输入/回执映射，产品规则保持同源，不能因只暴露少数模型工具而漏掉程序必需的查询准备、归一化、作用域或回执检查。

## 3. 回复中另需纠正的判断

- **JSON可以传布尔值。** `{"offset":true,"limit":1}`是合法JSON；Python的isinstance(True,int)为真。当前产品对该输入实际exit2/QUERY_OPTIONS_INVALID。数值类型的CodeCheck整改必须保留排除bool的行为，原补丁所称“JSON解析不会出现bool，行为等价”不成立。
- **LOADED_CODE是代码身份基线。** 当前MC实现将模块文件摘要记录为LOADED_CODE，用于发现代码被替换；它不证明知识结果缓存、同轮去重或上下文去重。Relay的具体缓存仍需查实际实现。
- **基线身份存在不一致。** 回复给出contentVersion为1-bb4ddee3e562cd88，却给contentSha256为e785c443…；现行Content版本规则要求二者前缀一致。需核对是否来自不同快照或改包后未完整生成，不能据此重新计算摘要来追认现场包。
- **归档名字存在矛盾。** 回复开头称归档目录为mc-tools，R03又称归档文件为mc-tool.md。本地同摘要0.2.2为单数。需以原始ZIP摘要、归档成员名和包内releaseId定位实际收到的批次；名称已确认采用复数，不代表旧包已经更名。
- **UUID不证明Java幂等。** operationId和一次HTTP调用只能说明本地关联/发送形态。需核对Java是否接收并约束该ID、超时如何核对原写入结果；当前无unknown恢复、取消/迟到处理的自报应列为真实接入缺口。
- **引用作用域不等于完整结果证据。** RESULT_SCOPE_MISMATCH证明引用的范围核对，不能替代辅助槽的complete、totalCount、sampleTruncated和查询窗口事实。回复中“能提供完整性”还需要实际字段样例。
- **import模式仍可能有子进程。** 当前知识、校验、升级路径会调用Node；新CLI适配仍须明确UTF-8、超时、requestId和退出码处理，不能由“当前采用import”推出不存在编码问题。现有300秒MCP总超时不替代取消/未知写入恢复。
- **三项旧工具不能统一改名后视为兼容。** tool_mc_query与content.read可做输入/预算映射；compile_layout消费布局envelope，inspect_assembly还核对specification、绑定和关联证据。page.compose.v2/page.validate不能仅因功能相近就作为后两者的等价别名。MC须逐项给出适配或明确能力缺口，Relay按新接口接线。

## 5. Relay 只需继续补充的三组材料

1. **身份**：原始ZIP SHA-256、原始成员清单、收到包的完整releaseId；当前旧Content的完整version文件及来源。确认复数是否来自人工改名，并解释bb4ddee3与e785c443的差异。
2. **实际调用**：完整list_tools快照；一组新建、一组编辑的脱敏请求/回执；一条局部编辑的工具定义与逐次知识/摘要装载记录。剩余14工具“略”及估算大小不足以关闭真实注册和上下文验收。
3. **关键语义**：resultRecords实际字段及完整性/窗口证据；Java operationId接收/幂等/核对契约；unknown、取消和迟到的现有处理或明确待实现项。MC提供样例后用同一材料回放。

MC可立即推进复数导出、共享目录校验、映射/样例和Node路径核对；上述材料只阻塞具体现场适配及最终验收，不阻塞MC自身工作。
