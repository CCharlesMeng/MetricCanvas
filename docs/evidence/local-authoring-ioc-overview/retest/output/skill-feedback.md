# Skill 反馈

## 有效之处

- `overview-layouts.md` 给出了三卡 4+4+4、明细/地图同分区的清晰映射，能避免把同一业务卡的指标和分类拆开。
- `component-recipes.md` 对 metricCard changes、Tab、分类色点的短写法很实用。
- 快照脚本和校验器无需安装依赖，首次失败能被原样保留；错误路径准确指向 `dashboardToolbar`。
- 具名 `delta`、`ratio` 支持本任务主要派生口径，并要求显式零分母策略。

## 知识缺失或歧义

1. `local-workflow.md` 建议多筛选使用“标准工具栏”，但 `dashboardToolbar` 的页面协议并不存在 `variant: standard`；对象分支示例更常见 `compact`。我第一次把自然语言“标准工具栏”映射为 `standard`，导致结构校验失败。建议文档明确写成 `dashboardToolbar: "visible"`，并说明“标准”是呈现概念而非枚举值。
2. 世界地图按实际底图国家名称绑定，业务需求却使用“中国、欧洲、亚太”等宏观地区。Skill 有国家地名清单，但缺少“业务宏观地区如何映射到世界底图”的推荐策略与能力边界。本次只能用代表国家承载业务地区并明确部分完成，不能表达真正的宏观地区块。
3. inline 数据下，层级地图声明与筛选控件之间没有可执行的数据过滤/回写能力；文档清楚禁止伪称联动，但缺少一个“只展示层级路径、地图不可下钻”的标准降级示例。
4. 分类颜色只通过饼图与 `categoryBreakdown.swatches` 共享类别顺序，协议没有面向“金/银/红/黄固定业务语义色”的显式颜色映射。结构能表达类别，不能保证颜色语义与名称一致。
5. 页面协议可声明表格链接和数值排序，但静态校验不确认链接只在名称单元格触发、窄屏表内滚动或排序运行行为。Skill 已提示浏览器验收，本测试按要求留给主验收方。
