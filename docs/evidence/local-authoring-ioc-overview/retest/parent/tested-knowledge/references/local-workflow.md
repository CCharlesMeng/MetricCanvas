# 本地创作与验收

## 输入与输出

本地创作形成页面文档；页面数据源、结果字段契约、筛选器、内容分区和组件由文档显式声明。数据上下文快照提供创作依据，不写入页面；查询定义在创作期确定，渲染期只执行已有查询，不临时发现数据或生成查询。

输出文件用页面 id 命名，例如 id 为 operations-dashboard 时保存为 operations-dashboard.json。新增文件的身份由用户项目约定确定，不把本地 id 冒充已分配的线上资产身份。

## 自然语言与设计源

自然语言创作先将需求对应到章节、组件、字段与交互；完整页面保留必要的口径和数据范围说明。仅在需求明确要求时配置动态 AI 总结；已有文字说明可使用 text 或 fieldText。

设计稿或旧系统截图还原时，先列出可检查的对应关系：内容顺序、完整字段/列、布局、图形、单位与颜色、日期控件、点击目标和窄屏行为。截图里的示例数值不证明业务数据或字段映射。用已有组件表达；customBlock 的结构、样式与行为依目录内契约声明，不引入任意脚本或绕过数据槽。

在目标运行时预览，按相同视口对照源图并记录实际截图；覆盖需求涉及的切换、筛选、排序、翻页、详情与导航。用户没有指定的交互不从截图猜测。只有 JSON 校验时保持“结构通过，视觉还原未验收”。这些步骤可独立执行，不要求安装另一份设计还原 Skill。

## 数据配置

先读[数据源](page-metadata/data-sources.md)、[字段](page-metadata/fields.md)和[查询绑定](page-metadata/queries-and-bindings.md)。

- inline 行使用稳定页面字段 id；query 初始行保留实际查询响应字段，按 queryField 映射到页面字段。
- 组件引用数据槽与稳定页面字段 id；筛选器 dimension、页面字段 id、DQE 字段属于不同空间，显式配置绑定。
- 已有查询只做样式调整时保留查询与原始数据。新增或变更查询需要可信字段/口径与实际执行；缺少时交付明确的缺口，不用示例补造真实字段或执行成功。
- query.initial 必须对应该查询与初始条件。改变查询条件后重新取得匹配结果，或移除不再有效的初始快照；不能保留旧行制造查询正常的假象。
- 缺失值、零值、比率、金额与已缩放数据按实际契约区分。显示格式负责缩放，原始数值不为呈现而改写；金额身份和单位不能只由字段名称推断。
- 计算只使用目录内[具名算子](page-metadata/compute.md)，保留完整性与依赖证据；不把样例行证明为完整结果。

完整参考：[内联页面](page-metadata/examples/inline-report.json)、[查询看板](page-metadata/examples/query-dashboard.json)、[跨源计算](page-metadata/examples/cross-source-page.json)。复用后重新核对版本、实际字段与业务口径。

## 业务口径复核

从原始输入独立计算验收值，不从页面结果生成期望值。先选定期间，再按全局、区域、办事处分别汇总。比率先汇总分子与分母再除，不平均已有比率、不复用全局值填区域。逐项记录字段来源、排除项、单位、分组键及零分母规则；验证零、缺失、负数和大于100%的结果。缺少数值应标为未知，不能补零制造完整地图。匿名项目明细与全量汇总如果粒度不同，不能相加对账。

分类数据需核对完整性、图表和列表的同色同序、合计与主指标是否同一口径。允许自造分类演示行时单独说明它们不代表真实分类。涉及地图读[绑定检查](map-bindings.md)，涉及概览读[常见布局](overview-layouts.md)。

## 日期、参数与交互

只有需求需要日期选择时增加筛选器。dashboard 通过统一工具栏呈现页面 filters，report 通过 reportHeader.filterIds 选择日期控件；二者都通过对应查询的 filterBindings 传递应用值。dashboard 页头不能写 filterIds。多个控件优先使用可换行的标准工具栏，紧凑工具栏须实测窄屏溢出。readOnly 会禁用控件，不能仅因 inline 数据自动添加。inline 控件变化不会自动过滤数据，必须明确标注未接通的行为；期间文字使用已应用筛选的显式引用。展示日期变化不证明重新取数成功。查询参数与展示参数分别声明；时间点绑定查询时给出合法窗口。

参考：[日期筛选完整页](page-metadata/examples/report-date-filters-page.json)、[期间文字](page-metadata/examples/report-filter-text-page.json)、[参数与文字](page-metadata/params-and-text-values.md)。

点击、详情与导航查[交互与导航](page-metadata/actions-and-navigation.md)。表格行字段、页面参数、当前筛选和固定值按实际来源绑定；验证目标 URL 与目标页接收值，再验证它们是否影响真实查询。静态校验不检查外部 URL 是否存在或目标业务是否正确。

## 尝试快照

生成器只写工作文件。每次完整 JSON 生成后先运行目录内[快照脚本](../scripts/snapshot-attempt.mjs)，再校验快照文件，保存命令、退出码、原始回执和修复原因。父目录由调用者创建，attempt-N 必须不存在：

```sh
node "<skill-dir>/scripts/snapshot-attempt.mjs" "<output>/working/page-id.json" "<output>/attempt-1"
node "<skill-dir>/scripts/validate-page.mjs" "<output>/attempt-1/page-id.json"
node "<skill-dir>/scripts/snapshot-attempt.mjs" --check "<output>/attempt-1"
```

快照保存未经解析的原始字节（包括错误 JSON）、SHA256 清单并设只读；重复目录会失败。每轮新建目录，不能重跑生成器到旧尝试目录，也不能从最终产物重建第一次失败。--check 验证当前文件与捕获时哈希；本地只读不是操作系统级隔离，仍需审计产物与命令。最终交付另外复制已通过的工作文件。

## 错误定位与证据

从[校验模块](page-metadata/validation.md)读取错误类别，沿 JSON Pointer 找到最上游的错误声明，修复后重跑独立校验器。目录内 errors 文件是触发片段；只有 examples 中的完整页面可作为生成起点。文件名校验与单文档校验不证明跨页面业务正确。

| 验收层 | 可用证据 | 不能据此声称 |
|---|---|---|
| 文档与文件名 | 独立校验器退出码及 JSON 回执 | 真实 DQE、视觉和业务口径正确 |
| 视觉与交互 | 目标运行时、实际截图、交互结果 | 外部服务或生产部署完成 |
| 数据与口径 | 明确的数据上下文、真实查询请求/结果与字段映射 | 其他身份或部署也已接通 |
| 线上交付 | 项目提供的实际保存/发布回执 | 本地文件已自动成为线上资产 |

缺少某层环境时说明未执行与所缺条件，继续完成可以验证的部分。无需为了文档生成主动接通生产服务或发送业务数据。
