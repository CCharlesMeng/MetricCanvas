## 第二轮结果

第二轮仍采用完全相同的原始输入，使用新的空白上下文GPT-5.6-sol。输入与独立Skill副本全部哈希未变；没有交给模型旧页面JSON或首轮产物。首次4个错误均来自猜写 `dashboardToolbar.variant="standard"`；第二次结构通过。两次原始快照的哈希均保持一致。

| 项目 | 首轮 | 第二轮 |
|---|---|---|
| 结构校验 | 499 → 1 → 0 | 4 → 0 |
| 信息组合 | 长竖排指标、分类拆离、表/地图分行 | 三张组合卡内聚，分类饼图和明细保留，表/地图同一行 |
| 标题、筛选 | 重复标题，readOnly禁用 | 标题一次，checkbox可切换；数据没有重算并明确说明 |
| 明细 | Tab、排序、导航通过 | 三Tab、数值升降序、标识与月份导航继续通过；目标为stub |
| 证据 | 初版被覆盖并近似重建 | 两次原始快照完整保留并通过哈希检查 |
| 窄屏整页宽度 | 375视口/1254页面 | 375视口/385页面，仍失败 |
| 数据与地图 | 中国算错；地图行被过滤且地名不匹配 | 主金额/数量正确，但百分刻度错误；中国仍算错；擅自代表国家投影且亚太不命中 |

**结论：部分通过，未通过完整IOC项目概览验收。** 静态通过和布局改善不能替代业务或视觉正确性。

第二轮独立验收的新问题：

- 百分刻度：ratio没有scale:100；percent格式不自动乘100。管道率应显示73.0%，实际0.7%；其他管理比率、表格比率与项目赢率也出现100倍误差。原有协议已说明，模型读过却未正确落实，属于执行/验收缺陷。
- 中国管道率：CSV正确分母350M−55M−35M=260M，分子150M，结果57.6923%；模型写57.8947%，另有百分刻度错误。欧洲真实128.5714%不可钳制。
- 宏观区域：把欧洲写Germany、亚太写Singapore等没有输入依据；标注“代表国家”并不满足原需求。Singapore也不存在于实际底图。null虽然存入页面，但不证明图形中保持未知语义。
- 地图图例越出组件到邻卡附近；管理卡标签拥挤；金/银/红/黄使用普通类别色板，未满足固定业务颜色。这里仅记录实际失败，不采信模型“协议不能支持颜色”的未核实判断。
- 窄屏溢出来自长指标标签与Tab；表格有内部滚动仍不能豁免整页溢出。

## 复测后进一步收紧资料

本轮复测后又补充了：确切的 `dashboardToolbar: "visible"` 写法；突出ratio.scale:100与原始百分数不能除100；要求程序独立输出每组分子、分母与容差断言；禁止以代表国家代替宏观区域，并给出“明确国家+原名称数值表+覆盖缺口”的降级方式；提醒regionalOverview专用呈现需检查图例边界。

这些追加文档有静态检查，**没有再做第三次模型测试**。下一次模型验证应把独立数值断言与最终呈现文字检查作为交付门槛；不能仅靠继续增加文档认定模型会遵守。宏观区域完整地图仍需要业务区域到几何的明确契约；真实筛选与下钻仍需要可执行数据与查询前提。
