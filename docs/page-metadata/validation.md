# 校验、错误与修复

先验证JSON结构和版本，再验证引用/角色/映射/绑定等页面语义。错误使用稳定type与JSON Pointer定位，message只用于解释。修复原始文档后重新完整校验，不能吞掉错误字段来强行渲染。

SCHEMA_ERROR对应结构和页面语义；FIELD_CONTRACT_ERROR对应结果字段契约；QUERY_MAPPING_ERROR对应查询输出映射；FILTER_BINDING_ERROR对应筛选绑定。查询执行错误是运行期证据，不能由静态例子证明。

本册example是完整页面，短JSON片段必须注明插入路径与依赖；生成器会核对完整例子。实际受控工具是否支持、外部服务是否接通分别查Authoring及集成证据。

## 页面数据源分支诊断

页面数据源按显式 `source.type` 报告对应结构分支的错误，不混入其他类型的字段要求；未知类型定位到 `source.type`，允许值由产品 Schema 提供。未声明类型时保留结构错误，不猜测类型。这只改善诊断，不改变文档接受规则，也不自动修正文档。

每个查询定义的 `body.dsl_list` 必须且只能包含一条查询。空数组或多条查询定位到该数组，并报告实际条数和修复建议；多条查询应拆为独立页面数据源，再按需关联展示。一个查询分支失败不应导致合法的 `queryField` 被报为未定义，也不应提示补其他分支的 `currency`、`items` 或 `members`。其他数据源和同一数据源内的独立错误继续保留。

可观察入口 `/pages/data-source-diagnostics`；使用合成初始行，不需要 DQE 服务。在 JSON 即时预览中复制该页唯一的查询项形成两项，应只报告 `dsl_list` 条数错误；步骤见 `pages/capabilities/query/README.md`。

## 文件与目录校验

页面文件名去掉 `.json` 后须与页面 `id` 一致。目录可按业务或能力嵌套；路径只组织文件，不进入页面元数据，也不改变页面身份或跨页导航。

仓库 `pnpm validate <directory>` 与独立本地创作校验器的目录模式递归检查全部子目录中的 `.json` 页面，并拒绝跨目录同名页面。空目录或重复文件名属于目标目录错误；文件名与页面 id 不一致属于文档错误。只对专门存放页面文档的目录执行，其他 JSON 应放在目录外。Playground 按文件夹发现页面，继续使用 `/pages/<id>` 访问。新增业务主题只需在 `pages/business/dashboard/<业务>/` 或 `pages/business/report/<业务>/` 放入合法页面，目录与卡片自动出现，应用不维护逐页登记表；目录路径与页面实际布局形态应一致。目录直接显示实际路径，标题、说明、组件类型和数据来源从页面文档提取。体验步骤、运行条件和关联入口由同目录 README.md 承载，文档不参与渲染，也不推断未知数据服务。
