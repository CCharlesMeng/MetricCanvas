# Handoff：qiankun 服务/子应用维护者执行 Platform 集成

## 目标与执行范围

请在现有独立维护的 qiankun 2.x 子应用内增加一个 MetricCanvas 平台功能区域，消费 MC 交付的固定版本平台包。保留现有子应用技术栈、生命周期与发布体系，完成区域载体、真实配置接线、生产构建和集成验证。

先读 [整体方案](./integration-plan.md) 的默认接口、导航行为、部署和集成方事项。本文可在外部仓执行；相对链接不可访问时，由交接方提供同目录方案文件。官方版本/loader 事实按需参考 [官方研究](./official-research.md)，以现网 2.x 锁定版本为准。

职责边界：

- MC 源码保留在其 `apps/platform/`；你方安装编译后产物，不复制工作台代码。
- 子应用负责一个区域，例如 /ops/metrics，以及配置、挂载、卸载；平台自行完成页面管理、页面选择、工作台与预览切换。
- 不需要传页面标识、location 或 chrome，也不需要维护平台内部页面路由。
- 嵌入内部导航不写浏览器 URL；刷新区域默认进入工作台。浏览器返回/前进属于子应用，不代表平台内部页面历史。
- 首版单活动实例；保留现有 qiankun 2.x 构建链，不增加第二层 qiankun。
- 当前交接时 MC 接口与产物仍待实现。下面代码是目标调用形状；包名暂定 `@metriccanvas/platform`，实际以 MC 交付版本为准。

## 1. 先完成可独立开展的盘点

读取本仓工作约定，核查而不是猜测：框架、构建工具及版本、qiankun 精确小版本、目标浏览器、生命周期入口、路由模式、区域尺寸约束、构建与发布方式。

确认真实配置与身份通知来源：Java 页面资产和 DQE 地址、用户 token、operatorId、workspaceId、是否需要 cftk；登录退出及身份/工作空间变化如何通知。确认最外层门户是否提供离开 guard、盘古是否已加载、是否已有 Relay 通道。

**完成条件：** 形成简短接入基线，列出实际代码位置及需要门户/服务方提供的信息；可先完成区域载体与配置读取模块，使用明确标为测试的替身验证外部生命周期。MC 包缺席不能宣称集成已完成。

## 2. 接收并核验 MC 交付

从 MC 维护者获取：固定版本包或 tarball、摘要、导入路径、声明文件、配置订阅/事件/guard 的最终签名、兼容范围及验证记录。

安装精确版本并提交依赖锁文件；按现有构建器消费 ESM 与 CSS。子应用最终产物仍符合现有 qiankun 2.x HTML entry 和生命周期要求。较老构建器需要实际生产构建验证，不把平台 ESM URL 直接填进 qiankun entry。

**完成条件：** 使用真实 MC 包完成安装、类型检查、生产构建；没有依赖 MC 源码目录或 Svelte 编译插件。MC 未交付时列明缺少的版本/类型/产物，继续做不依赖它的工作。

## 3. 实现区域挂载与运行配置

在子应用创建一个菜单/路由区域和具有明确可用宽高的挂载节点。父级布局同样需要确定高度。通过 MC 工厂连接配置源：

```ts
// 目标示例：发布路径与类型以实际 MC 包为准。
import { createPlatformAdapter, mountPlatform } from '@metriccanvas/platform';
import '@metriccanvas/platform/style.css';

const adapter = createPlatformAdapter({
  readConfig: () => appSession.getMetricCanvasConfig()
});
const platform = await mountPlatform(container, adapter);

// 离开区域或卸载子应用
await platform.destroy();
```

appSession 是你方真实会话模块的示意名称。配置返回字段为 dqeEndpoint、pageMetadataBaseUrl、authToken、operatorId、workspaceId，及可选 cftk；无会话返回 null。不要将用户凭据固化到构建产物。

存在运行中身份切换时，必须进一步连接实际配置订阅：MC 挂载时注册、卸载时取消。普通 token 刷新不重挂；登录退出、actor/workspace/服务目标变化按 MC 会话失效事件等待销毁并重挂。门户不会因为初始 props 包含凭据就自动保持后续同步，须检查现网真实通道。

**完成条件：** 区域可显示完整平台，用户能在平台内部找到页面管理与工作台；真实请求携带预期配置，同身份 token 刷新和身份切换分别符合约定。

## 4. 接入卸载与按需能力

保持原有子应用 bootstrap/mount/unmount 管理整个子应用。平台只随区域进入/退出挂载和销毁；整个子应用卸载时也 await 平台销毁后再移除外层 DOM。

串行化进入与退出，处理“mount 尚未完成就退出”、挂载失败、重复销毁和快速再次进入。首版退出即销毁；若使用 KeepAlive/缓存，先转换成明确的进入退出行为，不擅自假设暂停恢复。

需要离开保护时，将 MC 提供的检查注册到外部路由，并协调最外层门户在导航提交前检查。unmount 只负责清理，不能靠挂起或拒绝卸载弹出阻断。门户无 guard 时记录恢复限制。

有 AI 创作需求时接入真实盘古/Relay，使用 MC 发布的对话/可信程序接口；核实 SDK 资源 URL、版本及实例所有权。共享 SDK 的销毁不得影响其他功能。缺少 SDK/Relay 时可先完成人工业务闭环，将 AI 接线单列待办。

**完成条件：** 挂载/退出/重挂无残留；身份切换不提交旧用户草稿；可选能力已真实接通或明确标记未接通。

## 5. 生产资源、网关与验收

分别确认 HTML entry、浏览器路由前缀、静态资源 publicPath 和业务服务端点。平台包被编译进子应用，生产资源随子应用一起发布。按现网构建器配置资源路径；不要把 Webpack publicPath 变量当作 Vite 通用设置。

平台功能区域深链刷新应回到正确门户/子应用入口；静态 JS/CSS 缺失应返回 404，不回退 HTML。核实真实 API 的 Cookie、CORS、CSP 与权限；开发代理不能证明生产可达。

用实际 qiankun 2.x production dist 验证：

1. 首次挂载、区域退出、再次挂载、快速切换、子应用整体卸载。
2. 外部区域刷新/前进后退，平台内部切换不篡改子应用 URL。
3. 全局 CSS、弹层、图表 resize、SDK 在真实容器中工作。
4. 页面管理→打开页面→编辑保存→重新打开；DQE 查询及筛选重查。
5. token 刷新、身份切换、登录失效和权限拒绝；保存未知结果不盲目重试。
6. 若已接 AI，另行验证真实创作回执/产物与工作台接受。

产物固定版本并保留旧静态资源。依照现有发布流程完成灰度与回滚准备；实际部署权限及变更流程由你方仓库/环境规则确定。

**完成条件：** 生产构建、真实 qiankun、真实服务、发布回滚分别有证据；无法访问的环境标 NOT_RUN 并列责任方，不能用替身成功替代。

## 最终回交

向交接方提供：子应用提交 SHA、MC 包版本/摘要、qiankun 精确版本、实际区域路径、资源与网关配置、执行过的构建/验证结果、部署或回滚状态，以及仍需 MC/门户/服务提供方处理的具体问题。

第一终点线是人工业务闭环和生命周期通过。MC 实现缺陷请附最小复现、版本与脱值错误；生产服务问题与接口缺失单独归因，不在子应用复制平台实现绕过。
