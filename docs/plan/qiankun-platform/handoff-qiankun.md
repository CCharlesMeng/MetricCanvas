# Handoff：主应用维护者集成 Platform HTML 微前端

> 2026-09-28 实施进度：源码、静态归档及候选 qiankun 2.10.16 测试主应用验收已落地；目标门户与真实服务仍为 NOT_RUN。现行实现、证据与交付摘要见 [实施验收](../../evidence/qiankun-platform/implementation.md)。下文方案阶段状态描述保留为交接基线。
> 当前补充：普通 Svelte 与 URL 路由已按 ADR-0093 实现；先复用最新源码，不重做 Kit 迁移。门户专属接线由仓外独立部署 Adapter 维护，GitHub 只保留版本化契约和组合工具，见 [部署维护边界](./deployment-boundary.md)。本文早期 Kit 验证步骤参考既有实施证据，真实门户验证仍待执行。

## 目标与职责

将 MetricCanvas platform 直接注册为主应用的微前端子应用，加载 MC 交付的 HTML entry。主应用管理平台路由前缀，平台管理内部 URL 路由。先读 [整体方案](./integration-plan.md)，版本事实参考 [官方研究](./official-research.md)。

不再向现有业务子应用安装平台 npm 包，不复制工作台源码，也不嵌套启动第二套 qiankun。本文文件名保留供现有链接使用，执行责任改为主应用/集成门户维护者。

## 1. 提供现网基线

核查主应用 qiankun 精确版本、框架/路由器、构建器、目标浏览器、平台预期前缀、挂载容器、静态部署位置和服务器回退规则。当前暂按 qiankun 2.x，不能直接套用 3.x 配置。

确认运行配置读取与通知源：Java/DQE 地址、token、operatorId、workspaceId、可选 cftk，以及登录退出/身份变化通知。确认主应用 guard、盘古和 Relay 是否需要及接线所有权。

平台已使用普通 Svelte 客户端路由；主应用提供真实前缀，由独立部署 Adapter 映射为运行时 routeBase。首版同一部署固定服务目标，不承诺跨目标草稿隔离。

## 2. 接收完整静态交付

接收固定版本 HTML + JS/CSS/其他资源、归档摘要、兼容说明和正式 props 契约。将完整目录部署到版本路径，entry 指向 HTML。

主应用不安装平台包，也不需要 Svelte 插件。缺少真实产物时可准备容器/注册配置，但不能宣称完成平台集成。

## 3. 前缀激活与内部路由

例如主应用拥有 `/metrics`：只匹配该路径段及后代，不误匹配 `/metrics-other`。从 `/metrics/manage` 到 `/metrics/manage/pages/abc` 保持平台实例，由 platform 处理内部导航；离开 `/metrics` 才卸载。

主应用不为列表、详情、编辑逐项注册业务路由，但其路由器需要允许该前缀内深路径进入同一平台区域，不以主应用 404 页面抢占。禁止主应用与平台各自改写同一次内部导航。

直接访问/刷新内部深链接时，服务器返回主应用入口，主应用加载平台，平台按当前 URL 展示目标页面。前进/后退必须覆盖区域内和跨区域两类。平台取消离开时 URL 与视图应保持一致；跨区域保护通过可选 guard 在提交导航前协调，不能在 unmount 阻塞。

## 4. 配置与生命周期

在独立内网项目实现部署契约 v1，读取主应用已有 props/全局能力，映射为标准 routeBase/readConfig/subscribeConfig/onEvent；无需主应用必须改为直接传这些字段。使用归档内 compose-deployment.mjs 组合自己的经典脚本与平台产物。身份变化保证整页重载时可显式 configChanges: reload，其他情况必须真实订阅。不要将凭据固化在 HTML、构建产物或日志中。

初始 props 里的凭据快照不能替代后续通知。同身份 token 更新无需重挂；登录退出、身份/工作空间变化按会话失效协议销毁重挂。服务目标变化会封住旧会话，但本期不支持跨数据域恢复保证。

平台入口自己实现 bootstrap/mount/unmount，主应用通过 qiankun 调用，等待清理完成后移除容器。串行化快速进入退出、挂载中离开与再次进入；首版退出即销毁，不启用未定义的 KeepAlive。

主应用提供明确容器高度；平台只清理自有 SDK 实例。AI 接线缺席时先验证人工管理编辑闭环。

## 5. 部署与验证

分别配置：用户路由 `/metrics/...`、HTML entry `/micro/metriccanvas/releases/R1/index.html`、静态资源路径、业务服务端点。静态资源缺失返回 404，API 不回退 HTML。开发代理不能证明生产 CORS/Cookie/CSP 正确。

用平台实际 production dist 验证：

1. 首次挂载、范围内导航保持实例、离开卸载、重新进入、挂载中退出。
2. 列表/详情/编辑 URL、前进后退、深链接刷新；验证激活前缀边界。
3. 编辑保护，取消离开后 URL/视图一致；主应用路由不与平台竞争。
4. 容器、弹层、全局样式、图表 resize 与可选 SDK。
5. 页面管理→打开→编辑保存→重新打开，以及 DQE 查询。
6. token 刷新、身份失效、权限拒绝、未知写入结果不自动重试。
7. 若接 AI，单独验证真实可信产物与工作台接受。

先上传完整不可变版本目录，再切换 entry；保留上一版本和旧资源，回滚切回对应静态发布。实际部署与灰度遵循主应用团队流程。

## 回交材料

主应用提交 SHA、平台版本/归档摘要、qiankun 精确版本、路由前缀、HTML entry、资源与网关配置、验证结果、发布/回滚状态和剩余责任项。

区分测试主应用、目标门户和真实服务证据；无法访问的环境标 NOT_RUN，不能用本地替身或静态构建成功代替真实集成通过。
