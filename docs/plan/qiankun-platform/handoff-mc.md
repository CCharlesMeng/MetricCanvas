# Handoff：MC 维护者执行 Platform 双入口改造

## 目标与执行范围

请在 MetricCanvas 仓内实施 `apps/platform/` 双入口改造，使同一份平台业务既能本地/独立运行，也能由外部独立维护的 qiankun 2.x 子应用嵌入。此次交接要求完成实现、构建、必要验证和可消费产物，不止补充方案。

先读 [整体方案](./integration-plan.md)，执行范围以其中已确认边界为准。需要核对 qiankun/构建器事实时再读 [官方研究](./official-research.md)。研究中的版本信息是调研时快照，真实兼容目标以集成方锁文件为准。

已确认的约束：

- 业务源码保留在 `apps/platform/`，双入口、双构建、单业务实现。
- 公共调用为 `createPlatformAdapter({ readConfig, ...按需接线 })`、`await mountPlatform(container, adapter)`、`await instance.destroy()`。
- 实例首版只公开 destroy；页面选择和内部导航由平台完成。默认嵌入工作台，保留页面管理入口；嵌入不写外部 URL。
- 独立入口继续使用 SvelteKit；嵌入入口默认采用精简外壳。首版单活动实例。
- 平台内部不实现 qiankun 生命周期；集成方负责现有子应用入口。源码目录与发布包独立，发布名暂定 `@metriccanvas/platform`。
- 当前交接时只有方案，公共接口、嵌入构建脚本和版本包尚未实现。先检查最新代码，复用已经完成的对应工作。

## 1. 确认现状与接口

读取仓库 AGENTS.md、CONTEXT.md、ADR 索引及相关主题，核查工作区与已有实现。重点检查 apps/platform 的构建、routes、PageAuthoringWorkbench、page-assets、dialogue，以及 application-runtime 配置源。

落实最小公开类型、默认 Adapter 工厂输入、配置变化通知、事件和可选离开 guard。类型和示例由 MC 发布，集成方不需要推断内部端口。维护一份正式契约，方案只引用它。

**完成条件：** 可说明当前哪些功能直接依赖 Kit/全局变量/单例，各自如何改为内部或实例依赖；公共契约不要求 location、chrome、openPage、setLocation 或平台页面 URL 映射。

## 2. 在原目录实现共用业务与双入口

将现有管理列表、详情等路由中的业务界面提取为唯一可复用实现；独立路由保留薄包装。共用工作台从 MC 内部视图状态获取页面选择，不直接读取浏览器 page/resource 参数。

独立入口保留原路由体验；嵌入入口使用内存导航。保留平台自己的页面管理、返回工作台、内容预览和已有人工保存/发布操作。内部切换执行编辑保护；嵌入刷新默认进入工作台，恢复记录沿用现有规则。

默认 Adapter 工厂负责组装既有 Java/DQE 客户端与实例服务。外部只提供真实配置源及所需系统接线。现有私有配置模块若被其他应用共用，应保留独立入口既有语义并做对应回归。

**完成条件：** 本地入口与嵌入入口复用相同业务实现；嵌入依赖图无 `$app/*`；用户在嵌入平台内可自行选择、打开和编辑页面。

## 3. 完成配置变化、SDK 与生命周期

实现方案中的配置读取和订阅语义。同身份刷新 token 不重建；登录退出、actor/workspace 或服务目标变化封住旧会话并通知外层重挂。保存前和异步结果回写前验证会话作用域，保留原身份恢复记录。

挂载只等待有限的本地初始化，不等待 Java/DQE/SDK 网络。工厂不启动监听，挂载时创建资源；失败挂载负责清理；destroy 可等待且幂等。对话、可信创作程序、通知桥按实例注入，保留权限与精确引用核对。共享 SDK 只能销毁本实例拥有的资源。

平台内部提供离开检查；通过可选 registerLeaveGuard 将其注册到外部路由。外层通知只包含稳定事件码与脱值消息。精简外壳和弹层使用容器尺寸与局部样式。

**完成条件：** 挂载中离开、重复销毁、重新挂载、旧请求返回和身份变化不会产生遗留写入或监听；未提供 SDK 时如实显示未接通；不自动保存/发布来完成卸载。

## 4. 增加双构建与发布产物

保留 platform 的 dev/build；新增 build:integration 和 pack:integration。应用根仍为私有 workspace 包，在 `apps/platform/dist/integration/` 生成独立发布清单、JS、CSS、完整声明和文档，独立 SPA 继续写 build/。

产物要能由非 Svelte 应用消费：运行实现编译完成，公开声明不泄漏 Kit/私有源码；依赖、exports、CSS sideEffects 和版本明确。生成 tarball，并在仓外干净消费者中安装、类型检查和生产构建。按仓库正常交付流程准备固定版本 RC；registry 不可用时先交付本地 tarball、摘要和清晰的发布阻塞。

**完成条件：** 双构建互不覆盖，产物无 workspace:*、DEV 入口或开发凭据；真实 tarball 能独立消费，不能仅凭 workspace 链接通过即宣告完成。

## 5. 验证与交付

执行与改动相称的类型检查、现有业务回归和生命周期契约测试。必要浏览器验证仅覆盖嵌入挂载、容器/弹层、内部导航、卸载及快速切换；无需扩大到无关全站浏览器测试。外部真实 qiankun 与内网服务不存在时，明确记录未运行，并继续完成本仓可验证部分。

实施时更新相关 ADR、主题页、host-contract 和消费说明。保存结果未知沿用现有恢复规则；不要用重试写请求掩盖不确定状态。

**交给集成方的材料：**

1. 源码提交 SHA、实际包名与固定版本、tarball/registry 地址和 SHA-256。
2. 稳定 JS/CSS 导入路径、完整公开类型、最小接入示例。
3. readConfig、subscribeConfig、会话失效通知及可选 guard/SDK 的最终签名与语义。
4. 目标浏览器和构建器限制、发布文件清单、升级与回滚说明。
5. 本地类型/测试、双构建、仓外消费、浏览器、真实服务五类证据，分别标注通过/失败/NOT_RUN。

## 协作与阻塞处理

集成方需要提供框架、构建器、qiankun 2.x 小版本、浏览器范围、真实配置/身份通知源、盘古/Relay 接线资料。资料未齐时先完成公共接口、双入口和 tarball 验证，不猜测真实门户协议。

真实门户联调属于双方共同任务；不把本地替身通过称为生产集成通过。具体提交/PR/发布按当前仓流程和执行会话授权进行，保留其他任务改动。

最终汇报：已实现事项、产物位置、各层证据、未完成项及其责任方。首个业务终点线是“挂载→页面管理→打开→编辑保存→重新打开→卸载→重挂”，AI 创作另列结果。
