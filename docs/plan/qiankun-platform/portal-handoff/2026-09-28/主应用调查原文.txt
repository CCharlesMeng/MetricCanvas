**## A. 一页结论**

**### 推荐采用的接入方式**

1\. **\*\*框架是 qiankun 2.10.16（package.json 精确锁定，带 patch-package 补丁）+ Angular 17（history 路由 + EmptyRoute 通配路由）\*\***。主应用用 \`registerMicroApps()\` 批量注册、\`start()\` 启动，**\*\*不是\*\*** \`loadMicroApp\` 按需挂载。子应用注册数据**\*\*全部来自服务端接口\*\***（\`/rest/cbc/cbcbipermissionservice/v1/apps\` 返回的 \`appList\` 中带 \`entry\`/\`activeRule\` 的应用），前端仅在 \`LoginService\` 中组装 \`{name, entry, container:'#child-container', activeRule, props}\` 后传给 qiankun [代码证实]。

2\. **\*\*前缀分配是服务端下发的\*\***：\`activeRule\` 由 \`/apps\` 接口返回（\`LoginService.ts:366-384,399-424\`），前端 \`main.ts\` 里的 \`preDefinedApps\` 硬编码列表仅用于 prefetch 预加载，不参与注册 [代码证实]。MetricCanvas 的 activeRule（如 \`/metrics/...\`）需在应用注册表（服务端）配置，而不是前端硬编码。

3\. **\*\*子应用必须暴露 qiankun 标准生命周期\*\*** \`bootstrap/mount/unmount\`（入口文件导出），主应用没有自定义生命周期约定；主应用额外监听 single-spa 全局事件（\`single-spa\:first-mount\`、\`single-spa\:before-app-change\`、\`single-spa\:app-change\`）驱动 loading、埋点 [代码证实]。**\*\*未找到\*\***任何子应用源码级接入模板，主应用仓库内**\*\*没有\*\*** Svelte/SvelteKit/Vite/ESM 子应用实例——已接入子应用均为同源 \`/static/\<name>/index.html\` 的 HTML entry，且**\*\*推断\*\***为传统打包（qiankun HTML entry + import-html-entry 抓取静态资源）。

4\. **\*\*props 仅两个：\`appList\`（当前应用权限列表）和 \`roleList\`\*\***（角色列表）[代码证实]。**\*\*没有\*\*** globalState、没有 token、没有用户信息在 props 中下发；用户信息在 \`window\.currentLoginUser\`。

**### 可直接复用的公共能力（主应用已实装，子应用可消费）**

\- \`window\.currentLoginUser\`（用户信息）、\`window\.relogin\`（SSO 重登）、\`window\.pSite\`（站点）、\`window\.biLanguage\`（语言）、\`window\.cftk\`（CSRF）、\`window\.cloudbi.\*\`（导航/双因子/鉴权弹窗/角色变更事件）、\`window\.pangu.\*\`（盘古对话 SDK，主应用动态加载）、\`window\.errorMessageInterceptor.errorProcess\`（HTTP 错误统一处理）、\`window\.iocSysInfo\`/\`window\.doubleCheckFlag\`、URL 级 \`identity=\`/\`appId=\`/\`focusApp=\` 深链参数。

**### 关键限制**

1\. **\*\*静态资源必须同源部署\*\***：子应用 entry 全部是相对路径 \`/static/\<name>/index.html\`（或 \`\_sys_configs\` 覆盖的 \`wcmUrl\`），走主应用 Tomcat 同域；\`SsoFilter\`/\`TokenSetFilter\` 对静态资源 ignore，但非静态请求必须带 \`cftk\` 头 [代码证实]。

2\. **\*\*无独立沙箱\*\***：\`start({sandbox:{strictStyleIsolation\:false, loose\:true}})\`，CSS 不隔离，子应用自带样式默认注入 body（有 \`window\.cloudiocTargetToHead\` 补丁开关强制注入 head）[代码证实]。主应用有 patch 允许 \`window\.top/parent\` 逃逸沙箱（主应用可能嵌在 iframe）。

3\. **\*\*容器滚动在主应用\*\***：\`#child-container\` 由主应用 \`overflow\:auto\`，子应用内容高度由主应用 \`calc(100% - 导航/公告高度)\` 控制 [代码证实]。

4\. **\*\*没有 KeepAlive/页签缓存/多实例\*\***：qiankun 标准单实例，路由切换即卸载重建 [推断：代码未见相关配置]。

5\. **\*\*主应用路由"吞掉"一切 path\*\***：\`path: '\*\*' → EmptyRouteComponent\`（空模板），无 404 重定向逻辑；深链接刷新由**\*\*服务端 \`web.xml\` 的 404 error-page → /index.html\`\*\*** 兜底 [代码证实]。MetricCanvas 内部深路径刷新会被这个机制接回主应用 index.html。

6\. **\*\*子应用刷新后注册依赖登录流程\*\***：刷新 → 服务端 index.html → Angular 启动 → \`APP_INITIALIZER\` 登录/权限查询 → \`registerMicroApps\` 重新注册 → 匹配 activeRule 挂载。深链接（如 \`/metrics/manage/pages/abc\`）默认**\*\*原样保留\*\***（主应用不重写 URL），qiankun 首次挂载即匹配。

**## E. MetricCanvas 需要满足的要求 & 主应用团队需确认事项**

**### MetricCanvas 侧要求（由本仓库代码推导）**

1\. 产出**\*\*同域可部署的 HTML entry + 完整静态资源\*\***（entry 相对路径 \`/static/metricscanvas/index.html\` 或 WCM 版本化 URL），且 index.html 中资源路径与部署路径匹配。

2\. 入口 JS 导出 \`bootstrap/mount/unmount\` 三个 qiankun 生命周期；\`mount\` 挂到 \`props.container\` 内自己的根节点；\`unmount\` 完整销毁（事件监听、定时器、Svelte 实例）。

3\. **\*\*适配层集中在入口文件/独立 module\*\***：读取 \`window\.currentLoginUser / biLanguage / pSite / relogin / cloudbi.\* / errorMessageInterceptor / cftk(localStorage)\`，业务代码不得直接依赖主应用内部实现。

4\. **\*\*路由 base 正确性\*\***：\`\<base href="/metrics/">\` 或等价配置；内部路由用 history 模式；**\*\*不接受主应用 404 拦截\*\***（主应用 \`\*\*\`→EmptyRoute 空模板不重定向，服务端 404→index.html 兜底，已满足）。

5\. 业务请求：\`/rest/...\` 同域 + Cookie（\`cloudbi_session_id\`）+ \`cftk\` 头 + \`x-language\` + \`appId\` 头（对齐 [header-setter.interceptor.ts:13-29]）；401 时调 \`relogin()\`。

6\. **\*\*样式自洽\*\***：\`strictStyleIsolation\:false\`，子应用样式会与主应用（tiny3/ana）同层作用；避免污染 \`#child-container\`、\`body\` 滚动（滚动在主应用容器）。

7\. 初始化时机约束：**\*\*模块顶层不能依赖 \`window\.currentLoginUser\` 等\*\***（它们登录完成后才存在）；要在 mount 里读。

1\. **\*\*应用注册表如何维护\*\***：\`/apps\` 接口由 \`cbcbipermissionservice\`（另一服务，本仓库只消费）提供——MetricCanvas 的 \`entry/activeRule\` 由谁、在哪个配置/DB 里登记？\`permMark\`/\`isHidden\`/菜单权限如何分配？
