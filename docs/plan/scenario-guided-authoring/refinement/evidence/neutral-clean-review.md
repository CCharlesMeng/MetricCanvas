# 修正后的 DeepSeek 干净对照

## 结论

12 轮真实中性需求对照已完成。**新版在本批 6 轮中，均正常结束、一次 create 成功、无工具错误、无缺失占位，且全部使用 compactSummary 主辅组合。** 新旧运行时与参考分别隔离，未人工拼接或改写模型产物。

这支持“新版 Skill 与工具能让真实模型生成对象卡与主辅层次”，不支持“所有业务语义和视觉已经通过”。用量第 1 轮存在对象范围与计划不一致的具体问题，见下文。用户负责视觉验收，本轮无截图。生产接入、刷新、保存及发布未验证。

## 方法与隔离证据

- 同一 `deepseek-v4-flash`、冻结模型参数、相同中性需求和修正后的合成样例；经营／用量每组各 3 轮，单轮最多 6 次模型请求、12 次工具调用。
- 需求没有预设章节、卡片数量或完整页面。新版参考按场景注入；旧版使用其当时已有的统一场景参考，这是受测版本差异的一部分。
- 收费启动前实际调用公共工具：两边均能看到固定期间；新工具含 v2，旧工具不含 v2；导入路径及 Schema hash 见 [preflight](neutral-clean-preflight.json)。
- 真实轨迹中的 `tools.json` hash 也不同：新 `5bd66e2f8706d2d226431ecfe4ece7cf9dd2612ada4d3f2605314e3ca493266e`，旧 `acf7599cd6970679d5f1c96f150cdbb175c9760867257329fb15c00d3df40a22`。
- 原始目录为 `neutral-clean-v2/`、`neutral-clean-v1/`，首批有缺陷的轨迹仍保留，不混入本批统计。12 轮模型通道审计均通过。

## 业务内容审阅（agent 初审，非用户签收）

| 新版轮次 | 问题 / 对象 / 信息增量 | 评语 |
|---|---|---|
| 经营 1 | 当前对象规模与变化 → Core/云通信实际预测 → 稳定/一次性另一口径 → 年度推演与支撑 | 各章解释口径差异；信息更全，也比另外两轮更长；未强制相同章数 |
| 经营 2 | 整体 → Core/云通信重点对象 → 全年走势 → 另一口径结构走势 | 整体与重点对象分章，非同对象同内容重复；主辅格式、对象匹配明确 |
| 经营 3 | 整体/Core/云通信同章 → 全年走势 → 结构走势 | 3 张对象卡各两行主值，变化为辅助，接近用户已认可的阅读结构 |
| 用量 1 | 整体主辅卡 → 对象柱图和核对明细 → 月度走势 | 图/表分工明确；但“只比较 model-a/model-b、不重复整体”的计划未落实筛选，图和表仍含 all 行，语义不完全通过 |
| 用量 2 | all/model-a/model-b 当前规模与同比 → 月度走势 | 三张对象卡，每卡 Tokens/请求量及同比，走势使用独立来源，未跨源互算 |
| 用量 3 | 当前对象规模与同比 → 近月走势 | 与用量 2 相似，但不规定固定卡数或章数；无图表/明细重复 |

用量 1 的证据：`neutral-clean-v2/usage-neutral/1/after.json` 中 `object-bar`、`object-detail` 都引用 `usage-kpis`；查询 `filter.dims=[]`，初始行包含 `all/model-a/model-b`。该轮计划却明确只比较 model-a/model-b，且 `distinctFrom` 声称不重复整体。最早可控边界是模型提交的对象筛选和复用选择，不是渲染器。后续可让模型使用带明确对象筛选的独立取数需求，或诚实声明全量对象比较；本批不修改原始候选来掩盖问题。

因此 A11 的“各场景三次真实运行、轨迹及成本记录”已完成；全面业务签收仍待用户，不能将这一处已发现问题记为通过。
