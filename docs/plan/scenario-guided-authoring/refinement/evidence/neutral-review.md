# DeepSeek 中性需求评测：首批 12 轮

结论：**已真实执行，但不能据此宣布 S6/A11 通过，也不能得出完整新旧版本的胜率或成本改进结论。** 原始轨迹不修改、不拼接、不重标通过。

本轮向 `api.deepseek.com` 请求 `deepseek-v4-flash`，两场景每组各 3 轮，共 12 个创作任务；任务内部共尝试 65 次模型请求，收到 63 个响应。响应记录合计 **1,788,227 tokens**，包含缓存 token，不等于按全价计费的 token，也不提供未核验的金额估计。没有追加收费重跑。

## 可用的观察

- 新版 6 轮有 4 轮产生候选，另外 2 轮 ConnectError；4 个有候选的轮次全部生成了主值／变化值组合，变化绑定数分别为 8、6、6、6。
- 新版经营第 3 轮自主选择整体／Core／云通信三张 compactSummary，每卡年累计＋同比、本月＋环比。不是把人工计划作为用户请求传给模型。
- 新版用量第 1 轮按整体／对象／走势分区，第 3 轮按当前规模／走势分区，说明没有机械固定相同章数。第 3 轮通过局部修订补出了趋势，但仍因 6 次模型请求的上限未正常收尾。
- 两组全部 13 份已接纳候选修订均通过当前 TypeScript `parsePage`。这只证明结构合法，不证明需求完整、模型正常结束或视觉通过。
- 所有已完成响应均来自真实模型调用；10 轮原始请求/响应完整且模型通道审计通过，2 轮因网络中断存在请求无响应，审计为 inconclusive 而非泄露判定。

## 为什么不能作为完整对照

“neutral-v1”加载了旧 Skill，但公共 fixture helper 在导入时重新把当前工作区放到模块搜索路径前面，实际使用的是新版工具。两组 `tools.json` SHA256 完全相同：`5bd66e2f8706d2d226431ecfe4ece7cf9dd2612ada4d3f2605314e3ca493266e`。

因此这批至多提供“新旧参考文案在同一新版工具上的行为观察”；不能追认为事先设计好的纯 Skill 实验，更不能称为完整版本对照。旧组用量第 2 轮甚至尝试提交 v2，进一步证明新能力已污染旧组。原始 manifest 的 baselineHashes 只说明磁盘源文件存在，不证明进程实际导入了它们。

## 根因与本轮离线修正

| 现象 | 根因层 | 修正与证据 | 剩余边界 |
|---|---|---|---|
| 指定旧根目录却导入新工具 | 评测入口 | `scenario_flow_server.py` 按 LIBRARY_ROOT 选择 helper；启动断言实际导入路径；替代目录回归修复前失败、修复后通过；真实旧目录只读探针也通过 | 新收费对照尚未重跑 |
| 趋势请求反复 time:null / DQE_QUERY_REJECTED | 样例发现投影 | 固定期间原来只写在未返回的 Schema 描述；现写入可返回的指标描述；公共 discover 测试修复前失败、修复后通过 | 样例修正不是产品时间语义能力扩展；不能倒推旧轮次本应成功 |
| blocked 轮次已有候选却被汇总丢弃 | 评测汇总 | scorer 按轨迹引用读取最后已接纳候选并核对 hash，明确标记 unfinished-run，不修改原始 after/result | 候选存在不等于完成 |
| 结构合法但趋势缺失或循环未结束 | 创作结果/评测边界 | 保留缺口、原始问题及上限；不放宽约束、不隐藏失败 | 仍需干净对照、模型正常收尾及业务审查 |

下一批必须使用新的证据目录，冻结修正后的相同样例，并先确认新旧工具实际导入路径和 Schema 不同，再开始收费调用。用户已经认可的确定性最终 JSON 未被这批部分成功候选覆盖。视觉仍由用户验收，未截图、未保存、未发布。
