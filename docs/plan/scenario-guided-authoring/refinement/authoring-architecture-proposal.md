# 页面创作架构调整方案

状态：方案已获授权，v3 本地工具与 Skill 已实施，2026-09-17。完成项与剩余验收见[实施结果](architecture-implementation-results.md)；日常维护入口见 [Bundle 架构与范式维护](../../../../metriccanvas-authoring/README.md#v3-页面创作架构与范式维护)。未调用外部模型验证 v3，未修改渲染器。

下文是实施前冻结的现状、缺口与设计依据；“当前事实”“推荐处理”“实施前确定”等均属于提案时点，不能作为现有工具能力清单。实际输入以工具 Schema 为准，能力投影与 Skill 使用说明见 Bundle。

## 1. 目标与证据

目标：面对不同需求与数据能力，模型能选择合适的信息结构；工具稳定、透明地将计划编译为普通页面文档。灵活性来自可组合的表达，不来自开放任意 JSON/CSS；可靠性来自可信绑定和可测试的编译，不来自固定整页模板。

证据：

- [丰富数据评测](rich-data-evaluation-results.md)：丰富组 0/3 正常收尾、1/3 有合法候选。purpose/intent 混淆、错误位置不精确和预算消耗是已观察到的稳定性问题。
- [原候选](evidence/rich-business-candidate.json)与[用户认可的人工调整版](evidence/rich-business-layout-v2.json)：数据源完全相同，后者改变主次层级、目标对比表达、列表密度与说明位置。认可来自本会话，不等于跨场景质量已验证。
- [ADR-0082](../../../adr/0082-explicit-business-sections-in-platform-authoring.md)：保留业务章节组织、一源多组件、跨口径同章与五工具入口；差异口径仍须随页面可见。不退回按数据源机械分区。

## 2. 现状：四类知识各有责任

| 知识 | 当前真源 | 当前作用 |
| --- | --- | --- |
| 页面协议与呈现能力 | `packages/page/src/schema/`、统一运行时、组件实现 | 合法字段、组件表现、12 列网格、响应式 |
| 创作入口实际开放的能力 | `metriccanvas-authoring/contracts/authored/`、工具实现 | 结构计划、修订、输入限制；不等于全部页面协议 |
| 阅读与选型判断 | `metriccanvas-authoring/skill/metriccanvas-platform-authoring/` | 创建/修改流程、布局形态与按需场景参考 |
| 默认展开规则 | `section-patterns.json`、`page_structure.py`、`section_presentation.py` | 默认 span、metric-summary 映射、行内占位调整 |

当前 pattern 主要是组合名称及默认占位，不是智能布局算法。`metric-summary` 固定展开为 compactSummary；`pack_section` 按原顺序填充未显式指定宽度的行，不判断业务重要性。table/lineChart 默认通栏，但显式 width 已可覆盖，不能把这些能力误报为缺失。

结构检查已经在查询前执行；精确字段、唯一行及可信主辅关系等检查依赖后续证据。局部修订和查询缓存已经存在。当前创建与修订分别处理口径说明，均会生成原始参数式正文。

## 3. 推荐结构：深化现有 Module，不再叠一套编排

```text
用户意图 + 可信上下文 + 当前可执行能力
                  ↓
Skill：选择业务问题、阅读层级、组件与呈现
                  ↓
页面结构计划（创作期）
                  ↓
同一内容装配 Module
  静态检查 → 受控取数/复用 → 可信绑定与呈现展开 → 整页校验
                  ↓
普通页面文档 + 安全诊断 + 调整记录
                  ↓
统一运行时；视觉验收独立于结构校验
```

外部 Interface 继续由 create_content_page/edit_page 承载，不增加“规划→选型→排版→审核”四个强制模型往返。上图是内部职责，不是四次调用。结构计划不进入渲染协议。

内部 Seam 放在“经验证的数据源与呈现计划 → 页面片段及诊断”：创建和修订共用绑定、呈现、说明处理。查询、身份、候选版本和保存回执继续由已有应用流程负责。只把已重复的逻辑收拢，不为假想插件创建新的 Adapter 注册框架。

### 模型负责什么

- 从需求选择业务问题和阅读顺序；说明哪些内容提供信息增量。
- 根据数据形状、单位、证据完整性及读者任务选择组件；图表数量不作为质量目标。
- 明确主次、并排与通栏，选择必要显示字段。保留用户显式选择。
- 对缺证据的问题说明缺口；不从指标元数据编写数值结论。

### 程序负责什么

- 验证输入能力、预算、引用、单位、可信关联、唯一对象和结果字段契约。
- 忠实实现显式选择，缺省值按可追溯规则补齐；不按 pattern 偷换组件或删除重复绑定。
- 报告每项默认补齐/宽度调整及受影响对象。不可执行的选项报错，不能静默忽略。
- 保持局部修订、人工属性和查询复用的既有保证；无副作用地返回候选，不扩张保存权限。

## 4. Skill 如何组织

主 SKILL.md 保留路径选择、可信输入、能力路由、交付边界。create/edit 工作流保留操作顺序。布局形态参考只解释 report/dashboard 的容器与呈现语义。

选型知识按真正分支按需读取：摘要与主辅指标、类别比较、时间变化、对象清单/精确核对、口径说明。经营/用量场景串联这些选择，提供有适用条件的示例，不重复能力枚举、不规定固定章节数。

只拆有实际复用且足够长的参考；短规则仍就地维护。新增参考必须同时打通文件读取与部署注入路由，不能只在 Markdown 中挂链接。当前评测注入入口为 `test-harness/model-evals/reference_injection.py`，部署路径也需单独核验。

本次布局作为经营场景参考偏好，不上升为硬约束。核心启发是“先定阅读层级，再选信息表达”，不是“所有页面必须整体一行、三个子卡、左右两表”。

## 5. 能力缺口与处理优先级

下表区分原生结构计划与最终页面文档；既有 operations 是否支持某设置须按对应操作核验，不用“可编辑”推导“可一次创建”。

| 项目 | 当前事实 | 推荐处理 | 优先级 |
| --- | --- | --- | --- |
| 摘要主次 | 页面支持 compactStrip 等；结构计划 metric-summary 固定 compactSummary | 增加有限摘要呈现选择，继续复用可信 rows/changes 绑定 | P1 |
| 横向类别比较 | 页面支持 horizontal；结构计划数据块没有该选项；普通编辑已有横向属性能力 | 创建/结构修订共享受控图表选项 | P1 |
| 紧凑对象列表 | fields 已能选少量列；结构计划未开放紧凑 variant、列对齐和副标题等 | 先开放认可案例必需的密度、列角色/格式选项，不照搬全部 table props | P1 |
| 说明层级 | 每个数据分区被追加原始查询参数 | 改为结构化范围事实驱动的公共说明与局部差异说明；创建/修订共用 | P0 |
| 重复标题 | v2 分区 title 必填，页面分区 title 可省略 | 新计划允许业务问题与可见标题分离，避免用空字符串绕过 | P1 |
| capability 漂移 | 页面 Schema、创作 Schema、实现开放面有区别；部分枚举又来自登记表 | 各层事实仍由各层拥有，生成并验证创作能力投影；不手写第二份全组件目录 | P0 |
| purpose/intent | 两套相近但不同的枚举造成实测错误 | 新输入收敛一套用途，适配器推导旧内部参数；无损映射不了的项目明确保留区分 | P0 |
| 错误反馈 | 已有预检但联合分支错误可落在整个块；入口异常可能绕过摘要 | 输出安全叶子路径、规则、允许值和受影响 ID；不回显原始数据/凭据 | P0 |
| 数据依赖校验 | 部分检查只有取数后才可完成 | 用快照提前检查可知项，取数后检查唯一行/完整性；不承诺一切错误零查询 | P0 |
| 组合嵌套 | 普通分区是平面 12 列；有特定容器组件不代表任意嵌套 | 首期维持平面组合，不新增通用嵌套布局 DSL | 非目标 |

### 能力投影与版本

页面 Schema 继续是渲染协议真源；创作能力由“该协议支持且本工具已实现”的交集决定，含路径、输入约束和展开规则。能力投影从契约与显式实现登记生成，测试保证每项确有可执行路径，未知能力默认不开放。

改变结构计划的必填项、用途含义或默认可见说明可能影响旧调用，建议用新结构计划版本承载，而非原地改变 v2。具体版本号在实现前确定；发布前保留 v1/v2 解码与兼容用例。既有页面文档不迁移。旧版工具缺能力时明确拒绝新版本，不静默降级。

### 口径不是隐藏开关

公共账期只在所有适用内容的可信范围一致时上移。年度目标/推演、月度实际、不同筛选范围不能被一个“本月”标签掩盖；指标时间语义不等同于请求筛选窗口。

重要差异就近展示，来源字段名转换使用可信标签；没有标签时给出可理解的限制说明并留诊断，不把原始键当自然语言。技术查询明细留在审计中。局部修订改变期间/筛选后重新计算受影响说明，不能留下旧页头。人工正文不按字符串相似度删除。

## 6. 三种需求的设计检验

以下是基于接口和证据的桌面检验，不是模型生成成功率测试，也不是视觉测试。只有 A 有当前页面产物与用户验收；B/C 是明确条件的待构造测试输入，不假称现有数据已经具备。

| 用例 | 输入与阅读任务 | 合理结构（允许其他等价方案） | 反例及失败判据 | 当前结论 |
| --- | --- | --- | --- | --- |
| A 经营阅读 | 当前四源；整体/对象、年度目标与推演、两类客户名单 | 主次摘要、年度对比图、紧凑对象表；显著保留样例与名单限制 | 目标/推演与月实际混画；名单称为增长贡献；技术键铺满正文 | 人工 JSON 可表达，结构计划还缺摘要/图表/表格呈现选项及可选标题 |
| B 用量监控 | 测试输入：时间序列、按资源类别的当前用量；无年度目标、无客户名单；数据不完整时声明范围 | 趋势优先，当前摘要辅助，按资源做比较；无依据时不用占比 | 硬套经营页面的目标图和客户表；缺分母却画完整构成 | 既有组件可承载主体；需验证选型自由与能力缺口表达，不需新模板 |
| C 明细核对与局部修改 | 测试输入：需要逐列核对的宽表、已有人工列宽/标题；用户只要求调整一列展示或移动说明 | 通栏表为主，保留必要列与手工设置；按稳定 ID 局部修订 | 为“丰富”插入 KPI/图；强压成三列；仅改展示却重新查询或覆盖其他属性 | 现有编辑/缓存方向正确；须补具体路径的零查询及不变性回归 |

结论：A 的改进不应强制传播为 B/C 的布局。范式应复用“用途→表达”的决策，不能复用固定外形。C 尤其说明“字段越少越好”“一定左右并排”都不能成为全局规则。

## 7. 回归与验收

先冻结用例和判断标准，再修改实现。用例从公开 create/edit Interface 运行，不只测试内部 helper。

硬性验收：

- 新旧计划均有合法/非法输入测试；不支持的选项、非法用途、缺 title 等能返回安全可修正的结构化诊断。
- 可静态判断的错误在 DQE 调用次数为零时拒绝；取数后证据失败不生成伪成功。
- A 新计划能表达认可页面的关键结构：主次、横向同量纲对比、两份精简名单、公共/局部说明。比较绑定与结构，不要求逐字或字节一致。
- 创建与修订在同一显式呈现选择下结果一致；标题/展示修改零查询，数据需求改变只执行受影响查询。
- 原始数据、凭据、完整页面不进入模型摘要；修改不触发保存或发布。
- 与原候选对比，未涉及的数据源、查询、数值和人工属性保持不变。局部口径改变时，派生说明正确更新。

质量验收：每例审阅“问题覆盖、信息层级、组件适配、重复内容、口径可读性”，允许多种合理答案。重叠字段是事实，不是重复内容的自动定罪。没有数值行时不评价模型数值洞察。

后续模型评测固定能力/Skill 版本、样例、预算与失败计数，分别报告：合法候选率、正常收尾率、业务覆盖、人工视觉验收。未经授权不调用收费模型；未运行记为未验证。浏览器和视觉验收仍按用户选择执行，JSON 校验不能替代。

## 8. 实施顺序与完成边界

1. **基线与诊断**：冻结 A/B/C 输入和反例；先解决入口/叶子错误反馈与能力投影一致性。完成标准：旧回归不退化，非法请求能精确定位。
2. **共享装配能力**：以 A 的缺口实现最小受控呈现与说明策略，创建/修订共用；采用版本化兼容。完成标准：不手改最终 JSON 也能生成 A 的关键结构。
3. **Skill 重组与分发**：写决策原则、带适用条件的示例及按需参考；接通注入路由，重建 Bundle 锁与一致性检查。完成标准：实际部署收到匹配的参考和工具能力，不只源码文档正确。
4. **差异场景回归**：执行 A/B/C 与旧用例，再按授权开展独立模型评测。完成标准：B/C 不被 A 的偏好绑死，结构与行为证据分别报告。

暂不做：通用 CSS/坐标、任意嵌套分区、模板市场、另一个规划服务、渲染期自主设计、自动业务结论、新数据权限、保存发布改造。

范式维护规则：先确认变化属于决策参考、创作能力还是渲染协议，再只在该真源修改；生成副本与 Bundle 由现有导出链更新。参考组合需要适用条件及反例，能力登记需要契约和展开测试。单个用户认可案例可以作为参考资产，但不足以把偏好变成全局硬规则。
