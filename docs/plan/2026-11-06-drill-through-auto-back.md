# 下钻详情页自动返回方案

日期：2026-11-06；实施更新：2026-11-07。状态：用户已授权实施，本仓实现及约定范围内本地验收完成。未提交、推送或部署。本文是本项工作的唯一实施入口，实际结果见第 9 节。

## 1. 目标与已确认规则

清单 A 点击业务记录，下钻进入详情 B。B 的 IOC 页头配置自动返回后，有有效下钻来源才显示返回按钮，点击回到进入详情前的 A。

| 操作 | 自动返回行为 |
|---|---|
| 同标签页从 A 的跨页下钻链接进入 B | 记录本次来源 A，B 显示返回 |
| 首次直接输入、粘贴或通过收藏夹打开 B | 没有有效下钻来源，不显示返回 |
| 在 B 修改筛选，页面自身更新 URL | 保留来源 A |
| 刷新 B | 保留来源 A |
| 从 A 进入项目 1 的 B，再手改查询参数查看项目 2 的 B | 仍属于同一个详情页，保留来源 A；返回 A，不退回项目 1 |
| 手改 URL 切换到另一个页面 C | 清除当前下钻来源；再次直接打开 B 不恢复旧来源 |
| 用新标签页打开 B，包括通过下钻链接打开 | 视为独立打开，不显示返回 |
| 点击 B 的自动返回按钮 | 回到来源 A 当时的 URL，恢复其中记录的筛选条件 |

“同一个详情页”按宿主解析出的页面身份判断，不能按完整 URL 字符串判断：查询参数变化不改变页面身份；页面身份变化表示已切换页面。不能按标题、项目编号、布局类型或 URL 中是否出现 `detail` 推断。

本轮不要求恢复未写入来源 URL 的分页、排序、Tab、滚动及其他完整视图状态。同页详情视图不是跨页下钻，不新增返回来源。

## 2. 最小声明与兼容

沿用 IOC 页头的 `props.back`，增加一个取值 `"auto"`。以下为已在本仓实现的 6.96 协议组件片段：

```json
{
  "id": "detail-header",
  "type": "iocHeader",
  "layout": { "span": 12 },
  "props": {
    "identity": { "title": "项目详情" },
    "back": "auto"
  }
}
```

组件仍放在首 section 首组件，同层的 `identity`、`readOnly`、`filterIds`、`components`、`presentation` 等声明沿用已有含义，不增加独立页头、隐式组件或全局默认开关。

| `props.back` | 含义 |
|---|---|
| 省略 | 沿用现有行为，不显示页头返回 |
| `true` | 沿用现有浏览器默认返回及集成应用可选覆盖，不改变旧页面 |
| `"auto"` | 只在有效下钻来源存在且有相应返回处理时显示；执行返回来源动作 |

自动模式缺少来源时隐藏，不能回退到 `history.back()`。单独存在通用 `navigation.back` 函数也不证明有下钻来源。只读允许返回，静态导出不包含返回按钮，页头条件显隐沿用现行规则。

### Schema 最小化

现有 `back:true` 表示浏览器默认返回，不能同时表达“仅有下钻来源时显示并返回该来源”；直接修改其含义会改变已发布页面。用户需要选择这两种行为，因此仅扩展现有字段的取值。

- Schema 字段新增 0、删除 0；既有 `back` 新增 `"auto"` 分支，保留 `true`。
- 不增加 `from`、`returnUrl`、来源页面参数、来源业务字段或作者维护的导航栈。
- 来源识别、有效性判断、生命周期和返回执行由引擎与集成应用承接，页面只声明返回意图。
- 实施基线为 6.95，本批分配 6.96，并补充版本门禁、旧版本拒绝及既有取值兼容校验。

| `apps/platform/src/lib/integration/navigation.ts` | history state 服务于宿主导航和离开保护 | 来源记录与现有 state、路由前缀、导航取消机制共存 |

现行 [ADR-0048](../adr/0048-navigation-intent-and-host-routing.md) 及[IOC 主题基线](../adr/topics/ioc-operation-map-batch.md) 将来源记录和自定义导航交给集成应用，允许 `back:true` 使用浏览器默认返回。本方案保留上述所有权和旧语义，为显式自动模式补充更严格的有效来源要求，不让统一运行时拥有宿主路由。实施时同步现行接入说明，避免历史 Canvas 描述代替当前 Playground/Platform 实现。

## 4. 来源生命周期与职责

### 来源的建立与使用

1. 只有受控的同标签页跨页下钻成功到达目标后，才激活本次来源。来源 URL 取离开来源页时的当前地址，包含当时已写入 URL 的页面参数与已应用筛选。
2. 来源至少关联来源地址、目标页面身份及本次导航上下文。具体内部类型实施时确定，不成为页面 Schema。
3. 来源记录与当前标签页、当前下钻上下文关联；不能仅按目标 pageId 查询“上一次访问来源”，也不能仅凭 `history.length`、可后退标记或 referrer 推断。
4. 当前详情页刷新、筛选及同页参数变化保留来源。换项目不更新来源 A，也不把旧项目详情作为新的来源。
5. 页面身份变化且不是新的受控下钻时，终止当前来源上下文。A → B 后改到 C，再直接到 B，不得复活 A。
6. 新的受控下钻建立新的来源关系。例如 B 点击进入另一详情 C 时，C 的直接来源是当时的 B；不能继续把 A 当成 C 的直接来源。
7. 返回使用已记录的来源 URL，通过集成应用导航执行。不能因 B 中间产生过查询参数历史记录而退错页面；不改变浏览器自身前进/后退按钮的原生含义。

### 引擎与集成应用

- 引擎解析声明，根据有效来源与返回能力决定是否显示；复用现有导航意图，不推断页面成员或业务层级。
- 集成应用拥有来源建立、刷新连续性、同页 URL 变化、跨页失效与返回执行；Playground 和 Platform 实现同一行为契约。
- Embed 接入复用可选导航接缝。独立嵌入若无法提供可验证来源，自动模式隐藏；`back:true` 保持当前默认行为。
- 返回目标只消费已记录且经宿主校验的来源地址，继续服从宿主导航范围与既有权限、离开保护。不接受普通查询参数伪造来源。
- 导航失败、被取消或未获准离开时，不激活新来源或提前丢弃仍有效的来源；存储不可用、记录损坏或身份无法验证时隐藏自动返回。

## 5. 实施前必须验证的浏览器边界

本节列出实施前置验证要求；选定机制及实际结果见第 9 节。不能将“按标签页存一下来源”视为已经满足手改 URL 与新标签页要求。

首个实施步骤用最小浏览器场景验证：同页手改查询参数后上下文如何连续；跨页手改时如何失效；刷新如何保留；新标签页如何拒绝继承旧上下文；浏览器前进/后退如何匹配相应进入上下文。覆盖原生整页跳转与宿主客户端路由，并检查筛选的 `replaceState` 不抹掉来源信息。

地址栏输入和粘贴本身不作为可信事件。应依靠宿主可验证的页面身份与导航上下文判定：有活动下钻上下文且仍为同一详情页时保留；没有上下文的直接进入不创建来源。对无法区分的场景记录实际限制，不用旧 pageId 缓存或浏览器历史长度补造来源。

尤其需要防止：手改到 C 后，因为 C 不受当前宿主管理而没有执行清理，之后直接打开 B 又恢复旧来源。新标签页也不能仅凭存在 sessionStorage 记录获得返回资格。

若技术验证无法同时满足已确认行为，先在本计划列出具体冲突和可选调整，不能静默改成“手改参数就隐藏”或“所有同 pageId 访问都继承”。

## 6. 后续实施顺序

以下为方案阶段确定的实施顺序；2026-11-07 已获实施授权，实际完成情况以第 9 节为准：

1. **验证导航生命周期**：完成上一节的最小浏览器验证，确定来源与标签页/进入上下文的关联方式，以及返回导航后的记录处理；复用宿主机制，避免独立的通用导航栈。
2. **协议与引擎**：扩展 `props.back` 取值、版本门禁、页头解析及返回决策；明确有效来源端口，回归 `true`、省略、只读、静态导出与旧工具栏兼容路径。
3. **宿主接线**：修复 Playground 旧来源复用，接通 Platform；验证导航成功、取消、刷新、手改 URL、路由前缀和外部离开。来源会话逻辑不堆入 RuntimeSurface 或页头组件。
4. **场景与文档**：新增或扩展 `layout:"dashboard"` 的下钻来源页、详情页和无关页面，配套 README 操作步骤；同步页面元数据文档、宿主契约和 Embed 接入说明。
5. **创作与分发**：按产品真源生成 local-authoring 知识、示例、校验器及清单，仓外独立安装校验；交付 Embed 时执行公共入口、分包闭合及每个 JS 文件 ≤1,000,000 字节门禁。
6. **验收收口**：执行下表行为测试及真实浏览器验收，记录类型检查、适用回归、复杂度前后结果与分发结果。真实门户集成单列，不能以 Playground 通过代替。

编码时按[代码复杂度规则](../agents/code-complexity.md)先识别协议解析、有效性判断、来源存储及宿主导航职责，实测所有修改函数与新增辅助函数，并处理涉及的存量超限。方案落盘阶段只有文档变更；实施阶段的实测结果见第 9 节。

## 7. 验收矩阵

下列为验收要求；实际执行范围和证据边界见第 9 节。按[功能与协议能力验收要求](../agents/feature-acceptance.md)同步 Playground、页面元数据文档和 local-authoring。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | A 带筛选下钻到配置 `auto` 的 B | 显示返回；点击回到 A 当时的 URL，URL 内筛选恢复 |
| A02 | 无活动来源，直接打开 B；此前浏览过无关页面 | 隐藏，不能因浏览器可后退而显示 |
| A03 | A → B 后刷新 B | 来源 A 保留且可返回 |
| A04 | A → B 项目 1；地址栏改为 B 项目 2 | 保留来源 A，点击返回不落到项目 1 |
| A05 | A → B；在 B 操作筛选并产生 URL 更新 | 来源不改变，返回 A |
| A06 | A → B；手改到 C，再直接打开 B | 隐藏，不复用旧 A；C 包含宿主外页面 |
| A07 | 新标签页打开 B | 隐藏；覆盖普通新开链接、修饰键及存在旧来源记录的情况 |
| A08 | A → B；B 受控下钻到 C | C 的返回指向 B 当时的 URL，不能误指 A |
| A09 | 浏览器后退/前进、返回后再进入详情 | 上下文与实际历史进入匹配，直接进入不复活已失效来源 |
| A10 | 导航取消、失败，或来源记录损坏/存储不可用 | 不产生伪来源；无有效来源时隐藏；未完成导航不破坏原有效上下文 |
| A11 | `auto` 无来源但注入通用 `back`；或来源有值但无可执行返回 | 隐藏，不绕过来源和可执行性校验 |
| A12 | 原 `back:true`、省略、只读与静态导出 | 既有行为保持；只读允许有效返回；导出不包含按钮 |
| A13 | 普通 URL 输入试图设置来源；部署前缀、来源不可访问 | 不伪造来源；遵守宿主路由及权限处理，不退回无关历史 |
| A14 | 当前版本/未来新版本分别校验 `auto` | 按能力版本接受或拒绝；旧页面不被自动改写 |
