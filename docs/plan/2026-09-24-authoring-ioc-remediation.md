# 创作取数与 IOC 能力迁移整改说明

日期：2026-09-24。状态：公共对接整改已实施，验证与内部采用状态见末节；IOC 扩展仍待来源证据与具体设计。

本文汇总 IOC 存量审计报告审阅、用户提供的真实 `query_data` 回执以及本地代码诊断。交付范围是问题、根因、修改方案、职责和验收要求；不表示业务代码已修复、内部环境已验证。用户已要求增加可快速开关的查询语义严格校验，默认关闭，具体要求见 R12；其余尚待评审的接口与页面协议扩展不以本文自动批准。

## 1. 结论与整改范围

现有架构方向继续成立：模型描述业务需求，公共 Python 实现确定性查询构造、验真与页面装配；统一运行时消费声明式页面文档；适配器连接真实服务；集成应用提供身份、端点与应用导航。

本次问题集中在三个方面：

1. **发现与执行未形成完整契约。** 执行需要业务域、维度和时间粒度，实际启用的语义发现分支没有完整提供这些信息。失败后又丢弃了可用于纠正的候选信息。
2. **源协议转换存在缺陷，公共规则维护边界过宽。** 时间维度类型大小写导致时间能力丢失；通用投影和治理诊断与公司接线混在内部自有适配目录，公共修复需要人工移植。
3. **IOC 存量接口清单不能直接作为目标实现规格。** 应补齐业务行为与确定性能力，不能复制任意脚本、SQL 拼接、DataV/ANA API，或让集成应用逐页补足引擎缺失能力。

优先修复创作取数闭环，再收敛公共模块与适配职责；IOC 新能力另按逐页证据设计和验收。本批不增加 GraphQL/REST 查询分支，不扩张真实取数协议。

**新增确认要求：查询语义严格校验默认关闭，可通过一个可信配置开关快速启用或关闭。** 默认宽松模式将可选语义预检降级为诊断，能够确定性构造且已授权的查询交由真实 DQE 验证；身份权限、协议结构、执行资源约束及保存安全不受此开关影响。该要求修订下文原有“一律先通过语义闭集预检”的处理方式，以 R12 的规则矩阵为准。

## 3. 问题、根因与修改方案

### R01 · 发现缺少查询必需的业务域（P0，公共代码确认）

**问题。** 装配 SemanticCatalog 后，发现结果没有顶层业务域列表，指标卡也没有所属业务域；查询却要求业务域精确命中快照 Schema 名称。模型容易误用 modelId、展示标题或自行概括的业务域。

**根因。** [platform_authoring.py](../../metriccanvas-authoring/tool/metriccanvas_authoring/pages/platform_authoring.py) 的两条发现分支返回不同语义面；[semantic_catalog.py](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/semantic_catalog.py) 没有建立指标来源到执行域的规范关联，而 [executable_units.py](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/executable_units.py) 直接按 `businessDomain` 查找。

**方案。** 公共发现契约提供可枚举的规范业务域和每个指标的域归属，使用与执行快照一致的投影规则及版本。原始语义可被发现但尚不可执行时，明确标记执行能力未知或未就绪，不能为展示发现结果伪造受治理快照。遇到同名域或跨模型身份歧义，明确报冲突，不默认取第一个或做模糊授权匹配。

**归属与验收。** 公共数据模块负责；适配器提供真实来源标识。装配 SemanticCatalog 后，查询域必须能从发现结果取得，无预先写死的测试业务域。用户本次真实错误已经越过此检查，R01 是独立缺陷，不是本次回执的直接原因。

### R02 · 发现遗漏维度、时间粒度与组合约束（P0，已复现）

**问题。** discover 能找到指标，但不能找到构造地域筛选、分组与时间查询所需的维度。指标卡里偶尔出现 dimensions，不代表完整维度发现已实现。

**根因。** SemanticCatalog 只遍历 `field_schema.metrics`，检索只匹配指标名和别名；指标卡仅读取 `metric.dimensions`，没有读取模型级维度定义及时间层级。真实样例中指标自身 dimensions 为 null，但模型级维度实际存在。详情投影也没有补回这些查询能力。

**方案。** 统一发现投影，按需返回带种类和来源身份的指标、维度及时间能力；至少包含规范查询名、展示名、所属域、类型、时间粒度、是否可筛选，以及有可信依据的指标维度组合关系。维度取值按权限和实际能力受控获取；缺失就报告未知，不让模型编造。区分“该模型存在此维度”和“该指标可与此维度组合”，不能把所有模型维度直接挂到所有指标上。

**归属与验收。** 公共发现模块负责契约与选择投影；适配器负责真实源字段映射和取值服务接线。用“指标自身 dimensions 为空、模型级维度存在”的向量验收；搜维度名能返回维度，时间能力可直接用于查询，未知组合不会被声称为已支持。需保留结果大小限制与分页/截断说明，避免改成全量元数据灌入模型。

### R03 · 月粒度编码不一致及时间维度被误识别（P0，已复现；现场映射待确认）

**问题。** 用户提交 `granularity: "M"`，回执在 `/units/0/time/granularity` 失败。改成 month 仍可能失败，因为参考适配器会丢掉某些真实时间维度的时间角色。

**根因。** 执行端按快照粒度闭集精确匹配，不将 M 自动转成 month。参考 [data_context_http.py](../../metriccanvas-authoring/examples/adapter_template/firstparty/data_context_http.py) 用 `== "strDateTypeDimension"` 判断时间类型，而 [真实样本](../../调查报告/数据/语义层查询结果.json) 使用 `StrDateTypeDimension`。此外，当前转换器只承认 year/month/day；源端存在其他层级不表示本产品已支持它们。

**方案。**

1. 对已证实的源类型编码建立明确映射，归一化后再做时间角色和层级投影；未知编码不静默当普通维度。
2. 发现结果直接提供执行可接受的粒度值，Skill 优先选择这些值。是否因快照未枚举该粒度而阻断由 R12 控制；DQE 请求编码仍须符合已支持的协议。
3. 本批纳入明确的月粒度别名 `M → month`，在单一输入边界归一化，严格与宽松模式共用，并保证授权摘要、查询身份和执行语义一致；不在多个层里各自猜测。其他缩写仅在语义明确、有协议依据时增加。
4. 时间类型存在但没有任何受支持层级时，明确暴露时间能力缺口；不默认补 month。季度、周、小时等能力另按真实协议与产品支持范围评估。

**验收。** 两种已知时间类型编码投影一致；未知编码、空层级可诊断。M 规范化为 month；规范化后按 R12 选择警告或阻断，合法查询到达 DQE。现场检查受治理快照中的时间 roleHints 和 granularity 后，再确认是否完成恢复。

### R04 · 问题包含“中国区”，执行请求却无地域条件（P0，真实请求确认）

**问题。** 用户问题是“2026 年上半年中国区 Tokens 消耗量和 Tokens 流水总量”，但 `filters: []`。修复时间编码后，请求仍不一定回答原问题。

**根因。** 当前生成器消费显式取数单元，不从 question 自动补地域谓词；维度发现缺失又使模型难以填写正确过滤字段。没有证据证明这两个指标本身已经限定中国区。

**方案。** 发现正确地域维度及合法中国区取值，把地域范围写入取数计划和显式 filters，再确认执行范围。禁止猜维度名或值。时间窗口与“半年总量”也要分开核对：groupBy 为空不自动证明返回的是所需跨期总量，须核对指标可加性、时间聚合语义与真实结果形状。

**归属与验收。** Skill 负责提取需求并展示计划；公共查询层按已确认结构化条件执行并回显实际 scope；数据提供方确认口径和粒度。修改查询范围后重新绑定确认授权，不复用旧请求摘要。验收必须证明地域条件进入生效查询、结果确为上半年所需总量；无法确认则报告缺口，不能将全域结果标成中国区。

### R05 · 错误丢失恢复线索，重试语义不清（P0，代码确认并复现）

**问题。** 底层异常带候选名称或允许粒度，模型最终只见 code/path。相同失败反复出现，用户容易误以为每次都重新访问 DQE。

**根因。** [results.py](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/results.py) 持久化失败时只保留 code/path；查询签名包含轮次、版本和去掉 dataSourceId 的请求。相同签名命中已有失败记录直接返回，这本身是去重机制，不能简单删除。

**方案。** 公共错误投影保留经过授权范围过滤的有限 candidates、失败阶段及明确恢复提示；区分修正请求、更新上下文后重新确认与不可重试。保留相同查询去重，不靠换 dataSourceId、删状态库或无条件自动重试恢复。代码升级而上下文版本未变时，通过新的可信创作轮次执行修正后的查询；如需要更细的执行版本策略，另行设计，不偷偷改变历史 resultRef 含义。

**验收。** 业务域、维度、粒度错误均有可操作信息；候选不跨权限范围，不包含 SQL、凭据或原始内部响应。同一校验策略下原样重试无重复执行；修正请求并取得匹配授权后可执行。切换模式时的缓存和结果引用隔离按 R12 执行。保存未知状态仍保持禁止自动重发，与查询诊断改动隔离。

### R06 · 公共语义算法被下放到内部适配目录（P1，维护边界问题）

**问题。** 内部不仅维护端点、认证和响应转换，还需要手工移植通用治理回退、投影与诊断修复。公共升级后，公司自有 adapters 不被覆盖，旧缺陷可能继续存在。

**根因。** 通用中立快照投影与公司 HTTP 接线放在同一参考实现；[RELAY-HANDOFF.md](../../metriccanvas-authoring/RELAY-HANDOFF.md) 已要求手工采用公共修复。保护公司接线是合理的，但同时复制公共算法增加了维护负担。

**方案。** 提议拆成两个边界：公司适配器将源响应转为约定的源元数据输入并传递治理事实；公共模块拥有中立快照生成、规范名称/粒度处理、缺失诊断、版本计算规则和契约校验。已知 Java/Lab 格式可有公共可复用转换器，公司只维护确有差异的部分。工厂显式装配同源的发现与执行能力，不靠类名推断或隐式环境配置。

**归属与验收。** 公共模块重构需先做接口评审；本文不冻结新类型名称。验收公共升级无需内部复制通用算法，同时不覆盖身份、URL、权限与真实协议映射。既有端口调用方的迁移方式和版本策略须明确。

### R07 · 治理事实与技术派生责任混淆（P1，边界约束）

**问题。** 为通过校验可能补全局 nullable/sensitive/isRatio 或由 SUM 推断所有可加性；另一个方向是把通常能由查询和快照派生的字段契约全交给额外服务实现。

**根因。** 将“业务事实不足”和“公共工具未完成派生”都归类为适配工作。

**方案。** 数据治理方确认可加性、时间聚合、敏感性、金额/百分比尺度等真实事实；适配器传递，不能创造。公共代码负责 DQE 构造、稳定页面字段 ID、通常的结果字段映射、时间列/公式别名处理和行值校验。一般查询不强制额外源描述服务；只有真实重命名或尺度等无法内部确定时，使用已有可选扩展或限制该能力。

**验收。** 没有语义依据时保持未知或拒绝，不用默认值伪造治理。已明确的普通查询不要求适配方重写字段派生。具体依据见[结果字段来源核查](../evidence/2026-09-23-authoring-result-field-sources.md)。

### R08 · 现有测试没有覆盖真实发现到查询的断点（P1，代码确认）

**问题。** 数据集提供方相关成功用例没有启用 SemanticCatalog，查询参数又来自预置夹具；时间类型夹具采用参考适配器认可的拼写，因此没有捕获上述问题。

**根因。** 校验了单个部件可用，但未验证实际装配后的发现结果足以构造合法查询；夹具未覆盖已有真实源响应形状。

**方案。** 在现有测试层固化最小必要向量：正式 MCP 装配启用 SemanticCatalog、指标 dimensions 为空但模型维度存在、实际时间类型拼写、缺粒度、错误候选、业务条件保留。成功请求中的域、维度与粒度应来自发现结果，不能另设与发现无关的隐藏答案。

**验收。** 先使这些向量能捕获缺陷，再修复并复验。保留创建页面和调整页面两条必要主流程，不为本次逻辑修复增加无关浏览器测试。真实模型与内部服务验收独立报告，不能用替身通过替代。

### R09 · IOC 报告把存量 API 当成目标能力契约（P1，报告审阅确认）

**问题。** 报告 §4.8 将 fitFunction、ECharts formatter/option、SQL 字符串拼接、DataV/ANA/Tiny3 类接口列为目标“须提供”。照此实施会把旧框架内部接口引入页面协议或交给集成应用实现。

**根因。** 没有区分业务可观察行为、旧实现手段和集成应用职责。

**方案。** 将每项改写为“输入字段与口径 → 确定性变化 → 用户动作 → 可见结果”的行为契约。格式化采用受控格式声明；计算采用已批准具名算子；筛选采用显式绑定；导航采用现行 URL 与参数绑定。不得在页面中开放任意 JS、SQL 片段、样式 HTML 或任意 ECharts option。受控语义 HTML 仍按既有白名单协议处理，不等于任意 HTML 开放。

**验收。** 复刻不依赖 DataV/ANA；适配方无需实现其类库 API。已批准的行为可由同一页面协议和统一运行时表达，缺口明确列出而非放进组件回调。

### R10 · IOC 确定性能力仍有缺口（P2，待逐场景设计）

**问题。** 跨源计算、日期补齐、多类型 Tab、趋势/表格弹窗、地图提示、搜索与查询分页、格式和空值语义不能仅凭现有组件数量证明等价。

**根因。** 四份现有 IOC 页面不能覆盖报告中的全部入口；当前具名算子和组合结构未覆盖全部来源行为；部分行为还没有完整源码或输入输出证据。

**方案。**

| 能力 | 整改方向 | 不允许的替代 |
|---|---|---|
| 多源合并、日期对齐、动态比较 | 补关联键、粒度、缺源/重复键/零值/空值样例；评审最小具名算子及依赖顺序 | fitFunction 或适配器逐页算数；未经评审直接引入 joinAggregate |
| 多类型 Tab、复杂详情浮层 | 明确同页内容切换还是独立页面导航，再设计受控结构和状态生命周期 | 集成应用按页面标题外挂组件或开放任意组件树 |
| 图表和地图 | 逐场景核对系列、维度、提示、下钻和数值，扩充必要受控属性 | 暴露任意 ECharts option/formatter |
| 搜索、排序、查询分页 | 核对来源是否面向全量；现有 DQE 不支持的行为标记前提缺口，单独裁决 | 将当前窗口搜索宣称为全量搜索 |
| 格式与空值 | 建立原值、单位/尺度、null/0、显示字符串的黄金样例 | 因名称近似就认为 ANA 格式等价；未知金额自动乘除 |
| 导航与筛选状态 | 显式保留行级/页面级 mtime、参数来源和返回状态 | 复制隐式单例状态或 SQL WHERE 字符串 |

**归属与验收。** 公共协议/运行时负责页内能力，集成应用负责应用导航栈与身份。逐项能力扩展先评审；页级验收关注口径、信息层级与交互等价，不要求旧 API 或像素级复制。详见[IOC 差距记录](2026-09-23-ioc-full-page-capability-gap.md)。

### R11 · 报告完成度与实际证据不一致（P1，报告审阅确认）

**问题。** “127 请求全量完成”的附录未附逐条内容；主要深入三个页面，其余简表；页面 ID、Tab 启用状态和共享状态叙述存在需复核之处。

**根因。** 把入口穷举、源码阅读和运行验收合并为一个完成状态。

**方案。** 建立 21 路由入口到页面资产的映射，禁用功能单列；补完整活跃变换与交互条目，不强制路由和页面资产一一对应。修正 P-01→customer-list 的 ID、P-18 启用 Tab 数；核对“无共享状态”与 HeaderOptionService 副作用传值的矛盾。每项分别记录源码盘点、目标表达、夹具对账、真实集成状态。

**验收。** 所有活跃入口和变换都有可定位条目；缺证项显式保留。来源能力清单完成不等于迁移完成，四页本地演示不等于 21 入口完成。

### R12 · 查询语义严格校验开关，默认关闭（P0，用户已要求纳入）

**问题。** 实际元数据不完整、不同系统编码不一致，叠加多层前置校验，使可执行的业务查询反复被阻断。排查每个错误后才能推进一次查询，执行过程难以预测。

**根因。** 当前把“快照未能证明该查询受支持”“查询无法构造”和“查询不被授权”都当作硬失败，缺乏统一校验策略；部分检查在适配投影阶段就已中止，单纯在最外层忽略异常无法恢复执行。

**已确认行为。** 增加单一配置项 `queryValidation.strict`，默认 `false`。关闭时使用宽松模式，开启时使用严格模式。默认关闭必须在未提供配置的正式启动路径生效，不能只在测试或开发环境生效。开关由可信部署配置控制，不作为模型可传入的 MCP 参数。

**规则矩阵。**

| 校验内容 | 默认宽松模式（false） | 严格模式（true） |
|---|---|---|
| 已知等价编码和唯一、无歧义别名 | 先规范化，如 M→month；记录转换 | 同样先规范化，不因纯写法差异拒绝 |
| 支持的 DQE 粒度未出现在快照中、维度值枚举不完整、可组合关系未知 | 能保持请求含义并确定性构造时，警告并提交 DQE | 按规则要求证明；不足则返回具体问题和候选 |
| 指标/维度名未命中本地清单 | 若现有受控协议可表达、来源/权限范围明确，且结果字段契约可从可信声明或真实执行元数据确定，则警告并执行；不得编造字段类型或直接保存未验证结果 | 阻断未命中项 |
| 业务域未命中或名称存在歧义 | 唯一可信映射可规范化；无法确定来源或查询含义仍阻断，不默认取首项 | 相同，不将语义选择变成模糊猜测 |
| 非授权性质的可加性、时间聚合、尺度信息缺失 | 对不依赖该属性的直接查询不作统一前置阻断，保留 unknown；依赖它的二次聚合、缩放或结论仍不能凭空生成 | 按严格治理规则检查并报告缺口 |
| 源声明存在明确口径冲突、单位含义歧义 | 保留阻断或限制依赖能力，不能用默认值覆盖明确矛盾 | 相同 |
| 身份、权限、敏感数据策略、可信轮次、确认授权和上下文版本一致性 | 始终校验 | 始终校验 |
| 协议结构、必填执行参数、支持的查询语言、字段映射确定性、返回值基本校验 | 始终校验；结果契约仍不足时不能进入页面装配/保存 | 始终校验 |
| 超时、资源预算、分页/证据上限、服务端真实拒绝 | 始终生效，不吞掉 DQE 错误 | 始终生效 |
| 保存修订冲突、幂等、未知写入禁止重发 | 始终生效 | 始终生效 |

**配置与快速切换。** 公共组合根读取可信配置，通过现有公司配置能力或本地可原子更新的配置文件提供该布尔值。每次 `query_data` 批次开始读取并固定本批策略；更新后下一批请求生效，无需改代码或重新打包，正在执行的批次不改变行为。可提供 `METRICCANVAS_QUERY_VALIDATION_STRICT=false|true` 作为启动配置入口；环境变量只在启动读取的部署须明确需要重启，不能称作热切换。实现必须提供前述下一批生效的可信配置路径。配置缺省为 false；非法值显式报配置错误，不能悄悄切换模式。

**公共实现要求。**

1. 建立公共策略对象和明确的可降级规则清单，覆盖发现投影、查询派生及执行前检查。不要用 `except: continue` 或按错误码一概吞异常；可诊断的语义不足须保留中间结果，继续走确定性构造。
2. 拆开执行最低必需事实与可选治理信息，必要时调整内部投影模型，避免宽松模式尚未生效就被旧快照全量治理要求拦住。未知保持未知，不往现有 Schema 填假值过检；相关契约变更需明确迁移。
3. 同一查询走同一条确定性构造与 DQE 执行链，模式仅控制列入清单的预检是否阻断。不另建绕过公共工具的“直通查询”，不放宽 SQL/脚本执行面。
4. 两种模式均返回实际 `validationMode`、有限 `warnings`、已应用规范化与实际查询 scope。宽松放行表示已尝试执行，不表示语义已获治理背书；仍以真实返回的成功/失败状态报告。
5. 原请求、规范请求和策略版本留在受信任记录中，授权绑定实际规范查询，确保规范化没有增加指标、扩大地域或移除时间条件。开关不产生新的授权，也不免除已有确认流程。
6. 校验模式及规则版本进入查询去重/结果记录身份。严格失败切换为宽松后允许按新策略执行；宽松成功切换为严格后不能直接当作严格验证通过。读取历史 resultRef 保留原模式，重新作为严格流程证据时须重新校验。不能通过清空状态库实现切换，也不能因此重发未知保存。

**开关与已诊断问题的关系。** 开关不是 R01–R03 修复的替代：没有维度信息仍会使模型无法构造正确请求；时间类型识别错误仍须修复。“中国区”遗漏也不能靠宽松模式自动补齐或忽略，应按 R04 明确范围。宽松模式允许缺少预先能力证明的确定查询交给 DQE 验证，不负责发明业务事实。

**归属。** 公共代码拥有规则分类、规范化、执行策略、结果诊断与缓存隔离；适配方只接入可信配置和真实服务，不自行重写宽松路径。此项列入恢复查询闭环的首批整改，不延期为可选优化。

**验收。**

- 未设置配置时，真实组合根报告 relaxed，缺少可选能力证明的有效请求到达 DQE；显式 true 时，同一向量在预检阻断。
- 对矩阵中的每个可降级类别至少有一个实际调用点的对照，不允许只是最外层开关存在而深层仍无条件阻断。
- 运行中改为 true/false，下一批请求采用新策略；当前批次策略不变，无需打包或删状态。
- M→month 在两种模式都规范化；不增加范围、不丢“中国区”和时间条件；无法确定的名称仍给具体诊断。
- 模式切换不复用另一模式的失败或伪装严格成功；历史结果可追溯原策略。
- 两种模式下越权、错轮次、过期上下文、非法结构、超预算和未知保存重发均被拒绝；真实 DQE 拒绝不会被报告为成功。

## 4. 责任划分与禁止外推的内容

| MetricCanvas 页面协议与统一运行时 | 页面声明、受控计算、格式化、筛选绑定、页内动作和呈现 | 旧框架 API 兼容层、运行时临时生成业务查询 |
| 公司适配方 | 真实 URL/认证/信封映射、源协议差异、可信轮次与授权接线、CAS 存储、Java 读写和 Relay 交接 | 复制公共算法、补页面布局、猜时间粒度/业务域、重写 DQE 或默认授权 |

| 集成应用/集成门户 | 按装载对象承担端点与身份注入、应用路由、导航栈、登录恢复 | 为每个页面补计算、格式化和引擎缺失交互 |

公共输出需要暴露的是**足以构造合法查询的受控语义**。不应暴露的是物理 SQL、凭据、内部原始错误、旧框架脚本与公共实现细节；不能以“隐藏内部信息”为由连维度和时间粒度也隐藏。

## 6. 验证、分发与现场恢复

### 必要验证

- **确定性缺陷验证：** R01–R05/R08 的最小向量；启用实际 SemanticCatalog 分支；合法粒度和维度从发现结果获取；校验 DQE 是否真的被调用。
- **校验开关验证：** R12 的默认值、双模式对照、下一批生效、当前批次固定、深层检查可降级性与跨模式结果隔离；两种模式共用安全负向向量。
- **口径验证：** 中国区过滤、2026 上半年窗口、两个指标的组合与跨期总量；空结果、0 和失败必须区分。
- **状态验证：** 原样失败去重；更正请求需匹配授权；新上下文版本拒绝旧引用；创建/调整轮次分开，未知保存不重发。
- **分发验证：** 若修改契约真源，运行 `pnpm authoring:contracts`、`pnpm authoring:contracts:check` 和 `python3 metriccanvas-authoring/scripts/check_bundle.py`；不能手改生成快照或摘要锁。核对 wheel、Bundle、Skill 和实际 MCP 注册形状，记录最终提交与制品版本。
- **真实模型与内部服务：** 需要改 Skill 并复验 DS 时，按[六层验收约定](../agents/skill-ds-model-acceptance.md)分别报告。浏览器只用于适用的页面验收，不把本次纯查询逻辑整改扩成无关截图任务。

### 内部升级顺序

1. 保存版本与脱敏失败证据，不清除未知写入状态。
2. 采用公共修复与必要适配迁移，保留公司身份、真实端点和权限实现；确认 `queryValidation.strict` 缺省为 false，验证可信配置能在下一批请求切换模式。
3. 检查投影快照，确认规范域、维度、时间类型和允许粒度；快照校验通过不等于真实查询成功。
4. 新建可信创作轮次，重新发现并确认更正后的查询，使用该轮返回的数据上下文版本；不要仅改 dataSourceId 或直接复用原失败请求。
5. 查询真实 DQE，核对请求范围、返回行、总量与字段契约；随后按授权范围验证创建和调整页面。
6. 回传分层验收结果，逐项标记 pass/fail/blocked/not-run/out-of-scope。提交、推送、CI、真实模型与内部部署分别记录。

### 当前未完成项

本轮已实施公共对接缺陷修复；现场快照与部署版本仍未取得，真实 DQE/DS/Relay/Java 未执行。IOC 全量行为证据未补齐，新算子/Tab/浮层等扩展没有按未知业务事实实现。
