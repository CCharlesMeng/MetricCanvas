# 页面创作协作与呈现改进方案

日期：2026-09-17。状态：方向经用户确认，本轮仅落盘规划和实现计划，尚未实施本改进。

入口：[实现计划](tasks.md) · [验收用例](acceptance.md) · [首期方案](../../archive/scenario-guided-authoring-phase1/2026-09-17-scenario-guided-page-authoring.md) · [首期技术验证](../../archive/scenario-guided-authoring-phase1/verification.md)。本文是首期之后的修订，不把首期技术通过等同于业务组织和视觉验收通过。

## 1. 目标与事实基线

目标：模型表达业务意图，tool 优先完成确定性工作；页面先有清楚的业务章节，再有合理的章内组合，最终复用既有组件实现视觉层次。正常成功路径不增加必需的模型往返。

首期已有页面结构计划 v1、一源多组件、显式章节、局部编辑及受控查询。用户复核指出顶部拥挤、卡片缺少原示例层次、章节命名含糊及表达重复。核查发现：

| 事实 | 来源 | 本次处理 |
|---|---|---|
| 原示例按整体/Core/云通信组织卡片，卡内主值带同比/环比 | `pages/flow-analysis-report.json` | 参考业务对象组合，不复制样例数字或固定章节 |
| 新路径只装配 title/rows，没有展开 compactSummary 和 changes | `domain/page_structure.py`、`domain/page_building.py` | 增加受控指标组合与确定性呈现展开 |
| section-patterns 当前主要声明默认 span | `contracts/authored/section-patterns.json` | 补充组合的能力与呈现规则，仍允许 custom |
| 原测试提示已经指定概览、趋势、结构分析，并给出同名业务域 | `test-harness/model-evals/scenario-flow.case.json` | 保留旧证据，新增不预设章节的中性测试组 |
| “结构分析”实际上是稳定/一次性流水的趋势和同源明细 | 首期生成 JSON | 要求章节说明业务问题；检查信息重叠，不能靠名称判定分析成立 |
| 首期技术校验通过，但没有验证章节信息增量与主次质量 | `../verification.md` | 分别验收数据正确、业务组织、视觉质量与协作成本 |

本文代码路径以 `metriccanvas-authoring/` 为根，另有说明的除外。领域概念沿用 CONTEXT.md 的页面结构计划、章节组合、分区、页面数据源和候选。

## 2. 已确认的职责边界

| 环节 | 模型的判断 | tool 的确定性职责 |
|---|---|---|
| 发现能力 | 判断需了解的业务范围 | 有界枚举、分页、权限/快照、字段与可信关联信息 |
| 业务大纲 | 章节问题、业务对象、优先级、顺序及必要性 | 引用检查，规范化数据需求与引用，计算重叠事实 |
| 章内组合 | 主值/辅助值/趋势/明细的用途，决定是否保留相似内容 | 验证关联依据、单位/期间、唯一行选择、组件适用性 |
| 视觉装配 | 选择已支持的表达意图，必要时给语义宽度 | 样式变体、字段绑定、组合展开、栅格、标题去重、响应式及口径说明 |
| 修订 | 解决语义歧义、删减或保留内容并给用途 | 批量问题定位、复用合法数据、局部补丁与候选隔离 |

硬边界：

- tool 不按相似名称推断同比/环比归属。关联依据来自受信元数据，或用户明确关系；模型可提出显式关系，但不能把提议标成受信事实。缺证据时反馈歧义，不自动附加变化值。
- 金额和百分比不能不加区分地共轴；金额主值与有明确关联的同比/环比可以同卡展示，各自保留格式。
- 程序只认定“引用/数据重叠”，不能据此认定“业务内容无用”。同数据的趋势图与核对表可共存；模型负责说明区别或删减。
- 工具内的确定性检查不调用另一个模型。模型不接收原始数据行、完整 DQE、凭据或完整候选；需要数据分析事实另立范围。
- 不枚举整个系统所有数据再布局。先按需求发现相关业务域，有界返回覆盖范围与缺口，必要时继续分页。

## 3. 协作流程与轮次

正常路径保持一次能力发现批次、一次完整计划提交；具体发现调用数由范围和分页决定：

```text
用户目标 + 场景参考
  → 模型发现相关能力（独立请求可在同一响应中发起）
  → 模型一次提交完整页面结构计划
  → create_content_page 内部：
       全计划静态检查 → 查询执行/复用 → 字段与关系验证
       → 章节组合展开 → 布局/页面校验 → 候选与批量摘要
  → 模型说明结果；仅语义问题需要修订
```

“大纲 → 章内组合 → 装配”是信息依赖和模块职责，不是三个强制模型调用。首期五工具入口保持不变，不新增必须调用的预检、装配或验收工具。可提供内部纯预检函数用于测试，但不是模型前置调用步骤。

静态阶段收集当前可知的全部问题；未知取数结果相关问题在执行后集中汇报。不以“批量报错”名义承诺一次就发现尚未可知的问题。

返回摘要分三类（名称为提案，S0 冻结实际 Schema）：

- `appliedAdjustments`：仅登记规则内的确定性展开，例如选择 compactSummary、去掉同层重复标签。记录规则和对象，不改变业务含义。
- `issues`：引用错误、关联歧义或能力缺失，含 code、path、受影响稳定 ID、是否阻断以及可用修订选项。
- `overlapFindings`：可核对的相同查询/字段/选择范围，附相关内容块 ID；不自动删除或重排章节。

非阻断的重叠提示可以随成功候选返回，不制造额外往返。需要改变业务选择的阻断问题才触发模型修订；独立有效内容按已有 partial 机制保留。仅布局变更不查询；指标需求变更只执行受影响的查询。

## 4. 页面结构计划的演进

推荐新计划使用 `version="2"`；保留 v1 和旧 operations/compose_page 兼容路径，避免静默改变旧计划的含义。候选最终仍为既有页面协议，不新增渲染 DSL。v2 是待实现契约，本文不能当成已可调用接口。

### 4.1 大纲信息

每个章节增加创作期语义：它回答的业务问题、业务对象、与其他章的区别；每个内容块说明用途（主值、变化、趋势、分布、核对或说明）。自由文本有长度预算，闭集用途有实际 Schema。模型一次提交这些信息及具体内容，工具不要求另交一份长篇规划。

语义声明由模型承担，tool 检查存在性、引用完整性及可计算的重叠，不用规则伪装成语义理解。“结构分析”不是必需章节；标题应指向具体业务对象与问题。

### 4.2 指标组合

增加受控指标组合输入，明确业务对象的唯一行选择、主值引用、辅助变化值引用和关联证据。优先支持同一页面数据源的同一唯一行；跨源指标组合本期不自动配对。

程序展开为既有 metricCard 的 rows/changes/variant；`compactSummary` 作为报告对象概况的首批映射。首期不为覆盖所有既有变体扩大范围；`dualSummary` 等需有明确使用场景和验证后再纳入注册表。单值强调仍可使用适合的既有变体。

需要分开两个预算：一个取数单元的指标数量上限，及多卡复用结果的展示预算。保留现有上限，不为视觉组合无条件扩大查询。

### 4.3 章节组合与视觉规则

组合注册表成为能力/呈现规则的单一作者源，工具 Schema 与 Skill 枚举从它投影，避免多处复制。登记内容包括允许的语义角色、组件映射、默认宽度及可选覆盖；不是固定槽位或必须补齐的模板。

模型选择表达意图；程序选择注册的既有样式，复用渲染器的间距和响应式规则，不开放任意 CSS。若现有样式不足，作为明确能力缺口处理，不让模型猜 props。

### 4.4 局部修订与缓存

通过 edit_page 的候选路径支持稳定 ID 的受控结构修订，明确父候选及计划版本；新增的具体补丁 Schema 在 S0 冻结。禁止把“修订”实现为从零重跑 create_content_page。

每个查询需求用规范化字段计算签名；命中复用须同时满足身份、权限、快照、有效查询、字段契约和结果完整性。不能只凭 dataSourceId 相同复用。数据结果和签名留在程序通道，同轮候选间按已有可信存储承载，跨轮默认重新验证。

只修改指定组件/章节，保留人工标题、容器、布局与未知扩展。检查更新后的完整文档，源仍被引用时不得删除；移除/替换有明确冲突处理与原子性。

### 4.5 可见口径与说明

确定性口径来自结构化查询与源描述，程序集中生成并稳定更新。模型只补用户用途和确有依据的局限；同一系统口径不由模型再复制一份。程序可以合并相同的结构化说明，不能靠模糊文本相似度删除人工正文。差异口径必须就近可见，不能去重到页面不可辨认。

## 5. Skill 的变化

主流程保持短：选相关场景 → 发现必要能力 → 一次提交带业务大纲的完整计划 → 阅读批量摘要 → 必要时局部修订。

场景参考给出对象、问题和主辅关系的正反例，不给固定章节名单。例子突出“整体/Core/云通信等业务对象”与“金额主值/变化值”是不同层次；示例名和数字不进入正式查询。只有用到的场景参考被注入，并记录注入成本。

删除以逐组件设置样式为常态的指导；引导模型选择有实际 Schema 支持的组合。已有页编辑不按场景重新排版。禁止把例行 read_page_context 回读整个候选当成成功路径的必要步骤；需要补读时按投影和分页精确读取。

## 6. 验收与成本

验收分四层，任何一层的通过都不替代其他层：数据与协议正确性、业务组织质量、视觉质量、协作成本。详细用例见 acceptance.md。

正常成功路径不新增必须的模型工具往返；发现之后可一次提交完整计划成功。异常路径集中反馈并局部修订，不承诺所有模型每次只需固定轮数。

同时记录：模型请求数、工具调用数、数据查询次数、输入/输出 token、耗时、有效候选数、修订原因。分开记录确定性离线重放与真实模型证据。对照固定模型配置、能力目录、样例快照和相同中性需求；不再用预设章节的旧提示证明自主组织能力。

真实评测首轮至少经营与用量各 3 次；单次最多 6 次模型请求/12 次工具调用/35 万 token（测试上限，不是生产默认），到限保留失败证据而非另起轮次拼成成功。先通过离线用例，再进行付费真实评测。报告逐次结果和中位数，不凭少量样本声称统计显著或掩盖失败。

## 7. 范围与完成条件

本期包括 v2 协作契约、指标主辅组合、确定性装配、批量反馈、局部修订、Skill 引导及对照评测。不包括自动经营分析、自由公式、生产保存/发布集成或全组件变体覆盖。

完成须同时满足：契约兼容；业务判断边界没有被算法替代；正常路径没有新增必经往返；卡片有对象层次和既有视觉样式；重复内容得到正确处理；同口径复用/布局零查询；两类场景留下模型与视觉证据。纯技术通过不能再标注为整体页面质量通过。
