# 创作架构收敛实施计划

日期：2026-09-22。状态：本仓结构计划旧解析分支及参数候选链迁移已完成；C1 与 C4 本仓清理完成，C2 参数能力已接入现行工作稿。C0 外部事实验收、C3 Relay 接线、C5 真实联调与 C6 模型质量门禁仍需各自证据，不能将本仓清理视为跨仓规划全部完成。

依据：[ADR-0083](../adr/0083-platform-evidence-work-and-internal-draft-save.md)、[ADR-0080](../adr/0080-java-assets-single-attempt-save-and-status-publication.md)、[ADR-0064](../adr/0064-agent-returns-page-artifact-relay-and-java-own-persistence.md)、[Relay 集成调查报告](../../.codex/attachments/d6f7e4aa-5768-41cf-ad78-9bfa3e33dd38/已粘贴的文本.txt)以及[现有 Relay 架构影响说明](./2026-09-20-authoring-relay-impact.md)。调查报告是跨仓源码证据，未完成真实部署验收；涉及 Relay、Java 和前端的结论必须在接线阶段复核。

## 1. 收敛目标

生产只保留一条页面创作流程：模型负责理解业务问题、选择分析范围和页面表达；确定性程序负责数据发现、受控取数、页面装配、整页校验、工作稿竞争和单次草稿保存；Relay 负责可信上下文、步骤状态、产物交付和会话恢复；Java 页面资产服务负责权限裁决与持久化；前端负责审核、预览、人工修改和明确发布。

“没有多种版本混合”指生产入口、模型工作流和业务实现只有一套。页面 Schema 的兼容读取、外部 HTTP `/v1/` 路径、Bundle 版本和历史 ADR 不与结构计划版本混用，也不为了统一编号而删除已保存页面的读取能力。

### C0 事实冻结结果（Relay 集成调查）

调查报告确认生产入口是 **Skill → MCP stdio server → FastMCP tool**，不是模型可调用的通用 shell，也没有独立任务级 CLI。所谓“受控 CLI”在当前部署中只意味着由 Relay 受控启动 MCP stdio 子进程；模型只看到 Skill `allowed_tools` 与 MCP 工具 Schema。该结论取代“等待 Relay 是否支持受控 CLI”的待决项。

当前模型可见面保留数据发现、页面组装和只读读取；草稿保存、发布、删除、预览产物注入等副作用收进可信程序编排。MCP 注册、stdio 传输和工具隔离已有源码证据，但以下真实接线仍是上线阻塞：`agent_context` 没有注入 MCP 调用、内部请求使用共享环境凭据、HTTP 缺少分层超时与取消、保存请求缺少轮次关联、未知保存必须停止自动重发。远端幂等和操作查询未证实，按 ADR-0080 不作为本期强制新增前置。调查报告未运行代码，不能把这些源码结论升级为生产验收。

当前目标名称固定如下：

| 名称 | 含义 | 收敛规则 |
|---|---|---|
| 现行页面创作流程 | 平台新建、数据修改、样式修改及其保存/预览链 | 只保留一套；普通问数/探索仍是临时页面态的另一业务入口 |
| 页面结构计划 | 创作期的业务章节、内容顺序和数据引用输入 | 生产只接受现行版本；历史 v1/v2 仅作离线读取或迁移证据，不作为缺依赖回退 |
| 页面 Schema | 页面运行时协议 | 独立维护兼容读取与增量次版本，不能称为结构计划版本 |
| Bundle / 软件包版本 | 分发物版本 | 只用于发布与锁定依赖 |
| 外部 API 版本 | Relay、DQE、Java 的路径或契约版本 | 由服务方维护，不与页面结构计划编号对齐 |

## 2. 修改范围

### 2.1 MetricCanvas 本仓：必须修改

1. **统一创作内核与入口**
   - `metriccanvas-authoring/` 只保留统一 platform 内容入口、普通问数兼容入口和必要的协议兼容入口。
   - 平台新建与编辑共用发现、查询、证据、结构计划、页面校验和工作稿实现；不让 MCP 入站重复实现业务规则。
   - 将保存、预览准备、产物关联和状态分类集中到程序用例；模型不搬运完整 document，也不通过模型参数传递完整预览 JSON。

2. **退役旧页面创作流程**
   - 删除生产可路由的旧 `report-metadata-creator` 创作入口及其旧工具依赖；如仍有历史消费者，先改为显式迁移/只读归档入口，不能作为新流程回退。
   - 删除页面结构计划 v1 的生产解析、生成、默认分支和新建测试输入；历史样例与 ADR 迁入 `docs/archive/` 或迁移测试夹具，明确不可被生产路由。
   - 清理旧候选链、Relay 选候选提交和 Agent/Python 直接保存正式修订的文档与代码引用。保留页面 Schema 5.x/6.x 的读取兼容边界及外部 API 版本。

3. **版本与文档真源**
   - `ARCHITECTURE.md`、`README.md`、Skill、Bundle manifest、安装说明和部署示例统一使用“现行页面创作流程”“现行页面结构计划”等名称。
   - 删除“Agent/Python 不保存正式页面修订”这句笼统表述，改成：内容工具可提交平台草稿；Java 页面资产服务负责持久化和权限裁决；发布仍由用户明确触发；Relay 保存会话检查点；普通问数不自动落库。
   - 对 `v1/v2/v3` 每处标注所属版本序列。不得把 `formatVersion`、页面 Schema、Bundle 或 HTTP API 版本写成结构计划版本。
   - 新增或修订 ADR 主题页，记录生产硬切换、旧入口退役、工作稿与草稿保存、Relay 产物交付和版本术语；历史 ADR 原文保留并标明被后续决策替代。

4. **确定性执行边界**
   - `discover_data_context`、受控 `query_data`、页面装配/编辑和只读页面上下文可以作为模型可见的任务级能力；底层 DQE、Java、数据上下文、预览缓存和保存适配器由程序内部调用。
   - 草稿保存、发布、删除、预览产物注入和完整页面交付不作为模型自由组合的低级 MCP 工具。若 Relay 需要 CLI，CLI 只委托同一业务用例，不复制实现。
   - 写操作使用冻结的 document、基线修订和操作上下文；成功、冲突、失败、结果未知、预览失败分开返回。未知写入不自动重发。

5. **测试与分发**
   - 更新契约导出、Bundle lock、安装入口和测试分类；删除的旧入口必须有“不可路由”测试，而不是只删除文件。
   - 增加有意义的跨边界测试：产物与预览作用域、partial 保存、并发基线、未知保存、迟到结果、计划确认不发布、普通问数不落库。
   - 模型评测固定新建报告、新建看板、局部数据修改、整体重组、样式修改、页面参数提取/填值、失败恢复七类任务，并记录工具次数、重复查询、总耗时、上下文量、保存状态和页面呈现结果。

### 2.2 Relay 仓：必须修改

1. 用 Relay 已注册的 MCP stdio server 调用统一创作能力；MCP 子进程由 Relay 受控启动，模型不可调用通用 shell，不可提供身份、端点、路径或认证头。若未来提供 CLI，它只能委托同一用例，不能形成第二条生产流程。
2. 在每个工具调用边界注入经过宿主验证的当前用户、应用/工作区、页面目标、创作轮次和基线引用；不得回退到跨用户共享的环境变量服务账号并宣称按用户执行。
3. 为页面产物建立明确作用域：完整 document/previewJson 由程序持有并交给前端，模型只接收业务所需证据、modelSummary、状态和引用；现有 `{{RESPONSE_START}}` 与 `{{PAGE_METADATA_PREVIEW_JSON}}` 协议在替换前后均须绑定本轮、页面和保存回执。
4. 将子进程退出、HTTP 超时、取消和 Agent 级重跑分开处理。写操作关闭自动重试；保存结果未知时停止重发并向前端报告未知状态。
5. 固定 CLI/MCP 运行时、依赖、工作目录、stdout/stderr、退出码、超时和取消协议，补充步骤事件与最终事件的关联字段。不能把“源码配置启用”写成“生产已验收”。
6. 清理重复或死的 mode/plugin 定义，并撤下已退役 Skill 的生产路由。旧能力如需保留，必须标记为兼容/只读且不能作为新流程 fallback。

### 2.3 Java、数据服务、前端：需要对账，不由本仓臆造

- Java：确认保存草稿、基线修订比较、资源归属过滤、发布状态转换和响应字段；本期不把未证实的服务端幂等、操作查询或不可变修订扩成强制新增功能，但必须明确能力缺口及未知保存的处理边界。
- 数据服务：确认 Data Context、DQE 请求/响应、权限和结果截断；查询执行必须保持数据网关边界。
- 前端：确认工作台如何消费匹配的预览产物、处理保存成功/失败/未知、拒绝过期结果，以及人工修改和模型执行的竞争。

## 3. 不在本期范围

- 不统一页面 Schema、结构计划、Bundle 和外部 API 的编号。
- 不删除已保存页面的 Schema 兼容读取，不把历史 ADR 改写成当前事实。
- 不把普通问数/探索改成资产保存，不把渲染期筛选排序翻页送回 Agent。
- 不因为调查报告未发现 Java 操作查询端点就虚构端点；是否新增由 Java 团队和真实契约另行裁决。
- 不通过增加提示词来替代身份注入、超时取消、保存状态或产物隔离。

## 4. 实施阶段与门槛

| 阶段 | 交付 | 完成门槛 |
|---|---|---|
| C0 事实冻结 | Relay MCP stdio 入口、身份、Java 保存、前端预览四组契约 | MCP 入口与模型可见面已有源码证据；身份注入、Java 幂等/结果查询、前端消费和真实运行仍明确列为外部验收缺口 |
| C1 版本收敛 | 版本词汇表、现行入口清单、退役清单、ADR/主题页更新 | `rg` 不再发现生产文档把结构计划与 Schema/Bundle/API 混称；旧入口有路由拒绝或归档证据 |
| C2 内核收敛 | 单份工作稿、共享查询/装配/编辑/保存用例、统一状态和产物引用 | 新建/编辑不复制业务规则；document、previewJson、保存回执作用域一致 |
| C3 Relay 接线 | 可信上下文、受控 CLI/MCP 适配、超时取消、未知写入和占位符交付 | 隔离环境实际调用通过；无共享服务账号越权；迟到和重复结果不覆盖新状态 |
| C4 旧入口退役 | 本仓已删除旧平台入口、结构计划 1/2、候选链与旧 Skill；Relay 侧路由待接线 | 契约、Bundle、单元和入口检查；本次遵照用户要求不做浏览器测试 |
| C5 真实联调 | Java/DQE/Relay/前端端到端 | 新建、修改、样式、partial、未知、冲突、预览失败和明确发布均有实测证据 |
| C6 模型质量门禁 | 七类任务的固定评测与呈现检查 | 口径、查询、布局、修改保真、调用效率和保存状态均达到发布阈值；阈值在评测报告中固定 |

任何阶段失败都不能通过启用旧入口作为静默 fallback；应返回明确不可用或保留工作稿，等待修复。

## 5. 第一批具体修改清单

MetricCanvas 首批只做以下可审查改动：

1. 更新 `metriccanvas-authoring/ARCHITECTURE.md` 和 `README.md` 的现行职责、版本术语、草稿/发布/会话边界。
2. 新增一页 ADR 或现行主题页条目，明确本计划的硬切换与退役范围；生成 ADR 索引并通过检查。
3. 建立 v1/v2/v3、Schema、Bundle、HTTP API 的引用盘点表，逐项标注保留、迁移或删除，不先批量删代码。
4. 确认 `report-metadata-creator`、旧 candidateRef、`build_page` 保存包装及旧 MCP 注册的真实消费者，形成删除顺序。
5. 为 Relay 适配器写出最小输入/输出契约草案，保留现有预览占位符；不把未核实字段写成已实现。

首批文档工作及本仓代码删除已完成。参数能力已迁移为九工具平台入口的一部分，模板准备不自动保存，实例不执行查询或落库；后续跨仓接线与模型质量验收独立记录。
