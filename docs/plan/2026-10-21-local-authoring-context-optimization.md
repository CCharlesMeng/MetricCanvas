# local-authoring 输入上下文优化实施方案

状态：本仓实现已完成，本地验收见第10节；独立前向试用完成，完整重复模型对比及真实业务查询验真未执行。日期：2026-10-21。

目标：使 `metriccanvas-local-authoring` 按实际任务读取知识，降低模型输入与查阅轮次，同时保持页面协议、业务口径、布局确认和独立安装的现行保证。本文件是本批唯一实施入口。

补充目标：支持以已有页面 JSON 和指标/指标表说明 MD 为输入，快速列出页面元素对应的指标候选、取数条件和缺失信息。材料分析与真实查询验真分开，具体见第 9 节。

与[范式规划](2026-10-19-local-authoring-patterns.md)及其他设计知识/确定性选型工作独立：本批优化知识如何被读取，不实施组件选型求解器，不重定页面范式。

## 2. 方案取舍

采用“任务分流 + 确定性知识读取”两步实施。第一步独立产生收益，第二步解决大模块整份读取的问题。

保留现有完整参考、Schema、示例和独立校验器作为深查与最终验证依据。新增的精确读取入口从相同真源生成内容；作者只维护主题归属与触发条件，不再编写一份精简版协议语义。

本期不增加在线服务、MCP、向量检索、运行时依赖或模型生成的知识摘要；不依赖缓存命中实现节省，也不改变页面 Schema 或业务行为。

## 3. 第一步：按任务限制读取范围

入口先根据本次修改对象和影响选择下列路径。任务类型可组合，出现新的依赖时扩展相关路径。

| 路径 | 触发条件 | 首次读取 | 扩展条件 |
|---|---|---|---|
| 局部呈现修改 | 标题、显示格式、列宽、已存在组件的呈现属性 | 原页面相关对象、对应属性知识 | 涉及字段引用、数据槽、查询或筛选行为时补读依赖主题 |
| 数据或交互修改 | 新增/修改页面数据源、结果字段契约、计算、筛选、导航 | 本次相关声明与相应主题 | 跨源、跨页及完整结果能力按依赖扩展 |
| 新建或整页重组 | 新页面、重组业务章节、切换布局形态 | 形态确认、一个候选范式、基础页面与涉及组件 | 仅加载实际采用的能力与示例 |
| 校验修复 | 已有 type/path/message | 原始错误、最上游声明、相关模块主题 | 错误涉及跨引用时补读两端声明 |

执行规则：

1. 已有页面局部修改沿用布局；新建/整页重组仍按现行规则确认形态。用户已经有效确认时不重复询问。
2. 首次查看页面以定位结构和受影响对象为目的。大页面中的数据行不整份打印给模型；用脚本检查必要的类型、引用和样本，原始文件保持完整。业务核对确需更多数据时按需读取。
3. 仅当修改数据声明或需要核对已有绑定时，才读取数据源、字段、查询主题。样式修改保持查询和结果字段契约原样。
4. 范式只读一个候选结构摘要；需要比较另一范式时再读。复杂组件知识与完整页面示例按实际采用的变体加载。
5. 版本由 `node "<skill-dir>/scripts/validate-page.mjs" --version` 获取；完整清单仅由维护和一致性检查消费。
6. 保留完整生成后的尝试快照、产品校验、涉及行为的预览和分层交付。错误修复不通过删除合法配置或放宽校验换取通过。
7. 当原页已不合法时保留原始诊断，说明其与本次改动的关系；未通过的页面不宣称完成验收。

删除 `local-workflow.md` 中无条件连读要求。范式卡、短写法和协议索引中所有指针同步表达触发条件，防止从入口收紧后又沿链接扩大读取。

## 4. 第二步：新增一个确定性知识读取入口

以下路径与命令已实施，支持 --help；精确子节点可追加 --pointer。

### 4.1 使用方式

```sh
# 首次精确检索；只列出匹配主题及一句适用范围
node "<skill-dir>/scripts/read-knowledge.mjs" list --module table

# 已知主题时直接读取；多主题在一个调用内合并、去重
node "<skill-dir>/scripts/read-knowledge.mjs" show --topic table.columns --topic fields.format

# 新页面的基本约束；只在相应任务需要时读取
node "<skill-dir>/scripts/read-knowledge.mjs" show --topic page.core --topic data.inline
```

主题 id 已对照实施基线 Schema 冻结；示例命令可执行。首批涵盖：page/core、分区布局、inline/query、字段与格式、表格列/搜索/分页/导出、指标卡、文本、筛选/时间绑定、报告导出。其余能力仍可读取完整参考，本批交付前须给所有现有模块建立可发现的深查入口。

`list` 只列出主题 id、范围和依赖摘要；`show` 返回：

- 当前知识版本、主题范围与内容摘要哈希。
- 相关语义原文、适用条件、能力限制。
- 精选 Schema 节点的紧凑结构、必填性、类型、枚举、约束和字段说明。
- 必须一起读取的语义依赖，以及本次尚未展开的结构引用。
- 最相关完整示例和完整参考的安装目录内路径，默认不输出示例全文。

查不到主题时返回非零退出码与小范围候选，明确进入深查；不返回“空内容即没有约束”。有效输出用 stdout，诊断用 stderr；0 表示成功，1 表示主题或参数错误，2 表示知识损坏/版本不一致。仅接受封闭模块/主题 id，不接受文件路径、表达式或可执行代码。

### 4.2 真源与生成方式

| 内容 | 真源 | 生成/消费方式 |
|---|---|---|
| 字段结构与分支 | 产品 Schema | 复用 `referenceNodes` 等遍历结果，紧凑序列化 |
| 字段与枚举解释 | `docs/page-metadata/reference-map.json`、Schema description | 原值投影，不由模型重写 |
| 业务语义与限制 | `docs/page-metadata/*.md` 及组件模块 | 按显式语义章节选择器 提取原文 |
| 主题归属 | `reference-map.json` 新增可选 `authoringTopics` | 仅声明模块、Schema roots、语义块、规则、示例、必要依赖 |
| 语义规则与反例 | 既有契约规则和反例 | 输出选定规则说明与局部参考路径 |
| 工作流与读法 | Skill 入口及作者维护的流程文档 | 与现有维护归属一致 |

实施采用现有 H2 语义章节及 reference-map 中的显式登记/选择器，减少对并行协议正文的侵入。authoringSemanticHeadings 锁定章节次序，新增/重命名章节未登记时生成失败，要求复核公共限制和专题归属。结构直接复用 Schema 节点；语义提取原文，不从长 Markdown 逆向解析结构。

全模块语义须有归属：开篇公共说明是 overview，每个已登记章节自动成为可发现主题，常用主题另以精确选择器组合所需章节；原文没有被摘要或删除。新增/更名章节须同步登记并复核主题作用范围；现有章节内的补充继承原归属。跨模块依赖逐项声明，不建立包含全部知识的全局 common。

主题记录内仅保存选择器和依赖，不复制语义句子；示例仍指向既有合法夹具。完整参考的正文、链接及原有分支覆盖保持可用。

### 4.3 结构选择与大小约束

- 选定节点同时返回判定其有效性所需的父级结构与分支条件；保持 `oneOf/anyOf/allOf` 的身份，不把不同分支的 required 合并。
- 展开本主题约定范围的结构；可复用类型以稳定 id 引用。列明未展开引用及其主题/完整参考，不能把局部输出伪装成完整 Schema。
- 主题依赖自动闭包、去重；有环、缺失语义块或无归属 Schema 节点在构建时失败。
- 不以截断字符串满足大小指标。过大的主题在构建检查中要求按操作拆分，必要语义和依赖完整保留。
- 运行时读取本地机器知识包，模型只接收查询结果。机器文件可以大，不把其体积等同于上下文消耗。
- Node 不可用或读取脚本失败时走完整参考，说明精确读取/自动校验的实际状态；不为节省 token 猜测协议。

### 4.4 分发闭合

新增生成产物建议为 `references/authoring-knowledge/` 和 `scripts/read-knowledge.mjs`。前者包含机器索引与主题包，后者仅依赖 Node.js 22+ 内置模块。

接入 `export-authoring-contracts.ts` 的 local 投影分支、生成文件排除列表、子树清理、漂移检查和 `localKnowledgeManifest`。清单应包含新脚本和机器知识包，清单自身不递归计入自身哈希；脚本校验版本和请求数据的摘要，避免混装。

特别处理“重新生成时删除已退役主题”和“作者流程文档保留”两个方向；不能只增加写出步骤。仅 local 投影发生变化，其他 Skill 无须改读取行为。

## 6. 效果衡量与通过标准

### 6.1 统计口径

每次运行分别记录：

1. 知识读取总量：所有返回给模型的 Skill/知识内容累计量，重复读取也计入；同时记录去重后的量。
2. 任务材料量：需求、设计、原始页面、数据样本；与 Skill 知识分开。
3. 模型请求数、工具调用数、重复读取、校验修复轮数及耗时。
4. 若运行面可提供 usage，逐请求记录 input、cached input、output，以及可用的 reasoning 细分，最后求和。界面口径缺失时记 unavailable，不从最终回复长度反推 output。
5. 静态统计始终提供 UTF-8 bytes；token 统计固定实际编码器及版本。无法确定目标编码器时不以字符/字节数冒充实际模型 token。

累计 input 包含反复携带的上下文，不能拿去重文件大小与其直接相减。费用只在取得对应模型、计费方式和 usage 时计算；本批不改缓存设置。

### 6.2 对比任务

至少覆盖 12 个任务：标题修改、列宽修改、金额/百分比显示、已有列绑定修复、未知属性修复、inline 看板新建、已有确认的 Report 新建、未确认形态的新建、表格搜索、期间筛选绑定、报告导出、pagedJoin 排序/分页。

每个任务冻结需求、页面/数据输入、业务期望、模型配置和初始环境。基线与优化版分开全新会话运行，双方获得同等项目级指令，不共享答案或上轮修复结果。未确认形态的任务以正确停在识别摘要为成功，不以 JSON 产出量评分。

复杂任务的期望包括业务语义与操作结果，例如保持查询不变、百分比刻度正确、筛选绑定生效、完整结果范围不误判；最终 JSON 的等字节匹配不作为正确性标准。

实际 Coding Agent 对比每任务每版至少 3 次，报告中位数、范围与失败样本；小样本只描述观察结果，不声称统计显著。运行通道不可用时完成确定性和静态检查，行为/token 优化效果保留未验收。默认不追加真实 DS 模型、真实 DQE/Relay 验收。

### 6.3 预算与质量门槛

以下为拟定验收门槛，P0 冻结后实施中不得为过关放宽；确有必要时记录原因并重新评审。

| 项目 | 通过标准 |
|---|---|
| Skill 入口 | ≤ 6 KiB UTF-8；必要保证不因字数删除 |
| 查询输出 | `list --module` ≤ 4 KiB；单个常用主题含必要依赖 ≤ 16 KiB，复杂主题显式拆分 |
| 三类呈现小改 | 相对同任务基线，Skill 知识累计读取量中位数至少降低 60% |
| 整页/复杂任务 | 全部复杂任务合计的知识读取量中位数至少降低 30%；逐任务列出例外 |
| 轮次与总 input | 单独列数值；每任务工具调用中位数增加超过 2 次或总 input 变差时必须解释并优化后复测 |
| 质量 | 确定性契约向量保持一致；所有任务业务期望通过，首次生成校验成功率不低于基线；布局确认等流程无新增违例 |
| 分发 | 仓外复制可运行、链接闭合、主题完整、哈希一致、退役文件清理通过 |

绝对输出预算约束的是知识查询结果，复杂页面的业务数据和最终 JSON 不受此限。节省比例约束的是实测知识读取；不能据此承诺总 input 或账单同幅下降。

## 7. 验收命令与页面场景

实施后先运行与本批相关的检查，生成命令会更新产物，应在独立检出中执行：

```sh
pnpm authoring:contracts

python3 metriccanvas-authoring/scripts/check_bundle.py

pnpm exec tsc --noEmit -p tests/tsconfig.json
```

依照当前仓库 Skill 验收范围，不运行历史 authoring Bundle 行为测试或真实 DS 专项。

若新增知识读取专用测试，将其加入定向命令。`authoring:test` 是维护流程已有检查，不以此扩展其他 Skill 的专项行为复验或真实模型调用。

按[功能与协议能力验收要求](../agents/feature-acceptance.md)落实：用优化后的入口生成 `pages/capabilities/layout/local-authoring-knowledge-demo.json`，显式 dashboard、inline 演示数据，复用现有组件；注册 Playground 并写入 `pages/README.md`。页面覆盖标题、列宽、金额/比率格式等可观察结果，不展示内部 token 统计。

查询、时间绑定、报告导出和组合源任务复用相应现有可观察示例及其已有数据环境。验证浏览器实际行为；只有 Sim 的证据不能写为真实 DQE。`PAGE-METADATA.md` 及对应模块仅更新精确知识查阅入口/示例路由，不制造新的协议语义。新知识工具的操作说明归 Skill 维护文档。

不新增视觉方案。如执行中发现组件实际样式与明确需求冲突，按仓库协议先展示差异并等待针对该呈现的审核，其他优化工作继续。

## 8. 风险、回退与最终交付

| 风险 | 处理 |
|---|---|
| 精确知识漏掉跨模块限制 | 显式语义依赖、common 块、未归类语义失败、跨主题行为用例 |
| 小改动被误判为纯呈现 | 以实际受影响字段和引用扩展任务范围，最终仍执行完整校验 |
| 主题过细导致工具轮数增加 | 已知 id 直接 show，多主题批量去重；用实际调用数识别是否需要合并 |
| 两套文档语义漂移 | 主题只保存选择器，输出提取原文；结构和说明复用同一真源 |
| 摘要隐藏 Schema 分支 | 原样保留联合分支/祖先条件；用复杂合法与非法向量回归 |
| 知识包新旧混装 | 版本、内容哈希和仓外安装检查；不一致明确失败并整体升级 |
| 少读资料但修复更多 | 同时评估首次通过率、修复轮次、总 input 和业务质量 |

回退以完整 Skill 版本为单位，不混装旧脚本和新知识包。独立读取脚本不可用时可深查完整参考；静态校验器的失败仍必须修复或明确保留未验收。

最终交付包含：优化后的完整 Skill、维护及查阅说明、可观察页面与浏览器证据、同条件对比报告、失败样本、生成/独立安装检查结果。分别报告“确定性检查通过”“实际 Agent 效果”“真实模型/服务未运行”等证据层级。

## 9. 补充：页面 JSON + 指标说明 MD 的数据识别流程

### 9.1 现状与本次目标

现有 local-authoring 能消费页面、结果字段契约、已验证查询和用户数据说明，形成页面数据源并进行结构校验；分发脚本目前只有快照与校验能力，没有自动扫描页面用数需求、索引任意 MD 和匹配指标的专门入口。线上数据发现、NL2DQE 与执行工具不能据此视为本地 Skill 已内置能力。

本次增加“先分析，后接数”任务路径。用户可以只提供两份原始材料，无须预先转换完整 Schema 元数据。输入不全时仍输出逐项匹配与缺口，只有满足执行与结果证据的部分进入页面数据源写回。

### 9.2 输入分层

| 输入 | 用途 | 缺少时的处理 |
|---|---|---|
| 页面 JSON | 读取组件、数据槽、字段引用、分组、筛选、参数、排序/分页与已有查询 | 这是本路径的必要输入；解析异常先报告位置 |
| 指标/指标表 MD | 指标业务名/别名/口径、对象与字段、单位/币种、时间/维度/关系和查询约束 | 这是本路径的必要输入；内容可不齐，逐项记录 unknown |
| 本次范围说明 | 指明要补哪些区域、保留哪些已有源和默认时间/组织范围 | 缺省先分析全页，保持原文件不变；不猜默认业务条件 |
| 查询协议及已验证查询 | 把业务取数条件变成合法查询候选 | 物理表结构不能替代 DQE 的指标/维度标识；缺少映射时列为执行阻塞 |
| 查询执行入口与响应 | 验证字段、粒度、条件与完整性，形成查询定义和结果字段契约 | 无执行环境仍交付分析/候选；明确未验证，不伪造响应 |

“指标表”仅作为用户原始文档称谓，不推定其等同于页面数据源。MD 中的业务指标、物理表字段与可查询的 DQE 标识分别保留来源。已有 Schema 元数据可直接消费；从 MD 提取的局部事实不伪装为已完成授权裁剪的正式数据上下文快照。

### 9.3 处理步骤与分工

1. **提取页面用数位置。** 确定性解析 JSON，递归覆盖 Tab、组合卡、详情视图等嵌套结构，以及非 main 数据槽、文本取值、条件和相关数据引用。输出组件 id、精确 JSON Pointer、显示名、现有数据源/字段、期望结果形状和上下游引用。静态标题/装饰独立标记；不把每段文字都视为指标。通过组件契约定位数据引用，未知组件输出诊断，不能静默漏掉。
2. **索引用户文档。** 脚本建立标题层次、表格/段落范围、原始行号和内容哈希。模型按文档实际格式提取候选指标条目与表字段事实，并保留证据片段；任意 MD 的语义提取由模型完成，不宣称用正则即可理解。模型产物需结构校验，并检查所有来源范围确实存在。一次分析可复用相同内容哈希的索引；事实结论同时绑定提取规则/模型版本，变更时失效。
3. **按页面需求检索并判断匹配。** 用现有字段映射、指标 id、业务名和别名生成候选，再核对业务口径、单位、粒度、可用维度、时间聚合与结果形状。名称命中只算候选；同名不同口径列出差异，部分匹配列出缺少的维度或适用范围。纯名称或模糊相似度不能自动确认为正确指标。
4. **整理取数单元和缺口。** 输出指标、分组维度、时间窗口/粒度、固定条件、动态筛选/参数、排序/分页、结果范围和跨源关系；每个条件区分页面明确声明、MD 依据、建议、unknown。同一需求被多个组件消费时只询问一次；同指标但粒度/条件不同的需求分别保留。资料冲突展示两端证据，不自动采用某一方。缺可加性时不折叠已有结果，缺连接键/关系基数时不直接连接物理表。
5. **形成查询候选。** 已有可信 DQE 映射和足够条件时形成协议合法的候选；仅有业务/物理表说明时先给业务取数条件和协议映射缺口。不将指标表名直接填进 DQE，不自行换成 SQL。建议时间、状态、去重、比率分母或排名规则须在报告中可见，不因“快速生成”默认为事实。
6. **按可用环境验真并写回。** 查询真实执行后核对响应字段、类型、单位、行粒度、空值和完整性，再形成/更新页面数据源、结果字段契约及 `queryField` 映射，保留组件稳定引用。只有条件完全一致的真实结果才能成为 initial。按原流程快照、静态校验和浏览器验收。无环境时停留在报告与候选文件，不把未验证替换写入正式目标页。

查询合并是独立判断：只有指标、维度、时间、条件、执行能力和结果范围兼容时才考虑共享。查询定义复用、查询分页表独占以及 pagedJoin 的既有限制继续适用，不能为减少查询数改变业务口径。

### 9.4 第一阶段交付物

默认先形成创作期的 `page-data-analysis.json` 及便于人审阅的 `.md`；协议候选充分时再形成 `query-candidates.json`。这些是工作目录内的分析产物，不是新增页面协议字段，也不进入 Skill 的分发知识包。

每条记录至少包含：

- 页面元素 id/JSON Pointer、可见标题、数据槽与原字段。
- 指标候选、匹配结论、支持证据、口径差异；无依据时标为未知。
- 来源 MD 路径、章节、行号/片段及内容哈希。
- 取数条件、绑定来源、期望行形状与完整性需求。
- 缺口、影响哪些元素、最小补充问题，以及它阻塞“匹配/形成候选/执行/写回”中的哪一步。
- 独立的匹配状态（有据匹配/多候选/未找到/冲突）与执行状态（未生成/候选/未执行/执行失败/已验证）。匹配成功不等于查询已验证。

报告先汇总已覆盖、待确认、缺资料的用数位置，再列影响面最大的共性缺口。数量只衡量覆盖情况，不能替代具体匹配证据；不要给未经校准的“95% 置信度”。

### 9.5 结合 token 优化的执行原则

先用脚本从页面提取用数位置和从 MD 建立块索引，再让模型读取命中片段与必要上下文。候选不足时逐步扩大范围，并记录尚未检索的部分；检索未命中不能直接宣称整份文档没有指标。

对格式不规则或缺别名的文档，首次语义抽取可能需要分批覆盖全文，这笔成本必须计入统计。缓存只复用绑定原文哈希的中间产物；不能把第一次建索引消耗隐藏，报告冷启动和同文档复用两种结果。

本路径只加载数据源/字段/查询与所涉交互知识；保持原布局时不再读取整页范式或视觉组件全册。查询分析不要求先生成页面 JSON，从而避免为了发现缺口反复生成和修复整页。

### 9.6 增量实施与验收

| 批次 | 交付 | 验收 |
|---|---|---|
| D0 | 冻结页面+MD输入与独立标注；对照真实样本文档定主题和输出结构 | 名称、口径、证据位置与关键缺口可独立核验 |

在原 12 个任务之外新增至少 6 类：明确同名匹配、别名匹配、同名不同口径、仅有物理字段而无 DQE 映射、缺时间/过滤编码、跨表粒度或连接键不明。夹具包含嵌套组件和同指标多组件引用，检验报告覆盖与缺口去重。

质量门槛：所有需数据位置被解释或明确诊断；每个确定匹配均有可定位来源；预设关键缺口全部报告；无依据的字段/条件不得标为确定。候选有静态校验不等于执行通过。该路径另报冷启动、复用时的知识/材料读取量和轮次，不套用仅呈现修改的 60% 节省承诺。
