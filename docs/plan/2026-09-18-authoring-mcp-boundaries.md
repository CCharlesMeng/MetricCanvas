## 9 个工具的外部依赖与内部职责

| 工具 | 外部服务对接 | 内部职责 / 调整归属 |
|---|---|---|
| discover_data_context | Java 语义分词、指标和维度能力；具体采用既有 MCP 还是公共接口由 Adapter 接入 | 结果归一化、业务域、支持范围、消歧和数据上下文投影 |
| compose_page | 数据上下文提供方、DQE 执行；源描述是否单独远程获取取决于接入实现 | 当前包含查询派生、验真、映射、组件构造、章节布局和页面校验；最终职责范围待 grilling |
| save_page_metadata | Java 页面资产创建 | 候选与提交条件校验、命令构造、回执核对 |
| update_page_metadata | Java 页面资产更新 | 候选与修订基线校验、冲突和回执处理 |
| get_page_metadata | Java 页面资产详情 | 引用、文档和结果映射 |
| list_page_metadata | Java 页面资产列表 | 分页、筛选和列表结果映射 |
| delete_page_metadata | Java 页面资产删除 | 目标与执行条件校验、结果映射 |
| execute_page_metadata | Java 页面执行 | 传递资源标识及参数、归一化执行结果；与创作组装分开 |
| page_metadata_emit_preview | 无外部服务请求；向工作台输出事件 | 从指定候选取得 previewJson，组装交付事件，不取数、不重新查页面、不保存 |

按工具的功能链路分类为 8 个涉及外部服务、1 个本地交付工具；不表示每次调用都必然发生远程请求，也不表示必须新建 8 个远程端点。

外部访问集中在我们维护的 Adapter：参数转换、协议解码、鉴权传递、超时和外部错误映射。应用用例通过端口调用；查询派生、构造、布局、编辑、校验和纯状态迁移留在内部模块。内部模块不必逐一暴露为模型工具。

## 已认可的调整方向

1. 保留我们的现有 MCP 名称与协议兼容入口，内部调用共同应用用例。核心可作为 Python 包嵌入内部工程，独立 MCP Server 保留为部署选项。避免创建另一个 MCP Server 再调用工具来复用本方逻辑。
2. 按变化原因划分数据能力发现、取数验真、页面创作、创作轮次与候选、页面资产、页面执行与交付六类职责。这是模块职责草图，不机械拆成六个服务或六个限界上下文。
3. 其他人的能力经我们的 Adapter 复用。协议变化集中修改对应 Adapter；归因算法、模板、HTML、订阅、水印等原实现本轮保持。仅在我们需要消费结果时增加必要适配。
4. 查询准备、执行与证据在我们的调用链内收敛。我们管理自己发起的调用，尊重对方现有限额；没有对方支持，不承诺跨工具全局预算、内部查询计数或取消能力。不得为了绕过限制而换用下层接口。
5. 来源保持能力差异：可重复执行的查询与一次性结果分别表达；列式结果、格式化字符串、单位刻度必须有明确映射。NL2SQL 的查询说明不自动等于可刷新查询定义。
6. 逐步消除整页生成后拆取数据/组件、组件能力名单散落、两套操作执行器、业务状态迁移落在 SQLite 等耦合。具体公共接口在 grilling 后确定。
7. 我们的 Skill 负责业务判断、目标选择与结构计划；确定性核心负责可信绑定、派生、验真、构造和校验。模型是否需要在阶段间作出新决策，是工具面是否拆分的重要判据，尚未裁决 compose_page 的最终工具面。

## 真源与派生关系

| 事实 / 规则 | 权威作者 |
|---|---|
| 指标定义、维度支持、权限事实 | 外部提供方，我们保留来源与版本 |
| 页面结构与合法性 | 产品页面契约，导出结构与共同语义向量 |
| 组件构造、编辑权限与布局需求 | 本方组件能力模块；产品事实引用产品契约 |
| 操作依赖、回滚与部分成功 | 公共操作执行器 |
| 创作基线、候选内容与身份 | 可信轮次及候选模块 |
| 执行记录不变量与合法迁移 | 执行记录领域模块 |
| 原子 claim/CAS 与持久化 | 存储 Adapter |
| 持久化资源、修订和保存结果 | Java 页面资产服务 |

系统注入 compose_page_result 的机制可保留，但要明确绑定轮次和候选，避免笼统消费“最近一次结果”。document、previewData、previewJson 可以共存，须具有共同候选身份与明确派生关系，不能独立修改成为多个真源。previewJson 已携带完整预览时，工作台直接应用，避免再按 pageId 读取不同内容。

保存沿 ADR-0080 的单次提交、可信回执确认；未知写入不自动重发。现有接口未证明的强幂等、历史精确读取或跨窗口保证不自行补成产品承诺。

### 2026-09-20 已确认的目标工具面与运行方向

用户认可以下设计方向并要求继续 grilling。以下是目标职责，不宣称当前实现或内部生产接入已完成；取代此前关于是否合并新建入口、是否允许结果驱动补查的未决项。

| 目标工具 | 职责 |
|---|---|
| read_page_context | 读取当前页面或候选的有界结构、配置和可复用数据引用 |
| discover_data_context | 发现能力、候选与歧义，不执行业务查询；不作为每次取数的强制前置 |
| query_data（暂名） | 独立取数，内部复用当前 Lab 寻源、查询生成、DQE 执行及结果整理；不是另一个自主规划 Agent |
| compose_page（合并入口暂名） | 合并原 compose_page 与 create_content_page 的新建职责，消费页面结构计划与已取得的数据引用，完成装配、校验和候选生成 |
| edit_page | 修改已有页或同轮候选，复用共同构造、布局和校验能力；新增取数由取数工具承担 |

旧协议可保留兼容入口，同一个目标 Skill 不同时暴露两个职责相同的新建工具。实际工具命名、既有取数能力的适配与注册迁移尚待细化；不修改他人存量工具的所有权。

正常新建路径：直接批量取数 → 模型分析真实结果并确定表达 → 创建页面。只有能力不明确时先发现；只有存在具体证据缺口时补查，不强制固定多轮。页面创建遇到缺少趋势数据等业务问题时，返回缺口让模型决定补查或调整表达，不暗中改变查询口径。

运行约束方向：首批独立取数可批量并发并遵守服务限额；结果引用在身份与创作上下文约束下复用；模型收到实际口径、相关数据和截断说明，不能把抽样当作全量；相同解析后请求复用结果，无实质修改的重复失败不再执行；校验反馈一次聚合；权限拒绝、能力不支持和预算耗尽终止对应分支，不自动放宽条件。业务补查、技术重试和页面修复共用本轮时间与调用预算，不叠加无界重试。预算只约束本方调用，不承诺控制 Lab 内部行为。

试验初值：首批后最多两轮业务补查、最多一次模型页面修复，并配置整体截止时间。上限不要求用满，具体数值和截止时间通过真实任务评测调整，不作为已验证性能承诺。

近期内部调整方向：抽出共享取数能力，消除造整页再拆数据或组件；合并新建入口；MCP Adapter 直接调用应用用例，不经另一个 MCP Server 复用。验收同时观察口径与答案正确性、首次取数满足率、重复查询、补查轮数、总耗时和页面成功率。

当前尚未决定：

- 大结果向模型提供哪些分析证据，如何按需读取已有结果而不重复查库？
- 关键证据不足、部分取数失败或预算耗尽时，完整页面与部分候选的交付界限？
- 取数结果与页面表达的生命周期、复用和失效规则？
- 在上述决策基础上细化输入输出、兼容迁移与内部模块接口。

### 2026-09-20 数据侧对账与部分交付补充

用户认可部分交付原则：不影响核心回答的缺失允许生成部分候选，缺失内容和原因随页面保留；影响核心回答时停止生成看似完整的结论。无数据、查询失败、无权限分别表达，预算耗尽也遵循该原则。上面的部分候选未决项因此收敛，具体反馈契约仍待定。
