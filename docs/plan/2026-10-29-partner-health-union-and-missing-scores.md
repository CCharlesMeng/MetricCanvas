## 目标与口径

同一期间、筛选范围和组织粒度下，所有参与得分的查询按稳定组织键取并集：有任意一组返回该组织，就展示该组织。按键关联，不按行号关联；区域与代表处分别计算。

单项缺行、null、空字符串、仅空白字符串统一展示 `--`；真实 0 展示 0。计算总分时缺项按 0，真实 0 保留，负数直接相加，不重复乘权重。用户已确认：所有单项都缺失时总分为 0，单项仍为 `--`；已接入正式页面的组织得分计算。

“某组织在全部查询中都没有返回”不在查询并集中；如果仍需展示，必须另有完整组织目录查询作为行集合，不能从计数或静态名称推测。

## 推荐实施

1. **数据源层明确组织行集合。** 增加受控的多源组织键并集能力，再复用现有左关联与计算算子。具体协议名称、Schema 及声明结构待设计，本方案不提供可被误认为现行协议的伪 JSON。每个来源必须读取完整结果，检查 TopN、分页或预算截断；不允许将不完整集合宣称为完整组织集。
2. **复用现有计算，统一所有消费者。** 从并集行集合出发，逐项 `joinAggregate`；保留缺项为 null，分类及总分使用 `sumFields` 的 `onMissing: "zero"`。把区域、代表处表格 main 与总分列接到统一计算数据源，替换空 pending 总分绑定；总分卡片、图表、导出按各自粒度复用相应计算结果。所有实际参与计算的得分查询都要纳入，不能只合并本次 Mock 的三个来源。
3. **修正空文本呈现。** DQE 数值归一化与表格原文回退协作识别空文本：空/空白显示 missingText `--`，计算继续使用 null；保持真实 0、负数和有效数字字符串。非空非法文本继续保留诊断证据与明确告警，不能悄悄归为正常空值。
4. **保持错误与缺项分离。** 查询正常但无该组织可当缺项；请求失败、权限拒绝、返回属性缺失、重复组织键或截断不能冒充 0。每来源预期组织键唯一，沿用 unique 聚合校验，不静默选择一条或求和。空键应明确失败，不能制造组织键。

若能确认后端已有一个随筛选变化且完整覆盖目标组织的查询，也可用它作为主行集合，全部复用现有 `joinAggregate`，避免新增并集协议。但单纯选择“返回最多的一组”不能保证完整，因为并集可能大于任一单组。

不建议只改表格全局对齐逻辑：会隐式改变所有表格行为，且总分数据源、卡片、图表与导出仍然缺行。`pagedUnion` 是纵向拼接，不是按组织横向合并；现有 `pagedJoin` 依赖指定主成员，也不会自动形成组织并集。

## 验收与实施顺序

先落实行集合能力及确定性回归，再调整页面计算与空文本呈现，最后做页面试验场及真实 DQE 验证。

| 验收场景 | 通过标准 |
|---|---|
| 1/10/13 行交叉集合 | 恰好 15 个唯一组织，缺项 `--` |
| 主查询为空、辅助查询并集14 | 展示14；所有查询为空时0行 |
| 各组组织顺序不同 | 相同组织正确对齐，无按序错配 |
| 0/null/空/空白/数字字符串0/负数 | 单项正确，分类及总分可算；全缺总分按最终确认口径 |
| 属性省略、重复键、请求失败、权限拒绝、结果截断 | 明确错误或未完成状态，不输出伪造完整总分 |
| 筛选、期间、组织粒度变化与过期响应 | 行集合与得分来自同一轮条件，旧回执不覆盖新结果 |
| 表格、总分、图表、导出 | 同一粒度的组织集合与计算一致 |
