# Platform 创作 Skill 优化：设计访谈

状态：历史访谈记录。正式实施依据为[统一创作 Skill 规格](../specs/2026-09-15-unified-authoring-skill.md)，架构解释见[页面创作 Agent 方案](2026-09-15-authoring-agent-architecture.md)。下文包含已撤回的“暂留两个薄入口”备选，不能作为当前实施依据；当前方案采用一个创作 Skill，任务参考内部拆分。

## 证据基线

- 评测任务：`01a0a2c4-be2b-7361-8d6d-b42022abc912`，消费提交 `d015c22`。
- 14 例：6 pass、3 fail、5 blocked；三个失败为修改场景把数据发现当文档查阅，最终编辑产物符合要求。四个数据创建场景缺数据配置；所有真实路由断言未验证。
- 评测仅注入 Skill 正文、共同约定与两份布局参考，没有读取完整参考目录；全部内容工具可见是诊断设置。不能据此将失败或输入 token 归因于 18 万行分发资料。
- 既有边界参考 ADR-0060/0061/0064/0077/0078。独立安装要求不等于两个 Skill 必须各复制完整参考库。

## 第一轮已确认（用户答复：都可以）

1. 允许重新讨论整个创作执行流程，包括 Skill 数量、模型职责、上下文与工具供给；不预设保留两个 Skill。页面协议、精确修订和人工确认发布暂作为既有约束，若需改变须单独论证。
2. 首要目标为 Platform 经真实 Relay 执行的创作流程。Codex 直接使用可保留兼容，但不得假定 Relay 具备 Codex 文件读取能力；评测应复现目标环境。
3. 首要质量目标为正确完成用户要求、保留未涉及内容，能力不足时准确说明；随后优化澄清、调用次数与耗时。文件行数是维护指标，不代替执行质量。

## 第二轮已确认

4. 统一对话入口。当前页面状态与明确意图共同决定创建或修改；已有页面默认修改，明确另建才创建，没有当前页面时进入创建。意图含糊且可能影响现有内容时澄清；程序最终约束操作对象。
5. 模型负责完整页面方案，包括分析内容、合适的组件与组织顺序；工具负责合法字段、确定性装配、布局规则及校验。实质业务歧义须澄清，常规呈现选择可采用合理默认。
6. 独立需求允许部分完成并准确报告；相互依赖的改动整体等待。操作依赖须可验证，不能只依赖口头说明。

用户逐项答复：Q4“统一入口”；Q5“是的，完整方案”；Q6“可以的”。上述为对本轮问题及推荐边界的确认，尚未决定具体 Skill 数量、接口或事务实现。

## 尚未决策的设计树

- 已确认统一入口、模型规划职责和部分完成原则；待决定具体任务切换机制、方案执行时机和依赖分组实现。
- Skill 数量、工具装载、参考获取、状态与保存交接。
- 能力缺口与规划范围，需核对现有工具对新增数据组件的支持。
- 错误恢复、事实依据、输出与身份上下文。
- 分发策略及分层对照评测、验收标准。

本轮尚未形成新的领域术语或满足条件的架构取舍，不修改 CONTEXT.md 或新增 ADR；形成共识后及时记录。

## 第三轮反馈

- Q8 已确认：没有实质业务歧义时直接生成可查看初稿，不固定增加方案确认；保存时机另议。
- Q7 未决：用户最担心手工编辑与语言编辑交替后，Agent 持有旧页面元数据，以及每轮重新获取和内部路由复杂性。未确认合并为一个 Skill。
- 下一决策前提：分清每轮间刷新与一轮执行中的并发变化；明确创作草稿当前状态的权威来源、本地未保存修改的处理、应用前过期检查及冲突策略。程序持有完整页面、模型仅消费必要摘要是既有边界，不应要求模型记住并维护完整 JSON。

## 第四轮已确认

- Q9：AI 修改与人工修改互斥，同一时刻只能一方进行。用户明确要求 AI 回答过程中锁定人工操作，人工修改期间反之。
- 因此第一版不采用 AI 与人工同时修改后自动合并的交互方式。互斥由程序执行，不由 Skill 文案或模型记忆保证。
- 待明确：人工修改开始/结束边界，AI 等待澄清时的占用，自动同步和未决写入恢复，其他窗口或会话的并发范围。尚未将其定为页面级服务锁或等同于发布租约。

## 第五轮已确认与范围收敛

用户对 Q10–Q12 推荐回答“都可以”，并要求快速收敛，核心为 Skill 的执行逻辑、结构和体积优化；额外发现的平台交互问题必须记录，但不扩大为本轮实现前置。

- Q10：发送 AI 请求是交接动作，提交当前人工输入并等待同步成功后才启动；交接期间暂停新增手工修改，不增加单独退出人工模式的按钮。同步失败保留原工作内容，不启动 AI。
- Q11：AI 等待用户澄清时，如无未决写操作，恢复手工编辑；下一次用户回答时重新交接并取得当前基线。
- Q12：首版当前工作台内严格互斥；其他窗口或用户的变化由保存时版本检查处理，冲突拒绝覆盖、不自动合并。不新增页面级全局编辑占用服务。

以上是已确认的交互设计方向，不是声明现有实现全部满足。真实 Relay 基线取得、手工输入提交、澄清解锁、取消/未知结果恢复与外部版本冲突需另行验收。不能把它们混入 Skill 优化的通过条件。

## 快速优化候选方案（待最后一轮确认）

注意：下列“保留两个薄入口”是为快速实施提出的备选，用户没有确认。用户已指出它与此前单一 Skill 建议不一致；Q7 仍未决，不能按保留两个或合并一个擅自实施。统一用户入口、完整方案和编辑互斥已确认，Skill 数量尚未确认。

### 本轮做

1. 保留创建/修改两个薄 Skill 入口，共享规则单处维护。统一用户入口不要求本轮合并 Skill；不以新增平台路由、状态机或服务端能力作为前置。
2. 执行逻辑：普通编辑使用已提供基线摘要和受控操作，不先做数据发现或全套布局查阅；数据发现只找业务能力。明确已注入的参考无需重读；只有真实读取能力存在时才指示定向查阅，不用业务工具模拟文档搜索。仅针对不可恢复的配置错误停止同条件重试，其他错误按分类处理。无证据不编造业务行为，使用用户语言，简明报告实际产物/保存状态。
3. 结构：入口只含触发范围、最短执行流程、必要停止条件和结果报告。模型可用的任务指南围绕受控工具操作组织，完整页面协议不等同于可执行能力。新增数据图表的现有工具缺口如实说明，不能以重建或类型转换冒充追加。
4. 体积：调整标准生成/投影路径，裁剪每个 Skill 默认携带的完整错误夹具、机器索引及重复 Schema；保留任务指南、布局规则和必要的最小例子。完整协议、校验和测试覆盖仍保留在作者/工具/测试层，不手改生成物、不另写第二份 Schema。必须验证独立安装后的引用闭合及版本一致性；先实测裁剪结果，不承诺未经验证的 token 降幅。
5. 评测接入：角色工具过滤和明确的参考注入只在评测/适配边界处理，不依靠 allowed-tools 文案假装权限执行。保留全部工具可见的独立诊断模式。避免混淆新页面身份与基线身份。

### 本轮验证

- 先保持诊断工具集合可见，比较指令与参考注入修正，复测三个误调用场景；再单独评估角色工具过滤对 token/耗时的影响，不混合归因。
- 补新的同类任务，检查产物正确、过程合规、答复有据、调用与上下文成本。保留精确目标、未涉及内容保持和缺基线不重建等正例约束。
- 全量参考检索尚未真实验证；数据环境阻塞、真实路由和跨端同步另记，不用修改提示词制造通过。付费模型复测的批次/预算在执行前单独明确，本次讨论不等于授权无限追加调用。

### 另行跟进

平台交接与互斥、精确基线刷新、取消/未知结果恢复、跨窗口冲突、真实 Relay 工具装载与路由；已有页新增独立数据图表/新查询的工具能力补齐。上述事项均不由 Skill 文案代替实现。

## 新增：组件选中询问（待核对与决策）

- 用户指出必须覆盖选中某组件后询问，包括云宝集成和 Skill 行为；后续已确认云宝就是盘古，方案沿仓库盘古命名。具体 SDK 上下文接线仍需核实。
- 核对方向：选中组件在发送时成为本轮上下文，须与精确基线关联；视觉选中不自动授权修改，也不自动意味着业务数据已经提供。分析/解释、修改当前页面、明确另建是不同意图。
- 建议方向尚未确认：选中组件作为指代消解的默认对象；显式用户目标优先，矛盾/歧义时澄清；本轮冻结选中目标，不读后续变化的全局 selection；失效目标不回退到另一个组件。完整 JSON 仍由程序持有，模型获得必要目标摘要和有效引用。
- 组件上下文传递若当前缺失，是实现该场景的最小必要接缝，应与完整平台交互改造分开列项；不得只修改 Skill 并声称端到端场景已支持。
