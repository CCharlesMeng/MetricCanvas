## 1. 推荐结论与交付范围

在 `reportHeader` 现有导出位置增加选项，用户可见名称固定为**“导出图片”**。默认 3 倍、可选 4 倍；不论报告长短，成功时只下载**一张完整 PNG**。这是用户已确认的约束，不提供多图、ZIP、其他图片格式或格式降级。

长报告采用内部有界分块截图、Worker按行流式编码为同一张PNG；内部块不对应下载文件，不降低倍率、不漏内容、不重复接缝。生成前显示整张图片的实际像素尺寸。确实超过经验证的单图资源上限时明确失败，不改成其他格式或只下载部分内容。

水印处理采用**独立导出文档重新渲染**：捕获本实例状态和查询作用域，在干净 iframe 文档内使用正式静态视图渲染，再截图该文档。原页面上的水印继续正常显示，导出全过程不隐藏或删除它。不从浏览器可见画面取屏，不从已叠水印的画面做像素修补。

首期针对集成门户/集成应用附加的 DOM 浮层、全局伪元素和背景水印。实际注入方式尚未核验，同源 iframe 不能阻止主动遍历 frame 的脚本；是否满足原系统要求必须用真实门户验收。若门户会向独立文档注入水印，转为集成应用提供干净导出运行环境，不把选择器黑名单当保证。

首期保持纯浏览器闭环、现有实例任务与分发方式。不恢复已删除的公共 DOM 回调，不引入服务端截图服务、全局导出单例或集成应用自装的 PNG 编码器。PDF 下载入口与既有数据语义保留，共用准备链路的改动须完成 PDF 回归。

## 3. 用户操作与输出规则

1. 只声明 PDF 的旧页面保持原按钮和自定义文字。
2. 同时声明 PDF、PNG 时，在现有位置显示“导出”菜单，包含既有 PDF 项与“导出图片”项；原自定义 PDF 名称作为 PDF 项文字。新增图片项只输出 PNG，既有 PDF 是独立功能，不作为图片失败时的回退格式。
3. 选择“导出图片”后，轻量面板提供“高清（3倍）”“超清（4倍）”；默认来自页面声明，未声明时为 3 倍。只声明 PNG 时入口同样叫“导出图片”，也进入该面板。
4. 点击“生成图片”才冻结本次状态并取数。数据与布局准备完成后显示整张图片的实际尺寸，由同一确认区域保存这张 PNG；不提供文件格式或多图选择。
5. 文件按 `报告标题.png` 保存，每次成功只发起一次 PNG 下载。文件名复用现有文本取值与安全清洗规则，不拼接未解析对象，并规范为单一 `.png` 扩展名。
6. 任务状态为准备报告、渲染高清图片、生成图片、可下载；生成期间禁止重复创建 PDF/PNG 任务，不新增用户取消按钮。关闭设置面板不等于取消已经开始的任务；已生成资源在保存、关闭结果面板、页面更新或销毁时释放。
7. PNG 保留页面标题、期间、背景、全部正文；日期输入、格式菜单、进度、分页、链接浮层不进入图片。默认不透明，使用页面合法背景，未声明时白色。

第 4 步只显示整图尺寸，无须再生成一份缩略图；不宣称浏览器已经将文件写入磁盘。面板复用现有中性按钮、菜单及焦点管理，支持键盘、Esc 关闭、焦点返回和窄容器布局。

## 4. 干净导出文档

建议执行链：

```text
Report 页头选择“导出图片”与倍率
  → 同步捕获页面/已应用状态/查询作用域
  → 既有数据网关准备导出数据
  → 新建独立文档，装载引擎拥有的样式与资源
  → 在独立文档挂载正式 ExportView，等待字体/图片/图表
  → 按像素计划分块截图
  → Worker 按行流式编码为同一张完整 PNG
  → 用户保存唯一 PNG 文件 → 释放全部临时资源
```

### 4.1 文档和样式来源

干净 iframe 从空文档创建，不加载平台框架、导航、分析侧栏、门户脚本和水印脚本。只装载引擎自身的基础样式、组件样式、布局样式，以及允许的主题与字体资源；不复制整个原文档 `head`、所有 style 标签或任意计算样式。

实施采用正式Svelte组件显式`css="injected"`，让运行时、widgets、ui样式直接进入实际挂载根；随npm与HTML ES/IIFE分发，不复制父文档CSS，也不另生成第二套样式实现。主题名称白名单由构建脚本从源码提取，字体通过资源集合传递。独立安装消费者验证样式闭包，避免只在Vite开发环境成立。

继承范围为明确的主题值、字体配置和布局几何。主题使用已知变量及值类型白名单，不再无条件复制所有 `--mc-*`；URL 背景和字体资源必须来自明确的引擎/集成应用资源描述。禁止从原页面的任意 `background-image`、伪元素或全局选择器反推背景。页面正式声明的装饰仍渲染；已经画进业务图片或图表像素的水印不能靠文档隔离移除。

页面宽度、内边距、分区间距及容器查询上下文沿用当前布局的几何值，在图表初始化前确定；不把 3 倍倍率当作 CSS 宽度，不强制切换 794px/A4 布局。横向超宽内容沿用当前自然宽度展开规则，最终尺寸在展开后计算。

### 4.2 隔离强度与真实接入

| 水印来源 | 推荐路径的预期 | 验收要求 |
|---|---|---|
| 父文档固定浮层、门户导航层 | 截图只读取独立文档内容，不包含父层 | 父层水印始终可见，下载像素中不存在水印标记 |
| 父文档全局 CSS、body 背景、伪元素 | 独立文档不带入这些规则 | 人工注入水印背景与伪元素进行反例验收 |
| 同源脚本主动遍历/监听 iframe | 单纯同源 iframe 无法保证隔离 | 真实门户核验；由门户提供不注入水印的专用导出运行环境 |
| 浏览器扩展、终端软件或操作系统覆盖层 | 取决于覆盖层是否进入导出文档/资源 | 单独实测，不用本地合成测试代替 |
| 原始图片、服务端图像、图表数据画面自带水印 | 独立重渲染仍会保留原始像素 | 需要合法干净素材或上游输出能力，PNG 导出不做图像去水印 |

同源 iframe 的职责是避免正常样式和页面内容污染，不是对抗同源脚本的安全沙箱。`sandbox` 使用现有最小能力策略作为起点；由父文档代码在 iframe 挂载正式组件是否满足 Svelte 样式注入、ECharts、定制组件 Worker/iframe 的要求，先做验证，不能仅凭“iframe 是独立文档”视为已解决。

若确需更强隔离，备选为专用导出 origin/运行页：只接收一次性任务标识和冻结后的渲染材料，严格校验消息来源与任务身份，不在 URL、日志中传查询、数据行或凭据。查询仍由现有授权数据网关完成。该路径需要实际门户允许加载、CSP、字体图片访问和部署资源，独立估算与验收；不在第一版强行加入一个只用于转发的 Adapter。

“线上单独截图”不必等于服务端 Chromium。若要求关页后继续，或真实门户隔离无法成立，再另立服务端任务：明确鉴权、状态传递、受控资源访问、任务存储、过期清理和部署责任。当前纯浏览器方案不承诺这些能力；本次单张长PNG要求由浏览器流式编码方案承接，不推迟为后续可选工作。

## 5. 高清与长报告

### 5.1 分辨率契约

- `scale` 是源内容 CSS 像素到输出像素的倍率。最终宽高基于布局完成后的内容包围盒取整；所有分块共享同一组整数像素坐标，避免块与块各自舍入。
- 示例：1200×2400 CSS 像素，3 倍为 3600×7200，4 倍为 4800×9600。倍率不再乘屏幕 DPR，因此 DPR=1/2、浏览器缩放等条件下同一布局得到约定像素尺寸。
- 图表初始化显式使用本任务倍率，渐变文字冻结和自定义画布采用相同上下文。低分辨率原图不会凭空产生细节，需要高分辨率素材；不能只检测 PNG 文件尺寸就声称高清通过。
- PNG 无损编码，不提供无意义的 JPEG 式“quality=1”设置；对外使用真实像素尺寸，不以修改 DPI 元数据代替高清。浏览器原生编码的分辨率元数据可能为 96dpi，见 [MDN convertToBlob](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob)。

### 5.2 单张长 PNG 的强制策略

沿用现有最长边 8192、面积 16,777,216 像素作为**内部截图块**的保守预算，不把它当作最终 PNG 的宽高上限。最终像素空间预先确定整图宽高与连续行坐标，再计算可容纳的块高；不按 A4 切图。以上示例的 3 倍图约 2592 万像素，可以分多块截图，但下载结果仍必须是一张 3600×7200 PNG。

Worker顺序消费每块ImageBitmap，在有界OffscreenCanvas中读取行像素，送入增量PNG编码Module。整个任务只创建一个PNG文档：一个整图IHDR、连续行的过滤与压缩状态、按顺序输出的IDAT块和一个IEND。不能把各块独立PNG直接串联，或把独立压缩流当作同一图像流；跨块行过滤所需的前一行状态必须连续保留。

所有块共享整数像素边界；不重复表头、页码、标题或边界行，最后一块不增加尾部空白。完成全部行和文件校验后才提供唯一PNG下载；失败时丢弃中间编码数据，不保存部分图像。

若 3/4 倍下单行宽度就超过已验证的截图预算，明确提示“当前报告尺寸超出图片导出支持范围”；不擅自降倍率、不切成多个下载文件、不改用其他格式。单个超大图表和自定义画布须单独预检；不能以最终流式编码为由忽略其源画布内存分配。

B0必须选定并锁定支持增量行输入的PNG编码依赖，验证Worker适配、持续压缩状态、透明度/颜色、包体积和许可证。不手写完整PNG压缩器。若现有原生编码仅能基于整张OffscreenCanvas输出，就不能直接承担长图主路径；禁止把多块再合入一张整图画布来假装流式。短图也消费同一套单PNG任务契约，避免两套结果语义。

流式编码消除整图画布分配，但最终图片查看器仍可能完整解码。当前整图预算为宽8192、高32767、面积134217728像素，编码128MiB；与单块预算分别检查。Chrome已原生解码4800×23539的长图；这不是最大预算或所有查看工具的验收，不承诺无限长度。[html2canvas FAQ](https://html2canvas.hertzen.com/faq/) 说明画布限制随浏览器、系统和硬件变化，相关预算必须在目标 Chrome/Edge 上实测。

### 5.3 内存、性能与结束条件

沿用一次解析、多块复用与一块在 Worker、一块在主线程准备的背压。主线程处理 DOM/布局和分批截图，Worker逐块取行并持续编码同一PNG；iframe不充当后台线程。消费后的原始画布、ImageBitmap和临时URL立即释放，只保留压缩状态、必要行缓冲及已编码文件片段，不持有完整整图RGBA。

每个任务的PNG编码结果建议固定上限128 MiB，超限失败且不保存部分结果；最终Blob/缓冲区仍可能形成额外复制，已编码文件片段占用也随文件增长，因此不承诺总内存恒定。B0测量后可以调整预算，但不得依靠自动减低倍率或改格式来过关。进度按已消费像素行/整图总行数计算，内部块数不作为输出图片数展示；准备60秒、编码无进展60秒沿用现有规则。待保存结果最多保留5分钟；期间仍占用该实例导出名额，保存、关闭结果或到期后释放并恢复入口，到期明确提示重新生成。

## 6. 共用 Module 与 Interface

保持一个实例任务协调 Module，统一负责状态捕获、并发、超时、更新/销毁中止及结果释放；复用 `createExportController` 与 `page:export`，不让 PDF、PNG 各自创建互不知情的任务。

内部仅区分三项职责：准备可渲染材料、创建干净导出文档、按格式生成文件。面向页头的 Interface 保持“格式 + 倍率 + 触发页头”，复杂的字体就绪、尺寸计算、分片与资源管理收在 Implementation 内。格式实际已有 PDF/PNG 两种差异，适合在文件编码处形成内部接缝；不建立通用插件注册体系。

建议内部形状，非公共承诺：

```ts
type ReportOutput = { format: 'pdf' } | { format: 'png'; scale: 3 | 4 };
// 捕获与准备由实例内完成；返回材料只在任务生命周期内有效。
// PNG编码结果只有一个文件：.png文件名、image/png、整图尺寸、Blob和dispose。
```

通用准备链路不再创建第二份原文档静态视图。PNG 先采用干净文档，PDF 在同批共用迁移后保留现有 A4 连续分页、方向判断和文件名行为；PDF 输出效果回归失败时必须修复，不同时维护两套长期静态渲染链路。现有 PDF 截图派生代码及 Worker 继续由构建脚本生成，不能手改内嵌字符串。

## 7. 页面协议与兼容

推荐增量字段，实施版本号在届时主线能力表中分配，本计划不占用版本：

```json
{
  "pdfExport": { "label": "导出 PDF" },
  "pngExport": {
    "filename": "经营分析报告.png",
    "scale": 3
  }
}
```

这是 `reportHeader.props` 片段，不是可加载的完整页面。`pngExport`存在即启用，`{}`使用标题文件名和3倍。图片入口名称固定“导出图片”，不新增可覆盖它的`label`字段；`filename`使用既有非空文本取值并规范为`.png`。`scale`仅接受数值3/4，用作用户面板默认值，用户选择在点击生成时冻结。不开放图片格式或多文件模式，不把倍率、内部截图块和水印实现写进页面参数或查询绑定。原PDF的可配置`label`仍按原契约使用。

PNG 与 PDF 一样限定报表布局，新增版本能力及正负契约向量；旧 PDF 声明和旧页面可读性按现行版本政策保持。旧引擎对新能力按门禁拒绝，不静默忽略。没有 `pngExport` 时不增加 PNG 菜单，也不批量修改所有业务页面。

不增加 `removeWatermark` 开关、任意 CSS 选择器或字符串脚本；干净渲染是导出机制的职责。后端权限、网关凭据不进入页面协议。若真实门户需要专用导出运行环境，它属于集成应用接线能力，不转成业务页面里的地址。

页面文本解析、组件类型、验证、版本、属性面板/编辑定位、参考投影和 Python/独立校验器必须一起覆盖新字段；避免仅改 Zod Schema 导致生成/编辑丢配置。创作流程只需识别是否启用与默认倍率，无须扩展日期提取或改变查询语义。

## 8. 数据与错误语义

沿用现有导出范围：全部内容分区、内容分区组、Tabs、表格当前筛选/搜索范围；重新取全部匹配行。TopN 保持声明范围，级联分页窗口保持当前窗口契约；详情专用查询不执行。AI 总结使用捕获时已有文本，图表恢复完整类别，不将屏幕 dataZoom 可见范围冒充全部内容。

沿用部分失败保留可用内容、查询错误空态、异常数字为缺失、`EXPORT_PARTIAL_DATA` 与总数不匹配诊断。下载成功不表示数据完整；日志不包含查询体、筛选值、业务行或凭据。10,000 行上限、完整性结构错误等仍按现行规则处理。冻结的是查询作用域，不是数据库事务快照。

新错误区分无效尺寸、整图/截图块/单资源超预算、资源加载失败、图片非origin-clean、流式PNG编码、行数/文件结构不完整、输出字节超限、Worker/CSP和超时。明确失败且不下载半成品；不静默丢图片、自动降低清晰度或改成其他格式。跨源图片需要合法CORS/受控资源接入，设置`allowTaint`不能使污染画布可导出，见[html2canvas配置](https://html2canvas.hertzen.com/configuration)与[MDN编码错误](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob)。

页面更新、销毁及集成应用已经具备的身份失效重挂载必须中止任务和丢弃待保存文件。新的权限修订通知机制不借本功能偷偷引入；该接线缺失时在真实集成验收中单独列明。
