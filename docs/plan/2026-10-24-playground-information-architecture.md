# Playground 目录与数据联动改进计划

日期：2026-10-24。状态：P0–P5 首轮实施及本地关键链路验收完成；P6 内嵌下载回执等专项保留，Git 交付按用户授权使用 `[skip ci]`，最新基线复验见[交付记录](../evidence/playground-information-architecture/delivery.md)。本文件是本批唯一执行主计划。结果与未关闭项见[实施记录](../evidence/playground-information-architecture/result.md)。

页面试验场按「布局、组件、数据与联动」提供三个并列入口。每个组件都有独立、可直达的目录；数据能力按取数、条件、关联、交互、结果范围和跨页输出组织。同一场景由多个入口引用，把操作、说明、配置与试改集中在一个上下文内。

本批目标是降低找功能和理解数据关系的成本，并归并重复演示。页面文档数量、场景数量和默认入口数量分别统计，不能仅通过隐藏页面宣称页面已经合并。

## 已确认的设计规则

1. 布局回答「页面怎样组织」，组件回答「这个组件怎样使用」，数据与联动回答「数据怎样查询、关联和继续分析」。三个维度并列，不构造成布局下复制组件、组件下复制功能的多重树。
2. 组件目录完整覆盖产品实际注册的全部类型。当前为 19 类，以产品组件能力目录为准；新增组件自动出现目录，缺少演示时明确列为待补场景。
3. 组件自身能力集中在该组件内；跨组件协作、页面级数据行为放入数据与联动。跨入口访问同一个场景，并定位对应说明或重点组件。
4. 功能围绕数据主线组织，区分数据之间的关联与操作引起的联动。不得把共同展示、并行查询、按键补列和逐行拼接混称为同一种关联。
5. 推荐演示与全部文件分开。业务示例、临时评测有次级入口，临时页不进入默认推荐和默认搜索结果；可显式切换到全部文件检索。
6. 页面仍由实际文件自动发现，页面 id 与文件名一致，移动目录不改变 `/pages/<id>`。普通页面不需要登记才能访问。
7. 演示复用正式组件、页面协议和统一运行时。场景组织信息属于开发工具，不进入页面协议、业务筛选状态或产品查询定义。

## 目标目录

### 布局

| 目录 | 场景内容 | 与组件目录的关系 |
| --- | --- | --- |
| Dashboard 看板 | 满幅外框、分区、标题、宽窄屏 | 关联实际组件，不复制组件手册 |
| Report 报表 | 定宽外框、报告页头、章节与长内容 | 关联报告页头及整页输出 |
| 内容分区与网格 | 分区容器、列宽、排列和响应式 | 分区与组件分别解释 |
| 容器组合与嵌套 | Tab、组合卡及合法组合边界 | 指向各自独立组件目录及同一演示 |

Dashboard 和 Report 是同一页面资产的布局形态。切换对照使用合法的对应文档实例，不把切换外框等同于完整迁移页面声明。

### 组件

每个类型都有独立目录和固定地址。下表按阅读便利分组，分组不取消任何组件的独立入口。

| 阅读分组 | 必须独立可查的组件 |
| --- | --- |
| 页头与操作 | 报告页头 `reportHeader`、按钮 `button`、独立筛选 `filterGroup` |
| 指标与图表 | 指标卡 `metricCard`、柱状图 `barChart`、折线图 `lineChart`、饼图 `pieChart`、地图 `mapChart`、仪表 `gauge` |
| 表格与明细 | 明细表 `table`、排行卡 `rankingCard`、详细排行卡 `rankingDetailCard`、信息面板 `keyValuePanel`、分类明细 `categoryBreakdown` |
| 容器 | Tab 容器 `tabContainer`、组合卡 `compositeCard` |
| 文本与总结 | 文本 `text`、字段长文本 `fieldText`、AI 总结 `aiSummary` |

组件目录内部使用「基础用法、专属能力、组合场景、关联数据功能」组织。少量场景直接展示，不创建空层级。基础演示突出该组件；业务页偶然包含某组件，不自动成为该组件的推荐演示。

IOC 公共页头是页面级 `iocHeader` 声明，主入口位于「数据与联动／条件驱动查询／页面级筛选」，保留 `/ioc-header` 直达；报告页头和独立筛选目录提供关联入口。报告页头的名称、类型和数据绑定规则仍按产品真源展示。

### 数据与联动

| 阶段 | 子主题 | 演示需要回答的问题 |
| --- | --- | --- |
| 定义取数 | 内联与查询、查询定义、结果字段、页面参数与初始条件 | 查什么，行粒度是什么，字段怎样对应 |
| 条件驱动查询 | 时间与期间、维度与金额、页面级与局部筛选、组合条件、级联候选、必需条件与等待 | 条件影响哪些查询，何时提交，哪些来源不受影响 |
| 数据关联与组合 | 共用数据源、同一结果的不同消费方式、多查询组合、主记录与明细关联 | 按什么字段和规则关联，是否改变行粒度，数据是否完整 |
| 交互联动与继续查数 | 记录选择、层级下钻、按父行查子表、带记录条件打开详情 | 操作写入什么，哪些查询重新执行，状态怎样隔离 |
| 查询结果与范围 | 搜索、过滤、排序、分页、总数、完整结果、空与失败 | 当前窗口与完整结果分别是什么，上游与本地各做什么 |
| 跨页延续与输出 | 参数与筛选传递、URL 初始化与恢复、Excel、PDF、PNG、关联数据生成总结 | 带走哪些条件，输出范围是什么，重新打开怎样恢复 |

「数据关联」按实际实现区分共享页面数据源、结果过滤、按键关联和行拼接等方式。决策意见明细的专用模拟适配器与待实施的通用 pagedUnion 必须分别标识，不因被收录而扩大产品能力结论。

条件显隐、只读、加载、空、失败、无权限和未配置优先作为相关场景的状态分支。需要解释页面级语义时，在对应阶段提供专门场景并互相引用。

## 场景归属与内容组织

### 一个场景一份声明

一个场景有一个主要目录归属，可有多个关联入口。主要归属决定默认说明顺序，关联入口只改变定位和阅读重点，不复制 JSON、操作步骤或查询配置。

例如「点击区域表格，联动趋势图」主要归属数据与联动，明细表和折线图目录都能进入。表格入口定位到选择写入，折线图入口定位到筛选绑定，数据入口展示完整链路。

每个推荐场景包含：

- 要解决的使用问题，以及重点演示的组件。
- 实际页面或来源与目标页面，及必要的明确演示参数。
- 数据来源、启动条件、适配器和数据性质。
- 操作步骤与可观察结果。
- 数据链路说明：来源、字段、条件、关联、消费者和结果范围。
- 从当前运行文档提取的关键配置、完整 JSON 和试改入口。
- 适用条件、产品限制、关联场景及真实服务验收边界。

### 自动发现与场景索引的边界

保留页面仓储递归发现及全部文件视图。组件清单、标题、别名、实际布局、存在的组件和页面数据源类型从产品或页面文档读取；不手写第二份组件注册表，也不从标题推断布局或真实服务可用性。

推荐场景需要少量开发工具信息：主归属、重点组件、数据主题、引用的页面 id、场景切换和运行环境。实施时集中在 Playground 自有场景模块中，使用类型约束的引用；普通页面无需登记。场景模块不能包含另一份页面协议或整份页面 JSON。自动检查引用存在、重点组件与实际文档对应、每个场景只有一个主归属。

操作说明在相应目录 README 的有稳定锚点的场景段落维护，开发工具通过只读加载展示同一段内容。P1 验证现有 Markdown 能力，明确允许的正文、链接与代码块；不通过解析自然语言猜测组件归属、运行环境或查询配置。

当前[功能验收规则](../agents/feature-acceptance.md)明确不维护逐页目录元数据。P1 同批补充「页面自动发现不变，推荐场景允许轻量语义索引」及说明展示约定，避免将全量页面重新变为手工登记体系。

### 页面内交互

主题和组件页面就地切换场景，保持查找上下文。演示旁提供操作、数据关系和配置；完整 JSON 与试改按需展开，避免压缩默认演示空间。

「在此基础上试改」带入当前页面文档、可信的演示环境标识和必要输入。草稿使用既有校验与统一运行时；配置无效时显示准确错误，恢复后重新渲染。草稿不保存为页面资产。运行环境按明确场景绑定，不因草稿碰巧使用某个页面 id 而授予模拟适配器能力，也不在模拟能力缺失时静默访问真实服务。

切换场景时明确销毁或保留实例；独立查询、候选、详情、子表和 AI 总结遵循各自现有生命周期，不通过复制全局状态实现上下文保持。临时编辑会影响状态时，提供重置和明确的重建行为。

每份页面在 P0 清单中记录「保留为代表、合并后保留旧地址、流程目标、测试依赖、临时保留」及理由。实际删除必须确认没有测试、文档、外部深链接或其他批次依赖；默认先保留原页面。旧地址有确切等价场景时可以跳转，必须保留业务参数与筛选语义；不能可靠映射时继续运行旧页并链接新入口。

本批不预先承诺将 111 份文档压到某个数字。P0 冻结可合并范围，P6 分别报告默认入口、交互场景、实际文档和兼容保留数量，以及未合并原因。

## 搜索与导航状态

搜索覆盖组件正式名称与产品别名、场景用途、数据主题、说明及页面 id。结果优先推荐场景，显示「组件／明细表／搜索与筛选／字段切换」等可理解的路径；同一场景多个入口合并展示关联归属。

默认搜索范围为推荐场景，业务示例与全部文件可显式选择。独立组件目录全部可见，未有代表演示的组件显示缺口，不用无关业务页填充。

目录维度、主题、场景及说明定位应可复制链接。Playground 导航参数与运行页面参数、筛选参数保持隔离，沿用或明确登记已有开发工具参数，不覆盖运行时查询串。返回、刷新、前进后退恢复主题、搜索、筛选和滚动；失效场景回退到有效父目录并说明原因。旧目录存储结构作有界迁移，存储不可用时仍能浏览。

## 检查与文档交付

实施按变更运行以下检查，不把计划文件生成视为功能验收：

- 修改页面通过 `pnpm validate <本批页面或目录>`；自动化直接消费实际页面并保留交互声明。
- 运行受影响的 Playground 测试、目录导航浏览器用例及表格／IOC／导出等对应回归。
- 执行 `pnpm --filter playground check` 和 `pnpm build:playground`。
- 编码前识别职责与复杂度基线，编码后用 `metriccanvas-ts-ast/1` 测量修改函数及所有新增辅助函数、闭包，按[复杂度规则](../agents/code-complexity.md)报告前后结果与未关闭项。
- 更新根 `pages/README.md`、各场景目录 README、Playground 路由说明及[功能验收规则](../agents/feature-acceptance.md)。
- 按[功能验收要求](../agents/feature-acceptance.md)核对 `PAGE-METADATA.md`、对应页面元数据模块及 local-authoring。受影响知识和示例由真源再生成，执行一致性及仓外独立安装、页面校验；纯开发工具组织信息留在 Playground。确无产品知识变化时记录对应关系与原因，不手改派生产物。
- 证据保存至 `docs/evidence/playground-information-architecture/`，包含页面处理清单、目录覆盖、任务结果、截图、实际命令、复杂度及数量前后对照。
- 提交与 push 在执行阶段按 [scoped-main-delivery](../../.agents/skills/scoped-main-delivery/SKILL.md)进行，保留并行改动；本地验收、远端 SHA、CI 和真实服务分别报告，收口执行已合并分支与工作树清理。

本批采用本地数据、明确的模拟适配器和 DQE Sim 验证交互。真实 DQE、Relay、CloudIOC、门户和 DS 模型不因目录改进获得验收，也不作为本地目录实施的前置。
