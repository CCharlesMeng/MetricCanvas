# 平台创作 Bundle 接口与部署就绪调整计划

日期：2026-09-23。状态：范围已由用户确认；本期实现尚未开始，结果字段契约派生链已完成初步代码核查。

## 1. 已确认的交付边界

本期完成创作工具与 Skill 的必要修正、Adapter 接口契约及本地契约验证；内部自主实现接线。正常多次工具调用所需的状态共享必须支持，故障恢复作为后续优化。结果字段契约优先从已有 Schema 元数据、查询定义及 DQE 结果派生，不预设新增外部服务。页面产物交给内部 Adapter 后，后续前端流程不属于本期。

用户本轮决定取代本计划早期较宽的恢复和页面交付验收范围：

- **Relay 核心不改。** 只使用既有插件、配置与包外 Adapter。若真实扩展点不足，报告具体阻塞，不修改共享环境变量绕过身份隔离。
- **接口优先。** 本仓定义输入、输出、可信边界、失败语义及契约测试；不要求在本仓完成全部内部 Adapter 代码。
- **正常跨调用状态必须可用。** oneshot 调用之间的工作稿、预算、查询引用和提交状态不能丢失。实例故障、跨节点迁移及自动恢复不作为本期交付前置。
- **结果字段契约由已有事实派生。** 不把 SourceDescriptionPort 这个实现接口当作新的领域概念，也不因代码存在该接口就要求内部新建服务。
- **产物交接是本期终点。** Skill 根据工具回执结束；卡片替换、实际显示、显示回执和前端失败恢复归内部页面流程。
- **真实环境由用户同步后执行。** 本地没有内部联调条件；交付接口、固定版本包及验证材料，由用户同步内部，再回传脱敏结果。

依据：[ADR-0090](../adr/0090-authoring-flow-hard-cutover-and-version-vocabulary.md)、[创作架构](../../metriccanvas-authoring/ARCHITECTURE.md)、[Skill 验收规则](../agents/skill-ds-model-acceptance.md)。既有[主流程测试计划](2026-09-22-skill-main-flow-test-plan.md)继续管理独立的页面业务/视觉验收；本批不把它扩展成内部前端工程改造。

## 3. 工作包

### A0：冻结接口与最小部署要求

本仓负责契约；内部确认插件和配置实际支持的传递方式。

| 接口职责 | 必须约定的内容 | 本期负责边界 |
|---|---|---|
| 可信创作轮次 | 身份、工作区、轮次、页面、固定创作基线、有效性及 contextRef | 本仓定义校验规则；内部自主实现提供方 |
| 当前身份 | 每次调用的真实用户凭据与 binding 一致；不接受模型自报 | 内部接线，本仓消费并核对 |
| 工作状态 | read/CAS、命名空间、作用域、并发及同轮跨调用持续性 | 提供既有 SQLite 复用说明；内部选择部署位置 |
| 计划与证据授权 | 确认范围、请求摘要、数据上下文版本、binding、modelEvidenceAllowed | 内部实现；本仓提供正反用例 |
| 数据上下文与 DQE | 现有元数据和查询契约、治理配置、字段映射与执行结果 | 复用既有实现，按 A1 处理额外依赖 |
| 页面资产 | 新建、更新、当前资源读取、基线修订、回执 | 复用 KnownLifecycleHttp；内部配置真实服务 |
| 页面产物交接 | binding、operationId、artifactRef、ref、document/previewJson，接收成功及失败语义 | 本仓定义接口；内部自主实现程序通道 |
| 可选能力 | 页面参数、指标关系等的可用性与缺失行为 | 明确声明，不把缺少参数能力作为主流程阻塞 |

同轮绑定和数据库定位保持稳定，新创作轮次不得继续使用旧 contextRef。取消、过期的写权限仍需校验。不得把 sessionId 不加区分地替代所有轮次标识。

内部使用调用专属上下文/env 映射，不能修改主进程共享 os.environ 承载并发用户身份。若现有插件不支持该能力，内部回传接口限制，本仓不擅自改 Relay 核心。

完成条件：每个必需接口有输入/输出样例、失败码、契约测试及实现责任；未实现接口明确列出，不伪造生产实现。

### A1：审查并收敛结果字段契约派生链（优先）

使用 CONTEXT.md 中的“数据上下文快照”“查询定义”“结果字段契约”“查询字段映射”。SourceDescriptionPort 只作为代码定位名，不增加产品术语。

本轮初步发现：

1. data/executable_units.py 的 _field_contracts 已从数据上下文派生字段名、类型、角色、单位及可空性，并生成查询定义。
2. adapters/firstparty/dqe_http.py 已按 queryField 核对返回行中的字段及类型。
3. 平台 data/results.py 强制 require_source_description=True，导致 data/query.py 在执行 DQE 前要求额外描述提供方。
4. data/source_mapping.py 额外消费逻辑字段身份、投影身份、输出字段名、数值尺度及显示格式；这些不全等于现有字段契约，因此不能只删开关便宣布等价。

实施顺序：

- 先读取用户已提供的 DQE/语义查询示例、当前接口契约及映射代码，制作“所需信息 → 已有来源 → 派生规则 → 实际缺口”表；不先要求用户重复提供资料。
- 核查普通指标、维度、时间粒度、公式、重名/别名、空值、金额和百分比各自的映射及尺度规则。
- 已有事实足够的部分由确定性工具直接派生；仅在真实输出重命名或必要语义无法从现有契约得到时保留对应的可选 Adapter 扩展。
- 缺少单位、比例尺度或稳定身份时不得猜测；判断哪些是必须拒绝的缺口，哪些可保留 unknown 或不生成特定展示。
- 保留查询版本核对和真实返回行验证；空结果不能用于推断字段类型。不同 DQE Adapter 也需满足一致验证规则。
- 若取消现有强制提供方，回归稳定字段 ID、已有页面局部编辑及所有原有负向用例，不能以恢复旧顺序字段 ID 造成无授权页面差异。

完成条件：是否保留额外接口由来源核查得出明确结论；不再要求部署方为重复事实新建服务。真正缺失的信息逐字段列明，才提交内部核对。

#### A1 信息来源对照与待验证项

下表来自当前代码和仓内协议，不代表已经完成对用户所有历史示例的核查。实施时先定位并登记示例路径，再补充样本证据；只在确实找不到相关资料时报告具体缺口。

| 所需信息 | 当前已有来源 | 本期处理方向 | 尚需验证的具体问题 |
|---|---|---|---|
| 业务字段名及输出字段名 | Schema 元数据的 name；查询定义；DQE 实际返回的行键 | 生成 queryField，再以实际返回验证 | 各查询形态是否改变字段名；发现 aliases 不得作为输出名 |
| 字段类型与维度/度量角色 | 数据上下文中的类型及指标/维度声明；_field_contracts | 由程序派生，DQE 返回值验真 | 时间粒度转换、公式结果和空结果的类型依据 |
| nullable | Schema 元数据及数据上下文 | 保留声明，按返回值验证 | 公式当前固定为 False，是否符合执行契约，不能仅凭无空样例作结论 |
| label、unit | 元数据规范名称、单位 | 标签和单位复用已有声明，未知不补造 | 临时指标单位的声明/验证边界；单位不能替代数值尺度 |
| 金额/百分比尺度与格式 | 现有额外描述里的 scale/currency/defaultFormat；部分元数据治理配置 | 只消费有依据的语义，显示格式与数值尺度分别处理 | 比例是 0.15 还是 15；金额是否元；未知时不自动转换或套百分比/金额格式 |
| 稳定页面字段 ID | 现有 _field_contracts 使用顺序 ID；source_mapping 使用字段身份派生 ID | 保持已有页面 ID，确定新字段的可重复生成规则 | 重排、补字段、重名及不同投影不能使已有绑定漂移 |
| logicalId/projectionId/providerNamespace | 额外描述契约要求，当前基础字段派生未提供这套身份 | 审核哪些是稳定 ID 算法内部需要，哪些确有外部语义 | 不能仅为填满旧接口字段要求外部创建新服务；也不能将显示名冒充永久身份 |
| 数据上下文版本与查询绑定 | 现有 dataContextVersion、最终查询定义及其摘要 | 由程序计算并校验，属于内部一致性约束 | 重映射前后摘要绑定的查询必须一致 |
| descriptorRef/descriptorVersion | 额外描述契约 | 若内部派生不需要外部描述记录，评估是否退出必需输入 | 确认有无真实消费者，不保留无意义的占位值 |
| 实际返回行与空结果 | DQE HTTP 返回、_normalize_rows；共享行校验 | 保留全量已返回行验证，不依赖预览前若干行 | 非 HTTP Adapter、空数组、缺字段、空值和非法数值覆盖一致 |

A1 的收敛规则：已有可信事实足够时，默认走内部派生；仅有明确的外部字段重命名或未覆盖语义时，保留可选扩展。若证明某类查询无法安全派生，只限制该类能力并报告具体缺口，不恢复一个阻塞全部查询的笼统前置。

输出一份随本计划维护的核查结论，列明每项处理为“内部派生 / 可选扩展 / 真实缺口 / 不再需要”，并附对应测试。不得在未核查前将整项宣布为已解决，也不得仅删除 require_source_description 来使测试变绿。

### A2：部署就绪检查和最小装配示例

本仓维护公共依赖规则，内部包外入口调用它，避免两套检查漂移。

- 一次列出配置缺口、影响操作和修复位置；区分“已装配”“连接已验证”和“业务已验收”。
- 必须装配创作轮次提供方，但启动检查不要求此时已有用户轮次；参数能力仍可未配置。
- 静态检查不调用模型、不执行 DQE、不写页面；诊断不污染 MCP stdout，不输出凭据。
- 严格部署检查与显式协议发现模式分开；测试组合工厂保留负向测试能力。
- 示例只装配已存在的通用组件，内部特有接口明确留为待实现，不能以 mock 身份/授权/保存回执自动补齐。
- 修复 SQLite 连接释放，验证正常 oneshot 调用共享状态及 CAS；不建设跨节点恢复平台。
- Skill、工具、契约、快照按同一版本交付，包外 Adapter 保留；不能只覆盖 tool 后混用旧契约。

完成条件：干净环境可安装、加载包外入口并运行契约验证；完整缺配可诊断，同轮跨进程查询到装配的引用有效。

最小能力检查按操作说明依赖，不把所有参数简单合并为非空检查：

| 操作 | 必需条件 | 不应强制要求 |
|---|---|---|
| 协议发现/静态诊断 | 可加载的安装包、契约及诊断配置 | 已存在用户轮次、模型调用、业务查询或保存 |
| 新建轮次读取 | 有效轮次及工作状态 | 已有页面基线、分析计划授权 |
| 已有页面读取/配置调整 | 有效轮次、工作状态、真实身份、当前资源读取；修改另需保存能力 | DQE、参数能力 |
| 数据查询 | 轮次、状态、数据上下文及治理配置、DQE、匹配请求的计划/证据授权、A1 确定的字段派生能力 | 页面参数、前端显示回执 |
| 数据装配及保存 | 本轮可用查询结果引用、有效工作版本、真实身份及保存能力 | 重复执行同一查询 |
| 产物交接 | 已保存的精确产物、匹配引用、交接 Adapter | 前端卡片渲染和用户已看到页面 |

对外声明支持完整数据创建的部署，必须具备查询、装配保存和交接全部条件。操作级依赖区别不等于可以将缺预览或缺授权的部署宣称为完整可用。

### A3：Skill 错误分流及交接边界

- 补齐轮次、状态存储、授权提供方、保存能力及参数能力缺失的处理，区分部署未就绪与用户尚未确认计划。
- 基础设施错误不反复调用、不伪造 contextRef、不切换旧创作链。
- 未知保存停止重发，保留原提交以供核对；不在本批实现自动恢复。
- 保存成功但 Adapter 接收失败，分别报告保存和交接状态，不重新查数或保存。
- 明确 ready 表示 Adapter 按契约接收成功，不表示前端已显示。保留现有 Skill 占位符约定，不建设新的前端显示回执。
- 内部如果丢弃 structuredContent，可自主实现文件/IPC 通道；子进程 env 不能作为向父进程回传载荷的方式。完整产物不进入模型消息，交接必须匹配精确引用。

完成条件：Skill 轨迹符合错误语义；内部可按接口自主实现交接，不依赖我们编写其前端或插件代码。

### A4：本地验证与内部交付

复用既有测试 runner，不新建重复业务框架。

| 必需用例 | 验证重点 |
|---|---|
| 缺配与可选能力 | 一次报告必需缺口，参数未配不阻塞创建/调整 |
| 数据页面创建 | 已授权取数、正确结果字段契约、一次草稿保存、精确产物交接 |
| 纯配置调整 | 从已保存页面建立新轮次，仅修改授权字段，不执行 DQE |
| 新增数据组件 | 保留已有内容，只执行新增授权查询 |
| 每次工具调用新进程 | 查询引用、工作稿、预算和提交记录在正常同轮调用间持续可读 |
| 错身份/旧轮次/过期修订 | 明确拒绝，不扩大权限或自动重放 |
| 未知保存 | 保留提交并停止重发，不承诺自动恢复 |
| Adapter 接收失败 | 已保存状态不丢失，不重复保存，不声称前端已显示 |
| 字段派生回归 | 真实字段名、类型、单位/尺度、公式、空值、稳定 ID 与局部编辑一致性 |
| 独立分发 | 支持的安装/复制方式在仓库外可运行，接口和参考链接闭合 |

按项目验收规则执行必需无模型预检、确定性主流程及适用的真实 DS 验证，分别报告 not-run/blocked，不把本地替身当内部联调。最终 document.json 的数据与差分仍需验证；本批不要求内部浏览器、卡片或显示回执作为本仓交付条件。

交付：固定版本包及哈希、Adapter 接口说明、契约用例、最小装配示例、就绪检查、Skill 更新、验证命令与脱敏回传模板。用户同步后内部自主实现 Adapter 并执行接口/主流程验证；尚未执行标记 not-run，不阻塞独立的本仓工作。

#### A4 分层验收与本地执行要求

| 层次 | 本批通过条件 | 明确的证据边界 |
|---|---|---|
| 无模型预检 | 实际注册工具/Schema 与 Skill 一致，参考齐备，模型请求为零 | 不证明模型行为 |

| 真实 DS | 受改动影响的创建、调整及错误分流有实际轨迹；失败与重试完整记录 | 外部模型不可用时记 blocked，不能以脚本代替 |
| 页面产物 | 可消费 document.json，字段契约、实际数据及局部差分正确 | 不要求内部前端配合 |

验证脚本委托现有 runner，最终报告包含实际命令和退出码。实现阶段按最终改动范围运行测试清单检查、相关 Python 回归、契约生成与检查、Bundle 检查及 git diff --check；涉及字段派生时增加对应 TS/运行时一致性验证。新增测试文件必须登记到既有测试分类。

本期不预先固定新的命令名、接口错误码或 Bundle 版本号；这些由 A0 和兼容性评估冻结，并同步文档、配置与实际测试，避免计划中的示意名称被当成可运行入口。

挂起不改变最低正确性：正常调用不能丢状态；不确定写入不能自动重发；未核对提交不能在会话结束时无条件删除。若当前部署无法满足这些最低条件，记录明确阻塞，不把高级恢复方案拉回本期隐性范围。

## 5. 顺序与完成标准

实施顺序：A1 信息来源核查 → A0 最终接口冻结 → A2/A3 → A4。已经明确的公共错误处理与存储资源修复可独立推进。

本仓完成以接口、必要实现、本地验证与交付材料齐备为准，不要求本地连接内部环境，也不要求本仓写完内部特有 Adapter。内部完成以用户同步后获得的接口及主流程证据为准；前端后续流程由内部自行验收。

本计划只记录范围和执行安排；尚未实施代码变更。实施前记录工作区状态，保护其他任务修改。修改契约真源后生成副本与锁文件，并在最终文件树运行必要检查。
