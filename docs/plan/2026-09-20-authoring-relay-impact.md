## 2. 对上一版判断的纠正

1. 实际流程已经由系统注入完整 compose_page_result，模型只传少量业务参数。此前将其描述为模型搬运完整 document 不准确。
2. “程序通道交付”在此部署中具体依靠预览工具产物与最终响应占位符完成；不能直接用理想中的 artifactEnvelope 分流替换现有机制。
3. 保存草稿与准备预览可以分属不同内部职责。用户认可保存内部化，不等于认可删除 Relay 需要的 page_metadata_emit_preview。
4. Agent 与 MCP 在图中分栏仅为解释内部职责。统一请求进入同一个 Agent 执行流程，不要求工作台额外先向 MCP 发送上下文。
5. 数据修改重新进入共同分析流程，不只是补一个查询；最后局部更新以保留不受影响内容。

## 3. 必须保留的 Relay 契约

```text
{{RESPONSE_START}}
{{PAGE_METADATA_PREVIEW_JSON}}
```

前者是 Skill 声明的响应开始标记；后者由系统替换为完整预览内容。模型必须原样输出，不能自己生成 JSON 替换，不用本地文件或其他占位符代替。进展播报与最终协议输出分开，沿实际 Skill 的播报机制。

现有调用顺序：compose 产物 → 系统注入保存工具 → 保存成功 → 系统注入预览工具 → 得到预览卡片 → 模型输出占位符 → Relay 替换 → 工作台渲染。

目标调用顺序：compose/edit 内部保存 → 系统持有本次产物与回执 → 系统注入现有预览工具 → 得到预览卡片 → 模型输出同样占位符 → Relay 替换 → 工作台渲染。

迁移要求是保持可消费的产物，而不是盲目保留旧字段全集。compose/edit 的统一产物如何映射到现有 compose_page_result 注入键，须查实际注入实现后确定；不可假设 Relay 已支持 edit 产物。产物关联至少要防止跨页面、跨请求和过期结果串用，并对应本次确认的保存修订。

## 4. 改动影响矩阵

| 区域 | 保留 | 目标改动与限制 |
|---|---|---|
| 工作台入口 | 问题、页面、选中目标；所有用户交互 | 同一次请求进入 Agent；不另建上下文预注入操作 |
| PlanAgent / 语义摘要 | 已有指标、维度条件、时间等输入 | 核对有效性后复用，不机械重复 Lab 解析；不宣称完全替代发现 |
| create 工作流 | 诉求检查、进展播报、精确 description、错误反馈 | 增加计划审核与查询后分析；删除独立草稿保存调用；保留预览工具与两个占位符 |
| 数据修改工作流 | 当前页面和选中范围 | 提炼需求后复用完整分析流程及计划审核，最终 edit 局部更新 |
| 样式修改工作流 | 局部操作 | 不查数、不整页重建；保存后走相同预览协议 |
| compose/edit | 确定性构造和整页校验 | 单份工作稿、不可变提交快照、内部草稿保存；partial 保存有效内容 |
| 保存适配 | Java 资源标识、基线修订、成功回执 | 集中复用；未知结果停止重发；不向前端交第二次保存任务 |
| Relay | 产物注入、预览卡片、占位符替换 | 核对新工具产物来源与作用域；不要求改造成独立候选提交编排器 |
| 页面产物 | document、previewData、previewJson 的区别 | document 不带查询结果行落库；previewJson 带本次有效 initial，仅预览 |
| 会话状态 | page_metadata_id、revision_id、必要 draftSpec/draftPageId | 不把完整 document 塞入模型上下文；跨会话计划保存挂起 |
| 发布 | 现有发布意图、维度实例选择及 update_page_metadata | 不在本轮擅改公共参数提取、发布版本或召回规则；计划确认不能误触发发布 |
| 普通问数 | 临时页面态 | 不因平台工具内部保存而自动落库 |

description 的指标/维度清单应与实际交付内容一致。partial 时不能把失败、未加入页面的指标写成已经支持；保留明确未完成项供用户理解。具体生成位置与字段映射在实施契约中确定。

## 5. 三种状态必须分开

| 场景 | 行为 |
|---|---|
| 构造全部或部分成功，页面合法 | 保存有效修改；partial 明确完成项与失败项 |
| 构造全失败、无变化或整页不合法 | 不新增保存，不假装有新草稿 |
| 保存被拒绝或冲突 | 保留工作，说明未保存，按原因处理 |
| 保存响应超时或无法核验 | 保存状态未知；不重复发送、不换操作标识重试 |
| 保存成功、预览注入或替换失败 | 告知已保存但预览失败；仅修复对应产物的交付，不重新保存 |
| 预览内容与保存的定义或修订不匹配 | 不展示为该草稿的成功预览；定位产物关联问题 |

预览与保存一致性针对页面定义及绑定关系；previewJson 比 document 多本次数据实例，不能用两者字节完全相等作为判据。维度实例值是否保留属于既有发布选择，不是 initial 数据行是否落库。

## 6. 实施前核对与验收

待核对事实：Relay 占位符解析和卡片缓存的生命周期；compose_page_result 的选取与注入规则；edit 产物如何接入同一预览链；发布跨轮时如何定位已保存页面而非旧 compose 响应；Java 字段、维度裁剪和公共参数结构的真实兼容性。不因这些事实尚待查证而新建一套协议。

验收必须覆盖：首次构建、数据修改回流和计划审核、样式修改零重复取数、partial 保存、保存未知不重发、保存成功而预览失败、交错请求不串预览、两个占位符准确输出与 Relay 替换、initial 不落库、计划确认不触发发布。源码测试不能代替真实 Relay 工作台渲染验收。

本轮只更新设计文档，不改正式 Skill、MCP 注册、Java 接口、Relay 或发布行为。结构性方向已收敛，后续以接线事实核验及实现为主。
