## 1. 结论与范围

保留现有 Skill 入口和工具，按任务选择最短路径。模型的共同主线收敛为：**确定本轮改动 → 必要时取得数据证据 → 组织表达与变更 → 应用并交接结果**。页面先行与数据先行保留各自起点，沿同一工作副本接续；局部修改直接复用已有可信部分。

前序流程图的三个前置检查是工具内部的职责位置，不新增三个模型步骤、MCP 工具或管理器：字段描述映射时核对语义；查询结果返回前核对格式；页面变更应用前核对绑定与显式呈现。页面元数据和可用预览继续兜底。

本轮只写设计与流程图。Skill 正文删减、工具行为修复、知识生成、分发和真实接入分别在后续实施时验收。权限、计划授权、当前工作副本、版本竞争、单次保存、unknown 恢复和精确产物交接继续沿既有契约。

物理文件多不等于模型每次都读取全部内容。2026-11-02 静态统计：Platform 根入口54行、4,747个 UTF-8 字节；完整数据 Report 相关的11份候选阅读材料合计56,794字节。11份为根入口、create、data-analysis、tools、discovery-query、numeric-format、execution、reading-design、scenarios、report-composition、delivery；其中含条件参考，不表示全部必读，更不是实测 token 或耗时。

MC、Platform 和 local 的独立安装需要生成副本。减负应消除重复维护与重复加载，保持产品知识完整可查，不能靠删除分发必需的 Schema、示例、校验器或诊断降低文件数。

历史记录中的数据比例呈现分析实现位于独立工作树；当前 `tools/mc-content` 没有 `analyze-presentation.mjs` 或 `presentation-policy.json`。它不算当前已接入能力。后续先核对该分支与当前格式处理的职责再复用，不在本文假设它已生效或再造一份策略实现。

## 3. 目标职责结构

| 归属 | 保留职责 | 使用方式 |
|---|---|---|
| Skill 方法 | 理解本轮需求、保留已确认意图、选择所需能力、组织页面、解释真实回执和缺口 | 根入口及命中的任务说明；保留当前两个安装入口，不新增总控 Skill |
| MC 产品知识 | 完整协议、组件能力、数据语义、错误解释、可选阅读组合与例子 | 从当前工具 Schema、精确主题或安装内参考按需读取；事实从产品真源生成 |
| 共享确定性能力 | 字段/查询相容性、格式默认与检查、绑定/依赖检查、页面装配与校验 | 收敛到现有数据与页面用例；小 Interface 后面承担检查和修正，调用方不逐项调闸 |
| 集成与宿主适配 | 身份/权限、可信轮次与工作副本、执行环境、持久化、保存恢复和产物交接 | 沿现有 Adapter 和程序通道；能力缺失返回实际状态 |

业务单位、币种、原始刻度和指标含义来自可信证据；`defaultFormat` 是展示建议。显式显示要求或已有页内设置只有在语义相容时才优先于产品默认；显示选择不转换查询原值，也不改变指标身份。

现有部署可以注入完整工具 Schema 时，不要求模型再读一份完整参数手册。只有参数疑问、未展开约束或实际 Schema 不足时读取精确契约；Schema 不可得则报告对应调用缺口，不能假定支持。

共享方法若值得跨入口复用，沿 M1/M5 冻结单一作者源和固定投影；先合并确实重复的方法段落，再按证据决定目录。独立安装内部包含所需正文，不在运行时跨仓读取，也不把全部方法塞入 MC 产品协议。

## 4. 按任务选择最短路径

| 任务 | 模型要做的事 | 需要读取 | 完成依据 |
|---|---|---|---|
| 已有配置问答 | 读取必要配置，回答实际返回内容 | 根入口与命中属性；无需新建/取数/模板说明 | 精确配置证据；未返回内容保持未知 |
| 改标题、列宽、顺序或已有可信呈现 | 识别目标与影响，提交局部变更 | 命中的编辑操作和相关属性；不加载新建、发现和整套范式 | 操作回执与受影响部分验证 |
| 页面先行补接数据 | 保留结构意图，提取缺失用数，确认映射后受控接数 | 页面用数/映射任务片段和受影响契约 | 兼容的字段、粒度、期间、行身份、依赖和真实执行证据 |
| 数据先行新建/新增分析 | 澄清有影响的口径，取证据，按问题组织表达 | 数据任务片段；需要布局启发时选相关参考 | 问题覆盖、证据、合法变更及实际交接状态 |

两种创作逻辑不是多一层强制流程：在已有页增加一个分析问题可以数据先行，已生成页固定布局后换数据可以页面先行。已确认事项和仍有效的查询结果继续复用；切换不新建会话或重跑全页。

线上页面先行补接数据仍依赖 M3/M4 的受控能力；本表是目标路由，不表示当前 MCP 已支持全部源/字段/绑定修改。本地 JSON 编辑继续使用独立脚本与目录内知识，不伪装成线上受控写入。

## 5. 前置检查怎样收进现有工具

| 位置 | 工具内部职责 | 模型只需要知道 |
|---|---|---|
| 字段描述映射，查数前可判断的部分 | 核对单位/刻度证据与格式建议；确认百分数值还是小数比例；按本次约定检查非 Tokens 的百万格式 | 该字段可用、未知或冲突，以及具体原因；无需手动运行一个“语义闸工具” |
| `query_data` 返回前 | 形成语义相容的格式，核对 %、精度、非零舍入和重复缩放；完整性只限制需要全量分布的推断 | 可使用的字段/格式证据、覆盖缺口及实际调整 |
| `compose_page` / `edit_page` 应用前 | 核对实际支持的字段绑定、期间/单位关系和显式格式覆盖；再沿原装配、整页校验、原子操作和保存路径 | applied/failed/skipped、adjustments、具体问题与下一步 |
| 元数据及可用预览 | 检查最终继承/覆盖结果与实际呈现；遗漏回溯到上游职责 | 结构、数据、视觉、保存分别有哪些证据 |

能够由已确认事实和已约定默认值唯一确定的格式错误，由程序修正候选并记录调整；用户明确设置与业务语义冲突、单位/刻度不清或存在多个业务解释时，返回缺口，不擅自改值、改口径或静默覆盖用户设置。partial 与阻塞范围沿既有独立操作和依赖规则确定。

本地直接写 JSON 不经过公共 `query_data`。后续在现有本地分析/校验入口复用同源语义与适用检查，并保留需要数据证据的输入；不能仅改 Python 后就删除 local 的兜底说明。没有单位证据时，结构校验不宣称语义已证实。所需的跨入口证据传递在 M1 定义，不新增正式页面 Schema 的创作状态字段。

精度规则在现有格式能力内集中选择；本文没有裁决全产品统一保留几位，也不创建按场景不断膨胀的配置矩阵。先处理本次实例，再按真实业务需求收口默认值与显式覆盖方式。

Relay 的确定性前置检查只依赖实际能取得的字段证据、数值、完整性和组件声明。DOM、屏幕尺寸、截图属于有运行时环境时的呈现验收，不进入 Relay 普通创作的必需输入。

## 8. 对本次错误的完整走读

1. 上游描述若有可信百分比刻度，即使提供 `defaultFormat=number`，也先识别为显示建议与正常百分比展示不相容；查明是否有明确原值展示意图。单位和刻度缺失时先补可信证据，不按“同比”名字自行断定。
2. 取数返回20/29行时保留覆盖缺口；已经确认的百分比语义不受行数影响。自动尺度选择若需要全量分布，则停止该推断或使用已确认的显示要求，不清除单位。
3. 收入字段的 `compact-million-1` 在映射或格式决策处处理；按本次业务约定仅 Tokens 允许百万。不等到模型排完两张表才让它找错误。
4. 模型取得可用证据后自由安排收入与变化值、图表或明细；它不需要知道格式函数的分支顺序，也无需先选某张编号卡。
5. 应用变更时核对最终绑定与显式覆盖。失败只返回相关字段/组件；查询未变就复用已有结果。

当前粘贴页面和只读函数探针证明页面中确有普通 number 与百万配置，且现有分支存在上述风险；缺少本次完整调用轨迹与旧版包身份，尚不能证明线上生成的唯一根因。走读是目标行为，不是修复验收。
