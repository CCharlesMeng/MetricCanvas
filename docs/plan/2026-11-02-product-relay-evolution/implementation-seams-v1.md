## 1. 实施顺序与范围

Relay 接入线先处理**独立版本采用、唯一工具注册、逐请求工作副本输入、程序产物交接**四个现存接缝；产品线可独立启动**呈现正确性收敛、共享分析核心和多槽表达补齐**，再接增量接数。保留现有公共用例，暂不新建 mc-tools 包或大搬目录。产品线不等待私有环境提供全部运行证据。

两线共同遵守：**普通任务的模型阅读和步骤应减少；确定性正确性在现有工具内部承担，模板按需查阅。先验证工具承接，再删兜底说明。** 架构图中的职责不能变成新公开工具、强制模型闸门或总控 Skill。

```text
两种 Skill 策略（页面先行 / 数据先行）
    └─ 共享核对/映射/修复方法 + 各自流程顺序
          ├─ 本地 CLI Adapter ──────────────┐
          └─ Relay 唯一工具绑定/可信调用 ───┤
                                            ▼
                产品分析核心 + 公共 discover/query/compose/edit/parameters
                    （内部承担语义/格式/绑定检查与明确回执）
                                            │
                       共同 Schema / 校验 / 数据执行 / 引擎
                                            │
                    版本化 Port（既有 AuthoringAdapters）
                       ├─ 公司 Java/DQE/元数据/存储 Adapter
                       └─ Relay 上下文 / 文件桥 / 卡片 Adapter
```

Relay 报告的 temp_subprocess、SQLite、文件交接是具体 Implementation 线索，不能改变公共 Interface 的身份、引用、CAS 和副作用规则。MCP 进程运行在 Relay 机器上，也不改变产品用例所有权。

## 2. 接缝 A：内容采用与真实工具注册

### A1. 版本组合

必须分别记录以下现有事实，不新增一个万能版本号：

| 事实 | 权威源/采集方式 | 消费要求 |
|---|---|---|
| 产品/作者工具来源 | 公共完整提交或冻结发行摘要 + 私有 diff | 区分上游与 fork，不以共同的 0.3.1 版本号认定字节一致 |
| 页面读写/校验能力 | 活动 contract-lock、实际 schema.json、catalog、validator/bridge 及引擎来源 | 版本标签、实际表达和运行行为共同对账；旧页可读/可迁移/需人工分开 |
| 工具契约 | 实际 list_tools 完整 inputSchema、描述及摘要 | 当前函数定义、模型可见描述和验证器一致；不从报告概要生成 |
| MC 内容 | 完整 manifest、alignedWith、内容/脚本摘要 | 配套产品组合通过既有 check_bundle/MC 检查；不能只升级 mc-content 子树 |
| Skill 方法 | 作者文件/引用清单与摘要 | 保留 Relay 改良；产品事实来自上述实际组合，方法正文不被生成物覆盖 |
| 内部 Adapter 与 Relay | 内部提交/配置身份、Interface 版本、装配清单 | 私有值和凭据不进入公共内容；其字节不随公共同步覆盖 |

当前产品已有 `check_bundle.py:validate_mc_content` 校验 alignedWith 和资源摘要，本轮整体检查通过。先让部署流程采用这些现有检查，不为相同职责新建第二个通用兼容框架。若部署裁剪目录，显式声明裁剪与剩余检查范围，不能把子集称为完整 Bundle。

报告中 6.54/6.77/6.11 的混合组合需要按依赖整体处理：先恢复可信上游基线，定向重放已核对的内部扩展，验证旧页面与接口。不能仅把版本号改成 6.77，也不能让所有消费方降到 6.54 来遮蔽差异。

### A2. 工具名与来源

- 一次 Agent 装配中，一个可见工具名只有一个确定提供方。`tool_mc_query/compile/inspect` 保留哪个入口，由真实参数、输出、程序交接与 loader 能力决定；不先删除其中任意一套。
- 首选保留现有对模型工具名，配置上排除重复提供方；若 Relay 必须同时暴露两个语义不同的入口，再显式命名并同步 allowed-tools、工作流和实际注册。不能依赖加载顺序碰巧覆盖。
- 产品提供公开 MCP 描述和 MC 确定性脚本；Relay 负责唯一绑定、可信上下文与程序回执。公开注册描述随产品更新，Relay 不维护冻结的嵌套业务 Schema。
- 新反馈静态确认 list_existing_page_urls/submit_ai_summary_body 不在十工具注入集合：I02 扩展可信供给、保留 Gate，不选择门禁豁免。tool_mc_* 三签名不接受 context_ref，但 inspect 读取程序产物，仍须以可信上下文核对作用域。

**验收**：导出实际模型可用列表及提供方，每个名字唯一；同一合成 query/compile/inspect 输入命中预期 Implementation；allowed-tools、注册、包装和返回预算对账。公共离线 list_tools 通过不替代 Relay 装配验收。

## 3. 接缝 B：会话、轮次和工作副本输入

沿用现有 `DialoguePageRequest`、`CurrentAuthoringTurnPort`、`PreparedAuthoringTurn` 与公共 Gate，不新造会话状态系统。

| 身份/状态 | 持有者与要求 |
|---|---|
| sessionId | Relay 持有会话；可以稳定，但不能单独充当逐请求隔离依据 |
| requestId / runId / turnId | 可信 Adapter 映射到当前请求的完整 binding；requestId 变化、取消和迟到要可判定。报告缺完整映射，不能仅因 turnId 稳定就认定漏洞或正确 |
| 当前工作副本 | 工作台锁定并发送完整 documentJson、documentSha256、persistedRef；Relay 转换为当前轮次基线，不能改为读 Java 旧页面覆盖未保存修改 |
| 旧 current_match 模式 | 保持现行旧接入语义；用显式模式与当前工作副本模式区分，不强行套同一远端读取前置 |
| 工作稿、预算、查询、冻结提交 | 公共规则负责；StateStore 具体存储由内部 Adapter 提供。短进程不得落回内存导致跨调用丢失 CAS 或 unknown 记录 |
| 查询结果引用 | 继续由 QueryResults.require 重核完整 binding、元数据版本、策略、授权、可用状态；不复制旧引用来“恢复会话” |

CurrentAuthoringTurnPort 的文件桥与 StateStore 是两个端口。新旧报告分别声称 SQLite/文件桥、session/trace 派生，实际 store 工厂和派生函数尚未统一根目录证实；原子文件写+Gate 不证明 CAS。版本 6.77 在 Relay 内容中的存在性也有前后冲突，三项均按具体源码/摘要消歧，不覆盖历史证据。

**必须回放**：同 session 连续两次请求、两个页面、人工未保存修改、身份变化、并发、取消后迟到、进程退出重启、保存 unknown。分别验证何时继续已有业务依据、何时重新取数；不把拒绝全部续轮当隔离完成，也不把全部复用当接续完成。

## 4. 接缝 C：模型摘要与程序产物

公共 `artifactEnvelope`/精确 preview 语义保留。报告称 Relay 丢弃 structured_content，因此设计必须明确当前真正的程序承载路径，不能假定原字段已被接住。

- 产品：在既有状态/预览 Port 中输出与 binding、operationId/artifactRef、页面内容精确关联的产物；检查原始 inspectionSpec 与 compileInput，不能回退“最新预览”。
- Relay：可信程序取得完整产物，完成现有 pangu/data-agent 卡片、占位符或 SDK 更新；模型只消费有界摘要和精确引用。若继续用文件桥，写入、读取和回执均绑定同一请求与产物，不能扫描全目录后直接信任命中。
- 暂不删除 spool：先建立替代交接并验证两种卡片、流式和最终响应，才收掉多余分支。gzip/base64 不改变数据仍经过模型 content 的事实。
- 取消/会话结束可以清理可重建预览缓存；保存 unknown 的冻结提交记录按恢复协议保留，不能用统一 TTL 清掉所有状态。

**验收**：压缩预览全文不进入模型；错误/过期/异绑定引用不能采用；精确新产物只更新当前页面；取消和迟到不替换已有页面；两类卡片均保留正确业务信息；unknown 可查而不重发保存。

## 5. 接缝 D：共享分析、映射与变更

### D1. M1 的最小业务连接

扩展现有 DataUse/分析报告与公共查询记录之间的联系，按下表冻结实现不变量。记录只属于创作期，不写进 PageDocument 的未知字段。

| 对象 | 必须保留的事实 | 明确不承担 |
|---|---|---|
| 分析输入身份 | 当前完整页面字节/摘要及其产生方式、Schema 摘要；材料存在时记录材料摘要；线上关联当前 binding/workVersion | 不混用文件原始字节摘要和另一种序列化结果，不把相同 pageId 当同一基线 |
| 页面用数位置 | 稳定页面/组件/源/槽/字段身份、实际 pointer；嵌套容器/子表上下文；读取范围与完整依赖闭包 | pointer 不是永久主键；选中组件不授权忽略共享消费者 |
| 用户保留意图 | 已有组件身份、结构/列/格式/交互及明确固定项；可变范围；缺口与决定来源 | 不从模型一句“保留布局”推导所有配置已保留 |
| 取数需求与映射 | 口径、单位、粒度、期间、筛选/参数、行身份、完整性；用数位置到取数单元及输出字段的对应 | 名称命中不等于语义一致；一个组件可以消费多个取数单元/源 |
| 证据 | 材料引用、元数据事实、真实请求/响应记录各自关联；执行证据使用程序持有的现有结果记录 | local 分析报告继续 execution:not-run，不能由模型改成 ready；不再复制业务行建第二个缓存 |
| 呈现依据 | 可信单位/币种/原始刻度、提供方格式建议、用户或已有页面的显示意图、程序格式决定及出处分开；未知明确保留 | defaultFormat 不自动成为业务事实；不完整结果不抹去已知百分比语义；不凭名称猜比例刻度 |
| 候选变更 | 绑定确切基线/workVersion、目标和已核对结果；列出受影响源/组件/引用；整页验证 | 候选不是保存回执、不是授权凭据；过期时不自动套在新基线上 |

同一逻辑适用于两个方向：页面先行从用数位置生成需求与映射；数据先行从需求/结果形成页面并回填用数位置。切换时接续同一工作副本与仍有效依据，引用重新经过现有 Gate。

M1 的字段/版本修改先在现有报告/请求相关类型旁落具体实现和向量，再选择最小序列化格式。表格是不变量规格，不宣称已有一个已注册的新协议。

### D2. M2 的第一批文件范围

首批只提取已有只读扫描与读取范围，不同时新增保存和语义匹配：

1. `tools/scripts/local-authoring-data-analysis.ts`：将 scanPageData 及其字段/容器/子表扫描职责提为共享纯 Module；原导出继续兼容，draft/check/material 检索和 Node hash 各按现有职责保留。
2. `tools/scripts/local-authoring-data-scope.ts`：共享读取闭包，保留全局诊断、筛选/参数及输入不变性；不把 scope 当授权或缩小最终校验范围。
3. `tools/scripts/local-authoring-data-cli.ts`：保留文件/manifest/退出码；共享核心以显式页面和 Schema 输入执行。线上先用已有 Node 程序桥，不宣称直接浏览器可用。
4. 生成/打包沿现有 projection/export-authoring-contracts 流程；local 安装目录依赖闭合。待工具 Interface 和输入冻结后再同步 MCP/Relay 入口，避免先做无人消费的公共接口。

**退出**：原 CLI 与新程序调用同输入同完整有序输出；原对象不变；不取数/写页；子表/嵌套/多槽/共享消费者被覆盖；独立安装通过。编码前后测量修改和所有新增函数，不能以文件移动算降复杂度。

### D3. M4 与 T1 的区别

- M4 首条切片保持：普通查询源的受控替换，保留已有合法表格身份、布局、列和交互，核对所有消费者。新增/删除组件的流程继续可用，但不作为此验收的替身。
- T1：产品补齐受控多槽表格创建/编辑表达，验证每槽引用、rowKey/列槽归属与期间/完整性。先在产品补齐并同批生成，再测 Relay 采用；不等待大搬目录。

### D4. 现有工具承担呈现正确性，随后做流程减法

纳入[「优化 mc-content 创作规范」](codex://threads/01a19b3f-9a13-7c42-92c8-c7d13ddc4a6d)的已讨论结论。首批处理可复现的百分号、精度、百万误用问题，不借此建立全场景配置矩阵。

1. `data/source_mapping.py` 及描述适配处：分清可信语义和显示建议，保留单位/刻度及其来源；有冲突返回具体字段，不改写查询原值或猜测指标含义。
2. `data/field_presentation.py` 及现有查询返回路径：已有 defaultFormat 也核对语义相容；结果不完整只限制依赖全量分布的推断，不能让已确认的百分比丢掉 %；微小非零值不得靠改成无单位 number 掩盖舍入问题。
3. `compose/edit` 的现有应用/校验处：核对最终实际绑定、默认与显式覆盖。字段/表格列/卡片/图表轴、标签、Tooltip 的有效格式应符合相同语义；格式修复不改变粒度、源身份、业务值或保存循环。
4. local 直接写 JSON 的路径不经过 Python query_data；复用产品真源和适用检查，通过现有生成/独立工具提供，同一行为向量核对两入口。缺少业务证据返回未证实，不宣称静态校验已完成语义验收，也不在仓外新增 Python/开发仓依赖。
5. 工具证据充足且默认值唯一时，修正候选并返回调整位置/原因；显式用户设置与语义冲突或缺证时报告缺口。保留相容的已有设置，partial/保存仍沿既有用例，不增加整页采用闸门。

“百万仅用于 Tokens”按用户明确的本轮呈现约定落实。原始数据已按某数量级计量是可信输入事实，不能为满足显示规则篡改它或再缩放；Tokens 语义与原始尺度都须有依据。精度按字段用途及现有格式能力处理，当前未裁决所有字段统一几位；采用新格式能力须另按协议验收，不自行加枚举。

已只读确认独立工作树 `presentation-knowledge/DataDashboard` 中存在未提交的 `analyze-presentation.mjs`、`mc_presentation.py`、`presentation-policy.json` 及 P01–P04 说明。该策略 JSON 当前是单系列柱图轴空档策略，不能当作百分比/所有格式问题已经修复。实施先核对可复用函数、依赖与向量，按需吸收，不能整包覆盖当前真源或再建同类策略。此工作树的代码未在本轮运行或迁入主工作区。

随后沿[文件处置表](skill-flow-simplification.md#7-文件处置清单)删减生产方法正文：根入口只选任务和处理回执；MC 保留完整协议与可选组合；模板不要求先选编号或固定章节。对应工具尚未覆盖的 local/Relay 分支保留必要兜底，不能提前删掉提醒。

**退出**：完整/部分结果、已设 number 的百分比、未知刻度、已缩放值、微小非零值、非 Tokens 百万、相容/冲突显式覆盖均有确定结果；原始值和无关配置不变。标题/列宽修改不读新建/查数/模板；默认路径不新增模型工具步骤；记录实际读取、调用和修复轮次，静态字节不代替 token 或模型效果。Relay 普通创作只需要其可取得的证据，DOM/截图归有运行时环境的工程验收。
