## 1. 迁移结论与第一条纵向切片

优先复用已有页面分析、公共查数、操作批处理、工作副本和生成分发链。主要新增工作是连接这些能力：页面用数需求与真实查询结果的映射、受控地修改已有页面的数据对接、保留用户意图，以及在两种策略之间继续同一页面。

第一条切片限定为：**一个已有合法表格，保留页面/组件/字段 ID、列配置、布局和交互，用同粒度且字段角色/类型兼容的已验证查询结果替换该表对应的普通查询源。** 核对所有共享消费者、筛选/参数及依赖；任一受影响位置无法解释则返回具体缺口，不能只更新选中表或重建整页。

这条切片先证明页面到数据闭环和策略接续。新增字段/组件、跨源组合、父子表和复杂期间映射在后续能力批次扩展；不把首批支持扩大为全部合法 Schema 的在线创建/编辑能力。

## 2. 可迁移范围与建议落点

下列新落点是逻辑职责建议，未创建包或注册接口。实施先提取 Interface 与依赖，再决定是否移动文件；现有 CLI/Skill 入口在迁移中保持可用。

## 3. 实施任务、依赖和退出条件

### M0：冻结迁移基线与失败台账

- 实施前 fetch/核对最新 main、工作树与并行改动，使用干净且范围明确的检出；本次探查没有执行 Git 交付，也未校验远端。
- 冻结本文涉及的源与派生清单、实际 MCP 输入摘要、Skill/Schema 版本、测试回执和来源指纹。不得把当前并行修改混入生成物。
- 对本轮公开回归和既有失败分型：产品行为、陈旧测试输入、缺失页面路径、生成漂移、环境依赖分别处理。修测试时先核对产品约定，不直接重录错误输出。
- 已登记来源输入中有两个内容变化；生成器还读取 `pages/` 全文件，存在图像等输入。先核对真实生成分母，再经官方导出生成，禁止手改来源摘要或简单删除输入消除 stale。
- 补充公共源、Relay fork、安装副本、实际加载与模型可见注册的差异台账，完整 inputSchema 与文件摘要逐项关联。内部 firstparty/Relay/storage 具体实现继续受 ownership 保护；共享接口不拆成两份自由修改的 dataclass。
- 同时核对独立 `presentation-knowledge` 工作树的作者规则、分析程序与行为向量；其未提交实现不是主工作区已生效能力，先确认可复用范围与新呈现约定，再按职责合入，避免重复实现或整包覆盖。
- 当前接收件是静态报告：15 个入口中的 9 个名字与本仓实际注册重合；报告 JSON 的 6 处未解析引用、2 处说明占位使其不能用于精确兼容闸门。先采用完整产品基线及原始契约/私有差异，不能降级 MC 或只改版本号遮蔽 6.54/6.77/6.11 混合组合。

**退出**：基线可复现；每个失败有原因、责任位置和关闭条件；原作者文件、内部 Adapter 和并行工作保留。M0 未完成时不把产物作为正式发行组合。

### T1：多槽表格的同步验证支线

依赖 M0 的干净产品基线；可与 M1–M5 分开推进，不以大规模目录搬迁为前置。先复现页面/引擎支持而工具输入拒绝，再确定受控多槽装配的最小接口、每槽结果证据、行键/字段/期间与完整性规则。沿实际 compose、section_editing、结果组件路径实现，不照存量材料的文件表盲改。

同批核对产品实现、完整工具 Schema/注册、MC、local 和 Relay 工作流；Relay 调度可不手改，但实际描述与缓存必须更新并验收。创建/编辑与召回分开报告；外部 recall/plugin 未取得时保留接入验收项，不阻塞本地产品修复。缺行、重复键、失败槽、空集合/级联、分页和过期结果均按产品约定核对。

**退出**：新能力有产品可观察场景和正反例，单源无回归，工具/实现/知识同批发行；Relay 实际采用和召回若未验证须明确标注。T1 不代替 M4 保留既有表格意图的增量接数验收。

### M1：冻结最小创作连接契约

依赖 M0。扩展已有 `DataUse`、报告 formatVersion 与取数单元之间的连接，不另造通用 Page Schema 或创作会话系统。

需要明确：

1. 页面位置与稳定组件/源/字段身份，绑定当前基线摘要；数组位置改变后重新核对，不能把旧 JSON Pointer 当永久身份。
2. 用数需求的口径、单位、粒度、行身份、时间、筛选/参数和完整性要求；缺少信息显式未知，不能从标签/样例猜测。
3. 材料引用、元数据确认、真实执行、关系证据分别有来源；`matched` 不自动等于执行成功。
4. 字段映射、意图保留约束、共享消费者和影响闭包；候选变更绑定基线和精确结果记录。
5. 查询引用继续受当前身份/工作空间/轮次、元数据版本、验证策略和授权约束。跨轮次接续须由可信程序重核或重新取数，不能直接搬旧 resultRef。
6. 业务单位/币种/原始刻度、上游格式建议、用户/已有页显示意图和程序决定的出处分开；材料匹配不能证实百分比刻度。已有 defaultFormat 不自动等于可信业务事实，部分结果不清除已知单位。

**退出**：用已有页面和实际受控查询夹具完成双向关联正例/反例；数据先行生成页能够形成页面先行的需求记录；中间状态未进入渲染 Schema。新增字段/版本与现有消费者的兼容方式有明确表。

### M2：提取共享脚本并保留本地适配

依赖 M1；不必等待线上 UI。

- 从文件路径、manifest 读取、进程退出和 Node hash 中隔离纯分析/候选逻辑；提供明确的输入输出 Interface。CLI 保留原命令、退出码、清单校验、只读语义和完整报告边界。
- 首阶段线上调用沿已有 Node 程序/Bridge 方式消费共享核心，不立即将 `node:crypto` 模块直接装入浏览器，也不重写一套 Python 扫描器。
- 公共数据链与共享脚本之间用 M1 契约连接。MD 分块与 find 是材料候选能力，不新增未经依据的自动语义匹配保证。
- 若触及 `auxiliaryUses` 或 `checkAnalysis` 的内层回调，按本轮复杂度基线先拆本次职责；不得把外层 CC=1 或移动文件当治理完成。
- I08 呈现纠错沿现有映射、query 返回及 compose/edit 内部实现；local 直接写 JSON 的适用检查必须同源承接。复用现有格式器/语义规则与向量，不增加公开“闸门”工具或第二个总控流程。其工具回归通过后，M5 才删除对应兜底说明。

**退出**：现有本地 CLI 与仓外独立运行结果保持；共享程序输入不变、诊断顺序保持；无查询/写页副作用；所有新增函数 CC≤15，修改存量超限项符合仓库规则。独立 Skill 仍只需 Node，不能新增开发仓或兄弟 MC 目录依赖。

### M3：线上只读页面用数分析

依赖 M1/M2，复用当前工作副本入口。

- 经可信程序将冻结页面交共享分析脚本，模型只消费有界的需求/映射/缺口摘要；完整页面和查询留程序通道。
- 从当前页面提取需求后，使用现有 discover/query 形成真实候选，展示与页面要求的兼容性和缺口；不得在此步骤保存页面。
- 同页重排、人工修改或新轮次导致旧分析失效时，明确重新分析/重核；用户只改标题等情况保留已有能力，避免无意义全量查数。

**退出**：在真实工作台或公开合成 Agent fixture 中，从未保存工作副本得到完整分析；页面/资产未改变；错误绑定、过期、身份切换、输出预算和取消均有确定结果。真实 Relay 注册和部署仍单列。

### M4：受控增量接数操作

依赖 M3。在已有 edit_page 及公共应用协调内实现第一条纵向切片，不创建第二个保存入口。

- 模型只能引用可信程序中已核对的绑定方案/结果和目标；完整源、查询体及字段契约由程序取得，不开放任意 Page JSON 或任意属性补丁。
- 一个逻辑接数操作原子处理所有必要的源定义、字段映射和绑定，完整验证后交给既有批处理。与其他独立编辑操作的 partial 行为继续保持；不要把多条互相依赖的改源拆成中间非法状态。
- 核对稳定字段、角色/类型/单位、行粒度/rowKey、筛选/参数及上下游，清除条件改变后不再有效的 initial，并沿产品执行规则失效依赖。
- 保留页面、组件、合法字段身份、布局、列显示/交互和无关源；无法兼容明确失败/报缺口，不能重新 compose 代替接数。
- 继续使用 expected_version、当前模式的基线、原 operationId/单次保存、unknown 锁定和精确预览。

**退出**：同粒度换源成功；共享消费者、未映射字段、单位/粒度/键冲突、权限、过期结果、版本竞争和保存未知均有正反例；输入不变，失败不留下半个绑定。完整工具注册与 MC 示例对账通过。

### M5：两套 Skill 工作流和跨策略接续

依赖 M3/M4 的受支持范围，工作流草稿可在 M1 后并行准备。

- 页面先行：页面意图 → 用数分析 → 数据发现/验真 → 用户核对映射 → 受控接数 → 预览修复 → 原保存/发布路径。
- 数据先行：保留现有查数到页面流程，输出可继续编辑的同一工作副本；后续固定结构、换源或补字段进入页面先行。
- 页面已有新问题时可以数据先行补查再回当前页；不因切换策略自动新建页面、丢弃未保存修改或跨作用域复用引用。
- 将方法论/产品事实/调用包装/部署配置逐段登记。事实指向 MC/生成投影，共享确定性逻辑指向同一实现，Relay 特定步骤独立。
- 工作流减负按[职责整理](skill-flow-simplification.md)的文件处置表与最短任务路径实施：前置检查收进现有工具，根入口和命中材料按需加载；相应工具检查验证通过后才删除兜底提醒，按实际读取与任务回放验收，不以包文件数或静态字节冒充模型收益。
- 模板继续作为可选的信息关系/组合参考，不要求每次选编号或固定章节。标题/列宽等局部任务不读新建、数据与模板说明；本次用户确认的呈现规则由工具执行，模型只处理回执和无法确定的业务选择。
- 从 Relay 已迭代的真实 Skill 与共同基线逐段核对规则/引用及调用回放，再归并共享方法与私有规则；参考文本不能覆盖已接入版本。
- 接收报告的路径/规则摘要可用于设计，尚未附 Skill 全文或可信共同基线；按 I01/I07 明确保留项，不以 git log 的提交次数代替行为差异。
- 共享方法正文采用单一作者源和固定“源→两个安装目录”投影表；产品事实仍引用 MC/产品知识，不把方法论整体塞入 MC 协议目录。生成器显式登记新增输入、文件所有权和引用，local 安装目录内包含所需正文，不依赖运行时跨目录读取。现有作者文件先核对原文/扩展再迁，不以生成覆盖丢失内容。

**退出**：两个方向、两个切换场景、纯呈现修改及缺数据场景均有任务回放。线上页面先行无需人工离线搬文件；现有本地目录安装和原数据先行流程保持。Skill 行为验收不以脚本单测代替。

### M6：覆盖扩展与同步分发

依赖 M5，按业务需求逐项推进，不一次开放全部 Schema。

- 先扩新增字段/多源与交互绑定，再核对 IOC/时间程序、pagedJoin 查询分页、父子表/parentLookup/完整导出、表格自动同比环比、组合卡/页签等。
- 每项同时记录页面先行的接数/编辑、数据先行的装配和策略接续；明确不适用或未实现的条件，不能凭知识存在标记已支持。
- 同批更新产品规则、受控请求/实际注册、共享脚本、页面示例、MC、local 投影和受影响工作流；生成后才打包并回读实际归档。
- 增加 Relay loader/SDK 的实际注册与缓存对账，并定位外部 recall-report/执行插件的版本和运行语义；不由“已发布页面可读”推导多槽/级联召回已验收。

**退出**：具体能力的页面/脚本/协议/知识/Skill/宿主证据完整；安装和真实部署回执分开，未验项明确保留。

依赖主线：`M0 → M1 → M2 → M3 → M4 → M5 → M6`。M1 后可同步设计工作流和测试场景；产品补齐按首条切片需要分批插入。先只读后写入，避免在迁移第一步改变资产保存行为。

## 4. 同步责任矩阵

## 5. 发布、兼容与回退

- 页面 Schema、创作连接契约、公开工具协议、Skill 软件版本、内容摘要与外部 API 各保语义，回执关联精确组合；新增接数输入不自动要求升级 Page Schema。
- 默认保持现有 Skill 标识、local 命令与 MC 检索 key。结构变化若破坏消费者，升级所属接口并提供明确迁移，不长期维护两份业务实现。
- 同一轮次固定产品/MC/脚本组合；新进程整包切换。报告/映射记录格式变化先做读取兼容或要求重新分析；旧引用不能通过改版本号复活。
- 正式切换前清点活动工作稿与 unknown 提交。回退使用完整已验收组合，不能只回退代码后重新发送原写入。内部 Adapter 与私有扩展不随公共同步覆盖。
- 本地仍整目录安装，不要求运行时另找开发仓或 MC 兄弟目录；线上通过受控程序和实际注册消费能力。

## 6. 完成说明与范围

本计划的完成表示探查及迁移/同步任务可评审；M0–M6 均为后续实施。当前没有新增产品脚本、MCP 操作、页面字段或 Skill 行为，不宣称线上用户自定义闭环已具备。
