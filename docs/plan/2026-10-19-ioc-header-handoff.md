## 3. 第一阶段：可交互 Prototype

### 目标和位置

回答：IOC页头的身份区、密集筛选、详情、时间/金额联动和操作区是否清晰好用；前进继承与返回恢复是否符合B策略。

使用 prototype 技能的UI分支。用户已经选定内部视觉方向，围绕该方向提供可切换场景和必要布局比较，不重新发散成无关视觉风格。原型使用本地演示数据和内存状态，明确标记未接真实DQE、权限和后端。所有拟实现协议均标为草案，原型变量不直接变成正式页面协议。

优先参考既有 [Dashboard时间原型](../../packages/ui/prototypes/dashboard-time/README.md) 的Svelte/Vite组织和启动方式。新IOC原型建议在当前仓库独立prototype目录组织，具体位置按现有约定核对；IOC业务组合正式归引擎，放在UI原型目录不改变中性UI包的产品职责。尽量复用现有UI，保持单条启动命令和README入口，原型不进入正式包导出或生产页面目录。

### 必须可切换的场景

| 原型场景 | 核心内容和操作 |
|---|---|
| 概览 | 标题、说明/刷新时间、区域、月份、币种；可选模式/全屏入口 |
| 密集列表 | 多维度筛选、按实际换行展开/收起、选中摘要、区域/行业层级、操作位置 |
| 项目详情 | 长标题、编码、月份、多个状态标签、返回；缺少来源时的入口状态 |
| 精简合同 | 无标题、区域、离散月份多选；选1月和3月不包含2月 |
| 复杂时间 | 日/月模式、近1/7/30/90天、周/月与模式切换后状态；未知周兼容行为标注草案 |
| 金额与币种 | 预设、自定义、确定/取消、无效输入、换币清金额的一次状态变化 |
| 跨页流程 | 概览→列表→详情→返回；目标修改不污染来源；显示恢复了哪些视图状态 |
| 异常与布局 | 候选加载/空/失败/不可用/只读，长标题、多标签、窄容器和弹层 |

不用为88项功能各造一个独立屏幕；相同控件形态可共用演示场景，但保留对应H/F/M/T/L/N/O编号。可选操作通过场景开关展示，供用户选择，避免默认全部开启。

### 原型检查和交付

每次操作显示相关状态：已应用值、必要草稿、期间实际起止、币种/金额、候选状态、模拟查询触发次数或事件记录、来源/目标视图。点击展开只改变布局；取消金额不改变已应用值；币种切换与清金额只产生一次有效状态提交。

运行页面并实际查看桌面、窄容器、详情和弹层，提供可复现入口和简短操作步骤。1440×900可作主要观察尺寸；1024和390宽用于观察容器适应，不把这些数字当成来源已有断点。浏览器能力不可用时说明未验证项目并提供可启动产物，继续完成其他不依赖浏览器的部分。

第一阶段出口：可运行原型、场景切换、上述关键状态可操作、查看入口、已验证与未验证清单，以及用户需选择的具体布局/功能。交付后供用户查看、调整，再进行正式API审查。此阶段不做生产协议、数据执行和业务页面迁移。
