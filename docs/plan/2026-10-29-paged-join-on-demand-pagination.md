# pagedJoin 按需查询分页与单查询源操作方案

状态：业务口径已确认，已从候选代码合入后的最新main开始实施；本地核心与Chrome场景已通过，分发与扩大回归进行中。更新：2026-10-29。

目标是一张表格组合两个查询源的列时，首屏和翻页只查询当前页，再补齐本页其他来源的列。默认每页 10 条、补列批次 10 条。表格同一时刻只保留一个成员的排序和过滤状态，后提交的成员操作覆盖其他成员的表格操作状态。DQE 只执行普通单源查询，查询顺序与关联键传递由共享执行器负责。

本计划是本批唯一实施入口。只讨论一个组合表格中的多个查询源，不涉及行内子表格；不引入后端跨源关联接口，不动态改写固定 `resultBindings`。当前先支持两个成员，内部规则按成员归属实现，不为未来任意查询图增加配置。

## 1 已确认的业务规则

| 项目 | 规则 |
| --- | --- |
| 基准查询源 | 复用 `domainMember` 指定业务行域；一行代表该源的一条记录，而不是本轮先查源的一行 |
| 关联 | 复用成员 `key` 与最终字段 `projection`；补列源同一关联键多条报错，不取第一条，不扩展主记录 |
| 分页 | 默认 `pageSize: 10`；普通浏览只读取当前页及其补列，不自动循环读完整业务行域 |
| 批次 | 默认 `batchSize: 10`；限制补列编码批次与单次响应读取窗口，不等于完整读取全部批次 |
| 操作覆盖 | 后提交操作的成员生效；清除其他成员全部表格排序和过滤；同一成员内部条件可以组合 |
| 条件组合 | 同列表头多选 OR，不同列表头条件 AND；有效条件变化回到第一页 |
| 保留条件 | 页面筛选、参数、固定查询条件和权限条件始终保留，不能被表格操作覆盖 |
| 缺失补列 | 无对应 B 记录时保留 A，补列为 null；B 普通条件排除缺匹配；显式“为空”包含缺匹配和字段为 null |
| 能力不足 | 不能保持原有行粒度、准确总数和分页时明确提示，不自动完整关联，不筛当前页冒充全局过滤 |
| 行为范围 | 新模式允许能力成立的成员接管排序或过滤；早先讨论的“只开放 A 排序”被最后操作源生效规则替代。记录模式的非基准成员操作仍须通过能力检查 |
| 创作 Skill | 新建页默认生成新模式；局部编辑旧页时检查、迁移；冲突明确列出，其他旧页另列清单 |

“主表”统一称基准查询源或业务行域成员；“本轮先查谁”称选页成员。文档和实现沿用 [领域词汇表](../../CONTEXT.md) 的组合查询源、查询分页、生效查询、查询结果绑定等术语。

## 3 查询与分页设计

### 3.1 基准成员选页

1. 解析当前页面条件和基准成员的表格条件，生成单源生效查询。
2. 请求 `offset = pageIndex * pageSize`、`limit = pageSize`，后端执行排序、过滤和计数。
3. 验证窗口与总数；保留返回的每条记录，提取并去重本页关联键。
4. 每批最多 `batchSize` 个键查询补列；每次请求的读取窗口也受该值限制，完整性检查只针对本批编码。
5. 按原记录顺序投影最终列。公开快照属于组合源，不写入成员普通快照或 `initial`。

例如 A 当前页 10 条审批属于 6 个项目，只请求这 6 个项目的补列，最终仍是 10 条审批。A 总数采用 A 在当前有效条件下的记录总数，不采用去重项目数。

### 3.2 非基准成员接管操作

普通一键一行模式中，B 可作为选页成员的前提是：其当前约束下的键域、每键一行、计数和排序能够代表最终表格行域，且已有 `canSelectPage` 能力声明经过验真。B 的键必须能映射回满足基准源固定条件、页面条件和权限条件的 A 记录。

执行顺序为 B 按自身条件排序、过滤、取当前页键，再按这些键查询 A 及其他成员，按 B 页内顺序投影。A 的旧表格条件已经清除，但 A 的业务条件仍然参与查询。B 的 `totalCount` 只有在上述行域等价成立时才能用作组合总数。

不能仅凭两个源使用相同键名就允许 B 接管；一页内发现 B 键不在 A 行域必须失败，一页内未发现异常也不证明其他页全部成立。能力声明是接入前提，不是执行器自行证明的事实。

记录模式下，A 同一关联键可对应多条记录。B 的 10 个键可能展开为 A 的 50 条记录，不能用 B 页码和总数代替 A 的记录分页。第一阶段这种 B 操作明确不可用；后续若新增记录级选页方案，应独立设计，不通过后台扫描全集补齐。

### 3.3 反向传键方案的取舍

DQE 不支持跨源关联已作为确定前提。一般的“B 完整筛选得到键集合，再用集合约束 A 分页”可以由引擎编排，但需要读完 B 的匹配键；B 仅取前 10 个键不能得到全局正确的 A 页和总数。

本轮用户以最后操作源生效规则替代跨源排序、过滤同时保留，并接受不能保持行粒度时提示不可用。因此，第一阶段不增加完整匹配键收集器，也不假定用户已经同意 Q8 中额外读取全部 B 键。可选页的 B 直接选页反查 A；不可选页的 B 操作在发请求前阻止。

### 3.4 无匹配、空值与真实性

- 空选页返回空结果及准确总数，不发送失去键条件的补列请求。
- 补列本批完整返回后缺少某个键，按 `onMissing: "null"` 投影；分页截断或上游失败不能伪装成缺匹配。
- `batchSize` 同时限制编码分组与响应窗口；补列唯一性不成立时拒绝，不通过继续读批次拼成一对多结果。
- “B 字段为空”包含 B 缺失。直接查 B 的 null 只能覆盖“B 有记录且字段为空”，无法覆盖缺失行；这种情况不能直接走 B 选页。仅在选页成员能完整表达空值语义时执行，否则显示能力缺口。
- 不自动追加后端不支持的第二排序字段。当前 metric 仅支持单字段排序，object 多字段排序需要可信编码；稳定记录顺序仍须真实 DQE 验真。实时 offset 查询可能受两次请求间数据增删影响，不宣称事务快照。

## 4 Schema 调整

以下显式声明已按 Schema 6.76 实现；历史执行分支继续保留。实施基线与验证结果见第9节。

### 4.1 用查询分页分支承载新语义

建议扩展 `source.pagination`，复用表格既有的 `mode: "query"` 词汇：

```json
{
  "pagination": { "mode": "query", "pageSize": 10, "batchSize": 10 }
}
```

| 字段或同层对象 | 新分支规则 | 历史兼容 |
| --- | --- | --- |
| `pagination.mode` | 显式 `"query"` 启用按需选页、单成员操作和禁止完整回退 | 未声明继续原执行语义；不能只改默认解释 |
| `pagination.pageSize` | 1—1000，产品要求显式声明；Skill 默认写 10 | 旧 `pageSize` 保持现行定义 |
| `pagination.batchSize` | 1—1000，缺省规范化为 10；普通和记录新模式共用 | 旧模式不接受该字段；不改变历史 `records.batchSize` |
| `fallback` | 新分支禁止，不能出现“有 fallback 但不使用”的声明 | 旧分支保留原 1000 行有界完整路径 |
| `records` | 有则允许基准成员关联键重复，记录身份仍由外层 `rowKey` 指定；保留 `maxBytes`、`timeoutMs` 资源约束 | 新分支不再使用旧 `records.batchSize`，新旧路径不能同时声明 |
| `records.maxRows/timeFilters` | 新分支禁止完整读取预算与分页后本地时间筛选；可下推的时间条件迁至基准查询 | 旧记录分支仍按原协议读取和执行，迁移时逐项报告 |
| `members.canSelectPage` | 复用作为选页能力声明；新模式校验选页成员能代表最终行域 | 不更名、不把 false 自动改 true；记录模式非基准成员第一阶段不可选页 |
| `rowKey` | 记录新模式必须投影基准源真实非空唯一记录字段 | 旧完整记录模式继续允许快照内生成标识 |
| `ordering` | 默认排序同属一个成员；可声明不同成员的可操作字段，但运行时只能提交单成员状态 | 不将旧混合排序文档自动解释为最后成员生效 |
| `initial` | 最终字段的完整默认第一页、准确总数、单成员视图，资格沿共享执行规则验证 | 旧第一页 initial 不能证明完整记录状态；不能直接升级为新模式证据 |

`mode` 在这里区分历史完整关联语义和新增查询分页语义，不能由已有 `pageSize` 推导；不再增加 `executionMode`、`activeMember`、`reverseQuery` 等第二份配置。批次配置只保留一个有效位置，新旧结构通过联合分支隔离，不能让两个 batchSize 静默竞争。

下面是一份完整组合数据源声明。A、B 引用页内普通 query 定义；它们的真实键域、粒度与能力需要按接入合同核对。此 JSON 是源声明草案，不是可直接交付的完整 Page。

```json
{
  "fields": {
    "project-id": { "type": "string", "role": "dimension", "nullable": false, "label": "项目编号" },
    "project-name": { "type": "string", "role": "dimension", "nullable": false, "label": "项目名称" },
    "approval-count": { "type": "number", "role": "measure", "nullable": false, "label": "审批次数" },
    "project-status": { "type": "string", "role": "dimension", "nullable": true, "label": "项目状态" },
    "contract-amount": { "type": "number", "role": "measure", "nullable": true, "label": "合同金额" }
  },
  "source": {
    "type": "pagedJoin",
    "rowKey": "project-id",
    "domainMember": "a",
    "members": {
      "a": { "source": "project-approvals", "key": { "field": "project-id", "queryField": "项目编号" }, "canSelectPage": true },
      "b": { "source": "project-information", "key": { "field": "project-id", "queryField": "项目编号" }, "canSelectPage": true }
    },
    "projection": {
      "project-id": { "member": "a", "field": "project-id" },
      "project-name": { "member": "a", "field": "project-name" },
      "approval-count": { "member": "a", "field": "approval-count" },
      "project-status": { "member": "b", "field": "project-status" },
      "contract-amount": { "member": "b", "field": "contract-amount" }
    },
    "ordering": { "default": [{ "field": "approval-count", "direction": "desc" }], "sortableFields": ["approval-count", "contract-amount"], "nulls": "last" },
    "pagination": { "mode": "query", "pageSize": 10, "batchSize": 10 },
    "onMissing": "null"
  }
}
```

该例按项目汇总，一项目一行；B 能代表 A 行域才可声明为 true。B 金额列虽可声明排序，但可空字段的后端 null 顺序未验真时，该排序仍不可执行，不能靠示例声明豁免。

记录变体保留相同层级，`rowKey` 改为真实审批记录 id 并投影自 A；成员关联键仍为项目编号；B 的 `canSelectPage` 为 false。新增分支中的记录资源对象草案如下：

```json
{
  "records": { "maxBytes": 67108864, "timeoutMs": 60000 }
}
```

### 4.2 表头 null 条件

建议向 `TablePredicate` 增加 `{ "field": "project-status", "op": "isNull" }`，本阶段只实现已确认的“为空”，不顺带扩展 `isNotNull` 或通用表达式。需要同步 `TableHeaderFilters`、草稿类型、选项值编码、查询编码和本地求值，不能使用空字符串或可与业务值碰撞的字符串哨兵。

“为空”是表格条件，不等于 `resultBindings.where.isNull`。源支持 null 谓词和组合缺匹配语义是两项检查；缺匹配需要反向补集查询时，本阶段明确不可用。不能把判断 null 全部下放为前端当前页操作。

这会局部修订 ADR-0114 首批不提供 null“空白”选项的限制，需在实施 ADR 与主题索引中明确版本和适用范围。不能只改一个菜单选项便宣称已支持。

## 5 状态与架构调整

### 5.1 TableSession 原子提交

保持现有 TableSession 为唯一已提交视图所有者。新增私有纯转换步骤，根据 `projection` 解析本次事件字段的成员，将“校验能力、清除其他成员 sort/predicates、保留本成员条件、页码归零”组成一次提交。

| 当前状态 | 新操作 | 提交结果 |
| --- | --- | --- |
| A 排序 | B 过滤 | 清除 A 排序，只保留 B 条件，第一页 |
| B 条件 | A 排序 | 清除 B 条件，只保留 A 排序，第一页 |
| B 状态过滤 | B 金额排序 | 保留 B 过滤和排序，第一页 |
| B 多条件 | 删除其中一项 | 其余 B 条件保留；全部清空后恢复默认成员视图 |
| 任意有效状态 | 打开另一源的筛选菜单或编辑未提交草稿 | 已提交视图不变，不提前清空条件 |
| 任意有效状态 | 提交能力不成立的操作 | 不发查询；保留原有效视图，通过业务字段标签说明该操作不可用 |

后提交以一次有效操作提交为准，不以请求返回先后为准。`setHeaders` 当前接收整份过滤对象，不能从对象键顺序推断最后操作字段；内部命令需携带本次修改的字段，批量恢复视图则直接校验不能混合成员。公开 Page JSON 不存事件时间或操作日志。

成员归属可从最终 sort/predicates 和 projection 推导，不增加第二份可漂移的活动成员状态。`TableQueryView` 继续是已提交结果，不把历史动作或可变数据源定义放进去。

只有 B 条件而无显式排序时，不恢复 A 的默认排序。执行器采用 B 查询已有合法默认排序，缺省时采用可验证的成员键排序；不会偷偷写入另一成员的排序。取消全部条件、恢复默认、列条件显隐和用户排序取消也通过同一规则调和，防止默认排序重新引入混合源。

### 5.2 SourceProgram 与 QueryRunner

SourceProgram 内新增封闭的按需组合执行路径，收拢窗口验证、键提取、补列、投影和能力拒绝。复用成员定义和受控查询编码，不复制 DQE body，也不为普通成员建立额外公开快照。

建议内部规划产出为“可执行按页计划”或“不可用原因”。计划只携带选页成员、有效视图与成员定义引用；不把策略开关分散到 widget、UI controller 或网关。原完整执行器保留给历史分支，新的 page-only 路径不能调用 `executeCompleteJoin` 或完整 `recordJoinReader`。

QueryRunner 继续管理请求去重、缓存、总并发、优先级和消费者取消，承接候选任务新增的前台抢占后台机制。分页与本页补列使用前台路径，不另建分页专属请求池。缓存身份包含页面/权限上下文、有效条件、选页成员、排序、页码、页大小、补列键及模式；后台优先级只影响调度，不进入结果身份。源切换、筛选变化和刷新必须硬失效不兼容组合结果；取消旧代次，丢弃迟到响应。缓存按既有有界策略维护，不建立页面级完整记录缓存。

记录路径需要替代按整轮下标生成身份的做法；真实记录 id 从查询结果映射。序号仍由页偏移生成，与记录 id、关联键分开。

### 5.3 UI 与诊断

UI controller 只拥有草稿，提交后从会话重新投影勾选、排序标记、分页与菜单上下文，不能只清执行条件却保留旧勾选。预先已知不可用的操作可显示禁用原因；动态发现的能力问题通过局部操作反馈呈现业务原因，不把技术路径、键值或 DQE 响应暴露到界面。

当前页面查询失败沿用空态与 console 诊断。这里的局部“此列暂不支持按审批记录分页筛选”等能力反馈与普通后端错误区分，实施 ADR 应明确它的适用范围。不能通过修改所有查询失败 UI 来实现本次提示。

### 5.4 候选值、搜索和导出

候选值获取承接第 2.1 节约定的 main 合入结果。该实现是按原查询分批完整读取后前端去重，并非 DQE 原生 DISTINCT；同时已增加表格可见后的空闲预热、菜单懒加载和主查询优先。本方案复用这些模块，不把完整候选读取当成反向分页能力。

打开 B 的菜单时，候选请求应基于“若提交 B 操作将保留的条件”计算：保留页面/固定/权限条件和 B 其他条件，移除将被覆盖的 A 表格条件，再排除目标列自身条件；只预览，不提交 TableSession。否则菜单先被 A 条件缩窄，实际提交后 A 被清除，候选域就不一致。查询输入和缓存 key 共同使用一份纯上下文计算，不能只改执行条件或只改 key。这需要局部修订 ADR-0114 对新模式的条件上下文。

**新分页模式的候选策略：** 禁用自动完整预热；表格可见、绘制完成或浏览器空闲均不自行扫描全集。通过 controller 提供给现有预热模块的字段资格实施这一规则，不新增 Page Schema 的 `preload` 配置，也不删除共用可见性与调度模块。用户打开菜单后才允许按需请求候选；该请求只影响菜单加载状态，翻页、排序和本页补列可以抢占它。

**原有模式的候选策略：** 保留对方已经确认的可见后空闲预热、隐藏暂停、在途与已完成结果复用、前台查询优先；本次不全局关闭预热。

新分页模式的候选入口先进行模式与能力分流。能够用单个成员准确表达完整组合候选域时，复用已有网关候选适配器；需要旧 `completeJoin`、完整记录扫描才能得到准确候选时，返回不可用，不强制调用历史 `joinedCandidates` 分支。用户显式打开菜单后，获准的完整候选读取仍可能有较大成本；懒加载不等于消除了这项成本。

候选搜索、加载更多复用已有完整候选集合的优化沿用对应任务进展。本计划的 `batchSize: 10` 只控制组合浏览，候选网关的默认 500 行批次和菜单每页 50 项分别保持独立；不能据此宣称候选无需完整扫描。候选无能力时返回不可用，不退回当前页去重或全域字典。

现有候选收集忽略 null；新“为空”选项按第 4.2 节增量扩展，并保留旧表候选语义。能力不成立时不展示可执行的“为空”选项，不能用当前页是否出现 null 判断全局可筛选性。

新模式第一阶段不新增跨成员自由文本搜索；现有旧页搜索声明列入迁移检查，不能保留入口后悄悄触发完整关联。单成员搜索若纳入实施，必须经过相同归属调和和网关能力检查，不能扩大到多成员字段。

导出冻结已提交的单成员视图，用户显式导出时才逐页取完整匹配记录，保持最终行粒度和原导出上限。不能导出当前 10 行冒充完整结果；新路径失败不给部分文件。历史显式部分导出与告警继续按其原分支处理。权限上下文变化中止任务，Excel/PDF 不复用过期浏览快照；这不扩大导出能力范围。

## 6 兼容性与决策冲击

| 现行结论或模块 | 冲击与处理 |
| --- | --- |
| ADR-0051 增量能力与版本门禁 | 用显式新分支增加能力；不更改已有 pageSize 的缺省执行含义；新结构、null 条件分别登记能力下限 |
| ADR-0108 组合执行与有界完整回退 | 保留执行所有权、普通结果隔离和固定级联；新模式局部替代自动完整回退，实施时补 ADR，不直接把历史 ADR 原文改成“已实现” |
| ADR-0114 匹配候选与无 null 选项 | 新模式采用候选预期提交上下文；新增 null 选项和能力拒绝，限定修订，不影响旧模式候选语义 |
| 候选懒加载与空闲预热改动 | 作为先合入 main 的依赖承接；原有模式行为保持，新模式禁用自动完整预热，菜单按需查询及调度机制复用 |
| Schema 6.66 记录模式及后续修订 | 新增按页记录路径；批次字段迁至新分页分支，拒绝本地时间筛选和伪造记录身份；旧记录分支保留 |
| 当前超时与恢复告警 | 以刷新后的 main 为实施基线；按页操作和单批超时复用既有语义，完整导出总预算单独保留 |
| 字段显隐 | 去掉某列状态时不能恢复其他成员默认排序；会话、候选菜单与导出可见列必须使用同轮结果 |
| 普通 query、pagedUnion、行内子表格 | 不套用单成员覆盖规则，不改变原查询与合并逻辑 |
| 同源共享消费者 | 组合内部窗口和补列不能污染图表、另一张表或普通查询 initial；维持组合表独占交互源规则 |

旧页迁移分类：普通一键一行且可选页能力成立；记录页具备真实记录 id 且条件可下推；混合源默认排序或搜索冲突；依赖本地时间过滤、生成身份或完整关联；能力/数据契约未知。前两类进入迁移候选，后三类列明问题；局部编辑只处理用户目标页，不批量改变未涉及页面。

不自动授予 `canSelectPage`，不把“字段可查询”“同名编号”“静态合法”当成真实行域与分页证据。真实服务只需证明单源条件、计数、稳定分页、键谓词及返回窗口契约，不需要证明跨源 JOIN。

## 8 风险与尚未验收事项

1. `canSelectPage` 不能证明键域、固定条件、权限和计数真的等价；真实 DQE 接入仍要有请求和响应证据。
2. 数据量小的完整读取会掩盖策略错误；需要十万级按需合成源与请求轨迹，独立断言不扫描全集。
3. 记录模式的 B 过滤、B 排序和缺匹配 null 可能不可用；这是已接受的第一阶段边界，不能包装为“所有列全局操作均已支持”。
4. 候选任务仍有完整读取成本且没有默认总量上限；原有模式的空闲预热可能扫描全集。新模式须关闭自动完整预热，显式菜单读取仍按能力和独立资源约束验收，不能以“空闲”或“不阻塞首屏”冒充读取量有界。
5. 小 batchSize 增加本页请求数；补列并发与请求缓存仍受 QueryRunner 总资源约束，不能逐行无限扇出。
6. 后端分页和本页补列之间数据可能变化；没有事务令牌时准确总数和窗口检查不能证明整页事务一致。
7. `isNull` 类型会影响普通表格与候选值类型消费者；新增能力门禁须按真实声明检测，不能只更新组合执行器。
8. 本地 HEAD、远端 main 和并行工作区不同；按第 2.1 节在编码前同步候选已合入的 main，重新核对版本、单批超时、恢复告警及候选导出入口，生成知识时使用隔离的确认范围。
