## 消息与工作区

每个会话一个独立 worktree。S0 使用额外集成 worktree 合入已验收提交，维护唯一 coordination.md，并公布其绝对路径和当前基线 SHA；所有开发会话只读台账，各自交付回执。原始工作区可能有未提交规划和其他工作，先按 common.md 准备基线。

有会话工具时，S0 按登记的真实任务 ID 发进展和续跑消息；没有工具时，使用下方回执人工转交。暂时阻塞的会话先做验收设计等独立工作；无工作可做就结束该轮，收到续跑消息再继续，不进行无限轮询，也不承诺后台自动工作。

### 每票回执格式

```text
Issue：#...
状态：本仓完成待集成 / 等待具体依赖 / 真实联调完成
范围：本次完成什么，未完成什么
提交：基线 SHA；交付分支与 commit SHA
接口：新增/变更公开契约及其版本
验收：逐条 AC 对应测试/浏览器/构建证据，失败和未运行项单列
外部：已确认事实、模拟行为、仍缺的真实能力
下游：可解锁哪些任务，需要消费哪些提交
回退：恢复到哪个基线或如何撤销本票
```

S0 验收后追加集成 SHA；Issue 的完成状态与真实外部门槛分别维护。统筹用如下内容续跑下游：

```text
你的前置 #... 已按本仓范围验收，已进入集成基线 <SHA>。
请读取原票最新回执，取得该基线并完成必要兼容检查，然后继续你负责的 #...。
本次新增/变更契约：...；仍未就绪的外部能力：...。
```
