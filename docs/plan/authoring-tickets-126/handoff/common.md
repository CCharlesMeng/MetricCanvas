# #126 并行执行共同约定

这是新会话的必读交接，不是实施完成记录。先读此文，再执行角色提示词；用户在新会话中的明确指令优先。

## 背景与目标

MetricCanvas 正在补齐进入 Platform 创作页面后的生命周期：语言创建合法页面、手工/语言修改同一创作草稿、保存不可变修订、浏览器恢复、精确预览、提取参数候选、人工确认发布及执行接入。#126 是规格；#127–#146 是已认可的 20 张实施票；#95 继续跟踪原有静态化、真实部署、异构消费及盘古基础接入。

本版架构调整优先。内容 MCP 只负责确定性内容编辑；生命周期 MCP 负责外部管理服务调用。Java 拥有持久化、提取和发布裁决，Relay 理解意图并编排；本仓只给 Java/Relay 修改方案及消费适配，不修改外部服务。DataAgent、普通问数能力推进、手工添加组件不在本版范围。

页面参数复用 params，不新增 globalParams/dimensionValues 根字段；filters 是页内可变筛选；layoutForm 按受控兼容策略迁移到 layout。盘古接管现有侧边栏对话，工作台保留画布、工具栏和检查器；源码、集成适配及部署配置分离。

## 开工步骤

1. 确认当前任务对应的 MetricCanvas Git 仓及工作树。每个会话使用独立 worktree 和 codex/ 分支，既有用户修改保持原位。共享原始工作区只用于读取交接材料，各会话不在其中并发实施。
2. 读执行仓的 AGENTS.md、CONTEXT.md、ADR 基线、规格 #126，以及自己负责 Issue 的完整正文、最新评论和依赖；涉及 #95 时以最新有证据的评论及当前代码为准。重点定位 ADR-0070/0073/0077/0078 与本票相关决策，不重复扫描全部历史。
3. 交接材料目前可能尚未提交，新 worktree 默认分支不一定含这些文件。可从原始工作区绝对路径只读读取；统筹会话会把本次规划及新决策的明确范围纳入共同基线。缺失材料先读取 GitHub 规格和任务，不能把工作树里看不到文件当作产品决策不存在。
4. 向统筹会话登记角色、task/thread ID、工作树路径、分支、当前票、计划修改文件及共享触点。目录不是排他锁，必须明确文件和公开接口所有权。并行者已占有同一文件时，先由统筹指定唯一所有者。
5. 核实技术前置及阶段门槛。在前置未满足时可做资料核验、验收用例设计和独立调查；依赖代码的实施要等已验收提交进入共同基线。新功能统一在 M0 后启动。

## 共同基线与合入

统筹会话 S0 建立并维护本地集成分支 codex/authoring-126-integration，记录其 commit SHA；这个名称是建议，若实际有既定分支则沿用并通知全员。集成 worktree 必须与开发 worktree 分开。统筹只整合已验收的任务提交，保留提交身份与证据；其他会话根据统筹公布的精确集成提交开始下一票。

实现者可提交本票相关代码到本地分支，提供 commit SHA、基线 SHA 和验证记录；Issue 执行记录回写自己负责的票。远端 push、PR 合并及 main 更新遵循当次会话的明确授权，不因本交接自动获得远端发布权限。本地集成与消费已验收提交可以先继续。

目前原始工作区还有未提交文档和其他会话可能添加的内容。统筹先逐项识别本版交接资产，不能将工作区全部改动直接打包进规划基线；代码实现从干净、明确的提交基线出发。

技术依赖的“就绪”必须同时包含：提供方给出验收证据；统筹确认本票范围通过；提交进入共同基线；消费方拿到基线 SHA 并通过针对性兼容检查。Issue 被关闭或某个 PR 已创建，都不能单独代替这些条件。

M0 是本版架构阶段门槛：#127、#128、#129、#130、#131、#132、#133 全部按本仓范围验收并进入共同基线。#132 的 Python 迁移在 M0 前正常推进；#133 等待 #131/#132，不等待 M0。避免建立循环等待。

## 验收与回执

每张票按自己的 Acceptance criteria 验证公开行为。复用现有测试和契约门禁；UI 行为补浏览器证据，需要依据外部设计还原页面时遵循仓库 SDD。不能只跑类型检查便宣布完整交互完成，也不为未改变的层重复建设同义测试。

本仓通过、外部契约确认、真实联调通过分别记录。涉及外部能力未完成时保留明确跟踪入口，不能用替身或本地页面成功关闭外部任务。#95/#126 是整体目标，不由工作会话随意改写或关闭。
