## What to build

让外部服务方能按明确输入、输出和失败语义实施本版本所需变更，本仓开发有可验证的边界样例。

## Acceptance criteria

- [ ] 按 #105/#106 最新资料建立现有能力、拟新增能力、待验证事实对照，明确 Java/Relay 代码不在本仓实施。
- [ ] 覆盖精确读取、修订历史、写后读取、稳定幂等及结果查询、冲突、说明字段、维度取值保留选择、候选提取修正确认、执行与最后筛选。
- [ ] 明确内容 MCP 与生命周期 MCP 分工、可信程序产物传递、用户身份、来源及已保存草稿引用；完整文档和数据行不经模型转抄。
- [ ] 提取算法与权限约束归 Java，语言计划归 Relay，方案给出成功/失败/重复/过期候选样例及联调清单；不虚构提供方已支持的 HTTP 或 SDK 字段。
