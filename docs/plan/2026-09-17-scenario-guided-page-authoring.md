# 场景参考驱动的页面创作：整体修改方案

日期：2026-09-17。状态：用户随后明确“开工，进行实现”，首期代码与本地验收已完成。实现与证据见 [实施记录](scenario-guided-authoring/verification.md)。下文保留已确认方案；接口示意以实际工具 Schema 为准。

当前入口：[v3 架构调整方案](scenario-guided-authoring/refinement/authoring-architecture-proposal.md)、[实施与验证](scenario-guided-authoring/refinement/architecture-implementation-results.md)。此前的 [v2 协作改进方案](scenario-guided-authoring/refinement/design.md)与本文保留各阶段设计背景；下文“待授权”“尚需完成”等均为当时状态，不是当前执行指令。最新模型端稳定性仍待评测，不能用本地实现完成替代。

## 1. 要解决的问题与已有证据

目标是让 Platform 创作的报告围绕业务问题组织内容，并在可控范围内接近 `pages` 示例的结构丰富度。不能用“更自由的布局”替代数据可信，也不能用固定模板替代今天的固定口径分区。

现有问题有四层：

1. Skill 的 `workflows/create.md` 第 3 步把数据页面优先导向 `compose_page`；没有先组织阅读顺序和章节的显式步骤。
2. `domain/page_building.py::_sections_of` 以口径组生成分区，自动生成分区标题和 panel 容器。只改变一个取数单元的时间口径，就会增加分区，已通过调用实际装配函数的最小复现确认。
3. `application/unified_composition.py` 从固定 `main` 开始组合；当前创建操作不包含显式多分区编排。`unified_edit_page.py::_add_data` 又要求每个新增取数单元恰好产出一个非页头组件。章节自由度和“一源多组件”都不充分。
4. 真实模型测试中，生成合法页面仍不代表呈现合理：概览把元和百分比放进同一柱状图；样例说明仅存在于 `meta.description`，没有可见正文；模型误读参考入口、耗尽工具预算，随后还传入非法 `intent: overview`。

流水示例的实际结构为：流水总览、公网 Region 流水、客户视角、赛道视角、产业视角；同一分区混合指标卡、趋势、说明与明细。Tokens 示例同样将概况卡和趋势同章组织。示例证明页面协议已有相当的表达能力，缺口主要位于创作工具与模型引导层。

## 2. 已确认方向与范围裁决

已明确：

- 采用“场景参考 → 章节组合 → 确定性装配”。
- 模型决定业务组织，程序负责查询、稳定字段绑定、布局展开与校验。
- 完整报告不再以口径组强制划分分区；同章展示与跨数据计算分别约束。
- 场景参考来自现有示例，但不复制示例里的业务数字、完整页面或固定章节数量。
- 复用统一 Skill、五工具、创作轮次、候选和交接机制；不新增报告专用 Agent。

用户于 2026-09-17 回复“可以，按照你的建议进行推进”，确认以下两项推荐选择。当时仅推进方案定稿；随后用户明确授权开工，现已实施。

| 决策 | 已确认选择 | 本期不采用的选择及影响 |
|---|---|---|
| 需求不适合已有章节组合时怎么办 | 允许受控组合已有组件，经过相同硬校验及更强呈现检查 | 只允许登记组合：实现较窄，但容易再次形成死模板，需要频繁扩充组合库 |
| 首期是否自动生成有数据依据的分析结论 | 首期解决结构与呈现；允许已有受信结论和静态口径说明，自动分析另期 | 同期做分析：需新增有证据引用的分析事实摘要及事实校验，不能仅向模型开放更多布局能力 |

首期按这两项决定推进：S1–S4 必须覆盖登记组合之外的受控组件组合；S5 分析事实摘要列为后续独立范围，不作为首期完成前置。接口、术语和 ADR 细节仍在 S0 收敛。

## 3. 成功标准与非目标

成功标准：

- 同一业务章节可以容纳不同时间范围或分组维度的内容，并在页面可见位置保留必要口径。
- 一个已验证的页面数据源可以被多个展示组件复用，不因组件数量增加而重复查询。
- 报告包含有业务含义的章节、合理的主次与阅读顺序，而不是“一组查询一张图”。
- 场景参考能够裁剪、重复、重排；缺数据时不补造章节内容，不凭模板推断业务结论。
- 同量纲、同口径比较与计算边界可靠；手工编辑后的局部修改保持未触及结构。
- 实际模型自主完成的结果与人工提示修复后的结果分开记账。

首期非目标：

- 逐像素复刻已有示例、任意 CSS、绝对定位或开放任意组件嵌套。
- 新增页面渲染 DSL、重写统一运行时、迁移历史页面到新结构。
- 放开自由公式、隐式聚合、在浏览器补造查询或数据。
- 自动归因、业务建议或无依据的结论生成。
- 改造普通问数的现行装配行为、Java 保存协议或 Relay 注册与身份链路。
- 完整覆盖所有报表、看板和内部扩展；首批以两类报告建立完整闭环。

## 4. 三层职责

| 层 | 决定什么 | 不决定什么 |
|---|---|---|
| 场景参考 | 阅读目标、典型路径、可选章节、适用与缺失条件、正反例 | 真实业务数字、固定查询、必须生成多少章 |
| 创作期结构计划（暂用名） | 本页章节、标题、内容块、顺序、组合方式、数据引用及可见说明 | 原始 DQE、可信字段 ID、像素布局、页面身份 |
| 确定性装配 Module | 查询执行与复用、字段解析、组件展开、占位、响应式兼容、校验、候选 | 编造业务问题、替模型任意重排章节、静默改变指标含义 |

“创作期结构计划”“章节组合”是本方案暂用设计名称，不视为已经纳入领域词汇表。在 S0 中确定正式术语后再同步领域文档。

业务章节默认对应一个页面分区；章节是设计意图，分区是现有页面协议结构。首期不引入独立的多层章节树。复杂嵌套只通过已有组件能力表达，并受当前深度与支持面约束。

## 5. 场景参考如何设计和维护

### 5.1 首批范围

| 场景 | 首期 | 来源与用途 |
|---|---|---|
| 经营分析报告 | 是 | `pages/flow-analysis-report.json`：总览、业务板块、重点对象、明细的组织方式 |
| 资源用量报告 | 是 | `pages/tokens-report.json`：概况与趋势同章、区域/模型/客户分析 |
| 风险排查报告 | 后续 | 先盘点风险页的数据与交互前提，再增加参考 |
| 监控看板 | 后续 | 保持现有 dashboard；后续单独验证密度、筛选与下钻，不照搬报告规则 |

每份参考包含：适用问题、读者目标、默认阅读路径、章节候选、组合候选、数据前提、缺失策略、允许的变化、反例，以及源示例和参考版本。

参考分为语义说明和小型结构示意，不把整页 JSON 直接塞进模型上下文。示例的数字、客户名称、源 ID 与业务口径不能随结构借用。明确的用户结构要求优先于场景默认，但不能越过数据与组件硬约束。

### 5.2 选择与加载

- 保留统一 Skill 入口；只加载所选场景和实际使用的组合参考，不把全部场景全文常驻。
- 模型依据用户用途选择；明确“流水分析报告”不需要再问是否做经营报告。
- 没有唯一场景时，选择最接近参考并使用受控组合；只有歧义会实质改变业务内容时才澄清。
- 独立部署必须声明参考的真实提供方式。初期建议提供简短场景索引，在结构计划预检时由可信宿主补入选中参考；宿主不支持动态补入时，显式预注入首批所需参考并记录成本。
- 不能要求模型通过 `read_page_context` 或 `discover_data_context` 阅读 Markdown。参考、实际 Schema、允许枚举和部署能力必须可获得。
- 场景内容需单一作者维护；Skill 投影和测试夹具引用同一版本，不在 Python、Markdown、前端各抄一套规则。

## 6. 章节组合与自由度

### 6.1 首批建议支持的组合

| 组合 | 用途 | 默认展开 | 数据前提 |
|---|---|---|---|
| 概况与趋势 | 先看当前状态，再看变化 | 指标卡行 + 通栏趋势 | 单值/单行引用可确定，趋势维度可用 |
| 双项对照 | 对照两组业务表现 | 两个等宽内容块 | 对照声明需通过单位和口径检查 |
| 结构分析 | 看分布及重点构成 | 构成图或排名 + 可选说明 | 占比必须有有效分母，不能把不完整 Top N 当整体 |
| 重点对象 | 定位需要关注的对象 | 说明、排名、明细按阅读顺序排列 | 对象标识、排序与明细来源真实可用 |
| 明细核对 | 逐项核查 | 通栏表格，按需复用现有筛选 | 列与交互均受当前能力约束 |
| 口径与说明 | 展示范围、局限、既有结论 | 通栏正文，紧邻相关证据 | 数字与判断必须有可引用依据 |

首期可以先落地其中支撑两类报告的最小子集，不因列表存在而虚报所有组合可用。组合标识、插槽规则与程序展开方式需要版本化。

### 6.2 模型能调整的内容

- 章节增减、业务标题、顺序、组合选择和内容主次。
- 一个章节组合多个取数单元；一个数据源绑定多个组件。
- 从实际支持的组件中选择类型；使用语义宽度，如通栏、等分或主辅。程序再映射到现有布局。
- 同一类业务章节重复出现，例如多个业务板块；默认不按指标个数生成章节。
- 允许登记组合之外的受控自由组合，但仍必须使用已支持的组件、容器、属性及布局词汇，不能提交未经契约验证的 props 或源码。

默认组合可以自动补齐布局细节，但不能静默换成另一种业务叙事。实质调整需出现在模型可见结果摘要中，供模型修订。

### 6.3 防止重新变成模板

- 不规定每份报告必有六章，不规定每章必有图、表、文字各一个。
- “缺少数据”不等于自动生成空卡；可选章节省略，明确要求的内容缺失则可见说明。
- 控制的是可表达的形状和数据关系，不限制业务主题必须来自固定列表。
- 组合之外的请求使用受控组件组合并接受同样的硬校验；能力不足时精确报告缺口，不能暗中降级成固定 `main` 或口径分区。

## 7. 数据需求与展示结构分离

当前 Page Build Spec 的单元同时带取数、分析意图、组件提示，且输出基本沿一个单元一个组件展开。新路径应拆开“要什么数”和“怎样展示”，避免给旧 spec 塞进大量不相关字段。

推荐接口是一个聚合输入，内部包括两个部分：

- **数据需求**：复用现有受治理指标、维度、筛选、时间与快照版本；稳定 `dataSourceId`。不让模型传查询体或完整字段契约。
- **展示计划**：章节、内容块、组合、展示意图、标题和数据引用；绑定已验证数据需求。

数据需求里的旧展示字段如何拆分，由新契约显式定义；不让 `unit.intent` 和内容块的展示意图同时拥有最终决定权。旧 `compose_page` 输入保持原义，新路径只在内容块定义展示意图。

结构示意（不是可调用的最终 Schema）：

```json
{
  "planVersion": "1",
  "scene": "business-report",
  "title": "流水分析报告",
  "layout": "report",
  "dataRequests": ["由已有受治理取数契约定义的单元"],
  "sections": [
    {
      "id": "flow-overview",
      "title": "流水总览",
      "pattern": "overview-with-trend",
      "blocks": [
        {"id": "current-flow", "role": "headline", "source": "current-total"},
        {"id": "monthly-flow", "role": "trend", "source": "monthly-history"}
      ],
      "notes": ["各卡片分别注明统计期间；趋势区分实际与预测"]
    }
  ]
}
```

最终引用不能是自由文字占位符。数据源引用必须命中计划中的单元或当前可信候选；字段通过已发现的语义名称及工具返回的受控引用解析为稳定字段 ID，歧义时报错，不让模型猜哈希字段 ID。

同一个返回行集被多组件复用不代表允许在本地任意切粒度。单行选择、字段选择、具名算子和筛选只能使用现有已实现语义；需要新的统计粒度时增加取数单元并真实执行。不会用截断的 initial 样本计算全量结论。

复用范围限定为同一可信创作轮次/候选及兼容口径；跨用户、快照版本或权限范围不共享查询缓存。同名源 ID 但查询或字段契约不同仍冲突，不自动覆盖。

## 8. 工具接口与执行流程

### 8.1 推荐保留五工具

| 工具 | 计划变更 |
|---|---|
| `discover_data_context` | 保持数据发现职责；补足“列出某业务域能力”的明确查询方式与有界分页，避免靠模型猜词反复搜索 |
| `read_page_context` | 补充有界章节/内容块结构摘要，仍不作为文档读取工具，不暴露原始业务行 |
| `compose_page` | 保留快速取数装配及旧调用兼容；完整报告不再默认走它，普通问数保持现行策略 |
| `create_content_page` | 增加版本化结构计划输入，与现有 operations 输入明确判别；新输入由结构装配 Module 处理 |
| `edit_page` | 扩展受控分区与内容块操作，支持章节增改/重排及在候选内复用已有数据；保留局部修改与未知字段保持语义 |

新旧创建输入建议为互斥契约，不允许同一次请求同时提交计划和任意 operations。具体采用 `request.plan` / `request.operations` 或版本判别字段，在接口切片确认；不靠提示词猜调用属于哪种模式。

创建计划先做本地结构与能力预检，再执行数据，再装配页面。同一个工具内完成，不额外增加一轮“用户审批计划”。只有现有业务澄清或成本/权限政策要求时才等待用户。

### 8.2 执行链

1. 可信宿主准备创作轮次、空基线或当前基线，按现有机制保护人工修改。
2. 模型理解用户用途和明确结构，选择场景参考，发现必要数据。
3. 模型提交数据需求与结构计划；此时不提交最终页面 JSON。
4. 程序验证结构、组件与布局能力，返回明确缺口；非法枚举在模型输入 Schema 中就应可见。
5. 程序按真实身份和快照执行唯一取数需求，建立字段契约和源描述证据。
6. 展开章节组合，绑定组件，加入可见口径与缺失说明；输出合法页面候选。
7. 返回有界结构摘要、已应用的布局调整和可修复问题；模型仅修受影响的内容，不重跑整页查询。
8. 页面校验、适用的呈现检查和可信交接完成后，沿原草稿提交与发布边界处理。

“预检”“查询执行”“布局展开”是 Module 内部阶段，不必每一阶段新增模型工具调用。外部 Interface 应比模型手写完整页面更小。

### 8.3 修改与部分失败

- 只改标题、顺序、占位时不重新发现或执行查询。
- 默认保留用户已经修改的分区、容器、列宽、字段格式和未触及组件。
- 将章节组合展开为普通页面协议后，不要求页面永久满足当初组合。再次编辑以真实页面为准，不根据历史场景强制还原。
- 数据失败时，以依赖闭包为最小原子单元：失败数据及依赖组件不产生悬空绑定；独立成功章节可按现有部分成功策略形成候选。
- 用户明确要求的章节缺失必须可见报告；不可只返回“页面生成成功”。全失败不保存，未知写入不重试。
- 结构删除须有明确修改意图；移动最后一个组件后的空分区处理应确定、可回归，不顺便删除独立正文。

## 9. 校验：同章不等于可比较

| 检查层 | 硬性要求 | 可修复或人工评审项 |
|---|---|---|
| 数据 | 真实源、字段身份、查询/映射一致、权限、空值/单位/刻度正确 | 不支持的口径明确说明；不凭标签判断可加性 |
| 比较与计算 | 已知不同量纲不能共用单一比较轴；禁止无依据求和、占比或全量结论 | 语义可比性无法证明时不声称已通过，建议分图或改呈现 |
| 结构 | 有效引用、合法容器、无环依赖、支持的嵌套、无悬空组件 | 章节过碎、重复图表、正文脱离证据、过度空白 |
| 布局 | 当前轨道/占位和响应式协议合法 | 宽窄屏可读性、主次、表格密度及滚动负担 |
| 报告内容 | 可见期间、单位与实际/预测区分；明确的数据缺口不能被隐藏 | 标题是否业务化、结论是否有证据、阅读顺序是否合理 |

不可把所有审美判断升级为硬阻塞。程序可确定的事实用硬校验；启发式用提示和受控修复；业务叙事质量由冻结的评测准则和人工审阅判断。

修复次数、模型请求、工具请求、唯一查询、token 和耗时各自有预算并记账。达到预算时停止并保留候选，不以无限续跑把失败变成通过。结构调整优先复用已验证数据；超出原预算的恢复单独立项记账。

## 10. 分析正文的边界

当前模型只消费安全摘要，不看原始业务行。拥有章节自由度不会自动获得生成数值结论的证据。

已确认的首期范围：

- 允许模型写用途、阅读说明、口径、局限和用户提供的明确结论。
- 数字正文使用已支持的字段绑定能力，避免把一个数抄成永久静态文本。
- 不把“示例里有分析正文”理解成每页必须现场生成同比、预测或归因结论。

后续自动分析作为独立切片另行立项：程序从已验证且覆盖范围已知的数据形成有界分析事实摘要，包含事实 ID、来源、期间、单位、可比较性和样本/全量范围。模型结论引用事实 ID，程序审计支持关系。数据刷新后的事实过期、授权范围和可见性必须同步设计。不得直接将整页数据行外发，亦不得用静态旧结论冒充刷新后的分析。

## 11. 流水报告的具体目标

数据充分时，允许生成如下业务组织：

```text
流水分析报告
  流水总览：总量 / Core / 云通信卡片 + 月度实际与预测趋势
  公网 Region 流水：分类卡片 + 已有风险说明 + 对应趋势
  客户视角：增长/下降对象 + 明细核对
  赛道视角：结构或明细
  产业视角：结构或明细
```

这不是固定五章。实际数据只支持概览、趋势和结构时，生成相应子集；不复制示例的客户、赛道或产业内容。

当前三组样例数值口径独立，因此验收不能要求跨源核对一致，也不能据此生成经营判断。新装配必须让“本地样例、非生产数据、来源独立”成为可见正文，不仅放入 `meta.description`。

金额与百分比应分别呈现，或选择各字段独立格式的表格；不能通过结构场景改造掩盖现有选型问题。前两个月实际、后三至十二月预测的表达需在图例/说明中保持明确。

## 13. 与现行决策的关系及迁移

- **ADR-0055**：当前明确“一个口径组一个内容分区”。本提案与其被应用于完整页面创作的做法冲突，需在实施前补充/替代相应范围，普通问数默认保留。不能只改提示词而让规则来源互相矛盾。
- **Page Build Spec 的领域定义**：现行定义不承载组件 JSON 或布局。新增结构计划作为独立创作期输入，不静默改变旧概念；如正式合并输入也必须先裁决术语与契约版本。
- **ADR-0057**：现有比例装配和页头仍可复用，扩展为章节组合的确定性布局默认；不能让自动排布覆盖用户钉住项。
- **创作/渲染分离**：场景、组合选择、结构计划留在创作期；最终仍输出现有页面协议。若实现发现必须新增渲染语义，单独评审，不能假定无须升级 Schema。
- **ADR-0079/0080**：本方案不绕过可信轮次、候选和 Java 单次提交约束，不恢复已被替代的强 latest/历史接口前提。

旧调用按原路径运行，新结构计划通过工具能力版本显式启用。独立分发时 Skill、Schema、注册表与装配版本必须匹配；新 Skill 对旧工具应给出能力缺口，不能静默退回死板布局并声称成功。

旧页面不批量迁移。新能力关闭后，已生成的普通页面仍应可渲染；避免在页面里留下只有新创作器才能解释的私有结构。保存保持单写者，不引入新旧两条保存链。

## 14. 验证与评测方案

### 14.1 确定性公开工具验证

1. 同一章放两个不同时间/维度的单元，保留显式章节，不自动拆分；必要口径可见。
2. 同一数据源绑定卡片、趋势或明细时，按真实可用形状复用；不允许从错误粒度推导新结果。
3. 一源多组件的同轮查询执行次数可审计；不能以数据源 ID 相同就跳过契约核对。
4. 金额与百分比进入同一单轴图时被拒绝或明确修复；分卡或独立格式表格合法。
5. 缺预测、客户维度或归因依据时不编造对应章节内容。
6. 组合默认可裁剪/重复；有一个不匹配登记组合、但可由现有组件表达的场景能成功装配；不支持的能力精确拒绝。
7. 部分查询失败只影响依赖内容；候选合法、缺失可见、无空悬绑定。
8. 仅修改章节顺序/标题不发查询，不覆盖人工列宽、格式、未知扩展或独立正文。
9. 普通问数仍走原口径装配；旧 operations 与新计划输入互不混淆。
10. 独立 Bundle 中参考可达，实际 Schema 公布合法意图值；文档不足不会引导模型读业务工具找文件。

### 14.2 页面与执行验证

- 使用同一公开创建工具生成页面，再用真实页面校验器和统一运行时验证；不能只在 Python 私有函数中通过。
- 检查宽屏与窄屏上的卡片行、趋势、明细与正文，确认无重叠、截断和不可读布局。
- 校验 initial 数据与刷新/筛选执行一致。此次 scratch 流水适配器不具备现有 DQE Sim 通用重执行证明，不能直接作为该项通过依据。
- 首期用已适配的 DQE Sim 或提供方执行端建立可复跑样本；真实生产服务另记状态。

### 14.3 真实模型评测

- 冻结流水报告、Tokens 报告及未参与编写参考的留出业务场景；包括数据不足和明确用户结构覆盖场景。
- 旧 Skill 与新 Skill 使用同模型、同能力/数据快照、同输入意图、同预算；新增结构工具另标为工具能力变量，避免把所有改善归功于提示词。
- 区分“只改 Skill”“工具能力变化”和“完整新方案”能回答的因果问题，不为完整交付强求没有意义的全排列。
- 固定场景参考版本、工具 Schema、输入输出、模型标识、用量、调用次数、耗时和原始产物 hash。
- 首轮自主成功、引导修复成功、预算失败、外部阻塞分别报告；不得覆盖首次失败。
- 质量准则包括：业务章节、同章组合、量纲正确、口径可见、无虚构内容、局部修改保持、阅读顺序和实际渲染。Schema 通过仅是其中一项。
- 具体样本数、重复次数与质量通过门槛在执行前冻结；不根据跑出来的分数倒推门槛。复用现行规格的每适用场景至少三次独立重复，费用和外发按当批范围管理。

## 16. 主要风险与应对

- **组合库成为新死模板**：以语义插槽、可选内容和受控组合扩展，而非固定整页数量。
- **模型 Interface 膨胀**：尽量表达业务结构，隐藏字段 ID、布局计算和最终页面细节；按选中参考注入。
- **口径提示丢失**：对明确需要区分的内容验证可见位置，不能只依赖聊天或 meta。
- **样例过拟合**：留出不同名称、不同数据规模和缺数据场景；不以章节名称逐字一致作为通过条件。
- **一源多用导致重复/错误计算**：唯一查询执行与稳定字段绑定分别审计，复用不授权新聚合。
- **合法但难读**：独立的呈现检查和真实渲染验证，避免所有质量责任都落在模型提示词。
- **旧页面重排或数据丢失**：新建计划与局部编辑分开；已有页面的场景重构必须来自明确请求。
- **把测试投影当生产接入**：模型、内容工具、样例数据、DQE 重执行、生产身份、保存发布逐项记账。
