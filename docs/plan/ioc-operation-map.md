# IOC 作战地图落地方案

**目标**：让 MetricCanvas 具备承载多页数据应用的能力，以 IOC 作战地图（项目地图链路）为首个实例落地三个页面。

**来源规格**：`参考/项目地图/` 下的 `000-overview.md`（链路与跳转契约）、`001-project-overview.md`、`002-opportunity-list.md`、`003-project-detail.md`、`004-indicators.md`（55+ 指标逐字段口径）、`设计稿/`（三张 Figma 导出稿）。

本文是执行计划。所有架构裁决在 [ADR-0045 ~ ADR-0051](../adr/README.md#速查表)，本文不重复论证，只做索引、排期与验收。开工所需的外部输入清单见 [`ioc-legacy-handoff.md`](./ioc-legacy-handoff.md)——那是一份可独立带走、发给旧项目源码持有者的寻源问卷。

---

## 1. 前置裁决

以下五条是业务侧已经拍板的输入，全部 ADR 建立在它们之上。任何一条变化都需要回来重估方案。

| 议题 | 裁决 | 影响 |
|---|---|---|
| 目标形态 | **平台通用能力**，IOC 作战地图是首个实例 | 能力必须进页面协议、可校验、可被 AI 生成，不能写死在宿主 |
| 应用外壳归属 | **已有门户（Cloud BI）提供**，MetricCanvas 通过 `packages/embed` 嵌入 | 不建导航树与菜单；跨页路由由宿主执行（ADR-0048） |
| 前端计算 | **进页面协议** | 修订 ADR-0003 措辞，部分恢复 ADR-0033（ADR-0046） |
| 数据侧协议 | **全部使用 GraphQL** | 新增查询协议分支；DQE 的 `formula` 与 `total_count` 都不可用（ADR-0045） |
| 设计稿保真度 | **信息结构与交互必须一致，视觉细节可让步** | 卡内复合排布用 12 列栅格重表达；卡内 Tab 是交互，仍须实现 |

## 2. 能力差距

### 2.1 现有能力（无需新建）

盘点后确认这些已经具备，不要重复造：表格的递归列分组（多级表头）、`fixed` 冻结列、`selection.writes` 原子写多筛选、`pagination: 'query'` 服务端分页；跨页 `navigate` 及其 `carryFilters` / `setFilters`（值可取自当前行）；URL → 筛选状态水合；`mapChart` 的 china/world 着色与散点；受控语义 HTML；`money` 字段五档自适应格式；行对齐运行时不变量；`pageQueryZ` 已经是判别联合的形状，加协议分支是被预留的。

### 2.2 差距与归属

| 差距 | 归属 ADR | 批次 |
|---|---|---|
| GraphQL 查询定义、结构化谓词、排序绑定、总条数、响应摊平 | 0045 | P1 |
| 行内派生、小计/合计、行转列 | 0046 第一批 | P2 |
| 跨数据源聚合（管道支撑率） | 0046 第二批 | P4，形状待裁决 |
| 页面参数、`setParams`、标题栏绑定、跨页引用校验 | 0047 | P1–P2 |
| 导航意图事件、`mount()` 双向契约、宿主对外契约文档 | 0048 | P2 |
| 服务端排序与列头筛选、行点击导航、行类别呈现、首列合并 | 0049 | P2–P3 |
| `timePoint` / `boolean` / `numberRange` / `search`、层级维度、级联、结构化相对时间 | 0050 | P3 |
| `gauge`、Tab 容器、key-value 信息面板、字段绑定长文本 | 组件目录扩展，无独立 ADR | P2、P4 |
| 地图三级下钻 | 0050（层级筛选器）+ 0048（末级跳转） | P4 |
| 行级数据权限、真实身份 | 未裁决，见 §5 | P5 |

### 2.3 `schemaVersion` 5.1，纯增量，不硬切换

本批全部页面协议变更逐条核对后**没有一处是破坏性的**：

| 变更 | 增量判据 |
|---|---|
| `pageQueryZ` 新增 `graphql` 分支 | 判别联合新增分支 |
| 数据源新增计算阶段 | 新增可选字段 |
| 新增顶层 `params` | 新增可选字段 |
| 文本属性取值放宽为 `string \| 参数引用` | 放宽既有约束 |
| 筛选器闭集从两类扩到六类、`hierarchy` 与 `dependsOn` | 闭集新增成员 + 新增可选字段 |
| `timeRange.default` 新增结构化相对时间分支 | 判别联合新增分支 |
| 表格新增 `rowKindField` / `mergeBy` / 列 `link` | 新增可选字段 |
| 删除「查询分页不支持排序与列头筛选」两条拒绝 | 放宽既有约束 |
| ADR-0048 的导航契约 | 不动页面协议 |

因此本批交付 **5.1**，存量页面不迁移，`versionPolicy` 保留 5.0 读取路径。版本策略本身由 [ADR-0051](../adr/0051-additive-minor-versions-for-page-schema.md) 裁决：次版本仅用于纯增量演进，主版本递增必须单独写 ADR 论证为什么无法增量表达。

**这里原本写的是「6.0 硬切换」，是错的。** 硬切换与本仓的生命周期模型冲突——页面修订不可变（ADR-0008）、模板引用精确的已发布修订（ADR-0010）、报告冻结在采集时点（ADR-0030），三者都要求旧文档长期可读，而「迁移一份不可变修订」的产物是新修订，模板与报告指向的仍是旧那个。ADR-0017 与 ADR-0038 能硬切换，只是因为当时没有生产内容。

变更范围：zod schema、生成的 JSON Schema、`Page` 领域类型、`PAGE-METADATA.md`、`packages/page` 校验器与能力表、`packages/mcp` 的示例资源。`pages/*.json` 与 `packages/page/fixtures/` 保持 5.0 声明不动，新页面声明 5.1。

## 3. 分阶段计划

原则：**每个业务页只拉动它真正需要的框架能力。** 不预先把框架建全——没有真实页面拉动的能力，边界一定定错。

三个页面按复杂度递增排序，不按业务重要性排序。详情页无筛选栏、无地图、参数全来自 URL，是最干净的端到端切片；概览页的跨源聚合与地图状态机放最后。

### P0 决策评审（约 1 周）

ADR-0045 ~ 0050 当前状态是 `proposed`。本阶段完成评审并置为 `accepted`，同步 `CONTEXT.md` 词条与 `docs/adr/README.md` 主题段落。

**评审重点**（这几处最可能需要改）：ADR-0045 的谓词算子闭集是否覆盖三个页面的全部 WHERE 形态；ADR-0046 第一批算子是否够用、分母为零语义的声明方式；ADR-0047 关于「只有 `reportHeader` 能读页面参数」的特例是否可接受。

**出口**：六份 ADR 状态为 `accepted`，或明确记录哪几份需要重做。

### P1 GraphQL 竖切（约 3 周）

只做**一个数据源的端到端通路**：详情页的 `projectDetailData`（表 `PROJECT_MAP_OPPORTUNITY_DETAILS_M`，WHERE 是 `opportunity_code` 与 `mtime` 两个等值条件）。

交付：`graphql` 协议分支的 schema 与校验；数据网关的 GraphQL 适配器（谓词编译、响应摊平、结果归一化）；GraphQL 仿真服务；页面参数从 URL 进入并绑定到谓词；一份能通过 `pnpm validate` 并真实取到数的页面文档。

**这个阶段排 3 周而不是 1 周，是因为它是唯一能证伪 ADR-0045 谓词模型的机会。** 如果发现某类 WHERE 形态表达不了，此时回到 P0 重新裁决的成本最低。

**出口**：真实 GraphQL 端点上取到数并渲染；谓词模型经三个页面全部 WHERE 形态的纸面复核（不只是这一个数据源）。

### P2 详情页完整（约 3 周）

拉动：ADR-0046 第一批算子（销售预测表的分组小计与全局合计、客户关系规范性的行转列）、ADR-0049 的行类别呈现与首列合并、ADR-0048 的导航意图与宿主契约、`reportHeader` 的页面参数绑定、key-value 信息面板组件、字段绑定的长文本组件。

**注意**：详情页的客户关系数据在来源实现里依赖 `party_number`，而 `party_number` 来自项目详情查询的结果，构成级联数据源依赖。按 ADR-0047，改由清单页下钻时作为页面参数传下来——清单页的查询字段本就包含 `party_number`。[ADR-0015](../adr/0015-defer-cascading-data-source-input-semantics.md) 保持挂起，不为本项目解冻。

**出口**：project-detail 在生产宿主中可从 URL 直接打开并正确渲染；回跳链路在生产宿主上验收通过。

### P3 清单页（约 4 周）

拉动：ADR-0050 全部六类筛选器与层级维度、级联、结构化相对时间；ADR-0049 的服务端排序、列头筛选下推、行点击导航；ADR-0045 的排序绑定与总条数声明。

清单页有 32 列（含 12 个月度预测列）、五段 WHERE 拼装、服务端排序与分页，是筛选与查询能力的完整压力测试。

**出口**：搜索、11 个筛选控件、列头筛选、服务端排序、分页在真实数据上全部可用；跳详情页携带全部八个值。

### P4 概览页（约 4 周）

拉动：ADR-0046 第二批（`joinAggregate`，需先完成形状裁决）、Tab 容器组件、`gauge` 组件、地图三级下钻（层级筛选器 + 末级跨页跳转）。

**管道支撑率阻塞于第二批算子的形状裁决。** 该裁决应在 P2 结束、第一批算子有实战经验之后立即启动，不要等到 P4 开工才开始。在它落地前，概览页的其余部分可以先行。

**出口**：三级地图下钻可用且当前层级可通过 URL 分享；三个 Tab 的表格与 KPI 区完整；管道支撑率与来源实现逐位对账一致。

### P5 生产化（待定）

行级数据权限裁决与落地、真实身份接入、宽表性能、发布治理接入。见 §5。

## 4. 数据侧对账

来源规格的 `004-indicators.md` 逐字段列出了 55+ 指标及其口径。落地时必须做的两件事：

**逐处显式声明空值语义。** 来源实现里存在三套互不相同的空值判断：`CommonUtil.isNull` 把 `0` 也视为空（详情页金额格式化）、`IndicatorCalculate.validate` 不把 `0` 视为空（立项率与赢单率的分母判断）、`StringUtil.isNotEmpty` 用于搜索值。同一份代码里三种语义并存且只能从实现读出来，是最容易产生错数又最难发现的一类差异。ADR-0046 要求 `ratio` 显式声明分母为零语义，正是为此。

**金额单位不做隐式转换。** 来源实现有三条格式化路径：自适应万/亿（KPI 卡与表格）、先除以 10000 再格式化（详情页销售预测表）、以及一段用表达式算单位的 `unit` 字段。按 [ADR-0013](../adr/0013-format-belongs-to-component-field-binding.md) 与 [ADR-0042](../adr/0042-money-fields-and-semantic-embedded-values.md)，数据源字段保持原始单位（元），格式全部由组件字段绑定决定。来源实现里那批 `_label` 字段在本模型里不应存在。

## 5. 已知风险与未决

**GraphQL 路径上没有发现描述，AI 建页能力退化。** ADR-0034 要求 GraphQL/REST 路径补一份以操作名、参数、响应字段为可枚举面的发现描述，ADR-0045 本批不交付。这与「目标形态是平台通用能力」的裁决存在张力：三个页面本身可以人工建，但「后续同类应用由 AI 生成」这个目标在发现描述补齐前不成立。**补齐它需要一份独立决策，建议在 P3 期间启动。**

**ADR-0046 第二批未定形状，概览页核心指标因此无排期。** 跨数据源聚合正是 ADR-0015 与 ADR-0033 共同挂起的那批语义（空集与失败传播、输入集合上限、循环依赖、缓存键、取消）。用第一批的实战经验去定它是有意的选择，但代价是 P4 的关键路径上有一个未定项。

**行级数据权限未裁决。** 设计稿侧边栏显示「Region 经理」，这个应用天然按区域授权，而 `docs/adr/README.md` 的未决事项明确记录「数据权限本身（行级与指标级过滤由 DQE 承担还是由本平台承担）尚未裁决」。真实身份接入是上生产的前置条件。**这两项不解决，P1–P4 的成果只能在受控环境演示，不能对外。**

**Canvas 通过不等于接入通过。** ADR-0048 把路由交给宿主，Canvas 只是参考实现。下钻与回跳链路必须在生产宿主上单独验收一次。

**`Table.svelte` 的既有拆分欠账。** ADR-0025 待决节已记录。P2–P3 会大幅改动它，是处理欠账的合适时机，但拆分应作为独立提交，不与能力扩展混在一起。

**`ioc-workflow.md` 不在本方案范围内。** 该文档描述的是 IOC 数据开发（ADS 表设计到 SQL 到作业）的垂直领域流程，属于数据侧。本方案假定所需 GraphQL 表与字段已经存在。**若实际需要新建表，P1 之前须插入数据侧工作，本方案的排期不含这部分。**
