## 一、已经裁决的前提，不要在对话里重新打开

前四条是 2026-09-07 早先 grill 的产出；第 5 条是同日晚间本会话的产出。对方若给出与之矛盾的说法，记下来回报，现场不改裁决。

1. **发送消息服务与 Relay 是同一个东西**，不是它前面的一层；`role_name` 已被 `user` / `query_type` 取代。ADR-0063 的 WebSocket + `role_name` 记载等 #107 出 ADR 时对账，本票不改 ADR。
2. **编排所有权：请求要跳过服务端自己的意图理解与工具规划，直通 skill。** 提供方已口头保证支持。本票仍要把口头保证换成**书面字段名与语义**，只是字段落在 `PanguQuery` / adapter 上，不再落在我们自打的 HTTP 入参上。
3. **Chat 入口这一版的下限已定**：若问出「无回传、无会话读取、只能出文本流」，降级为「只出文本结论的问数」并如实告知不能恢复。问出「不支持」只决定降级幅度。
4. **通用知识污染的顾虑已消解**（跳过意图路由后不会走知识搜索），不必再追。
5. **对话与问数所有权分离（2026-09-07 本会话）**
   - **盘古助手拥有**：输入框、流式文本、停答、主题、历史面板、会话续期、HIS、对发送消息服务的实际调用。
   - **MetricCanvas 拥有**：问数 / 探索的临时页面态、取数核对、RuntimeView、页面资产。结果画在对话旁边，**不**把 `customRemoteCard` 当本版产物通道。
   - **Chat Interface** 改指 `window.pangu.instance(id)` + `adapter`，不再指我们自己打的 HTTP/WS。
   - **platform 是微前端子应用**：父页面已加载 `loader.js`，子应用不重复加载，用独立 `instanceId` 挂第二实例；卸载时 `destroy()`。
   - **分析会话仍是我们的词**（步骤事件 + 最新检查点）；盘古的会话历史是另一份对象，id 可以对齐，不是同一个东西。
   - 仓内 `pangu-sse`（页面 AI 总结）**不是**这条集成，不合并、不拆除。
   - 先前面向发送消息服务的 17 问停发。

票内第 1、4、8 项（调用地址与传输、`traceId`、浏览器 WebSocket 自定义 header）**内部关闭**：改由盘古客户端承担，不再向发送消息服务问。关闭不是「接口不支持」，是「我们不再实现这一层」。

## 二、对外提问稿（对象：盘古助手对接方）

> 以下可直接复制发送。编号 1–10 是对外编号；落评论时仍按票内 1–12 归档。

### 第 1 组：子应用第二实例

1. 父服务已加载 `loader.js` 并注册 `window.pangu` 的前提下，子应用用独立 `instanceId` 挂第二实例、不重复加载 loader，是否就是标准做法？`instanceId` 有没有必须与父实例协商的命名规则或禁区（例如不能用某些前缀、不能与 `'default'` 并存于同一页）？
2. 第二实例的容器选择器是子应用自己页面里的一个普通 DOM 节点即可，还是必须满足额外约束（必须在 Shadow DOM 外、必须由父页面预留、不能放在 iframe 里等）？

### 第 2 组：指定走我们自己的技能（解阻塞 #107）

3. 发送问题时，`skillInfo`、`referrer`（含 `agentId` / `agentBuilderCode` / `topicBuilderCode` 等）、`holdingSkill` 分别做什么？我们需要**跳过服务端的意图理解与工具规划，直接唤起某个 skill**。请给出：
   - 用哪个字段、什么取值格式；
   - 我们的 skill 对应的标识值；
   - **指定之后哪些事件不再出现**（我们预期意图理解、知识搜索不再出现，工具规划变成该 skill 自己的规划——请确认）；
   - 这个字段是否只接受受控标识，端侧**不能**通过它提交或覆盖 skill 的正文内容与工具权限。
4. 如果这个字段传了但仍然走了通用问答（版本不匹配、灰度未覆盖、取值拼错），**端侧能不能从 `adapter.getCustomOnMessageEvent`（或其它回调）里分辨出来**？有没有一个明确的信号？我们最怕的情形是：用户问一个数据问题，被路由到通用知识问答，返回一段读起来很正常的文字，而我们无法察觉。

### 第 3 组：事件、确认、会话（决定产品能做到什么程度）

5. `adapter.getCustomOnMessageEvent` 回调里，每条事件的字段是什么？是否就是「发送消息服务」文档那张事件表（`analyzing` / `thinking` / `generate` / `suggest` / `finish` 等），还是另一套形状？请给出一份实际 payload 示例（可打码）。
6. **同一次对话能不能在生成中途提交用户的选择 / 确认 / 取消，而不新开一轮 `ask`？** 我们的场景里，有时需要停下来等用户从几个候选里选一个，或者让用户改完查询条件后重跑、且不要重新走模型。如果只能再 `ask` 一条新消息，请明确写出来。
7. `config.autoRecover`、`config.initialConversationId`、`adapter.customHistory`（含 `queryConversationHistory` / `queryConversationHistoryContent`）分别：
   - 会不会按会话 id 持久化？
   - 能不能按 id 读回历史消息或最新状态？
   - **存了什么**——只存元数据，还是连模型思考文本、工具规划全文、工具返回内容一起存？保留多久？谁能查？
   - 这些存储和「发送消息服务」自己的持久化是同一份，还是两份？
8. `stopPanguMsg()` 与服务端停止是什么关系？它会不会同时取消服务端生成？`config.streamEventStop` / `pingCheck` 在什么情况下需要打开？

### 第 4 组：身份与是否自定义发消息

9. `adapter.getCurrentUser` 的返回值服务端怎么用？和 HIS 服务订阅拿到的身份是什么关系——做鉴权 / 权限过滤，还是只当展示名？会不会覆盖订阅凭证对应的身份？
10. 作为内部助手接入时，是否**必须**实现 `adapter.getCustomSendMessageRequest`（以及 `getCustomConversationStart`）？还是不实现就走盘古默认的发送消息服务？如果必须自己实现，请给出请求/响应的契约，而不是「按发送消息服务文档自行拼接」。
