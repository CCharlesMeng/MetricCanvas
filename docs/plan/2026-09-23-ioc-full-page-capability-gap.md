# IOC 全量页面复刻：已知差距与补证请求

状态：进行中盘点，2026-09-23。本文记录当前可证实的能力边界和下一轮取证要求，不表示 21 个页面已经完成设计或验收。

## 本轮范围与已确认裁决

- 目标覆盖来源项目的**全部 IOC 页面**。来源仓报告列出 21 个路由入口（其中 3 个无接触详情路由复用同一组件）、15 个子组件（2 个已禁用）、8 个弹窗和 18 处 Tab；这些是**报告中的源码盘点**，不是本仓运行验收结果。
- MetricCanvas 最终独立承接 IOC 实际使用的 DataV/ANA 页面呈现与交互能力，运行时不依赖 DataV/ANA。视觉细节允许调整，业务口径、数值、信息层级与用户可见交互需要等价。
- 页面仍是独立资产；跨页导航意图由统一运行时表达，路由、导航栈、面包屑、身份与凭据由集成应用承担。暂不引入一等“多页应用”资产。
- **本轮不处理真实取数接线**：保持现有 DQE 查询协议、数据网关和执行语义。来源项目的 GraphQL/REST 请求仅作为识别业务字段和页面行为的来源，不转植其协议、WHERE 字符串模板或 HTTP 客户端。本轮使用现有 DQE 路径与可控夹具验证查询结果之后的行为；新页面可先列出将来所需的 DQE 结果字段契约。缺少可用 DQE 字段的场景标为数据前提未满足，不宣称完成，也不借此改变取数协议。
- 本轮仍须设计**查询结果之后**的确定性计算、组合、格式化和交互。同一页面内多个页面数据源之间的计算属于本轮能力问题；真实端点与生产身份联调不属于本轮。

上述 DQE 范围是**本轮工作裁决**，不改写既有 GraphQL 提议的 ADR 状态；另见[IOC 批次现行主题页](../adr/topics/ioc-operation-map-batch.md)。

### 不转植来源 API

来源报告把 `DVCanvasConfig`、`globalVarsEmitter`、`fitFunction`、任意 ECharts formatter HTML、`DataFilter` 类、Tiny3 Module 等逐项列为“须提供”。本轮目标是**可观察行为与业务语义**，不要求 MetricCanvas 复制这些接口。现行产品边界禁止页面执行任意脚本、HTML 和计算表达式，见 [`origin.md`](../../origin.md)；新能力须是可校验的受控声明、确定性运行时行为，或集成应用职责。
