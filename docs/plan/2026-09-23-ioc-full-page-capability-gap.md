# IOC 全量页面复刻：已知差距与补证请求

状态：进行中盘点，2026-09-28 更新。本文记录当前可证实的能力边界和下一轮取证要求，不表示 21 个页面已经完成设计或验收。

## 本轮范围与已确认裁决

- 目标覆盖来源项目的**全部 IOC 页面**。新一轮来源仓报告逐项列出 P-01～P-21、S-01～S-04 与 S-07～S-09 共 7 个启用子组件、S-05/S-06 两个禁用子组件、D-01～D-08 八个业务弹窗；其中 3 个无接触详情路由复用同一组件。这些是**报告中的源码盘点**，不是本仓运行验收结果；旧报告的“15 个子组件、18 处 Tab”口径未经新报告逐项重核，不再作为验收分母。
- MetricCanvas 最终独立承接 IOC 实际使用的 DataV/ANA 页面呈现与交互能力，运行时不依赖 DataV/ANA。视觉细节允许调整，业务口径、数值、信息层级与用户可见交互需要等价。
- 页面仍是独立资产；跨页导航意图由统一运行时表达，路由、导航栈、面包屑、身份与凭据由集成应用承担。暂不引入一等“多页应用”资产。
- **本轮不处理真实取数接线**：保持现有 DQE 查询协议、数据网关和执行语义。来源项目的 GraphQL/REST 请求仅作为识别业务字段和页面行为的来源，不转植其协议、WHERE 字符串模板或 HTTP 客户端。本轮使用现有 DQE 路径与可控夹具验证查询结果之后的行为；新页面可先列出将来所需的 DQE 结果字段契约。缺少可用 DQE 字段的场景标为数据前提未满足，不宣称完成，也不借此改变取数协议。
- 本轮仍须设计**查询结果之后**的确定性计算、组合、格式化和交互。同一页面内多个页面数据源之间的计算属于本轮能力问题；真实端点与生产身份联调不属于本轮。

上述 DQE 范围是**本轮工作裁决**，不改写既有 GraphQL 提议的 ADR 状态；另见[IOC 批次现行主题页](../adr/topics/ioc-operation-map-batch.md)。

**原问题的前提不成立：上一报告对JavaScript分支作了错误推断。**新报告给出的核心片段是：

```ts
if (data.ytd_amt) {
  card.value_str = new DataFilter(data.ytd_amt).filterData(card[currencuConfig.filterFlag]);
} else if (data.ytd_amt === 0) {
  card.value_str = '0';
} else {
  card.value_str = '--';
}
```

`-1200` 与 `1200` 都进入格式化器；0进入第二支；null/undefined进入第三支。因此源码片段没有“小于0就隐藏”的逻辑。来源仓称未找到负值哨兵、需求、注释或提交说明支持隐藏负数。不能推测开发者意图，也不能把“如果ANA输出--则会显示--”当作ANA实际这样做的证据。新报告代码块中“1265行←负数落入此分支”的行内注释依然错误，以实际表达式和报告§0.3纠正为准；它称“完整函数”但仍含省略号，只能作为关键分支片段。

本仓用Node独立执行了分支选择和直接减法的断言：

| 输入 / 表达式 | 本地实测结果 | 能证明什么 |
|---|---|---|
| `-1200, 0, 1200, null, undefined` | formatter / zero / formatter / missing / missing | 片段中的分支选择，不证明DataFilter结果 |
| `100-null`、`100-undefined`、`100-0` | 100、NaN、100 | T-11/T-31所给直接减法片段的JS语义 |
| `null-0.9` | -0.9 | 新报告T-61的NaN推断再次错误 |

这是**本仓JavaScript语义检查**，不算来源组件运行、ANA运行、页面夹具或浏览器验收。负收入隐藏从缺陷清单撤回；负值作为有效数值送入格式化，不新增负值抑制规则。精确单位、舍入、负号和空值样式仍按消费者验收。

报告§0.5的“同字段比较”也要收窄：指标卡/表格是收入 `ytd_amt`，仪表盘使用的是目标完成率 `budget_completion_y_ratio`，它们并非同一字段。表格0显示--与卡片0显示0属于另一个已指出的显示差异；仪表比率究竟是0～1还是0～100尚有契约冲突（报告称小数，同时给出/100），不能据此判定仪表数值正确。
