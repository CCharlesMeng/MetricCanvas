日期：2026-09-08。已确认产品边界见 [ADR-0077](../adr/0077-pangu-dialogue-in-existing-workbench-and-ask-turn-outcomes.md)。本文件是 #95/#106/#107/#108 的接续入口，不将本地原型视为真实接通证据。

## 理解偏差对账

| 过往表述或推导 | 修正后的含义 |
| --- | --- |
| 没有自己的结果区域，所以去掉原页面画布、改成独立页面视图 | 没有额外的自有对话结果面。只将原左侧对话区整体替换成盘古，导航、工具栏、画布和检查器保留。独立视图原型已撤回。 |
| 在 MetricCanvas 自有区域选择业务/技术过程详情 | 前提错误，第 4 问作废；用户没有选择其 A 或 B。全部对话内容归盘古，不能自行补建第二套反馈 UI。 |
| 一问一答，因此不能澄清、确认或继续分析 | 每次 ask 都有本轮答复；答复可以是问题。流程可以等待确认，并在用户回应后继续。 |
| 必须取消旧确认、完整重问，或者将就地校准改走模型 | 均未获用户裁决。先保留旧确认与 ADR-0040 目标，单独验证承接接口。 |
| 一问一答，因此一次只允许一个指标/取数单元 | 用户约束的是轮次答复，不修改 ADR-0055 的多取数单元能力。 |
| 缺阶段事件，所以不能交付第一版问数 | 用户已选 A：允许整体处理中，再返回答案或确认问题；可靠实时事件到位后再显示分步进度。 |
| 旧发送服务文档没列事件/读取接口，所以盘古没有、恢复能力为零 | 现行盘古事件 payload、历史读取形状与检查点能力未知；没有文档不等于不支持。 |
| `autoRecover/customHistory` 有方法名，因此分析会话可恢复 | 方法存在不证明读取内容、保存期限、权限或结构化续跑能力；聊天历史与分析会话是不同对象。 |
| 盘古保存完整对话，因此推翻 Relay 是分析会话持久化所有者 | 两者对象不同。只有查明实际内容、存储关系及数据流后，才能判断冲突；不能由聊天记录存在直接推出所有权冲突。 |
| 从 `toolplan` 文本解析阶段/确认，即可补齐结构化控制 | 自由文本不能作为可靠控制状态；Skill 文案也不能单独证明强制确认等待已经实现。 |
| 仍按 WebSocket/`role_name` 自建浏览器 Chat | 本仓使用盘古实例 API + adapter。旧传输调查只作历史，不定义新回调映射。 |
| 新一轮失败或取消就清空已有页面 | 用户已选 3A：保留上轮页面并标识，合格的新产物才替换。 |

## 固定布局与职责

```text
全局导航 │ 文档工具栏（跨工作台）
         ├──────────────┬─────────────────┬───────────┐
         │ 盘古对话区   │ 原页面画布      │ 原检查器  │
         │ 所有对话内容 │ 页面/人工搭建   │ 组件配置  │
         └──────────────┴─────────────────┴───────────┘
```

代码来源：`apps/platform/src/routes/+layout.svelte` 和 `apps/platform/src/lib/PageAuthoringWorkbench.svelte`。当前桌面结构为全局导航 60px、工具栏 46px、对话区 292px、检查器 260px、画布自适应；窄容器沿用原响应式规则。这些数字是原型对齐的实现事实，不新增跨版本尺寸契约。

盘古承担对话的呈现和发送；MetricCanvas/Relay/Python 仍按既有边界承担取数核对、确认、编排和验真的业务规则。呈现所有权转移不能使这些规则变成纯 Skill 提示，也不把全部业务逻辑交给盘古 UI。

## 可验收行为

| 场景 | 本轮 ask 与分析流程 | 画布 |
| --- | --- | --- |
| 首次提问处理中 | 盘古显示整体处理中，不猜具体阶段 | 无旧页则保持空态 |
| 需要消歧或确认 | 盘古给出明确问题，结束本轮答复；受确认约束的执行等待 | 保留旧页并标为上轮结果 |
| 用户回应 | 必须关联正确的待确认内容，校验候选；确认有效后才能继续 | 新产物就绪前保留旧页 |
| 新页面就绪 | 答案、口径说明等仍只在盘古中呈现 | 校验通过且非过期/取消产物，才替换旧页 |
| 本轮只有文本 | 盘古明确本轮未生成页面 | 有旧页则保留并标识，无旧页则不造页面 |
| 本轮失败 | 盘古给出失败反馈，不从未知事件猜失败阶段，不默认自动重发 ask | 保留旧页，失败不能隐式清空 |
| 用户停止 | 按真实接口说明停止范围；仅停止接收时不宣称服务端取消 | 保留旧页，迟到结果不覆盖新状态 |
| 用户显式清空/删除或切换分析会话 | 按对应操作处理；保留旧页不跨越这些明确操作 | 不套用“永远保留”的错误规则 |
| 刷新/重新进入 | 按已验证历史与检查点能力恢复；未恢复时如实反馈 | 不能由“原页仍在内存”推导出刷新可恢复 |

确认可通过新轮承接，与 `metriccanvas-authoring/RELAY-HANDOFF.md` §6.3 “检查点保存 pendingInteraction、等待不保持长运行、确认后新轮恢复”一致；这是目标契约，不是现有盘古能力证明。
