# IOC 内容切换与锚点 · Frontend Design Delta

## 目标与 AC 引用
源为主计划 C3/F4 与 B2，用户已在交接前确认，并授权正式实施及本轮继续。AT-01～04见 tasks.md。不追加业务决策。

## 对接模式
页面试验场消费普通页面文档；RuntimeSurface 持有页实例状态；ComponentRenderer 和 RuntimeSection 继续是唯一渲染树。组件不查询，导航/返回栈属于集成应用。

## 文字规格
内容分区组使用有标签的选择按钮，仅所选组的分区可见，未归组分区一直可见；初始为显式默认组或第一个组。切走再切回保留每张表的页码、排序、局部筛选。全页筛选变化仍复位受影响表页码，包括隐藏组；不重置仍有效排序和局部筛选。
锚点有可访问名称，指向既有内容分区；目标位于隐藏组时先显示该组再定位目标。定位后用户可以继续从该章节阅读，不触发查询、不新增浏览历史。没有组或锚点的页面保持既有结构和行为。
缺乏旧站视觉基线，因此不承诺像素还原。布局使用现有token并允许窄屏换行；不提出新的响应式布局设计。

## 当前代码事实
表格视图已由RuntimeSurface按组件id持有，Tab卸载不会丢弃这些状态；所有数据源由orchestrate统一调度。已有RuntimeSection承担章节渲染。

## 状态、交互、接口与数据映射
sectionGroups是既有分区id的有限分组；每个分区至多归一个组，无递归。sectionAnchors直接引用分区id，拒绝不存在目标。没有远程接口增量。

## 风险与依赖
隐藏分区尺寸、键盘焦点、实例隔离需要页面验收。初始数据不证明真实DQE联通。新协议契约生成与创作能力仍放在全量IOC实施最后阶段。

## 入口参数（已确认P-02/P-04语义）
可选sectionGroupParam引用string页面参数，只初始化当前页面实例的内容组；缺席走既有默认组，非空未知组拒绝，不修改URL或共享状态。该增量承接主计划入口tab命中四组之一，不增加新的业务选项。
