日期：2026-10-21。

## 1 入口、范围与现行约束

- [完整需求与 gap 分析](table-column-candidates/analysis.md)：E1—E8、D1—D7、源码证据与证据层级。
- [DQE 简要对接说明](table-column-candidates/dqe-handoff.md)：可转发的请求样例、优先核验问题和回传要求。
- 术语：[CONTEXT.md](../../CONTEXT.md)。现行结论：[数据获取主题](../adr/topics/data-fetching-and-query-model.md)、[包边界主题](../adr/topics/domain-modeling-and-package-boundaries.md)。

本批能力目标：本表完整匹配结果按列去重，保留其他条件，只排除目标列自身表头条件；统一处理 inline、已证明完整的 query、普通查询分页与 pagedJoin。不同类型允许不同执行策略，但语义一致；能力无法证明时明确不可用，不以当前页或全局字典代替。

不增加任意 SQL、表达式、运行时模型生成查询、独立计算资产或页面内凭据；不扩大查询结果绑定的声明范围；不自动请求所有列的候选；不要求用户在页面中手写第二份候选 DQE。逐项计数不是首批必需能力。

依据：[ADR-0086](../adr/0086-server-side-sorting-and-header-filters-under-query-pagination.md)、[ADR-0105](../adr/0105-shared-page-data-execution-and-initial-consumption.md)、[ADR-0107](../adr/0107-query-page-windows-drive-result-dependencies.md)、[ADR-0108](../adr/0108-paged-join-and-unified-source-program.md)、[ADR-0051](../adr/0051-additive-minor-versions-for-page-schema.md)。

## 2 核心规则与条件来源

定义 R(c)：对目标列 c 排除其表头条件后，按本表原业务范围执行得到的完整匹配结果。候选为 R(c) 中字段 c 的稳定值去重，再按候选自己的搜索、排序和分页输出。这里的定义描述执行语义，不要求引擎实际把所有行下载到浏览器。

条件组合分两步：

1. 先按既有页面参数、筛选绑定及查询结果绑定规则，得到本表业务基线。页面绑定替换查询默认值的约定不被通用 AND 擅自改变。
2. 叠加本表已提交搜索与其他列表头条件。表头条件只能收窄业务基线；同字段多选条件取交集，区间合取。不支持无损编码时明确不可用，不能依靠最后一次赋值。

目标列表头条件应在来源尚未丢失时移除；不能对扁平生效查询按 queryField 删除。权限谓词仍由可信部署链路注入，页面不能声明、删除或缓存跨身份的权限范围。

空交集是已知空结果，不发送无约束请求。候选响应不写 FilterState、不写 TableSession 已提交视图、不覆盖普通源快照或 initial。

## 3 架构实现

### 3.1 Module 与 Interface 所有权

| Module | Interface 与职责 | 不承担 |
|---|---|---|
| 页面协议与校验 | 复用现有 select 列声明，检查字段及新增结构的能力版本；不增加候选 scope 开关 | 远程 URL、凭据、候选查询体 |
| SourceProgram | 新增列候选读取 Interface，统一条件编译、依赖、行域、执行策略与完整性 | DOM、弹层状态、下载文件 |
| TableSession | 唯一持有已提交表格视图，提供快照 | 候选数组、候选关键词、分页游标 |
| 候选读取会话 | 按使用者持有候选搜索、续页、状态、请求代次和取消 | 第二份已提交业务视图、业务条件改写 |
| QueryRunner | 主数据与候选共享总并发、完全相同请求复用及独立消费者取消 | 模型选择、范围扩大、完整性策略 |
| 数据网关 Adapter | 将受控的原查询字段去重意图编码成真实 DQE，归一化值和分页结果 | 识别页面列、选择哪些表头条件排除 |
| runtime-ui / widgets | 壳发起读取并投影状态；纯表格展示选项、搜索、续页与重试事件 | 解析 DQE、直连端点、判断全量 |

继续使用 codebase-design Skill 的 Module / Interface / Seam 分工。公开调用者只描述“读取本表某列候选”，执行细节集中在共享执行核心；不让 UI 选择普通源、组合成员或拉全量策略。

~~~mermaid
flowchart TD
  UI[表格交互与候选会话] --> SP[SourceProgram 列候选读取]
  TS[TableSession 已提交视图] --> SP
  SP --> PLAN[保留条件来源与选择执行策略]
  PLAN --> LOCAL[完整行集或有界组合结果去重]
  PLAN --> RUN[QueryRunner 共享请求资源]
  RUN --> GW[数据网关候选 Adapter]
  GW --> DQE[同身份的 DQE 执行链路]
~~~

### 3.2 Interface

共享执行 Interface 已落在 packages/data-execution/src/source-program/column-candidates.ts；以下为核心输入摘录，不是页面字段：

~~~ts
type ColumnCandidatesRead = {
  sourceId: string;
  field: string;
  conditions: FilterValues;
  view: TableQueryView;
  candidateSearch?: string;
  offset?: number;
  pageSize?: number;
  signal?: AbortSignal;
};

// SourceProgram.readColumnCandidates(request)
// 内部由候选会话携带 owner / generation；不把它们写入页面文档。
~~~

SourceProgram 接收完整 view，在内部按目标字段排除其表头条件并冻结输入。候选搜索与表格搜索分开：前者仅过滤候选列表，后者定义本表业务匹配范围。

网关已增加可选的受控查询字段去重端口，输入原生效查询、目标查询字段、候选搜索和分页；不输入 TableComponent，不暴露任意查询改写函数。现有 fetchDimensionValues 继续服务页面维度筛选器；表格统一走本表结果候选语义，不能因新端口缺席回落到全局维度字典。

候选结果至少表达：稳定值/显示名、当前页、是否有后续页及可验证的完整性信息；如返回 total，必须是当前候选搜索范围内去重数量。空结果、能力不可用、失败、部分可续页、完整均可区分。稳定值保留结果字段原始类型，显示名独立；首批不提供 null“空白”选项，也不把 null 转为空字符串。保留既有非成功码带非空数据的消费规则（包括 NO_PERMISSION）；消费资格与候选完整性分开判断。

QueryRunner 的数据与候选操作共享资源调度、并发、缓存及独立消费者取消；候选保持单独的结果类型，不写普通源快照。EffectiveQuery.filterValues 继续提供完整条件以保留既有网关读取能力；新增 bindingValues/tableFilters 来源信息供内置适配器按业务基线后追加表头合取，结果绑定同步更新两种投影。

### 3.3 执行策略

| 来源 | 执行方式 | 限制 |
|---|---|---|
| inline / 已证明完整的 query | 复用完整基线和纯 TableView 的过滤、搜索比较；应用其他条件后去重 | 不能从已被目标列条件过滤掉的快照恢复，也不能从当前页补猜 |
| 普通 query | 网关执行等价的字段去重查询 | DQE 必须证明相同模型、业务范围、原粒度及筛选顺序；不盲目删 output_metrics |
| pagedJoin | 在 SourceProgram 内对最终组合行域按目标列枚举 | canSelectPage 只证明选页，不能直接证明候选；先复用有界完整关联规则，不扩大当前 1000 行上限 |
| 计算产出列 | 仅在完整结果经过原具名算子后本地枚举 | 未完整时不可下推，不用页面字段 ID 冒充 queryField |
| 业务 TopN / 固定有限选择 | 保留业务窗口和决定该窗口的业务排序 | 不能为取候选移除原业务 limit；需与可变表格展示窗口区分 |

普通查询远程去重不可用时，首批不自动拉取 10 万行兜底。只有显式完整、已有范围证明或组合既有有界规则内才走本地策略，超限如实不可用。

### 3.4 请求、缓存、失效与批量

状态身份：表格使用者 + 字段 + 候选条件版本 + 候选搜索/页。请求身份：规范化执行内容 + 操作类型 + 可信会话范围 + freshness。两者分离：两张表不共享 UI 状态，完全相同请求仍可共用在途执行。

| 变化 | 候选处理 |
|---|---|
| 本表普通展示翻页、页大小、展示排序 | 不改变候选集合，不使候选范围失效 |
| 目标列自身的勾选 | 不改变该列候选集合；改变其他列候选 |
| 页面条件、其他列表头、已提交表格搜索 | 相关候选失效；可取消后按新条件读取 |
| resultBindings 的上游窗口 / 排序 / 过滤改变且提取集合改变 | 这是业务输入变化，必须使本表候选失效；不得扩大上游窗口 |
| 候选搜索 | 只重置该候选列表分页；不修改表格搜索或页码 |
| 身份、工作区、部署配置或可信权限范围改变 | 结束旧会话，丢弃旧候选及缓存，不依靠前端过滤旧结果 |
| 页面卸载 / 弹层关闭 | 释放该消费者；共享请求仅在最后消费者退出时取消 |

采用按需加载并可复用同条件结果。第一页初次读取或条件变更时，只对实际需要的候选做同轮批量。一次 HTTP 两项 DSL 是传输优化，正确性不依赖批量，也不承诺表格与候选事务一致。刷新使用新鲜作用域，普通翻页不触发全局候选重新读取。

## 5 规则冲突与处置

| ID | 冲突 / 风险 | 建议处置 | 状态 |
|---|---|---|---|
| C1 | 统一修改现有 select 会改变旧页行为，与 ADR-0051 的既有语义兼容要求冲突 | 用户选择 A：现有表格统一升级，无 scope 开关或旧语义分支；ADR-0114 对本次运行行为作局部例外，实施前盘点存量页 | 已裁决 |
| C2 | 当前按字段覆盖条件，与“保留同字段业务范围”冲突 | 保留绑定替换默认值规则；表头附加条件合取。不可表达时失败关闭，空交集不发请求 | 本仓实现及行为测试完成；真实 DQE 另验 |
| C3 | ADR-0086 对无 queryField 的上游条件跳过；新能力不能宣称这类列可远程筛选 | 完整计算结果可本地；非完整计算列候选明确不可用；如需收紧旧声明须走版本策略 | 已按完整结果 / 查询字段映射限定 |
| C4 | 按维度名共享缓存，与表格独立范围冲突；盲目禁用共享又违背 ADR-0108 请求复用 | 展示状态隔离、执行请求按内容复用；旧页面候选加载器不直接复用为新会话 | 本仓已实现 |
| C5 | 旧候选依 dependsOn 清下游值；本表候选变化若自动删已选值，会改写已提交业务条件 | 保留用户选中值，显示“已选，当前条件下无匹配”并允许移除；不把值混入可用候选；页面维度级联保持原规则 | 已裁决 |
| C6 | “翻页不影响候选”与 ADR-0107 上游窗口驱动输入冲突 | 限定为本表展示窗口；保留上游窗口作为业务输入，按提取集合失效 | 按现行规则可解 |
| C7 | 为取候选去掉全部 order/limit 会扩大 TopN、固定业务集合 | 保留业务选择，仅移除可变展示分页；TopN 条件施加顺序需单独核验 | 本仓保留业务范围已测；远程实际执行待 DQE 核验 |
| C8 | ADR-0108 要求共享 SourceProgram；在 RuntimeSurface 中直接拼候选 DSL 会新增第二套规则 | 统一执行核心，UI 只调用新读取 Interface；候选不成为新的页面数据源或普通 initial | 本仓已实现 |
| C9 | 非成功码带非空 data（含 NO_PERMISSION）的既有消费规则不能与候选完整性混为一谈 | 用户要求保留现有支持：HTTP/信封成功后沿用 canConsumeResult 及字段校验；无数据的非成功候选仍按不可用处理。另验分页、完整性和真实权限链路，不加 SUCCESS-only 门禁 | 消费规则已裁决；DQE 事实待核 |
| C10 | 完整读取与导出已有策略不等于候选完整性；当前 range-policy 有警告后保留或部分结果返回路径 | 只复用调度及分页基础，不直接将其快照标为候选完整；增加候选自己的完整性证明 | 本仓已实现 |
| C11 | “一请求两查询”与独立取消、懒加载可能冲突 | 批量只优化传输；取消按消费者，不能为批量让候选必须依附表格请求 | 按 ADR-0108 可解 |
| C12 | 候选状态按表格隔离，不能顺带使原本共享的普通查询源拥有多个相互覆盖的已提交视图 | 保留现有交互查询源独占要求；定义共享继续经独立组合源表达。候选读取按值接收 view，不写回其他消费者 | 按现行约束保留 |

详情表格当前明确不支持列筛选（validate.ts 的详情能力检查）；本批不因新增普通表格候选而暗中解除限制。单次页面取数仍返回页面文档，不为候选修改 ADR-0105 的输出封套；候选为按需运行态，不增加持久化采集资产。
