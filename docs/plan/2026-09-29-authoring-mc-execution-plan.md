## 1. 目标、范围和完成口径

目标：减少可避免的元数据重复读取、组件装配失败和语义试错，同时保持文件所有权、可信创作轮次、授权、结果与版本隔离。通过可复现证据说明哪些问题在 MC 已解决，哪些需要内部采用或真实接口事实。

| 角色/系统 | 承担任务 | 本计划产物 |
|---|---|---|
| MC 公共 Tool | 确定性语义解析、取数、结果证据、页面装配、失败反馈 | 公共实现、错误行为、针对性测试 |
| MC 公共 Adapter 模板 | 示范身份校验、快照接线、HTTP 分类和协议转换 | 可定向采用的参考实现、契约测试 |

不新增全局缓存，不放宽 RESULT_SCOPE_MISMATCH，不删 binding 字段，不恢复默认累计轮次预算，不引入稳定 ID 大迁移或统一就绪协议。保留当前显式预算配置、单次超时和证据大小限制。业务域继续是路由标签，不承担租户隔离。

完成分三级记录：

2. **MC 模型/页面验收完成**：真实 DS、页面产物及适用的本地浏览器验收分别通过。阻塞层保留 blocked/not-run。

## 4. M1：MC 可观测性与部署指纹

**问题**：统一约 14 秒不足以定位元数据；源码一致也不证明服务加载的是同一安装包。

**步骤**

1. 扩充部署指纹重点检查模块，覆盖 `metadata_session`、`results`、`executable_units`、页面装配与校验器等本轮路径；继续报告真实服务解释器下的 import 位置。
2. 复用现有诊断方式输出有限事件：操作阶段、耗时、缓存命中/认领/等待/重新获取、尝试次数、返回码类别和数据集数量。关联 ID 必须来自可信程序上下文并遵循脱敏策略。
3. 公共 helper 使用既有日志机制或最小可选诊断回调；优先不扩张 AuthoringAdapters 强制 Interface。模板记录元数据 HTTP 段，公共 Tool 记录自身可观察阶段，不伪造进程启动或 Relay 阶段。
4. 禁止输出 token、原始元数据、SQL、数据行、请求/响应全文和原始异常文本；日志写入失败不能改变查询或保存结果，不写 MCP stdout。
5. 建立本地冷/热调用计数基线；部署采用说明提供端到端分段表，要求 Relay 自行补其阶段。

**文件范围**：`scripts/deployment_fingerprint.py`、`data/metadata_session.py`、必要的公共诊断调用点、`examples/adapter_template/firstparty/dataset_metadata_http.py`、已有诊断/同步测试。

**完成标准**：文件漂移、旧安装包可识别；命中/未命中可解释；日志不泄露敏感内容；日志 sink 故障不影响主流程。性能回归主要断言 HTTP 次数与等待行为，避免依赖易抖动的毫秒阈值。

**Relay 配合 R1**：用真实服务 Python/PYTHONPATH 执行指纹，接程序日志并补进程启动、工具加载、可信轮次/页面核对等耗时。不阻塞 MC 本地实现；阻塞真实 14 秒归因。

## 5. M2：快照、重试与多进程隔离

**沿用设计**：完整可信 binding + source_identity；同轮固定发布快照；新轮刷新；存储由 metadata_session 注入；模板只负责源事实和接线。不会在 provider 中再引入另一份 store 缓存。

**步骤**

1. 将 source_identity 的端点、actor/workspace、凭据指纹、有效 dataset 范围、投影配置固化为可测试规则；检查 detail 子集与全量读取行为，以及 None/空 dataset 范围的现行含义，不能将空列表当零权限。
2. 为正常认领、等待、异常释放、取消、过期接管、迟到发布补确定性状态机验证。除可复现缺陷外不重写现有 CAS。
3. 新增独立 Python 子进程测试：共享真实临时 SQLite，使用本地可计数 HTTP fixture；父进程通过事件/屏障协调并发。覆盖进程退出及新进程恢复，不能以新建应用对象代替多进程。
4. 模板区分网络瞬断、超时、429/可重试 5xx、永久 4xx、鉴权拒绝、协议/业务错误；只有明确瞬时错误可重试。默认推荐初始请求失败后最多再试一次，最终上限与总截止时间一起冻结。
5. 传输重试和失败 dataset 补取共享获取预算，不能三层重试相乘。沿用现有加载上限，退避不能超过剩余时间；每次实际 HTTP 前后复核身份，不捕获取消后继续工作。
6. 检查查询已有 RetryingDqe 与 attempt 恢复的组合上限，补回归而非新增 Relay 重试层。成功结果不可变，保存 unknown 继续核对原操作。
7. 以故障注入检查同步中断的可检测性与恢复步骤；继续使用部署副本和配套版本回退，不扩张为新的在线发布系统。

**文件范围**：`data/metadata_session.py`、必要的 `data/results.py`/`query_attempts.py` 修复、公共元数据模板、`test_authoring_tolerance.py`、`test_dataset_metadata_http.py`、`test_deployment_sync.py`、新增多进程测试及 `test-layers.json` 登记。

**完成标准**

- 无故障且同键并发时只执行一次快照获取；租约失联可能重复只读调用，但只能接受有效 owner 的发布，不宣称远程恰好执行一次。
- actor/workspace/turnId/runId/requestId/contextRef、凭据、dataset 范围和投影分别变化时不误复用；新轮刷新。
- 同轮快照命中后取消/撤权仍阻止后续受控查询及结果消费；policy 变化不复用原政策结果。
- partial 保持缺口；完全失败/超限不冒充可用完整快照；失败后可恢复；晚到结果不覆盖新 owner。
- 永久拒绝不重试；瞬断有界重试；时限到达终止；未知保存不重发。
- 公共同步前后内部目录逐文件字节相同；本地公共补丁触发零写入失败；半更新状态可检测并按文档恢复。

**Relay 配合 R2**：定向采用模板、稳定完整 binding、持久共享 StateStore、确保实时撤权可由可信上下文/授权端口传达。做不到撤权保证时保持原读取方式。MC 用 fixture 完成上述验证，不修改内部 Adapter。

## 6. M3：让装配消费完整程序证据

**问题**：程序状态保留完整 execution.rows，但装配只看 20 行 initial 样本，导致完整性判断与样本数量耦合。

**推荐方案**：给内部装配调用传入从已授权 record 派生的最小证据视图。沿用 `QueryResults.require` 的身份、版本、政策与授权检查；模型不能提交 completeness 或原始 rows 自证完整。

**步骤**

1. 明确三个不同事实：DQE 返回行、页面 initial 样本、模型可见样本；上游 total_count=None 保持 unknown，不能用 effective_total_count 回退值证明全量。
2. 使用私有装配证据表达 returnedCount、可信总数/完整性与可验证选行。优先就地复用 record，不新增存储命名空间、MCP 参数或页面 Schema 字段。
3. 在 compose 和 add_result_component 两条路径接入同一验证逻辑。已有 source 无可信执行证据时保持保守行为，不从模型数据恢复证明。
4. metricCard 单行总量不要求 dimension；多行 match 必须证明唯一。pieChart 必须有完整且合法的占比证据；未知总数保持明确拒绝/调整指引，不仅改 count 比较符。
5. 核对 initial 样本在正式渲染前是否会被当完整饼图显示。若会，优先使用现有协议允许的省略 initial、等待查询或已有完整性判断；不能将 20/41 行先画成整体比例。若只能通过页面协议变化解决，转入设计裁决，不悄悄加字段。
6. 维持页面/模型证据大小上限；不得为“完整性”把所有行塞进模型消息，不能因超限自动放大预算。

**文件范围**：`data/results.py`、`data/executable_units.py`、`pages/referenced.py`、`pages/composition/page_structure.py`，必要的内部编辑装配调用点；`test_structure_current.py`、`test_platform_v2.py` 及相关夹具。

**验收用例**：1 行总量卡；多行唯一/重复/不存在 match；20、21、41 行；已知全量 41/41、截断 20/41、未知总数；无 initial；空结果；跨轮引用；strict/relaxed 切换；相同已授权结果同时供表格、卡片与饼图。页面重开取数不得出现样本比例失真。

**完成标准**：41/41 完整证据不因样本裁剪失败；20/41 和未知总数不被错误升级为完整；单行总量卡无需造维度；模型通道仍有界；页面协议保持现状，或先完成明确裁决。

**Relay 配合 R3**：DQE Adapter 保留真实 totalCount/分页事实，不把返回行数当总数。MC 不替外部服务推断完整性。

## 7. M4：规范名可用，歧义别名不静默选取

**推荐规则**：规范名唯一时精确命中规范名；别名只在候选唯一时解析；多个候选返回歧义诊断；重复规范名仍拒绝。不得以元数据顺序决定查询哪个指标。

**步骤**

1. 分开构建规范名索引和别名候选索引；合法别名冲突不阻塞无关规范名查询，别名不能抢占规范名。
2. 让发现、查询规范化、投影和错误候选遵循同一规则，保持业务域范围和候选输出预算；不公开未授权候选。
3. 确认消歧错误按请求返回，不使无关独立请求整体失败；strict/relaxed 对歧义保持相同安全规则。
4. 检查内容版本/缓存兼容性。规则变化不得复用旧语义执行结果；优先通过配套版本发布、排空活跃轮次和新轮采用解决，若需状态版本迁移先设计。
5. 为时间维度基名与 queryField 粒度列名增加现行协议回归。caption/name 的全局优先级保持不变，直到真实接口差异有证据；提供规范名、响应列名、标签的对账表。

**文件范围**：`data/data_context.py`、`validation_policy.py`、语义发现相关调用点、必要的 `lab_projection.py` 修复及相应 tests；字段协议检查复用现有 Python/TS 校验器测试。

**完成标准**：输入顺序置换不改变结果；共享 alias 不阻塞无关规范名；使用歧义 alias 不触发 DQE；规范名不被 alias 覆盖；候选不跨授权范围；时间列协议两端一致。

**Relay 配合 R4**：提供脱敏元数据与 DQE 请求/响应字段事实；撤回“setdefault 选第一个”和未经对账的全局 caption 补丁前，先按迁移表比较真实部署。MC 不直接操作这些补丁。

## 8. M5：口径文本统一且不残留

**步骤**

1. compose/add_result_component 复用同一口径格式化函数，统一换行、时间粒度和重复来源去重规则。
2. 成功组件按本 section 实际引用来源生成口径；失败块沿用明确未完成提示。不能把全局 sources 当 section 使用证明。
3. 对自动生成口径与组件引用关系作内部维护；替换、删除、移动、重复编辑后检查陈旧或重复说明。优先利用现有确定性标识，不向页面 Schema 添内部 provenance。
4. 用户编辑的普通文本不能仅因前缀像“数据口径”被删除。若来源关系无法确定，保留文本并明确自动维护范围。
5. add_source_component 无 resultRef 时不补虚构查询口径；文档说明能力差异。

**文件范围**：`pages/referenced.py`、`pages/composition/page_structure.py` 及必要的编辑辅助模块、平台编辑测试。

**完成标准**：同来源 compose/edit 格式一致；混合来源不串口径；全失败 section 不声称成功；重复编辑无重复说明；来源替换/删除无自动文本残留；人工文本保留。

**Relay 配合**：采用公共更新即可；不要求 Relay 复制页面装配逻辑。

## 9. M6：公共 Skill 修订与分层验收

本阶段编辑 Skill 时使用 `writing-for-agents` 指引；它属于实施阶段要求，本次计划不修改 Skill。

**修改内容**

- 单行总量卡直接绑定 measure；按行选取才用 match；字段只取 query_data 返回的字段 ID。
- 用例区分完整占比、截断样本和未知总数；barChart/table 也不能把局部样本称作全量排名或完整占比。
- discover 返回的规范名和时间粒度进入请求；不复制内部名猜测映射。
- 独立取数可在现有上限内合批，修改可按实际依赖合并；需先取得 resultRef 或新 workVersion 的操作不得强行合批。
- partial 明确缺失项；按现有 retrySafe/action 修复，不无界重试、不删除隔离字段。
- 格式只用有效预设和可信单位；不从“流水”推币种，不指示模型造 totalCount。

**文件范围**：`skill/metriccanvas-platform-authoring/SKILL.md`、`references/tools.md` 及必要引用文件；现有 preflight、cases 和评分器。

**验收**：按 `docs/agents/skill-ds-model-acceptance.md` 分层执行。首先预检（modelRequests=0），再确定性主流程，再相同清单的真实 DS，最后检查页面文档；本批涉及占比/选行呈现的代表产物进行窄范围浏览器重开取数与宽窄屏验证。其他纯隔离测试不扩展浏览器范围。

必需业务场景：总量卡、时间趋势、时间筛选下的类别排行、完整 41 行分组、截断/未知总数、含别名冲突但规范名明确的查询、局部失败后修复、既有页面追加组件和替换/删除后的口径。

**完成标准**：必需场景逐层有结论；失败轨迹保留；真实模型与 fixture/确定性分开报告。生产 Relay 不可用不阻塞 MC 本地测试；DS 或浏览器未运行则对应层不得标 pass。

## 10. M7：分发、迁移与回滚交付

**步骤**

1. 每个批次先跑变更相关 tests，最终一次执行测试清单、公共 harness、契约与 Bundle 检查；无新增变更或疑点不重复跑全量。
2. 修改契约源或公共分发文件后，使用现有生成器更新导出/摘要，不手改生成 lock。新测试登记到 `test-layers.json`。

## 13. 最终完成判据
