状态：2026-10-14 用户已授权开始实施；本仓实现与本地验收完成，真实 DQE 文本搜索编码／接入待验。[验收记录](../evidence/table-toolbar/acceptance.md)。

实施安排：用户先要求记录并等待统一实施，后于2026-10-14明确要求“开始实施”。本次在最新共享查询执行及查询结果过滤代码上接入表格工具区，保留其他在途改动。

## 实施结果

- 页面协议6.21新增 `props.toolbar`，支持分别声明搜索和 `xlsx` 导出；同步版本门禁、文本字段／映射校验、契约反例、完整示例及创作分发。
- 表格搜索草稿与已提交关键词按组件 id 隔离；查询搜索进入共享生效查询、缓存键、取消及依赖更新，提交重置第一页。内联及显式完整结果在分页前本地搜索。
- 查询搜索继续沿用独占页面数据源约束，没有引入新的共享查询视角或 `pagedJoin` 数据源分支。该约束在产品校验器和创作端校验器中同步执行。
- DQE 网关提供可注入的 `encodeSearch` 接缝；缺少经过核验的编码器时在传输前明确报告 `DQE_CONFIG_ERROR`，用户仍可清空搜索恢复原查询。
- 单表导出复用完整取数规则，按目标数据槽及依赖闭包准备数据；上游查询分页输入保留捕获窗口，目标表格展开全部匹配页。超限、总数变化、取消及准备超时明确失败。
- ExcelJS 4.4.0负责客户端工作簿编码；多级表头、复合字段、数据槽对齐、数值与单位、静态展示格式、日期、文本及实际下载已接入。HTML发行保持单文件，编码库代码随同打包并按需初始化。
- 普通表格、Tab及表格变体、完整详情表格共用工具区；报告静态导出隐藏工具区并保留提交后的搜索结果。
- 创作端的 `record-list` 呈现和 `set_properties` 受控编辑均支持工具区；Python语义校验、Schema版本门禁与TypeScript契约一致。

剩余工作：当前真实DQE的文本谓词编码、组合规则和匹配总数需要实际接口证据与联通验收；尚未执行真实DS模型、Java／Relay／部署验收或Git交付。注入网关的浏览器通过不能替代真实DQE证据。

## 已确认的目标

- 所有 `table` 都具备可配置的右上角搜索与导出入口，两项可独立开启。
- 搜索覆盖整张表的数据，查询分页时也覆盖全部记录。
- Excel 导出包含当前筛选、搜索条件下的全部结果。

“全部记录”指当前查询定义及页面筛选限定的结果集合，不扩大查询授权范围，也不去除业务上的 TopN 等显式集合限制。

## 已认可的结构影响与统一实施边界

本次是中等范围的跨层能力扩展。页面分区、布局及 Tab 结构基本保持；主要变化集中在表格视图状态、查询执行和完整导出。

| 层次 | 结构影响 | 统一实施时需要合并的改动 |
|---|---|---|
| 页面协议与创作 | 每张表新增可选工具区声明，旧页缺省行为保持 | Schema、公共类型、版本门禁、校验、协议说明、中立契约和创作 Skill 分发统一更新 |
| 表格呈现 | 共用右上角工具区，呈现输入、加载、错误并上抛操作 | 各表格变体、Tab 和详情中的表格复用实现；搜索、查询和文件编码不进入纯渲染组件 |
| 统一运行时 | 按表格隔离搜索草稿与已提交值，协调页码、排序、筛选和导出作用域 | 与其他表格视图状态、页面实例生命周期及导出状态改动一起收口 |
| 查询执行与数据网关 | 查询分页搜索下推，上游返回匹配结果与总数 | 复用共享查询执行模块，合并搜索条件、字段映射、取消与结果归属；不另建重复的查询通道 |
| 完整取数与文件导出 | 增加单表依赖范围、列投影及 Excel 编码／下载 | 与现有完整导出共用完整性规则，保留报告 PDF 的集成应用编码职责 |
| 平台与外部接入 | 页面管理、Java 页面资产存储、qiankun 接入原则上无需新增业务流程 | 采用更新后的协议与引擎产物；真实 DQE 搜索能力单独核验 |

**最关键的结构风险是查询状态隔离。** 当前查询执行状态主要按页面数据源管理，而新搜索状态按表格管理。两张表共用一个查询页面数据源时，独立搜索不能相互覆盖，也不能影响共用该源的图表。优先沿用独立页面数据源承载独立查询视角；若统一需求明确要求共享数据源且各表独立搜索，需进一步设计运行时查询视角与执行身份，不能仅在界面层增加关键词。

与[共享页面取数与 Relay 召回计划](2026-10-14-shared-page-data-execution.md)在查询执行模块、字段映射、生效查询与初始结果消费方面存在交集。统一实施时以核对后的共享模块接口为准，本方案不预先冻结当下源码路径或形成平行实现。

用户认可的是需求口径与上述结构方向。当前批次采用查询源独占策略和ExcelJS编码库；共享数据源的独立查询视角属于后续组合源设计，真实DQE搜索编码仍是集成待办。

## 现有实现与缺口

- `packages/page/src/schema/components/table.ts` 的严格 `props` 尚无搜索与导出声明。
- `packages/engine/widgets/src/components/table/Table.svelte` 是纯渲染组件，当前只有标题、列头交互和分页；不持有查询状态。
- `packages/engine/runtime-ui/src/RuntimeSurface.svelte` 持有按组件 id 隔离的表格视图状态，适合作为本次交互的状态所有者。
- `packages/engine/runtime-ui/src/filters/inline-search.ts` 实现的是页面级搜索，不具备每张表的独立搜索字段与关键词。
- `packages/data-execution/src/effective-query.ts` 及 DQE 编码目前只有维度枚举、范围与时间等筛选分支，没有搜索分支。ADR-0086 明确记录查询分页搜索仍有缺口。
- `packages/engine/runtime/src/export-snapshots.ts` 已有通过同一数据网关准备完整数据的逻辑，但入口面向整页，不能直接作为单表 Excel 导出使用。
- 现有报告 PDF 导出接口交给集成应用编码；单表 Excel 的入口、数据投影、编码和下载尚未实现。

以上为实施前源码检查结果；实施后的代码与本地浏览器证据见本文件开头的验收记录，真实DQE尚未验收。

## 页面配置（6.21）

在每张表的 `props` 中新增可选 `toolbar`：

```json
{
  "toolbar": {
    "search": {
      "fields": ["customerName", "projectName"],
      "placeholder": "搜索客户或项目"
    },
    "export": {
      "format": "xlsx",
      "filename": "项目明细"
    }
  }
}
```

- 省略 `toolbar` 不显示入口，保留现有页面行为。
- 省略 `search` 或 `export` 分别关闭该入口。
- 搜索字段显式声明，首版限当前表格 `main` 数据槽的文本标量字段。查询页面数据源必须具有有效的 `queryField` 映射；计算产出字段不能冒充上游字段。
- `placeholder`、`filename` 可选，省略时采用通用文案和已解析的表格标题。
- 配置放在当前表格内，关键词、加载与错误状态属于页面实例，不写回页面文档。
- 首版搜索与导出同时覆盖普通、`reportCompact`、`embedded`、`forecastMatrix` 表格以及 Tab 内表格。详情中的表格需复用当前详情查询作用域，避免套用正文状态；只读呈现由实例能力控制。

当前Schema6.21已支持此结构，字段语义见[正式表格协议](../page-metadata/components/table.md)。

## 搜索行为

- 右上角搜索只影响当前表格；多张表关键词分别保存。
- 搜索多个字段采用“任一字段包含关键词”，与页面筛选、列头筛选采用交集。
- 按 Enter 或点击搜索按钮提交，提供清空入口；草稿与已提交关键词区分，导出只捕获已提交值。
- 搜索提交及清空均重置为第一页，保留当前排序和其他筛选。
- 内联页面数据源先搜索再排序、分页；具有完整结果契约的查询结果可在完整结果上执行同一文本匹配。
- 查询分页通过统一运行时、共享查询执行模块和同一数据网关下推搜索，更新匹配总数。禁止以当前页筛选充当全表搜索，也不自动拉全表替代查询分页。
- 同一查询页面数据源被多张表共用时，需要独立的表格查询视角。实施前验证现有共享数据源约束；无法隔离时在创作／校验阶段明确要求独立页面数据源，不能让一张表的搜索改动另一张表或图表。
- 清空、连续提交、查询失败与页面销毁使用既有取消和请求结果归属机制，防止旧结果覆盖新关键词。

## 单表 Excel 导出

- 导出开始时捕获当前表格已提交搜索、页面筛选、列头筛选和排序。
- 仅准备该表格使用的数据槽及查询结果绑定、计算所需依赖，不执行无关表格或整页查询。
- 复用完整取数规则，按同一已认证数据网关逐页取得完整匹配集合，独立于当前浏览页码。
- 根据当前表格声明的列顺序、多级表头、主／次字段形成工作簿；列标题保留业务单位，链接、选择按钮和图形装饰不进入单元格，语义 HTML 转为可读文本。
- 数值保留数值类型，采用 Excel 可表达的显示格式；涉及缩放的展示策略须验证值、单位和显示结果一致，不能把显示文字误当原始数值。
- 表格渲染组件只显示导出状态并上抛请求。完整取数与列投影归统一运行时；浏览器文件模块按需加载编码库并发起 `.xlsx` 下载，HTML 与 Svelte 入口复用。编码库选型、打包体积与离线运行在实施阶段核验。
- 本次拟沿用现有导出每个结果最多 10,000 行、准备最多 60 秒的规则；超限、总数变化、分页提前结束、缺少完整性证明均明确失败，不下载部分文件。
- 页面更新、销毁或取消终止导出；正在导出时防重复点击，失败后允许重试。正常页面搜索与浏览继续独立进行。
- PDF 静态导出视图移除搜索与导出交互，但保留已提交搜索限定的数据集合。

## 尚需核验的真实接口

仓内 `docs/evidence/中间层分析.md` 记录了旧 GraphQL `@where` 的 `like` 用法，但它不能证明当前 DQE JSON 协议支持相同编码。

实施查询分页搜索前必须取得当前 DQE 的证据：文本包含、多个字段 OR、与既有谓词 AND 组合、字面量／通配符转义、大小写规则、匹配结果总数，以及这些条件与分页和排序同时使用的请求／响应。不能凭旧接口样例新增一个假定支持的 DQE 请求字段。

本仓已完成协议、表格入口、内联搜索、查询搜索执行链路和Excel导出。真实查询分页搜索只有在编码证据确认并接入后才可宣布可用。若真实DQE暂无该能力，需由DQE维护者补齐，不能降低已确认的全表搜索需求。

## 实施顺序与验收

1. 冻结配置与搜索／导出行为，核验 DQE 搜索请求证据和共享数据源隔离策略。
2. 更新页面 Schema、公共类型、版本门禁、字段校验、组件说明及最小有效／无效示例。
3. 实现表格工具区、按组件隔离的草稿／已提交搜索状态，以及本地搜索和查询搜索链路。
4. 提取可复用的完整数据准备能力，实现单表范围、依赖闭包、列投影、Excel 编码与下载。
5. 同步中立契约、创作 Bundle 和本地创作 Skill 分发产物；遵循仓内 Skill 维护流程。
6. 完成协议、运行时、编码与浏览器验证，报告本地证据与真实 DQE 验收分别达到的范围。

关键验收用例：

- 未配置、只搜索、只导出、两项均开；无标题表格仍显示右上角工具区；窄屏不产生页面横向溢出。
- 两表分别搜索互不影响；Tab 切换保留各自已提交关键词；各变体与详情表格行为一致。
- 唯一命中位于第二页之后，提交后第一页正确出现该行且总数正确；清空恢复集合；排序及其他筛选仍生效。
- Excel 覆盖所有匹配页，行数与总数一致，顺序与当前排序一致，表头、文本、日期、数字和缩放单位正确。
- 在导出期间改变搜索不改变已捕获文件范围；取消、超限、总数变化或编码失败不下载部分文件。
- 同一能力通过内联页面、本地 DQE Sim、HTML 集成和 Svelte 集成验证；真实 DQE 请求／响应另行保留证据。
