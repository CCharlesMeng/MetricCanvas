# 表格默认排序与决策意见明细合并分页方案

日期：2026-10-23；更新：2026-10-26。状态：6.61 pagedUnion 通用协议、整体默认排序、检查点、完整表格操作与 local-authoring 引导已实现并完成本地验收；真实 DQE/Relay 接入未验。现行实现与未关闭项见[验收记录](../evidence/paged-union/acceptance.md)。

本轮确认将整体默认排序放在合并源 `ordering.default`，Table 首屏同步、清除用户排序后恢复。早期独立 `props.defaultSort` 草案未纳入本次；下文保留原方案与专用预览背景，实施状态以本段和验收记录为准。新入口为 `/pages/multi-source-table`；本地开发服务使用 5193 端口，模拟与真实服务分别验收。

预览入口：`http://localhost:5173/pages/decision-opinion-details`，运行说明见[表格示例](../../pages/capabilities/table/README.md#决策意见明细)。本次采用既有 query 数据源和专用模拟适配器，冷跳页扫描前缀并保留最多 8 页缓存，尚未实施通用执行器、检查点或真实 DQE 接入。

决策意见明细需要把合同、商务两份统计结果放入同一张表，按决策总次数降序展示，并支持全局排序与查询分页。首选在本仓实现前端有序归并，复用现有查询接口；真实接口能力不足时，再协调上游。用户已授权自拟数据和字段契约推进，不以补充真实查询资料作为本地建设的前置条件。

## 已确认的业务规则

| 项目 | 规则 |
| --- | --- |
| 页面 | 决策意见明细，使用 Dashboard 布局 |
| 列 | 审批人、区域、代表处、审批人角色、类型、决策总次数、有效意见数、有效意见占比 |
| 行粒度 | 审批人 × 区域 × 代表处 × 审批人角色 × 类型 |
| 合并 | 合同、商务记录逐行拼接，保留来源，不跨源聚合或去重 |
| 默认排序 | 决策总次数降序，两类记录混排 |
| 用户排序 | 决策总次数、有效意见数、有效意见占比支持升降序 |
| 占比 | 后端直接返回，前端不重新计算 |
| 类型筛选 | 位于类型列表头，合同、商务多选及清除恢复全部；筛选参与全局范围与总数计算 |
| 分页 | 准确匹配总数、总页数、任意页跳转；接受首次深页加载更慢 |
| 数据变化 | 实时浏览，接受数据变化对连续翻页的影响，不要求跨请求事务快照 |
| 部分失败 | 任一参与来源失败，整次合并查询失败，不展示半份结果 |
| 上游改动 | 优先只改本仓，无法满足时再讨论上游能力 |

## 合成字段契约

完整输入和预期顺序见 [合成样例](paged-union-table/example-input.json)。它是设计夹具，不是当前可加载的页面 JSON，也不描述真实 DQE 指标名。

两份结果除决策总次数字段的名字外，使用相同的原始字段。类型由来源显式赋值。缺少真实资料时，按以下固定契约开展本地实现与验收：

| 页面字段 | 合同结果字段 | 商务结果字段 | 合成约束 |
| --- | --- | --- | --- |
| localRowId | 统计行编码 | 统计行编码 | 来源内唯一、非空 string |
| approverId / approver | 审批人编码 / 审批人 | 同左 | 稳定编码与显示名分开 |
| regionId / region | 区域编码 / 区域 | 同左 | string |
| officeId / office | 代表处编码 / 代表处 | 同左 | string |
| roleId / role | 审批人角色编码 / 审批人角色 | 同左 | string |
| businessType | 字面量 contract | 字面量 commercial | 显示名分别为合同、商务 |
| decisionCount | 合同决策总次数 | 商务决策总次数 | 非空、非负整数 |
| validOpinionCount | 有效意见数 | 有效意见数 | 非空、非负整数 |
| validOpinionRate | 有效意见占比 | 有效意见占比 | 原始为 0—1 或 null；现有 percent 格式需要适配为 0—100 后展示 |

全局行键采用结构化的“来源 ID、来源内行键”二元组，编码后交给现有 rowKey。不同来源的 001、同名审批人、同一人在不同代表处或角色下的记录都不能相互覆盖。来源内行键须对应上述完整统计粒度，不以姓名或业务编号猜测。

占比样例中，合同 001 的总次数为 120、有效意见数为 90、占比为 0.63。前端必须显示 63%，不能自行改成 75%；这里只验证占比透传，不定义其业务公式。

## 表格默认排序草案

新增可选 `props.defaultSort`，结构复用现有 `TableSortRule[]`。本例为：

```json
{"defaultSort":[{"field":"decisionCount","direction":"desc"}]}
```

该字段为待实施协议，当前页面校验器尚不接受。默认排序使用页面字段，不写查询字段名；初始表头须显示相同排序状态。

1. inline 或显式完整结果：先筛选、搜索、排序，再本地分页。
2. 普通查询分页：默认排序进入生效查询，在上游排序后取页，不对当前页补排。固定业务 TopN 的选取范围保持不变，无法安全覆盖其排序时拒绝冲突配置。
3. 合并分页：同一排序通过每个成员的字段映射下推，再进行有序归并。
4. 有该配置时，用户清除临时排序恢复表格默认排序；无配置的旧页面保留现有行为。改筛选条件或页大小保留当前排序并回第一页。
5. `sortable` 只决定用户能否点击列头，默认排序本身仍生效。普通表格沿用已有可排序标量范围；本次合并示例仅开放三个数值列。
6. 表格默认排序优先于普通查询的展示排序；未声明时保持原查询顺序。已有 pagedJoin 未声明表格默认排序时继续使用 `ordering.default`，声明时须满足其可排序字段约束，不新增相互竞争的会话状态。
7. 查询分页表继续独占公开页面数据源；不要通过同一查询源给两张表配置互相冲突的排序。

协议版本在实施时扫描当前版本分配，按增量能力登记，不在计划中预占次版本或 ADR 编号。首次实施也应明确行内子表对 defaultSort 的支持范围，不能由父表配置暗中继承。

## 分页合并源草案

新增 source.type 判别分支，暂名 `pagedUnion`，与 pagedJoin 分开。对表格只暴露一个 `data.main`。

- 成员引用页内普通查询定义，每个成员声明来源内稳定行键，以及最终页面字段到成员字段的显式映射。常量类型通过受控字面量投影声明，不执行函数、公式或字符串表达式。
- 最终结果字段契约只维护一份；校验各成员类型、单位与可空性是否兼容。成员原有 queryField 负责外部字段归一化，不复制查询体。
- 初版不支持成员 compute、resultBindings、嵌套组合或业务 TopN。分页窗口由内部执行角色拥有，不能把普通成员的已返回第一页当作合并输入全集；成员也不因被引用就被要求返回 complete 结果。
- 组合结果只写入组合源的公开数据快照，成员的独立消费者保持原状。组合结果不是完整跨源计算输入。
- 类型列表头筛选决定参与的成员集合；未筛或全选时相加两个匹配计数，单一类型时只查询该成员。区域等条件如接入，必须先下推到各源，再计数和归并。当前类型列结果使用合同、商务显示值，候选与筛选保持相同值域，适配器显式映射至来源 ID。
- 表格 defaultSort 为默认展示排序真源，最终业务排序后追加来源 ID 升序和来源内行键升序。成员内部按相同业务排序和本地行键排序；来源 ID 在该成员内部为常量，无须伪造查询字段。
- 页大小示例取 3 以观察边界，正式演示取 20；读取批次初值建议 200，具体限制由 mock 性能验收调整。批大小属于执行策略，不作为作者必填业务配置。

## 前端有序归并执行

1. 根据已提交类型筛选选择成员，组合页面筛选与成员原有条件，构造同一视图版本的生效查询。
2. 分别读取有序批次及匹配总数。任一成员失败、缺少必需计数、返回结构错误或来源内行键重复，整轮失败。
3. 将各成员当前头行按统一比较器比较，取最前一行后推进该成员。缓冲耗尽时继续读取该源，不能按“合同第 N 页 + 商务第 N 页”拼出全局第 N 页。
4. 消费全局 offset 之前的行，保留目标页的 pageSize 行。未读来源可能全部排在目标页之前，因此不能各取半页，也不能假定每页都有两种类型。
5. 保存有界的页结果与检查点。检查点包含各成员已消费 offset 和可恢复的缓冲位置；记录已抓取 offset 却丢弃未消费行会跳数，必须覆盖此回归。
6. 新排序、筛选、页大小、数据刷新或身份权限修订清除受影响页缓存和检查点。取消中止成员请求，迟到结果不能覆盖新视图。
7. 数据源由正常非空变空或页码越界时，根据本轮计数执行一次有界纠偏，不无限重试。读取中发现同一来源计数改变，丢弃本轮进度并最多重试一次；再次变化失败，不把不完整扫描标成正确结果。

运行职责继续由 SourceProgram、QueryRunner 和 TableSession 承担，UI 不实现另一套查询规则。QueryRunner 当前缓存无逐项容量限制，实施时必须处理归并扫描产生的前缀请求缓存，不能只丢掉归并缓冲却让所有历史批次留在普通会话缓存。检查点、页结果、请求缓存分别设置容量，淘汰后允许重新扫描。

来源数为 k 时，冷跳到 offset 的扫描工作量随 offset 增长；用堆归并可将比较工作控制在 O((offset + pageSize) log k)，缓冲和缓存保持有界。接受深页更慢不等于承诺任意数据规模下固定响应时间。合成验收分别记录首屏、冷深页、缓存深页、请求次数、读取行数、缓存容量与取消行为；不把 mock 耗时写成真实 DQE 指标。

实时浏览不提供事务快照。准确总数指本轮各参与源按相同业务条件返回的匹配计数之和；计数和数据页来自多次请求时，无法仅凭浏览器保证同一数据库时点。数据变化且总数未变也可能无法检测，这属于已接受的实时浏览语义。

## 模拟接口与真实接入

本地模拟网关明确提供以下能力：两个独立统计结果、三列数值排序、来源内行键次序、升降序 null 排尾、offset/limit、匹配总数、类型选源、取消和可注入错误。按规范先排序完整合成数据，再切页，归并执行端只能消费分页端口，不能偷读 mock 全集。

有序归并正确性依赖成员流使用同一比较语义。真实接入必须核实数值类型、占比刻度、空值位置、多列排序和同值稳定性。前端对已返回小批次重排不能修复跨批次的不稳定次序；仅有分页数据也无法在未知全量上重新计算后端占比。

适配器由集成应用注入，保留现有权限、凭据和正式 DQE 路径。mock 的能力不能自动成为真实适配器的能力声明。真实接口若无法兑现稳定有序流或匹配计数，记录具体不兼容项后再讨论上游修改，不退回当前页拼排。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 默认降序，每页 3 行 | 第 1 页为商务 001、合同 001、商务 002；总数 8，总页数 3 |
| 同值跨页 | 三条总次数为 100 的记录按来源和本地键稳定排序，合同 002、003 位于第 2 页 |
| 重复局部 ID 和同名 | 两边的 001 都存在；同一审批人不同代表处或角色分别保留 |
| 切有效意见数降序 | 商务 001、合同 001、合同 002 排在前 3 位，页码回到 1 |
| 切占比降序 | 合同 002、合同 003、商务 002 排在前 3 位；null 最后 |
| 切占比升序 | 合同 004 的 null 仍最后，按原始数值而非百分号字符串排序 |
| 后端占比透传 | 合同 001 显示 63%，不根据 90 和 120 重算 |
| 类型仅合同 | 总数 4；首 3 行为合同 001、002、003，不请求商务源 |
| 前几页全来自同一源 | 扩展数据中不按固定来源配额取行 |
| 冷跳页与缓存跳页 | 与独立完整排序基准一致；检查点恢复不漏未消费行 |
| 失败与并发 | 单源超时、拒绝、计数错误整轮失败；取消和迟到响应不污染新视图 |
| 数据变化 | 计数变化触发有界重试或纠偏，权限变化清除旧缓存 |
| 大规模数据 | 增加 10 万、100 万行的按需生成模拟数据，验证内存有界；实际性能记录后评估，不预填通过 |

搜索、其他列头筛选与导出只有在新源能兑现完整匹配范围时才开放，不能继承按钮后筛当前页。若接入导出，沿用 10000 行与 60 秒上限、冻结已提交条件和失败不输出部分文件；百万行导出不属于本次范围。
