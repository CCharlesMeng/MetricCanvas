# 统一 Platform 创作 Skill：整体方案

状态：历史方案与内部调查分析记录。正式实施依据为[统一创作 Skill 规格](../specs/2026-09-15-unified-authoring-skill.md)，当前目标架构统一维护于[页面创作 Agent：统一目录、执行契约与功能迁移](2026-09-15-authoring-agent-architecture.md)。其中候选准备/程序提交、可恢复执行和扩展契约替代本文较早的接口提案。已确认的用户目标与交互原则不等于所有接口均已实现。

## 1. 目标与依据

采用一个 Platform 创作 Skill，统一处理解释当前页面或组件、修改当前页面、明确新建页面。内部参考按任务拆分，工具按确定性职责拆分，不再维护创建与修改两套独立工作流。保留普通问数 Skill 的独立入口与临时页面态语义。

用户已确认：统一对话入口；模型负责完整方案；无实质歧义时直接生成初稿；独立任务允许部分完成，依赖任务不得留下不完整结果；AI 与人工编辑互斥；发送时交接，等待澄清且无未决写入时解锁；当前工作台严格互斥，其他窗口变化由版本冲突处理。用户确认“云宝”就是仓库中登记的“盘古”；本方案沿用盘古命名，不另建一套产品对象或 Adapter。

本次优先交付 Skill 的执行逻辑、结构与体积优化。选中组件上下文为必要的最小平台接缝，独立交付；完整交互恢复、真实外部接线及新增工具能力单列，不让它们无限扩大首批范围。

依据：评测消费提交 d015c22（模型请求 deepseek-v4-flash，响应 deepseek-flash，固定版本未验证）。14 例为 6 pass、3 fail、5 blocked；三个失败均误用数据发现查文档，编辑产物正确。运行器只注入主文/共同规则/布局，没有加载完整参考包。34 次请求的 558,252 tokens 不能归因于 18 万行 Skill 分发资料。四个数据创建场景缺服务配置，所有真实路由断言未验证。

## 2. 领域与不变量

沿用 CONTEXT.md 的页面、创作草稿、页面修订、页面模板、页面实例、页面数据源、页面构建规格、取数单元、临时页面态等术语，不另造等价概念。

- 人工和语言编辑作用于同一份逻辑创作草稿。浏览器工作副本承载尚未同步修改；已保存修订是不可变的持久化事实。两者是不同阶段，不是互相竞争的作者源。
- 对话历史不是页面状态真源。模型记得旧标题、旧 JSON 或旧 token，不授予覆盖当前页面的能力。
- 每次收到用户指令，包括澄清回复，已有页面都必须在可视化修改同步成功后，按 pageId 获取服务端最新页面元数据及其精确修订。不得用上轮上下文或本地缓存跳过本次获取。每个可执行修改绑定本次取得的精确基线；每次写入仍验证基线及当前权限。获取最新元数据不等于每轮向模型发送全文，也不等于重新执行业务查询。
- 选中组件是指代消解的上下文，不是修改授权，也不证明存在真实数据证据。
- 解释不产生内容改动；内容生成不等于保存；保存不等于人工确认发布。保留 ADR-0078 的内容与生命周期职责。
- 完整页面、数据行和原始查询保留在程序通道。模型只接收完成任务所需的安全摘要及引用。
- 用户未涉及的内容保持；歧义不通过猜测解决；不支持的能力不得通过重建整页或替换别的组件冒充完成。

## 3. 真源归一

“一处编写、多处生成或消费”是目标，不要求所有运行环境读取同一个物理文件。

| 事实 | 唯一作者/责任方 | 其他位置如何消费 |
|---|---|---|
| 领域含义 | CONTEXT.md | Skill、方案、代码使用同一术语，不在词汇表写流程或 SDK 细节 |
| 页面结构、组件能力、页面校验规则 | 现有 Page 作者及中立导出 | Python 使用锁定快照，Skill 不复制字段全集 |
| 受控请求字段与合法操作 | 现有 Authoring authored contracts 及其工具声明 | MCP Schema、请求测试和指南示例校验；不新增手写 JSON/TS/Python 平行契约 |
| 自然语言任务策略 | 一个创作 Skill 的主文及任务参考作者 | 盘古与本地评测消费同版本作者；适配器不另写一份业务 prompt |
| 当前草稿、同步状态、编辑占用、结果接收 | 现有工作台协调 Module | UI 订阅状态；Skill 只消费本轮上下文，不持有第二份状态机 |
| 精确已保存修订、权限、幂等及原子保存裁决 | 外部 Java 页面资产能力 | 生命周期端口消费，浏览器与模型不自行宣称强保存 |
| 本轮页面/选中对象/关联信息 | 程序在交接时生成的不可变本轮上下文 | 盘古 Adapter 原样传递受控内容；模型历史不得覆盖该上下文 |
| 盘古 SDK 协议 | 提供方正式协议 | 只由盘古 Adapter 翻译；内部上下文不直接假定为 SDK wire 字段 |
| 参考分发、manifest、锁 | 标准导出器 | 生成物不手改；生产、本地测试和独立分发校验同一版本 |

新增的跨语言本轮上下文结构沿现有中立 Authoring 作者/导出机制只定义一次；TypeScript 与 Python 不各写一套 DTO。先复用现有 LanguageContext/精确引用/产物关联；确有缺失才扩展，不重造身份、版本或保存协议。上下文中的身份字段用于关联，服务鉴权仍从可信程序身份获取，不能相信模型回传值。

## 4. Module 分工与 Interface

这些是职责归属，优先深化现有 Module，不意味着必须新增五个包或服务。

| Module | 对外提供的行为 | 内部集中处理 | 不承担 |
|---|---|---|---|
| 创作协调 Module | 开始一轮、接收结果、取消/查询恢复 | 手工输入交接、同步门禁、精确基线、编辑互斥、选择冻结、过期结果拒收 | 理解业务指标、生成组件 JSON |
| 对话 Adapter | 把本轮上下文与请求交给盘古，返回结构化结果 | SDK 装载、消息关联、取消映射、资源释放 | 页面修改算法、另一套任务策略 |
| 创作 Skill Module | 根据可信上下文理解任务、组织方案和受控调用、解释结果 | 指代消解、业务澄清、任务分支、指南选择、错误后行动 | 自行获取凭据、保存全页状态、互斥、原子发布 |
| 内容工具 Module | 按受控规格生成/修改页面，返回校验后的产物与摘要 | 查询验真、组件装配、参数校验、未涉及内容保持、操作结果 | 模型会话、页面持久化、SDK 协议 |
| 生命周期 Module | 精确读取、保存与原操作恢复、发布消费 | 修订关联、完整性、幂等和外部权威结果消费 | 组件装配、对话推理 |

Module 内部允许组合现有小函数；调用方不需要知道“先等哪个队列、何时换 token、何时比较 epoch”。这些顺序约束集中在创作协调 Module 的 Interface 后。测试从相同 Interface 验证，不要求 UI、Skill 与 Adapter 分别重复整套顺序。

不新增通用 Agent Runner、通用意图路由服务、页面自动合并引擎或协议检索服务。本地模型运行器仅用于评测，不成为第二套生产编排。

## 5. 一轮执行流程

1. 用户在统一对话入口输入请求，可能选中一个组件。
2. 发送触发交接：提交当前输入、暂停新增手工修改、等待同步确定成功。失败保留工作副本，不启动 AI。
3. **按 pageId 获取最新页面元数据**：已有页面每轮都实际执行此步骤。服务端返回的元数据必须与精确修订一致；获取失败则不执行依赖页面状态的任务，不回退到旧上下文。程序以本次结果固定基线、重新解析选中对象，再生成模型所需摘要与引用。尚不存在的全新页面没有可读取基线，由程序在明确新建时分配身份，不借用原页身份。
4. 同一个 Skill 判断解释、修改或新建：目标明确则继续；业务或目标存在实质歧义则提问。历史意图与当前明确请求不一致时，以本轮请求和可信上下文为准。
5. 模型形成方案并直接执行已支持的受控操作，不增加通用的“方案批准”步骤。工具自行校验结构与业务不变量。
6. 内容结果进入程序通道。沿既有生命周期保存流程处理可保存结果，发布仍须独立人工确认。程序核对本轮关联与基线后更新画布；Skill 仅按已确认结果报告。
7. 无未决写入时结束本轮并恢复手工编辑；等待用户澄清也释放占用。下一轮重新交接。超时、取消不视为撤销服务写入，保留原操作查询恢复路径。

互斥范围首版为当前工作台。其他窗口使服务端基线前进时，原子保存拒绝旧基线，不换 base 自动重发，不自动合并。

上述“同步 → 按 pageId 获取最新元数据 → 固定本轮基线 → 生成上下文”由创作协调 Module 确定性执行，并在 Skill 主文列为执行前置条件。它不是让模型自行决定是否调用的可选步骤。当前实现仅使用本地已确认引用，尚不满足每轮获取最新元数据的要求；此处是明确的平台改造项。

### 必要摘要与引用的定义（本轮细化提案）

摘要是程序从本次页面元数据中按明确字段投影出的结构化上下文，不是另一轮模型自由概括。优先复用现有内容工具摘要与契约；缺失部分在同一中立作者中定义，Adapter 不再手写一套。

| 内容 | 首次提供 | 按目标补充 |
|---|---|---|
| 页面身份与基线 | pageId、精确修订引用、本轮关联、绑定该修订的工具引用 | 不接受历史消息覆盖或模型自行更新 |
| 页面结构 | 布局类型、区块及组件的稳定 ID、类型、标题、所属位置 | 大页面允许分段读取，但必须声明未提供范围，不能把截断当成不存在 |
| 选中对象 | 精确 locator，以及由最新基线解析出的类型、标题和受控可编辑配置 | 表格列宽任务提供列 ID、标签与当前宽度；图表转换任务提供相关字段与绑定 |
| 关联配置 | 当前目标所需的数据源、字段、筛选器和参数引用及已定义的含义 | 需要跨组件修改时补充受影响对象与依赖，保留未涉及配置 |
| 完整性 | 已提供哪些内容、哪些未提供、是否有可用的补充读取能力 | 缺配置不能猜测；缺真实数据不能推导业务归因 |

“引用”指程序可以解析并验证的精确修订/内容 token 和对象定位信息，不是一个让模型自行追索的模糊文件名。完整页面由工具通过引用读取；原始查询、数据行和鉴权信息继续留在对应程序通道，不能为了摘要方便直接放入模型上下文。

一轮内的补充上下文读取必须绑定同一精确基线，不能一半使用旧修订、一半使用新修订。下一条用户指令则重新执行最新获取。若首批尚无按目标补充读取能力，应由程序一次提供该任务所需配置，并明确能力边界；不得在 Skill 中写入实际不可调用的读取指令。以上字段为语义约定，尚不是已实现的新 SDK 或工具 Schema。

### 意图与工具范围

一个 Skill 不等于每个请求携带所有工具。目标执行配置区分：解释（无页面写入）、已有页修改（编辑能力）、新建（数据发现/构建及静态内容能力）。解释实际数据原因需要对应真实证据能力，本轮不借此新增分析服务。

解释分支收窄为创作过程的配置问答：说明组件展示什么、绑定了哪些字段、使用了哪些筛选配置，以及受控修改的限制。它不承担涨跌归因或独立业务分析。配置问答规则并入主文，不设独立 explain.md，不为三种表达形式建立三套执行流程。

本轮意图由用户请求与可信工作区状态共同确定；无歧义可直接路由，需模型理解时由同一 Skill 做最小意图判定，Adapter 再提供相应工具配置。明确另建须先由程序分配新页面身份。不要新增第二个分类 Skill或让模型伪造模式、页面身份来取得操作能力。

程序可验证身份、基线、目标、操作白名单及产物关联，但不宣称仅凭字段校验就能证明模型完全理解用户语义。歧义处理与语义准确性仍需行为评测。

盘古是否支持阶段性工具装载、结构化上下文与模式交接，必须核对实际接口。缺少能力时先交付单一 Skill 与可复现诊断评测，将部署优化标为未接通；不在本仓模拟一套 Relay 并声称生产可用。

## 6. 选中组件询问

### 程序处理

- 输入区展示本轮拟引用的组件名称，可清除选择。切页清空旧选择。
- 发送时按当前精确基线解析稳定组件 ID，确认存在、类型及所属位置，生成本轮目标摘要。不要只传标题或长期持有数组下标。
- 选择与本轮基线、身份和操作关联。运行中后续选择变化不改变本轮目标；返回产物也不能按新的全局 selection 应用。
- 缺目标、已删除、无法精确定位则明确失败或澄清，不回退到同名组件。显式文字目标优先于视觉选择；仍有冲突或歧义时确认。
- 当前已实现的 UI 是顶层单组件选择。首批明确支持该范围；容器子组件、多选必须有真实 locator、摘要和工具支持后再开放，不能从模型推断路径。

### Skill 处理

| 场景 | 行为 |
|---|---|
| 选中后“这个图是什么意思” | 用目标类型、标题、已提供字段/口径摘要解释；无修改 |
| 选中后“为什么下降” | 有真实数据与足够分析证据才给分析结论；只有配置时说明缺什么，不编造因果 |
| 选中后“改成柱状图” | 检查该组件和数据形状是否支持受控转换，使用精确目标执行 |
| 选中 A，但明确说修改 B | 解析 B；唯一且意图明确则使用 B，选择不强行限制范围 |
| 未选中且“改一下这个图” | 若本轮可信上下文不能唯一确定目标则澄清 |
| 选中后明确另建页面 | 走新建分支，默认不复制选中组件或原页，除非用户明确要求 |

### 盘古接入

通过正式支持的程序上下文通道传递本轮引用与摘要，用户原话单独保留。不可仅拼一句“当前选中某图”代替身份/版本绑定，也不可猜测 SDK 的 referrer/skillInfo 等字段承载它。现有 adapter 主要完成对话装载，选中上下文传递须单独实现和验收。

## 7. Skill 作者结构与体积

建议唯一新入口名为 `metriccanvas-platform-authoring`，名字在实施时与已部署引用核对。旧 create/edit 入口在切换完成后退出运行注册；如果存在已部署兼容需求，仅保留由同一作者生成的兼容入口并设定退出条件，不维护第二份正文，也不把三个入口同时交给模型选择。

```text
skill/metriccanvas-platform-authoring/
  SKILL.md
  references/
    tasks/create.md
    tasks/edit.md
    layouts/report.md
    layouts/dashboard.md
    errors.md
    examples/                 # 少量受控工具请求，不放完整错误页面
```

主文集中写：触发范围、当前上下文优先、任务分支、目标解析、必要停止条件、部分结果和结果报告。任务参考仅给策略与最小请求，参数字段以实际工具 Schema 为准。共同规则只在主文出现，子参考不复制；布局规则各自一个作者；由标准导出器装配自包含目录。

高频执行规则：普通编辑不发现数据；已提供参考直接使用；只有环境确有读取能力时才指示查阅指定主题；业务数据发现不是文档搜索；不可恢复配置错误在条件未变时不重复；参数错误允许根据具体反馈修正；无证据不补业务事实；使用用户语言；简洁说明完成内容、阻塞与真实保存状态。

完整 Page Schema、1 万行机器索引、169 份完整错误夹具以及全部页面样例退出 Platform Skill 分发，继续在产品/Bundle 契约与测试层保留。标准导出器仍维护锁步版本，参考例子通过真实请求 Schema/工具验证，不另建手写能力矩阵。

分发目标：新 Platform Skill 合计不超过 10,000 行，相对原两套约 181,606 行减少约 94.5%；同时报告文件数、UTF-8 字节数与实际输入 token。不通过压缩排版凑指标，不把磁盘裁剪当成已证明的推理成本降低。

### 参考加载约定

本地评测与目标 Adapter 使用同一版本的主文/参考源，并显式列出已提供的参考。常用必要内容直接注入，确需补充时按任务定向提供，不注入完整协议目录。无文件读取能力的部署不得保留不可执行的相对路径指令。无需为首批引入远程搜索或向量库。

## 8. 已发现的能力缺口

- 现有 edit_page 能改标题、布局、追加文字，并复用本页数据源构造部分受限组件；不能通用追加独立柱状图/折线图/普通表格，更没有新查询生成后并入旧页的公开受控通路。
- create_content_page 的 source_token 不是合并旧页入口：它创建新骨架，不保留原页组件。不得把它当作添加图表到既有页的方法。
- compose_page 的当前形态由工具确定性装配；模型的“完整方案”只能映射到现有受控规格与能力。精确组件/排序方案若超出已有表达面，应扩展受控 Interface，而非在 Skill 中暗示已支持或让模型输出原始组件 JSON。
- 当前 dependsOn 与逐项部分成功，不自动等于依赖任务整体回滚。已确认的“依赖任务不能留下半成品”需要原子分组/应用前验证能力；未具备时只执行独立可用部分，有整体一致性要求的组先阻塞。

上述属于内容工具能力任务，单列后续实施，不靠 Skill 补丁伪装成已实现。

## 9. 分阶段实施与所有权

### A：Skill 快速优化，可独立交付

## 10. 验证与验收

四层证据分别记录：静态分发自洽、确定性工具行为、本地真实模型行为、真实盘古/Java 联调。任何一层通过都不替代另一层。

1. 保留原14例原始结果。先复测3个误调用例、3个关键正例（精确修改/缺基线/多轮保持）和3个未用于改写提示词的新同类例；实际模型/参数/作者SHA/工具Schema版本固定并记录。
2. 单独增加统一入口与选择场景：解释零写入、明确新建、选中目标、目标失效、同名歧义、切页、无数据证据的分析请求。旧两Skill路由断言改成统一Skill中的意图/目标断言，但真实路由仍需真实集成测试，不能手动指定预期模式冒充通过。
3. 第一轮保持全部工具可见，只改Skill/注入资料；第二轮单独启用执行模式工具限制，分别报告两类收益。新旧入口与参考裁剪不能只靠提示词关键词检查验收。
4. 分项统计：产物正确、未涉及内容保持、工具范围、业务依据、用户语言、无效重试、调用次数、输入/输出/缓存token及延迟。不要仅报一个总成功率；单次样本不足以保证稳定率。
5. 首批硬条件：分发与请求样例检查通过；不可出现错误覆盖、身份/目标串用或明确虚报保存；三个误调数据发现案例须在修正后的本地行为评测中无同类误用，关键正例不退化。角色限制不能代替全工具诊断结果。能力/环境缺失单独标记，不能算通过。
6. 数据服务缺失仍标 blocked，不用静态假数据提高创建成绩。真实模型复测按明确有界批次及预算执行，不无限续跑；性能改善以实测为准，不能由行数或Schema字符数等比例推断。
7. 平台增加“人工修改后再次发送、澄清期间人工修改后回复、读取失败、其他窗口修改、选中对象在最新修订中删除”场景；验证每条指令先获取最新页面元数据、摘要与引用同修订、失败不回退，以及写入时仍校验基线。模型摘要测试验证必要字段、未提供范围及数据边界，不只检查提示词包含“最新”。

## 11. 与既有 ADR 的关系及取舍

延续 ADR-0060 的 Relay/Skill 与 Python 分工、ADR-0061 的自包含与单向生成、ADR-0064 的完整产物程序通道、ADR-0077 的工作台与旧页保持、ADR-0078 的保存/发布分离。后续受控编辑已扩展早期仅 Page Build Spec/两个工具的表达范围；不将旧 ADR 的历史工具数量作为恢复限制。

本方案替代此前创建/修改双入口的分发选择，并调整将整套产品参考复制进每个 Platform Skill 的测试假设。自包含交付、产品契约完整覆盖和普通问数入口继续保留。

重要取舍：单一Skill减少流程重复及跨Skill切换，代价是必须清楚表达意图/目标；程序负责基线与互斥以集中状态复杂度，代价是SDK上下文接线必须真实交付；精简参考降低模型查阅负担，代价是必须维护任务指南与合法请求样例，而不是仅复制全量协议。这里不再维持“先保留两个”作为另一个当前方案。

待正式进入实施时，将跨Module的本轮上下文归属与互斥取舍写入编号ADR并更新索引；不把接口尚未确认的盘古协议或未实现能力写成 accepted 事实。没有新领域概念需要强行扩充词汇表，“云宝/盘古”的产品别名记录于集成资料即可。

## 12. 内部 define-report 调查带来的架构修订提案

依据：用户提供的《define-report Skill 架构调查报告》，2026-09-15，内部 HEAD aef4400d。这里只能核读报告，未直接验证内部源码、Java 或前端；以下区分报告事实与架构推论。此节为待收敛提案，不表示已完成迁移。

### 12.1 先修正证据解释

- 报告比较的是公司 Agent 执行环境的发布分支，不是 MetricCanvas 的来源提交。它能证明公司发布分支未含该功能，不能证明这些实现全为公司原创或与 MetricCanvas 无共同基线。后续分别记录宿主发布基线、MetricCanvas 来源基线、内部改造版本；MetricCanvas 来源未知时不做逐行来源断言。
- “代码存在”只能支撑静态实现证据。报告未提供当前自动化测试或端到端执行证据，不能沿用“已实现有验证”作为运行验收结论。被删除测试可从 Git 历史恢复评估，不能直接断言完全不可复用。
- 乐观锁不等于人工/AI 互斥；生成幂等键不等于持久化端执行了幂等；错误码映射与 Skill 错误后行动也不必然是重复实现。
- recall-report 的列出/打开/执行已发布报告属于消费能力，不等于创作配置问答，不因采用统一创作 Skill 就将它强行合并。

### 12.2 主要结论

共同范式可以保留：模型输出页面构建规格，程序派生查询、选型、布局并校验。主要冲突在“修改”的语义：内部报告 D14/D21/D27 表明，多轮沿 draftSpec 重新装配整页，尚不从最新页面执行受控局部修改。即使不保留旧 JSON，旧 Spec 仍会造成过期状态覆盖；只增加 get 调用、随后仍从旧 Spec 重建也不能解决。

创建使用页面构建规格；修改使用最新页面精确引用和受控操作。Spec 可以保留需求来源，但不能成为既有页面的第二个状态真源。现有 assemble_page_document 可先保留为创建实现，不能直接充当局部编辑实现。无法保留现存组件或扩展字段时明确不支持，不静默丢弃。

### 12.3 共享核心、内部扩展与 Adapter

| 归属 | 负责什么 | 内部内容如何迁入 |
|---|---|---|
| 共享创作 Skill | 上下文前置条件、目标/意图解析、计划、工具策略、澄清及结果表达 | define-report 通用规则迁入同一作者；配置问答留主文；不写内部 REST 或输出占位符 |
| 共享内容 Module | 创建/修改受控契约、组件装配、能力校验、内容保持 | compose、选型、布局与校验按语义和行为对齐，不能仅凭同名直接覆盖 |
| 内部业务扩展 | 公司指标别名、组织映射、专有口径及必要业务规则 | 从 business_terms 和 API 文件抽出；输入输出受约束，返回可核对的指标/维度候选；通用日期解析与公司财年规则分开 |
| 内部数据 Adapter | 指标/维度发现、查询执行协议及外部错误归一化 | 保留内部数据接口实现，对外提供既有数据上下文与执行契约；不能成为所有页面请求的意图路由器 |
| 内部页面生命周期 Adapter | 页面身份映射、最新读取、草稿保存、发布消费与恢复 | 迁移 metadata_crud / Java 接口适配；保留草稿/发布、维度取值选择和 globalParams 兼容行为 |
| 内部对话 Adapter | 盘古上下文传递、工具暴露、产物缓存与预览输出协议 | 迁移工具可见性覆写与占位符处理；兼容旧占位符，但将其限制在集成协议中 |

这些职责对应已经观察到的变化点，不要求建设通用插件平台或每行新增一个包。内部可以提供实现与业务参考，不能用任意 prompt 覆盖共享基线、权限、发布确认和内容保持规则。内部工具仍按统一 Interface 暴露，真实不支持的能力明确报告，不靠适配层补出虚假成功。

### 12.4 必须显式定义的兼容契约

1. **页面身份与本轮基线**：报告中的 get 接受 page_metadata_id，而目标入口是 pageId；需程序维护经验证的映射，并明确读取创作草稿还是发布修订。不得混同两种 ID、由模型生成资产身份，或默认 get 返回的就是最新创作草稿。
2. **上下文与产物引用**：内部 modelSummary 只有 pageId/unitCount/hash/key，不足以定位选中对象。新增目标配置投影；完整 document、previewJson 通过程序产物通道传递。当前报告的 MCP Schema 要求后续调用提交完整对象，不能仅凭“会话不存 JSON”断言模型没有接触数据行。需验证工具结果过滤和程序转交的实际实现。
3. **创建/修改能力**：兼容当前取数单元上限、组件集合和受控参数；由实际实现与契约生成能力信息及工具配置，不再手写平行能力表。暂不支持新操作时阻塞，不能重建整页冒充修改。
4. **页面格式兼容**：schemaVersion 同为 5.0 不证明字段语义一致。比较实际 Schema、queryField、组件 props、globalParams 和无数据实例 document/预览的行为。内部扩展必须同时覆盖装配、校验、渲染与编辑保持；只追加组件目录是不完整扩展。
5. **生命周期语义**：原子基线校验、幂等受理与未知写入查询需实际服务证据。冲突后不能把旧产物换成最新 revision 重交。维度取值裁剪和公共维度提取必须有明确执行时机、最终候选及用户选择关联，不得绕过人工确认发布。
6. **分发版本**：记录 Skill/工具契约/页面契约/内部扩展/Adapter 的兼容版本与验收证据；沿用现有 Bundle 导出与锁定机制。内部手写作者与生成物分开，禁止修改生成后的共享 SKILL.md；过渡确有内部输出指令时从 Adapter 所属参考生成，设退出条件。

“创建/修改/问答”属于任务意图；“趋势/对比/构成”属于分析意图；“指标名及组织别名”属于业务解析。三者不能为了去重都塞进 discover_data_context。普通标题修改仍不应调用数据发现。

### 12.5 内部功能迁移顺序

1. 固定三个基线及当前可运行分发，恢复可用历史测试，按报告 H1–H15 建立当前行为证据。澄清报告中“已发布页调整先存草稿”与“调整时 is_draft=false”的矛盾；后者不能直接作为兼容要求继承。
2. 先保留内部 define-report 注册名、CRUD 请求形状、预览占位符和已发布页面读取，通过 Adapter 接入共享契约。注册名可以保留，但不得同时暴露两个竞争的创作入口。先不批量改写存量页面。
3. 优先补每轮最新读取、页面 ID 映射、基线绑定和局部编辑。加入人工改标题/列宽/布局后 AI 修改另一处仍保持原改动的验收；读取失败、目标删除、跨窗口冲突都应阻止旧结果覆盖。
4. 将内部数据、业务词汇与组件能力接入明确扩展位置，再替换 Skill 为单一共享作者的内部构建。保留召回报告能力；校验引用传递确实隔离完整页面和业务数据行。
5. 分阶段切换，每次仅一个执行路径持有写入权。只读比较或离线评测可以并行，不对生产页面双写。回退须验证旧实现能消费新页面格式；不能消费时只回退到兼容版本或只读模式，不让旧链路重建覆盖新页。

正式迁移前仍需补齐：公司前端/Java 的最新草稿与精确修订语义、原子保存/幂等/发布证据、盘古模型输入与程序产物分流机制、MetricCanvas 原始导入基线。未知项限制对应功能声明，不阻塞 Skill 作者和 Adapter 分离等可独立工作。
