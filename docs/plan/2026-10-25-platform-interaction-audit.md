## 审计原则与确认范围

面向业务创作者，以完成页面调整、预知结果、放心试错为目标。默认界面隐藏内部 ID、协议 JSON 和存储实现；始终解释当前修改对象、保存范围、操作限制及恢复方式。复杂能力按任务展开，沿用 `@metriccanvas/ui` 的控件和对话框。

用户确认接纳原审计的 P1-2、3、4、5 和 P2-1、2、4；先处理其他已采纳项，P1-4、5 后续分别专项解决。没有确认的条目只保留问题，不在本批实施。

## 本批职责与实施顺序

1. 标题改为复用 `editPageTitle` 和工作副本保护/保存，不再从工作台直接调用 PageInfo 更新。管理页直接接口与并行工作保留。
2. 管理信息从画布上方移至现有 `Dialog`，更名区分页面管理与页面属性。
3. 条件规则的摘要、基础编辑与高级 JSON 分层；只操作现有 Condition 协议，不新增页面字段。
4. 目录选择定位与常驻切换入口；可用形态及不适用原因分层展示。
5. 定向回归、Platform 实际浏览器走查、既有 Playground 页面可观察验收、文档及 local-authoring 同步；按 AST 口径实测修改函数及全部新增辅助函数。

## 待专项：P1-4 多步撤销与重做

现有入口：`apps/platform/src/lib/workbench/authoring-sync.ts` 的 `enqueue/undo`，`authoring-coordinator.ts`，`PageAuthoringWorkbench.svelte`。

需单独确认：历史归属及容量；输入提交与拖动的合并粒度；撤销后新操作截断重做；AI 完整修改；显式保存、发布、服务端规范化、恢复及身份变化；失败和未知结果是否阻塞以及如何恢复。本批只记录，不实现或宣称关闭。

现有入口：`PageAuthoringWorkbench.svelte` 的 `previewOpen/previewRef` 与 `MetricCanvas/RuntimeView` 条件挂载；`packages/metric-canvas/src/AuthoringSection.svelte` 的点击截获。
