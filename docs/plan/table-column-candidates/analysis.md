# 表格列筛选候选值：需求与能力差距分析

日期：2026-10-21。

状态：业务范围及四项产品裁决已确认，见[ADR-0114](../../adr/0114-table-column-candidates-use-matching-results.md)。本文为源码与已有调查材料的分析，不代表引擎实施或真实 DQE 验收完成。实施与外部待核事项由[唯一主计划](../2026-10-21-table-column-candidates.md)维护；对外沟通使用[DQE 简要说明](dqe-handoff.md)。

## 1 已确认需求

某列候选值来自本表全部匹配行中该列的去重值。它受页面条件和其他列筛选影响，但排除当前列自身的表头筛选。

以“代表处”为例：页面时间为 2026 年 1—9 月，区域列选中国区，代表处列选北京代表处。表格请求保留三个条件；代表处候选请求保留时间和区域条件，排除“代表处表头选北京”这一条件。

必须区分三个集合：

| 集合 | 含义 | 本需求 |
|---|---|---|
| 当前页出现值 | 从当前 20 行提取选项 | 不满足，会遗漏其他页 |
| 维度取值域 | 整个维度定义或业务数据中的取值 | 可能包含本表没有的值 |
| 表格匹配结果中的出现值 | 本表全部匹配行对目标字段去重 | 已确认采用 |

规则：

1. 权限、固定业务条件、页面筛选、已提交表格搜索、其他列表头筛选均保留。
2. 只排除目标列自身的表头条件。同字段上的页面筛选、固定条件和查询结果绑定不能一并删除。
3. 候选集合不受当前表格展示页码、页大小及普通展示排序影响。候选值有自己的稳定排序和分页。
4. 上一条不扩大业务 TopN，也不扩大现有查询结果绑定声明的上游窗口；它们本来就是本表业务输入。
5. 候选值去重不要求逐项数量；显示“北京（126）”属于可选增量，尚未确认。
6. 当前请求样例中的“详情”是按声明维度和指标返回的表格结果，不承诺交易级原始明细。
7. 已有表格统一升级，无候选 scope 开关；页面维度筛选器保持原语义。失配已选值保留，稳定值保留原始类型，首批不提供 null“空白”选项。
8. 保留 NO_PERMISSION 带非空数据支持及既有消费规则；候选完整性另验，不以返回码代替完整性判断。

## 3 引擎 gap

| ID | 当前缺口 | 必需变化 |
|---|---|---|
| E1 | 候选端口只有维度和维度级联约束 | 共享执行核心接收源、目标字段、已提交视图、页面条件，形成候选读取计划；网关只接收可执行查询语义 |
| E2 | 缺少排除自身及条件来源语义 | 按目标列表头条件身份排除；同字段的独立条件合取，不能按字段名整体删除 |
| E3 | 状态按维度名共享 | 展示状态按表格、字段及条件版本隔离；底层完全相同请求仍可复用 |
| E4 | 候选刷新依赖不完整 | 页面条件、其他列、搜索、绑定输入改变时失效；普通翻页和展示排序不重取 |
| E5 | 无候选分页与完整性 | 返回完整性、后续页及可验证计数等能力，部分结果不得标为完整 |
| E6 | 完整本地行集直接去重 | 先应用其他条件与搜索，再从未分页的完整匹配行去重；不得从已被自身筛掉的行集倒推 |
| E7 | 组合源只追溯成员维度 | 按最终组合行域、投影和跨源条件枚举，保留有界关联上限 |
| E8 | UI 只接字符串数组，reload 只依赖取消 | 保留稳定值和显示名，支持候选搜索、续页、重试与请求代次；候选响应不写业务筛选状态 |

额外正确性问题：普通查询在 effectiveDqeItem 中顺序编码筛选，setDimensionFilter 依查询字段更新既有条目；页面条件与表头条件同字段时可能被后者覆盖。组合计划已有 predicate-target-conflict 检查，普通查询仍需补同字段多来源条件的合取语义。页面筛选绑定替换查询默认值的既有规则，应与“表头额外收窄”分开处理。

并发审计：当前加载器的 settle 只检查维度处于 loading，reload 会先取消旧请求并重新进入 loading。若旧适配器忽略取消后返回，旧结果仍可能结算新请求的状态。新候选读取需要校验请求标识或 generation；仅调用 abort 不够。

## 4 DQE gap 与核验问题

以下都是待核验能力，不等同于确认后端缺少实现。

| ID | 必须回答的问题 | 可接受结果 |
|---|---|---|
| D1 | 仅输出目标维度、指标为空时，如何锁定原表数据集及查询范围，时间和其他维度筛选是否生效？ | 证明同一查询范围；或提供显式、受控的原查询字段去重能力 |
| D2 | 原表含聚合、公式、度量条件时，如何保持原粒度后枚举？ | 候选等于原表完整匹配结果的字段投影去重，不改变聚合粒度 |
| D3 | 度量、其他条件、去重、计数和分页按什么顺序执行？ | 条件作用于完整业务结果，再去重，再计数及候选分页 |
| D4 | 最大返回上限是多少？total_count 是去重候选总数吗？ | 稳定分页和明确结束判据；不将截断集合声明完整 |
| D5 | 候选关键词如何编码？排序与翻页是否稳定？ | 对完整候选集合按约定匹配后分页，并提供确定性排序 |
| D6 | 候选是否经过与表格相同的当前身份、工作区和权限注入？ | 权限范围一致；无权记录中的取值不会进入候选 |
| D7 | 稳定值、显示名、数字、空字符串和 null 如何返回与回传？ | 有明确类型与筛选语义；需要“空白”选项时有合法表达 |

本仓调查还记录：dsl_list 按请求项位置返回；非分页 total_count 可能为 0；所谓不限条数可能被 MAX_LIMIT_VALUE 钳制，具体值未提供。不能用“没有显式 limit”证明候选完整，也不能默认将任意 total_count 当去重数量。

多项请求只减少网络往返，不证明后端共用一次扫描，也不证明表格和候选读取同一事务快照。组合表格在本地跨源关联，其最终候选语义由引擎负责，不要求 DQE 理解页面组合协议。

## 5 请求示例的适用范围

完整单次 HTTP、两项 DSL 及预期响应见[DQE 对接说明](dqe-handoff.md)。

第一项取区域、代表处和收入，保留代表处表头选择；第二项只输出代表处，保留时间和区域条件，不带代表处表头选择。第二项不是“把所有候选列一起放入 output_dims”：那会返回维度组合，尤其不能表达每个目标列分别排除自己的不同筛选条件。

该示例采用调查材料的 order_by_field/type 和紧凑期间格式。本仓交互排序目前编码为 order.by，属于适配器对接差异；不能直接据此修改页面参数格式或把两种排序形状混用。无度量筛选的维度样例仍须验证 D1、D4、D6；加入度量条件前另验 D2、D3。
