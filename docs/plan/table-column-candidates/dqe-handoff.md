# DQE 对接说明：完整原查询与前端列候选去重

2026-10-29：用户确认目前采用整体查询与前端去重，且 DQE 查询必须保留至少一个 output_metrics。本仓已按此注册平台及 Playground 共用网关；下面是参数组织约定，不代表真实服务已联调。原先仅输出目标维度、清空指标的待联调建议不再作为当前实现。

## 注册

```ts
createDqeGateway({
  columnCandidates: { mode: 'fullQuery', batchSize: 200, maxRows: 1000 }
});
```

`createInjectedDqeGateway` 已默认注册此方式，平台普通呈现、工作台和 Playground 共用。独立嵌入可显式使用相同配置。默认最多扫描1000条原始结果、200条一批，恰好1000条时5批；超过1000须显式提高 `maxRows`。平台门户 `readConfig()` 或独立入口 `__METRICCANVAS__` 使用可选正安全整数 `columnCandidatesMaxRows: 2000`，同样每批200条；懒加载与预加载共用上限，不写入页面JSON或DQE业务条件。现有 `encodeColumnCandidates` 优先，留给已支持原结果去重查询的部署；本实现不依赖它，不添加尚未确认的 DISTINCT 参数或新接口。

## DQE 参数如何组织

复制本表当前生效的完整查询，保留原始模型定位字段、全部 output_dims 和全部非空 output_metrics，保持原业务粒度。保留固定条件、页面筛选、权限身份、查询结果绑定、已提交表格搜索和其他列表头条件；只移除目标列自身的表头条件，同字段固定条件或页面条件仍保留。多个待筛选列分别读取其作用域，不将候选搜索词混入表格查询。

例如表格原来按区域、代表处、项目取收入，页面选了2026年1—9月和中国区，代表处表头选北京，收入列设置不低于100万元。打开代表处筛选时，保留收入条件，排除“北京”这项表头选择；请求形状如下（全部为合成业务名称与取值）：

```json
{
  "dsl_list": [{
    "output_dims": ["区域", "代表处", "项目"],
    "output_metrics": ["收入"],
    "filter": {
      "time": {"period": "month", "start": "2026-01", "end": "2026-09", "is_aggregate": true},
      "dims": [{"dim_name": "区域", "dim_value_list": ["中国区"]}],
      "metrics": [{"metric_name": "收入", "metric_value_list": [1000000], "operator": ">="}]
    },
    "order": {"order_by_field": "收入", "type": "desc", "offset": 0, "limit": 200}
  }]
}
```

发送到既有 `/rest/cdi/cdinl2databuilderservice/v1/dsl/execute`，仍使用既有 `X-Auth-Token`、`X-Operator-Id`、`X-Workspace-Id`；注入面现读实际端点与身份。时间和排序方向经过既有 DQE 编码器规范化，不新增一套编码规则。模型定位字段如原查询声明则原样保留，不猜模型。

第一批 offset=0、limit=200；第二批 offset=200、limit=200，以实际完整响应行数递增，默认最多5批覆盖1000条。首批 total_count 超过上限时（保留业务 TopN 截止），立即停止后续批次并返回 `DQE_CANDIDATE_LIMIT_EXCEEDED`，提示缩小筛选范围或显式提高上限，不把首批当成完整候选。表格的当前页码不影响这次读取。原始 order 只有 limit、没有 offset 时按业务 TopN 截止，不将它扩大；上游有限结果绑定也保持。

## 前端如何处理

候选不参与表格主数据加载门禁。表格可见且完成绘制后，空闲时逐列后台预加载；点击菜单复用同条件的在途请求或候选页，未就绪时仅菜单等待。主查询、显式菜单请求优先于后台预加载；主查询可抢占候选并释放执行位置，不等迟到回执。完整读取每批之间让出事件循环，隐藏与销毁时取消后台工作。该调度不改变DQE业务参数。

每批只提取目标页面字段的有效字符串/数字稳定值，逐批去重；null 不成为首批选项，数字保留数字类型。内存保留去重集合和当前批次，不保留完整原始行集。全部完成后在该集合上进行候选关键词搜索、稳定排序、分页，再计算候选 totalCount。原始 total_count 是匹配结果行数，候选 totalCount 是搜索后的去重数，二者不能互换。

原始 total_count 必须为非负安全整数，跨批一致；返回行数必须等于当前窗口应有行数。缺失/矛盾总数、截断、任何批次失败都不展示部分候选。取消会停止后续批次，迟到回执被丢弃。沿用既有非成功码带非空 data 的消费规则，消费资格与完整性分别判断。

候选扫描有独立的1000行默认上限，不套用导出10000行限制。显式提高后完整读取成本随匹配行数增长，候选每页50项不意味着后端只读取50行；未命中候选页缓存时，候选搜索和继续加载会重新完整读取。DQE 未提供快照令牌时不承诺跨批事务一致性；总数不变也不能证明数据未变化。

## 验证与入口

- `/pages/table-column-candidates-query`：620条合成原始记录、80个代表处，跨过200行批次边界；保持非空指标，支持自身选择后候选仍完整、其他列联动、候选搜索与加载更多。
- `?state=truncated`：普通表格可用，候选明确失败并可重试。
- `?state=blocked-candidates`：候选始终不返回，表格仍先显示20行，点击下一页显示第21行，并取消后台候选。合成请求事件用于验收触发顺序和取消，不当作真实HTTP证据。
- `?state=over-limit`：1001条原始记录，默认上限1000时不展示部分选项，菜单提示缩小筛选范围，表格仍可翻页。
- `?state=raised-limit`：同一1001条记录，注入配置显式 `columnCandidatesMaxRows: 1200` 后按200一批完整读取。
- 行为测试覆盖默认1000条正好5批、1001/10000条超限首批停止、显式提高后10001条读取、非法上限、业务 TopN、数值零、空结果、缺失/变化总数、后续失败、取消与迟到响应。

以上为本地合成 HTTP 信封、集成及浏览器证据；真实 DQE 的最大 limit、稳定分页与权限仍需在实际端点验证。既有候选语义见 ADR-0114，主查询和候选共用网关资源。
