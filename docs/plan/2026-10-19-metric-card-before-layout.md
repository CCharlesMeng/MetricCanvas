# 指标卡前置连接文字实施方案

状态：实施及本地验收完成，远端交付与CI待核对。2026-10-19。已按用户补充收敛隐藏规则，并补充四卡同行的空间预算。

用户已确认方向：在指标卡的布局声明中提供前置连接文字，由父级统一排布，实现 `[指标卡] ←8px→ 文字 ←8px→ [指标卡]`。本文提出具体范围、约束与异常行为，按用户批准范围实施；Skill 验证仅验收 local-authoring。

## 1 目标与基线

- 第一版提供 `metricCard.layout.before`，暂不提供 `after`，避免相邻双方重复声明连接文字。
- 文字按内容占宽，指标卡按比例分配剩余宽度；间距不再通过权重列近似。
- 页面文档仍为内容分区直接包含组件，不增加页面文档中的 group、row、递归容器或计算公式。
- 不声明 before 的页面保持原有布局、间距、DOM 路径和行为。
- 本地 main 尚落后于跟踪的 origin/main；已检查的 origin/main 为 `c47232887233a9340268e8442a118b2e4508d7c7`，当前协议 6.33。本批在实施前重新 fetch，以最新 main 建立独立工作区。若无其他协议增量先行，新能力拟登记为 6.34；不提前占用版本号。
- 工作区存在页面目录、协议文档、可见性计划及创作分发等并行修改。实施不从混合工作区批量复制，不在本批带入这些修改。

现有机制：`componentLayoutZ` 严格接受 span/connectPrevious/layer；`RuntimeSection` 直接渲染网格单元格；分区缺省为 12 列，columnTracks 是纯数字权重；每个组件单元格建立 mc-component-box 尺寸容器。当前文字示例通过七条权重轨调整空白，基础组件间距仍为 16px。

## 2 拟议页面契约

```json
{
  "id": "product-income",
  "type": "metricCard",
  "layout": {
    "span": 3,
    "before": {
      "text": "=",
      "gap": 8
    }
  },
  "data": { "main": "income" },
  "props": {
    "variant": "compactStack",
    "rows": [
      {
        "label": "产品收入",
        "valueField": { "data": "main", "field": "product" },
        "unit": "万元"
      }
    ]
  }
}
```

以上是未来契约示意，当前校验器尚不接受。四卡公式为 A 无 before、B before `=`、C before `+`、D before `+`，四张卡均 span 3；分区删除旧示例的 columnTracks 和独立连接 text 组件。

| 项目 | 第一版建议 |
|---|---|
| 声明位置 | 只扩展 metricCard 的 layout Schema，不直接扩大全部组件的共享 layout |
| 文字 | 必填非空文本取值，复用参数、筛选值和 parts 的既有规则；按纯文本渲染，不接受 HTML、脚本、动作 |
| 间距 | gap 可省略，缺省 8；受控闭集 4/8/12/16/24，单位 CSS px；不支持负数、字符串或任意 CSS |
| 间距定义 | 前一张卡外部布局盒右缘到文字内容盒左缘为 gap，文字内容盒右缘到当前卡外部布局盒左缘也为 gap；字形自身的字体侧边留白不属于 gap |
| 呈现 | 水平排布时垂直居中；字号、字重和颜色由统一主题控制，不开放自由样式 |
| 文字宽度 | 短文字使用固有宽度；长文字单行省略，完整文案保留 title 与可访问名称；使用运行时受控宽度上限，不能撑出页面 |
| 准入范围 | Dashboard、顶层相邻 metricCard，分区 container 为 plain 或 card，使用默认 12 列 |
| 暂不支持 | Report、columnTracks 分区、panel 分区、组合卡/Tab/详情视图内的子组件、包含 backdrop 的分区、与 connectPrevious 混用 |

准入限制仅作用于新 before 声明，不收紧既有页面的合法范围。超出范围给出指向 before 的结构或语义校验错误，不静默失效。

文字长度、字体和缺值验证需消费物化后的文本。缺失可选参数使 text 属性缺席时，该连接边不显示文字或额外留白，卡片继续显示；不得把缺值显示成公式中的半个连接词。筛选值与 parts 的现有求值规则不新增替代实现。

## 3 排布算法与宽度语义

### 3.1 从显式声明派生排布

在统一运行时内部增加一个纯函数，消费已经校验的内容分区及已解析的文字，产出普通单元格与相邻连接排布单元。它不改写页面文档，不读取指标数据，也不根据指标名称、variant 或组件组合猜测连接关系。

连续声明 before 的指标卡与其前一张卡构成一个内部连接排布单元。隐藏只采用最小规则：原文档中相邻两张卡都呈现时，才显示它们之间的连接文字；否则不显示。不查找替代前项，不自动重连，不增加隐藏状态机。文字为空时也不显示该连接。

### 3.2 保留外层栅格

外层仍是 12 列。内部连接排布单元占用成员 span 之和；和不得超过 12，超出时拒绝页面配置。排布单元作为整体参与既有自动流，因此可能整体移到下一行，不在普通横排中间拆散。

内部使用内容宽度文字轨与可收缩卡片轨，扣除所有文字宽度和每条边的两侧 gap 后，按各卡 span 比例分配卡片宽度。例如四卡 span 均为 3，整组占 12 列，四卡在扣除连接文字后仍等宽；6/3/3 则按 2/1/1 分配。

这是一条新能力的明确宽度语义：组内 span 表示剩余卡片空间的比例，不能再把单卡 span 3 理解为包含连接文字前的整组宽度四分之一。不声明 before 的组件继续使用原栅格算法。

四卡同行的预算公式为：`单卡宽度 = (组内容宽度 - 三处文字宽度之和 - 6 × gap) / 4`。以组内容宽度 1000px、三处文字各假设为 16px、gap 8px 为例，单卡宽度为 226px；普通四卡在三个 16px 间隔下为 238px。这个例子中每卡只额外缩小 12px。文字实际宽度随字体和内容确定，示例数字不作为固定像素配置。

正常桌面宽度优先维持四卡同排，文字不扩成第五至第七个栅格组件，不挤占新的 span 或撑大外层。整组换行只处理外层剩余列不足；它不能解决组自身过窄，后者必须走窄屏单列退化，不能声称仅靠移动到下一行就能恢复可读性。验收既检查整组占满 12 列，也检查页面较宽但组只占部分列的情况，确认组实际宽度不足时不会硬挤或产生横向溢出。

### 3.3 DOM 与尺寸隔离

- RuntimeSection 拥有额外的内部连接排布盒；卡片仍使用原 article.cell、组件 id 和 mc-component-box，不在 MetricCard 纯渲染实现里插入连接文字。
- 连接文字位于这些尺寸隔离盒之外，拥有真实文本节点和固有宽度；不能把文字放进现有 inline-size 隔离盒后直接期待内容尺寸参与列宽计算。
- 连接文字轨不参与剩余空间拉伸；间距通过连接文字两侧的受控布局空间实现，不依赖负 margin、覆盖原网格 gap 或页面专属 CSS。
- 连接文字不获得组件 id，不是可独立选择、删除、拖拽、查询或触发动作的实体。
- 不声明 before 的分区沿用原渲染路径。

### 3.4 窄屏

沿用统一运行时的页面级窄屏切换条件，不引入页面 JSON 断点。进入单列时，卡片全宽，连接文字居中放在两张卡之间，纵向两侧仍各为 gap。文字与后一张卡在分页或分片时尽量作为不可拆开的单元，避免文字单独留在前一页。卡片字体、内部行轨与缺值呈现仍由指标卡自身处理。

## 4 连接关系与编辑规则

| 场景 | 建议行为 |
|---|---|
| 原文档第一张卡有 before | 暂不显示该前缀，不产生占位；编辑器显示其存在，允许用户清除 |
| before 前面是其他组件类型 | 拒绝该布局配置，不能跨过图表或正文寻找前一张卡 |
| 查询加载、失败或空数据 | 卡片按现有规则显示加载或缺值；连接文字保留，数据状态不充当可见性条件 |
| 卡片因展示条件未呈现 | 相邻两卡都呈现才显示连接文字；否则隐藏文字，不做补位或重连 |
| 拖拽或删除导致相邻关系改变 | 清除对应失效边上的 before，未变更的相邻边保留；与本次编辑组成同一次撤销记录，不把旧等号自动连接到新的指标上 |
| 修改标题、数值格式、gap 或 span | 保留连接文字；span 改动重新检查整组跨度不超过 12 |
| 整组宽度不足 | 正常横排先整体参与外层换行；窄屏按既有条件切为单列，长文字不得撑出页面 |
| 文字动态缺失 | 该边不绘制，释放其文字与两侧 gap；不改数据、查询或卡片是否显示 |

用户要求隐藏逻辑保持简单。可见性能力仍属于另一实施批次；本批不新增隐藏配置、权限求值或条件系统。仅复用实际实施基线已有的呈现结果做一次相邻端点判断。若基线尚无组件隐藏能力，不为本批搭建可见性框架。

页面搭建工作台为指标卡提供“前置文字”和“间距”的布局编辑入口，清除 before 等价于取消该连接。搭建画布继续只发送编辑意图；工作台持有文档修改、完整校验和撤销。连接文字的点击归属后一张卡的选择操作，不触发其数据动作。

before 仅声明展示关系，不执行 A=B+C+D，不校验各数值能否相加，也不推断指标口径。

## 7 冲击与兼容边界

| 项目 | 结论与措施 |
|---|---|
| 旧页面 | 缺省行为不变；不自动修改普通 text 的宽度，不统一把 Dashboard 间距改成 8 |
| 新页交给旧消费者 | 旧运行时/旧校验器会拒绝版本或 before 字段；先升级消费者，再发布新页面，不提供静默降级 |
| 12 列语义 | 外层不变；新连接排布内部先扣文字与间距再按 span 分配卡片空间，必须在文档说明 |
| 拖拽与 DOM | 新增内部布局盒会影响直接子节点选择器、落点与覆盖层定位；按原实体 id 测试，禁止依赖新容器索引替代组件索引 |
| 响应式 | 不能让尺寸隔离吞掉文字固有宽度，不能让单列规则继续把内部成员误当外层栅格列；两者需真实浏览器验证 |
| 可见性并行工作 | 采用原文档相邻边，过滤后不重连；不复制条件求值或权限逻辑 |
| 目录与协议并行工作 | 最新 main 已有 6.32/6.33 和页面使用指南；实施时整体基于新基线生成契约，不覆盖旧工作区的目录/版本产物 |
| 回退 | 先把使用 before 的页面恢复为旧声明，再回退消费者；不能只回退渲染包而保留新协议页面 |

现行决策存在需要显式修订的地方：ADR-0038/0054 拒绝开放 gap 等样式轴；本方案仅为前置连接关系放开封闭间距档位，不增加通用 margin/padding/CSS。ADR-0038 的直接子单元格行对齐实现需要登记内部布局盒的所有权；ADR-0059 的直接组件尺寸盒保留。实施时新建或修订对应 ADR 并进入现行主题页，批准前不写成已生效结论。

## 8 审核建议

建议批准：layout.before、两侧 gap 缺省 8、仅短连接文字、外层 12 列、内部扣除连接空间后按 span 分配、窄屏纵向连接、断边清理不重连、默认行为不变。

建议第一版保留限制：Dashboard 顶层、plain/card、默认 12 列；不开放 after、通用文字自动列或自由 CSS。若后续需要 Report、权重列轨或组合卡内连接，另行证明相应布局语义，不通过静默忽略或复制布局代码扩展。

本批已实现协议6.34、连接排布、搭建编辑、示例迁移及local-authoring同步；本地验收见 [验收记录](../evidence/metric-card-before-layout/acceptance.md)。远端提交与CI以交付回执为准。
