# MetricCanvas Authoring 完整整改计划

日期：2026-09-28。状态：首轮公共整改与简单 DS 验证已执行，内部接入和原线上故障复验待进行。调查基线：`d84ebaa4`。

本计划覆盖 dataset 元数据复用、维度查询绑定、结果引用、页面组装、错误恢复、Skill 与内部接入。目标是在不改变用户业务范围的前提下，使带有轻微输入偏差或局部失败的创作也能继续完成，减少不必要中断、重复发现、重复查数和遇错重启。不能以减少错误码为代价静默生成错误页面。

实施结果见 [整改与验证报告](../evidence/2026-09-28-authoring-robustness.md)。下文保留完整规划；具体完成范围以报告为准，不将尚未执行的生产验收记为完成。

## 1. 目标、范围与完成定义

用户反馈：首次取得 dataset 后仍多次 discover；查询失败后反复换维度名称；compose 被 RESULT_SCOPE_MISMATCH 拒绝，模型解释为需要程序注入引用映射。用户要求前期减少非必要阻断，提高容错与鲁棒性。

用户澄清（2026-09-28）：核心诉求是“小错误不要影响系统正常运行”，不是要求所有错误都确定性恢复。之前方案偏重报错后的恢复机制，本版将容忍轻微偏差、缩小失败影响和不中断主流程置于首位。

整改原则：先判断问题是否真的影响本次操作，再选择兼容、默认、提示、局部降级或修正；只有必须停止的部分才停止。不要求所有输入先达到理想完整度，也不要求每个小错误都建立恢复状态机。程序处理容易规范化的偏差；模型可以依据返回的具体候选和原因修正局部输入，成功部分继续复用。对可能改变业务含义的修正进行相应核对，不以“无法自动确定”直接推导整轮失败。

完成须同时满足：

0. 可选字段遗漏、允许的等价写法、非关键展示参数错误、可选能力不可用及独立局部失败，不使整轮退出；容错后的有效输出仍符合最终页面契约。
1. 同一创作轮次、同一授权数据范围、完整元数据已取得时，连续发现、补详情、查数和组装共享快照；正常路径只完整读取一次元数据。
2. 发现明确告诉模型查询维度用什么值；可依据明确候选局部修正名称，不重启整轮；真实业务歧义再澄清，无依据换名不再触发新查询。
3. query_data 返回的合法 resultRef 可直接交给 compose_page；同轮多进程和重启可恢复；单纯组装、重试预览不重复执行 DQE。
4. 可重试的读失败能够实际重试成功，失败记录不永久占住查询身份；并发等待和中断恢复有明确状态。
5. 错误同时表达原因、影响范围、恢复责任和下一步；模型无需从错误码猜系统机制。
6. 真实身份隔离、查询授权、业务条件、最终结果字段契约、最终页面合法性和保存幂等不回退；不能因此要求模型原始输入一步到位满足最终存储格式。
7. 本地确定性、真实 DS、页面产物、必要浏览器与内部生产联调分别报告，不能互相替代。

排除：新增查询语言、通用数据集运行时、改 Relay 核心、全面重构全部校验器、跨用户共享结果、任意跨轮复用查询、重做页面协议或发布体系。本批不新增模型工具；优先改现有工具内部与增量返回字段。

## 2. 当前事实与证据边界

| 发现 | 证据 | 结论等级 |
|---|---|---|
| Java 元数据搜索每次读取整批，query/limit 只用于本地筛选 | [参考 Adapter](../../metriccanvas-authoring/examples/adapter_template/firstparty/dataset_metadata_http.py)，search/detail/current_for_query | 源码确认；相同发现连续两次产生两次 HTTP 请求已本地复现 |
| 完整元数据不等于模型已看到全部信息 | [SemanticCatalog](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/semantic_catalog.py) 的 matches/维度覆盖；[增强发现](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/discovery/service.py) 限量摘要 | 源码确认；不能要求所有场景只能 discover 一次 |
| 现有规范要求维度用 name，并已有别名规范化 | [数据分析工作流](../../metriccanvas-authoring/skill/metriccanvas-platform-authoring/workflows/data-analysis.md)、[validation_policy](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/validation_policy.py) | 源码确认；真实失败是否因 name/caption/code 不一致尚待轨迹 |
| compose 接受 sources 中的原始 resultRef 字符串 | [referenced](../../metriccanvas-authoring/tool/metriccanvas_authoring/pages/referenced.py)、[PlatformAuthoring](../../metriccanvas-authoring/tool/metriccanvas_authoring/pages/platform_authoring.py) | 现有查询→组装→保存测试通过，仅一次 DQE；“必须程序注入映射”的解释不成立 |
| 不存在引用与绑定不一致共用 RESULT_SCOPE_MISMATCH | [QueryResults.require](../../metriccanvas-authoring/tool/metriccanvas_authoring/data/results.py) | 源码确认；此次线上属于哪种尚未定位 |
| binding 整体参与状态 key、结果身份与比较 | [TurnState](../../metriccanvas-authoring/tool/metriccanvas_authoring/work/state.py)、[可信轮次](../../metriccanvas-authoring/tool/metriccanvas_authoring/work/authoring_turns.py) | 源码和测试确认；runId/requestId/contextRef 改变会拒绝，不代表这些字段应删除 |
| 错误出口丢失诊断信息 | [platform_mcp.call](../../metriccanvas-authoring/tool/metriccanvas_authoring/entrypoints/mcp/platform_mcp.py) 通常只返回 code 和空 path | 源码确认；易诱发模型猜测，但不是线上根因证明 |
| 已有查询记录直接返回，未区分恢复策略 | QueryResults.execute 对已有 pending/failed 的分支 | 待故障注入验证；不能把所有已有记录都视为可用缓存 |
| 累计调用/查询/时间预算目前默认不限 | TurnState.Limits | 源码确认；不把再次放宽预算当成本批核心措施 |
| 语义预检默认 relaxed | [ADR-0091](../adr/0091-query-validation-policy-and-public-semantic-projection.md) 与 validation_policy | 已有决策；需检查实际部署策略，不新加一套开关 |

规划期运行了三项现有测试：直接引用组装、绑定变化拒绝、保存重启及预览失败不重复保存。三项均通过。一次初始测试选择使用了错误的测试类名，修正选择后重跑通过；此为测试调用错误，不计产品失败。元数据重复读取的临时断言已失败，证明缺少复用；不是已修复。

尚缺生产证据：失败前后工具入参/回执、部署公共提交与内部 Adapter 提交、可信轮次变化、共享存储配置与结果是否存在、DQE 的脱敏原因分类。可先完成本地整改，但不能在缺这些证据时宣布该线上故障关闭。

## 3. 角色、任务、资产与系统全景

| 角色/系统 | 应承担任务 | 持有的信息与资产 | 不应交给模型的负担 |
|---|---|---|---|
| 用户 | 明确业务目标、选择真实歧义、决定范围变更 | 原始需求与确认 | 内部引用格式猜测、状态修复 |
| 模型与 Skill | 提取需求、选择有证据的指标/维度、组织章节、解释缺口 | 有界语义摘要、查询证据、页面结构计划 | 身份构造、缓存失效、映射修补、无依据重试 |
| 公共 Authoring | 快照复用、名称解析、查询派生、结果管理、组装、诊断恢复 | 数据上下文快照、结果记录、工作稿、恢复回执 | 对 Adapter 特例逐处兜底 |
| 内部 Relay Adapter | 提供稳定可信轮次、身份与授权，连接程序通道 | binding、确认事件、有效访问状态 | 要求模型伪造确认或刷新 runId |
| Java/DQE Adapter | 获取权威元数据、执行查询、归一化提供方错误 | 原始语义、源版本、查询响应 | 把私有错误原文与物理 SQL 暴露给模型 |
| 持久存储 Adapter | 跨进程共享状态、CAS、恢复与清理 | 快照、结果、执行尝试、工作稿 | 依赖单个 MCP 子进程内存 |
| Java 页面资产与预览通道 | 当前修订核对、条件保存、匹配产物交接 | 页面修订、保存回执、artifactRef | 通过重复保存解决预览错误 |

业务知识与模型解释仍是可选增强。修复基础元数据/引用链不依赖新增知识库或模型判断；可选服务不可用不能阻断已有明确语义上的主流程。

## 4. 目标流程与校验处置

目标流程：可信轮次就绪 → 获取/复用授权范围的快照 → 一次返回任务所需语义 → 规范化并授权精确查询 → 执行或复用成功结果 → 原引用直接组装 → 条件保存 → 精确预览交接。

正常操作无需新增确认。优先级为：接受可理解输入 → 使用已有合理默认值 → 非关键问题给提示并继续 → 隔离失败项 → 必要时局部修正 → 最后才中断依赖该问题的操作。只有业务范围改变或真实歧义需要用户选择；模型能根据具体反馈自行修正的小错误不转交用户。

在最终执行/保存前核对有效产物；入口用一个集中兼容步骤吸收约定内的轻微偏差。不是取消最终合法性，也不是每一层各自增加严格校验。

| 校验/问题 | 建议处置 | 自动化的限制 |
|---|---|---|
| 可选展示字段遗漏、约定等价的空值形式 | 使用现有默认值或按未提供处理，继续组装 | 不替业务时间、地域、单位或授权补默认值 |
| 无语义影响的展示参数偏差 | 按明确兼容规则归一化或回落默认显示 | 不吞掉未知查询参数、筛选或用户明确要求 |
| 单个图表的可选表现不支持 | 优先回落到使用同一数据的可用表现，或只跳过该图表 | 用户钉住的表现无法满足时说明；不伪称已按要求完成 |
| 明确且唯一的别名、已支持粒度编码 | 程序归一化，记录 from/to/path | 不做模糊拼写猜测，不改变业务域/筛选语义 |
| 单位、频率、非安全治理或组合能力声明缺失 | 保留 unknown/warning；可构造且已授权时交 DQE 验证 | 不能伪造单位、类型、组合支持或汇总可加性 |
| 已知明确不支持的组合 | 阻断依赖项并说明证据 | 不静默改为整体或删除筛选 |
| 完整快照已存在、详情同源且同版本 | 直接复用 | 不缓存身份授权结论，不跨数据范围复用 |
| 未知/错误引用 | 定位参数；程序核对本轮精确请求与记录 | 不搜索“最近结果”，不从其他轮次借用 |
| 调用级标识被错误地轮换 | 内部 Adapter 修正生命周期 | 不能通过删 scope 字段掩盖错误 |
| 短暂网络失败 | 程序按读操作规则有界重试 | 不重试取消、权限拒绝、业务拒绝或未知写入 |
| 并发查询仍运行 | 等待已认领执行并返回状态 | 不创建第二次并行 DQE |
| 独立取数/表现失败 | 成功部分继续；失败只沿真实依赖传播；可交付部分保存并说明缺失 | 核心缺失影响整体完成结论，不因此取消无关成功项；不隐藏业务范围变化 |
| 跨身份/工作区、撤权、错误结果字段、非法页面 | 保留硬阻断 | 仅阻断受影响操作；不泄露其他范围记录存在性 |
| 保存未知、修订冲突 | 核对原操作，保留工作稿 | 禁止自动换 operationId 重发或盲目重放 |

同一权威检查的派生层不重复做独立版本的判断；不同可信消费位置的必要核验不能仅为减少次数删除。

## 5. 七项整改工作

### W0 优先消除轻微错误造成的整轮中断

- 按真实主路径盘点入口 Schema、require/异常、查询批和组件批处理。每项记录：异常是否影响执行、合理默认、可隔离范围、现在是否中断整轮、准备如何处理。以中断影响排序，不以新增错误码数量交付。
- 首批建立小范围输入兼容清单：可选展示项遗漏、文档已有默认值、语义等价的可选空值/编码，以及可忽略的非执行性展示元信息。逐项明确兼容，不默认删除所有未知字段，避免把拼错的筛选当成无关字段。
- 校验作用于兼容后的有效输入。一个可选样式参数有问题，优先采用默认值；一个组件失败，继续其他组件；一个可选增强不可用，继续基础能力；一个查询项失败，继续不依赖它的查询与组装。
- 已取得的查询结果、合法组件和工作稿不因局部重试清空。反馈指向最小修改范围，允许模型依据具体证据修正该项，不要求重新发现、重新查询或重新创建整页。
- “核心项失败”决定能否声称完整完成，不自动等同于停止所有其他工作。可交付内容与缺口一并呈现；没有可用业务产物时才以整体失败结束。
- 将“每个小问题都必须先解释清楚才能继续”的 Skill 规则改为提示并继续；对可选问题合并反馈，避免逐项打断用户。
- 先使用默认值、兼容映射、已有批处理和局部异常隔离。只有真实故障证明有需要，才增加持久恢复状态、租约或新接口。W4 是补充，不是所有容错的前置。

### W1 元数据快照生命周期与复用

- 优先在公共 data/work 中集中实现，复用现有 StateStore；不把缓存算法复制到每个内部 HTTP Adapter，不引入第二套存储平台。
- 建议同一有效创作轮次固定首次完整快照。范围由可信身份、工作区、数据集范围、轮次与投影配置标识确定；记录 sourceVersion、获取时间、coverage 与配置版本。密钥不入 key/日志。
- discover、detail、query 和 result 消费共享同一快照；每次仍检查当前身份与精确查询授权。跨进程首次读取用 CAS/有限租约合并并发，返回值隔离复制。
- 增强发现的需求状态/用户确认仍按当前事件处理，只复用源元数据，不能缓存整个 discover 响应绕过新需求或确认。
- partial/失败不能标记为完整；保存已成功来源与缺口，按真实需要补缺失来源。新旧来源混合形成新快照版本，已授权查询和结果不能偷偷切换版本。
- 新轮次、授权数据范围改变、可信显式刷新或投影配置改变重新读取。长轮次/快照到期先恢复到明确状态，不在一次操作中静默换快照。清理不能删掉仍在使用的结果依赖。
- 发现返回匹配覆盖和元数据覆盖两个维度，明确是否截断、缺什么、是否需要补发现；必要时在同一快照内扩大候选/补读，无新增全量 HTTP。
- 只有业务执行因源变化失败且原因可验证时刷新并重新核对；不因任意 DQE 错误重新 discover。
- 新鲜度行为属于待裁决设计，需同步 ADR-0091 的版本语义；默认提案见第 9 节。

### W2 可执行维度契约与查询规范化

- 统一发现卡片、查询语义面和 DQE 派生使用的规范维度名；检查 name/caption/code/id/column_id 的真实源定义，建立字段不同名的夹具。
- 发现结果补充可直接消费的 queryBinding（建议语义，字段名在实现前固定）：groupBy/filter.dimension 使用哪个值、时间维度怎样配 granularity。name 保留为规范名，不创造另一套相互竞争的查询名称。
- label 只展示，source 标识只定位来源；结果字段 queryField 只描述 DQE 输出映射，不能当输入维度使用。补一份 name≠label≠id 且结果时间字段带粒度的完整示例。
- 指标声明中的 column_id/label 与模型维度目录仅做有唯一来源证据的连接。无法连接则标记 unknown，不把模型所有维度当该指标可组合集合。
- 审计已有别名规范化，补齐名称碰撞和多域同名行为；唯一合法别名自动归一化，歧义返回小规模候选和差异。
- DQE 失败保留脱敏原因分类与路径；名称正确时不建议改名。无新证据的同类错误停止该分支，失败条件不能被静默删掉。

### W3 结果引用与可信轮次接入

- 保留现有 sources: {dataSourceId: resultRef} 输入；优先让正确输入始终成功，不新增模型必须掌握的引用注册/注入协议。
- 区分未知引用、已过期、已撤权、不兼容策略、未完成执行与当前上下文不匹配。对模型统一提供不泄露他人记录的安全说明；内部诊断才区分记录存在性及变化字段。
- 为 compose 的引用问题标注 /sources/<id>；query_data(result_ref) 和 edit 引用消费走同一解析逻辑。返回操作状态、可恢复性、由程序还是模型/用户恢复。
- 核实共享存储和稳定 binding 是优先项：连续工具调用、独立子进程、进程重启必须访问同一状态；内部工厂不能每次造新的 run/request/context。
- 本批默认修复集成层使其遵守现有轮次协议。若真实业务必须跨 run 恢复，再单列可信续接授权与结果重新验证方案；不得直接去掉 binding 的字段比较。
- 不存在引用不自动重新查询。若可由同轮已授权精确请求与唯一有效记录恢复，可由程序返回原引用；未取得这些证据则明确缺口。首批不提供跨轮“最近结果”自动选择。
- 组装多来源时共享一次操作内的快照读取与解析结果，避免每个 resultRef 再读取完整元数据；每个来源的授权仍独立核对。
- 生命周期政策改变导致失效的记录不原地重绑定，不把旧引用解释成新结果。

### W4 查询恢复、并发与 partial

- 先故障注入确认 failed/pending 再请求的行为；成功记录、永久失败、短暂失败、活跃执行、失联执行分开处理。
- 成功结果按精确业务请求、快照、授权范围、策略复用；查询身份与 attempt 身份分离。失败恢复创建新 attempt，不能把失败记录永远作为最终缓存。
- 合法的只读网络超时/瞬断，建议默认自动重试 1 次并短退避。每次重试检查取消和授权；保留原请求与首次失败，不改变业务条件。
- 活跃 pending 等待原 owner；进程中断后只在执行租约失效且可安全恢复时接管。对于远端可能仍执行的只读查询记录潜在重复执行，不声称 exactly-once。
- 元数据读取、DQE、保存分别定义重试策略；保存未知不受“可重试读”规则影响。
- 将已有 partial 行为扩到已确认的独立、非核心失败项；身份/来源问题不能被 partial 吞掉。核心依赖来自用户需求与已确认计划，模型不能为通过率擅自把核心项降级。
- 不以放大总预算代替恢复；正常路径不新增调用轮数要求。

### W5 统一诊断与简化 Skill

- MCP 出口保留经白名单投影的结构化诊断，不能只留下 code 与空 path；不把整个 exception 或 retDesc 直出。
- 建议问题字段语义：code、stage、path、简短 message、recoverable、nextAction、recoveryOwner、可选候选与 correlationId；具体字段尽量复用现有 action/retrySafe，避免建立平行协议。
- 同一错误响应明确是否已经自动恢复，以及恢复后的结果；模型不再重复执行已完成的程序恢复。
- Skill 主路径收敛为“复用已发现能力→提交业务请求→使用返回引用组装→保存回执后预览”。工具描述和真实 Schema 承载关键参数说明，不只藏在多级参考文档。
- 明确三个禁止猜测的点：结果引用无需额外注入；维度查询值来自规范绑定；RESULT_SCOPE_MISMATCH 不能单凭错误码解释为格式错误。
- 正常问题不新增审核卡片。仅业务歧义、用户范围变化需要交互；内部恢复尽量透明。
- 诊断日志关联同轮快照、精确请求摘要、attempt、结果和保存操作，记录命中/失效原因及变化字段名；不记录 token、原始凭据或无关业务行。

### W6 交付、内部采用与回滚

- 当前架构以 [ARCHITECTURE](../../metriccanvas-authoring/ARCHITECTURE.md) 和 [ownership](../../metriccanvas-authoring/ownership.json) 为准；不存在继续维护旧包外 Relay 扩展的计划。
- 公共模块、契约、Skill、参考 Adapter、测试与迁移说明一起交付。tool/metriccanvas_authoring/adapters 是内部自有目录，公共更新不能覆盖；内部按清单吸收 examples/adapter_template 的修复。
- 若需要新的持久记录结构，使用明确命名空间/记录版本，旧结果不静默改写。旧版回滚只消费其能识别的记录；切换时排空在途写入，重新建立必要轮次。
- 尽量增量字段保持旧 resultRef 输入可用；实质修改授权/轮次/版本语义时同步协议、兼容说明和 ADR，不能只在实现中改比较逻辑。
- 生成契约与锁只走 pnpm authoring:contracts，不手改哈希。公共 Git 提交、内部 Adapter 提交、构建哈希共同确定部署版本，不能只看 Bundle 0.3.1。
- 部署先本地替身，再内部小范围验证；观察成功率、重复 HTTP/DQE、无进展重试与引用拒绝的归因。回滚触发：错范围复用、重复保存、合法结果串错、恢复死循环任一出现立即回退。

## 7. 验收矩阵与量化指标

| 用例 | 必须证明的行为 |
|---|---|
| A01 完整 dataset 连续发现/详情/多查询/多来源组装 | 同轮完整元数据 HTTP=1；第二次语义检索允许但不拉后端；用户新需求重新处理 |
| A02 元数据 partial、补缺失来源、摘要截断 | 覆盖状态准确；不把未显示当不存在；已取得数据可用范围明确；版本变化可追溯 |
| A03 同轮重启、多 MCP 进程、并发首次读取 | 共享快照和结果；正常并发仅一个读取 owner，无永久 pending |
| A04 新轮/范围变更/撤权/取消/配置变化 | 正确刷新或拒绝；不得凭旧缓存继续访问 |
| A05 name≠label≠id、别名唯一与冲突、时间粒度 | 查询使用规范名；输出 queryField 不混作输入；歧义不猜；无证据改名查询数=0 |
| A06 unknown 与明确 unsupported 组合 | 前者按 relaxed 且已授权时执行验证；后者保留具体原因；不改筛选 |
| A07 query→compose，直接字符串引用 | 成功保存；DQE=1；没有额外引用注入工具/步骤 |
| A08 不存在/跨范围/过期/策略变化引用 | 可定位原因和恢复责任；安全摘要不暴露其他范围记录；不盲目重查 |
| A09 稳定 binding 与错误轮换 | 稳定同轮调用成功；非法变化仍拒绝；适配诊断指出生命周期问题 |
| A10 DQE 首次超时后恢复、永久业务拒绝 | 前者有界恢复、保留首次失败；后者不重复执行；成功记录可复用 |
| A11 进程崩溃、执行中取消、并发相同请求 | 有界等待/接管，取消有效；不把 pending 当成功；不无限重试 |
| A12 非核心失败与核心缺失 | 非核心可见 partial；核心不足明确未完成；成功项不重复取数 |
| A13 保存未知/修订变化/预览失败 | 核对原操作；不新增保存、不盲目覆盖；预览恢复不重新组装取数 |
| A14 纯文字/样式调整 | 不发现、不查数；既有页面无关内容不变 |
| A15 宽松/严格和旧输入兼容 | 保持策略证据区分；合法旧 sources 输入有效；错误模式不被伪装 |
| A16 可选展示字段遗漏、约定空值/等价写法 | 归一化或使用现有默认后完成，不要求用户介入，不影响业务条件 |
| A17 单个非关键展示参数错误、组件表现不可用 | 默认/回落/局部跳过；其他组件保存成功；不重新查数 |
| A18 可选知识/解释/详情能力不可用 | 已有明确语义的基础流程继续，缺失能力只作说明 |
| A19 一批多项中一项失败，随后局部修正 | 其他项继续；修正后复用已有结果；不从头执行全批 |
| A20 核心项失败但其他独立项成功 | 保留并呈现可用部分，明确整体未完成；不撤销无关成功项 |

确定性指标：A01 的 HTTP=1 以“完整源、同轮同范围、未刷新”为前提；A07 的 DQE=1；A13 的成功保存次数不因预览重试增长；禁止范围替换=0；跨范围泄漏=0；无新证据改名重试=0；已授权唯一别名无需用户介入。

首要容错指标：在 A16–A19 明确兼容范围内注入小错误，整轮非必要中断数=0、为修正展示问题重复查数=0、用户被迫处理内部小错误次数=0。A20 必须保留成功项。回退、缺失与最终业务正确性同时验收，不能仅用无报错判定通过。

真实模型效果：固定相同案例、模型与配置比较整改前后。分别统计轻微偏差下任务完成率、非必要中断率、局部失败扩大为整轮失败的比例、首次完成率、程序或模型局部修正后完成率、discover 次数、元数据 HTTP、DQE、无进展重试、用户干预次数、耗时和 token。保留首次失败与全部重试；若为观察性少量运行，不宣称稳定统计提升。至少覆盖正常创建、维度不同名、元数据缺失、引用恢复、暂时执行失败、保存/预览恢复六类必需轨迹。

验证顺序遵循 [Skill 对接 DS 模型验收](../agents/skill-ds-model-acceptance.md)：无模型预检 → focused 确定性/HTTP 夹具 → 真实 DS → 页面产物 → 涉及保存与重开取数的最小浏览器验收 → 分发自洽 → 公司真实联调。浏览器不用于证明缓存和作用域内部逻辑，不扩大到无关视觉回归。

metriccanvas-authoring/tool/.venv/bin/python metriccanvas-authoring/scripts/check_bundle.py

测试、正式组合根、HTTP Adapter 与模型 runner 复用同一用例；不写只验证新增字段存在的镜像测试。生产联调重点是实际的稳定轮次、共享状态、元数据权限、DQE、保存和预览，不用本地 mock 冒充通过。

## 8. 风险、迁移与剩余不确定性

- 快照固定会延迟感知源元数据修改；必须明确新鲜度契约、可信刷新与授权撤销检查。不能同时承诺“全程只读一次”与“每次实时验证源版本”。
- dataset 接口是否能证明完整授权范围需由实际 Adapter 核实；无覆盖保证不能把首读当全量。
- 参考实现与内部版本可能不同；公共同步保护内部目录，因此更新公共包本身不证明部署采用了 Adapter 修复。
- 更宽松前检仍需足够源信息确定查询和结果字段。缺类型/授权等无法可靠执行的情况不是提示文案能修复的。
- 使用相同 resultRef 重试失败的语义需要避免已有消费者看到不同成功结果；只允许未曾成功的请求进入新 attempt，成功结果不可变。
- 当前实际用户失败没有原始调用记录；引用丢失、轮次变化、部署不一致只是待验证分支，不预先选一个作为根因。

## 9. 实施前需要裁决的行为变化

以下是建议，不是已获批准的架构事实。先完成计划评审，再按 [验收约定](../agents/skill-ds-model-acceptance.md) 对涉及身份、轮次和职责的变化进行 grill；普通诊断和回归实现无需另设审批。

| 决策 | 推荐 | 替代与代价 |
|---|---|---|
| D1 元数据新鲜度 | 同一有效创作轮次固定完整快照，新轮次/可信刷新再读取；当前访问授权仍核对 | 每次查源维持最高新鲜度，但不能消除重复 HTTP；TTL 自动换源易造成同轮混版 |
| D2 结果作用域 | 首批保持现有轮次隔离，修稳定 binding 和共享存储；不自动跨 run/轮次借结果 | 跨 run 续接需要新的可信授权、生命周期和迁移设计，另立子项 |
| D3 降级范围 | 用户已明确要容忍小错误、减少中断；按此制定兼容清单和局部降级，核心缺失标记未完成但保留独立成功项 | 不再重复询问是否需要容错；具体涉及业务含义的回退才需另行裁决 |
| D4 自动恢复限度 | 自动恢复是补充；允许模型据具体反馈局部修正；只读瞬断建议自动重试 1 次；保存未知只核对 | 不要求全部错误确定性恢复；无依据无限重试仍不能解决问题 |
