# 表格列条件显隐实施计划与兼容性审查

日期：2026-10-26。状态：产品规则已确认；本仓实现与本地验收完成；已授权提交推送 main，真实接入另验。实施证据见[本地验收记录](../evidence/table-column-visibility/result.md)。

本批目标：顶部页面筛选器可以通过统一展示条件控制同一张表的字段列和分组列，搜索、表头交互及导出与可见列保持一致。这里只扩展列的展示资格，不切换结果行粒度、统计口径或查询结构。

## 1. 基线与结论

- 初次规划时主工作区 HEAD：`ea40f6641e41e974dd3f1801c4613c5a1a7fcd45`；本地 `origin/main` 引用：`7834fbc5bc2534209e9358c2252bc9bd50e1eec8`。本轮未联网刷新远端，不能把该引用当作最新远端基线。
- 初次规划快照的 [version.ts](../../packages/page/src/version.ts) 的 `CURRENT_MINOR = 51`，即 `versionPolicy.current = 6.51`。工作区有大量并行修改和其他工作树；实施时重新核对目标检出、最新版本与派生物，不在本计划预占版本号或 ADR 编号。
- 现有 [列 Schema](../../packages/page/src/schema/components/table.ts) 的字段列和分组列均为严格对象，没有列级 `visibleWhen`。`selection`、`navigate`、`openDetail` 上的同名条件仅控制入口，不是整列显隐。
- 可以用新增可选字段和独立能力登记做增量演进，前提是新增搜索约束、状态清理和查询独占规则只对实际声明列条件的表格生效。
- 有一项明确的现行 ADR 冲突：空列组收起是 ADR-0112“子项全隐藏不反推父级”的表格结构性例外。需要在实施批次记录修订，不能默默扩大为通用容器自动收起。
- 实施重点在统一列投影、已有表格状态的原子调和、私有作用域和导出冻结；只在 Table 里过滤 `columns` 不能完成本能力。

以下区分“已确认产品规则”“建议的内部实现”与“实施前需完成的技术核验”。技术核验不代表重新开放已确认的产品选择。

## 2. 已确认产品规则

| 编号 | 范围 | 规则 |
|---|---|---|
| C01 | 声明 | 普通字段列和递归分组列均可就地声明 `visibleWhen`；不新增另一套列显隐语言、规则库或表达式 |
| C02 | 条件 | 读取所在作用域已声明的筛选状态、已有权限结果和有限业务事实；沿用 `all/any/not`、类型规则及复杂度限制；禁止列条件读取当前行 |
| C03 | 默认与异常 | 未声明列条件时沿用原行为；条件为 deny/pending/error 时列不展示，未知输入不能通过取反获得允许 |
| C04 | 父子关系 | 分组列隐藏覆盖后代；分组内全部叶子列不可见时不生成空分组表头。此例外仅限列树 |
| C05 | 覆盖 | 普通表格、现有表格变体、详情表格、行内子表格统一支持；序号、展开按钮等生成列不开放独立条件，跟随有效列结构处理 |
| C06 | 排序与筛选 | 隐藏列的用户排序、表头筛选及未提交草稿清除；其他列的操作保留；重新显示不恢复被清除状态。查询业务条件和默认排序保留 |
| C07 | 分页 | 单纯改变列显隐保留页码；清理操作改变行集、顺序或已提交搜索范围时回第一页。页面筛选本身的既有分页重置规则仍生效 |
| C08 | 搜索字段 | 隐藏列的主字段、次字段、徽标字段都退出工具栏搜索；同一字段仍属于其他可见列时继续可搜 |
| C09 | 搜索声明 | 启用列显隐的表格，搜索字段必须对应本表某列的主/次/徽标字段，否则校验报错；不启用列显隐的旧表格保持原规则 |
| C10 | 多字段搜索 | 有效字段始终为声明搜索字段与当前可见字段的交集；保留有效关键词，字段隐藏或重新可见导致范围变化时，重新计算并回第一页。不恢复已清空的关键词或失效选项 |
| C11 | 搜索选项 | 隐藏字段的选项移除；当前选项失效时清空关键词和相关草稿，选择首个可用项，不自动提交一次新搜索 |
| C12 | 无搜索字段 | 清除已提交搜索并隐藏搜索框；重新显示不恢复已清除的关键词、选项状态 |
| C13 | 无业务列 | 保留表格标题，显示“当前条件下无可见列”，暂停表格操作和该表导出；不补第一列、不显示仅含生成列的表体、不伪装为无数据 |
| C14 | 导出 | Excel、PDF、图片只含当前可见列，开始时冻结列条件及相关状态；后续操作不改变进行中的导出 |
| C15 | 查询所有权 | 有列显隐且有远程排序、表头筛选或搜索的表格，必须独占查询页面数据源。不满足时校验报错；内联及显式完整且无分页窗口的结果允许共享，各表独立处理 |
| C16 | 数据与执行 | 列隐藏不删除结果字段、不改变共享数据快照、不自动停止查询，也不构成数据权限控制。顶部筛选通过原有筛选绑定影响查询；清理表格操作产生的查询变化走已有执行机制 |
| C17 | 展开实例 | 父表全部业务列不可见时释放其全部展开实例，取消在途请求并忽略迟到结果；包括由条件等待或错误造成的零列。恢复列后默认收起，再次展开按原规则重新加载，不恢复旧搜索、排序或页码 |

“隐藏就当不存在”限定在该表的列呈现、工具栏搜索和用户列交互。业务查询谓词、结果字段契约、行身份、具名算子、默认排序和查询结果绑定不因此被删除。页面级筛选器与表格工具栏搜索是不同状态，不能混同清理。

所有“无可见列”判断均以业务叶子列为准。整张表本身被父级展示条件隐藏时，继续沿用父级资格及已有生命周期，不额外露出该提示。

## 3. Schema 兼容性与版本策略

### 3.1 增量形状

拟在 `TableColumn`、`TableColumnGroup` 及相应 Zod 对象上新增同一个可选字段：`visibleWhen?: Condition`。不增加列级 `enabledWhen`，不把单元格入口条件解释为列条件，也不要求存量叶子列新增 id。

示意片段，不是可直接校验的完整页面：

```json
{
  "field": "contractAmount",
  "title": "合同金额",
  "visibleWhen": {
    "filter": "business-type",
    "part": "values",
    "op": "containsAny",
    "values": ["contract"]
  }
}
```

`business-type` 必须在页面筛选器中声明；维度单选仍读取 `part: "values"`，不臆造一个维度 `value` 部分。

能力登记为 `conditional-table-columns`（与示例页面 id 分离），在实际实施版本登记新的次版本，设置 `legacyReadable: false`。原 `conditional-presentation` 的 6.35 下限不能替代新能力下限。

### 3.2 兼容矩阵

| 输入/运行环境 | 要求 |
|---|---|
| 既有受支持页面，不声明列条件 | 列、搜索字段、默认选择、分页和导出行为保持；不强行迁移旧页版本 |
| 新版文档声明列条件 | 使用实施时分配的新能力下限；新增校验与运行语义按表格启用 |
| 旧声明版本带列条件 | 以精确 JSON Pointer 报能力下限错误，不能只按通用条件能力放行 |
| 5.x 只读兼容输入带列条件 | 新能力拒绝借旧版兼容路径进入 |
| 旧引擎消费新页 | 版本门禁明确拒绝；不能忽略新字段后把全部列显示出来 |
| 没有列条件、仅有列入口的 `selection.visibleWhen` 等 | 不触发本批新增搜索字段约束或独占要求 |
| 仅行内子表声明列条件 | 约束在该子表实例生效；不把父表当作启用条件列，也不漏掉子表能力下限 |

启用判定必须基于**本表声明列树**内是否存在列级条件，而不是版本号达到某值、当前是否真的有列被隐藏、或页面任意位置存在 `visibleWhen`。条件恒为真也属于显式启用。

### 3.3 必须避免的破坏性变更

1. 不把 C09 应用到所有旧搜索配置。当前合法搜索字段可以不出现在任何展示列中；全面加严将改变既有开放面的语义，与 [ADR-0051](../adr/0051-additive-minor-versions-for-page-schema.md) 冲突。
2. 不全面收紧所有共享远程查询。新增独占规则只约束启用列显隐、且具有相关远程表格操作的表格，原独占规则继续保留。
3. 不将源字段、查询输出或 `filterBindings` 改成可见字段子集。结果字段契约和行粒度不变，隐藏字段可能仍是行键、计算输入或默认排序字段。
4. 文档的 `columns` 和分组 `children` 仍要求非空；零可见列是渲染投影结果，不放宽页面文档 Schema 来容纳空声明。
5. 不改通用 `Condition` 语法来实现“列不允许 row”。在列条件的合法上下文校验中拒绝，不影响合法行交互。

能力探测从原始文档扫描全部合法列位置：正文、Tab、组合卡、详情以及 `rowExpansion.table.columns` 的递归分组。既有 `walkDocumentComponents` 不把子表模板当独立组件，通用 6.35 探测也没有覆盖所有子表列位置，须补专用列位置遍历。只遍历协议节点，不递归解释查询体、初始业务行或富文本。

## 4. 架构审查与模块职责

协议与字段身份归领域包，纯投影归统一运行时，已提交状态归 TableSession，草稿归原控制器；控件只消费结果。以这几个现有接缝集中职责，避免每条渲染和导出路径独立解释条件。

| 接缝/真源 | 当前事实 | 建议改动与约束 |
|---|---|---|
| [列协议](../../packages/page/src/schema/components/table.ts) | 字段列/分组列为严格对象；子表复用 `tableColumnNodeZ` | 类型与 Schema 一起扩展，不复制子表列协议，不在 widgets 定义第二份条件类型 |
| [条件位置与校验](../../packages/page/src/presentation-policy.ts) | 遍历列时仅登记入口条件；列组只向下递归 | 登记列节点但不给行上下文；统一校验来源、类型、深度；复用作用域验证及错误路径映射 |
| [展示投影](../../packages/engine/runtime/src/presentation.ts) | 统一纯求值，尚未投影列；表格工具栏有专门提前返回分支 | 同一纯列投影生成可见列树、有效字段集合和零列状态；工具栏与列投影必须组合执行，不能互相短路 |
| [TableSession](../../packages/engine/runtime/src/table/session.ts) | 已提交 sort/predicates/search/page 的唯一写入者；不接收列信息；`resetPresentation` 全清 | 新增内部原子调和入口，计算一次 next view、一次 commit；不拿全量重置替代选择性清理 |
| [表格控制器](../../packages/engine/runtime-ui/src/table/controller.ts) | 持有表头草稿、搜索草稿/选项及候选会话；本地按 table id，远程按 source id | 消费同一列投影，清理自己的草稿/候选状态；已提交状态仍交给原所有者，不复制 session |
| [编排器](../../packages/engine/runtime/src/orchestrator.ts) | 筛选变化、字段切换、远程表格状态在此影响生效查询 | 筛选与列状态调和先完成，再构造一次生效查询；同修订业务事实变化也要进入调和，不能只订阅筛选 |
| [详情](../../packages/engine/runtime-ui/src/DetailContent.svelte)、[详情输入](../../packages/engine/runtime/src/detail-view.ts) | 详情使用私有筛选副本和独立本地控制器 | 传递私有上下文，动态更新时执行相同调和；不能从主页面按组件 id 借用状态 |
| [行内子表实例](../../packages/engine/runtime/src/table/expansion.ts)、[模板作用域](../../packages/page/src/table/expansion.ts) | 子表按父行隔离执行；模板不是组件树普通节点 | 给每个实例传递实际筛选、事实和修订；复用列投影，不将父行变成允许的列条件 row 上下文 |
| [Table 布局](../../packages/engine/widgets/src/components/table/columns.ts)、[Table](../../packages/engine/widgets/src/components/table/Table.svelte) | 同一列树生成叶子与表头，已有空组不产表头保护；固定列按布局计算 | 接收投影结果并重算表头跨列、跨行、宽度和固定偏移；widgets 不负责读取全局筛选或写表格状态 |
| [Excel writer](../../packages/engine/runtime-ui/src/table/export/workbook.ts)、[导出准备](../../packages/engine/runtime-ui/src/table/export/prepare.ts) | writer 使用收到的组件列；准备函数内部的投影不会自动回传给外层 writer | 将冻结后的可见组件与已调和状态传到 writer；正文和详情两条 Excel 入口都覆盖 |
| [PDF/PNG](../../packages/engine/runtime-ui/src/ExportView.svelte) | 静态视图重新运行统一展示投影 | 使用冻结筛选与事实，不能读当前实时上下文；与 Excel 共用列规则 |
| [创作定位](../../packages/page/src/presentation-edit.ts)、[操作](../../packages/page/src/presentation-operation.ts) | 现有 `kind: column` 定位的是列内 action slot；没有列本体和列组定位 | 增量补充内部定位目标并复用现有条件编辑器；不能重解释已有 slot，不能在裁剪后的数组索引上回写原文档 |

查询独占校验按声明的操作能力和全部直接消费者计算，不按当前是否隐藏过滤；复用现有消费者统计，覆盖详情、嵌套组件和 relatedData。显式查询结果依赖仍沿现有依赖协议处理，不借本批修改其执行语义。

### 4.1 建议的统一计算流程

1. 从声明文档出发，先沿现有流程解析字段选择和文本取值，再以所在作用域的已应用筛选/事实计算列资格。始终保留声明文档，不把裁剪结果写回工作稿。
2. 纯投影返回可见列树、可见主字段集合、可搜索字段集合及无业务列标记。搜索字段身份按 `(数据槽, 字段)` 判定，只有 main 槽的文本字段能进入工具栏搜索。
3. 以已有会话和新有效集合计算 next view：删除失效用户排序、表头谓词；裁剪或清除搜索；根据实际行为差异决定是否回第一页。仅删除未提交草稿不触发数据查询。
4. TableSession 原子提交 next view，原控制器清理草稿、选项与候选；编排器使用同一代次的最终条件执行。不得先以旧列条件发查询，再逐个清理造成多次请求或短暂错数。
5. 渲染、点击资格、搜索提交、候选读取及导出入口都读取相同有效结果；隐藏列的迟到事件与候选回执不得重新写回已清除状态。

内部模块可拆为“列位置/字段身份”“列投影”“会话调和”三个稳定职责。不要新增一个同时拥有筛选、查询和导出状态的全局管理器；不要让纯 `compilePresentation.evaluate` 在 Svelte 派生求值中写 session 或发请求。

### 4.2 需要保留的现有行为

- 默认排序与用户排序分开。普通 query 的业务排序留在查询定义；`pagedJoin` 的 `ordering.default` 可能已经装进 `view.sort`，不能把其中所有规则都当用户行为清掉。必要时在运行时保留默认/用户来源信息，不顺带增加页面字段。
- 已有 `byFilter` 字段切换会清理整表展示状态。本批选择性清理不能覆盖其既有规则；组合发生时按原字段切换语义处理，仍只形成一次最终提交。当前 `byFilter` case 限制为 money，搜索仅文本，不能假设搜索已具备动态字段绑定。
- 查询结果绑定读取上游当前窗口。清理操作若导致排序/筛选/分页变化，下游刷新沿现有依赖图处理；不能以“只是展示变化”为由跳过真实改变的窗口依赖。
- `mergeBy`、rowKey、rowKindField 是数据/行结构信息；字段列隐藏不删除这些声明。合并布局只对仍存在的目标展示列输出，不生成孤立跨行单元格。
- 行内子表已有折叠释放、并发和输入隔离规则继续生效；不得以列隐藏替代数据权限处理。对全零列时的已展开实例，实施前核验既有销毁接缝，避免遗留不可操作的实例。
- 行内子表及其父表/页面的现有导出限制继续保持；本次覆盖列显隐不等于解除导出范围限制。

### 4.3 防止架构腐化的实施约束

2026-10-26 补充：用户担心行为复杂度给代码架构带来过重负担。本批以“业务规则集中、状态保持单一所有者、接入方只传递上下文”控制维护成本，不能仅把函数拆小后宣称架构已经改善。

#### 核心增量及所有权

运行时核心增量限定为两个纯计算职责和现有会话的一次提交能力；以下名称是候选内部职责，不要求新增公共导出、包或框架：

| 职责 | 输入与输出 | 所有权约束 |
|---|---|---|
| 列投影 | 声明列树、已解析字段绑定、现有条件上下文 → 有效列树、可见字段/搜索字段、零列状态 | 复用条件求值器；结果随输入推导，不增加一份可编辑的 visibleColumns/hiddenColumns 状态 |
| 表格视图调和 | 已有 TableQueryView、有效列/搜索范围、默认排序来源 → 下一份视图及需要清理的交互信息 | 同一份算法供本地、远程、详情和子表使用；纯计算不取数、不操作 DOM、不拥有请求生命周期 |
| 原子提交 | 将已计算的下一份视图交给原 TableSession | 已提交状态仍由原 session 写入；草稿、候选和展开实例由现有控制器执行对应清理；沿用原 generation/取消机制 |

声明位置遍历、能力下限、错误路径和创作定位属于协议接入，继续归 page；它们不变成另一套列显隐业务规则。若一个通用工具需要调用方重复传入大量策略或重新解释条件，应回到具体列树职责收敛。

#### 强制约束

1. **一处业务算法，多处上下文接入。** RuntimeSurface、DetailContent、行内子表和 ExportView 可以适配输入及执行原控制器操作，但不能分别实现“哪些列有效、搜索剩哪些字段、哪些谓词要删”。Excel writer 只接收冻结投影，不自行解释条件。
2. **可推导信息不成为第二份状态真源。** 列资格、可见字段、搜索选项范围由声明与作用域输入计算；只保存用户操作产生的会话状态和原有草稿。确需缓存时必须按全部输入修订失效，缓存不能反过来决定规则。
3. **状态变更沿一条提交路径。** 列变化一次计算最终视图，再提交；禁止通过依次调用排序、筛选、搜索 setter 制造中间态和重复请求。无行为差异时不提交、不推进请求代次；仅布局变化不触发查询。
4. **默认状态来源可解释。** 默认排序与用户排序若在现有表示中无法区分，在会话的原所有者处补齐内部来源信息；不在各渲染入口放独立布尔标记猜测，不因隐藏而删除业务默认排序。
5. **作用域差异通过输入表达。** 正文、详情、子表分别传递自己的筛选、事实、修订和原会话；共享计算不判断“当前是不是详情页面”来选择不同业务规则。
6. **新能力局部启用，旧规则封闭保留。** 列级条件结构是启用点。对未启用表格沿原执行路径，不借新能力增加多个可配置兼容开关，也不在每个调用点手写版本分支。
7. **沿既有模块扩展。** 不增加全局列管理器、通用规则引擎、事件总线、第二套查询/导出状态机；只有在本批真实调用方已经需要共享职责时才提取模块。不以消除所有存量债务作为交付前提。

#### 架构验收与返工信号

| 验收问题 | 通过条件 | 需要返工的迹象 |
|---|---|---|
| 调整“隐藏列如何影响搜索”要改哪里？ | 修改同一个调和职责及相应行为用例；接入面不改业务算法 | 正文、详情、子表各改一段过滤/清理逻辑 |
| 新增一种表格展示入口，要理解多少内部规则？ | 提供作用域、原会话及清理接缝，消费同一有效描述 | 要了解清理顺序、版本兼容、搜索字段交集等并自行调用多个 setter |
| 修改列声明或事实，是否产生双份状态？ | 下次输入直接推导；已有会话原子更新 | 多个 Map 保存列资格，靠观察器互相修正；出现循环刷新 |
| 本地和远程是否采用相同清理语义？ | 同一输入/视图经纯计算得到相同下一视图，差异只在既有执行端 | 分别维护两份分支或两套状态恢复逻辑 |
| 代码复杂度是否真的可维护？ | 本次职责集中、依赖方向不变；新增函数逐个达标，修改的存量超限按规则处理 | 只把大函数分成多个透传 helper，跨函数共享可变上下文增加，或只看工厂 selfCC |
| 删除共享职责会发生什么？ | 同一组业务判断会被迫重复散落到真实调用方，说明提取有效 | 删除模块只需把参数原样转发，说明新增层没有实际承担复杂度 |

行为测试从共享输入输出及实际集成入口验证：投影不修改声明/快照；调和幂等；不会留下隐藏字段的用户约束；无行为差异不重查；旧页行为保持；每个作用域和导出使用相同列结果。不要为每个透传 helper 编写镜像测试来掩盖职责分散。

#### 实施顺序

先打通一个普通表格的纵向闭环：列条件 → 已有搜索/表头状态调和 → 本地/远程执行 → 冻结 Excel。验证单一算法与单一写入者成立后，接入详情、行内子表和页面导出。这个顺序用于尽早验证架构承载力，最终范围仍完整覆盖 C01—C17。

若接入第二种作用域就需要复制业务算法，先调整共享职责，再继续接入；不通过继续增加特判完成表面功能。架构验收和功能验收并列为完成条件，复杂度分数不能单独替代这项判断。

### 4.4 文件与目录组织约束

2026-10-26 用户进一步确认：高内聚、低耦合、真源归一、可阅读和变化率一致，必须体现在实际文件与目录划分中；不能只在大文件内部划分代码块，也不能把拆出的不同功能、不同类型文件继续平铺到一个目录。

#### 划分原则

| 原则 | 文件/目录要求 | 反例 |
|---|---|---|
| 高内聚 | 同一业务能力的文件在所属层内聚合；一个文件承担一个可命名的完整职责，相关实现和内部类型尽量相邻 | 新增 `table-visibility-*`、`table-search-*` 等一批文件散在 src 根目录；把同一规则拆成许多无独立含义的 helper |
| 低耦合 | 沿已有 package/layer 依赖方向访问能力的小接口；内部实现不反向依赖入口 Svelte、DOM 或宿主；不借 index 大范围导出所有内部符号 | page 引 runtime-ui 类型；多个目录循环导入；调用者跨目录直接写会话内部 Map |
| 真源归一 | Schema 与对应递归类型同处协议真源；列位置/字段身份一份，列规则一份，已提交状态一个写入者；参考、Skill、契约从产品真源生成 | 同一字段规则在校验、正文、详情、子表、导出各写一份；另建同名接口手工同步 |
| 可阅读 | 名称直接说明职责；每个能力目录有简短入口说明，标明读哪里、状态谁拥有、如何验证；业务命名优先，避免无边界的 utils/helpers/common/types 汇集文件 | 只能凭 import 猜目录功能；多个含糊 manager/service；为了理解一次显隐必须追踪大量透传文件 |
| 变化率一致 | 按“为什么一起变化”组织：列语义与字段身份、会话状态整理、UI 交互、工作簿编码分别聚合；经常一起修改的实现与内部类型同处，变化原因不同的部分分开 | 改 Excel 样式要触碰筛选会话；改表头交互要编辑协议校验；所有类型因扩展名相同集中到顶层 types.ts |

不以“一函数一文件”或“所有类型一目录”作为拆分标准。业务能力是目录主线，层间依赖仍按现有包划分；不会为了把所有 table 文件物理放在一起而跨越领域、运行时和 UI 的职责。

#### 本批目标结构

下列是职责布局示意，路径在 P0 按实际源码和构建入口核验后确定；只创建有实际职责的目录，不提前生成空壳。迁移已有实现时保留现有对外导出符号与包兼容性，更新直接消费者；不长期留下两套实现或一串旧路径透传壳。

```text
packages/page/src/
  schema/components/table.ts           # 列协议、Zod、递归类型的现有真源
  table/
    README.md                           # 领域职责、入口与依赖方向
    columns.ts                          # 声明列树、绑定身份与受控遍历
    validation.ts                       # 表格语义约束，调用共享字段规则
    query-view.ts                       # 既有表格视图契约及转换
    search.ts                           # 既有搜索声明解释

packages/engine/runtime/src/table/
  README.md                             # 纯规则、会话与生命周期的入口
  column-presentation.ts                # 复用统一条件求值器的列投影
  reconcile-view.ts                     # 已提交表格状态的纯调和
  session.ts                            # 迁入既有 TableSession，唯一提交者
  expansion.ts                          # 本批涉及的既有展开实例生命周期

packages/engine/runtime-ui/src/table/
  README.md                             # 接入方式、草稿所有权与渲染职责
  controller.ts                         # 原控制器的交互接入及草稿管理
  render-binding.ts                     # 与交互接入共同变化的内部契约
  views/
    ScopedTableContent.svelte           # 正文/详情/子表的实际共用接入
    ExpandableTable.svelte              # 展开呈现与原生命周期接入
  export/
    prepare.ts                          # 既有导出数据准备与冻结输入接入
    workbook.ts                         # Excel 格式编码，不解释列条件

packages/engine/widgets/src/components/table/
  Table.svelte                          # 表格组装入口，逐步剥离本批相关大块职责
  columns.ts                            # 既有表头几何布局，不重复领域列规则
  rows.ts                               # 既有表体取值与对齐
  header/                               # 仅在实际提取表头/筛选 UI 时建立
  body/                                 # 仅在实际提取表体/单元格 UI 时建立
```

同名概念跨层有明确区分：page 的 columns 解释声明及字段身份，widgets 的 columns 计算表头布局；两者不能各自再解释显隐条件。已有通用 presentation 仍负责统一条件语义，表格专属实现位于 table 目录，由通用入口调用；不创建独立的 visibility 平行子系统。

表格校验从大 validate.ts 中抽出本批涉及的完整职责，通用校验入口只保留编排。协议 Schema 文件保持唯一；其余表格语义、搜索、视图与生命周期按变化原因聚合。测试遵循现有消费者所在的 tests/fixtures 组织，只在实际用例增多时加 table 主题子目录，不把生产文件、演示和临时证据混放在同一能力目录。

目录 README 是职责导航，不手写另一份产品协议；协议知识继续链接现有真源并通过生成流程维护。公共包入口保持稳定，不为每层子目录无条件生成 barrel export；目录内部优先明确依赖，避免 index 造成循环与意外导出。

#### 大文件约束与迁移边界

- 本批新增手写实现文件以 150—300 行为常见尺度，400 行作为必须复核职责的阈值；不是要求凑行数。超过 400 行时先按变化原因拆分；确有不能合理拆分的情况，记录具体内容、保留原因和复核结论，不能只写“后续优化”。这属于本批新增设计约束，不声称仓库已有自动行数门禁。
- 当前源码已存在大文件。最近只读盘点：`validate.ts` 约 2516 行、`RuntimeSurface.svelte` 约 1835 行、`Table.svelte` 约 1752 行；工作区并行变化明显，实施基线必须重测。对本批触及的大文件先抽出相关完整职责，再接入列能力；不能以“只多几个 if”为由继续堆积。
- 原入口文件保留编排/组装，不承担新列业务算法；提取后旧实现必须删除。若仍保留大文件，完成报告列出剩余职责、规模及后续处理入口，不能宣称全仓大文件已经解决。
- 本批不一次搬迁全部表格或重排整个仓库。按当前修改涉及的职责迁移，同批更新 import、对外导出、引用与测试；并行工作涉及的文件先核对归属，避免大范围路径变更覆盖其他批次。
- 行数与 selfCC 分别检查。小文件仍可能高度耦合；大数据表、生成文件或稳定协议枚举也不能靠随意切片获得“达标”。生成产物继续遵守生成器目录，不手拆。

#### 文件组织验收

1. 只看 table 目录和入口 README，可以找到协议、列规则、会话写入、UI 接入和导出各自的唯一归属。
2. 同一业务变化通常集中于同一职责目录；跨层接入是明确调用，不复制算法。扩展一种导出格式不修改列条件算法，调整列条件不修改 Excel 编码细节。
3. 本批不新增一批平铺在 src 根目录的表格 helper，不留下新旧实现并存或跨层循环依赖。
4. 报告本批新增/修改文件的职责、行数、复杂度和剩余大文件；结合实际依赖与变更聚合判断，不单凭文件数量或平均行数验收。

### 实施前技术核验

## 9. 验收矩阵与交付物

### 9.1 页面与行为

拟新增 `table-column-visibility` 场景，入口 `/pages/table-column-visibility`，默认 `layout: "dashboard"`，以 inline 合成数据展示基本规则；远程部分显式标识 DQE Sim。Report 专属 PDF/PNG 验收复用或扩展独立 Report 场景，不把主示例改成 Report。

| 场景 | 可观察结果 |
|---|---|

| 隐藏前已排序/筛选、其他列仍有操作 | 仅失效用户状态清除；默认业务排序保留；重显不复活状态 |
