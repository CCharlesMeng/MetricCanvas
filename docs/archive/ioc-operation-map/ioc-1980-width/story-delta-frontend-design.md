# US1980 · Frontend Design Delta

## 目标与 AC 引用

- AC-1：宽度所有权按层分离：宿主提供可用宽度，页面布局形态决定外框，内容分区网格分配内容单元；组件根节点只服从所属内容单元，不读取页面 id、页面布局形态、页面固定宽度或全局视口宽度来决定自身外框。
- AC-2：`ioc-project-overview`、`ioc-opportunity-analysis`、`ioc-opportunity-list`、`ioc-project-detail` 在 1980px 视口下以看板布局形态占满宿主可用宽度；1980px 仅是回归样本，不进入组件契约。
- AC-3：项目详情页页头、档案卡、规范卡、预测表、叙事卡在任意父内容单元宽度下占满该单元；450:1168 等比例由页面的 `columnTracks` 表达，不在组件中重复声明。
- AC-4：组件内部确需响应式切换时，以分配到的容器宽度为输入；相同容器宽度在不同页面宽度或视口宽度下产生相同布局结果。1980px 下页面没有页面级横向滚动、组件重叠或构件根节点裁断；表格自身的内部滚动不算页面级溢出。

## 对接模式

沿用 `layoutForm: dashboard` 与宿主契约。页面元数据不新增组件宽度字段；Canvas viewer 只负责交出宿主全部宽度，运行时按现有内容分区网格分配内容单元。组件根外框使用父内容单元宽度，内部响应式只允许消费容器宽度，不消费页面或视口宽度。

## 文字规格

1. 宽度所有权分为宿主、页面外框、内容分区网格、组件四层；后一层不得反向编码前一层的固定宽度，父网格也不得读取子组件 variant 推断自身响应式结构。
2. 组件根节点宽度等于所属内容单元宽度，并设置可收缩下限；禁止用 1679、1632、1168、450 等页面设计结果声明组件根宽度。
3. 450:1168 等跨组件比例保留在页面 `columnTracks`；组件不知道自己与兄弟组件的比例。
4. 组件内部需要断点时按容器宽度判定；禁止用全局视口媒体查询决定组件根宽度或内部排布档位。
5. 1980×1080 是回归视口：四个 IOC 页面内容盒宽度等于宿主可用宽度，不受固定 1679px 页面轨道限制。
6. 1980×1080 下页面文档宽度不超过视口，无页面级横向滚动、重叠、根节点裁断；预测表超宽由表格内部滚动区域承载。
7. 相同容器宽度在不同视口宽度下，组件根宽度与内部布局档位相同。
8. 不新增响应式断点，不改变既有窄容器回流与宽表内部滚动语义；仅把判定输入从页面/视口迁移为容器。

## 当前代码事实

- 四个 IOC 页面均声明 `layoutForm: dashboard`；项目详情的 225:583 比例已由 `project-profile.columnTracks` 表达。
- 当前未提交候选改动已把 Canvas 看板外框由固定 1679px 改为占满宿主，但共享组件 variant 又写入 1679、1632、1168、450px 根宽，并用全局视口媒体查询切换为 `100%`；`RuntimeSection` 还按 `detailSummary` / `projectNorms` 子 variant 改写父网格。
- 1980px 实测：概览、机会点分析、机会点清单已由父布局自然铺满；项目详情有 10 个主要组件根节点因页面派生固定宽度欠宽 83.8–301px。

## 状态、交互、接口与数据映射

无状态、交互、接口与数据变化。

## 风险与依赖

- `packages/runtime-ui` 与 `packages/widgets` 是共享边界；容器契约必须覆盖顶层内容单元及项目详情有限 variant，不能用页面 id 分支规避。
- 把媒体查询迁移为容器查询时保留既有阈值和内部回流语义，不把 1980px 变成新断点。
- 真实渲染证据依赖本地浏览器；静态测试只能证明源码未写入页面派生根宽，不能替代相同容器/不同视口的几何测量。
