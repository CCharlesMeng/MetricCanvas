## 已确认范围

- 本版覆盖进入 Platform 创作页面之后的页面创建、手工/语言修改、草稿保存与历史、预览、发布及页面执行接入全链路。
- 不实现 DataAgent，不考虑普通问数入口。
- 外部 Java 与 Relay 不实施修改，只产出修改方案、所需交互契约和联调要求。真实端到端验收依赖外部提供方兑现；本仓契约验证不等于真实服务已接通。
- 早期同意一个页面身份、草稿编辑、参数化发布产物冻结。最新 Q17 明确引入模板与页面实例两种内容形态；是否需要不同持久化身份仍待确认，不继续将早期单身份建议当作最终数据模型。
- 后续修改回到草稿，再重新发布；修改草稿不改变正在运行的发布版本。
- Q4：采用模型表达受控修改意图、Python 确定性执行的方式，包含组件属性修改；扩展现有 MetricCanvas Authoring MCP 的方向获得认可。
- Q5：先限定语言修改范围；具体操作与属性清单仍待冻结，不能据此推断所有组件属性和远程表格排序已纳入。
- Q6：Relay Agent 需要能发起草稿保存，仅向前端交付草稿标识，前端再读取文档；自然语言应能发起保存与发布。撤回“统一由 Platform 发起所有保存”的建议。平台与 Relay 共用管理服务的修订、校验与冲突规则，管理服务仍为持久化真源。
- Q7：用户要求区分元数据内容修改与生命周期操作的工具角色；撤回将两者合成同一修改并保存工具的建议。允许多个 MCP 或 CLI；具体入口形态待确认。
- Q8：用户询问标识能否表达顺序，尚未将任何 id 编码策略确认为契约。建议 id 仅定位修订，顺序/基线冲突/迟到结果另有显式语义，不解析 opaque id 推断顺序。
- Q9：采用准备发布、预览与确认后提交的两阶段流程；发布前必须由用户确认 globalParams 提取正确。由此展开 globalParams 对渲染引擎影响的分支。
- Q10：组件属性修改按白名单开放；具体清单仍需根据页面协议和实现逐项冻结。
- Q11：同意两个独立 MCP 入口，内容编辑与生命周期调用分别交付，第一版不同时建设 CLI。
- Q12 收窄：globalParams 本意为公共维度取值的实例化，不建设通用参数系统。用户提出可称“维度值”；讨论暂用“维度取值”，实际字段命名待契约冻结。撤回让 globalParams 全面取代 filters 状态的扩张方案。
- Q13：URL 只在初次加载读取，不监听后续 URL 变化，不由此重初始化页面。
- Q14：接受显式入口条件、有效历史条件、页面默认值、授权范围回退的优先级；权限始终为查询约束。
- Q15：越权条件静默改用允许访问的数据范围；不额外要求用户确认。服务端返回实际取值，数据与已有筛选显示仍需一致；无任何可访问范围不能解释为无限制查询。
- Q16：允许只在部分数据源间共享维度取值，最终提取结果仍由用户确认。
- Q17：模板允许替换维度取值；页面实例是已确定取值或没有可变维度取值、在元数据中保存具体条件的内容。实例的持久化身份、后续页内筛选行为待细化。
- Q18：部分数据源失败时保留成功部分，沿用已实现的错误隔离，不作为新需求或重新审批项。已核实现有初始数据仅承载 rows/totalCount 等成功结果，新执行接口的失败结果如何注入现有 error 快照是接入任务，而非错误隔离功能重建。
- Q19：用户确认可纠正参数提取候选，并询问承载方。自动提取的权威逻辑按此前方向归外部 Java 管理服务；本轮建议由 Java 同时重校验修正候选、平台承载可视化确认、生命周期 MCP 代理候选操作、Relay 承载语言交互，细项尚未视为新确认。具体候选修正接口只产出外部方案。
- Q20：模板执行生成的运行实例不自动入库；不作为本版重点，范围继续聚焦创作侧。
- Q21：页面实例允许页内筛选；已确定的初始查询值不意味着禁止本次运行交互，不建设只读实例限制。
- Q22：同维度不同取值的共享提取场景暂不支持，作为明确延期项。自动提取不合并这些条件，不把用户手动合并该场景暗中纳入本版。
- Q23：首版仅提取 DQE 维度等值/多值条件，不做时间、金额范围提取。
- Q24：单轮修改允许部分成功，保存可用部分。撤回整轮任一失败即不保存的建议。依赖操作如何形成最小完整单元属于实现契约：不能保存不合法引用或半成品；只保存整体通过页面校验的成功子集。
- Q25：采用基线冲突拒绝、不自动合并；语言修改期间禁用当前工作台手工修改，管理服务仍检查其他窗口的并发。
- Q26：用户指出组件创建不应只包含指标卡。撤回从会议示例推导创建范围的限制；完整组件创建范围按目录和所需输入梳理后确认，既有构造器覆盖面是实现事实而非业务上限。
- Q27：首次合法 metadata 生成后才保存首个草稿，生成前不创建空白占位页面资产。
- Q28：手工编辑通过画布和属性面板，原始 JSON 查看保持只读。
- Q29：Relay 程序通道传递候选页面、模型只见摘要/引用的方案先记录；不阻塞本仓核心实现。真实 Relay 接通仍单独验收。
- Q30：用户提出手工修改每个生效环节自动保存。采用该方向讨论，撤回仅在显式保存/进入语言/发布时保存的建议；完整操作的提交边界、排队、失败和撤销语义仍待确认。
- Q31：组件创建覆盖当前目录全部 17 类，不新增组件类型；必需数据/配置仍需满足，缺失的专用创建路径计入任务。
- Q32：手工编辑每个完整生效操作保存一份修订；文本提交/失焦、拖拽结束等是操作边界，不保存按键与拖拽中间态，无实际改动不新增修订。
- Q33：保存失败时降级至浏览器持久化，之后重试，不只保存在内存。继续本地编辑的方向保留；不得把仅本地持久化显示为服务端已保存。
- Q34：提供撤销上一步和历史恢复；恢复有效文档后形成新修订，不删除或倒退已有修订。
- Q35：新增顶层字段正式命名为 `dimensionValues`，业务名为“维度取值”；不再使用 globalParams 作为本版字段名。
- Q36：现有画布没有手工添加组件入口；该能力后置。本版保留语言创建全部 17 类组件及已有组件的手工编辑，不为手工添加另建组件库面板或查询编辑器。

## 已同意方向与尚未冻结的细节

页面草稿和发布版本的权威持久化归管理服务。参数化发布转换由管理服务负责最终校验与裁决，平台呈现候选、差异与人工确认，Relay 理解修改意图。平台与 Relay 都能发起保存。算法物理实现位置、外部接口形状、Relay 通过哪种程序工具提交保存与发布、参数化策略字段、版本并发方式仍需逐项确认。

最新 Q17/Q20/Q35 的内容语义已记录于 ADR-0078，并更新 CONTEXT.md：模板承载可替换维度取值，页面实例承载已确定值，运行实例不自动入库。外部资产身份与修订 DTO 仍按提供方资料对齐，不自行创建第二套可编辑模板库。结构汇总见 `2026-09-14-metadata-structure.md`。

## 当前代码事实

- `apps/platform` 是静态 SPA，`PageAuthoringWorkbench.svelte` 持有工作副本和基线修订，已通过 `page-assets-client.ts` 保存页面；历史读取明确不可用，公共 Chat 未接通。
- `metriccanvas-authoring` 已有 Python FastMCP 入站。relay 工具面为 `discover_data_context` 与 `compose_page`；compatibility 工具面使用有 Java 保存副作用的 `build_page`，不能混称。
- Skill 规定 Relay 模型形成业务域、取数单元和分析意图等结构化决策；Python 派生 DQE、执行验真、构造字段契约、选择组件并装配页面。Python Tool 不再次调用模型。
- `PageBuildSpec` 有 `baseRevision` 身份信息，但没有完整当前 PageDocument 输入。这不等于基于现有页面无损局部修改。
- 完整页面与数据行不进入模型上下文；可信程序读取页面和模型消费编辑摘要应分开。
- 统一运行时支持内嵌初始行；当前按生效筛选与默认筛选是否相同决定采用初始数据。新执行结果的筛选、数据和修订需保持一致。
- 自动保存幂等缺口：工作台为 `saveRevision` 提供 `idempotencyKey`，但现有 `page-assets-client.ts` 的 POST/PUT 并未把该键发送到外部服务。不能因此断言提供方不支持幂等，但重试方案必须明确服务端去重或操作回执查询契约，前端自造 UUID 不等于幂等闭环。

## 盘古助手独立开发与上游同步

用户确认新增以下交付目标，具体技术细节在该模块实施时 grill：

- 保持 ADR-0077 的界面职责：盘古占据现有侧边栏对话区域，承载对话输出、确认、进度、错误和历史；全局导航、文档工具条、画布与属性面板继续由工作台负责。
- 工作台仅通过稳定接口提供必要的页面/修订上下文、消费对话结果；盘古专有实例 API、事件与配置封装在独立适配模块。对话模块不直接修改工作副本，不实现元数据编辑算法、草稿持久化或参数提取发布规则。
- Relay 返回的已保存草稿引用经对话适配边界交给创作流程，再由创作流程读取管理服务并检查基线、操作关联及迟到结果。具体载荷与回调协议待实施对齐，不能将提议协议当成盘古现有能力。
- 提供独立开发与验证入口：以受控上下文和事件替身验证对话模块，核心创作流程也能在盘古不可用时开发与验证；真实盘古接通另行验收。
- 上游源码、盘古适配与部署配置分离。同步上游更新后，通过保留的适配模块和注入配置恢复集成，不要求用户手工补改上游源码或工作台。沿用静态 SPA 与运行配置注入约束，不因此引入 Node 服务。
- 同步流程须成为可复用、可验证的交付方式；验收包含一次在兼容接口下更新上游代码、保留本地配置并验证集成的演练。若上游公开接口发生破坏性变化，由适配模块集中升级，不能承诺任意上游变化都零适配。

实施 grill 再确定上游同步对象、模块目录/包或加载方式、盘古实例 API、身份与会话、取消与历史、产物回调以及配置保存机制；本轮不重新展开这些问题。上述独立开发与同步验收目标必须进入规格及对应任务。

## 首版编辑清单

目前手工编辑只已接通标题、宽度、组件移动和受数据形状约束的类型切换；组件属性面板扩展、添加/删除、维度筛选编辑、表格下钻编辑属于新工作。Python 没有基于完整现有页面的局部编辑入口。

创建能力盘点：`packages/page/src/schema/component.ts` 的目录共有 17 类。浏览器 `constructComponent` 与 Python `_component_for` 有 10 类数据组件构造器：metricCard、barChart、lineChart、pieChart、table、gauge、keyValuePanel、categoryBreakdown、rankingCard、rankingDetailCard；Python 整页流程另会自动创建 reportHeader。text、fieldText、mapChart、tabContainer、compositeCard、aiSummary 还需补专用创建路径。17 是当前协议目录，10 是可复用实现数量，均不能代替用户对本版范围的选择。容器子树、地图语义和动态 AI 总结分别有实际协议约束。

- 语言操作：组件标题/宽度/移动、已有能力范围内类型切换、17 类目录组件创建、组件删除、白名单属性修改、维度筛选及绑定、表格链接下钻；查询分页交互排序后置。手工添加组件按 Q36 后置；手工编辑已有组件继续扩展白名单。具体属性字段建议仍需在最终任务基线中审阅。

## 自动保存与浏览器降级：实现规则建议

采用 IndexedDB 持久化工作副本和按完整操作排序的待同步队列。建议每次合法操作先写本地，再请求服务端，而不等网络失败后才开始落盘。以工作区、用户、页面区分恢复记录；不持久化运行凭据。字段形状在同步模块内私有，公开面提供提交操作、状态、重试和恢复能力。

保存串行执行，一项成功后将返回修订作为下一项基线。每个逻辑保存操作复用稳定幂等键；超时可能是服务端已提交、回执未到，必须按提供方去重/操作查询契约核实，不能换新键直接再保存。网络类暂时失败退避重试并在重连/重开时恢复；校验失败、身份失效和基线冲突不无限重试。冲突保留本地内容、暂停同步，不自动覆盖服务端更新。

同步回执不得覆盖更晚的本地工作副本。只有已确认服务端提交的队列项可标为云端已保存；本地持久化失败须明确提示，不能继续声称已保护。待同步时允许本地手工编辑，但语言修改与发布等待同步完成。撤销/恢复也是新操作；已发出的保存结果必须先核实，不能因为用户撤销就遗忘其可能已经提交。
