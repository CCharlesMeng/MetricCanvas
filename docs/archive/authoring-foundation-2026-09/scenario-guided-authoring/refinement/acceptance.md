# 验收用例与证据账本

本文保留 v2 的 A01–A11 验收基线和阶段成绩。当前 v3 的新增用例、已完成项及未验收项见[实施记录](architecture-implementation-results.md)与[架构方案第 7 节](authoring-architecture-proposal.md#7-回归与验收)。v3 允许不同摘要形态，不以固定 compactSummary 或固定页面外形作为全局验收要求；历史模型对照不替代 v3 评测。

状态：离线实现、结构验证、修正后的真实中性模型 12 轮对照已完成。新版 6/6 通过专项结构检查，业务初审发现 1 处对象范围不一致；人工业务/视觉签收待完成。逐项证据见 [verification.md](verification.md) 和 [真实对照](evidence/neutral-clean-review.md)。用户明确取消 agent 截图，视觉验收交由用户；下列原始视觉判据仍供人工使用。设计见 [design.md](design.md)，任务映射见 [tasks.md](tasks.md)。

| A02 | 给定相关业务域分页目录；按同一快照枚举；返回明确覆盖范围、可信关联和缺失信息，过期分页拒绝，不暴露无关权限数据 | S0、S1、S6 | discover 公共工具测试 |
| A03 | 给定多个可同时发现的坏引用及独立有效正文；提交计划；同批反馈各错误及稳定 ID，静态无效需求不查询，独立内容按 partial 策略保留 | S1、S3、S6 | 失败注入、查询计数与候选校验 |
| A04 | 给定同对象唯一行、金额主值与受信同比/环比关系；提交指标组合；产物用既有 compactSummary、rows/changes 和独立格式，不拆成同等强调的六个裸数字块 | S2、S6 | 产物契约断言 + 实际浏览器截图 |

## 视觉验收细则（A04/A08/A11）

实现前冻结示例中的组合原则及既有组件规则；由 SDD 流程记录可观察判据，不能拿本次新产物作为自己的参照：

- 卡片按业务对象组织，主值、变化值、标题可明确区分；对应参考变体的背景、边框、内边距生效。
- 相邻卡片/卡片与趋势之间使用运行时既有间距，不出现重复标题堆叠或数字块混成一片。
- 1440、768、390 视口逐一检查；窄屏按已有规则转列，长标签可读、图例不覆盖图表，表格可在自身容器滚动，页面无横向溢出。
- 不规定固定章数、卡数或必须出现“结构分析”；不能以与样例不同就判失败，也不能以“不溢出”就判视觉通过。
- 业务审查逐章记录“问题/对象/信息增量/与别章的关系”；不需要的数据允许省略，省略理由可追溯。

## 成本验收（A01/A09/A11）

确定性门槛：正常有效计划一次 create 成功；布局修订查询次数为 0；单次调用相同有效查询只执行一次；需修订问题批量返回。不得用安全范围之外的缓存达成指标。

经验指标：按相同需求/模型配置/样例快照对照，记录模型请求数、工具调用数、查询次数、输入与输出 token、端到端耗时、修订原因、成功/部分成功/失败。报告每次和中位数，任何新增必经调用都必须修正；偶发模型多轮单独解释，不能把“结构上不增轮”说成“实际绝不增轮”。

原旧测试的章节暗示会影响结果，不直接与新中性提示的分数混算。中性需求的新旧对照需重新运行两边；旧产物仅作为技术和历史呈现证据。离线脚本、人工修补、真实自主模型运行分别标记。
