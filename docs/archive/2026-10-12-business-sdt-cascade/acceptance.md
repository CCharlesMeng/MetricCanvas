## 确定性执行用例

| 编号 | 场景 | 必须断言 |
| --- | --- | --- |
| R01 | 主请求未结束 | 下游零次调用，目标保持加载 |
| R02 | 主请求返回5个项目 | 一次下游请求含全部且仅这5个商务编号；两个月份条件一致 |
| R03 | 上游顺序变化或编号重复 | 谓词集合去重且缓存身份稳定；主行顺序不被谓词排序改变 |
| R04 | 上游成功空集 | 下游无HTTP请求，空结果不被解释为全量查询 |
| R05 | 上游失败 | 下游无请求，保留错误分类；消息不含编号或业务行 |
| R06 | 缺键、null、空字符串、非法数值、超过上限 | 不发下游请求；不静默过滤坏行或截断 |
| R07 | 多个结果绑定一个未ready/empty/error | 等待全部；空集短路；失败传播；AND语义一致 |
| R08 | 新主结果到达、旧明细仍在途 | 同步失效旧明细；禁止任何新主行+旧明细合并快照 |
| R09 | 慢响应无法及时取消 | 迟到成功和失败均不得覆盖当前代次 |
| R10 | 两个消费者共享同一请求 | 取消一方不误取消另一当前消费者，沿用现有去重成员行为 |
| R11 | 时间/其他条件变化但编号相同 | 下游查询键变化，不能命中错误缓存 |
| R12 | 一次返回两度量、三个阶段 | 六列分别来自相应阶段时长与次数；0与null保持不同 |
| R13 | 同编号同阶段重复或无匹配阶段 | 新透视拒绝重复；无匹配仅相应列null；不丢主行 |
| R14 | 辅助totalCount大于原始行数 | complete核验失败；主Top5总数大于5不能使辅助截断被接受 |
| R15 | 同capturedAt的旧initial或执行回执 | 未证明级联输入的链整体重取，独立源仍按旧规则复用 |
| R16 | 未被组件直接引用的明细源 | 仍纳入运行依赖闭包；无关数据源不因级联盲目重查 |
| R17 | 导出前编号变化，导出主查询得到另一集合 | 导出明细使用导出本轮集合，保留5行与原选择顺序 |
| R18 | 主totalCount超过5，导出请求 | 不遍历全部项目；普通查询分页导出回归仍通过 |
| R19 | 导出/关闭/替换页面时取消 | 停止后续依赖请求，无孤立任务、迟到快照或旧编号复用 |

## 本地 DQE 仿真

为本场景新增精确匹配分支，保留现有未知查询失败关闭行为。仿真只理解普通DSL：主查询排序/limit，辅助查询的月份、商务编号集合和阶段维度。不能让mock自行执行cascade或代做pivot/join，以免绕过引擎验收目标。

仿真夹具由两部分组成：当前项目标识与测试用阶段行。现有null、0和次数可保留为基线；新增时长等数值明确标为合成夹具，不能宣称真实补齐。至少准备两套不同月份/集合、三个阶段、缺阶段、重复阶段、延迟和失败场景。消费者旁的fixture不进入计划目录充当已执行证据。

HTTP验收记录至少包含请求次序、逻辑查询项、月份、实际商务编号集合、响应状态/行数和取消事实。两组主查询允许同HTTP批量，下游不能与尚未返回的上游同批并发。每组在正常路径是一次主逻辑查询加一次明细逻辑查询，不按行扇出。

迁移报告的两组数据源后，仍使用原表格数据槽id。页面其余查询保留原内嵌初始行，避免本批扩大到全报告mock。级联链按实施方案从真实本地HTTP取数，不用旧initial伪装执行成功。

| 编号 | 页面检查 | 判据 |
| --- | --- | --- |
| B01 | 最快与最慢Top5 | 各5行，左四列由主查询，右六列与阶段夹具逐商务编号对照 |
| B02 | 两表并存 | 各用自己的编号集合，最快/最慢与asc/desc一致，无交叉填数 |
| B03 | 加载、空、主失败、明细失败 | 不把失败显示成普通缺失、不显示新旧混合数据 |
| B04 | 重开页面及切换测试输入 | HTTP证据能证明新编号集合实际传入第二请求 |
| B05 | 正常桌面与窄屏 | 列组与行关联可辨认，现有横向滚动可用；不重做视觉设计 |

浏览器至少保留项目效率分区截图与请求记录。截图必须标明是原页面基线还是新能力+仿真验收；不能只用截图证明请求顺序，也不能只用请求成功证明表格映射正确。此次没有外部设计源还原要求，不走SDD视觉实现流程。

## 真实数据验收与交付记录

真实数据验收须取得当前身份的数据上下文和第二项DSL真实响应。核对商务编号集合、阶段类别、每个组合键唯一性、数值单位、缺失含义、响应total_count及后端隐式上限。第一项返回的排名范围与第二项明细使用相同月份，结果经过现有字段映射和行契约。Top5时长相同的项目顺序由实际DQE决定，不能因页面显示都为0.0而认定所有原值相等。

最终交付分别填写静态、运行时、仿真HTTP、浏览器、导出、分发、真实DQE、Relay/Java、CI和部署的passed/failed/not-run/not-applicable；每项附证据路径与适用范围。本批实施验收至少要求静态、确定性、本地HTTP、浏览器、导出数据路径与分发通过。真实DQE未接通时明确留下真实集成缺口，不把本地结果当生产完成。
