# 商务 SDT 级联查询具体实施方案

本方案落实已确认的两阶段数据请求，保留普通DQE查询及组件数据槽。实施细则已落地，具体结果见[验收结论](../../evidence/2026-10-12-business-sdt-cascade/result.md)。业务说明和结构只维护于[讨论入口](README.md)与[结构草案](data-sources.proposed.json)。

## 协议与执行职责

| 位置 | 负责的行为 | 实施接缝 |
| --- | --- | --- |
| 页面协议 | 显式输入来源、字段角色、目标维度、集合上限、版本和依赖合法性 | `packages/page/src/query.ts`、`schema/data-source.ts`、`validate.ts`及依赖校验 |
| 查询编排 | 等待上游、提取集合、输入失效、生成生效查询、协调缓存与取消 | `packages/engine/runtime/src/orchestrator.ts` |
| 数据网关 | 普通DQE谓词生成、HTTP批量、响应对位和查询字段映射 | `packages/engine/data-gateway/src/dqe.ts`，优先保持公开Interface与协议不变 |
| 受控计算 | 多度量透视、按商务编号左关联 | `packages/page/src/compute.ts`、`schema/compute.ts`、`validate-compute-dependencies.ts`、`runtime/src/compute/` |
| 导出 | 使用导出本轮主结果重新解析明细输入，保留Top5范围 | `packages/engine/runtime/src/export-snapshots.ts` |
| 页面 | 四个命名数据源及原表格的数据槽 | `pages/business-sdt-report.json` |
| 本地仿真 | 两类普通DSL请求及响应，暴露请求条件供验收 | `tools/dqe-sim/src/execute.ts`、现有HTTP服务及消费者旁fixtures |
| 创作分发 | JSON Schema、TS/Python校验、参考文档和Bundle自洽 | 契约生成脚本与authoring页面校验 |

结果输入解析集中在一个私有Module，Interface接收已声明的绑定与原始快照，返回等待、空、错误或规范化维度谓词。它不访问页面筛选状态、不发HTTP请求；预览和导出共用它。调度继续使用现有执行通道，不增加第二套请求缓存或组件级请求机制。

## 结果绑定规则

下游 `query.resultBindings` 是可选非空数组。每项包含 `source`、`field`、`target: dimension`、`queryField` 和正整数 `maxValues`。当前草案上限为5。建议运行时另设共享集合硬上限1000，声明上限不得超过硬上限；这是待正式ADR记录的资源约束，超限报错且不截断。

首版支持查询源的原始归一化标量维度字段，类型限定string或有限number；字段必须具有queryField映射。计算产出、recordList、measure和缺失字段均不能作为输入。原始字段使用稳定页面字段id，目标使用DQE字段名，集合去重保留值类型。

首次输入集合不提供排序语义；用于谓词与缓存时规范化为确定顺序，保持主查询原始行顺序另行用于最终展示。相同集合不同返回行序不改变下游查询身份。

同一个下游查询的结果绑定之间不得重复目标维度；结果绑定与filterBindings、paramBindings及静态dims不得重复绑定同一目标字段。层级绑定按全部可能目标字段检查冲突，不自动覆盖或默默取交集。时间仍使用已声明查询值或页面参数，不因级联自动推断时间窗口。

首版结果输入读取上游查询返回的原始行集。上游允许显式正整数order.limit定义有限选择集合，但拒绝order.offset、运行时查询分页、服务端排序及表头筛选对该上游的窗口覆盖。计算后主表的本地排序和显示分页不改变编号集合。这样同一数据源被多个组件消费时只有一份依赖输入。

空上游或成功的零行结果使下游直接形成空原始快照，不发送无条件请求。上游加载时下游加载；上游失败保留错误分类并传播固定脱值消息。行中缺键、null、空字符串、非法类型或超限均报错，不能丢弃坏行或缩小到看似合法的集合。整个输入合法后才发一次集合查询。

## 按阶段建立依赖图

为每个查询源区分Q节点和C节点：Q表示经查询字段映射及行契约校验的原始快照，C表示执行compute后的快照。依赖关系以“消费者依赖输入”描述：

```text
Q(阶段明细) 依赖 Q(项目主源)
C(阶段明细) 依赖 Q(阶段明细)
C(项目主源) 依赖 Q(项目主源) 与 C(阶段明细)
```

这是一条有效执行链。不能把两个阶段压成一个数据源节点后将此例误判成环，也不能等待C(项目主源)就绪才触发阶段查询。用带阶段的图校验全部声明源，包括未被组件引用的源；未知引用、自引用和真实循环均拒绝。运行闭包包含组件数据槽、AI总结关联数据、compute依赖和结果绑定依赖。

若未来需要引用计算产出或inline源，应新增明确的版本能力和阶段规则；首版不通过可配置路径或任意表达式预留该行为。

## 调度与一致性

1. 页面初始化后，只有输入已满足的查询进入现有执行队列；两组主查询可以并行。
2. 主查询结果完成归一化后解析下游谓词。下游再使用现有并发槽、请求去重、缓存、AbortSignal和代次机制。
3. 任一上游生效查询变化，先同步使其所有下游原始快照失效，再启动新请求和计算。不得先发布新主行与旧明细的合并结果。
4. 下游全部结果绑定均ready后才提交请求；任一empty短路为空，任一error传播错误。首版多绑定为AND语义，不允许无条件降级。
5. 缓存键包含生效查询、字段映射、实际维度集合、时间与其他谓词。内存版本变化但实际输入相同，可复用已有正确缓存；输入变化产生不同键。取消复用现有共享请求成员规则，不能误取消另一当前消费者。
6. 迟到结果只允许落入匹配本次输入与请求代次的快照。错误也受代次约束。

原始快照缓存继续不保存透视和关联产物；计算由同一轮原始图推导。查询调度和计算共用输入代次，不把自动结果回写到用户FilterState或URL。

## 内嵌初始行与执行启动回执

旧页面的initial规则保持原样。新增级联链不能仅凭相同capturedAt证明明细属于当前编号集合。首版保守策略为：涉及级联链的查询不直接复用普通source.initial，统一按当前查询重新执行；不新增持久化证明字段。迁移当前页面时，主源initial中的六个阶段指标不能继续充当原始输入。

执行启动回执路径位于 `runtime/src/execution.ts`。首版同样让无法证明实际绑定集合的级联启动结果失效并重取，保留其他独立源的回执复用。将来若需要免查询启动，另行设计经过验证的执行输入证明，不能静默信任模型声明或缓存摘要。

## 透视与左关联

Pivot保留现有必填默认valueField，新增columns中的可选valueField。每个目标列从覆盖字段或默认字段取值。校验全部取值字段存在且为相容数值度量，输出字段类型、单位与输入一致且没有queryField。缺阶段输出null，真实0保留0。

当前TS和Python校验还禁止同一category映射到多个列。多度量透视必须同时把冲突判据改为“有效valueField与category的组合重复”：同阶段的时长和次数可以分别映射，同一度量同一类别仍只映射到一个目标列。默认valueField计入有效值，列内重复category及重复output继续拒绝。只有增加列级属性而未调整这项规则，完整草案仍无法通过语义校验。

使用列级valueField的新透视要求输入的 `keyFields × categoryField` 唯一；重复行产生计算错误，不把次数相加，也不把时长随意求和或平均。旧版本单度量pivot的首命中行为保持兼容。真实DQE须确认阶段查询返回的粒度和单位。

JoinAggregate继续左关联并保留主行与顺序，六个值使用unique，不需要新聚合方式。完整性校验区分两侧：辅助源仍必须resultScope complete、无分页和limit/offset；局部主集合可参与左关联，但不会被当成完整业务全集用于grandTotal、groupSubtotal、timeFill或其他全量统计。建议限定放开到“被结果绑定引用、显式order.limit且无分页覆盖”的主源，避免批量放宽旧页面。

上游Top5返回totalCount可以大于5，原始总数不得改写成5伪造全量。编号数量仅由实际返回行决定；校验rows不超过声明limit，辅助原始行数仍按complete要求与totalCount核对。Top5是声明的选择范围，不通过改写totalCount消除不完整提示；若UI因此显示误导提示，应让相关呈现读取明确的选择范围，而非放宽全局提示规则。

## 导出必须执行同一条依赖链

当前export-snapshots根据捕获查询并发获取数据，并将声明limit用作分页拉全起点；它不能直接消费新的结果绑定。

导出固定本次页面参数、筛选与查询定义，重新执行主查询，保留其Top5选择范围。下游谓词必须来自导出本轮主结果，不复用屏幕上的旧编号，不因totalCount大于5而扩展为全部项目。辅助源继续完整性核验。复用同一个结果绑定解析Module与调度语义，保留现有导出超时、取消和行数上限。

导出首版以运行时数据准备及DOM结果为必要验收；当前页面若有实际PDF入口，再增加PDF验证。没有入口时不得把数据准备通过称作PDF导出通过。

## 版本与分发

落地能力版本为6.14，保留当前可读5.0–5.4、6.5、6.11、6.12和6.13；实施前重查当前版本与同日其他工作。现有supportedVersions随当前版本增长可能丢掉6.13，必须显式加兼容回归。

结果绑定与列级pivot分别注册能力探测；有限集合左关联必须由结果绑定证明其选择范围，不把6.12页面仅通过改JSON变成合法新能力页面。迁移目标报告时增加明确layout report；完整草案当前只含dataSources，不是完整页面。

authoring至少同步结构和语义校验，不宣称AI装配已经能自动产生级联。若扩展装配工具或Skill，按 `docs/agents/skill-ds-model-acceptance.md` 追加分层验收；真实DS模型、Relay、Java保存与真实DQE各自保留独立结论。

现有contracts、authoring和运行时有其他在途改动。生成前审阅最新差分并协调其所有者，生成后核对范围，不覆盖其他会话工作。生成锁文件使用仓库脚本，不手改。

## 回滚和真实集成协调

实施前保存原页面字节与hash，回滚恢复原单查询页面，移除新结果绑定、产出计算及辅助源，并回滚同批协议/引擎版本。保留用户其他改动，不执行全仓重置。引擎在旧页面上保持原行为。

本地mock可先验证技术链路；真实集成需要提供方确认第二项DSL是否合法、阶段名称与结果粒度、单位、total_count及默认行数上限。浏览器执行普通DQE无需Relay新增调度。若后端执行回执或创作期验真也要识别级联，需明确其结果绑定解析与执行职责；该接线不能由前端测试替代。
