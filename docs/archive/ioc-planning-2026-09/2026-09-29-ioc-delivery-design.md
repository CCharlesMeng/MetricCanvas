## 1. 最终目标与范围

最终交付：来源21个路由入口的启用业务内容，在 MetricCanvas 中具备可追溯的页面文档、结果字段契约、受控计算、交互和本地验收证据；AI能够通过正式创作工具创建和调整这些页面。路由变体可以共用页面资产，但每个入口必须分别验收。

可见效果允许重新设计；业务信息、数值、筛选口径和启用交互不能因组件不足而静默丢失。禁用内容不制造可用入口，客户接触详情为用户明确延期。其余16入口和启用子内容不能因首批五页完成而从范围删除。

分清三个交付结论：

| 交付结论 | 所需证据 | 本阶段是否承诺 |
|---|---|---|
| 代表页本地可运行 | 已确认字段、匿名行集、真实运行时、必要浏览器交互 | 是，分五页交付 |
| 全量迁移及创作闭环 | 全部启用入口验收、创建/编辑、契约与Bundle自洽 | 最终目标；依赖第二批来源材料和搜索缺口解决 |
| 公司生产集成上线 | 真实身份、Java/Relay、DQE及门户部署联调 | 本阶段不包含，不能以mock或模型验收替代 |

不改DQE查询协议、数据网关和执行逻辑；不复制旧GraphQL/REST/SQL客户端，不引入任意公式、任意HTML格式化、ECharts option或第二套页面渲染器。页面、修订、身份和返回栈的所有权保持现行约定。

**必须显式保留的限制：** 查询分页的全量搜索尚不能在现有DQE约束下实现。该交互不能宣称等价；相关页面允许交付明确标注的候选版本，但不能标全页最终验收通过。最终若现有能力仍无法满足，必须单独处理范围约束冲突，不能偷偷扩大查询协议或静默删功能。

## 3. 成功标准与完成定义

每个消费者必须具备一条追踪链：来源位置/报告哈希 → 采用或修正说明 → 结果字段契约 → 页面绑定或具名算子 → 匿名输入/预期输出 → 目标执行证据。

- 所有启用可见字段、图表系列、表格列、动作逐项有记录。对缺证据项不得填写推测字段；UNKNOWN明确标受影响消费者。
- 原始数值与显示字符串分别断言；null、缺字段、0、负数、非有限数分别覆盖适用分支。严格断言不用JSON.stringify把NaN伪装成null。
- 标识、日期、整数、枚举及缺失状态精确相等；浮点按具体指标约定容差（比例可用1e-9），金额在原始单位对账，不能用显示舍入掩盖数值误差。
- 任一查询失败不变为成功空集；分页窗口不当作完整结果；旧请求结果不混入新口径。
- 新写6.12、旧6.11可读；6.11使用新能力必须拒绝；旧文档不批量重写，不修改不可变修订。
- 静态页面只证明组合和计算；查询交互必须经过正式编排器及mock/DQE仿真路径，不能靠inline页面证明查询成功。
- 每页分别报告源码材料、目标确定性、目标浏览器、模型、CI、生产集成。未执行就是not-run。
- 无未处理的阻断性语义差异；延期只有用户明确批准项。首批页面内部UNKNOWN未消除时允许分区验收，不允许整个页面“通过”。

## 4. 实施架构与职责

```
页面文档（字段契约 / 数据源 / 具名算子 / 详情声明 / 组件绑定）
    ↓ 校验版本、字段、依赖图、处理范围、作用域
统一运行时（主页面会话 / 详情会话 → 复用既有查询编排）
    ↓ 按会话和本轮查询发布数据快照
runtime-ui（筛选、表格状态、详情生命周期、呈现投影）
    ↓ 纯数据与事件
widgets（既有组件渲染）

数据网关：沿用现有接口及DQE执行逻辑
集成应用：路由、返回状态、身份和部署
内部响应适配：响应信封、列式数组归一化、稳定字段映射
```

Module以小Interface封装完整状态行为，避免在RuntimeSurface与DetailContent分别复制分页、排序、筛选处理。共享的是机制，不共享可变会话状态。

### 4.1 详情会话：查询分页及局部筛选

**选择：** 在统一运行时内复用编排器，为每次打开生成独立详情会话；不把详情变成独立页面资产，不在widget查询。

现有 `runtime/src/detail-view.ts` 负责输入绑定，`RuntimeSurface.svelte` 负责开启/关闭，`DetailContent.svelte` 仅做本地表格处理。拟提取内部详情会话Module，Interface提供打开输入、快照订阅、局部筛选更新、表格查询状态更新、销毁；不向页面文档暴露控制器对象。

| 状态事件 | 规定行为 |
|---|---|
| 打开 | 冻结行标识及当前全页口径，验证必需参数；创建独立筛选/表状态，开始依赖闭包加载 |
| 翻页/排序 | 使用当前详情会话和现有查询状态通道，只重取受影响数据源；查询窗口不再本地slice或重新排序 |
| 局部日期模式切换 | 仅更新详情可见筛选，重置受影响表到第1页；同步窗口/粒度/横轴；不改主页面 |
| 关闭/换行/全页筛选变化 | 取消请求、销毁订阅及代次；所有旧回调失效；关闭不入返回栈 |
| 请求错误 | 详情明确错误态；不留下无标识的上一行数据，不用0掩盖错误 |
| 重新打开 | 新会话，默认第一页及声明的默认局部筛选，不继承上一个客户 |

拟在detailViews声明中区分“打开时只读绑定参数”和“可在详情中修改的筛选”。复用现有筛选类型闭集，初期仅单选模式、时间点、时间范围；命名空间和依赖消费者受校验。输入绑定字段不可被用户改成别的客户。snapshot模式继续只读、不增加请求。

**Schema影响：** ADR-0096当前拒绝详情查询分页和可见局部筛选，实施前需修订现行决策与校验；不是只删两条拒绝规则。新增声明缺省保持当前行为，旧fields详情继续可用。

### 4.2 表格：明细、汇总与总数分开

**选择：** 通过命名数据槽绑定独立汇总行，由统一表格投影在完成明细过滤/排序/分页后插入；不把汇总写回主源数据快照。

拟增加固定汇总呈现声明：汇总数据槽、位置top/bottom、空明细时显示或隐藏。复用已有结果字段契约和rowKindField，显式字段映射；默认无汇总。多个原始返回集应先归一化成已声明页面数据源，表格组件不识别旧REST接口。

- totalCount只统计明细，不含固定汇总行。10条明细加1条汇总仍是10条/页。
- 本地表：在完整明细上搜索→排序→分页；汇总的范围要声明是整个筛选结果还是独立查询范围，不根据屏幕10行重算全量。
- 查询表：页码/排序按已有DQE查询通道；汇总与总数绑定同一业务筛选指纹，不随页码重新解释；有变化的口径不能混用旧汇总。
- 固定合计行与明细共享展示字段，但动作参数分别明确：云服务合计表示全部服务，不用空字符串蒙混“缺必需标识”。拟用有限的“全部/具体成员”选择声明，禁止任意条件表达式。
- 汇总失败时明确标注相关错误，不显示旧汇总搭配新明细。期望行数（如单行汇总）也必须验证。

Token开通表是“查询侧按客户分页、窗口内按客户+账号分组”。必须取得上游分页单位/完整组保证，不能把数据行总数当客户总数。先评估扩展已有mergeBy到组合字段和指定合并列；仍不足时再作最小协议增量。禁止用字符串拼接造复合键或持久化rowSpan值。

### 4.3 受控计算：按消费者补齐，不改变全局默认

以下为待评审的闭集方案。每个新增算子/参数只有在对应消费者夹具通过后才进入Schema，不为未来场景先造通用运算语言。

| 消费者需求 | 当前不等价点 | 推荐设计 |
|---|---|---|
| 12个月预测求和 | 全null在现有ignore策略仍为null，来源为0 | sumFields增加显式全缺失结果策略，缺省仍null；有效数字为0要保留；不得改变其他收入汇总 |
| 经营概览环比 | delta再ratio遇pre=null可能提前得到null，来源特定消费者返回0 | 专用增长率算子声明基期为0、基期缺失、当期缺失各自策略；只有被证据支持的闭集取值，不扩张成条件公式 |
| 两源概览表 | 来源键集合并集、同指标重复取后项，当前只有左关联unique/sum | 受控按键合并Module：键集合left/union、源字段映射、重复处理reject/sum/ordered-last；ordered-last必须有顺序证据，无证据拒绝 |
| 趋势按期汇总 | 原始多行同期间求和，全缺值保留null | 专用groupAggregate按声明键折叠行，校验collapsible/单位/币种；不以grandTotal每组追加行代替 |
| Token补日重复 | 源Map保留最后项，timeFill默认拒绝 | 明确duplicatePolicy reject/last并声明有序输入前提；不改变默认reject，不让来源不确定顺序决定生产结果 |
| TOP5+其他 | 需要稳定排名、尾部汇总及占比 | 专用topN分组保留+其余聚合，限定可加度量、明确空名称/空值次序，复用ratio求份额；不复制任意比较器 |
| 页面双年/云服务双年 | 系统年、页面窗口和最大有效数据年不同 | 时间对齐Module分开声明查询窗口和展示参考年；参考年closed enum，注入时钟；不能全部替成系统当前年 |

对缺匹配收入保留主行/null、源失败传播错误的既定行为不变。上表新增集合并集只能在有对应消费者依据时使用，不能全局替换joinAggregate。非数值字符串、缺失和null不能依赖JavaScript隐式强制转换。

### 4.4 时间、模式和显示

- 查询窗口推导放在统一运行时的筛选解析阶段，输出既有timePoint/timeRange值，经现有filterBindings传入查询；不改DQE语法。只提供明确的“页面月起止、页面年双年窗口、固定日数回溯”等具名闭集规则。
- 系统当前年以页面会话注入时钟为准；测试固定2026年并选2025页面日期。跨年刷新是否重建会话在页面刷新事件中统一处理，不能图表各自new Date。
- HOUR/DAY不仅换字段名，还要明确查询结果粒度；如既有查询不能表达切换，应提供不同已验证查询定义及有限选择，不向查询体插字符串。
- 原始金额/比率仍为数字。格式化只负责展示，单位与百分比刻度显式；百分比0.5与50不自动推断。
- 枚举通过完整字典映射；未知值按消费者契约显示缺失或原值，不自动变成“否”。ANA未实测的精确字符串继续not-run。
- 动态年份表头通过既有受控文本绑定能力评估；不足时只新增参数占位闭集，不引入任意模板求值。
- 表格趋势缩略图拟复用既有线图数据与绘制逻辑，给表格有限sparkline呈现选项；只消费已归一化的时间/数值数组，不在表格内JSON.parse旧接口字符串。具体字段契约等Token接口补证后定稿。

### 4.5 页面与路由

每页仍为独立页面文档，参数只负责入口初始化，筛选负责打开后的可变口径。返回栈和权限仍由集成应用持有。

机会点名称到项目详情采用行mtime；项目主页到项目详情采用页面月。机会点清单客户列新证据为禁用，暂不把通用导航测试当该业务入口已启用的证明。缺必需参数不补当前日期、不替用另一日期。

项目主页CSSC共享服务副作用改为显式入口参数/目标筛选初始化；不迁移HeaderOptionService。TOP已立项清单参数的正文矛盾在来源表中修正后再绑定。

### 4.6 版本和创作

当前6.12未交付的新增声明采用可选字段、明确缺省行为；实施前核对发布状态。如6.12已发布且拟变更改变已允许语义，另行次版本，不悄悄重定义。6.11读取兼容保持既定决策。

所有新能力同步Zod真源、类型推导、能力下限、引用与语义校验、运行时和定向夹具。最后阶段统一更新Python校验、装配/编辑支持、工具说明和生成契约。不能在前面阶段运行会写metriccanvas-authoring的生成命令。

## 8. Schema与实现任务拆分

1. `packages/page`：新增声明及严格校验、字段/数据槽/参数引用、作用域、版本能力下限、无效组合负例。原generated文件不手工改。
2. `packages/engine/runtime`：具名算子、查询会话/表状态复用、依赖同批、时间注入、取消；只使用现有DataGateway Interface。
3. `packages/engine/runtime-ui`：抽共享表格控制逻辑和详情会话绑定，主页面与详情分别实例化；不要继续把所有逻辑堆进RuntimeSurface。
4. `packages/engine/widgets`：固定汇总/指定列合并/有限趋势格的纯呈现；组件不得做查询、业务计算或解析旧响应信封。
5. 页面资产：先字段契约/依赖图，再图表表格，再动作；匿名行集在消费者旁夹具，可供仿真引用；不把旧接口参数语法存入页面。
6. 验证：每个Module通过同一Interface测试；先目标数值/生命周期，再页面浏览器；只在变更影响对应接缝时扩大回归。
7. 创作最后：schema工具、Python、编辑白名单、装配、Skill、创建/编辑回归，同一最终文件树执行生成与检查。

新增SDD Story只覆盖来源结构还原的页面/交互，引用该页明确文字基线，样例标签不当业务文案；纯计算重构不走视觉验收。现有导航Story缺失证据单独补记，不能以新Story覆盖历史缺口。

## 10. 本次需要评审的具体取舍

不再询问既定业务口径，仅评审以下新的协议/运行时设计：

1. **详情继续是页面内作用域。** 推荐扩展查询分页和局部筛选，复用编排器；替代是独立页面，但会增加页面身份/返回/嵌套生命周期，且背离当前单浮层设计。
2. **汇总使用独立命名数据槽。** 推荐保持明细行集不变，在视图层固定展示；替代是在每次响应拼入合计行，会污染分页、排序、总数和缓存。
3. **计算继续闭集、显式策略。** 推荐为真实差异增加少量具名算子与策略，保留所有旧默认；不通过隐式空值修正或通用表达式追求“一个算子解决全部”。

这些选择会扩展6.12工作稿，但不会要求重写既有6.11页面。具体字段名和算子名在M1给出可执行正负例后冻结，不把本文伪代码/命名当发布契约。
