## C1 Interface（已进入代码，创作契约待同步）

沿用页面数据源的 `compute` 阶段，增加封闭具名算子 `joinAggregate`，不引入第二种数据源资产或独立计算身份。形状：

```json
{
  "op": "joinAggregate",
  "source": "revenue",
  "keys": [{ "local": "customerId", "foreign": "partyNumber" }],
  "values": [{ "field": "amount", "output": "revenue", "aggregate": "unique" }],
  "onMissing": "null"
}
```

- `source` 是本页面数据源 id，依赖使用该源完成计算后的结果。
- `keys` 是非空有序组合键，逐字段声明，不拼接字符串、不以行序或标签猜关联。两侧字段类型与角色相容；缺键报错，不把多个缺失键关联起来。
- `values` 显式映射源度量到本源已声明的产出字段；`aggregate` 闭集为 `unique | sum`。`unique` 拒绝重复键；`sum` 必须有 `collapsible: true`，整组无值输出 null，部分有值求和，不合并币种或不同单位。
- `onMissing: null` 明示左关联保留主行；未匹配输出 null。成功的空依赖与请求失败不同，失败不能转成缺行或 0。
- 产出字段无 queryField，不能覆盖输入字段，不能提前读取后续算子的产出。类型、单位、币种必须与输入相容，缺行产出允许为空。
- 辅助源需要完整行集证据。查询分页窗口不得参与全量关联或聚合；查询源显式声明 `source.resultScope: complete`，拒绝查询分页及查询体limit/offset；返回totalCount时核对行数。没有totalCount时完整性仍是上游输入契约，不能当作真实联通证明。
- 校验整张依赖图，包括未被组件消费的数据源；循环、自引用、未知依赖、输出冲突均拒绝。

运行时接缝：保留原始查询快照缓存；计算快照由页面数据源依赖图统一形成。组件消费闭包内的源均参与调度，包括仅被具名算子引用的源。一次筛选变更先将所有受影响输入切到本轮状态，再沿依赖图计算，禁止先发布新主源与旧辅助源组合。未变更的有效输入可复用，不为整页盲目重查。

依赖加载时目标加载；任一必需依赖失败时目标错误，保留脱值后的结构化原因；只有请求成功但无匹配行才输出 null。沿用现有 AbortSignal 与代次丢弃，缓存始终保存计算前结果，避免重算重复合计。inline、initial、远程三条路径使用同一计算接缝。

验收先用 F2 的匿名键/单位/竞态样例，不能将其称作 T-41/42/44/48 的来源等价验收。后者仍需主计划所列精确补证。
