# Spec：统一创作 Skill 的执行逻辑、结构与体积优化

日期：2026-09-15。状态：正式实施规格，已发布为 [Issue #150](https://github.com/CCharlesMeng/MetricCanvas/issues/150)，标记 ready-for-agent。来源：本轮完整 grill、内部 define-report 调查、统一 Agent 架构，以及数据源映射补充。用户已确认验收入口：真实 Skill 任务评测、公开内容工具完整流程、构建交付检查；外部服务用可替换 Adapter 做契约验证，真实内网联调独立验收。

## Problem Statement

页面创作者希望在一个对话入口中创建页面、修改当前页面和询问选中组件的配置。当前创建与修改 Skill 分离，混合任务需要来回路由；人工页面搭建后，模型历史可能保留过期页面信息，局部操作有覆盖新设置的风险。选中组件与用户文字指代的关系也需要稳定规则。

维护者面对两个各约九万行的 Platform Skill 分发目录，完整页面资料、机器索引与错误夹具重复随包分发。已有 14 例评测记录为 6 pass、3 fail、5 blocked；三个失败涉及修改任务误用数据发现查阅文档，编辑产物本身符合要求。该评测只注入少量文档，不能把调用错误或输入 token 直接归因于分发目录行数；数据创建配置和真实部署路由未得到完整验证。

内部 define-report 已发生二次开发，业务词汇、数据服务、组件能力和盘古接线与共享创作策略存在耦合。缺少清晰迁移边界会使上游改进覆盖内部功能。数据源的字段身份、类型、单位和有序显示规则也需要稳定映射到页面元数据；仅靠模型解释 DataFilterType 会造成重复缩放、绑定错误或丢失人工格式。

## Solution

在同一 Authoring 项目维护一个 Platform 创作 Skill，创建和修改是入口内部的流程分支，配置问答是只读完成方式。先优化 Skill 主文、按需参考、工具选择与分发体积，再逐步补齐必须由程序保证的最新读取、候选校验、提交协调及恢复；不等待外部平台全部建好才改善 Skill。

每条用户指令开始前，可信程序完成手工修改交接，按 pageId 读取最新页面及精确修订，并形成有省略声明的必要摘要与引用。模型理解意图并提出受控请求，工具基于完整可信页面生成候选，可信程序验证后自动提交普通创作草稿；发布继续要求绑定精确候选的人工确认。

数据源映射纳入这条创建/修改流程：Adapter 解码真实源协议和规则，公共领域逻辑生成结果字段契约、查询字段映射与展示建议，应用用例完成组件绑定和候选验证。内部服务适配、业务规则和组件扩展通过稳定接口接入同一项目，部署名可以沿用 define-report。所有正式源码、规格和验收材料留在仓库维护。

## User Stories

1. 作为页面创作者，我希望用一个创作入口完成创建和修改，以便连续表达意图而不选择两个 Skill。
2. 作为页面创作者，我希望“给这页加一个图”修改当前页面，以便不意外另建页面。
3. 作为页面创作者，我希望明确另建时创建新页面，以便保留原页面。
4. 作为页面创作者，我希望一次表达完整页面方案，以便组合数据、文本和受支持组件。
5. 作为页面创作者，我希望 report/dashboard 遵守我的明确选择，以便得到合适的页面形态。
6. 作为页面创作者，我希望普通局部修改保留原布局，以便不引入无关变化。
7. 作为页面创作者，我希望先手工改列宽、再让 AI 改标题时列宽仍被保留，以便两种创作方式连续使用。
8. 作为页面创作者，我希望澄清回复后重新基于最新页面继续，以便等待期间的手工修改不会被覆盖。
9. 作为页面创作者，我希望人工未同步的编辑得到保护，以便 AI 不从旧服务器状态继续。
10. 作为页面创作者，我希望 AI 处理时当前工作台停止人工修改，以便同时只有一种编辑方式生效。
11. 作为页面创作者，我希望取消或失败后看到真实交接状态，以便安全继续人工操作。
12. 作为页面创作者，我希望选中组件后用“这个”询问或修改，以便省去重复描述目标。
13. 作为页面创作者，我希望明确指定另一个组件时文字目标优先，以便选中状态不会误导修改。
14. 作为页面创作者，我希望组件已被删除或目标有歧义时得到澄清，以便不会修改邻近或同名组件。
15. 作为页面创作者，我希望询问“这张图怎么配置”只读取配置，以便不触发数据发现或保存。
16. 作为页面创作者，我希望大页面中暂未展示的组件仍能被准确查找，以便摘要截断不被当作不存在。
17. 作为页面创作者，我希望新增查询和组件共同形成合法候选，以便页面不会留下无有效数据的半成品。
18. 作为页面创作者，我希望独立失败和依赖失败被区分，以便知道哪些操作已应用、失败或跳过。
19. 作为页面创作者，我希望同轮修改中间候选不反复保存，以便一次任务只提交最终选定结果。
20. 作为页面创作者，我希望合法的普通创作结果直接保存，以便不增加通用方案审批轮次。
21. 作为页面创作者，我希望只有明确保存回执才被报告为已保存，以便区分候选生成与页面修订成功。
22. 作为页面创作者，我希望保存回执丢失后查询原操作，以便不重复写入。
23. 作为页面创作者，我希望另一窗口已经修改页面时暂停提交，以便不会静默覆盖新修订。
24. 作为页面创作者，我希望发布确认绑定我看过的精确候选，以便后续修改不会替换确认对象。
25. 作为页面创作者，我希望数据源字段身份稳定，以便标签、查询别名或排列变化不破坏组件绑定。
26. 作为页面创作者，我希望页面中的单位、币种和百分比刻度与真实数据一致，以便显示结果可信。
27. 作为页面创作者，我希望同一字段在不同组件采用不同格式，以便展示偏好不改变原始数值。
28. 作为页面创作者，我希望上游默认格式不覆盖人工设置，以便普通编辑保持现有表达。
29. 作为页面创作者，我希望无法等价映射的规则明确说明缺口，以便不接受看似成功的错误显示。
30. 作为页面使用者，我希望首次显示与刷新、筛选后查询遵守同一数值语义，以便结果不会因执行路径改变。
31. 作为内部集成开发者，我希望用 Adapter 接入真实服务，以便不修改共享 Skill 主流程。
32. 作为内部业务维护者，我希望维护版本化业务规则和组件扩展，以便跟随核心升级而不丢内部能力。
33. 作为内部部署维护者，我希望继续使用 define-report 注册名，以便迁移不要求用户改入口习惯。
34. 作为 Skill 维护者，我希望每种规则只有一个作者，以便修改后生成一致的部署产物。
35. 作为 Skill 维护者，我希望按任务提供少量必要参考，以便避免无效工具调用和冗余上下文。
36. 作为测试维护者，我希望保留原场景并增加未参与改提示词的留出场景，以便判断真实改善和退化。
37. 作为项目负责人，我希望分别看到代码验证、真实模型表现与内网联调结果，以便准确判断交付完成度。
38. 作为迁移维护者，我希望旧页面和内部扩展在升级及回退时有明确兼容范围，以便不会因切换丢字段或双写。

## Implementation Decisions

### 1. 项目范围与交付顺序

- 采用一个 Authoring 项目、一个 Platform 创作 Skill 作者；不另建公司版创作项目或离线映射产品。普通问数的页面构建入口与页面消费职责保持现有独立边界。
- 第一交付切片聚焦入口合并、流程精简、参考投影和评测修正。后续按契约、局部编辑闭环、创建与数据映射、内部迁移推进，每片都有可观察验收结果。
- 复用已有内容工具、生命周期用例、操作结果与构建导出机制；实现路径以合并后的最新共同基线为准，不把目录搬家当作功能实现。
- 本仓实现公共接口、消费端逻辑、可替换适配边界与测试；真实 Java/Relay/盘古/数据服务变更保留提供方交付边界。已有生命周期规格和已关闭任务作为复用基线，不重复实现其完整功能。

### 2. Skill 文档、分发与执行策略

- 主文负责统一入口、当前上下文优先、任务分支、工具职责、澄清/停止条件和真实结果表达。创建与修改分别有流程文档；配置问答直接使用入口的只读规则，不新增解释 Skill 或独立解释流程。
- 布局、错误恢复、最小示例及数据映射操作约定作为按需参考。组件/字段全集、机器索引、全量反例和页面 Schema 留在产品契约、工具及测试层，由同一作者单向生成消费物。
- 第一版预算：主文不超过 200 行，创建/修改流程各不超过 250 行，统一 Platform Skill 分发总计不超过 10,000 行。统计正常格式下的文本行、文件数与字节数，分别记录实际模型输入 token；不压缩排版满足预算。
- 生成器仅清理其负责的过期生成文件；内部作者文件有明确所有权。独立安装后必须引用闭合、版本一致，避免只在源码仓内可用。
- 部署声明参考是已注入还是可按需读取；已提供的参考不重复索取。没有文件读取能力时不指导模型访问本地路径，不用数据发现冒充文档搜索。
- 数据发现只服务新增或变更的数据需求；标题、列宽、布局和配置问答在当前页面上下文及操作能力内完成。
- 初版使用少量固定内容工具，不增加一个模型分类步骤作为动态工具加载前置。工具允许列表与真实注册、能力验证分别处理，文档声明不充当权限控制。

### 3. 每轮最新页面与必要摘要

- 每条用户指令（含澄清回复和文字发布请求）先停止当前工作台新人工修改、收敛未完成输入、确认同步，再按 pageId 读取服务端最新草稿及精确修订；失败保留本地工作，不回退历史 token。
- 真正的新页面由可信程序分配身份并声明空基线；取消、心跳与状态查询是控制消息，不重复创建用户轮次。
- 本轮上下文绑定可信身份、工作区、请求/运行/轮次、页面精确引用和能力版本。凭据不进入模型参数；页面摘要不成为权威文档。
- 必要摘要由程序投影：页面身份与布局、区块/组件稳定 ID/类型/标题/位置、当前目标及任务相关配置、可用操作、版本与省略信息。完整页面、原始查询、业务数据行和预览 JSON 留在程序通道。
- 大页面返回总数、是否还有内容、已省略范围及补读引用。补读绑定本轮同一修订；候选补读明确指向候选。历史对话只保留意图和已确认偏好，不覆盖当前页面事实。
- 内容生成前验证新鲜上下文前置条件；必须由程序保证的最新读取不降级成 Skill 中一句建议。

### 4. 选中组件与配置问答

- 第一期支持顶层单选。界面传递稳定组件标识，程序在本轮最新页面中解析；选择状态与页面内容分开传递，跨页不复用。
- 用户明确指定的目标优先；选择状态解析“这个”等指代。无明确目标且选择缺失、已删除或存在歧义时澄清，不按数组位置或相近标题猜测。
- 询问配置时按需读取目标配置并只读回答；修改时提交精确目标的受控操作。对未知内部组件只在有效契约允许时读取或无损保留，不能删去扩展字段后继续。
- 盘古 Adapter 归一化选择与轮次关联，不另建意图判断主流程。迟到消息按轮次及代次隔离。

### 5. 受控创建、编辑与候选

- 既有数据发现、页面构建规格、内容创建和编辑用例承担底层实现；公开能力形成上下文读取、数据发现、创建候选、编辑候选四种职责。工具名称可兼容迁移，行为和输入边界必须唯一。
- 页面构建规格继续表达取数需求。布局、组件组合及顺序需要独立受控组合输入，不把组件 props 全集或整页 JSON 交给模型生成。
- 编辑以可信完整页面复制并应用受控操作，保留未触及内容；已有页新增组件仍是编辑，不能以旧构建规格重建整页。
- 新查询、结果字段契约、筛选依赖和组件形成可验证依赖组。独立成功操作可组成合法子集；失败依赖跳过，全失败或无变化不新增修订。
- 候选携带根基线、实际影响范围、验证证据、完整性信息及版本。同轮候选继续编辑保留根基线，最终只提交选定候选一次。
- 内容工具不保存或发布；生命周期用例由可信程序调用。模型可见候选摘要与引用，不承担完整页面传输。

### 6. 数据源信息到页面元数据的映射

- 这是统一创作能力的内部模块。外部字段/指标协议、DataFilterType 枚举及有序参数链由源 Adapter 解码；公共领域规则承担归一描述到结果字段契约与展示建议的映射；应用用例建立组件绑定、影响检查和候选校验；最终显示由既有统一运行时实现。
- 归一契约至少包含源系统/版本、稳定逻辑字段身份、真实查询输出列、类型/角色/nullable、单位/币种/刻度、显示建议及其来源、未解决差异。不同聚合/时间语义必须区分，不能使用可变标签或数组序号作为字段身份。
- 创建使用稳定页面字段 ID；编辑先复用当前页经来源关联验证的 ID。显式 queryField 指向真实查询输出列，装配前校验存在性和类型，再建立组件字段绑定。
- 区分数据语义转换与显示缩放。当前百分比格式在数值后附百分号，fraction 0.1234 与 percent 12.34 不能混用；百分点变化单独表达。元/万元、币种和原始符号/0/null 同样保留真实语义。
- 数据转换必须覆盖初次查询、刷新、筛选、召回及适用导出路径。缺少一致通路时返回阻塞，不在 Adapter 仅修改一次预览数据；不把格式化字符串或旧 HTML 塞进数值字段。
- 上游 defaultFormat 是建议，已有组件显式 format 优先；本次用户明确修改可覆盖目标组件设置。普通标题修改不刷新全页字段默认格式。
- 已验证的完整规则链才能映射为目标支持能力；未知枚举、参数、顺序、空值策略、截断或舍入差异明确报告。DataFilterType 不解释为页面 filters。箭头、颜色、进度和复合比较走受控组件能力，不扩张成任意格式脚本。
- 第一切片提供公共契约、替身源 Adapter、基础字段/格式映射，并接通创建和已有页新增数据的候选路径。真实内网解码器及高频规则行为向量由内网调试。独立字段映射函数通过测试不等于这条能力完成。
- 映射结果记录源、规则、目标契约版本及未解决差异。旧规则精确兼容需行为向量证据，Schema 合法或基础映射成功不能标记为旧行为等价。113 项完整支持不作为首批前置。

### 7. 人工交接、提交与恢复

- 当前工作台采用人工/AI 单一编辑者交接；跨窗口依靠页面资产服务原子比较基线。冲突保留双方信息，不自动换最新版重发旧载荷或自动合并。
- Relay 复用现有模型循环与运行记录，持久执行协调记录轮次、基线、候选、取消和未决操作；Java 保持页面修订、发布和写入结果的权威归属。前端仅展示投影，不成为后台运行唯一存储。
- 提交前验证身份、权限、基线、候选、取消状态、能力和完整性；普通合法创作自动提交，无通用方案确认。取消与已发出写入竞争时按服务真实结果恢复，不伪称撤销已提交事务。
- 同一操作关联不可变载荷；回执丢失查询原操作，权威确认未应用且可重试才重发原载荷。未知结果不能由新操作 ID 重做；进程重启或模型预算耗尽仍可恢复未决写入。
- 发布复用精确候选、来源修订和可信人工确认语义；最新页面读取不自动替换被确认候选。
- 稳定错误区分参数修正、缺配置/权限、冲突、取消和未知写入。配置未变不盲重试。运行预算共享模型与程序重试计数，记录真实结果而非模型隐藏推理。

### 8. 内部扩展与迁移

- 系统 Adapter 处理盘古/Relay、页面资产、身份、数据访问与预览协议；业务扩展处理公司词汇、组织和时间语义；组件扩展绑定同版本契约、创建/编辑能力、渲染支持及验收向量。
- 配置选择已实现且兼容的能力及部署注册名；未知能力或冲突注册拒绝。凭据以内部机制注入，不能进入共享主文或版本锁。
- 一个交付清单锁定 Skill、程序、契约、Adapter 与扩展来源。内网不能共用 Git 时仍记录上游提交和本地差异，按变更集迁移而非覆盖整目录。
- 按内部调查逐项承接：define-report 入口、数据发现、构建/编辑、metadata CRUD、业务词汇、选型布局、页面校验、缓存预览、工具可见性、错误阶段、幂等和既有测试。旧 CRUD 转生命周期 Adapter，旧构建规格退出已有页状态管理。
- 核心不含公司名称分支，扩展不重写创作状态机。普通问数与 recall-report 的消费能力不因本次统一创作入口被删除。
- 新旧切换每页只有一个写路径；影子比较只生成无副作用候选。旧文档可读、扩展字段保持和回退读写兼容通过验证后再退役旧入口。

## Testing Decisions

测试以用户可观察行为、公开工具产物、保存事实和分发可用性为准，不断言私有类名或 Markdown 固定措辞。用户已确认以下边界。

| 验收入口 | 复用的先例与验收重点 |
|---|---|
| Skill 真实任务评测 | 既有 14 例、Platform 创作模型用例与内部 H1–H15；观察工具选择、目标命中、回答、有效候选和输入成本 |
| 内容工具公开完整流程 | 既有编辑保持、组件构造、筛选下钻、stdio 与内容集成测试；验证归一描述到字段/绑定/候选，不只单测映射函数 |
| 构建与独立分发 | 既有产品契约导出、Bundle 检查、锁和独立安装；验证统一入口、引用闭合、生成文件所有权及体积 |
| 创作协调与 Adapter 契约 | 既有工作台交接、生命周期/发布端口和确定性替身；故障注入测试最新读取、互斥、精确引用、取消及未知写入恢复 |
| 真实内网接入 | 提供方确认的模型、Relay/盘古、Java 和源服务；观察真实请求/产物/回执，分别标记 blocked 或 verified |

必须通过的行为：

1. 同一入口完成新建、当前页新增组件、局部修改与只读配置问答；普通问数路由保持。
2. 标题/列宽/配置问答不调用数据发现；参考缺失不改用业务工具搜索文档。新增数据需求正常发现。
3. 人工改列宽后 AI 改标题保持列宽；澄清回复前页面变化时获取新基线；最新读取失败不使用旧 token。
4. 选中目标正确命中；文字明确目标覆盖选择；目标删除、跨页、同名歧义按契约处理；未知扩展字段保持。
5. 大页省略声明与补读完整，补读不能跨页/跨修订；模型上下文和摘要不包含完整页面、数据行或凭据。
6. 创建同时组合受支持的数据图表与静态内容；编辑新增查询和组件的依赖组完整闭合；失败不留下悬空绑定。
7. 源字段标签、别名和次序变化不改变逻辑字段 ID；现存绑定复用 ID，真实 queryField 不存在或类型冲突时阻塞候选。
8. fraction/percent/百分点与元/万元保持语义；默认格式和组件覆盖正确；未知规则及组合冲突明确失败；显示缩放不改变计算值。
9. 原始 0/null/负数、舍入边界和末尾零通过对应格式行为向量；涉及数值转换时首次与后续查询一致，否则明确未支持。
10. 候选链仅最终候选提交一次；合法独立成功子集可提交；全失败和无变化不生成修订。
11. 人工/AI 交接、迟到结果、取消和其他窗口冲突不覆盖新工作；提交前拒绝不匹配基线或身份。
12. 写入后回执丢失、重启和重复恢复不重复提交；未知状态保持可恢复，预算耗尽不丢未决操作。
13. 未确认或错误确认对象不能发布；已成功发布的原操作重放不重复发布。
14. 统一 Skill 可独立分发且引用闭合；移除过期投影不删除内部作者；部署工具面与能力清单一致，缺能力无成功兜底。
15. 内部扩展替换不修改共享流程；不兼容版本拒绝；升级/回退不丢字段且无双写。

首批评测先固定同一模型与全工具诊断配置，复测原三个误用场景、三个关键正例和三个未用于改写的新场景，再单独比较生产工具配置。每个可运行场景至少独立重复三次；关键违规（错误保存/发布、未触及内容丢失、泄露完整产物、重复写入）必须为零。记录逐例产物、工具轨迹、真实模型标识、采样参数、版本、token、耗时及 pass/fail/blocked/inconclusive，缺环境或轨迹不能计作成功。全量适用场景无关键退化、外部集成另有实证后才作生产切换。

## Out of Scope

- 独立内网映射 CLI、调试压缩包或第二套创作产品。
- 首批复刻全部 113 个 DataFilterType、任意公式/脚本格式器、未知币种转换与未有通路的数值转换。
- 新建通用 Agent Runner、多 Agent 页面协作、通用向量检索或插件市场。
- 首批多选/任意嵌套选择、自动冲突合并、对同一页面新旧双写或批量重写历史修订。
- 用本仓替身替代真实 Java/Relay/盘古服务的生产保证。
- 因统一 Platform Skill 而改造普通问数、recall-report、DataAgent 或全部渲染引擎架构。
