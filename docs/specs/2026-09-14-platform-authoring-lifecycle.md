# Spec：Platform 创作生命周期与盘古助手独立集成

日期：2026-09-14。来源：本轮完整创作生命周期 grill 及最终结构、架构裁决。状态：规格已综合，用户已确认验证边界；作为 GitHub 规格事项发布，后续拆分实施任务。本规格描述目标能力，不代表当前代码或外部服务已经支持。

## Problem Statement

页面创作者需要在 Platform 内用自然语言生成页面，接着通过画布或对话修改同一份创作草稿，保留历史、预览并发布。当前能力分散在工作台、Python 创作工具及外部页面资产服务中，尚未形成一致的修订、恢复和发布流程。语言改版缺少基于完整现有文档的受控编辑能力，容易丢失手工设置；保存失败后的恢复、历史读取及发布候选确认也未形成完整交付。

页面模板需要提取可替换维度取值，页面实例需要确定本次取值并正确渲染。重复建立 globalParams、dimensionValues 与 params 会使默认值、查询绑定和页内筛选产生多个来源。发布前，创作者必须能看懂并确认提取结果。

盘古助手侧边栏需要独立开发。集成逻辑与工作台、部署环境配置混在一起，会使并行开发相互影响，也会使用户同步上游代码后反复手工补改集成代码。

## Solution

提供从进入 Platform 创作页面开始的完整流程：语言生成合法页面 → 保存首个创作草稿 → 手工或语言修改并保存页面修订 → 精确修订预览 → 准备发布并提取页面参数 → 用户纠正、预览与确认 → 发布不可变页面模板 → 执行得到页面实例并由统一运行时呈现。

手工和语言编辑共用一份逻辑创作草稿。管理服务是页面修订与发布状态的权威来源；浏览器保护尚未同步的工作。内容编辑与生命周期操作分别通过独立 MCP 提供，语言改版最终向前端交付可读取的已保存草稿引用。

先完成本版必要的架构拆分与共享接口，再并行建设各模块。盘古助手集成具有独立开发和验证入口，工作台通过稳定接口消费对话结果；上游源码、集成适配和部署配置分离。

本仓实现核心能力与消费端适配；外部 Java、Relay 仅交付修改方案、所需契约和联调要求。DataAgent 与普通问数不在本规格实施范围。外部能力未就绪时，确定性替身支持本仓开发，真实接通单独验收。

## User Stories

1. 作为页面创作者，我希望进入创作页面后直接描述页面需求，以便从业务意图开始创建页面。
2. 作为页面创作者，我希望首次合法页面生成后才保存首个创作草稿，以便目录中不会留下生成前的空白占位资产。
3. 作为页面创作者，我希望通过自然语言创建当前目录内的全部 17 类组件，以便按表达需要组合页面。
4. 作为页面创作者，我希望必需数据或配置缺失时得到明确结果，以便不会把无法运行的组件当作创建成功。
5. 作为页面创作者，我希望对同一创作草稿交替使用手工和语言修改，以便保持连贯的创作过程。
6. 作为页面创作者，我希望未提及的组件属性、查询与手工设置保持不变，以便局部改版不会重做整页。
7. 作为页面创作者，我希望手工修改已有组件的标题、宽度、位置和受支持的类型，以便快速调整已有页面。
8. 作为页面创作者，我希望修改白名单内的组件展示属性，以便调整指标卡、图表和表格的表达。
9. 作为页面创作者，我希望用语言增加或删除组件、调整维度筛选及绑定、配置表格链接下钻，以便完成结构和交互调整。
10. 作为页面创作者，我希望一轮语言修改中相互独立的成功部分能够保存，以便个别失败不丢掉可用成果。
11. 作为页面创作者，我希望看到哪些修改已应用、失败或因依赖被跳过，以便继续纠正剩余问题。
12. 作为页面创作者，我希望非法引用和半成品不会入库，以便保存的页面修订始终可校验。
13. 作为页面创作者，我希望每个完整生效的手工操作自动保存，以便不用反复点击保存。
14. 作为页面创作者，我希望输入中间态和没有实际变化的操作不产生修订，以便历史能表达有意义的修改。
15. 作为页面创作者，我希望网络暂时失败时浏览器持久化工作并稍后重试，以便不丢失编辑成果。
16. 作为页面创作者，我希望能区分“服务端已保存”“仅保存在浏览器”和“未能保护”，以便准确理解当前状态。
17. 作为页面创作者，我希望重新打开页面后恢复当前用户和工作区的待同步工作，以便继续未完成的编辑。
18. 作为页面创作者，我希望重试不会重复创建修订、迟到回执不会覆盖较新编辑，以便历史和画布状态保持一致。
19. 作为页面创作者，我希望出现并发冲突时保留本地内容并暂停同步，以便不会静默覆盖其他窗口的更新。
20. 作为页面创作者，我希望撤销上一步或恢复历史版本后生成新修订，以便保留完整历史。
21. 作为页面创作者，我希望语言修改期间当前画布的手工编辑受到协调，以便两种修改不会互相覆盖。
22. 作为页面创作者，我希望语言修改已保存后，前端按精确引用读取页面，以便预览内容和实际保存内容一致。
23. 作为页面创作者，我希望失败、取消、等待确认或仅文本答复时已有页面仍保留，以便本轮未产页不会清空工作。
24. 作为页面创作者，我希望预览固定的页面修订，以便后续保存不会改变正在确认的内容。
25. 作为页面创作者，我希望发布前查看公共维度取值的提取结果及其影响的数据源，以便确认模板的可替换范围。
26. 作为页面创作者，我希望纠正提取候选并再次预览，以便在发布前修正自动提取的偏差。
27. 作为页面创作者，我希望自行确认是否保留具体维度取值，以便选择带默认取值的模板或不带具体取值的定义。
28. 作为页面创作者，我希望通过界面或自然语言发起保存、准备发布和确认发布，以便两种入口遵守同一生命周期规则。
29. 作为页面创作者，我希望只有我确认过的候选和对应修订能够发布，以便预览与发布不发生错位。
30. 作为页面创作者，我希望发布后继续修改创作草稿不会改变已发布模板，以便运行页面保持稳定。
31. 作为页面创作者，我希望页面说明准确表达用途、支持的指标和维度，以便后续理解和选择页面。
32. 作为页面使用者，我希望打开页面时参数、查询条件和筛选显示一致，以便不会看到与实际数据不同的条件。
33. 作为页面使用者，我希望入口参数只在初次加载生效，以便之后的页内筛选不会被旧参数反复覆盖。
34. 作为页面使用者，我希望有效的历史筛选能用于下次初始化，并在越权时采用允许范围，以便页面能够在当前权限下打开。
35. 作为页面使用者，我希望部分数据源失败时仍能看到成功部分，以便单个查询失败不会使整页不可用。
36. 作为盘古集成开发者，我希望独立运行和验证对话模块，以便不必等待整个创作生命周期或外部服务完成。
37. 作为创作模块开发者，我希望通过稳定接口和替身接入对话，以便与盘古集成并行开发。
38. 作为部署维护者，我希望同步上游代码后仍能通过独立适配和保留的配置完成集成，以便不再手工补改工作台或上游源码。
39. 作为模块开发者，我希望架构前置明确共享接口和修改所有权，以便并行任务不反复修改同一片代码。
40. 作为项目负责人，我希望本仓验证和真实外部联调分别记录，以便准确判断已完成能力与剩余依赖。

## Implementation Decisions

### 1. 范围与权威来源

- 只覆盖进入 Platform 创作页面之后的创建、改版、保存、历史、预览、发布和执行接入。普通问数的临时页面态、沉淀与分析会话策略不因本规格自动改变。
- 外部 Java 管理服务拥有页面资产、不可变修订、历史、冲突裁决、发布候选、参数提取与发布。Platform 和 Relay 都可发起保存，但不各自维护第二套权威历史。
- 本仓不实现外部 Java/Relay 服务。需要的服务变更形成可评审设计、接口差异、契约样例和提供方验收清单；不得以本仓新增后端绕过边界。
- 页面文档、外部 metadata 标识、页面修订引用/序号、操作关联、发布候选与发布状态分别表达。ID 仅定位对象，不解析其字面值推断顺序。

### 2. 架构前置与模块所有权

| 模块 | 责任与公开边界 | 并行前提 |
|---|---|---|
| C0 共享契约与架构前置 | 页面协议演进、精确修订与操作结果契约、共享验收样例；工作台对话接入、同步协调和配置注入的必要解耦 | 优先完成本版所需接口与可运行接入边界，并指定共享修改所有权 |
| C1 内容编辑 MCP | Python 创建、局部修改、校验与产物生成；不保存或发布 | 消费 C0 契约，不修改共享契约生成物 |
| C5 生命周期 MCP | 读取、保存、历史、发布候选与确认发布的管理服务调用；不编辑页面内容或实现提取算法 | 消费 C0 契约，外部调用可替换为确定性端口 |
| C2 Platform 创作与生命周期 | 工作副本、编辑协调、自动保存、恢复、历史、精确预览及发布界面；读取已保存草稿 | 对话与同步责任已拆出，独占修改范围明确 |
| C6 盘古助手集成 | 独立对话模块、实例适配、事件归一化、配置注入与独立验证入口 | 工作台仅依赖稳定接口；真实接线依赖提供方资料 |
| C3 执行与统一运行时接入 | 处理执行结果、实际参数/筛选初值、内嵌初始行与错误状态；保持后续交互 | 消费冻结后的页面与执行结果契约 |
| C4 外部服务方案 | Java/Relay 职责、接口差异、身份与产物传递、幂等与联调要求 | 可与架构前置同步完善，不改外部代码 |

必要的架构调整优先完成，再按真实依赖并行实现功能；不得把共享拆分分别藏在多个任务中重复实施。架构前置须产出可验证的独立接入边界，不以建立通用框架为目标。模块表是所有权划分，后续 tickets 仍应按可独立验证的完整行为切片拆分。

### 3. 页面结构与模板语义

- 顶层继续使用 schemaVersion、id、meta、params、dataSources、filters、sections 等既有结构；layoutForm 简化为 layout，值仍为 report 或 dashboard。根层 layout 表达布局形态，组件 layout 表达组件占位。
- filters 保持页级共享声明，不移入单个数据源或内容分区；声明层级不限定筛选控件的实际呈现位置。
- 不新增 globalParams 或 dimensionValues 根字段。维度取值是业务概念，复用 params 表达模板初始化输入。
- 现有 params 仅支持标量。本版补齐受控维度多值、查询目标绑定及筛选初始化绑定；不建设表达式或脚本系统。绑定须显式，不凭同名匹配。
- params 确定本次实例化或打开时的输入；filters 承担初始化后的可变筛选。共享条件只声明一份默认来源，受参数初始化的筛选引用该来源。页内交互不得被原始参数再次覆盖。
- 页面模板从精确创作草稿修订提取而来，保留可替换维度；页面实例具有已确定查询条件或没有可替换维度，仍可进行已声明的页内筛选。运行实例不自动入库。
- 元数据说明沿用页面 meta.description 语义，准确描述作用、支持的指标和维度；外部服务若使用 desc，由适配契约映射，不在页面协议中再造重复字段。
- 当前代码为页面协议 6.0。字段改名不可作为无说明的次版本替换；C0 必须依据 ADR-0051 冻结主版本迁移或明确兼容过渡、旧文档读取规则、写出规则及跨端升级顺序。最终版本号和绑定字段形状是架构前置交付物，未在本规格虚构为现有能力。

### 4. 内容编辑与语言编排

- LLM 将用户意图转为受控修改请求，Python 确定性应用操作、校验并生成结果，不由 Python 再次调用模型。
- 编辑输入必须能定位精确基线并由可信程序读取完整文档。未触及的手工设置、内容、绑定与查询保持不变。
- 内容 MCP 与生命周期 MCP 为两个独立入口；第一版不另建 CLI。Relay 依次调用内容能力和生命周期能力完成语言创建或改版。
- 完整页面文档及数据行通过可信程序通道传递，模型只消费必要摘要或引用；不得通过模型文本转抄完整产物。向前端交付可读取的已保存草稿引用，包含定位精确修订所需的信息，具体 DTO 与提供方对齐。
- 语言创建覆盖当前 17 类组件：reportHeader、metricCard、barChart、lineChart、pieChart、table、mapChart、gauge、tabContainer、compositeCard、rankingCard、rankingDetailCard、keyValuePanel、categoryBreakdown、fieldText、text、aiSummary。复用现有构造器，补齐缺失路径；容器子树、数据形状及必要配置仍必须满足协议。
- aiSummary 仅用于明确要求运行时流式生成且配置完备的场景；普通摘要继续使用 text。不得用虚构端点或空配置宣称创建完成。
- 语言操作包括组件创建/删除、标题/宽度/移动、符合数据形状的类型切换、白名单属性、维度筛选与绑定、表格链接下钻。结构和绑定走专用操作，不开放任意 JSON 路径。
- 手工添加组件后置。手工入口继续覆盖已有组件编辑，元数据 JSON 查看保持只读。
- 白名单基线：通用标题和布局操作；reportHeader 的标题/副标题/徽标/标签；metricCard 已有行说明、单位和趋势箭头；barChart 已有系列标签与横向/堆叠/圆角/标签开关；lineChart 已有系列标签与平滑/面积渐变/点标签/纵轴开关；pieChart 环形和引导线；table 标题/副标题/适配及已有列标题/宽度/固定/对齐。均以对应组件 Schema 实际支持为限，契约交付时列出精确字段，未列属性不自动放开。
- 单轮允许部分成功。单个完整业务操作失败则回滚该操作，依赖其结果的操作跳过，独立操作继续。成功子集整体通过页面校验后保存一次；全失败或无实际变化不产生修订。返回已应用、失败、跳过摘要，保存失败不得宣称已持久化。

### 5. 自动保存、并发与恢复

- 首次合法 metadata 生成后保存首个创作草稿；不在打开空白创作页时创建资产。
- 每个完整生效的手工操作形成一次保存：文本提交或失焦、拖拽结束、选项应用等；不保存按键和拖拽中间态，无实质变化不创建修订。
- 自动保存协调独立封装。采用浏览器持久化工作副本和有序待同步队列，优先在操作生效后本地保护，再串行同步；恢复记录按用户、工作区及页面隔离，不持久化运行凭据。
- 串行保存使用上次确认的服务端修订作为下次基线。一个逻辑操作复用稳定幂等标识；请求结果不确定时通过提供方去重或结果查询确认，不换标识盲目再建修订。
- 当前客户端虽然接收幂等标识，但尚未将其发给管理服务；本版需要补齐消费及外部方案。不能据此推断外部服务不支持幂等，也不能以客户端 UUID 代替服务端保证。
- 网络失败允许继续本地手工编辑并自动重试；身份失效、校验失败和基线冲突暂停对应同步，不无限重试。浏览器持久化本身失败须明确显示保护失败。
- 回执只确认对应队列项，不能覆盖较新的本地工作副本。未同步完成时，语言修改和发布等待同步完成；语言修改期间禁用当前工作台手工编辑。
- 管理服务对 Platform 和 Relay 共用基线冲突检查；其他窗口更新导致冲突时拒绝覆盖、不自动合并，保留本地内容。
- 撤销和历史恢复形成新操作、新修订，不删除或倒退历史。已经发出的保存须确认结果，不能因用户撤销就遗忘可能成功的提交。

### 6. 发布候选与人工确认

- 采用准备发布、确认后提交两阶段流程。管理服务从精确草稿修订提取 params 与绑定，并负责修正后的校验及最终发布裁决。
- 第一版只提取 DQE 维度等值/多值条件，允许仅部分数据源共享。同维度不同取值的共享提取暂不支持，不自动合并，也不暗中开放手工合并该场景；时间与金额范围提取后置。
- Platform 显示候选、与草稿的差异、作用数据源及预览。用户可修正候选、确认是否保留具体维度取值。保存前的取值选择与发布时的二次确认必须保留在设计中；不保留具体值时应明确参数缺值及初始化行为，不伪装为已有有效取值。
- 生命周期 MCP 代理候选读取、修正和发布操作；Relay 可用自然语言发起，但不能跳过人工确认。发布确认必须关联当前候选及其来源修订，不把模糊的对话肯定当作任意候选的发布授权。
- 若候选评审期间要求修改页面内容，则返回创作草稿修改、保存并重新准备候选。候选失效、基线变化或确认过期时不得发布旧结果；沿用既有发布租约和精确修订确认约束，外部映射在契约中说明。
- 发布模板不可变且可追溯来源草稿修订。后续改版回到草稿，不维护第二份独立可编辑模板库，不改变正在运行的发布版本。

### 7. 执行、初始化与筛选

- IOC 初次加载按外部 metadata 标识调用待建设的执行接口，由服务端确定实际取值、按 dataSources 查数并返回可渲染页面内容及必要的执行状态。Platform 预览须能消费对应候选/修订的执行结果。
- 初始取值优先级：显式入口条件、有效的用户历史筛选、页面默认、授权范围回退。权限始终为约束，不是可被优先级覆盖的普通默认值。
- 历史筛选只有全部处于当前权限允许范围时才复用；否则按页面支持的维度与权限维度的交集生成允许范围。越权输入静默回退，实际查询与显示值一致；无任何可访问范围绝不能转成不受限查询。
- 未暴露为页面参数或筛选器的权限限制仍由数据服务强制执行，不能因页面不支持该维度而去掉安全约束。
- URL 只读取一次，不监听后续变化。初始化完成后的筛选和下钻由前端通过既有受控数据网关查数；不反复调用模板初始化来覆盖本次交互。每次筛选更新对应用户、工作区及 metadata 的最后筛选记录，具体提供方键与请求形式在外部契约冻结。
- 内嵌初始行、实际查询条件、筛选初值和修订必须一致；不得采用旧默认条件的数据冒充本次参数结果。统一运行时沿用既有条件匹配及字段映射机制。
- 部分数据源失败保留成功结果，沿用已有错误隔离；新增工作是将执行接口的失败结果接入既有错误数据快照。缺少 rows 不等于已经表达失败。

### 8. 盘古助手独立集成与更新方式

- 只替换现有侧边栏对话区域。全部对话输入、答复、澄清、确认、进度、错误与历史由盘古呈现；全局导航、文档工具栏、画布和属性面板保持工作台职责。创作发布界面的候选与预览不另造一套对话轨道。
- 独立模块封装盘古实例 API、专有事件和配置。工作台仅提供必要页面/修订上下文并消费归一化结果；盘古模块不直接修改工作副本，不承载编辑算法、保存或参数提取规则。
- 已保存草稿引用交给创作流程鉴权读取、校验并检查基线和迟到结果后，才更新画布。新轮失败、取消、等待或仅文本时保留旧页；本地取消仅代表停止接收，不能未经验证宣称外部执行已经终止。
- 独立开发入口可注入受控上下文、对话事件和服务替身。盘古不可用时核心创作模块仍可开发验证；真实对话与程序产物通道仍须联调验收。
- 上游源码、集成适配及部署配置分离。兼容接口下同步上游更新后，无需手工修改上游源码或工作台即可保留/恢复集成；交付可复用更新步骤并实际演练一次。上游公开接口破坏性变化由适配模块集中升级，不承诺任意更新都无需适配。
- 保持静态 SPA 与运行配置注入，不新增 Node 后端，不自动引入微前端或通用插件协议。
- 模块形态、具体目录/加载机制、上游同步对象、盘古身份与会话、取消/历史和产物回调细节在该模块实施时 grill。缺少可靠实时事件时允许整体处理中，不伪造细粒度进度。聊天历史不等同于创作草稿历史或分析会话检查点。

## Testing Decisions

### 验证入口

以公开行为和最终可观察结果为准，不断言私有调用顺序、内部类结构或组件实现细节。优先使用现有最高层接口，跨浏览器与 Python 的独立交付面保留必要的独立验证，不为追求单一入口把所有能力绑到不稳定的真实外部服务。

| 入口 | 主要覆盖 | 既有先例 |
|---|---|---|
| Platform 工作台完整流程 | 创建后保存、手工/语言交接、精确读取、自动保存、恢复、历史、发布确认与打开 | 现有页面编辑、管理状态、页面资产客户端及工作台文档编辑测试；补完整浏览器行为用例 |
| 内容 MCP 公开工具 | 17 类创建、基于既有文档局部编辑、保留未修改内容、部分成功、无持久化副作用 | Python compose_page、build_page、组件构造、页面校验、stdio 及共享契约测试 |
| 生命周期 MCP 公开工具 | 精确修订读取、幂等保存、冲突、候选修正与确认、不执行内容算法 | 既有 Java 页面资产端口及 HTTP 适配测试，新增独立工具契约用例 |
| 页面协议与统一运行时/Embed 公共入口 | 版本迁移、参数多值和绑定、一次初始化、筛选生效、内嵌初始行及部分错误 | 现有 page-param/version/filter-invariants、runtime 参数/DQE 编排/迟到查询、Embed 浏览器测试 |
| 独立盘古模块与工作台接入 | 上下文/结果交接、失败保留旧页、取消和迟到隔离、独立运行、更新后配置与集成仍有效 | 既有工作台 analysis-page-state 测试；新增对话适配和独立入口验收；AI 总结的 pangu-sse 测试不代表助手已接通 |

### 必须覆盖的验收场景

1. 空白创作页不建资产；首次合法文档保存后获得精确引用并读取同一修订，失败不冒充成功。
2. 先手工调整组件，再语言修改其他组件，未触及内容保持；旧修订或已取消轮次的结果不得替换当前工作。
3. 17 类组件逐类满足必需输入；不支持的属性、非法引用和缺失配置明确失败；容器结构遵守限制。
4. 一批操作包含成功、独立失败和依赖失败时，仅保存合法成功子集一次；全失败和无变化不新增修订。
5. 连续手工操作遇到延迟、网络失败、重开、重复回执及服务端已提交但回执丢失，最终顺序正确、无重复修订、不覆盖新本地内容。
6. 身份变化、浏览器存储失败或并发冲突时显示真实状态、隔离用户数据并保留可恢复内容；不能无限重试永久错误。
7. 撤销与历史恢复产生新修订；不丢失已发出但尚未确认的保存结果。
8. 参数提取只影响目标数据源；候选修正后重新校验；未确认、确认旧候选、内容基线变化或租约失效均不能发布。
9. params 初始化 filters 后，页内操作使用当前筛选，后续 URL 变化和原始 params 不覆盖它；没有交互要求的参数不自动生成控件。
10. 历史条件完全有权则复用，否则回退；显式越权及空权限范围不产生越权或不受限请求，实际数据与界面条件一致。
11. 初始结果与本次条件匹配时正确采用内嵌初始行；部分数据源错误隔离且错误可见，后续查询与字段映射继续工作。
12. 新版布局字段输出及旧版文档读取符合冻结后的兼容策略，report/dashboard 行为保持；Python、浏览器校验与共享契约一致。
13. 盘古模块独立启动，工作台能用替身完成创作交接；真实失败或无产物不会清空画布；上游兼容更新后无需手工补改源码即可通过集成验证。

### 外部依赖与证据

核心确定性验证使用受控服务替身，覆盖失败与时序，不依赖模型自由输出。Java 持久化、权限、提取、幂等和发布的真实行为由提供方兑现后执行同一套外部契约验收；Relay 与盘古验证真实身份、工具路由、程序产物交付、确认和取消语义。结果分别标记本仓通过、提供方已确认、真实联调通过或待完成，不以替身通过关闭外部依赖。

本规格阶段不修改实现、不执行功能测试；实施时按改动风险选择必要验证，现有行为已有覆盖的部分复用回归，不重建同义测试。

## Out of Scope

- DataAgent 实现、普通问数入口及报告召回实现；为未来调用保留可理解的执行契约不等于本版建设它们。
- 外部 Java 和 Relay 服务的代码修改、替代后端及新的 Node 服务。
- 手工添加组件入口、手工查询编辑器、可直接编辑原始 JSON 的入口。
- 当前目录之外的新组件、任意属性路径编辑、通用表达式或脚本参数引擎。
- 同维度不同取值的共享提取、时间和金额范围参数提取。
- 查询分页下的交互排序和表头筛选等尚未支持能力；不因“表格属性修改”隐式解除限制。
- 第二套独立可编辑模板库、运行页面实例自动入库、跨窗口自动合并、把不合法操作保存为正式页面修订。
- URL 动态监听、运行筛选反向改写已发布模板、另造页面错误隔离体系。
- 第一版 CLI、通用插件平台、缺乏可靠事件时的实时分步进度，以及无事实依据的盘古恢复能力承诺。
