# DQE 明细支持受控语义 HTML，样式仍由前端拥有

部分 DQE 归因结果已经完成多段文案组合，并需要按业务方向呈现正负或中性视觉状态。如果继续返回对象数组，前端必须重新组合后端已经确定的文案；如果直接把任意 HTML 交给浏览器，又会引入脚本注入、内联样式和页面协议失控。数据层只应表达内容结构和业务方向，不应决定红色、绿色、字号或间距。

## 决策

**新增语义 HTML 明细字段。** 结果字段契约使用 `type: "semanticHtml"`、`role: "detail"` 表示 DQE 返回的一段受控 HTML 字符串。该能力与 ADR-0026 的 `recordList/detail` 并存：前者适用于 DQE 已完成内容组合的场景，后者适用于前端仍需按项字段组合视图的场景。

**DQE 返回语义类，不返回视觉样式。** 允许的结构类为 `detail-title`、`detail-value`、`detail-description`、`detail-meta`；允许的方向类为 `tone-positive`、`tone-negative`、`tone-neutral`。类名表达内容角色和业务方向，具体颜色及其他 CSS 只存在于前端消费者。禁止颜色名类、内联 `style`、脚本、事件属性和链接。

**数据网关保持 HTML 不透明。** `normalizeQueryRows` 只验证值为字符串且不超过 64000 字符，再按 `queryField` 映射为稳定页面字段 id。它不解析标签、类名或样式，也不修改 DQE 文案。

**安全解析和渲染收口在显式消费者 Module。** `rankingDetailCard` 通过 `props.semanticDescriptionField` 明示消费，并把结果直接放在与普通 `descriptionField` 相同的说明位置，不生成列表、折叠入口或明细计数。其内部解析 Interface 只接受 `div`、`span`、`strong`、`p`、`br`，只接受 `class` 属性和上述类名，并限制节点数与嵌套深度。未知标签、列表标签、属性、类名或错误闭合全部失败关闭。解析结果由 Svelte 节点分支渲染，原始字符串永不进入 `{@html}`。

**语义 HTML 不改变普通字段的格式归属。** ADR-0013 对标量字段的 `format` 归属仍然有效。语义 HTML 是显式的富内容明细类型，不参与标量格式绑定；其文本由 DQE 给出，视觉映射由前端消费者拥有。页面元数据仍不允许自定义 CSS 或脚本。

空字符串表示没有可展示明细；`null` 是否允许继续由字段 `nullable` 决定。普通字段绑定、表格、图表和 AI 总结不得消费该 `detail` 字段。

## Consequences

- DQE 可以拥有归因文案的组合结果，同时不知道红绿等具体视觉设计。
- 数据网关 Interface 不因 HTML 标签或类名扩张，复杂度集中在一个可测试的安全渲染 Module。
- 类名集合成为 DQE 与前端的受治理语义契约；新增类名必须同步扩展解析白名单、样式和测试。
- HTML 文本中的金额格式由 DQE 内容负责，不再适用组件标量 `format`；需要前端重新计算或多视图复用时，应继续选择 `recordList/detail`。

## Considered Options

- **直接使用 Svelte `{@html}`。** 无法阻止脚本、事件属性、危险链接和样式逃逸，不采用。
- **允许任意类名但只禁脚本。** 会让 DQE 暗中依赖页面 CSS，并使视觉契约不可枚举，不采用。
- **只返回对象数组，由前端重新拼文案。** 对需要多个富文本片段和后端已定稿文案的场景会复制组合逻辑；保留为另一种受支持能力，但不强制本场景使用。
- **返回颜色或内联 CSS。** 数据层将感知具体视觉样式，违反职责边界，不采用。
