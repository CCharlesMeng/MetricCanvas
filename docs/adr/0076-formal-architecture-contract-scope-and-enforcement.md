# 以概念、关系和约束形式化架构，并对照代码与交付事实

#95 的旧链路隔离讨论要求新代码和交付范围可控。用户进一步确认以本体论（概念设计）形式化表达架构：明确概念、关系、公理与操作语义，设计时检查概念是否自洽，实现时检查代码是否符合设计。模型规范与实际代码/构建事实分别维护并显式对照，不能从手工声明直接推断产物隔离。

第一版覆盖 #95 的架构主干：创作期与渲染期、页面/页面修订/临时页面态、工作台/搭建画布/渲染引擎、Python/Skill/Relay、外部页面资产与 DQE，以及交付物。纳入范围的未归属新模块、禁止的传递依赖和旧代码进入目标交付物时，应使 CI 检查失败，并报告规则、实际对象与依赖路径。先提供声明、校验和架构图，不生成业务代码。

迁移开发检查对新增、扩大和重新出现的违规立即阻断；既存违规逐条登记退出条件和对应执行票。目标交付门禁全量严格，旧代码进入目标产物不接受迁移豁免。此规则与 ADR-0074 的历史基线隔离配合，不把当前尚未完成的静态化描述为已经通过。

概念、表示与实现不混为一个对象：页面是领域概念，页面元数据文档是表示，代码模块实现相关能力，物理包组织交付。人工页面搭建成功保存也会产生页面修订，因此“只有显式沉淀才允许保存任何修订”不成立；显式沉淀约束的是临时页面态进入资产的路径。模型规则须明确作用对象和执行范围。

具体模型草案见 [`architecture-formal-model.md`](../plan/architecture-formal-model.md)。尚未决定由模型统一生成词汇表；`CONTEXT.md` 继续作为当前领域术语真源。机器格式/工具、形式约束的编辑来源及行为验证深度继续 grill，本 ADR 不提前选定 OWL、SHACL 或自有表达语言，也不把接口测试称为形式证明。架构校验器与 CI 接线尚未实现。
