# 页面 Schema v3 一次性删除旧结构化查询

看板页面协议升级为 `schemaVersion: "3.0"`，不再兼容 1.0/2.0。仓库内受治理页面一次性迁移后，页面类型、JSON Schema、校验器、统一运行时、数据网关、页面搭建工作台和 MCP 都删除旧结构化查询及指标目录链路。

v3 保留两类页面数据源：

- `inline` 页面数据源继续承载随页面固化的静态数据行；
- `query` 页面数据源完整声明结果字段契约并内嵌查询定义，当前只实现已经确认外部协议的 DQE。

DQE 是当前动态查询执行场景，不是平台唯一的数据形态。保留 `inline` 不属于旧模型兼容。

## 页面契约

- 字段角色由 `dimension | metric` 改为 `dimension | measure`；
- `inline` 与 `query` 都显式声明完整结果字段契约；
- DQE `query` 字段通过 `queryField` 显式映射外部响应字段；
- 页面筛选器通过 `filterBindings` 显式映射到 DQE 维度或时间语义位置；
- 页面字段 id、DQE 字段名和筛选目标永不隐式同名匹配；
- 展示格式仍以组件字段绑定为最终决定，结果字段契约只提供可覆盖的 `defaultFormat`。

## 删除范围

- `StructuredQuery.metrics`、`dimensions`、`aggregation`、`granularity`、旧排序和时间窗口；
- `CatalogSnapshot`、指标/维度目录和 `catalog/snapshot.json`；
- `fieldOverrides` 与页面字段旧 `format`；
- `METRIC_GAP`、指标候选、指标状态和指标履约流程；
- `search_catalog` 及相关 MCP 工具；
- 1.0/2.0 页面运行时读取和长期迁移器。

Schema 元数据改为创作期**数据上下文快照**的一部分，描述执行环境、Schema、对象、字段、关系、权限、执行约束和已验证查询。它不包含业务数据行，不进入看板页面，也不成为统一运行时依赖。

## 取代关系

本 ADR：

- 完成 ADR-0014 中“查询取代预定义指标”的迁移；
- 采用 ADR-0016 的页面内嵌查询定义；
- 取代 ADR-0011 的目录推导字段契约；
- 取代 ADR-0012 的指标履约流程；
- 修订 ADR-0008 中只针对旧结构化查询的页面数据源描述；
- 保留 ADR-0013 中“最终展示格式属于组件字段绑定”的原则；
- 不改变 ADR-0015 对数据源依赖继续挂起的决定。

历史 ADR 保留原文，用本 ADR 判断当前有效模型。

## Consequences

- 页面字段契约自包含，统一运行时不再加载目录；
- 静态页面继续零外部依赖运行；
- DQE 动态页面可以在请求前完成输出覆盖、字段映射和筛选绑定校验；
- 页面搭建从“检索指标目录”改为“检索数据上下文或选择 inline”；
- 数据上下文不足返回 `DATA_CONTEXT_ERROR`，不创建指标缺口；
- 仓库内所有页面、示例、模板和测试必须一次性升级；
- v3 是破坏性升级，外部 v1/v2 页面必须在接入前离线转换，运行时不会自动接受；
- SQL 只保留语言扩展接缝，在执行端点和请求协议确认前不提供虚构实现。

## Considered Options

- v2/v3 并行：降低短期迁移风险，但会长期维护两套生成、校验和执行模型，不采用。
- 在数据网关把旧结构化查询转换为 DQE：只是隐藏旧指标模型，不能删除目录依赖，不采用。
- 把所有页面改为 DQE：会错误删除正式的静态数据场景，不采用。
- v3 同时保留 `inline` 并只为当前已确认协议实现 DQE `query`：边界清晰且可完整校验，因此采用。
