# 看板形态的满幅布局、铺底层与安全区通道

IOC 作战地图的概览页要求一张地图铺满整个分区、指标卡与表格悬浮其上,而整个页面占满门户给出的全部宽度。此前的页面协议只有一种页面外框(定宽居中的报表)和一种分区内定位(12 列自动流),这两条都表达不了它。

**三个主题写在同一条 ADR 里,因为它们是同一条决策链:** 页面要能满幅(`layoutForm`)→ 满幅之后组件要能铺底(`layout.layer: "backdrop"`)→ 铺底之后被压住的组件要知道自己该画在哪(安全区通道)。拆成三条之后,单读中间一条的人不知道前因,也看不出为什么安全区不能由页面声明。

## 决策

**页面布局形态 `layoutForm` 是页面外框几何与画布外观的唯一真源。** 顶层可选字段,封闭两档:`report`(缺省,定宽居中的报表外框、浅色画布、分区自带外壳)与 `dashboard`(满宽看板外框、中性画布、缺省容器把外壳让给画布、由组件单元格自己成为模块卡)。看板与报表因此**不是两类资产,是同一个聚合根的两种形态**——同一个 `schemaVersion`、同一套组件目录、同一个校验器、同一个运行时。

外框几何依赖宿主:**声明 `dashboard` 的页面要求宿主交出全部宽度。** `apps/canvas` 已实现(正式路由按形态切换页面外框);门户等嵌入方按[宿主契约](../host-contract.md)实现,给定宽容器会让看板页在里面被裁掉。形态必须来自这个显式声明:不得按页面 id(ADR-0021)或组件组合(ADR-0038)推断。

**叠放层 `layout.layer: "backdrop"` 是分区内的层次声明。** 声明它的组件铺满整个分区并置于同分区其余组件之下,其余组件仍按 12 列网格自动流排布。**页面不写坐标、宽高或 z-index**,叠放只有「铺满分区的一层」与「普通流」两种位置;分区高度由叠在上面的组件决定,统一运行时另给高度下限。窄屏退化为普通流,按组件数组顺序上下排列。

**安全区经运行时通道下发,不进页面 schema。** 铺底组件需要知道自己有多少地方没被压住:地图的主体不能画在指标卡底下。这个未遮挡矩形由 `RuntimeSection` 计算——它是唯一同时知道铺底组件与所有覆盖单元格实际 rect 的层——再经 CSS 自定义属性交给铺底组件;`MapChart` 读它喂 ECharts 的 `layoutCenter` / `layoutSize`,读不到就退回全容器行为。

**明确否掉「在页面 schema 里声明安全区」。** 那等于把布局结果写进页面元数据:AI 生成时要算像素,视口一变就废,而且它与 12 列栅格是两套并行的坐标系,页面里会同时存在「第 7 列起 6 列宽」和「左边留 380px」两种说法。安全区是渲染结果,页面只声明层次关系。该通道已由 `RuntimeSection` 的几何测量与 `MapChart` 的 CSS 自定义属性消费落地,并覆盖加载、字体变化、窗口缩放和窄屏回流。

**三个声明各管一层,组合矩阵没有隐式耦合。** `layoutForm` 管页面外框(改变量的值)、`container` 管分区外壳(决定用哪套变量)、`layer` 管分区内层次(决定定位方式)。唯一的硬冲突是 **`backdrop` 要求 `container: "plain"`**——分区自带外壳会把铺满的组件裁掉——由 `validate.ts` 强制,它是 `backdrop` 四条不变量之一;另外三条是:只能声明在分区顶层组件上(Tab 内没有分区可铺满)、一个分区最多一个、分区不能只有 backdrop(没有东西叠在上面,叠放本身没有意义)。

**两个合法但未设计的组合不禁,补测试钉住现状。** `dashboard` + `container: "panel"`:看板形态的样式覆写没有碰 `--mc-section-panel-*`,会在中性灰画布上渲染报表风格的渐变面板。`report` + `backdrop`:`has-backdrop` 不读 `layoutForm`,报表形态下铺底一样生效。禁掉它们是收窄封闭闭集,按 [ADR-0051](./0051-additive-minor-versions-for-page-schema.md) 属破坏性变更;而且没人能证明将来不需要——报表里铺一张底图是完全可以想象的需求。因此保留它们,并用测试固定当前行为,使将来任何改动是有意的。

**已知的无意义声明:** backdrop 组件的 `layout.span` 被忽略(铺满由 `grid-column: auto !important` 加 `inset: 0` 实现)。概览页写的 `span: 12` 没有作用。`span` 是必填字段,因此这个声明必须存在但不表达任何东西;不为此新增校验错误,也不把 `span` 改成可选(那是破坏性变更)。

按 ADR-0051 的增量四条判据,本决策的两处协议变更都是纯增量:`layoutForm` 是新增可选字段,`layer` 是新增可选字段加一个封闭闭集,两者都已登记在能力表的 5.1。

## Consequences

- 页面外框的所有权从宿主移到页面文档。宿主此前可以自由决定容器宽度,现在满幅是页面的声明,宿主只是执行它;不执行的宿主会渲染出错的页面,而运行时无法检测到这件事。
- 安全区通道让 `RuntimeSection` 承担一件新职责:测量子单元格的实际 rect。这是运行时不变量的一部分(与行对齐同类),不进页面文档,但它使分区渲染从"只排布"变成"排布并回报几何"。
- `MapChart` 由此对安全区形成软依赖:有则用、无则退回。软依赖是刻意的——它让通道可以分批落地,也让报表形态下的地图无需特例。
- 两个未设计的组合被保留,意味着存在两组"合法但没人设计过观感"的页面。测试钉住的是现状而不是意图,读到那些测试的人需要知道这一点(本 ADR 就是它们的出处)。
- `layoutForm` 的闭集只有两档,新增第三档要按 ADR-0038 对 `container` 的同一条判据论证:结构上不可区分且视觉上必须不同。

## Considered Options

- **把看板做成第二类资产**(独立 schema、独立目录、独立发布链路)。两者协议完全相同,差别只有外框几何与几条能力;拆开会带来两份 schema、两个组件目录、两条发布链路,却没有两套东西需要治理。不采用——这也是把聚合根从"看板页面"改称"页面"、把看板与报表降为布局形态的原因。
- **在页面 schema 里声明安全区**(例如铺底组件上写 `safeArea: { left: 380 }`)。表达最直接,运行时不用测量。但它把布局结果写进元数据:AI 要算像素、视口一变就废、且与 12 列栅格构成两套坐标系。不采用。
- **让铺底组件自己测量上层组件。** 组件会需要遍历兄弟节点的 DOM,违反纯渲染组件边界(ADR-0025);而且每个铺底组件各测一遍。不采用:只有分区同时知道两边。
- **页面直接写坐标与 z-index。** 表达力最强,但它就是"自定义样式"的另一种拼法,与 ADR-0003 的严格声明式直接冲突,且 AI 生成的页面将无法被校验为"布局合理"。不采用。
- **禁掉 `dashboard` + `panel` 与 `report` + `backdrop`。** 让组合矩阵变得干净,少两种没人设计过的观感。但那是收窄闭集(ADR-0051 判定为破坏性变更),换来的只是省掉两组测试。不采用。
