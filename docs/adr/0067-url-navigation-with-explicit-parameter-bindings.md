# 页面声明 URL 与显式参数绑定，跨页链接无需宿主地址解析

[#97](https://github.com/CCharlesMeng/MetricCanvas/issues/97)/[#98](https://github.com/CCharlesMeng/MetricCanvas/issues/98) 讨论发现，ADR-0048 的 pageId→宿主地址解析适合 IOC 多页应用，却给普通单页嵌入增加不必要的适配。用户确认页面内容提供方直接给出绝对/相对地址，并承担部署路径变化后的链接调整。

## 决策

跨页目标直接声明 URL。绝对地址按其地址访问；相对地址按承载页面的浏览器 URL/文档基址解析，不按引擎 JS 资源地址解析。默认使用标准链接，复制链接、新标签页打开与普通点击遵循浏览器语义。引擎不要求宿主提供 pageId 地址解析或导航回调；IOC 子应用可按应用需要接管点击，保留正常链接的缺省行为。

目标地址配合显式参数绑定：参数可以取当前行字段、当前页面参数或当前筛选值，由引擎编码；只携带明确声明的参数，不自动复制全部筛选与状态。绑定仍为受控声明式能力，不引入脚本、任意表达式或通用 URL 模板语言。参数的选择属于页面内容，宿主不需要解析页面协议来拼接链接。

取消的是**跨页目标对 pageId 的依赖**，不删除页面资产身份、页面加载标识、修订归属或页面参数。引擎不拥有导航栈、面包屑与返回恢复；普通单页无须实现这些应用能力。应用需要恢复来源状态时自行承担，筛选变化与 URL 的可选同步沿用 ADR-0066。

## 取舍与历史对账

- 部分取代 ADR-0048 的“只发导航意图、所有跳转必须由宿主解析 pageId 并接管”边界；不取代它关于导航栈、面包屑与回跳所有权的结论。浏览器默认链接不等于在引擎里内建路由器。
- 接受页面链接与部署地址的耦合；页面搬到另一套系统后，内容提供方调整地址。放弃由统一宿主映射自动获得地址可移植性，换取单页可直接集成。
- 不要求每个单页宿主提供可选能力注册、缺能力占位或路由适配器；这些是讨论中的备选，并非最终方案。
- 任意 URL 无法沿用“目标 pageId 必须存在于本地页面集合”的完整静态证明。地址与参数声明可验证，不据此承诺外部目的页存在或业务参数正确。

## 实施状态与接缝

**这是已接受、尚未实现的目标。** 当前页面协议仍为 5.4，组件动作与文本链接仍使用 `page`；现有行字段绑定和 `carryFilters` 不支持本次新增的当前页面参数来源。现行协议以 `PAGE-METADATA.md` 与校验器为准，不得把本 ADR 中的能力当作已经可填写的字段。

由独立执行票 [#109](https://github.com/CCharlesMeng/MetricCanvas/issues/109) 完成字段设计、协议版本/迁移、组件动作与文本链接、URL 构造、渲染入口、真实 IOC 页面、示例和回归。实施前需明确普通查询参数与 MetricCanvas 类型编码的关系、已有 query/hash 合并、同名键优先级、缺值行为及 URL 校验范围；这些细节并未在本轮作为用户裁决冻结。特别关注缺项目编码后落入目标页演示默认值的现存风险。按 ADR-0051 处理协议演进，不在 5.4 上静默硬切。

#56 已交付：共享渲染主体在 `RuntimeSurface.svelte`，导航迁移复用此处，不复制到创作包，也不反向引入创作依赖。创作点击拦截、控件变化不重启查询和文档替换的初始化语义继续有效。#100 纳入导航公开面与协议支持范围；#103 的最终异构集成验收依赖 #109，而 #109 无需等待真实 DQE/身份服务。
