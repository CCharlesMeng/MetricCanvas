# 页面 id 不作为渲染分支条件

看板页面是聚合根和核心资产，同一性由页面 `id` 承载。页面 `id` 只用于文件命名、页面仓储加载、路由和修订归属；统一运行时不得根据某个正式页面 `id` 选择样式、组件、交互或开发工具。两份除 `id` 外完全相同的页面元数据，必须产生相同的 DOM 结构和计算样式。

渲染差异只能来自领域 DSL 中已受 Schema 约束的通用语义，例如组件 `variant`、`decoration` 和布局 `connectPrevious`。组件视觉由对应组件模块封装，统一运行时只负责通用页面组合与数据分发。Canvas 的默认预览使用内部最小示例，不把任何正式看板页面当作产品默认值。

Runtime UI 的页面组合样式必须遵循 DOM 所有权：`RuntimeView` 负责统一页面外壳，内容分区 Module 负责网格、组件单元格和 `connectPrevious`，纯渲染组件负责自身内容。父 Module 不得通过全局 class 选择器修改纯渲染组件内部 DOM；需要协作的外缘状态使用内部 CSS custom properties 或显式组件 Interface。内部视觉 token 不进入页面元数据，也不构成页面主题能力。

页面创作的示例和无外部模型回退同样不得内嵌正式页面的业务字段。动态页面只有在数据上下文返回可执行的已验证查询时才能生成；没有已验证查询时必须停止并说明原因，不能使用隐藏业务模板补全。

正式页面 `id` 可以出现在页面文件、测试、fixture 和文档中，但不能以字面量出现在 `apps/*/src` 或 `packages/*/src` 的产品源码中。这一约束由自动化门禁校验。

## Considered Options

- 根据页面 `id` 保留业务页专属样式：会让页面身份成为领域 DSL 之外的隐式输入，被否决。
- 从组件组合暗中推断整页类型：会把同样的耦合隐藏在结构推断中，被否决。
- 新增任意样式或页面主题字段：会扩张严格声明式页面规格，且当前产品选择统一页面外壳，不采用。
