# 筛选器类型闭集扩展，层级维度成为地图下钻的声明式来源

页面筛选器目前只有两类：`dimension`（多选，四种展现方式）与 `timeRange`（日期或日期时间区间，四个天级预设或绝对区间）。

IOC 作战地图的两条筛选栏要求六种输入：

| 设计稿控件 | 语义 | 现有类型能否表达 |
|---|---|---|
| 仅看重点国代 / 仅看 TOP100 / 仅看中资出海 | 布尔开关，勾选才加条件 | 否 |
| 2026/03/26（数据侧是 `mtime = '202604'`） | 单个月份 | 否——`timeRange` 是区间，且没有月粒度 |
| 全球 / 地区部 / 代表处 | 层级维度，且**层级决定谓词字段** | 否 |
| 全部行业（一级 + 二级） | 级联，二级候选随一级收窄 | 否 |
| 请选择预签金额 | 数值区间 | 否 |
| 搜索机会点名称 / 客户名称 | 跨字段模糊匹配 | 否 |

层级维度这一条影响面最大。来源实现里区域筛选不只是个筛选器：它同时决定 WHERE 用哪个字段（`region_dept_code_fin` / `rep_office_code_fin` / `geo_pc_code`）、决定地图显示全球还是某个区域、决定地图点击是下钻一级还是跳转到清单页。这三件事在来源实现里由一个 `regionType` 变量和散落在组件里的 `if` 分支共同维持。

同时 [ADR-0035](./0035-structured-relative-time-expressions.md) 的结构化相对时间表达已经裁决通过，但 `timeRange.default` 至今只有四个天级预设与绝对区间两个分支，是一笔未偿的欠账。

## 决策

**筛选器类型闭集扩展到六类**：`dimension`、`timeRange`、`timePoint`、`boolean`、`numberRange`、`search`。闭集就是闭集——新增类型必须走新的决策，不接受「先加一个通用类型以后再说」。

- `timePoint`：单个时间点，粒度为月或日。它不是 `timeRange` 的退化形态，谓词是等值而不是区间。
- `boolean`：勾选生成条件、未勾选无条件。它与 [ADR-0045](./0045-graphql-query-branch-with-structured-predicates.md) 的 `omitWhenEmpty` 配合，来源实现里那三处 JS 三元判断的语义全部落在这个组合上。
- `numberRange`：上下界，任一端可缺省。
- `search`：自由文本，绑定到一个或多个字段的 `like` 谓词。它跨字段，因此属于页面筛选器而不是表格属性（见 [ADR-0049](./0049-table-server-side-and-presentation-capabilities.md)）。

**`dimension` 筛选器可声明层级，取值携带当前层级。** 层级是一个有序列表，每级声明自己的维度。筛选值除了选中的取值，还携带这些取值所在的层级。[ADR-0045](./0045-graphql-query-branch-with-structured-predicates.md) 的谓词据此从一张层级到字段的映射表里取字段。层级语义的真源因此是筛选器一处，不是每个查询各拼一遍 SQL 片段。

**地图的下钻层级不是地图的私有状态，是层级筛选器的当前层级。** 地图组件读它决定渲染哪一级，点击时通过既有的 `writeFilter` action 写回下一级的取值——这与图表点击写筛选是同一条路径，不是新机制。到达最深一级后再点击则是跨页下钻（[ADR-0048](./0048-navigation-intent-and-host-routing.md)），由页面文档声明。来源实现里那个三级 `if` 分支状态机因此不需要在本仓重建。

**级联只收窄候选值，不改变谓词结构。** 筛选器可声明依赖另一个筛选器，候选值端口按上游当前值返回下游候选。一级行业与二级行业属于这种关系。级联**不允许**改变下游筛选器绑定到哪个字段、也不允许让下游筛选器出现或消失——那些是条件显隐，属于表达式的变体。

**ADR-0035 的结构化相对时间同批落地。** `timeRange.default` 增加结构化相对时间分支（粒度单位、区间描述、锚点、是否包含当前未完成周期），求值发生在服务端取数编排期，一次页面加载内共享同一求值时刻。既有的四个天级预设与绝对区间保留。

**本决策不做的事。** 不做筛选器之间的条件显隐；不做筛选器分组或折叠面板（那是布局）；不做跨页面的筛选器继承（跨页靠 URL，见 ADR-0048）；不做多层级联（只允许依赖一个上游）。

## Consequences

- URL 编码需要为四个新类型各定前缀，与现有的 `d:` / `t:` 并列。编码格式一旦发布就进入兼容负担，本批应一次定完。
- 候选值端口需要接受上游筛选值作为入参。现有端口是「按维度取去重取值」，级联后变成「按维度加上游约束取去重取值」，这是端口签名的变更，DQE 与 GraphQL 两侧实现都要跟。
- 层级维度让地图组件从「自带三级状态机」变成「读筛选值渲染」，这是一次实质简化，也让地图的当前层级可被 URL 携带与分享——来源实现做不到这一点。
- `boolean` 与 `omitWhenEmpty` 的组合意味着「未勾选」与「勾选为否」是同一件事。这对「仅看重点国代」成立（不勾选就是不限制，而不是「只看非重点国代」）。若将来出现真正需要三态的筛选，它是新类型而不是给 `boolean` 加一个 `allowFalse`。
- 六类筛选器 × 谓词算子闭集构成一张组合表，校验器需要判定哪些组合合法（例如 `search` 只能配 `like`，`numberRange` 只能配 `between` 或上下界比较）。这张表应显式写出来，而不是靠实现隐含。
- ADR-0035 的欠账在本批偿还。它与 [ADR-0044](./0044-first-class-metric-entries.md) Consequences 里提到的「相对时间词表尚未挂到指标条目上」是两件事：本批交付的是页面侧的结构化表达，词表属于问数链路，仍未开始。
- 与决策里「地图点击经 writeFilter 写下一层」的落差是：inline 页禁止 writeFilter（现有不变式），地图中间级点击由运行时直接写层级筛选状态，最深一级走 navigate；`setFilters` 仍不写层级。

## Considered Options

- **布尔用单值 `dimension` 表达（候选值是「是」「否」）。** 零新增类型。但会造出一个候选值只有两项的伪维度，且「未选择」与「选了否」在语义上必须区分，`dimension` 的多选模型表达不了。不采用。
- **月份用 `timeRange` 加 `precision: 'month'` 且 `from === to`。** 复用现有类型。但谓词侧需要额外知道「这个区间其实是等值」，否则会编译成两个比较；而「知道它其实是等值」这个知识没有地方声明。不采用。
- **加一个通用 `custom` 筛选器类型，形状由作者自定。** 一次解决全部当前与未来需求。但闭集失效，校验器退化为只能判「是个对象」，AI 生成不可控。这与 [ADR-0001](./0001-domain-dsl-over-a2ui.md) 选择封闭 DSL 的理由直接冲突。不采用。
- **地图自带层级状态机，不进筛选器。** 与来源实现一致，改动最小。但层级同时决定谓词字段，不进筛选器就意味着地图要把状态推给查询，那是组件反向驱动数据源，破坏纯渲染组件边界；且层级无法进入 URL，分享链接会丢失当前视图。不采用。
- **级联允许改变下游绑定字段。** 能覆盖更多场景。但那本质是条件分支，会把 ADR-0045 好不容易关掉的表达式从筛选器侧放回来。不采用。
- **把 `search` 做成 `dimension` 的第五种展现方式。** `dimension` 已有 `display: 'search'`（按维度取值做联想选择），名字相近容易混。但二者语义完全不同：前者是从候选值里选，后者是自由文本模糊匹配多个字段。合并会让一个类型承担两种谓词形态。不采用——反而应在实现时留意这两个名字的歧义。
