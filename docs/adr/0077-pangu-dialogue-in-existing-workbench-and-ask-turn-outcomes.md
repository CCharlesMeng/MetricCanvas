# 盘古接管现有左侧对话，每轮 ask 返回结果并保留已有页面

#95/#107 的盘古接入讨论曾把“所有对话内容交给盘古”误解为删除页面画布，又把“一问一答”误解为不能通过确认继续分析。用户于 2026-09-08 通过交互原型明确：保留 platform 的既有布局，只替换左侧对话区；每次 ask 必须返回本轮结果，结果可以是答案，也可以是澄清或确认问题。

## 决策

**只替换左侧对话区。** 全局导航、文档工具栏、页面画布与右侧检查器继续保留。盘古实例拥有左侧的输入、问题、澄清、确认、口径说明、进度、答案、错误、停答与历史等全部对话呈现。MetricCanvas 不在画布或检查器旁再建设一套对话结果或过程详情面；页面文档仍由原画布呈现，人工页面搭建和显式沉淀仍由工作台承担。“没有自己的结果区域”不指移除页面画布，也不引入“查看页面/返回对话”的独立视图切换。

**一次 ask 的答复结束与分析流程完成分别判断。** 保留原有条件式确认交互：本轮可以返回确认问题并结束答复，受确认约束的执行仍等待；用户回应后继续分析。语义上不需要把一次 ask 长时间挂起，更不要求所有输入都在同一轮收集后才回答。新 ask 或专用确认接口如何关联待确认内容，是尚待验证的盘古/Relay 接口事实；不能把聊天历史当成结构化续跑状态。歧义未解决不执行、候选精确校验与用户未修改的显式设置保持不变等既有约束继续有效。

**实时分步进度不作为第一版交付前置。** 缺少可靠实时事件时，允许盘古显示整体处理中，再给出本轮答案或确认问题。收到可靠事件后才能展示对应真实阶段；完成后取得的信息只作过程记录，不能伪装成实时进度，不从自由文本推断结构化控制状态。这一版暂未实现 ADR-0037 的实时分步呈现，不否定其后续目标。

**新一轮未成功产页时保留上一轮页面。** 处理中、等待确认、失败、取消或仅得到文本结果时，已有页面保持可见并标明“上轮结果，本轮尚未更新”；新页面通过校验后才替换。用户显式清空、删除内容或切换分析会话按相应操作处理，不由失败隐式清空。迟到或过期结果不能覆盖较新的状态，沿用 ADR-0058/0064 的约束。

## 生效边界与旧 ADR 对账

| 旧决策 | 本次处理 |
| --- | --- |
| ADR-0060：Svelte 是唯一产品界面 | 部分修订为平台保留 Svelte 外壳、画布与检查器，左侧对话整体由盘古实例提供；不引入第二个产品入口。 |
| ADR-0063：浏览器 Chat 按 WebSocket + `role_name` 接入 | 不再作为本仓接线依据。当前接入面为盘古实例 API + adapter；`skillInfo/referrer/holdingSkill` 的真实结构、受控标识和路由生效信号仍待 #106，不能据此发明字段映射。既有 Relay/DQE 调查的其他事实不受影响。 |
| ADR-0037：条件确认、分步流式、定向修改 | 确认与未修改设置保持继续有效；仅第一版实时分步呈现允许暂未实现。一次 ask 也不等于只能形成一个取数单元，不改变 ADR-0055 的多单元约束。 |
| ADR-0040：取数核对与确定性就地校准 | 业务语义继续有效，对话内的呈现由盘古承担。未裁决改为一律经模型、完整重问或取消就地校准；具体交互能否兑现仍需验证，不在画布另造确认面板绕过该缺口。 |
| ADR-0055：口径组与差异可见 | 页面内分区与口径事实保留，对话中的说明交给盘古。 |
| ADR-0058/0064：检查点、持久化与页面产物双通道 | 均继续有效。保留当前浏览器中的页面不等于刷新可恢复；盘古聊天历史不等于分析会话或会话检查点。 |

**未改变的接入门槛：** 完整页面文档和数据行不经模型文本流回传；`customRemoteCard` 不作为本版页面产物通道；Page Artifact Adapter 未验证前，`compose_page` 不向真实模型开放。仅文本问数的既定下限继续有效，但不证明受控 skill 路由、真实取数、身份或会话恢复已经接通。盘古停止接收也不能在无证据时被描述为服务端执行已取消。
