# 本地首版在存储与 HTTP 边界替代外部依赖，请求凭据归宿主

地图 #95 要求在真实 MySQL 与 DQE 不可达时先跑通本地版本，同时保持目标系统的契约。
2026-09-07，#99 grill 确认：页面资产使用真实 Java HTTP 服务与内存存储，DQE 使用现有
HTTP 仿真；所有数据请求的请求头和相关 Cookie 由宿主决定，不新增本仓开发身份系统；
旧 scripted/lexical 模型仅作测试与迁移对照。该裁决延续 ADR-0060～0064 的目标所有权，
并落实 ADR-0066 的宿主边界。

## 替代矩阵

| 对象 | 本地首版 | 保持真实的部分 | 验证限制 |
|---|---|---|---|
| Java 页面资产 / MySQL | 真实 Java HTTP 服务，`PAGE_ASSETS_STORE=memory` | Java HTTP Adapter、页面校验、修订、并发与幂等应用逻辑；仅在 Java 存储端口替换实现 | 接受重启清空；不证明 MySQL 事务、Flyway、持久化或跨进程锁正确 |
| DQE | `tools/dqe-sim` 的真实 HTTP 服务 | 请求/响应形状、批量项位置对应、网关归一化、筛选与分页接线、已定义的失败语义 | 只实现有依据的协议与明确的测试场景；未知能力明确报出，不据此证明真实计算、权限或协议符合性 |
| 请求头与 Cookie | 宿主提供请求配置或请求实现 | 按目标接口发请求，服务端继续按契约处理必填项与权限 | 本仓不新增身份适配器、登录体系或用户切换器；测试凭据不能证明生产身份可信 |
| scripted / lexical 模型 | 仅用于旧链路测试与迁移对照 | 现有行为基线可用于迁移核对 | 不作为静态产品备用问数路线；公共 Chat 未接通时呈现不可用 |

Java 内存存储是已有实现，不需要新建 Java HTTP mock，也不采用 Node offline lifecycle
绕过 Java 来验收目标页面资产链路。`PageAssetsConfiguration` 在组合根选择存储实现，
`PageAssetService` 与保存策略保持相同。该事实纠正了 #99 最初正文中
“Docker MySQL 或 Node 内存 lifecycle”的不完整二选一。

## 可检查的边界规则

替代发生在外部依赖的 HTTP 协议或明确的存储端口，选择放在宿主配置、组合根或测试装配。
不得为本地模式修改页面协议、削减请求字段、绕过页面校验，或在业务逻辑与组件中加入
返回假成功的分支。存储选择本身不是违规的业务 mock 分支；不以搜索全部 `if (mock)`
作为唯一门禁。合法的 `inline` 页面数据源保持原有定位，不属于此次替代策略。

DQE 仿真中的确定性测试数据可以保留；其支持范围必须明确，不能把未知查询或协议能力
补成看似成功的结果。真实 DQE 不可达时，本地执行只算仿真链路验证。

请求头和 Cookie 的所有权覆盖 DQE、页面资产与公共 Chat 的宿主请求。端点、凭据来源、
请求头、浏览器 `credentials` 策略、登录恢复与更新由宿主决定；引擎与通用适配器不自行
补默认用户、推断身份或覆盖宿主凭据。Cookie 仍由浏览器按其规则发送，不把 Cookie
原文作为引擎业务数据。platform 作为宿主也遵守此边界，具体接线由 #101 落实。

这不删除服务端契约中的 actor 等必填项，也不取消服务端校验。例如现行 Java 缺少
`X-Operator-Id` 时失败，本地宿主或测试调用方应显式提供符合契约的输入；不能让服务端
自动补人。最终头部形状由 #105 对账，可信身份与真实 CORS 能力仍须由宿主及提供方兑现。
本票不建设多用户切换功能，也不以它作为本地首版验收前置。

scripted 与 lexical 当前仍有实际消费者，不能称为死代码；默认 scripted 配置也不等于
外部模型请求失败后自动回退。目标静态产品不使用它们补公共 Chat 能力缺口。实际移除
范围与时机归 #102，并与 #107/#108 的迁移验收对账。公共 Chat 的传输、受控 Skill
路由与页面构建产物能力仍归 #106～#108，不能以旧 Relay 可连接为已具备能力的证据。

## 后续验证与执行归属

以下是后续执行的验收要求，本次仅完成事实核验与决策，没有启动服务或运行这些验收。

- #101：静态宿主提供端点、头部与 Cookie/credentials 策略，按 #105 的最终 Java
  契约接线；确认请求配置未被内部身份逻辑覆盖。仿真 CORS 应覆盖所验场景，不代表生产
  服务已支持跨源凭据。
- #104：本地验收穿过真实 Java HTTP，检查保存、最新页面、精确修订读取、目录、
  非法页面拒绝、基线冲突与幂等重放，并记录内存重启清空的行为。最终接口变化随 #105
  更新断言，不把当前接口形状提前冻结。
- #104：DQE 验收覆盖批量项对应、筛选/分页请求及已声明的错误场景，未知查询明确失败；
  缺必填请求项遵循服务契约，不补默认身份。真实 MySQL/DQE 验收仍单独记录。
- #102：旧模型与 Node offline 路径按测试、迁移材料及目标产品依赖分别处理，不提前
  批量删除；静态交付不得携带隐式旧问数路线。
- #107/#108/#104：公共 Chat 未接通可显示不可用，但这不满足 #95 要求的五项产品能力，
  不能据此关闭静态部署终点线。

以上工作由现有票承接；本票不增加独立实施范围，不执行删除、静态化、发布或部署。

## 取舍

本地首版接受进程内存储的易失性，换取真实 Java 接线与业务校验不被跳过；真实 MySQL
验证保留为独立证据。DQE 仿真保持有限且可检查的支持范围，避免用虚构行为提前冻结外部
协议。请求凭据统一交由宿主，避免在渲染引擎或静态产品中再建一套开发身份模型。
