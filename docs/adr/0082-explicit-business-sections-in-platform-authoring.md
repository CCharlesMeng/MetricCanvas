# 完整页面创作以业务章节组织，口径组不强制决定分区

2026-09-17 用户确认场景参考驱动的整体方案并授权实施。流水报告实测显示，按口径组机械分区无法表达现有示例中“概况卡与趋势同章”的业务阅读结构；只有修改 Skill 文案无法突破装配器的结构限制。

Platform 完整报告采用**页面结构计划**：场景参考提供阅读路径，章节组合提供默认占位，模型通过受控组件组合表达章节、顺序和数据引用，确定性装配生成普通页面文档。取数需求与展示分开，允许一源多组件和跨口径同章；原始 DQE、数据行、稳定字段 ID 和页面身份由可信程序管理。

本决策限定 ADR-0055 的适用范围：口径组分区继续用于普通问数和兼容的快速 `compose_page`，完整页面的显式计划不采用该分区规则。口径差异以随页面保存的可见说明呈现；同章展示不授权跨口径计算或混合量纲共轴比较。

不采用封闭的整页模板，也不放开任意页面 JSON/CSS。`create_content_page` 保留五工具体系并新增与 operations 互斥的版本化 plan 输入；局部修改继续消费完整可信候选，不根据历史场景强制还原。计划和场景证据留在创作期候选审计，不进入渲染协议，历史页面无须迁移。

首期覆盖经营报告与用量报告的结构、呈现和局部编辑。分析事实摘要及自动生成业务结论另期建设；模型不能仅根据指标元数据编写数值分析。
