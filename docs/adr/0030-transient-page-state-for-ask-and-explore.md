# 问数与探索使用临时页面态与轻量会话，沉淀才产生页面修订

产品目标不是让 AI 自动写一个大屏，而是构建 AI Native 数据分析与应用体系：用户从一句业务问题出发，经数据能力发现、自动查询、直接得到分析结果，再通过几轮自然语言做数据校准、筛选调整和展示调整，必要时才沉淀为持续运行的数据应用。至少存在五种形态：问数（Ask）、探索（Explore）、报告（Report）、Data App（App）和未来的监测（Monitor）。Data Agent 负责探索，Data App 负责固化高价值分析，二者不建设成两套数据能力。

当前领域模型只有资产态：页面文档进入平台的唯一写入口是 `saveRevision`，`page-lifecycle` 的其余写操作都作用在已存在的修订上。任何一次分析要被看见，都得先成为不可变页面修订。这让问一个问题和建设一个应用同样昂贵，与“不是所有问题都值得做成 Data App”的产品原则直接冲突。

## 决策

**页面文档是五种形态的统一表达，也是 Data Agent 与 Data App 的汇合点。** 问数与探索产生**临时页面态**：一份通过页面校验的完整页面文档，被现有统一运行时直接渲染，但不进入页面仓储、不产生页面修订、不占用页面目录、不参与发布治理。资产态仍然是 ADR-0008 的不可变页面修订加人工确认发布，语义不变。两端共享页面协议、数据网关、结果字段契约、归一化与创作期验真；共享的是执行路径，口径复用的欠账记录在 ADR-0033。

**临时页面态使用临时页面 id。** 临时 id 不进入页面目录、不承载修订归属，沉淀时才分配正式 `pageId`。ADR-0021 继续生效：统一运行时不得按页面 id 选择样式、组件或交互，临时态与资产态必须渲染出相同结果。

**沉淀是显式动作，且分两个方向。** 沉淀为 App 时交给 `saveRevision`，页面必须使用滚动时间（ADR-0035），临时口径需通过 ADR-0036 的门槛。沉淀为 Report 时保留查询定义与内嵌初始行、**不声明筛选绑定**——依据 ADR-0020，默认状态存在内嵌初始行且无筛选变化时统一运行时不重新查询，因此报告天然冻结在采集时点，同时保留查询定义作为口径溯源。Report 因此不需要新的数据源类型或渲染路径。两个方向的时间语义相反：Report 冻结在绝对时间才可引用，App 必须滚动才有意义。

**问数的查询生成发生在 Platform 创作期，不发生在统一运行时。** NL2DQE 由 Platform 侧编排完成（ADR-0037），统一运行时收到的始终是一份已经确定的页面文档。因此“统一运行时不执行 NL2DQE”这条不变式原样成立，不因新增问数形态而放宽。分析结论文本按 ADR-0027 由创作期写入 `text` 组件的 `props.body`，不使用运行时 SSE。

**分析会话是服务端一等概念，但取最轻形态。** 会话保存 `sessionId` 与步骤事件流：每步记录问题原文、路由域、候选与选中指标、生成的 formula、生效查询、执行结果摘要、意图与组件选择、失败分类。**不保存完整对话文本与模型 prompt。** 组件是自动推导还是用户显式钉住属于创作期状态，随会话保存，不进入页面文档。

选择轻量落库而不是继续只由浏览器持有，是因为缺口条目（ADR-0036）与失败分类本身就要求把问题原文和每步结构化结果落库；此时与会话落库的差别只剩一个 `sessionId`，维持“会话不落库”只会付出代价而换不到分享、回放与评测集。

**会话内容按 90 天保留，仅平台管理员与本人可见。** 身份当前允许 mock，但 mock 必须提供多个可切换用户，且按 `actorId` 的可见性过滤必须真实执行；不得因身份是 mock 而跳过过滤。mock 阶段的隐私承诺结构上成立、来源不可信，因此接入真实身份是上生产的前置条件。

**Monitor 暂不建设。** 记录它的依赖以免误判范围：主动洞察需要调度、基线与稳定的指标口径，其中稳定口径由 ADR-0031 的发现锚点承载，调度与通知均在当前系统边界之外。

## Consequences

- 问数与探索的成本从“产生一个受治理资产”降为“渲染一份临时文档”，产品原则中的“先问、再探索、值得了才沉淀”在架构上成立。
- 渲染侧零新增：`RuntimeView` 的 `document` prop 与 Embed 的 `mount` 本来就接收页面文档本身而非页面 id，临时页面态不需要新的渲染通道，也不需要新的页面仓储适配器。
- 页面校验仍是临时页面态的准入条件；不能因为“只是问一下”而跳过校验进入渲染。
- 发布治理的强度不被稀释：审计、租约与人工确认只作用于资产态，不会被高频问数淹没。
- 会话事件流同时承载分享、回放、评测集与自我改进四种用途，不再为它们各建管道；保留期与清理策略必须随之实现。
- 问题原文含客户名、代表处与业务黑话，属于真实敏感内容；`actorId` 可见性过滤是首版能力而不是后续增强。
- 领域词汇表已新增问数、探索、报告、Data App、监测、临时页面态、沉淀与数据校准词条。

## Considered Options

- **每次问数也保存为页面修订。** 治理对象被高频临时分析淹没，修订历史失去审计价值，且与产品原则冲突，不采用。
- **为问数与探索新建一套轻量渲染协议。** 会出现两套不兼容的表达与两套组件实现，沉淀时还需要协议翻译，正是多数 BI 探索态与看板态割裂的成因，不采用。
- **让统一运行时在渲染期生成查询。** 已发布页面将不再确定性可复现，破坏 ADR-0003 与发布治理的前提，不采用。
- **会话只由浏览器持有。** 曾一度采用；在决定落库缺口条目与失败分类后，它已名存实亡且额外放弃了分享、回放与评测集，因此改为轻量落库。
- **会话保存完整对话与 prompt。** 为训练留出最大空间，但显著扩大敏感内容面与保留成本，当前收益不足，不采用。
- **Report 物化为纯 `inline` 数据源。** 冻结最彻底，但丢失查询定义即丢失口径溯源，不采用。
