# 分析会话保存最新检查点以恢复临时页面态

ADR-0030 把分析会话裁成服务端一等概念,但当时的实现只保存步骤事件;`outcome` 帧里的页面文档与续跑基线只留在浏览器内存。因此带 `sessionId` 刷新后只能复看步骤,不能重现结果、继续探索或沉淀为报告/Data App;ADR-0030 声明的分享与回放价值只完成了一半。

## 决策

**分析会话在追加式步骤事件之外,保存一份最新会话检查点。** 检查点包含已通过页面校验的临时页面态、结构化问数续跑状态、组件钉住结果、待确认交互与运行终态;不保存完整对话文本、模型 prompt 或原始 `outcome.messages`。续跑时由结构化状态重建最小基线,不把浏览器消息历史变成新的服务端对话库。

**检查点是会话状态,不是页面修订。** 它不进页面仓储、不出现在页面目录、不获得修订历史或发布治理;`sessionId` 仍是它的归属边界。只有用户显式发起沉淀才会进入 `saveRevision`,ADR-0030 的两速生命周期不变。

**步骤事件解释过程,检查点恢复工作状态。** 完整页面文档不塞入 `document_ready` 事件,否则每轮都会在追加流里复制真实数据行。首版只保留最新一份检查点;“恢复离开前的状态”不等于“逐轮时光回放”,后者若成为真实需求再单独扩展。

**Agent 终态和工作台本地编辑都更新检查点。** Agent 产出页面后由服务端直接写;拖动、编辑标题、换组件等不经 Agent 的改动在本地页面校验通过后防抖写。持久化边界再次运行页面校验;运行终态用所观察的事件序号防慢运行覆盖新结果,本地编辑用检查点版本做乐观并发控制,冲突时拒绝静默覆盖。

**检查点沿用分析会话的可见性与 90 天保留期。** 它含查询的内嵌初始行,因而敏感性高于只含行数和字段名的执行摘要;本人/平台管理员可见性、过期清理与不记录请求体的约束必须与检查点一起执行。事件或检查点的有效写入会延长活跃期,单纯读取不会。

## Consequences

- 刷新后可同时恢复时间线、最新临时页面态、待确认交互和续跑基线;用户可继续探索或直接沉淀。
- 恢复默认呈现文档中已保存的内嵌初始行,不把“回到这个结果”静默变成一次新查询;后续刷新数据仍是显式交互。
- 页面文档的体积与更新频率进入会话存储成本;只保留最新一份、内容哈希和本地编辑防抖用于控制写放大。
- ADR-0030 “会话保存 `sessionId` 与步骤事件流”的内容边界被本 ADR 部分修订;它对临时页面态、沉淀、权限与保留期的其余决策继续生效。

## Considered Options

- **把完整页面文档放进 `document_ready` 事件。** 回放简单,但每轮追加一整份文档和业务数据行,无法控制体积与重复,不采用。
- **保存完整 `outcome.messages`。** 续跑最直接,但扩大对话与 prompt 敏感面,并推翻 ADR-0030 的明确红线;结构化问数状态已足够支撑定向增量探索,不采用。
- **每轮保存一份页面快照。** 可做逐轮时光回放,但当前真实需求只是恢复最新工作状态;在需求出现前不支付多版本存储与选择交互成本。
