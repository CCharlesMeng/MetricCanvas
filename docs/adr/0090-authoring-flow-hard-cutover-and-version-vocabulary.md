# 页面创作流程硬切换与版本术语分离

现有创作资料同时使用结构计划 v1/v2/v3、平台流程 v2、页面 Schema 版本、Bundle 版本和外部 HTTP API 版本。它们属于不同的版本序列，却在入口、Skill 和 Relay 说明中被并列称为“v1/v2/v3”，导致旧流程可能被误认为新流程的回退，也让“Agent/Python 不保存正式页面修订”与当前平台草稿保存实现冲突。

## 决策

生产只保留一套页面创作流程和一套现行页面结构计划。历史结构计划与旧创作流程不再作为生产路由、缺依赖回退或新建输入；需要保留的历史内容进入归档或迁移测试夹具。已保存页面的 Schema 兼容读取、普通问数的临时页面态和外部服务 API 版本继续按各自边界维护。

平台创作的职责划分如下：

- 模型与 Skill 理解业务问题、选择分析范围、审核计划并决定页面表达。
- 确定性内容工具负责数据发现、受控取数、页面装配/局部编辑、整页校验、单份工作稿、冻结提交和单次草稿保存。
- Java 页面资产服务负责资源权限、页面定义持久化和发布状态裁决。
- Relay 负责可信创作上下文、步骤事件、临时产物交付和会话检查点。
- 前端负责计划审核、预览、人工修改和明确发布。

内容工具可以提交平台草稿，因此不再使用“Agent/Python 不保存正式页面修订”作为当前架构描述。准确边界是：内容工具可提交草稿；正式页面修订和发布状态由 Java 页面资产服务裁决；Relay 会话检查点不是页面修订；普通问数和探索不自动落库。

保存、发布、删除、完整预览产物注入等副作用由可信程序控制。模型可以调用任务级的数据发现、受控取数、页面上下文和装配/编辑能力，但不能自由组合低级保存接口、传递身份或搬运完整页面 JSON。CLI 与 MCP 如同时存在，只能委托同一业务用例，不得复制页面装配和保存逻辑。

工作稿更新必须绑定页面目标、创作轮次和基线修订。有效变化冻结 document、基线和操作上下文后单次保存；失败、冲突、结果未知和预览失败分别返回。未知写入不自动重发，计划确认不触发发布。

## 版本序列

| 名称 | 作用 | 当前处理 |
|---|---|---|
| 页面创作流程 | 生产入口和业务编排 | 只保留平台现行流程 |
| 页面结构计划 | 创作期章节、顺序和数据引用输入 | 生产只接受现行版本；历史 v1/v2 归档或迁移 |
| 页面 Schema | 运行时页面文档协议 | 独立保留 5.x/6.x 兼容读取与增量演进 |
| Bundle/软件包 | 分发物和依赖锁定 | 独立递增，不与结构计划对齐 |
| 外部 API | Relay、DQE、Java 的服务契约 | 由提供方维护，不改名为页面版本 |
| `formatVersion` | 某个产物信封或局部契约格式 | 只能按所属信封解释，不能泛称结构计划版本 |

任何文档、Skill 或代码注释出现 `v1`、`v2`、`v3` 时，必须同时写明它属于哪一条序列。结构计划版本不得从页面 Schema 或 Bundle 字段推断。

## Consequences

- 退役范围包含旧页面创作 Skill、旧候选提交链、旧结构计划生产分支和误导性保存说明；旧页面读取与普通问数兼容入口不因名称相似而删除。
- 当前生产入口确定为 Relay 注册的 MCP stdio server；“受控 CLI”只指 Relay 对 MCP 子进程的受控启动，不是模型可调用的通用 shell，也不是第二条创作流程。身份注入、取消和产物分流仍必须由部署事实证明。
- 本 ADR 不新增 Java 幂等查询、操作结果查询或不可变修订能力。若提供方没有这些能力，系统必须保持结果未知并停止自动重发，不能假定恢复语义存在。
- 本 ADR 不改变页面 Schema 编号、外部 `/v1/` 路径或普通问数的临时页面生命周期。

## 迁移门槛

迁移必须先盘点旧入口的真实消费者，再删除生产路由；更新契约导出、Bundle、Skill 和部署配置后，完成新建、编辑、样式修改、partial、冲突、未知保存、预览失败和明确发布的真实联调。源码通过、测试替身通过或本地 Bundle 校验通过，均不能单独证明 Relay、Java、DQE 或前端已接通。
