# 挂起服务端计算数据集，问数期计算由 DQE formula 承担

DQE 现有语义面只能表达“取哪些指标、按哪些维度、在什么筛选与粒度下”，无法表达跨查询的关联与派生计算。实测既有页面的查询覆盖度约 60%–70%，缺口集中在率值、同比、环比、占比、累计与排名。为此曾设计**计算数据集**：一个服务端的 Transform 层（join、lookup、group、timeAlign、rank）加 Compute 层（`ratio`、`delta`、`pctChange`、`cagr`、`share` 等具名算子），作为问数与 Data App 共同引用的口径资产。

按 ADR-0014，这类跨查询计算只要落在服务端组合执行适配器内、不进入页面 DSL 与浏览器，方向上是被允许的。真正拦住它的不是位置，而是三件前置条件。

## 决策

**本决策保持 proposed 且暂不实现。** 问数期的派生计算改由 DQE `output_metrics` 内嵌 `formula` 承担（ADR-0032），DQE 表达不了的场景走 GraphQL/REST 适配器（ADR-0034）。记录挂起理由，避免日后换个名字重开同一场讨论。

挂起理由：

- **它要求领域层出现第二个聚合根。** 计算数据集若要成为可复用、可背书、可追溯的口径资产，就必须自带稳定 id、不可变修订、发布与引用完整性（被页面引用的数据集修订不可删）。这是对 ADR-0006、ADR-0007“围绕单一聚合根组织包与端口”的实质修订，不是补充。
- **Transform 的边界语义正是 ADR-0015 挂起的那一批。** join 的键缺失、1:N 放大度量、null 键、笛卡尔积上限；lookup 未命中是丢行还是补 null；timeAlign 缺失周期补 0 还是补 null（补 0 会让 `pctChange` 产出无穷增长）；日粒度合月是求和还是取期末值。ADR-0015 列出的空集与失败传播、输入集合上限、循环依赖校验、缓存键与取消语义，一条都躲不过。换名字不构成推进。
- **正确性依赖尚不存在的指标语义元数据。** 跨粒度时间聚合与聚合函数选择必须读指标的可加性与时间聚合方式，否则会安静地算错——把比率求和、对存量指标跨月累加都不会报错。该元数据由 ADR-0031 引入，但真实数据侧尚未补齐。

**已经取回的部分不随挂起丢失。** 具名算子闭集这一结论仍然成立并被记录：`arithmetic` 这类通用四则运算不可提供，因为任意嵌套的算术就是一棵表达式 AST，与 ADR-0014“不在页面 DSL 中增加计算表达式或 JSON AST”直接冲突。恢复设计时应从具名算子起步，而不是从表达式语言起步。

**恢复条件（需同时满足）：** 指标条目的可加性与时间聚合方式在目标域真实可用；ADR-0015 的五项语义有确定答案；有证据表明 formula 的口径复制成本已实际发生，即同一口径在多个页面各持一份副本并已出现漂移。

## Consequences

- 汇合点从计算数据集回落到**页面文档**。这反而更稳：页面文档已有完整协议、校验、渲染与发布治理，不需要新建一套资产生命周期。
- 领域层维持单一聚合根，ADR-0006、ADR-0007 不需要修订。
- 代价是口径从资产退化为用完即弃：formula 内嵌在页面文档中，同一算法被多个页面使用即被复制多份，改一次要改多处。这一代价被接受，其唯一退路是 ADR-0032 的 formula 留痕与 ADR-0036 的缺口计数——高频重复的 formula 应被提为指标或已验证查询。
- 行业参照相反：Databricks Unity Catalog Semantics 把比率、同比环比与累计做成受治理 measure 的规格，Agent 只选 measure 与维度、不发明口径。我们选择了相反的位置，因此“把口径收回资产”这条路必须留着而不是关掉。
- ADR-0015 继续保持挂起，本决策不改变其状态，只记录二者面对同一批未解语义。

## Considered Options

- **现在就实现计算数据集并接受第二个聚合根。** 口径可复用、可背书，与行业做法一致，但要在指标语义元数据缺失、ADR-0015 语义未定的情况下同时改动领域分层，风险集中爆发，不采用。
- **把 Transform/Compute 放进页面文档或浏览器。** 与 ADR-0003、ADR-0014 及 `origin.md` 的“页面不含计算表达式”直接冲突，不采用。
- **不挂起也不实现，留作待办。** 会导致同一场讨论被反复重开，且下次讨论时不会记得阻塞点是指标元数据而非架构位置，不采用。
