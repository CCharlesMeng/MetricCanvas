# 看板页面内嵌并直接提交查询定义

query 页面数据源直接内嵌 SQL 或 DQE 查询定义,统一运行时把查询原文和受控参数提交给服务端校验并执行,不再通过查询执行引用间接解析查询原文。外部查询协议的请求体不因页面协议而改写;当前已确认的 DQE 查询定义保持 `dsl_list` 结构并原样 POST 到 `/rest/cdi/cdinl2databuilderservice/v1/dsl/execute`。该决策缩短看板页面到现有查询服务的接入路径,代价是查询原文随页面分发到浏览器,查询治理、权限、安全和资源限制必须在每次服务端执行时完成。

本决策取代 ADR-0014 和 ADR-0015 中“页面与浏览器只提交查询执行引用、不得提交 SQL 或 DQE 原文”的边界;命名页面数据源、结果字段契约、纯渲染组件、最多五个运行时并发查询以及组件不得自行取数的约束保持不变。

当前交付只实现并验证上述 DQE 执行协议。页面查询定义为 SQL 保留可判别的扩展接缝,但在 SQL 端点和请求体得到外部确认前不提供虚构的 SQL 执行实现。

页面查询定义使用 `{ language, body }` 外层结构:`language` 是页面协议用于选择执行适配器的判别字段,`body` 是外部查询协议的原始请求体。DQE 执行适配器只把 `body` POST 到已确认端点,不把页面协议的 `language` 或 `body` 包装层发送给外部服务。

DQE 的批量能力是数据网关执行适配器内部的传输优化,不在看板页面顶层增加查询批次。每个 query 页面数据源仍表示一个命名数据集并持有自己的 DQE 查询定义;适配器可收集同一调度窗口内的查询,保持每个 `dsl_list` 项不变地合并为一个合法 DQE 请求,再按请求项与 `results` 的稳定位置关系把数据行和错误分发回各页面数据源。最多五个并发限制约束统一运行时交给数据网关的逻辑查询窗口,页面和组件不感知批量请求。

DQE 批量响应必须保持 `dsl_list[i]` 与 `results[i]` 的稳定位置对应,失败项也不得从 `results` 省略。数据网关以此把每项 `data` 或错误分发回原命名页面数据源;返回项数量与请求项数量不一致时按协议错误拒绝整批结果,不得猜测或错位回填。

页面字段 id 与 DQE 字段名永不隐式同名匹配。raw-query 页面数据源显式声明结果字段契约及每个稳定页面字段 id 对应的外部 `queryField`;组件只绑定页面字段 id,数据网关把响应键归一为这些 id。查询定义同时以显式筛选绑定把页面筛选器映射到 DQE 维度或时间目标,不得通过字段同名、JSONPath、字符串模板或表达式推断衔接关系。校验器在请求前检查输出字段覆盖、角色一致性、映射唯一性和筛选器引用。

## Considered Options

- 页面只保存精确查询执行引用,服务端解析不可变查询修订:治理和审计边界更强,但不满足当前直接配置并提交查询原文的要求。
- 页面内嵌查询定义,浏览器直接提交:接入链路最短且能让同一页面协议覆盖 SQL 与 DQE,因此采用。
- 页面顶层声明查询批次并由多个页面数据源引用结果下标:能显式控制物理请求,但把传输优化变成新的页面概念并扩大修改面,不采用。
- 数据网关透明合并同一调度窗口的 DQE 查询:保持一个页面数据源对应一个命名数据集,且页面协议不感知物理请求,因此采用。
