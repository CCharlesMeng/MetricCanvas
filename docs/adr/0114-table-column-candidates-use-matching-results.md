# 表格列候选值统一取本表匹配结果，已有表格同步升级

表头筛选需要枚举本表全部匹配行中目标列实际出现的值。现有维度取值域可能包含本表范围外的值，从当前页去重又会遗漏其他页。用户确认保留页面条件、固定业务条件、权限、查询结果绑定、已提交表格搜索和其他列条件，只排除目标列自身的表头条件。

## 决策

已有与新建表格的 select 表头筛选统一采用上述语义，保留现有声明，不新增 candidates.scope 开关，也不维护旧表格维度取值域分支。用户在“统一升级”与“显式启用”之间选择前者，以避免作者额外配置以及同一种表头交互存在两套规则。页面维度筛选器保持原语义，详情表格既有能力限制不在本次解除。

候选变化后，失配的已选值保持勾选，显示“已选，当前条件下无匹配”，允许用户移除；不得自动清空条件或把失配值混入实际可用候选。稳定值保留结果字段原始类型，显示名独立；首批不提供 null“空白”选项，空字符串不等于 null。

保留现有 NO_PERMISSION 支持：HTTP 和响应信封通过既有检查后，按 SUCCESS 或非空 data 的现行规则消费并归一化，包括 NO_PERMISSION 带非空数据；无数据的非成功候选仍按不可用处理。不得增加仅允许 SUCCESS 的候选门禁。消费资格和候选完整性分开判断，响应码不代替分页完整性证明；真实服务仍负责权限执行，产品裁决不证明当前部署权限已经验收。

## 与现行规则的关系

本决策局部修订 [ADR-0086](./0086-server-side-sorting-and-header-filters-under-query-pagination.md) 的表格候选行为，并与 [ADR-0051](./0051-additive-minor-versions-for-page-schema.md) 对既有字段语义变更的兼容要求存在冲突。用户明确选择统一升级，因此本次允许在已有页面声明上统一纠正 select 候选运行行为，不通过新主版本或新增 scope 保留两套表格候选语义。

这是限定于本次表格候选语义的例外，不是 ADR-0051 的一般性豁免，也不主张零使用例外。页面 JSON 继续可读；已保存的业务数据与 initial 不被本决策重写。实施时盘点依赖完整维度字典的已有页面并记录行为变化；其他字段结构或约束变更仍按版本策略独立评估，不在此预占 Schema 版本。

不扩大 [ADR-0107](./0107-query-page-windows-drive-result-dependencies.md) 已声明的上游查询窗口或固定业务 TopN。本表展示分页不改变候选范围；上游窗口改变并导致绑定集合变化，仍属于本表业务输入变化。数据消费规则延续 [host-contract](../host-contract.md)。

本 ADR 记录四项已确认产品裁决。本仓引擎已按此实现并完成本地验证，见[实施证据](../evidence/table-column-candidates/result.md)；这不确认真实 DQE 已支持按原查询结果去重，也不表示真实集成完成。架构草案、执行范围、验收与 DQE 对接见[唯一主计划](../plan/2026-10-21-table-column-candidates.md)。能力无法证明时明确不可用，不用当前页或全局字典冒充本表完整候选。
