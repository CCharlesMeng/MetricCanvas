# 指标条目一等化,Schema 元数据升到 1.1

[ADR-0031](./0031-metrics-as-data-context-discovery-anchor.md) 裁决指标以**指标条目**身份进入数据上下文快照并把 `formatVersion` 升到 `1.1`,但这一步从未落地。代码里的"指标"至今是某个表对象上 `roleHints: ['measure']` 的普通 `DataField`,可加性与时间聚合方式被 `tools/dqe-sim` 拼成一句受控中文散文写进 `description`:

```
统计期内发起过模型调用的去重客户数,与客户经营域的期末在册口径不同。可加性:不可加;时间聚合方式:均值。
```

这句话写出去之后没有任何消费者。全仓检索 `可加性`,只命中三类位置:`tools/dqe-sim` 的写入点、`packages/mcp/src/data-context.ts` 里一句承认"受控句式原文"的注释、以及测试夹具里的字面量。**仿真器按结构化的可加性决定跨坐标求和还是取均值,平台拿到的却只是一句话。**

散文形态有三个不可接受的后果:

- **结构只存在于仿真器内。** 对外契约(`docs/schema-metadata.schema.json`)对 `description` 的唯一约束是非空字符串,真实数据提供方没有义务产出该句式。据此解析会在开发环境成立、接上真实数据后静默失效。
- **闭集无法校验。** `可加性:可加的`、全角冒号、漏写后半句,今天都是合法快照。zod 与 JSON Schema 都碰不到句子内部。
- **拒绝规则无法实现。** [ADR-0039](./0039-derived-measure-templates-as-company-definitions.md) 要求"声明缺失时拒绝派生(错数比拒答更贵)",但散文让"声明了不可加""没有声明""解析失败"塌缩成同一个结果,而三者的安全行为并不相同。

`strictObject` 与 `additionalProperties: false` 挡住了新字段,这正是当初退化成散文的原因。封闭 schema 在按设计工作:它拒绝让一个只建模了一半的概念悄悄进来。

## 决策

**指标条目成为业务域级一等结构。** 快照中 `schema.metrics` 新增为必填数组,承载 ADR-0031 与 `CONTEXT.md` 已定义的指标条目字段:业务名、别名、口径说明、单位、是否为比率、可加性、时间聚合方式、可用维度。所属业务域由所在 schema 承载,不重复声明。

**度量不再是字段。** 指标条目从 `objects[].fields[]` 迁出,`roleHints` 闭集由 `dimension | measure | time` 收窄为 `dimension | time`。这是一次硬切换,不保留兼容分支:同一个指标同时以字段和条目两种身份存在会立刻产生第二个真源,而指标条目要承载的"可用维度"本就不是表列的属性。

**可加性保持三档,但修订不可加的措辞。** 闭集仍为 `可加 | 半可加 | 不可加`,时间聚合方式仍为 `求和 | 均值 | 期末值`。不采纳外部提案的四档动词模型(`SUM / RECOMPUTE / REQUERY / FORBID`):MetricCanvas 从不折叠已返回的数据行 —— 页内下钻是写入筛选状态后重新执行查询,探索改粒度是形成新的取数单元 —— 因此"重新查询"在本仓是默认且唯一的路径,不是档位表里的一个分支。四档中真正被本仓漏掉的语义,由措辞修订吸收:`不可加` 的含义由"不得跨粒度聚合"改为**"不得折叠已返回的数据行,可在目标粒度重新查询"**。`CONTEXT.md` 同步修订。

**`formatVersion` 升到 `1.1`,一次性切换。** zod、JSON Schema、示例快照、仿真投影与同面守卫测试同批变更,不提供 `1.0` 读取路径。

**语义面投影形状保持不变。** `SemanticSurfaceMetric` 现有字段(`name`/`aliases`/`description`/`type`/`unit`/`nullable`/`sensitive`)一个不动,新增字段为追加。因此问数链路(检索、消歧、取数单元派生、清单校验)本轮无需改动,可加性的**消费**留给 ADR-0039 的实现批次。

**本轮明确不做。** 派生度量模板声明(ADR-0039)、相对时间词表([ADR-0035](./0035-structured-relative-time-expressions.md))、指标归因定义([ADR-0043](./0043-attribution-diagnosis-as-a-sibling-analysis-form.md))、维度层级关系、比率指标的分子分母声明。它们的形状尚未设计,现在放进契约就是猜。本决策只交付**承载它们的那个结构**。

## Consequences

- 后续挂载这四项能力仍需继续递增 `formatVersion`,但届时是往既有指标条目上追加字段,而不是重建概念。一次性成本在本决策付清。
- ADR-0033 的恢复条件一("指标条目的可加性与时间聚合方式在目标域真实可用")**只被满足一半**。本决策让它变得可表达,不让它变得可用 —— 真实业务域里每个指标的可加性仍须由数据侧逐个声明,那是业务输入而非工程改动。不得据此认为计算数据集的挂起已解除。
- 示例快照中 `customer-activity` 域的 `NA客户数` 此前没有任何可加性声明(它早于组合式语义面)。迁移时须显式取值,本次按去重客户计数的性质声明为 `半可加` / `期末值`。这是一次基于口径说明的判断,不是从数据推断,真实接入时应由数据侧复核。
- `DataContextMatch` 新增 `metric` 分支,指标经检索命中时返回指标条目而不是字段。消费方按 `kind` 分支处理。
- 敏感标注对指标条目同样适用,但取值域受控句式只属于维度;指标条目不参与 `parseValueDomain`。
- 散文句式的写入点被删除。`description` 回归纯口径说明,不再承载结构化语义,`parseValueDomain` 仍是快照中唯一的受控句式解析(仅用于维度取值域)。

## Considered Options

- **保留度量字段,另加指标条目。** 迁移成本最低,但同一指标有字段与条目两个真源,且"可用维度"挂在表列上没有意义。真元归一违规,不采用。
- **只往 `DataField` 上加 `additivity` / `timeAggregation` 两个字段。** 改动最小,但指标条目的其余要素(是否为比率、可用维度)仍无处安放,下一次仍要重建结构;且它把"指标是一张表的列"这个与 ADR-0031"发现层描述 DQE 语义面而非 ADS 物理表"相悖的模型固化下来,不采用。
- **保持散文,由平台解析受控句式。** 零契约变更,但三条后果一条不落,尤其"接上真实数据后静默失效"是最坏的失败形态,不采用。
- **采纳四档 rollup 动词模型。** 与行业语义层一致,但 `REQUERY` 在本仓是默认路径而非分支,`FORBID` 因指标条目只覆盖度量而基本冗余,`RECOMPUTE` 依赖本轮不做的分子分母声明。引入四档会得到一张三格恒真、一格无法执行的档位表,不采用。
