# 平台创作共用入口，报告与看板分别装配，导航按需增量建立

IOC 概览与机会点列表需要多源、组合卡、Tab、层级地图、受控计算和宽表查询交互，当前面向报告的平铺装配不足以表达这些能力。用户确认保留一个平台 Skill、MCP 服务及 `compose_page`，在可信结果解析后、工作稿冻结前分派报告与看板的内部装配策略。组织规则分别维护，共享取数证据、结构构造、字段/筛选/计算校验、单份工作稿、CAS、草稿保存及精确产物预览，避免拆出两套生命周期或把全部差异塞进同一装配函数。

## 决策与边界

- 模型提供业务意图、可信引用及有界的页面结构计划；确定性工具解析依赖和绑定、构造闭集组件、校验页面并原子处理完整业务组合。模型不搬运任意页面 JSON、查询体、脚本或自授权标记。合法 partial 草稿可保存，完成度与保存/预览状态分开判断。
- report/dashboard 仍是页面的布局形态，不新增资产类别、权限或保存语义。创作表达按阅读目的选择组织规则，与布局形态独立；新创作输入本身不要求页面 Schema 升级。沿用 [ADR-0082](0082-explicit-business-sections-in-platform-authoring.md)、[ADR-0083](0083-platform-evidence-work-and-internal-draft-save.md) 与 [ADR-0090](0090-authoring-flow-hard-cutover-and-version-vocabulary.md) 的边界。
- 验收新路径后，公共工具、Skill、契约及 Bundle 整体切换，旧报告输入与被替代的装配退出生产。旧输入可留在迁移测试，已有报告行为及已保存页面的兼容读取继续回归；不维护长期双输入或以旧生产路径作失败回退。
- 比率口径、层级及业务映射可来自可信元数据，或由可信程序记录用户对具体规则的明确确认。用户确认不能制造物理字段、真实编码或执行能力，也不把无人负责的定义升级为公司口径。新增事实消费契约和确认回执须单列 Relay/提供方接入，不直接修改本仓内部 Adapter。
- 用户可先创建概览、随后决定下钻，也可先建目标页或选择已有目标。没有提出下钻时，概览可独立完成；明确要求但目标不可用时报告该项未完成，保留合法页面。目标可用后，以来源页当前修订及新可信轮次原子写入实际链接和参数绑定；来源修改、目标创建失败、回填失败及未知写入分别处理，不引入跨页事务。
- 本批不新增跨会话的长期下钻待办、占位导航或页面 pending 状态。已有导航继续消费实际 href 与 query（[ADR-0068](0068-plain-url-navigation-protocol.md)）。一条明确“创建目标并关联”的用户意图可授权两项动作，由可信程序分别供给单页轮次，不要求用户为技术步骤机械重复指令。

## 影响与验收

未选择独立 report/dashboard 工具或服务：当前目标没有独立权限、部署或容量隔离需求，而拆分会扩大 Relay 路由、状态与分发的迁移面。内部策略可以区分表达规则，真实公共不变量保留一份。也未选择模型逐项编排低级编辑：工具应拥有源、子树、计算和筛选之间的依赖，避免由模型安排几十步并处理局部失败。

公共工具输入发生不兼容变化，须独立升级工具协议并核对实际消费者；不与页面 Schema、Bundle、产物信封或外部 API 版本混用。新增投影、分页和排序需同步计划审核、规范授权摘要及 DQE 派生。跨页轮次、可信目标地址、业务确认回执和缺失能力的事实供给需明确接线；签名未变不能作为内部接入已兼容的证据。

实施顺序为冻结两页及报告回归、共同取数/证据/结构能力、列表纵切、概览纵切、联动与分发验收；工程先列表不限制用户先概览。确定性、真实模型、页面产物、浏览器及真实 Relay/Java/DQE/权限/门户联调分别报告。本 ADR 记录已确认的目标架构，不声明生成能力已实现。具体范围、源码定位、迁移与退出条件见 [实施方案](../plan/2026-10-12-report-dashboard-authoring-plan.md#4-架构调整与代码职责) 和 [两页调整目标](../plan/2026-10-12-report-dashboard-authoring-plan.md#2-两页目标与验收基线)。
