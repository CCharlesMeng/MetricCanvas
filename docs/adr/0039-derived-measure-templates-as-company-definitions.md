# 派生度量模板视同公司口径

环比、同比、占比是问数最高频的一类诉求，但它们不是语义面里的指标条目。按 ADR-0036，这类计算只能由模型现场生成 formula 走临时口径：每次阻塞确认、琥珀标注、登记缺口。这个待遇错配了它们的性质——环比的公式是业务通则，不是模型的发明；让用户每次为一个恒定公式点确认，是把治理成本转嫁给了使用者。竞品研究（`docs/reviews/2026-08-chat-bi-competitive-research.md`）显示声明化派生度量已是行业共识：Databricks metric views 以 `window.offset: -12 month` 声明同比，dbt MetricFlow 把 ratio/derived/cumulative 做成封闭指标类型。

## 决策

**数据上下文层新增派生度量模板声明，首批为环比、同比、占比三个封闭模板。** 模板声明公式与基期/总计的推导规则（环比基期=上一自然周期，同比基期=去年同期，占比分母=同查询总计），模型只能选用模板、不能改写公式。模板作用于指标条目产生派生指标（如「Tokens消耗量环比」）。

**派生指标视同公司口径。** 不触发 ADR-0036 的临时口径标注、不阻塞确认、不登记缺口条目；口径卡如实展示派生定义（模板、公式、底数指标、基期）供核查。这是对 ADR-0036 临时口径边界的显式收窄：公式由公司预先声明的计算不再属于「无人负责的口径」。模板闭集之外的计算（如「人均消耗」）仍走临时口径路径，ADR-0036 的全部治理原样适用。

**计算由本平台本地确定性完成，不依赖 DQE 原生能力。** 编排在执行阶段确定性扩展查询取基期/总计数据，装配层以纯函数计算比值。真实 DQE 是否原生支持派生语法属 #3 未知；确认后可将计算下推引擎，模板声明不变。

**派生受可加性与相对时间语义约束。** 按 ADR-0031，不可加指标禁用求和类派生，声明缺失时拒绝派生（错数比拒答更贵）；基期推导依赖 ADR-0035 的结构化相对时间表达（「上一自然周期」是相对表达的运算，不是日期减法的硬编码）。

## Consequences

- Schema 元数据需新增派生模板声明并升版本；`docs/schema-metadata.md` 与 JSON Schema 同步。
- ADR-0036「界面需区分三种数字」的分类不变：派生指标归入公司口径，不产生第四类视觉标注；区别只体现在口径卡的派生定义展示。
- 高频临时口径的缺口条目（如反复出现的「人均消耗」formula 形状）成为新模板/新指标的立项信号，经治理收件箱（ADR-0041）走人工采纳，不自动扩模板闭集。
- 黄金问题集（ADR-0037）应补充派生类样本，覆盖模板命中与模板外降级两侧。
- 业务口径约定（同比是比同月还是同期累计）确认后只改模板声明，不改实现。

## Considered Options

- **维持全部走临时口径。** 治理最保守，但高频通则每次确认、公式每次由模型重新生成（可能不一致），把最常见的诉求留在信任最低的层级，不采用。
- **等 #3 验证 DQE 原生派生能力后下推引擎。** 避免本地计算，但被未知能力阻塞整个批次，且口径定义权交给引擎方言，不采用（保留为后续优化路径）。
- **允许模型生成公式但白名单校验。** 表达力更强，但同一诉求可能生成不同公式，白名单校验通过不等于口径一致，不采用。
