# 静态平台以自包含 SPA 直连外部服务，运行配置由集成应用注入

平台要以纯前端静态产物部署（地图 [#95](https://github.com/CCharlesMeng/MetricCanvas/issues/95) 的 [#101](https://github.com/CCharlesMeng/MetricCanvas/issues/101)），静态化后它没有服务端可以藏凭据、代理请求或解析身份。本决策定下浏览器怎么拿到端点与凭据、平台在集成门户里长什么形状，以及为将来接入 qiankun 预留哪些接缝。与 ADR-0066（自包含渲染引擎与集成应用边界）、ADR-0069（请求凭据归集成应用）、ADR-0072（集成应用改名）配套。

## 两条被推翻的前提

**DQE 认的是用户态 header token，不是 SSO Cookie。** [ADR-0063](./0063-relay-dqe-facts-revise-authoring-boundaries.md) 记载 2026-09-02 对 `CDINL2DataBuilderService` 的实地调查：DQE 执行接口以用户的 `X-Auth-Token` + `X-Operator-Id` 鉴权并注入行级过滤；创作期 Python 适配器已按此接线（缺 token 直接失败，HTTP 401 映射为需要登录）。地图 #95 在 charting 期记的「靠 CORS + 内网 SSO」把凭据形态设想成 Cookie，与该事实不符——浏览器 `credentials` 策略再怎么配，也满足不了一个 header token 契约。**该条边界按本决策更正为「用户态 header token」。**

**现有取数通路从未按该契约接过线。** `createServerDataGateway` 接收 `actor` 但在解构时丢弃，`getServerDataGateway` 不传 `headers`；`createDqeGateway` 的 `headers` 默认为空、`credentials` 默认 `same-origin`。所以浏览器直连不是把已有身份搬个位置，而是这三个身份请求头的**第一次真实接线**。#101 正文「包装数据网关并绑定 actor」的描述据此更正。

## 裁决

**平台只认「挂在集成门户里」一种真形态。** 凭据由门户提供。独立 URL 保留为开发与演示形态，且明确不接真实 DQE。理由是任何「独立部署也能连真 DQE」的方案都要求本仓自建换取 token 的逻辑，直接违反 ADR-0069「本仓不新增身份适配器、登录体系或用户切换器」。

**平台不实现微前端协议，它是一个自包含静态 SPA。** 门户用什么方式装它（iframe、整页跳转、菜单链接，或将来的 qiankun）是部署期的事，平台不为此写分支。这与 ADR-0066 给渲染引擎定的调子同源，只是抬高了一层：引擎不关心微前端协议，平台同样不关心。「只认挂在门户里」约束的是**凭据从哪来**，不是**代码要长成子应用的形状**——这两件事在 #101 的早期讨论中被混为一谈。

**运行配置由集成应用注入，全应用只有一个模块碰注入源。** 注入面是一个由本仓定义的全局对象，五个扁平字段：

| 字段 | 用途 |
|---|---|
| `dqeEndpoint` | DQE 执行地址。填相对路径即同源反代，填绝对地址即 CORS 直连 |
| `pageAssetsBaseUrl` | Java 页面资产基址 |
| `authToken` | `X-Auth-Token` |
| `operatorId` | `X-Operator-Id` |
| `workspaceId` | `X-Workspace-Id` |

不加回调、不加嵌套、不加版本号：重登归外层，身份校验归服务端，这个对象只剩「发请求需要的东西」。名字由本仓定义、门户来满足，方向不能反过来去猜门户已有的全局变量叫什么。

**读取必须经由单一模块，其余代码一律调它的读取函数。** 该模块每次调用都重新取源、不在启动时快照，因此外层刷新 token 后下一次请求自然生效，平台里关于登录的代码是零行。散在每个取数点直读全局对象是明确禁止的写法——那会让将来「配置改从 qiankun `props` 来」变成一次散弹式修改。

**缺配置照常启动，取数时失败。** 页面目录与内联页面不需要凭据也能看，启动即停会把「配置错了」放大成「整个应用打不开」。但缺失必须在错误里明说是**集成应用未注入运行配置**，不能混进普通网络失败——否则内部部署的第一个错误现场会被误判成 DQE 侧的问题。

**同源反代与 CORS 直连不二选一。** 两条部署形态共用一份代码，差异只在 `dqeEndpoint` 是相对路径还是绝对地址。地图 #95 那条「不走网关反代到同源」收窄为「**不由本仓提供反代**」，选择权交给部署环境。DQE 与 Java 页面资产需允许 `x-auth-token` / `x-operator-id` / `x-workspace-id` 跨源并允许携带凭据——这是对提供方的诉求，归 #3 / #105，本版不作为前置要求。

**`X-Operator-Id` 是集成应用声明的 actor，不是已验证的 actor，前端不做任何校验。** 可信性由同行的 `X-Auth-Token` 承担。前端既解不开 token，也挡不住能改请求头的人改校验代码，所以这里的交付物是这句话本身，不是代码。对服务端的诉求（二者不一致时应由服务端拒绝）归 #105 对账。按地图对身份可信性的放松要求，此处与 #105 的 Java 同名请求头、#106/#107 的 `adapter.getCurrentUser` 互相引用：同一个用户在这几条链路上必须是同一个人，但取到他的方式不同，差异写下来而不抹平。

**重登不归平台。** DQE 的 HTTP 401 按 ADR-0063 已有的「需要登录」语义呈现，平台不弹登录框、不做刷新重试、不提供回调。外层处理重登并更新注入对象即可。

**浏览器直连覆盖 DQE 与 Java 页面资产两条。** 平台前端此前没有页面仓储，页面目录、页面详情、精确修订读取与工作台保存修订都是散在组件里的裸 `fetch('/api/pages/...')`；静态化后这些自家路由一起消失。这几处先收拢成一个页面资产客户端再换端点，不在组件里各自拼 URL。随静态化一起下掉的发布治理与模板库界面不迁。

**`/api/data/*` 两个自家端点与 `createPlatformDataGateway` 一并删除**，平台直接使用 `createDqeGateway`。不删就是双轨。`apps/canvas/frontend-baselines/api.md` 把它登记为「`API-1` 的第二个实现」，删除时同步该基线。

**`apps/canvas` 的数据网关改用同一个注入面**（`VITE_DQE_ENDPOINT` 退场），因为 `docs/host-contract.md` 称它为契约的参考实现，不改就会示范一条已作废的路。`VITE_PLATFORM_URL` 是 canvas 自己选静态页面还是连平台的本地开关，与凭据无关，保留。

**mock 用户切换器删除。** `+layout.server.ts` 投给外壳的 `mockUsers` 与 `+layout.svelte` 的下拉框在静态化后必然失效，ADR-0069 也明确本仓不建用户切换器。当前用户改为显示注入进来的 `operatorId`。

**为 qiankun 预留四条接缝，另三条不预留。** 判据是「将来接入时改动集中在几个文件」：集中的不预留，散的现在就立规矩。

| 接缝 | 现状 | 处置 |
|---|---|---|
| 配置读取点 | 尚未实现 | **预留**：单一模块，见上 |
| 路由前缀 | 7 处硬编码绝对 `href`，无 `paths.base` | **预留**：统一走 base，否则每新增一个页面就再犯一次 |
| 视口尺寸与固定定位 | rail 是 `position: fixed` + `100vh`，多个组件用 `calc(100vh - ...)` | **预留**：改成容器相对，应用不再假设自己占有视口 |
| 全局样式 | `+layout.svelte` 有 `:global(:root)` | **预留**：挪到应用根节点选择器；CSS 变量继承，子组件不用改 |
| 生命周期导出 | 无 | 不预留：一个入口文件加构建配置 |
| 资源 public path 改写 | 无 | 不预留：构建配置 |
| 卸载清理 | 组件级 `onDestroy` 已有 | 不预留：只要不新增模块级副作用 |

`src/lib/prototype/` 下的样式原型不计入，其去留归 #102。

## 取舍

- **不采用「平台实现 qiankun 生命周期」。** 微前端的复杂度在生命周期与沙箱，不在装载；那些代码全要对着一份本仓还没拿到的门户契约写。自包含 SPA 加四条接缝能拿到同样的将来可接入性，且今天不欠外部输入。
- **不采用运行时配置文件（`/config.json`）。** 它多一条与注入面并行的配置通道，而注入面无论如何都得存在（凭据不可能放进可被任意 GET 的静态文件）。一条路比两条路少一半的错配面。
- **不采用构建期 `VITE_*` 注入端点。** 一份产物要在多环境部署，构建期常量意味着换环境重新构建；且凭据绝不能进构建产物。
- **不采用导出配置函数供门户调用。** 只在微前端或 npm 集成下成立——独立应用形态下父页面拿不到平台的模块导出。
- **不采用照抄门户已有的全局变量契约**（如另一个仓 `CBCBIDataVWebsite` 用的 `window.currentLoginUser` / `window.relogin()`）。那是门户方的契约，本仓无权定义，现在照抄等于替对方猜。
- **不采用前端校验 `X-Operator-Id` 与 token 是否同一人。** 做不到也没意义，见上。
- **不采用现在就做 qiankun 接入的最小验证。** 验证留到实现阶段，代价是 `paths.base` 那个风险要多躺一段时间，见下。

## 后果

- **SvelteKit 的 `paths.base` 是构建期常量，而 qiankun 的 activeRule 前缀由宿主在运行时分配。** 这两者对不齐是本决策已知但未验证的风险；「路由前缀走 base」这条预留能否原样满足 qiankun，要到实现阶段接入验证时才知道。同类风险还有：SvelteKit 静态产物是 `index.html` 加带 hash 的资源，不是 qiankun 习惯的 UMD 库入口。两条都不阻塞本版，但不得默认它们成立。
- **issue #3 的凭据验收条件按种类改写**：服务态凭据（服务账号 token、数据库口令）不得进入浏览器产物、页面文档、日志或仓库；用户态凭据由集成应用在运行时注入，只存在于内存，不得写进构建产物、不落日志、不入仓库。原文「凭据只存在于服务端配置」写于平台还有服务端时，静态化后按字面读会禁掉唯一可行的方案。改写同步回 #3 本身，不只留在本 ADR 里。
- **本决策不改实现。** 按 #95「决策票本身不改实现」，配置模块与路由 base 并入静态化执行票，视口尺寸与全局样式整改单开执行票——拆开是为了不让「改视觉」卡住「能不能连上 DQE」。
- 平台不再有服务端取数入口，因此 ADR-0069 登记给 #101 的「静态集成应用提供端点、头部与 Cookie/credentials 策略」由注入面兑现；仿真 CORS 覆盖的场景仍不代表生产服务已支持跨源凭据。
- `tools/dqe-sim` 当前的 `access-control-allow-headers` 是 `content-type,client,env`，不含上述三个身份头，按新契约接线的第一个跨源请求会死在预检上。补齐是顺手执行项，不构成决策。
