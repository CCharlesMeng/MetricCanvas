# 页面元数据保持局部显式

看板页面不提供 `fieldDefaults`、`fieldSets` 或 `columnSets`，也不在顶层提供 `definitions`。每个页面数据源在当前位置声明自己的完整结果字段契约和查询字段映射，每个表格在当前组件中声明完整列。阅读者不需要跳转到文档其他位置或理解继承规则才能确定页面数据源和组件字段绑定的含义。

`query` 页面数据源可以把 `fields` 按 `dimensions` 和 `measures` 分组。分组名只补全与其重复的字段角色；每个页面字段仍必须显式声明 `queryField` 和 `type`，并在需要时就地声明 `label`、`unit`、`nullable` 和 `defaultFormat`。页面模块在不修改原文档的前提下把分组形式解析为统一运行时使用的完整 `Page`。

与查询定义一起保存的 `source.initial.rows` 保持 DQE 原始输出字段名。页面模块在同一解析边界使用当前数据源已经声明的 `queryField` 将其归一化为稳定页面字段；这不是第二套映射声明。

页面字段 id 与 DQE 字段名仍永不隐式同名匹配。分组形式不引入字符串简写、默认类型、默认格式、引用、参数、插值、合并或表达式。

## Consequences

- 页面数据源和表格可以局部、顺序地阅读与修改；
- 页面元数据可重复出现相同的结果字段契约和表格列；
- 网络和缓存体积通过 JSON 最小化和 gzip 处理，不由领域 DSL 承担物理压缩职责；
- 如果 AI 上下文体积成为已测量的瓶颈，应在专用适配器后生成紧凑交换形式，不扩大页面元数据接口。

## Considered Options

- 字段默认值、结果字段集和表格列集：能将当前页面的最小化 JSON 减少约 28%，但 gzip 后只减少约 7%，同时引入跳转、继承、展开顺序和引用错误规则，不采用。
- 只做 JSON 最小化和 gzip：不改变页面元数据含义，适合传输与缓存，采用。
- 短键、位置元组或通用宏：字节数更少，但扩大人工评审、AI 生成和故障定位所需的接口知识，不采用。
