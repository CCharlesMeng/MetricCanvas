# 指标履约只查询 DP 并以数据服务目录验真

MetricCanvas 通过 DP 的稳定指标 ID 查询候选和轮询 `draft` / `published` 状态,不在生产集成中创建、修改或发布 DP 指标。DP 返回 `published`、最终指标 code 和目标数据服务目录后,MetricCanvas 仍须从当前数据服务目录发现该 code,并验证原子指标需求所需维度与聚合全部可用,才能标记为已履约。

DP 属于外部治理上下文。MetricCanvas 只保存页面搭建蓝图、指标需求组、原子指标需求、用户确认、数据开发确认、DP 稳定 ID、验真结果和审计记录;不复制 DP 的内部阶段、负责人、预计时间或阻塞原因。测试仿真的 `__admin` 端点只供测试人员推进外部状态,生产代码不得调用。

## Consequences

- 生产 DP 适配器只有“查询候选”和“按稳定 ID 查询指标”两个公开能力;MCP 候选工具必须返回全部候选、匹配理由和能力缺口,不得自动选择。
- 新指标先经业务确认和独立数据开发确认,数据开发在 DP 完成创建后回到 MetricCanvas 关联稳定 ID。
- MetricCanvas 轮询 DP 与数据服务目录;超时或暂时不可用只记录同步错误,不回滚当前履约状态。
- DP `published` 不等于已履约;数据服务目录缺失 code 或能力不完整时继续等待并保留证据。
- 指标需求组就绪时只产生站内通知,不后台修改已发布看板页面。用户点击“继续页面”后读取最新页面修订,展示差异并形成新的页面修订。
- 页面可在指标需求组未完全就绪时由用户明确选择降级发布,发布前必须再次提示未满足依赖。

## Considered Options

- MetricCanvas 直接调用 DP 创建和发布接口:流程更短,但跨越外部治理边界并把 DP 的权限与状态机泄漏进平台,被否决。
- 看到 DP `published` 就视为已履约:无法证明数据服务实际可查询该 code 和所需能力,会产生可发布但运行时报错的页面,被否决。
- 复制 DP 全部内部状态到指标需求队列:展示信息更多,但形成第二事实源并与 DP 漂移,被否决。
- DP 发布后后台自动修改已发布页面:减少一次人工动作,但绕过页面修订、diff 和发布确认治理,被否决。
