# 组合查询源显式启用按需分页并由最后操作成员决定表格条件

记录关联完整读取后本地分页会使首屏请求量随总记录数增长。将 batchSize 调小只会增加完整读取批次，不能满足按页取数。DQE 不执行跨源关联，跨源查询顺序由共享执行器管理。

Schema 6.76 为 pagedJoin 增加显式 pagination.mode 为 query 的分支，pageSize 和 batchSize 均须写出，本地创作默认写10。未启用新分支的历史组合源继续既有完整关联策略。新分支不允许 fallback；记录变体的批次只在 pagination 配置，不声明完整读取预算、本地时间筛选或自动生成记录标识。

domainMember 仍决定业务行域和最终行粒度。选页成员按后端条件排序、计数并取得当前页，其他成员仅按本页关联键补列。记录模式保留每条基准记录，以真实唯一记录字段标识；不能以补列成员的10个项目替代10条基准记录。可选页能力不成立时明确不可用，不自动扫描全集，也不进入异常数据完整恢复路径。

表格同一轮只保留一个成员的排序与过滤。后提交成员操作清除其他成员的表格状态，同成员条件保留，页码归零。页面、固定业务和权限条件不被清除。TableSession 原子持有已提交状态，SourceProgram 管选页补列，QueryRunner 保留候选实现的优先级、取消和缓存职责。固定 resultBindings 及成员普通结果不被改写。

新模式关闭候选自动完整预热，原模式保留空闲预热。打开菜单基于预期提交后的成员条件查询，查询输入与缓存身份一致；不提前提交表格视图。只在单成员可准确代表组合候选域时复用已注册的候选适配器，不能强制调用完整关联；候选200行批次、默认1000行总预算与组合浏览10/10分别管理。

表格条件增加显式 isNull。null 不等于空字符串；缺失补列与字段为 null 都属于“为空”。目前没有已确认的后端完整空值编码，新查询路径在提交前明确说明不可用，保留原页，不以当前页过滤或只查补列表 null 冒充完整语义。局部能力提示使用业务语言，不改变普通后端错误的既有处理。

本决策局部修订 ADR-0108 的自动完整回退，仅适用于显式新分支；局部修订 ADR-0114 的候选预期上下文与空值操作边界。新页由本地创作默认选择新分支；旧页在实际编辑时检查能力后迁移，不批量重解释现有声明。实现、迁移及分层验收见[主计划](../plan/2026-10-29-paged-join-on-demand-pagination.md)。
