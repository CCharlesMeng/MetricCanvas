# 挂起级联页面数据源的输入绑定语义

看板页面需要支持“先查询 Top 客户,再以这些客户查询详情”等级联场景。在 ADR-0014 的查询产物模型下,这意味着一个 query 页面数据源执行完成后,另一个 query 页面数据源以其结果字段集合作为受控输入。

已确定以下边界:

- 页面和浏览器只提交受治理的查询执行引用、参数及数据源依赖声明,不提交 SQL 或 DQE 原文;后端服务决定实际执行 SQL 还是 DQE,内部是否采用适配器不进入页面协议。
- 级联采用集合式调用,不对上游结果逐行扇出请求。
- 数据源依赖声明在页面数据源之间;组件仍通过命名数据槽消费上游或下游页面数据源。
- 数据源依赖引用上游页面数据源的稳定结果,不引用某个组件的局部数据快照。
- 表格可由前端决定每页 10 条、15 条等局部视图,统一运行时将其作用于表格直接消费的数据源;该局部视图不隐式改变其他数据源的依赖输入。

本决策保持 proposed 且暂不实现。尚未找到能覆盖实际后端能力的输入绑定语义:把上游单字段值集合统一翻译为下游 `in` 筛选并不总是可行。在明确 SQL 与 DQE 共同支持的受控参数模型之前,不得向页面 schema 加入临时 `inputs`、表达式或任意结果转换能力。

恢复设计时还需依次确定空集与失败传播、输入集合上限、循环依赖校验、缓存键和取消语义。上述问题未解决前,当前页面 schema、校验器、查询编排和数据网关行为保持不变。

## Considered Options

- 上游单字段集合统一绑定为下游 `in` 筛选:结构简单,但无法可靠覆盖实际输入选择方式,暂不采纳。
- 对上游每一行分别调用下游查询:会引入无界扇出、部分失败与结果拼接语义,不采用。
- 读取某个组件的当前页快照作为依赖输入:同一页面数据源被多个组件以不同局部视图消费时语义不唯一,不采用。
