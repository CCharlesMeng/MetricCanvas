# 口径卡升级为控制面板：token 行呈现、要素就地修改与已验证查询快路径

ADR-0037 把口径卡定义为执行前的完整生效范围回显与条件阻塞确认。体验研究（`docs/reviews/2026-08-chat-bi-competitive-research.md` §7.5）显示「事前结构化回显」阵营的纠错优势在**要素级可改**：SuperSonic 解析卡的日期与筛选直改 1–2 步收敛且不过模型，ThoughtSpot 的 token 点改是四家最短动线。当前口径卡只能整卡确认，错一个筛选值要整轮追问；且每轮都以完整卡片呈现，非阻塞轮次的视觉重量与其信息价值不成比例。

## 决策

**口径卡默认以 token 行呈现，阻塞场景保持完整卡。** 非阻塞轮次压缩为一行要素 token（指标、时间、筛选、验证参照）加「详情」展开；消歧候选与临时口径确认这两类必须打断用户的场景保持完整卡片——打断处的醒目是功能不是负担。

**时间与筛选要素就地可改，修改是一次不经模型的数据校准。** 点时间 token 展开相对时间词表的预设选项与日期范围，点筛选 token 直改取值，选定即原地重跑。这次修改复用既有「数据校准」语义：产生新的生效查询与完整步骤事件（口径修订、执行、行就绪、文档就绪）落入分析会话，回放链路不断；除被修改的要素外，其余生效范围不变（ADR-0037「未提及的显式设置保持不变」对确定性修改同样成立）。指标与分组维度的修改仍走追问——它们需要重新检索与消歧，不属于纯确定性修改。执行后的口径卡同样可改：控制面板不区分「执行前确认」与「执行后调整」，两者是同一张卡的同一组交互。

**已验证查询命中走快路径。** 检索阶段词面高度匹配已验证查询时，跳过口径成形的模型调用，以其查询定义填参执行；清单校验与真实执行不可跳过（ADR-0032 的验真闭环对快路径同样成立）。命中宁缺勿滥：模糊相似不触发快路径，只作为生成参照。口径卡回显**验证参照**（已验证查询名、背书人、背书时间）——答案参照了谁认可的口径，是信任呈现的低成本高价值信息（Snowflake confidence 回显的先例）。

**消歧候选默认预选提问者本人的历史选择。** 信号取自已落库的会话步骤事件，按 actor 隔离、不跨用户、不进语义面。预选只是呈现优化：候选卡永远阻塞等待确认，用户可改选——这不构成 ADR-0037 否决的「系统替他选完再问对吗」，因为选择动作仍由用户完成，且预选的是他自己上次的决定而非系统的判断。

## Consequences

- 步骤事件契约需新增口径修订事件；口径卡修改轮不消耗模型调用预算，但消耗执行次数预算（ADR-0032 的运行内上限适用）。
- 快路径是编排状态机的旁路分支：命中时「口径成形◆」被跳过，其余阶段不变；黄金问题集应包含命中与不命中两侧样本，防止快路径判定过宽。
- 消歧偏好属个人层数据，随会话保留期清理；接入真实身份（ADR-0030 未决事项）之前不得跨用户聚合。
- 验证参照回显要求检索结果携带已验证查询的背书元数据，数据上下文快照的已验证查询条目需含背书人与背书时间。

## Considered Options

- **全要素就地可改（含指标与维度）。** 动线最短，但指标修改需要在卡内内嵌候选检索与消歧,交互复杂度回到整轮追问之上,且绕过消歧治理,不采用。
- **口径卡保持确认卡,修改一律走追问 patch。** 实现最省,但每个要素级纠错都要过一次模型(慢、贵、有漂移风险),纠错动线与竞品差距明显,不采用。
- **修改即时生效但不落步骤事件。** 交互与实现都最轻,但会话回放出现「结果与事件流对不上」的断链,违反 ADR-0030/0037 的可回放原则,不采用。
- **预选达到阈值后跳过确认直接执行。** 更顺滑,但系统开始替用户做决定,违反 ADR-0037 红线,不采用。
