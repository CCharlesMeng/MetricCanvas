# 按外部 Java 契约单次保存，发布更新页面状态

用户确认以 `service/platform-java.yaml` 快速接入。Platform 与统一创作的可信程序采用单次提交、成功回执确认；冲突、超时和不可信回执保留工作并停止，不要求当前服务提供幂等查询或历史精确回读。发布由明确的用户操作将当前资源更新为发布态，不等待参数提取候选、发布租约或不可变模板接口。

页面资产 Interface 与 Java Adapter 分离；路径、字段、业务码及响应转换由 TS/Python 各自的 Adapter 集中处理，消费同一契约样例。目录保留资源身份，打开/修改按资源 ID 定位，修订 ID 用于提交基线；不按 pageId 的最大修订猜选记录。一次 AI 保存只由可信程序提交，前端消费其保存回执而不重复保存；完整文档保留在程序通道。

这部分替代 ADR-0008 的强保存/发布治理前置和 ADR-0078 的本期模板发布旅程，调整 ADR-0079 的强 latest/保存后精确回读要求；身份、固定本轮基线、候选校验和迟到结果隔离保持。普通问数的临时页面态和显式沉淀边界不变。`execute` 与筛选历史归运行态，不进入本期 Platform 改造。

代价是未知写入需要人工核对，不能自动恢复发送；草稿历史只能展示服务返回的摘要，回退没有跨窗口基线检查，也不承诺一定追加新修订。草稿保存会更新当前资源状态，不承诺存在独立且不受编辑影响的已发布副本。旧未决记录不能因切换新模式而重放，兼容强保存实现不作为目标部署的回退。

设计与分批实施见 `docs/plan/2026-09-16-java-page-assets-architecture.md`、`docs/plan/2026-09-16-java-page-assets-implementation.md`。决策被接受不表示外部 Relay 接线或真实服务联调已经验收。
