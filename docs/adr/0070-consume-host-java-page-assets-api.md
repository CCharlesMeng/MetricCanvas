# Java 页面资产由宿主提供，本仓负责接口消费

2026-09-07，#105 grill 中用户明确纠正：“Java 服务不需要我们真的实现，直接对接即可”。
Java 页面资产服务按外部宿主提供的能力接入；本仓负责前端请求适配和消费验证，不负责设计、
实现或交付 Java 服务。该决策部分取代 ADR-0062 的第一方 Java Module 建设前提，
Java 承担页面资产的系统所有权不变。

POST/PUT/DELETE 的行为、资源 id、存储、修订实现及 SLA 以提供方接口为事实来源。
#105 本轮提出的“POST 首建、PUT 追加”“DELETE 转为目录隐藏”“取消 page_metadata_id”
和“响应改为 object”均未获用户确认，不能写成裁决或反向要求提供方按本仓方案实现。
先消费 #105 评论中已提供的 Swagger；请求和响应不对称时由适配器按该契约处理。

数据请求的头与相关 Cookie 继续由宿主决定（ADR-0069），不新增本仓身份机制。
目录发现、按页面身份加载和精确修订预览需要的接口若未在资料中给出，只登记为待确认事实；
不猜路径、不把“未写到”等同“不支持”，也不以浏览器映射表、假结果或新增 Java 实现补洞。
产品能力是否已兑现仍须消费验证，不能因本仓不实现服务而自动标记完成。

现有 `metriccanvas-page-assets/` 与旧 Swagger 是历史实现和对照资料，不自动作为宿主
当前接口真源。#99 已有 Java 内存链路只能证明其所实现的旧接口行为，不能据此要求外部
服务支持 `PAGE_ASSETS_STORE=memory` 或宣称宿主新接口已验证。现存 Java 代码的去留由
#102 另行处理，本次不删除。#101/#104 以实际宿主接口完成前端接线和验证。
