# 摘要默认由页面文档返回，SSE 生成必须明确声明

看板页面中的摘要、总结和已确认分析结论，默认使用 `text` 组件，由后端返回的页面文档在 `props.body` 中携带正文。“AI 总结”、“风险总结”等可见标题、页面上已有查询数据，以及文案由 AI 产生过，都不足以推断运行时需要生成。

只有需求或设计明确声明“在统一运行时中基于关联数据通过 SSE 动态生成”时，页面搭建 Agent 才能选择 `aiSummary`。一旦页面文档显式声明 `type: "aiSummary"`，其运行语义继续遵循 ADR-0019：使用 `promptTemplate` 和 `relatedData` 组装请求，并在组件边界内处理私有 SSE 协议。

两种组件之间不做隐式升级或降级：统一运行时严格按页面文档的 `type` 渲染。“默认 `text`”是创作期组件选择规则，不是为不完整的 `aiSummary` 添加运行时兜底。

## Consequences

- 后端已生成或已确认的摘要随页面文档返回，浏览器不再为此发起 AI 生成请求。
- 页面搭建 Agent 和组件能力目录必须把 `text` 作为摘要默认选择，不得根据标题或数据自动选择 `aiSummary`。
- 需求明确声明 SSE 时，`aiSummary` 能力仍保留，且继续受关联数据字段白名单与会话隔离约束。
- 场景页面测试应明确断言其摘要组件类型，防止后续改动意外引入 SSE。

## Considered Options

- 只要标题包含“AI”就自动选择 `aiSummary`：展示文案不等于运行时传输协议，不采用。
- 只要摘要可以引用页面数据源就自动选择 `aiSummary`：会在未经声明时增加数据出站和运行时失败点，不采用。
- 统一运行时在 `aiSummary` 配置缺失时自动改渲染 `text`：页面文档不包含可供兜底的正文，且会掩盖错误声明，不采用。
