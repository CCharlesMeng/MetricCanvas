# GraphQL 与数据接口以数据网关适配器接入，不由组件直连

数据侧的消费链路除 DQE 外还有表服务、GraphQL 与 REST 数据接口。挂起计算数据集（ADR-0033）之后，DQE 表达不了的取数场景需要一条出口，否则问数在这些场景上无路可走。“直接调用 GraphQL 或数据接口”存在两种读法：组件自己发请求，或数据网关新增一类执行适配器。二者对不变式的影响完全不同。

## 决策

**GraphQL 与 REST 作为数据网关的执行适配器接入，组件与浏览器不得直连远程数据端点。** ADR-0014 的“新增执行环境必须接入数据网关，组件不得直连”原样适用，不因协议不同而放宽。因此这是一次对既有分发点的扩展，不是破坏性变更。

**页面数据源的 `query.language` 从字面量升级为判别联合。** 现有 `dqe` 分支不变，新增分支各自声明本协议所需的查询定义形状。判别键仍是 `language`，`filterBindings` 与 `initial` 的语义不变：筛选绑定继续以页面筛选器 id 映射到该协议的具体输入位置，绑定形状按协议分支定义。

**端点、凭据与 Header 不进入页面文档。** 页面只声明协议分支与协议内的查询定义，具体端点与凭据由服务端配置持有。这与 ADR-0009 的 Secret 边界以及 `aiSummary` 不暴露端点与 Header 的既有处理一致。

**响应摊平语义由适配器负责，且必须是确定的。** GraphQL 与 REST 返回嵌套结构，而页面数据槽消费的是归一化行集。适配器必须显式声明从响应到行集的取值路径：哪个节点是行数组、哪些字段提升为行字段、数组内嵌数组如何处理。**不允许按响应样例自动推断行集位置**——理由与 ADR-0032 拒绝从样例推断字段契约相同：样例为空或结构可变时判定不唯一。摊平后仍走同一份结果归一化与结果字段契约校验，受控对象数组与受控语义 HTML 继续按 ADR-0026、ADR-0028 处理。

**发现层需要第二种形状。** ADR-0031 的发现层描述的是 DQE 中文语义面。GraphQL/REST 路径没有这层业务语义，其可枚举面是操作名、参数与响应字段。因此这些路径接入时必须补一份对应的发现描述，且必须同样携带口径说明与单位；缺少这层描述时该路径只能由人工构造查询，不进入问数的自动生成范围。

**创作期验真对所有协议一视同仁。** ADR-0032 的清单校验 → 真实执行 → 物化结果字段契约顺序适用于每个协议分支，不得因协议“更简单”而跳过真实执行。

## Consequences

- `packages/page` 的 `dqeQueryZ` 从单一对象改为判别联合的一支，页面 JSON Schema 与 `PAGE-METADATA.md` 需同步；已有页面文档不需要迁移，因为 `language: 'dqe'` 分支形状不变。
- 数据网关新增适配器，但 Interface 不扩张：查询执行端口与结果归一化能力仍是同一个。
- 统一运行时无感知：它继续只按页面数据源请求数据网关，不知道背后是 DQE 还是 GraphQL。
- 摊平规则成为页面文档的一部分，因此它同样受不可变修订与发布治理约束，不会被静默改写。
- 问数在这些路径上的自动生成能力取决于发现描述的完备度，早期很可能只能人工建页；这是有意的下限，不视为缺陷。
- 表服务路径同样按本决策接入，本 ADR 不为它单列分支，待真实需求出现时再定形状。

## Considered Options

- **组件直接调用 GraphQL/REST。** 接入最快，但破坏“远程查询只经数据网关执行”的运行时不变式，且端点与凭据会渗入页面文档与浏览器，不采用。
- **由适配器按响应样例自动推断行集位置。** 免去声明成本，但结构可变或空响应时行为不确定，且把契约判定推回样例推断，不采用。
- **为每个协议新建独立的页面数据源类型。** 会让 `inline`/`query` 的二分变成 N 分，组件侧数据槽消费逻辑随协议增长，不采用；协议差异应止步于 `query.language` 分支内部。
- **等计算数据集恢复后统一解决。** ADR-0033 的恢复条件不在短期内成立，问数会长期缺出口，不采用。
