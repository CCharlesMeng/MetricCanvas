# 查询产物取代指标成为页面的数据基础

新版本决定不再要求业务需求先映射到预定义指标，也不再把指标 code、指标目录、`METRIC_GAP` 和 DP 指标履约作为页面构建前置条件。已确认需求在受控的数据上下文快照中经 NL2SQL 或 NL2DQE 生成查询候选，候选通过权限、安全、资源、真实执行和结果验真后保存为查询产物的不可变查询修订；看板页面只持有精确查询执行引用、参数绑定和结果字段契约。

该决策把治理对象从“预定义指标”改为“可执行且可复现的查询”。度量仍作为结果字段角色存在，但不再是需要提前注册的领域资产。运行时只执行页面修订绑定的查询产物，不运行 NL2SQL/NL2DQE；跨 SQL/DQE 结果的计算通过服务端组合查询完成，不在页面 DSL 或浏览器中建立计算语言。

本 ADR 取代 ADR-0011 的 query 字段解析方式和 ADR-0012 的指标履约流程，并修订 ADR-0001、ADR-0003、ADR-0005、ADR-0006 与 ADR-0008 中“指标/维度结构化查询、数据服务唯一入口、复杂计算必须下沉为数据服务指标”的相关前提。自研领域 DSL、命名页面数据源、纯渲染组件、不可变页面修订、发布租约和人工确认发布仍然有效。

## Consequences

- query 页面数据源不再声明 `metrics`、`dimensions` 和全局 `aggregation`，而是引用精确查询产物修订并把筛选状态绑定到参数契约。
- 结果字段契约由查询静态分析与真实执行验真形成，字段角色使用 `dimension` 和 `measure`；`measure` 不表示预定义指标。
- 数据上下文快照取代指标目录，只提供受权限约束的 Schema、字段说明、关系、已验证查询示例和执行限制，不包含业务数据行。
- 数据网关按查询产物选择 SQL、DQE 或组合执行适配器；新增执行环境必须接入数据网关，组件不得直连。
- 查询产物与看板页面都以稳定 id 承载同一性，并分别形成不可变查询修订和页面修订。查询变化先产生新查询修订，再由新页面修订显式引用，已发布页面不会因查询被覆盖而漂移。
- 发布复验从指标目录复验改为查询执行引用、权限、可执行性和结果字段契约复验。
- 现有 `StructuredQuery.metrics`、指标目录、`METRIC_GAP`、指标履约 Module 和相关 MCP 工具属于待迁移的旧实现。

## Considered Options

- 保留预定义指标作为 NL2SQL/NL2DQE 的强制入口：口径集中，但会让直接查询生成仍受指标建设流程阻塞，与新版本目标冲突。
- 把生成的 SQL/DQE 文本直接嵌入页面文档：实现最短，但页面复制查询定义，难以独立验真、复用、授权、版本化和审计。
- 在页面 DSL 中增加计算表达式或 JSON AST：跨查询计算灵活，但会把页面语言膨胀为新的执行语言，因此继续禁止。
