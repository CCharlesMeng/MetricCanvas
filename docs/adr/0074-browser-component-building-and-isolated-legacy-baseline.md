# 人工组件切换在浏览器完成，旧服务链隔离为可复现历史基线

地图 #95 的 #102 去留讨论确认：人工页面搭建仍在浏览器使用旧 MCP 包的组件推荐、属性构造与沉淀能力，不能直接删除整个包；同时，把旧代码移到 `packages/server/` 并未隔离它，平台、workspace、测试与契约生成仍依赖这条链路。本决策先明确仍需维护的能力，再把旧实现的保留对象从主线代码改为可复现历史基线，使新代码的依赖与交付范围可检查。

## 人工页面搭建的长期能力

组件切换在浏览器内完成，不为这类人工操作新增 Python 远程调用。组件推荐、局部属性构造与沉淀所需的最小能力归页面搭建工作台；搭建画布继续只承担既有交互覆盖层职责，不因迁移而接管页面文档或业务规则。

人工组件切换覆盖 Python 当前可装配的全部十类组件。现有浏览器实现的七类之外，补齐 `gauge`、`keyValuePanel`、`categoryBreakdown`；以后新增可装配组件时，两侧同步支持。这里的全集是可装配组件集合，不是页面协议中全部纯渲染组件类型。组件目录准入与本地构造支持面必须相符，不能向用户提供可选择但无法构造的组件。

共同的字段绑定、默认属性与准入规则通过共享用例保持一致；人工调整过的布局继续保留。现有页面合法性向量不能替代逐组件装配用例，单柱图的整页差分也不能代表十类组件已等价。迁移只提取局部构造所需能力，不把整套旧问数编排与整页装配器移入工作台。

本条部分修订 ADR-0060 的“Python 页面装配算法真源”范围：AI 整页装配归 Python，人工局部文档改写归工作台；页面协议与组件目录等共享事实保持单一来源，两侧共同规则必须一致。它不恢复 TypeScript 问数服务端，也不改变 ADR-0065 的搭建画布边界。

## 旧链路的隔离与退出

以一个经过记录和验证的完整仓库提交及固定 tag 保存旧链路，保留该版本的锁文件、共享包、测试、启动脚本、夹具与旧 Java 实现；需要对照时按需在仓外检出独立工作目录。具体提交和 tag 由隔离执行时确定并记录，本 ADR 不虚构已经存在的基线。仅摘出几个包不足以保存可运行系统，也不另建嵌套 Git 仓库。

主线完成必要解耦后移除相应旧实现。至少处理四组依赖：工作台仍需的浏览器能力、旧对话及会话消费链、页面资产客户端、当前验证对旧问数算法的反向依赖。退出范围同时覆盖包依赖、workspace、默认开发入口、测试配置、构建与 CI，不能只移动目录。

主线保留有来源提交记录的迁移验收用例。当前产品契约继续从现行真源导出，主线构建和契约检查不再运行旧编排来生成当前预期，也不能用 Python 当前输出自动覆盖自身测试预期。旧基线只供按需复查和差分，不继续增加产品功能。

原先“替代链路验收后物理删除”的要求，由可运行历史基线承担保留义务；不要求为等待生产验收而把旧实现留在主线。真实 Relay、DQE、身份与生产验收要求继续由对应迁移及接线工作承接，本次不把隔离完成等同于功能等价、生产上线或 #95 完成，也不取消原生产门槛。ADR-0069 已允许公共 Chat 未接通时显示不可用，仍不能用旧模型充当静态产品备用路线。

旧代码不得进入现行交付物。隔离验收应同时检查依赖可达性与构建输出，覆盖传递依赖及实际交付的入口和资源；只有目录归类或搜索不到某个包名，不足以证明产物隔离。

## 其他去留结论

- 旧 Java 工程停止作为本仓交付物，退出服务构建、部署产物与现行接入说明；其实现由历史基线保留。旧 Java 适配器在新页面资产客户端完成已确认接口的消费验证后退场。目录与精确修订接口的资料缺口继续归 #105，不以旧工程无限期代替未知外部契约。此条落实 ADR-0070。
- `ioc-data-dev/` 退出主线维护，历史交给 Git；出现明确复用需求时再单独提取。
- `pages/` 与 DQE 仿真继续维护。模板库退场后删除顶层 `templates/` 的产品播种路径，确有测试用途的样例迁为测试夹具。
- 发布治理、页面模板与相关旧后端实现退出本版，不表示 ADR-0008/0010 的治理目标被否决；现行说明必须区分目标语义、暂未提供的能力与外部接口待确认事实。

## 执行与后续讨论

本记录落盘时只确认设计；随后 #122–#125 已建立并推送固定 tag `legacy/pre-static-platform-2026-09-08`，补齐浏览器十类组件构造，解耦契约导出，并移除旧对话/会话/模型链、发布与模板界面、MCP、模板库、旧 Java 源码及相关默认工具链依赖。页面试验场的去留由 ADR-0075 补齐。

旧页面资产适配器仍按本决策保留，待 #105 的新接口消费链验证后退场；平台静态化及 #105/#107/#108 的接线仍是独立未完成项，不由上述隔离交付代替。历史材料保留原时点背景并标注替代关系。

用户另提出以本体论（概念设计）形式化表达项目架构，帮助约束新代码与交付范围。已确认第一版覆盖 #95 的架构主干，并作为 CI 契约；范围、模型与事实的区分，以及迁移开发/目标交付门禁已记录在 [ADR-0076](./0076-formal-architecture-contract-scope-and-enforcement.md)。具体模型草案见 [`architecture-formal-model.md`](../plan/architecture-formal-model.md)，维护来源、表达方式与行为验证深度继续讨论，本 ADR 不把任何候选技术视为已选定。
