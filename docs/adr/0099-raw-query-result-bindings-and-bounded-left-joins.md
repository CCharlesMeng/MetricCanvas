# 查询以原始结果集合声明输入 计算继续在页面数据源内执行

商务SDT报告需要先选取最快或最慢5个项目，再以商务编号集合查询阶段时长和次数，并合并回同一张表。页面查询定义增加 `resultBindings`，引用上游查询经归一化后的原始维度字段集合，生成下游普通DQE维度谓词。此决策限定恢复ADR-0015中的DQE集合输入场景，不恢复任意参数、表达式、SQL或结果转换。

绑定只支持原始string/number维度字段，显式声明source、field、queryField与maxValues；共享硬上限1000。集合去重与确定性排序保留类型，原主行顺序另行保持。绑定目标与静态、参数、筛选维度条件互斥。空上游不发下游请求，失败保留错误分类，缺键、非法值和超限失败关闭。上游完整或为显式limit有限集合，查询分页、offset及运行时查询排序/表头筛选不能改变其依赖输入。

原始查询阶段和计算阶段分别建图：阶段明细Q依赖项目Q，项目C依赖明细C，不等待已经合并后的主源。所有声明参与循环检查。编排器复用既有生效查询、并发、缓存、取消和代次机制，上游改变先同步失效下游，缓存不保存计算产物。普通筛选状态和URL不存储派生集合，组件不发起级联请求。首版不复用无绑定输入证明的initial和执行启动回执，关联链重取；独立源沿用原规则。

Pivot保留默认valueField，允许列级valueField覆盖。类别冲突以有效取值字段与类别的组合判定，多度量透视拒绝重复分组键与类别行；旧单度量首匹配行为保持兼容。JoinAggregate按商务编号左关联，主集合可保留明确Top5范围，辅助源继续完整行集核验。这是ADR-0095对有限主集合的限定修订，不把Top5当作全业务全集或放宽辅助截断规则。

导出按同一原始结果依赖重新执行，使用导出本轮编号并保留Top5，不能按主查询totalCount扩展为全部项目。6.14为能力下限，读取保留5.0–5.4、6.5、6.11、6.12和6.13。TS、Python、生成契约与Bundle同批同步；真实DS、Relay/Java和真实DQE仍需各自验收。

未采用查询结果回写隐藏筛选器：空集合“不筛选”语义与本需求冲突，且派生输入会混入用户筛选/URL状态。未采用独立查询执行体系：会重复取消、缓存与并发。设计和验证矩阵见[实施计划](../archive/2026-10-12-business-sdt-cascade/README.md)。
