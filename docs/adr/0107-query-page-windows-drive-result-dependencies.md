# 查询分页窗口通过现有结果绑定驱动依赖更新

原始结果绑定此前只允许完整结果和固定有限选择，并拒绝查询分页和上游排序覆盖。用户需要任意可排序列改变服务端首轮查询，当前页的过滤结果又作为其他查询的输入；仅增加本地展示分页不能满足该需求。

6.20允许显式查询分页数据源被现有resultBindings引用。绑定消费上游本轮返回的原始查询窗口，按自己的where筛行后提取维度集合，不增加inputScope、不复制上游页码或排序参数进下游业务输入。分页源声明正整数order.limit与offset:0，不声明complete；totalCount可大于窗口行数。运行时使用实际窗口大小核验，包括交互修改后的每页条数。

任意已映射的可排序列、方向及多列优先级变化都进入同一查询状态更新，页码重置为第一页；服务端先排序再分页。引擎从结果绑定依赖图求受影响查询，使旧结果失效并取消过期请求，等待本轮输入齐备后继续执行。分支可并行、汇合等待、多层传递，无关查询不重查。输入集合相同则有效查询缓存可复用。受影响的下游查询分页也回到第一页。

保留原完整结果和固定有限选择的范围保护；分页窗口不作为全量统计输入。共享单次执行消费第一页窗口；导出重新查询捕获时的当前窗口并据此更新依赖，不自动扩大输入为全量。普通无级联分页表仍完整导出。

未选择新增scope字段，原因是查询分页声明已给出范围，用户要求简化绑定；未选择全量后台取数，原因是会掩盖分页对输入集合的影响；未选择组件级联动作或固定流程，原因是依赖关系已由resultBindings声明，运行时已有输入就绪、请求取消与缓存机制。

本决策修订ADR-0099的查询分页禁止条款并延续ADR-0106行过滤语义。TS/Python校验、版本门禁、契约及Skill同步。见[实施计划](../plan/2026-10-14-query-result-page-input.md)及[使用示例](../cascading-queries.md#11-任意列排序与分页窗口联动620)。
