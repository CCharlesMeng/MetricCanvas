# 术语围绕指标谱系规整：临时指标、派生指标模板、取数核对

问数链路的三个核心术语——临时口径、派生度量模板、口径卡——各自成词，词面上互不相干，学习成本高：新读者无法从名字看出它们与「指标」的关系，也看不出治理强度的排序。用户裁决围绕**指标**重整这批词汇。规整后指标的治理状态构成一条可读的谱系：**正式指标**（指标条目所描述的公司口径）→ **派生指标**（模板产出，ADR-0039 已用此名）→ **临时指标**（现场公式）→ **指标缺口**（指标需求条目所记录），从左到右治理强度递减。

## 决策

**临时口径改称临时指标。** 这显式推翻了词汇表原 _Avoid_ 列表对「××指标」类命名的刻意回避。原回避的理由今天仍然成立——它**不是**指标条目：没有可用维度与可加性声明、不进语义面、不可被后续问数检索。改名后这条边界不再由名字承担，改由两处承担：词条定义中的显式不变量，以及界面上与公司口径指标视觉可区分的标注（ADR-0036 的全部治理原样适用，一条不减）。名字换取可读性，治理分界不随名字松动。

**派生度量模板改称派生指标模板。** ADR-0039 本就把模板产物称为「派生指标」，模板名跟齐，同时消除「度量」「指标」双词混用——「度量」保留给结果字段契约层（度量字段），「指标」专属业务语义层。

**口径卡改称取数核对。** ADR-0040 把它升级为控制面板后名实已经偏离：非阻塞轮次它是一行要素 token，阻塞场景才展开为完整面板，「卡」是形态词而非本质词。新名对齐它的操作对象（取数单元的生效范围）与双重职责（首先消歧，其次确认），不再绑定任何呈现形态。

**历史 ADR 正文不改写。** 沿 ADR-0052「看板页面 → 页面」的先例：`CONTEXT.md` 是术语真源，旧称收进各词条 _Avoid_ 列表；`docs/adr/README.md` 转述现行结论时用新称呼，引用 ADR 标题与原文时保留原词；代码注释、UI 文案与测试断言批量切换为新词。

## Consequences

- ADR-0036「界面需区分三种数字」的措辞更新为：公司口径指标、已验证查询、临时指标。分类本身不变。
- 约 40 个文件的代码注释、UI 文案与测试断言需批量替换旧词；代码标识符（如 `ScopeCard` 组件名、`scope_card_presented` 事件名）属实现命名与已落库契约，不由本决策强制改名，改名须单独评估事件契约兼容性。
- 静态原型（`apps/platform/static/prototype/`）、历史评审与研究文档是时点快照，不回溯改写。
- 「临时指标」三个字含「指标」，评测集必须继续包含应当降级的样本（ADR-0037），验证改名后降级路径与视觉标注仍然生效——名字亲民了，信任分界的验证责任反而加重。

## Considered Options

- **保留原词。** 零迁移成本，治理边界由名字自带；但三个词各自为政，「口径」「度量」「卡」三个词面都需要先学一遍词汇表才能对话，与「围绕指标优化可理解性」的目标相悖，不采用。
- **临时口径改称现场指标。**「现场」强调生成时机，信息量与「临时」相当，但「临时」在沉淀设闸的警告语境（「本页面包含 N 个临时指标」）中更直接传达「不该长期依赖」，不采用。
- **口径卡改称取数核对卡。** 保留会话流卡片家族词（与候选卡同族），迁移直觉更顺；但非阻塞轮次它根本不是卡片，形态词与 ADR-0040 的控制面板定位继续冲突，不采用。
