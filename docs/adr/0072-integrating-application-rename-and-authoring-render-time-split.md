# 「宿主」改称集成应用，创作期与渲染期确立为一对对立时段

领域词汇表有一批承重词条从未定义：「创作期」在词汇表自己的定义里被引用 9 次却没有词条，「宿主」被布局形态与导航意图引用却没有词条，「页面搭建工作台」只作为反面词出现两次。本决策补齐这批词条，并顺带纠正一次误读与裁定一次改名。词条已写入 `CONTEXT.md` 新增的「阶段与角色」段。

**「宿主」改称集成应用，英文保留 `Host`。** 改名理由不是措辞偏好，是这个词在本仓重载了三个互不相干的意思：装载渲染引擎的应用（`docs/host-contract.md`）、页面资产 Module 要并入的 Java 服务 `CDINL2DataBuilderService`（`metriccanvas-page-assets/` 的「并入宿主 reactor」「避免与宿主撞名」）、以及包内技术容器（「ECharts 宿主」「组件宿主态 `WidgetHost`」）。只有第一种改名，后两种保持原样——它们既不装载渲染引擎也不供给数据网关，套用新词条会制造假等价。英文一律留 `host`，因此代码标识符、ADR 文件名与链接地址零改动，中文换而英文不换与既有的「统一运行时 (Runtime)」同一种风格。

**创作期与渲染期是一对对立时段，创作期同时容纳 AI 装配与人工页面搭建。** 这条纠正了一次误读：因为词汇表那 9 处「创作期」的语境多在讲问数与 NL2DQE，容易被读成「AI 独占的阶段」，从而推出「ADR-0065 的创作包用词有误、人工搭建那层该改名」。仓内证据一致地否掉这个读法——ADR-0043 明写「归因下钻是创作期的分析取证动作，页内下钻与跨页下钻是渲染期的筛选交互」，对立面是渲染期而不是人工；ADR-0032 明写「这条区分决定了人机分工：用户与 Agent 在取数单元这一层对话与修改」，并要求「未试算的取数单元不得进入画布与草稿」，画布本就在创作期内；ADR-0024 的文件名 `converge-authoring-time-packages` 直接给出 authoring time 的对应。**因此 ADR-0065 的「创作包」「创作画布」「创作消费者」全部成立，不改。**

**问数不拆成两种形态，platform 改为收窄入口语义。** 「一次性看个数」与「用 AI 起个页面」不是两种问数，是同一次问数的两种结局：从提问到临时页面态渲染出来，两条路共用同一套编排（ADR-0037）、同一份临时页面态、同一个 Chat 接口与同一次验真，区别只在用户事后有没有调用沉淀——而沉淀已经是词条。系统在沉淀发生之前分不出这两者，所以给它们各立词条会造出一个无法执行的区分。platform 能真正收窄的是入口语义而非能力：同一个问数可以呈现为自由问答助手，也可以呈现为新建页面的第一步。**问数因此留在 platform，地图 #95 终点线只改措辞，Relay 支线 #106/#107/#108 不受影响。**

**「画布」一词归搭建画布，页面自己的外框视觉面不再叫画布。** 原先「画布」在 ADR-0032/0065 里指搭建画布，在 `CONTEXT.md` 布局形态与 `PAGE-METADATA.md` 的 `layoutForm` 段里指页面外框视觉面。后者改称「外观」，`PAGE-METADATA.md` 表格里的「浅色画布 / 中性画布」改称「浅色底色 / 中性底色」——不用「铺底」，因为「铺底层」是 `layout.layer: "backdrop"` 的专名。

**「改版」立词条但进「提议中的术语」段。** 它指在已沉淀页面上以自然语言发起 AI 修改：与探索的区别在对象与后果（探索改临时页面态且不产生页面修订，改版改长期资产并受发布治理约束），与页面搭建的区别在驱动方。**系统当前不具备这个能力**——`packages/mcp/src/authoring/` 只有 `assemble-page`、`auto-visualize`、`promote`、`section-layout`、`unit-verification`，`apps/platform/src/lib/server/ask/` 里的 revise 改的是临时页面态。词条先立以统一后续讨论措辞，建成前不得在设计中假定它已存在。同批把该段引言从「IOC 作战地图批次的未生效决策」放宽到也收「系统尚不具备的能力」。

## 取舍

- **不采用全仓改名 380 处**：ADR 正文是决策当时的记录，改它等于重写历史措辞；`docs/plan/` 是过程产物，改它没有收益。代价是「宿主」与「集成应用」长期并存，靠词条的 `_Avoid_: 宿主（旧称）` 导航。改名范围因此限定为词汇表加七份活文档：`docs/host-contract.md`、`packages/embed/README.md`、`docs/frontend-runtime-capabilities.md`、`packages/metric-canvas/README.md`、`docs/solution.md`、`PAGE-METADATA.md`、`docs/runtime-architecture.md`，共 72 处。
- **不采用「集成应用 (Integrating Application)」作英文名**：中英不对应会让读者把代码里的 `host` 当成另一个概念。选 `Host` 换来代码、ADR 文件名与锚点全部零改动。
- **不采用连代码与文件名一起改成 `integrating-application`**：最一致，但要动四个 ADR 文件名与 `hostRenderSnapshot`、`widget-host-state`，换来的只是字面统一。
- **不采用把「创作期」窄化为 AI 阶段**：那要同时改词汇表 9 处与 ADR-0032/0065 的用词，是一次真重命名，且与 ADR-0043 已写下的创作期／渲染期对立直接冲突。
- **不采用「承载应用」**：弱化了集成应用要主动供给页面文档、数据网关与身份这件事，读起来像只是装着引擎。**不采用「集成方」**：既可指团队也可指应用，在词汇表里会模糊。
- **不为「一次性看数」与「用 AI 起页面」各立词条**：见上，系统在沉淀之前分不出来。

## 实施与行为约束

- 新增七个词条：创作期、渲染期、页面搭建、搭建画布、页面搭建工作台、平台、集成应用；「改版」进提议段。「平台」定义为第一方集成应用，与第三方的区别是第一方身份而不是装了哪些能力。
- 「渲染引擎」词条早已存在，形式是「统一运行时 (Runtime，又称渲染引擎)」的别名。ADR-0071 曾据错误判读声称该词条缺失并把补齐列为 `@metriccanvas/engine` 的发包前置，该句已更正——命名依据在裁决时即已就位。
- `metriccanvas-page-assets/` 的 10 处「宿主」指 Java 宿主服务，`WidgetHost`、`hostRenderSnapshot`、「ECharts 宿主」等指包内技术容器，均不在改名范围。后续若为 Java 宿主服务立词条，须与集成应用显式互斥。
- `docs/solution.md` 与 `docs/frontend-runtime-capabilities.md` 里的「创作画布」「画布交互」按新词条应作「搭建画布」，属同批可跟进项，不影响本决策成立。
