# 创作草稿经维度取值提取发布为模板，执行产生页面实例

2026-09-14，Platform 创作生命周期 grill 确认：页面模板保留可替换的维度取值，页面实例具有已确定的查询条件。模板从确定的草稿修订派生，提取结果经用户纠正、预览并确认后才发布；后续内容修改回到草稿再发布，不建设第二套独立可编辑模板库。运行实例不自动入库，也不因查询条件已经实例化而禁止页内筛选。本决策是已确认的新版本设计，当前页面协议和外部服务尚未据此实现。

维度取值复用顶层 `params` 表达，补齐维度多值、查询目标绑定和筛选初始化绑定；不新增 `dimensionValues` 或 `globalParams` 顶层字段。参数确定本次实例化输入，初始化后的可变状态仍由 `filters/filterBindings` 管理。同一条件的默认来源只声明一次，受参数控制的筛选初值引用该来源。第一版只覆盖 DQE 维度等值和多值，允许部分数据源共享；同维度不同取值的共享提取、时间与金额范围提取后置，不扩成通用变量规则系统。具体引用语法、执行结果与错误状态承载和协议版本由后续契约任务冻结。

本次讨论最初采用独立 `dimensionValues`，随后用户指出其与 params 重合，最终确认合并。该修订保留“维度取值”业务概念，但撤回独立字段设计。现有 params 的标量限制和缺失的 DQE 参数绑定仍需实现，不能只更名宣称能力已有。

自动提取、修正候选后的校验和发布裁决由外部 Java 管理服务负责，Platform 提供可视化确认，Relay 可通过独立生命周期 MCP 发起操作。元数据编辑 MCP 只构造或修改内容。平台与 Relay 都可发起草稿保存；仅覆盖进入 Platform 创作页面后的流程，不扩展普通问数或 DataAgent。本仓实现与外部 Java/Relay 修改方案分开验收。

## 与既有决策的关系

2026-09-17 实施修订：6.5 采用同一 Page Schema 的无值模板与填值页面，维度/固定时间区间在 DQE 取值位置引用 params，实际输入用 value；旧 paramBindings 显式迁移并保留窗口。确定性提取作者改由本仓独立 TS 程序承担，Python/Relay 通过可信程序通道消费，完整页面不经模型重写。人工预览与无值载荷分离，沿 ADR-0080 单次提交，不假定 Java 具备旧 PublicationPort 的 lookup/lease 能力。此修订取代上文“提取算法由外部 Java 实现”和时间提取后置的范围，保留外部资产所有权；真实保存、召回填值与执行提供方尚需 E1 联调。

- 部分替代 ADR-0010 的模板仅引用已发布页面修订的模型：本版模板具有维度取值替换语义，并由草稿经确认生成；不因此假定外部服务已提供独立模板资产接口。
- 在 Platform 创作范围内，调整 ADR-0064 的仅由前端显式沉淀后保存限制：语言修改可由 Relay 调用生命周期工具保存，手工生效操作自动保存；编辑算法本身仍不持久化，完整页面产物不经模型转抄。普通问数不在本次变更范围。
- 延续 ADR-0070 的外部 Java 所有权和 ADR-0073 的静态平台形态；不在本仓重建 Java 服务或 Node 后端。
