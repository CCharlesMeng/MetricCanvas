# 页内详情浮层作为第三支组件动作

`componentAction` 的闭集只有两支：`writeFilter`（点击把行上的值回写到某个筛选器）和 `navigate`（跳页并带上 query 参数）。**没有弹窗、抽屉、页内展开**——想看一行的完整信息，唯一的办法是跳到另一个页面。

这在 IOC 上是个具体的缺口。`ioc-opportunity-analysis` 的测试里当初就写明「首版不声明无内容的详情弹窗或页内打开动作」——不是不需要，是协议给不出。概览页的丢单表尤其别扭：它的 `navigate` 指向项目详情页，可**丢掉的项目往往根本没有项目详情**，而真正要看的「丢单原因」就在这一行里，跳走一趟再跳回来纯属绕路。

## 决策

**新增 `openDetail` 动作：点击在页内打开一层浮层，展示被点那一行的若干字段，不离开当前页。**

```json
{ "on": "click", "openDetail": {
  "surface": "drawer",
  "titleField": "opportunity-name",
  "fields": [
    { "label": "丢单原因", "field": "lost-order-reason" }
  ]
}}
```

**`fields` 必须非空。** 空的详情浮层是一个什么都不说的弹窗，比没有更糟——它把「这里应该有信息」的期待建立起来然后落空。校验期拒绝。

**每个字段都要能在组件自己的数据槽里解析。** 浮层读的是被点那一行，与 `navigate` 的 `source: 'row'` 同一套行上下文，因此字段绑定走与列绑定完全相同的判定；`titleField` 同理，省略时回落到组件标题。

**`surface` 是封闭二选一：`modal` 居中、`drawer` 右侧贴边。** 不开放尺寸、位置、层级这些呈现细节——它们属于渲染引擎的排版决策，放进页面文档只会让同一份文档在不同宿主里长得不一样。

**浮层同时只存在一个。** 它是「看一眼这一行」的临时视角，不是可堆叠的窗口系统；第二次点击替换第一次的内容。Esc 与点击背板关闭。

**`openDetail` 与 `navigate` 一样可以挂在 inline 组件上。** 两者都只读当前行、不依赖 query 重跑；只有 `writeFilter` 和单元格选择需要 live 数据源。这条把既有判定里「非 navigate 一律要求 live」的口径改成「只有 writeFilter 要求 live」，是放宽而不是收紧。

**本次交付页面协议 6.10。** 判别联合新增分支，满足 [ADR-0051](./0051-additive-minor-versions-for-page-schema.md) 的增量四条判据。

## Consequences

- `ioc-project-overview` 的丢单表从 `navigate` 换成 `openDetail`，七个字段含丢单原因。这是本决策的第一个行使者，也是它存在的理由本身。
- 浏览器证据钉的是「不离开当前页」：点击后 `page.url()` 与点击前逐字相同，浮层可见，Esc 后消失。只断言「浮层出现了」会漏掉一个跳走又跳回的实现。
- 链接列（`column.link`）的点击在 `linkHref` 返回 undefined 时改为进入页内详情。链接列声明的是「这一格可点」，点了之后是跳页还是开浮层由组件的动作决定——两者共用同一个可点击外观，不为浮层另造一种列类型。
- 浮层的字段值按原样格式化，不读列上的 `format`。`fieldReference` 的对象形态确实带 `format`，但那是**列绑定**的呈现声明；详情项有自己的 `label`，格式若要可配应当是 `openDetail.fields` 自己的字段，本次不开。

## Considered Options

- **用 `navigate` 跳到一个专门的详情页。** 不动协议。这正是今天的形状，也正是丢单表别扭的原因：为看一行的一个字段跳走整页，而那一页对丢单项目根本不存在。不采用。
- **让 `openDetail` 引用一个页面模板或子页面文档，浮层里渲染完整组件树。** 表达力最强，能放图表、表格。但它把「页面里嵌页面」引进来，牵动数据源作用域、筛选状态继承、布局容器嵌套一整套问题，而当前需求只是看一行的几个字段。不采用，留待真有嵌套渲染需求时再论证。
- **浮层内容由宿主实现，运行时只上抛一个事件。** 引擎最轻。但那等于把详情长什么样交给每个宿主各自发明，同一份页面文档在不同宿主里不一样——与 [ADR-0066](./0066-self-contained-rendering-engine-host-boundary.md) 自包含渲染的边界相悖。不采用。
- **复用 `navigate` 加一个 `mode: "overlay"`。** 少一支分支。但 `navigate` 的载荷是 URL 与 query 绑定，`openDetail` 的载荷是字段清单，两者没有共用字段；塞进一支只会得到一个一半字段永远不用的对象。不采用。
