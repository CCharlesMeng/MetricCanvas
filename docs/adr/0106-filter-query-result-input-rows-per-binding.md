# 下游查询结果绑定独立筛选上游原始行

同一查询页面数据源A需要完整展示，同时B只消费其中符合条件的对象。过滤归属于下游输入声明，在 `source.query.resultBindings[].where` 增加可选受控条件。上游行和总条数保持不变，不引入独立数据集、计算阶段依赖或隐藏筛选状态。

where只读取同一上游有查询字段映射的原始标量字段，支持eq/ne、in/notIn、数值比较、显式空值判断及all/any组合；组合最多4层、叶子最多64个、每个字面量集合最多1000项。比较严格按结果字段契约原始类型与单位，不强转或舍入；null不匹配普通比较，包括ne/notIn。首版条件仅字面量，不新增筛选/参数引用与通用表达式。

维度集合提取仍遵循ADR-0099：原始string/number维度输入、完整或显式有限选择、去重保留类型、空集合不查询、无效键和超限失败、查询和计算依赖分别校验。新增顺序为原始范围与字段核验、where过滤、field提取、去重排序和maxValues检查；被过滤掉的合法null键不需要提取，原始字段契约违规不能借过滤隐藏。

过滤规则同源复用于浏览器、导出与共享取数。声明缺省保持旧语义；6.19是能力下限，旧版本使用where明确拒绝。TS/Python语义校验、JSON Schema、契约向量、Bundle与独立Skill同步。

未选择修改A查询条件，原因是A完整结果仍需展示和复用；未选择在compute中筛行后绑定，原因是会改变原始查询与计算阶段的依赖分离；未选择新建查询执行体系，现有绑定解析已拥有输入就绪、空集合、错误和缓存语义。指标值集合输入不在本批，不把值集合隐式转换为区间。
