# 看板页面构建过程：从需求输入到人工确认发布

> 文档状态：新版本目标流程
> 编写日期：2026-07-30
> 关系说明：本文按 ADR-0014 描述 NL2SQL/NL2DQE 模型下的看板页面构建过程；领域术语遵循 [`CONTEXT.md`](../CONTEXT.md)。
> 配套架构：已发布页面的运行态见 [`dashboard-runtime-architecture.md`](./dashboard-runtime-architecture.md)。
> 范围说明：本文描述需求提出到页面上线的完整交付流程，不按旧版指标目录或 Module 清单反推。

## 1. 目标流程

新版本不要求需求先映射到预定义指标。业务需求在受控的数据上下文中经 NL2SQL 或 NL2DQE 生成查询候选，候选通过安全校验、真实执行和结果验真后保存为查询修订；看板页面只引用精确查询修订，不保存自然语言生成过程，也不在运行时重新生成查询。

流程中有四个不可交换的状态边界：

1. **先确认需求，再生成查询。** 页面目标、受众、分析问题、时间范围和验收标准存在实质歧义时，不能以模型猜测代替确认。
2. **先验真查询，再组合页面。** 查询候选只有通过静态校验、权限校验、真实执行和结果字段契约确认后，才能保存为查询修订。
3. **先保存页面修订，再做精确预览。** 未保存页面文档可以反复调整；用户明确保存后才形成不可变页面修订。
4. **先通过真实预览和业务验收，再人工发布。** 预览成功不等于发布同意，模型和 Agent 不能替代发布者确认。

### 1.1 从需求到上线的全景流程

下图以需求交付为主线，共八个框。生成失败、查询验真失败、页面校验失败和业务验收失败都返回相应创作阶段，不产生无效资产。

```mermaid
flowchart LR
    REQUIREMENT["① 需求输入与确认<br/>目标、受众、分析问题<br/>时间范围与验收标准"]
    CONTEXT["② 数据上下文准备<br/>数据源、Schema、字段说明<br/>权限、关系与执行约束"]
    GENERATE["③ NL2SQL / NL2DQE<br/>生成查询候选"]
    VERIFY["④ 查询校验、执行与验真<br/>形成不可变查询修订<br/>及结果字段契约"]
    COMPOSE["⑤ 页面方案与组件映射<br/>组织页面数据源、分区<br/>筛选状态与交互"]
    REVISION["⑥ 页面文档校验并明确保存<br/>形成不可变页面修订"]
    ACCEPTANCE["⑦ 精确修订真实预览与验收<br/>数据、展示、性能与交互检查"]
    RELEASE["⑧ 人工确认发布上线<br/>发布租约 + 引用复验<br/>形成已发布修订"]

    REQUIREMENT --> CONTEXT
    CONTEXT --> GENERATE
    GENERATE --> VERIFY
    VERIFY -->|"失败：修正需求、上下文或查询"| GENERATE
    VERIFY -->|"通过"| COMPOSE
    COMPOSE --> REVISION
    REVISION -->|"校验失败或继续修改"| COMPOSE
    REVISION -->|"明确保存"| ACCEPTANCE
    ACCEPTANCE -->|"查询问题：形成新查询修订"| GENERATE
    ACCEPTANCE -->|"页面问题：形成新的未保存页面文档"| COMPOSE
    ACCEPTANCE -->|"验收通过"| RELEASE
```

关键关系：

- 需求输入是流程起点，NL2SQL/NL2DQE 是把已确认需求转换成查询候选的创作期能力；
- 数据上下文快照限定模型可以看见和使用的数据范围，不能用裸库全量 Schema 或模型记忆代替；
- 查询产物是受治理的数据资产，页面通过查询执行引用绑定精确查询修订，不引用指标 code；
- 结果字段契约用维度字段和度量字段描述查询输出，字段角色不要求预先注册为平台资产；
- 统一运行时只执行生效查询并呈现数据快照，不在页面打开、筛选变化或组件交互时重新运行 NL2SQL/NL2DQE；
- 发布前必须复验页面修订引用的查询产物仍可访问、可执行且契约未漂移。

## 2. 四类创作输入

### 2.1 需求输入

需求输入回答“为什么做、给谁看、要回答什么、何时算完成”。

| 输入项 | 必须回答的问题 | 对后续流程的影响 |
|---|---|---|
| 页面目标 | 页面要支持什么业务判断或动作 | 决定整页叙事和验收标准 |
| 受众 | 谁使用、具有什么背景和权限 | 决定信息密度和可见数据范围 |
| 分析问题 | 要判断当前值、趋势、对比、构成、排名、异常还是明细 | 决定查询形状和候选组件 |
| 时间范围 | 分析哪个周期、默认粒度和时区是什么 | 决定查询参数与默认筛选状态 |
| 决策优先级 | 哪些问题必须首先被回答 | 决定内容分区顺序和组件权重 |
| 验收标准 | 什么结果、性能和交互才可上线 | 决定查询验真与页面验收项目 |

最小输入不应只是“做一个销售看板”，而应接近：

> 面向区域经营负责人，判断本月销售是否达标、最近十二周是否异常、哪些区域贡献最大，并能按区域查看明细；页面首次加载在约定数据范围内满足性能目标。

### 2.2 数据上下文快照

数据上下文快照是 NL2SQL/NL2DQE 的受控生成边界，至少包含：

- 当前用户有权使用的数据源和执行环境；
- 表、视图或 DQE 对象的 Schema；
- 字段名称、类型、业务说明、别名和单位；
- 可用关系、连接约束、时间字段与数据粒度；
- 行列权限、敏感字段和数据最小化要求；
- 只读限制、允许函数、查询复杂度和资源上限；
- 可选的已验证问题—查询示例。

数据上下文快照不包含业务数据行，也不把所有数据库对象无差别交给模型。上下文不足时应请求补充或缩小需求范围，不能转入旧版指标缺口履约。

### 2.3 查询生成能力与护栏

NL2SQL 和 NL2DQE 共享同一输入、输出和验真流程：

| 路径 | 适用条件 | 输出 |
|---|---|---|
| NL2SQL | 目标数据可通过受治理 SQL 执行环境访问 | 只读 SQL 查询候选 |
| NL2DQE | 目标数据由 DQE 语言和执行环境提供 | DQE 查询候选 |
| 组合查询 | 需求必须组合多个 SQL/DQE 小结果集 | 多个查询执行引用 + 服务端受限 SQL |

模型只负责生成候选，不拥有执行授权。所有候选必须经过解析器、允许列表、权限规则、资源限制和真实执行验证。

### 2.4 纯渲染组件目录与领域 DSL

组件目录和领域 DSL 决定已验真数据如何成为可运行页面：

- 组件目录声明组件类型、支持的分析任务、数据槽、字段角色、数据形状、必填 props、默认跨度和允许交互；
- 领域 DSL 声明命名页面数据源、查询执行引用、参数绑定、内容分区、组件字段绑定、筛选状态和跨页下钻；
- 页面文档不携带组件代码、任意脚本、HTML、CSS 或查询文本；
- 纯渲染组件只消费数据快照和结果字段契约，不访问查询执行环境。

## 3. 从需求到查询产物

### 3.1 拆解分析任务

生成过程先把分析问题拆成可执行任务：

| 分析问题 | 分析任务 | 典型结果形状 |
|---|---|---|
| 本月销售是否达标 | 当前值与目标对比 | 单行双度量字段 |
| 最近十二周是否异常 | 时间趋势 | 时间维度字段 + 一个或多个度量字段 |
| 哪些区域贡献最大 | 分类对比与排名 | 区域维度字段 + 度量字段 |
| 某区域为何下降 | 分组对比与明细 | 多个维度字段 + 度量字段 |

分析任务是创作期中间结果，不是平台长期资产。

### 3.2 生成查询候选

每个分析任务执行以下过程：

1. 选择有权访问的最小数据上下文；
2. 根据目标执行环境选择 NL2SQL 或 NL2DQE；
3. 生成只返回页面所需字段和行数的查询候选；
4. 把页面交互所需的动态条件声明为参数，而不是拼接查询文本；
5. 对跨执行环境计算生成多个上游候选，并在服务端以组合查询收口；
6. 记录生成所用的数据上下文快照和结构化需求摘要，不保存完整对话原文。

### 3.3 校验、真实执行与结果验真

查询候选必须依次通过：

| 校验层 | 校验内容 | 失败处理 |
|---|---|---|
| 语法与结构 | SQL/DQE 可解析、只读、参数完整 | 返回查询生成阶段修正 |
| 安全与权限 | 数据源权限、行列限制、敏感字段、禁止语句 | 阻断，不允许模型绕过 |
| 语义 | 字段、关系、时间范围、粒度和业务含义 | 修正需求、上下文或查询 |
| 资源 | 超时、扫描量、输入/输出行列数和复杂度上限 | 缩小查询或拆分执行 |
| 真实执行 | 在当前身份下可成功执行 | 返回结构化执行错误 |
| 结果验真 | 字段类型、角色、单位、空值、基数和样例值符合预期 | 修正查询并重新执行 |

不能只凭模型自评或静态解析认定查询可用。真实执行的业务数据只用于验真，不进入页面文档或普通审计日志。

### 3.4 保存查询修订

验真通过后创建或更新查询产物，并保存一个不可变查询修订，至少固化：

- 查询产物 id 和查询修订 id；
- 查询语言及目标执行环境；
- 精确 SQL、DQE 定义或组合查询定义；
- 参数契约；
- 结果字段契约；
- 数据上下文快照版本；
- 创建人、创建时间、内容哈希和验真记录；
- 超时、行列数和资源限制。

查询修订保存后返回查询执行引用。后续修改必须形成新的查询修订，不能原地改写已被页面修订引用的定义。

### 3.5 结果字段契约

结果字段契约至少声明：

| 字段属性 | 说明 |
|---|---|
| `name` | 查询结果中的稳定字段名 |
| `type` | 字符串、数值、布尔、日期时间等标量类型 |
| `role` | `dimension` 或 `measure` |
| `label` | 面向使用者的默认名称 |
| `unit` | 金额、百分比、数量等业务单位 |
| `nullable` | 是否允许空值 |
| `defaultFormat` | 可被组件字段绑定覆盖的展示建议 |

“度量字段”只是结果角色，不等同于旧模型中的指标资产，也不需要指标 code、指标目录或 DP 履约。

## 4. 从查询产物到未保存页面文档

### 4.1 声明页面数据源

每个 query 页面数据源：

- 引用一个精确查询执行引用；
- 继承查询产物的结果字段契约；
- 声明筛选状态到参数契约的绑定；
- 可覆盖字段展示标签，但不能改变字段类型、角色或单位；
- 不复制 SQL/DQE 文本。

固定时点数据仍可使用 inline 页面数据源，并在页面文档中完整声明结果字段契约和数据行。

### 4.2 映射纯渲染组件

组件映射依据“分析任务 + 结果字段契约 + 数据形状”完成：

- 度量字段可绑定数值卡、图表数值轴或表格数值列；
- 维度字段可绑定类别轴、时间轴、筛选器或表格分组列；
- 组件只通过命名数据槽引用页面数据源；
- 展示格式写入组件字段绑定，不改变查询语义；
- 无受治理组件能够承载时必须降级或阻断，不能现场生成组件代码。

### 4.3 组织整页

整页组织遵循：

1. 首屏先回答最高优先级的决策问题；
2. 当前值、趋势、原因和明细形成由总到分的阅读顺序；
3. 多个组件需要同一结果时复用命名页面数据源；
4. 页面级动态条件进入筛选状态，并只绑定查询产物公开的参数；
5. 目标页面和目标筛选器明确存在时才声明跨页下钻；
6. 页面模板可以提供布局起点，但不能覆盖当前需求和查询验真结果。

完成后只产生未保存页面文档及生成解释，不自动形成页面修订。

## 5. 从页面文档到发布

### 5.1 页面静态校验

未保存页面文档必须通过：

| 校验层 | 校验内容 |
|---|---|
| Schema 校验 | 页面结构、必填字段、类型和 `schemaVersion` |
| 引用校验 | 页面数据源、查询执行引用、数据槽、筛选器和跨页下钻 |
| 契约校验 | 参数绑定、结果字段、组件字段角色和数据形状 |
| 组件能力校验 | 组件类型、必填 props、允许交互和降级行为 |
| 治理校验 | 禁止页面内查询文本、脚本、任意代码、组件直连查询环境和页面层计算 |

### 5.2 用户审阅与明确保存

用户审阅页面是否回答需求、查询含义是否正确、数据是否可接受、页面结构是否清晰。只有用户执行明确保存动作后，页面生命周期 Module 才：

1. 再次校验页面文档及全部查询执行引用；
2. 检查 `baseRevisionId` 和并发条件；
3. 固化页面引用的精确查询产物修订；
4. 形成新的不可变页面修订。

### 5.3 精确修订真实预览与业务验收

统一运行时读取 `pageId + revisionId`：

1. 解析页面数据源和筛选状态；
2. 按参数契约形成生效查询；
3. 经数据网关执行精确查询产物；
4. 将标准化数据行与结果字段契约组成数据快照；
5. 由纯渲染组件呈现；
6. 用户检查数据正确性、空值、排序、单位、性能、可读性和交互。

查询问题需要形成新的查询修订；页面问题需要形成新的未保存页面文档。两者都不能原地改写既有页面修订。

### 5.4 人工确认发布

验收通过后：

1. 页面生命周期 Module 取得发布租约；
2. 复验页面修订引用的查询产物、执行权限和结果字段契约；
3. 发布者查看精确页面修订、真实预览、查询解释和风险提示；
4. 发布者明确确认或拒绝；
5. 确认后，该精确页面修订成为已发布修订；
6. 统一运行时确定性消费该修订，不重新生成页面结构或查询。

## 6. 服务与 Module 如何支撑流程

| 流程阶段 | 主要能力 | 输入 | 输出 |
|---|---|---|---|
| 需求输入 | 页面创作工作台、Agent | 自然语言与结构化补充 | 已确认需求 |
| 数据上下文 | 数据上下文发现 Module | 身份、数据范围、分析任务 | 数据上下文快照 |
| 查询生成 | NL2SQL/NL2DQE Adapter | 需求 + 数据上下文快照 | 查询候选与解释 |
| 查询治理 | 查询产物 Module | 查询候选 | 校验结果或查询执行引用 |
| 页面生成 | 创作期生成 Module | 需求、查询执行引用、组件目录 | 未保存页面文档 |
| 页面校验 | 看板页面领域 Module | 页面文档 | 结构化错误或通过 |
| 页面保存 | 页面生命周期 Module | 已确认页面文档 | 精确页面修订 |
| 预览取数 | 统一运行时 + 数据网关 | 页面修订 + 筛选状态 | 数据快照 |
| 人工发布 | 页面生命周期 Module | 当前最新页面修订 | 已发布修订或拒绝原因 |
| 生产呈现 | PageRepository + 统一运行时 | `pageId` | 可访问看板页面 |

## 7. 失败与续接

新版本不再使用指标缺口和指标履约分支。阻断按发生位置处理：

| 阻断 | 处理 |
|---|---|
| 需求含义不清 | 需求提出方补充或确认 |
| 数据上下文缺失 | 补充 Schema、字段说明、关系、权限或缩小范围 |
| NL2SQL/NL2DQE 无法生成合法查询 | 调整上下文、拆解任务或切换受支持路径 |
| 查询权限或安全校验失败 | 阻断并由数据所有方处理权限或数据边界 |
| 查询执行或结果验真失败 | 修正查询候选并重新验真 |
| 页面契约或组件能力不足 | 调整页面方案或登记平台能力缺口 |
| 业务验收失败 | 根据根因形成新查询修订或新页面修订 |

系统可保存结构化需求摘要和失败证据用于续接，但不保存完整对话原文、未经授权的数据行或不可执行的页面修订。

## 8. 角色协作

| 角色或职责 | 参与阶段 | 必须作出的贡献或决定 |
|---|---|---|
| 需求提出方 | 需求输入、查询含义确认、业务验收 | 明确目标、受众、分析问题、时间范围和验收标准 |
| 页面搭建者 | 全部创作期阶段 | 检查查询解释和页面方案，明确保存并申请发布 |
| 数据所有方 | 数据上下文与权限 | 提供字段说明、关系、安全边界和执行授权 |
| 查询治理职责 | 查询校验与验真 | 维护 SQL/DQE 护栏、资源限制、执行适配器和审计 |
| 纯渲染组件维护职责 | 组件目录与领域 DSL | 维护组件能力、数据形状和允许交互 |
| 发布者 | 人工发布 | 审查精确修订、真实预览、查询解释和风险提示 |
| 管理员 | 平台治理 | 处理发布租约异常、查询产物和页面资产治理 |

Agent 不是责任角色。它可以生成查询候选和页面文档，但不能替代需求提出方、数据所有方或发布者作出确认。

## 9. 关键不变式

1. 没有已确认需求，不生成可保存查询产物。
2. NL2SQL/NL2DQE 只发生在创作期，统一运行时不生成或改写查询。
3. 查询候选必须只读，并通过权限、安全、资源和真实执行验证。
4. 查询修订和页面修订都不可变；修改必须产生新修订。
5. 页面数据源引用精确查询执行引用，不引用“最新查询”或指标 code。
6. 筛选状态只能通过参数契约影响查询，不能拼接查询文本。
7. 结果字段契约来自静态分析和执行验真，不从某次数据行猜测。
8. 组件只消费数据快照，不访问 SQL/DQE 执行环境。
9. 页面文档不携带 SQL、DQE、任意脚本或页面层计算。
10. 组合计算发生在服务端查询产物中，中间结果不进入浏览器。
11. 真实预览必须绑定精确页面修订及其精确查询产物修订。
12. 人工确认发布是独立闸门，模型、Agent、查询成功和预览都不能代替。

## 10. 相对旧模型的变化

| 旧模型 | 新模型 |
|---|---|
| 需求先匹配预定义指标 | 需求直接生成 SQL/DQE 查询候选 |
| 页面以指标、维度和聚合声明结构化查询 | 页面引用精确查询产物并绑定参数 |
| 元数据快照提供指标目录 | 数据上下文快照提供 Schema、字段语义、关系、权限和执行约束 |
| `METRIC_GAP` 进入指标需求队列和 DP 履约 | 查询生成、上下文、权限或执行问题按根因处理 |
| query 字段契约由指标/维度目录推导 | 结果字段契约由查询静态分析和真实执行验真形成 |
| 复杂计算下沉为数据服务指标 | 复杂计算由 SQL/DQE 或服务端组合查询表达 |
| 数据服务是唯一入口 | 数据网关统一调度 SQL、DQE 和组合执行适配器 |

保留不变的部分是：看板页面仍是核心资产，领域 DSL 仍严格声明式，纯渲染组件仍不取数，页面修订仍不可变，真实预览和人工发布仍是上线前的独立闸门。
