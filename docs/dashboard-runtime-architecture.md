# 统一运行时架构

统一运行时加载、校验并渲染看板页面。它执行页面中已经声明的页面数据源，不生成查询或页面结构。

## 1. 运行边界

统一运行时接收：

- 页面文档；
- 页面仓储；
- 数据网关；
- 导航适配器；
- 可选创作能力。

统一运行时输出：

- 页面布局；
- 页面筛选控件；
- 组件数据快照；
- 组件交互事件；
- 页面导航。

统一运行时不负责：

- NL2DQE；
- Schema 元数据检索；
- 页面保存和发布；
- 组件内部取数；
- 任意页面脚本或计算表达式。

## 2. 模块

```text
应用壳
  ├─ 页面仓储
  ├─ 数据网关
  ├─ 导航适配器
  └─ Runtime UI
       ├─ 页面校验器
       ├─ 筛选状态
       ├─ 数据编排器
       ├─ 数据快照
       └─ Widgets
```

| 模块 | 职责 |
|---|---|
| 应用壳 | 注入页面仓储、数据网关和环境配置 |
| 页面仓储 | 按页面 id 加载页面文档和页面列表 |
| 页面校验器 | 验证页面结构、引用和能力约束 |
| 筛选状态 | 初始化、更新和序列化页面筛选值 |
| 数据编排器 | 执行页面数据源并维护数据快照 |
| 数据网关 | 执行生效查询 |
| Runtime UI | 组合页面布局、状态和交互 |
| Widgets | 纯渲染组件 |

## 3. 页面加载

```text
页面 id
  → 页面仓储
  → unknown 页面文档
  → 页面校验
  ├─ 失败 → 页面错误
  └─ 通过 → 初始化筛选状态
             → 编排页面数据源
             → 渲染页面
```

页面仓储返回的数据在校验通过前视为不可信内容。

普通页面访问加载发布修订。预览加载精确页面修订或未保存页面文档。

## 4. 页面数据源执行

### 4.1 静态数据源

```text
inline rows
  → 结果字段契约校验
  → ready / empty
  → 组件数据槽
```

静态数据源：

- 同步产生终态数据快照；
- 不调用数据网关；
- 不订阅筛选状态；
- 不进入远程查询缓存。

### 4.2 DQE 查询数据源

```text
可选内嵌初始行
  ├─ 默认状态且存在 → ready / empty
  └─ 不存在或状态不匹配
       ↓
DQE 查询定义
  + queryField 映射
  + filterBindings 对应的筛选值
  + 查询分页状态
  → 生效查询
  → 数据网关
  → DQE
  → 响应字段归一化
  → ready / empty / error
  → 组件数据槽
```

查询数据源的执行步骤：

1. 默认状态存在内嵌初始行时直接形成数据快照，不后台刷新；
2. 否则读取页面中的 DQE 查询定义和结果字段映射；
3. 读取该查询声明绑定的筛选值及查询分页状态；
4. 形成生效查询并调用数据网关；
5. 按 `queryField` 归一化结果字段；
6. 将成功结果的 `total_count` 归一为 `totalCount`；
7. 校验结果行并形成数据快照。

### 4.3 混合页面

混合页面中的每个数据源独立执行。组件根据数据槽获取对应快照。

一个数据源进入错误状态时，只影响绑定该数据源的组件。其他静态或查询数据源继续工作。

## 5. 生效查询

生效查询包含：

```ts
{
  language: "dqe",
  body: { dsl_list: [queryItem] },
  fieldMappings: {
    pageFieldId: {
      queryField: "external-field",
      type: "number",
      role: "measure"
    }
  },
  filterValues: []
}
```

页面查询定义保持不变。数据网关在克隆的 DQE 查询项上应用筛选值。

维度筛选写入或替换：

```text
filter.dims[].dim_name
filter.dims[].dim_value_list
```

时间筛选写入：

```text
filter.time.start
filter.time.end
```

筛选目标完全由 `filterBindings` 决定。

## 6. DQE 批量执行

每个 DQE 页面数据源声明一个逻辑查询项。数据网关把同一微任务窗口中的待执行查询合并为批量请求。

```text
逻辑查询 A ─┐
逻辑查询 B ─┼→ { dsl_list: [A, B, C] } → DQE
逻辑查询 C ─┘                              │
                                            ▼
                              results[0], results[1], results[2]
```

批量规则：

- 请求顺序与结果顺序一致；
- `dsl_list[i]` 对应 `results[i]`；
- 每个结果项独立成功或失败；
- 外层信封失败影响整个批次；
- 结果数量与查询数量不一致时拒绝批次；
- 页面和组件不感知批量边界；
- 网关限制同时执行的批次数量；
- HTTP 请求具有超时和取消信号；
- 单个逻辑查询的取消只结算它自己(按 `DQE_CANCELLED` 拒绝,诊断恰好一条),批次内全部查询都取消时才中止共享的 HTTP 请求,不误伤同批次其他查询。

## 7. 字段归一化

DQE 返回字段名通过查询数据源的 `queryField` 映射为页面字段 id。

```text
DQE row
{
  "地区": "华东",
  "成交额": 128600
}

fieldMappings
{
  "region":  { "queryField": "地区",   ... },
  "revenue": { "queryField": "成交额", ... }
}

page row
{
  "region": "华东",
  "revenue": 128600
}
```

归一化检查：

- DQE 结果是数据行数组；
- 每个映射字段存在；
- 映射字段不重复；
- 值类型与页面字段契约一致；
- 非空字段不接受 `null`；
- 页面数据行只包含声明字段。

## 8. 筛选状态

筛选状态是页面级共享状态。

初始化顺序：

1. 从页面 `filters` 创建默认值；
2. 解析相对时间预设；
3. 从 URL 恢复可识别的筛选值；
4. 向筛选控件和数据编排器发布状态。

筛选状态支持：

- 单值写入；
- 原子批量写入；
- 清除筛选值；
- URL 序列化；
- URL 反序列化；
- 订阅通知。

维度筛选 URL 值：

```text
d:<dimension>:<value1>,<value2>
```

时间范围 URL 值：

```text
t:<from>~<to>
```

只有声明对应 `filterBindings` 的查询数据源响应某个筛选器变化。

## 9. 页内联动

```text
用户点击筛选器或组件
  → 写入筛选状态
  → 识别相关查询数据源
  → 发布 loading 快照
  → 形成生效查询
  → 执行 DQE
  → 发布终态快照
```

表格单元格选择可以原子写入多个维度筛选器。图表和指标卡 action 可以写入一个维度筛选器。

组件之间不直接引用或调用。

## 10. 跨页下钻

跨页 action 指定：

- 目标页面 id；
- 需要携带的筛选器；
- 由点击数据行设置的目标筛选器。

运行时把筛选值编码到目标 URL。目标页面从 URL 恢复筛选状态并执行自身的数据源。

来源页面的数据快照和组件局部状态不传递到目标页面。

## 11. 数据快照

| 状态 | 数据 | 说明 |
|---|---|---|
| `loading` | 无 | 查询正在执行 |
| `ready` | 一行或多行，可选总条数 | 数据可渲染 |
| `empty` | 无，查询分页总条数为 `0` | 执行成功且结果为空 |
| `error` | 结构化查询错误(稳定分类 + 脱值消息) | 查询、协议、映射或契约失败 |

错误态保留数据网关的稳定查询错误分类(issue #51)。分类的唯一声明是 `@metriccanvas/page` 的 `QueryErrorCode` 封闭集,`DqeGatewayError.code` 以它为类型:取消(`DQE_CANCELLED`)、需要登录(`DQE_AUTH_REQUIRED`)、无权限(`DQE_FORBIDDEN`)、超时(`DQE_TIMEOUT`)、查询被拒绝(`DQE_QUERY_REJECTED`)、上游失败(`DQE_TRANSPORT_ERROR`/`DQE_ENVELOPE_ERROR`/`DQE_ITEM_ERROR`)、结果字段契约不匹配(`DQE_FIELD_MAPPING_ERROR`/`DQE_ROW_CONTRACT_ERROR`)与执行前的查询声明错误(`DQE_CONFIG_ERROR`/`DQE_FILTER_BINDING_ERROR`)各有独立分类;未携带分类的异常兜底为 `UNKNOWN`。组件呈现与嵌入事件按分类决定重试、重新登录或展示失败(`queryErrorDisposition`),不解析错误字符串;错误消息与 detail 不包含查询结果、筛选值、Secret 或上游响应正文(issue #47 红线)。

数据快照按组件 id 和数据槽组织：

```text
PageSnapshots
  componentId
    slotName
      DataSnapshot
```

同一个页面数据源可以被多个组件或数据槽引用。

## 12. 查询去重、缓存与竞态

数据编排器以生效查询的确定性 JSON 作为键：

- 相同生效查询共享一次执行；
- `ready` 和 `empty` 快照进入会话缓存；
- 并发逻辑查询数量上限为 5；
- 筛选变化为相关绑定生成新的请求代次；
- 代次推进后,不再服务任何当前代次成员的在途请求被主动取消(issue #53):标准取消信号经数据网关端口贯通到底层网络请求,不是只丢弃迟到结果;去重共享的执行仍有成员在当前代次时继续执行,未被触及的查询定义代次不变,不会发生误取消;
- 已取消请求的拒绝按 `DQE_CANCELLED` 分类(issue #51),不写入数据快照、诊断成功结果或用户可见错误;
- 即使上游未及时响应取消,过期请求返回时也不覆盖新代次结果,不触发越界页纠偏;
- 运行时会话结束(页面卸载或页面修订切换)时中止仍在运行的查询,停止发布结果并清理等待队列。

缓存只存在于运行时会话，不改变页面修订或数据权限。

## 13. 组件渲染

Runtime UI 负责：

- 页面加载、配置和校验错误；
- 筛选器区域；
- 12 列分区布局；
- 组件加载、空态和错误态；
- 创作态选择、标题编辑、尺寸调整和拖放；
- action 分发和页面导航。

Widgets 负责：

- 根据数据行和 props 绘制内容；
- 格式化字段；
- 发出组件交互事件。

Widgets 不负责：

- 查询；
- 页面仓储；
- 筛选状态；
- 数据快照状态机；
- 页面导航。

## 14. 表格视图与查询分页

绑定 `inline` 数据源的表格使用本地视图，排序、列筛选和分页只作用于已取得的数据快照，不触发远程查询。

```text
数据快照
  → 列筛选
  → 排序
  → 分页窗口
  → 表格
```

绑定独占 `query` 数据源的查询分页表格以 DQE `order.limit` 为页大小。页码变化更新克隆查询项的 `order.offset`；页面筛选变化回到第一页；成功结果的 `total_count` 驱动总条数和数字页码。查询分页暂不支持排序和表头筛选。

## 15. 错误隔离

| 情形 | 结果 |
|---|---|
| 页面不存在或不可访问 | 应用壳显示页面加载失败 |
| 页面校验失败 | Runtime UI 显示页面错误列表 |
| 查询页面缺少数据网关 | Runtime UI 显示配置错误 |
| DQE HTTP 或外层信封失败 | 批次中的相关数据源进入 `error`(401/403/超时/取消/传输各有分类) |
| DQE 单项拒答 | 对应数据源进入 `error`(`DQE_QUERY_REJECTED`) |
| 字段映射或类型失败 | 对应数据源进入 `error`(契约不匹配分类) |
| 查询成功且无数据 | 对应数据源进入 `empty` |
| 订阅方回调抛出异常 | 异常被隔离，其他订阅方继续接收状态 |

运行时不以历史数据替代失败结果。

数据源进入错误态时,`WidgetHost` 按分类的处理语义(重试/重新登录/展示失败)统一呈现标题、脱值消息与分类标识;统一运行时视图同时向宿主上抛 `data-error` 事件(页面数据源 id + 分类 + 脱值消息,进入错误态或错误变化时各一次),嵌入宿主据此决定重试或引导重新登录。

## 16. 查询诊断

生产态查询诊断默认不保留业务数据行(issue #47)。数据网关每次生效查询执行恰好落一条 `DqeDiagnosticRecord`,形状封闭、只声明一份:

| 字段 | 含义 |
|---|---|
| `executionId` | 数据网关生成的执行标识 |
| `batchId` | 批量请求标识(进入批次前失败的执行没有) |
| `requestId` | 上游响应头 `x-request-id` |
| `pageId` / `pageRevisionId` / `dataSourceIds` | 查询诊断上下文:看板页面、页面修订与页面数据源标识,由数据编排器随生效查询传入;生效查询去重后一次执行可对应多个数据源 |
| `startedAt` / `durationMs` | 开始时间与耗时 |
| `status` | `success` / `error` |
| `rowCount` / `totalCount` | 结果行数与总条数(只有数量,没有行) |
| `errorCode` | 结构化错误分类(`DqeGatewayError.code`) |

安全约束:

- 原始响应、数据行、字段值、筛选值和上游错误正文没有任何字段可以进入诊断记录;`DqeGatewayError.detail` 同样只允许结构化事实(类型名、数量、字段名、上游返回码)。
- 平台服务端取数入口(`/api/data/query`)默认把诊断记录写为 `[query-diagnostics]` 结构化 console 日志;请求体中的诊断上下文是不可信输入,只收编格式正确的字符串标识。
- 开发期明细(`DqeDevDetail`)是独立通道,三重闸门:必须显式配置(平台侧 `DQE_DEV_DETAIL=1`)、环境限制(仅 `development`,失败关闭)、按 `DQE_DEV_DETAIL_SAMPLE_RATE` 采样;落盘前对生效 DQE 项脱敏——保留指标名、维度名与结构,筛选值与未知取值一律替换为掩码。
- 开发期明细与 QueryInspector 类调试界面只允许出现在页面搭建或开发通道,不得进入正式渲染通道(统一运行时、Runtime UI、纯渲染组件、Embed、Canvas),生产构建无法通过普通页面参数开启;由守卫测试 `apps/canvas/tests/query-diagnostics-isolation.test.ts` 静态校验,`packages/data-gateway/tests/diagnostics.test.ts` 与 `apps/platform/tests/data-gateway-server.test.ts` 以敏感哨兵值断言诊断、日志与响应中检索不到业务数据。

## 17. 应用接入

### Canvas

Canvas 注入：

- Platform 页面仓储或静态页面仓储；
- DQE 数据网关；
- 页面导航。

### Embed

Embed 接收：

- 页面文档或页面加载函数；
- 查询页面所需的数据网关；
- 筛选初值；
- 导航和事件回调。

静态页面不要求数据网关。

### Platform

Platform 提供：

- 页面搭建；
- 页面修订 API；
- 精确修订预览；
- 页面和模板管理；
- 发布确认。

## 18. 运行时不变式

1. 页面文档在校验通过后进入渲染。
2. 页面字段契约是组件数据的唯一字段依据。
3. 静态数据源不访问数据网关。
4. 查询数据源只执行页面内声明的 DQE 查询。
5. 筛选值只进入显式绑定目标。
6. DQE 字段只通过 `queryField` 映射为页面字段。
7. 远程查询只通过数据网关执行。
8. 数据快照状态由统一运行时管理。
9. 组件只消费数据槽和 props。
10. 页面访问不执行页面创作行为。
