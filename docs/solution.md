# MetricCanvas（指标画布）整体解决方案

> 以业务需求为起点，以受控查询定义提供动态数据，以声明式看板页面描述应用，以统一运行时渲染页面，以 AI 完成查询生成、页面组合与数据分析。

## 1. 项目定位

MetricCanvas 是 AI 原生的数据分析与可视化平台。它把数据查询、页面描述、运行态渲染和发布治理分成清晰边界：

- 创作期在数据上下文快照约束下生成和验真查询；
- 看板页面以领域 DSL 声明数据源、组件和交互；
- 统一运行时确定性消费已发布页面修订；
- 数据网关统一执行 DQE 等查询定义；
- 纯渲染组件只展示数据快照；
- 页面修订与人工发布保证变更可追溯。

页面协议当前为 `schemaVersion: "3.0"`。1.0/2.0 的指标目录和旧结构化查询已退出，不保留运行时兼容层。

## 2. 架构分层

```text
┌─────────────────────────────────────────────────────────┐
│ 创作期                                                   │
│ 需求 → 数据上下文 → NL2DQE → 校验/验真 → v3 看板页面    │
└───────────────────────────┬─────────────────────────────┘
                            │ 保存不可变页面修订
┌───────────────────────────▼─────────────────────────────┐
│ 页面生命周期与发布治理                                   │
│ 校验 → 保存 → 精确修订预览 → 发布租约 → 人工确认         │
└───────────────────────────┬─────────────────────────────┘
                            │ 当前已发布页面修订
┌───────────────────────────▼─────────────────────────────┐
│ 统一运行时                                               │
│ 页面数据源编排 → 数据快照 → 组件数据槽 → 纯渲染组件      │
└─────────────┬─────────────────────────────┬─────────────┘
              │ inline                      │ query
              ▼                             ▼
       固化数据行                    数据网关 → DQE
```

### 2.1 创作期

创作期负责：

1. 明确需求、受众、分析问题、时间范围和验收标准；
2. 选择最小数据上下文；
3. 生成 DQE 查询候选；
4. 执行语法、安全、权限、资源和真实结果验真；
5. 形成查询定义和结果字段契约；
6. 组合为未保存看板页面；
7. 通过页面校验后保存页面修订。

统一运行时不执行 NL2DQE，也不在访问页面时重新生成查询或页面结构。

### 2.2 页面领域层

`packages/page` 定义：

- v3 TypeScript 类型；
- JSON Schema；
- 结果字段契约；
- 页面数据源；
- 筛选状态与筛选绑定；
- 组件数据槽与字段绑定；
- action 和跨页下钻；
- 结构、引用、字段契约和能力校验。

### 2.3 统一运行时

统一运行时负责：

- 加载已发布页面修订；
- 解析 `inline` 和 `query` 页面数据源；
- 初始化和更新筛选状态；
- 对 DQE 查询应用显式筛选绑定；
- 调用数据网关；
- 生成 loading / ready / empty / error 数据快照；
- 将数据快照分发到组件命名数据槽；
- 处理页内联动和跨页下钻。

### 2.4 数据网关

数据网关接收生效查询并返回标准化数据行。当前动态执行分支为 DQE：

- 原样提交查询定义的 `body`；
- 在受控语义位置应用筛选值；
- 透明合并同一调度窗口内的 DQE 查询；
- 保持查询项与结果项的位置对应；
- 用显式 `queryField` 映射归一响应键；
- 将逐项错误返回对应页面数据源。

数据网关不感知看板页面、组件或布局。

### 2.5 纯渲染组件

纯渲染组件：

- 只通过 props 接收数据行、结果字段契约和展示配置；
- 只通过事件上抛交互；
- 不发网络请求；
- 不访问全局筛选状态；
- 不管理加载、错误和空态；
- 不执行查询或页面层计算。

## 3. 看板页面 v3

### 3.1 顶层结构

```jsonc
{
  "schemaVersion": "3.0",
  "id": "page-id",
  "meta": {
    "description": "资产说明"
  },
  "dataSources": {},
  "filters": [],
  "sections": []
}
```

完整协议见 [PAGE-METADATA.md](../PAGE-METADATA.md)。

### 3.2 页面数据源

`inline` 页面数据源：

- 固化静态数据行；
- 完整声明结果字段契约；
- 不经过数据网关；
- 适用于固定报告、离线交付和确定性展示。

DQE `query` 页面数据源：

- 内嵌 `{ language: "dqe", body }` 查询定义；
- 完整声明结果字段契约；
- 通过 `queryField` 显式映射外部响应字段；
- 通过 `filterBindings` 显式绑定页面筛选器；
- 经数据网关动态执行。

`mixed` 页面同时使用两类页面数据源，能力按组件实际绑定的数据源推导。

### 3.3 结果字段契约

结果字段契约至少描述：

- 稳定页面字段 id；
- 标量类型；
- `dimension` / `measure` 字段角色；
- 默认标签；
- 单位；
- 是否可空；
- 默认展示建议；
- DQE 查询字段映射。

字段契约不从某次返回行猜测，也不由运行时目录推导。

### 3.4 筛选与联动

筛选状态是页面级共享状态。DQE 页面数据源只有通过 `filterBindings` 才响应筛选变化。

组件 action 只能：

- 回写页面筛选状态；
- 跳转到另一个看板页面并携带允许的筛选条件。

组件之间不直接连线。页面禁止 JSONPath、查询文本模板和表达式。

## 4. Schema 元数据与数据上下文

数据上下文快照是 NL2DQE 的创作边界，包含：

- 可访问执行环境；
- Schema、对象与字段；
- 字段类型、说明、别名、单位和角色；
- 关系、时间语义和粒度；
- 权限、安全与资源限制；
- 已验证问题—查询示例；
- 结果字段契约。

Schema 元数据：

- 不包含业务数据行；
- 不进入看板页面；
- 不参与统一运行时；
- 不替代结果字段契约；
- 只向创作工具和 Agent 暴露当前身份可使用的最小范围。

契约与示例见 [schema-metadata.md](./schema-metadata.md)。

## 5. 页面生命周期

看板页面以稳定 `pageId` 承载同一性。每次成功保存形成不可变页面修订：

```text
未保存页面文档
  → v3 校验
  → 用户确认页面 id
  → 保存页面修订
  → 精确修订预览
  → 申请发布
  → 发布租约
  → 人工确认
  → 当前已发布修订
```

页面修订记录：

- 页面 id 和修订 id；
- 完整 v3 页面文档；
- 创建人、时间和内容哈希；
- 基线修订；
- DQE 页面创作时使用的 `dataContextVersion`；
- 纯 `inline` 页面使用 `dataContextVersion: null`。

发布时重新校验页面、执行权限、查询定义和结果字段契约。模型、Agent、保存动作和预览都不能代替人工确认发布。

## 6. 页面搭建与 MCP

页面搭建 Agent 使用统一 Prompt、Resources 和工具契约：

```text
确认需求
  → search_data_context 或选择 inline
  → 生成查询定义与结果字段契约
  → 组合页面
  → validate_page
  → 确认页面 id
  → save_page
  → preview_page
  → 用户确认
  → request_publish
```

MCP Resources 至少提供：

- 当前页面 JSON Schema；
- 组件能力目录；
- 最小 `inline` 页面示例；
- 最小 DQE 页面示例；
- 页面生成规则；
- 数据上下文 JSON Schema；
- Schema 元数据示例。

旧的 `search_catalog`、指标候选、指标状态和指标缺口登记工具不再存在。

## 7. 错误模型

| 错误 | 含义 |
|---|---|
| `SCHEMA_ERROR` | 页面版本、结构或未知属性错误 |
| `FIELD_CONTRACT_ERROR` | 字段类型、空值、数据行或组件字段引用错误 |
| `QUERY_MAPPING_ERROR` | DQE 输出与查询字段映射错误 |
| `FILTER_BINDING_ERROR` | 页面筛选器与 DQE 目标绑定错误 |
| `DQE_PROTOCOL_ERROR` | DQE 请求/响应协议错误 |
| `DQE_EXECUTION_ERROR` | DQE 单项执行失败 |
| `DATA_CONTEXT_ERROR` | 创作期 Schema 元数据不足或不一致 |

系统不再产生 `METRIC_GAP`。

## 8. 工程与验证

关键命令：

```bash
pnpm validate
pnpm test
pnpm typecheck
pnpm check
pnpm build
pnpm dev:dqe
```

验收包括：

- v3 `inline`、DQE `query` 和 `mixed` 正反契约测试；
- 旧版本和旧结构拒绝测试；
- DQE 筛选绑定、批量请求、位置对应和字段归一化测试；
- 正式页面全量校验；
- 页面保存、预览和发布流程测试；
- Canvas、平台和嵌入产物构建；
- 非历史文档与活动代码的旧术语扫描。

## 9. 关键不变式

1. 看板页面是核心资产，统一运行时只消费已发布页面修订；
2. `inline` 与 `query` 都完整声明结果字段契约；
3. DQE 查询定义只出现在 query 页面数据源；
4. 页面字段与外部查询字段永不隐式同名匹配；
5. 筛选状态只通过显式筛选绑定影响查询；
6. Schema 元数据只服务创作期；
7. 所有远程取数都经过数据网关；
8. 组件不发请求、不执行查询、不访问全局状态；
9. 页面不表达任意代码或页面层计算；
10. 人工确认发布是独立闸门。
