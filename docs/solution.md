# MetricCanvas 整体解决方案

> 当前架构（2026-09-16）：Platform 是静态 SPA，页面资产遵循外部 Java YAML 与 [ADR-0080](./adr/0080-java-assets-single-attempt-save-and-status-publication.md)。本文描述已实现的本仓边界；真实 Java/Relay 联调与部署注入仍需独立验收。实现位置和验证证据见[实施记录](./plan/2026-09-16-java-page-assets-implementation.md)。

## 1. 系统定位

MetricCanvas 将数据查询、页面描述、运行时渲染和发布治理分为独立协作单元：

- 数据上下文为页面创作提供受控 Schema 元数据；
- 页面搭建能力生成 DQE 查询和页面；
- 页面以领域 DSL 声明数据、内容和交互；
- 统一运行时加载并渲染选定的页面文档；
- 数据网关执行 DQE 查询并归一化结果；
- 纯渲染组件呈现数据快照或 AI 总结快照；
- 页面生命周期管理修订、预览和发布。

## 2. 系统结构

```text
┌──────────────────────────────────────────────────────────┐
│ 页面创作                                                  │
│ 业务需求 → 数据上下文 → 查询/静态数据 → 页面 → 校验       │
└────────────────────────────┬─────────────────────────────┘
                             │ 保存
┌────────────────────────────▼─────────────────────────────┐
│ 页面生命周期                                               │
│ 单次保存 → 回执确认 → 当前内容预览 → 人工确认发布  │
└────────────────────────────┬─────────────────────────────┘
                             │ 加载
┌────────────────────────────▼─────────────────────────────┐
│ 统一运行时                                                 │
│ 页面数据源 → 数据快照 ┬→ 组件数据槽 → 纯渲染组件          │
│                       └→ AI 总结组件 → AI 总结快照 → View │
└──────────────┬──────────────────────────────┬────────────┘
               │ inline                       │ query
               ▼                              ▼
          静态数据行                    数据网关 → DQE
```

依赖方向：

```text
apps
  → application-runtime
  → metric-canvas
  → engine/runtime-ui
    → runtime
      → page
      → DataGateway 端口

platform(浏览器)
  → 页面资产内部接口 → TypeScript Java Adapter → Java 页面资产服务
  → application-runtime → 数据网关 → DQE

Relay 可信创作程序
  → Python 内容工具 → 合法候选
  → 持久提交协调器 → 生命周期 → Python Java Adapter → Java 页面资产服务
  → 已验证回执 → 工作台（只应用，不再次保存）

data-gateway
  → runtime 的 DataGateway 端口
  → page 的 EffectiveQuery
```

领域层不依赖应用壳、浏览器框架或具体 DQE 地址。

## 3. 页面

页面是平台的聚合根。页面协议见 [PAGE-METADATA.md](../PAGE-METADATA.md)。

顶层结构：

```json
{
  "schemaVersion": "6.0",
  "id": "page-id",
  "meta": {},
  "dataSources": {},
  "filters": [],
  "sections": []
}
```

页面声明：

- 命名页面数据源；
- 完整结果字段契约；
- 页面级筛选状态；
- 内容分区和缺省 12 列、可选受控权重列轨布局；
- 组件数据槽和字段绑定；
- 页内联动与跨页下钻。

页面不包含：

- 组件代码；
- 任意脚本或 HTML；
- 查询文本模板；
- 页面层计算表达式；
- 执行端点和凭据；
- 数据上下文快照。

## 4. 页面数据源

### 4.1 静态数据源

`inline` 数据源把数据行保存在页面文档中。

适用能力：

- 固定报告；
- 离线交付；
- 说明性数据；
- 确定性视觉验收。

静态数据源同步形成 `ready` 或 `empty` 数据快照，不访问数据网关。

### 4.2 查询数据源

`query` 数据源包含：

- `language: "dqe"`；
- DQE 原始请求体；
- 可选的 DQE 原始内嵌初始行、数据时点和总条数；
- 结果字段契约；
- DQE 输出到页面字段的 `queryField` 映射；
- 页面筛选器到 DQE 目标的 `filterBindings`。

内嵌初始行与查询定义一起保存，字段键保持 DQE 原始输出字段名；页面模块加载 `PageDocument` 时按 `queryField` 归一化为稳定页面字段。默认状态存在内嵌初始行时，统一运行时使用归一化结果直接形成数据快照且不后台刷新；没有内嵌初始行或入口筛选状态不同于默认状态时执行查询。统一运行时把查询定义、字段映射、筛选值和查询分页状态组合为生效查询，数据网关使用同一查询结果归一化能力返回以页面字段 id 为键的数据行及可选总条数。

### 4.3 混合页面

`mixed` 页面同时包含 `inline` 和 `query` 数据源。组件能力由其实际绑定的数据源决定。

数据源之间没有隐式依赖。一个数据源的结果不会自动成为另一个数据源的查询输入。

## 5. 数据上下文

数据上下文快照为页面创作提供：

- DQE 执行环境；
- Schema、对象和字段；
- 字段类型、业务说明、别名、单位和角色提示；
- 对象关系；
- 权限与安全范围；
- 查询资源限制；
- 已验证查询及结果字段。

Schema 元数据规则见 [schema-metadata.md](./schema-metadata.md)。

数据上下文只参与页面创作。统一运行时不加载数据上下文，也不根据 Schema 元数据推导页面字段。

创作程序保留所依据的数据上下文版本。当前 Java 页面资产响应未提供该审计字段，不补造修订级 `dataContextVersion`。

## 6. 页面搭建

Platform 页面搭建工作台持有工作副本、检查器、撤销和本地保护。人工完整操作先持久化本地记录，再通过串行队列单次保存。模型与统一创作 Skill 负责表达内容意图，Python 内容工具生成并校验候选；可信程序选择最终候选并提交，模型没有直接保存或发布权限。

三条主旅程：

1. **页面列表 → 打开**：按状态分页，保留每条资源；通过资源 ID 读取当前文档，建立创作基线。同 pageId 多资源不合并，旧链接仅在唯一匹配时解析。
2. **创建新页面**：进入空工作台，不创建 Java 空记录。可信程序选定合法候选后单次创建草稿，前端接收回执中的文档和资源身份。
3. **编辑已有页面**：人工修改经本地保护后串行提交；AI 开始前收敛输入并等待同步，固定本轮身份与创作基线。AI 成功回执只更新工作副本，不触发前端重复保存。

部署侧通过可信创作 Adapter 将盘古输入、轮次准备、结果查询和程序回执接到工作台。未配置时不能把对话面板已挂载当作 AI 新建/编辑已接通。具体程序接口见[创作架构](../metriccanvas-authoring/ARCHITECTURE.md)，普通问数的临时页面态与显式沉淀边界保持独立。统一运行时不执行 NL2DQE。

## 7. 页面资产边界

业务调用方依赖内部 `PageAssets` 接口：`list/read/resolve/save/history/restore/remove`。`page-assets.ts` 组合生产实现；`page-assets/java-adapter.ts` 集中 Java URL、字段、状态和响应校验；旧 `page-assets-client.ts` 仅兼容导出。Python 生命周期经 `KnownLifecycleHttp` 处理对应协议。两种语言共享契约样例，前端页面和 Skill 不解释 Java 响应字段。

资源 ID 定位持久记录，pageId 对应文档身份，revisionId 是更新基线，三者不能互相推导。读取返回本次服务状态，不保证强一致最新状态或历史精确读取。未提供的哈希、创建人和审计字段保持不可用。

| 写入结果 | 调用方行为 |
|---|---|
| confirmed：成功回执通过身份、文档、修订与状态校验 | 更新基线并保留已确认内容；陈旧 GET 不覆盖本地已确认的更高修订 |
| rejected：本地校验失败或明确服务拒绝 | 保留工作并显示原因；冲突不自动换基线重发 |
| unknown：超时、连接中断、服务错误或无法验证成功回执 | 保留候选和发送记录，停止重发；重连、重开和状态查询不触发第二次提交 |

浏览器保护人工工作，可信程序保护 AI 候选和执行记录，Java 拥有持久资产。程序操作 ID 只用于本地关联，不冒充 Java 幂等保证。旧未决记录不因升级而重放。

历史接口只返回草稿摘要；恢复始终指定草稿版本，不假定回退追加新修订或具有跨窗口基线检查。回退成功会替换本地已确认投影。删除消费服务成功响应，不要求返回文档。执行与筛选历史归运行态，不进入资产接口。

## 8. 发布

发布由用户在已保存、已同步的工作副本上明确确认，沿同一保存队列提交。Adapter 将发布意图映射为 `is_draft=false`，普通保存映射为 `true`；成功状态以回执为准。

当前 Java 接入不要求发布租约、参数提取候选、角色审计接口或独立发布修订引用。继续编辑保存会把当前记录改为草稿，不承诺另有不受编辑影响的已发布副本。服务端负责实际权限裁决。

## 9. 页面模板的范围

独立模板、模板修订和维度取值提取属于既有后续设计，未作为当前 Java 发布旅程实现，也不是发布的前置条件。历史设计背景见 [ADR-0010](./adr/0010-page-templates-reference-published-revisions.md)、[ADR-0078](./adr/0078-dimension-values-templates-and-page-instances.md)，本期替代范围以 ADR-0080 为准。

## 10. 统一运行时

统一运行时由以下部分组成：

| 模块 | 职责 |
|---|---|
| 页面仓储 | 加载页面文档和页面列表 |
| 页面校验器 | 验证结构、引用和能力约束 |
| 筛选状态 | 管理页面筛选值和 URL 序列化 |
| 数据编排器 | 执行页面数据源并生成数据快照 |
| 数据网关 | 执行生效查询 |
| Runtime UI | 组合页面布局、状态和组件 |
| Widgets | 纯渲染组件 |
| AI Summary 垂直组件 Module | 关联数据解析、请求组装、生成会话、私有 SSE 适配与纯渲染 View |

Runtime UI 内部按 DOM 所有权拆分：`RuntimeView` 是正式渲染入口，共享的 `RuntimeSurface` 负责页面校验结果、筛选状态、数据快照和组件分发；内容分区 Module 负责内容分区、网格、组件单元格和 `connectPrevious`。独立创作包 `@metriccanvas/metric-canvas` 通过 `MetricCanvas` 提供选中、拖拽、编辑触发和意图回传，复用同一渲染主体与布局；文档、属性面板、保存和撤销历史仍归集成应用。渲染包的 `./composition` 提供内容分区片段与单元格装饰接缝，渲染包不依赖创作包，正式渲染不加载创作专用代码（ADR-0065；包名和发布兼容策略仍需 #100 对账）。分区网格缺省为 12 列等权轨，Schema 5.3 起可把受控正整数权重列轨翻译为运行时 `fr` 模板；页面不能注入 CSS 字符串。纯渲染组件的内部 DOM 只能由对应组件 Module 设置样式；内容分区与组件外缘通过内部 CSS custom properties 协作，不使用全局 class 选择器穿透。

查询数据源执行行为：

- 默认状态优先使用可选内嵌初始行，不发起后台查询；
- 只对声明相关 `filterBindings` 的筛选变化重新查询；
- 查询分页通过 DQE `order.offset` 和 `order.limit` 重新查询，筛选变化回到第一页；
- 使用生效查询内容作为去重和缓存键；
- 复用相同生效查询的结果；
- 限制并发查询；
- 使用请求代次丢弃过期结果；
- 将单个数据源错误限制在绑定该数据源的组件。

数据编排器以 `dataSourceId` 为键保存页面数据快照。普通组件的数据槽与 AI 总结的关联数据都投影到这份唯一存储；同一数据源不因消费者数量增加而重复执行。

## 11. DQE 数据网关

DQE 数据网关：

1. 克隆页面中的单个 DQE 查询项；
2. 在 `filter.dims` 或 `filter.time` 应用筛选值，并在查询分页时应用 `order.offset`；
3. 在同一微任务窗口合并待执行查询；
4. 提交批量 `dsl_list`；
5. 按位置对应 `results`；
6. 检查外层信封和逐项状态；
7. 按 `queryField` 归一化字段名；
8. 读取成功结果的 `total_count` 并归一为 `totalCount`；
9. 按结果字段契约校验数据行。

外部批量请求是数据网关内部行为。页面数据源始终表示一个命名结果集和一个逻辑查询项。

## 12. 数据快照与组件

数据快照状态：

| 状态 | 含义 |
|---|---|
| `loading` | 查询正在执行 |
| `ready` | 存在至少一行有效数据，并可携带查询分页总条数 |
| `empty` | 执行成功且没有数据行，查询分页总条数为 `0` |
| `error` | 执行、协议、映射或数据契约失败 |

统一运行时按页面数据源 id 保存数据快照，并在渲染时投影给组件数据槽。纯渲染组件：

- 不发起网络请求；
- 不访问筛选状态；
- 不解析 DQE 响应；
- 不管理数据加载状态；
- 只呈现传入的数据和属性；
- 通过事件上抛用户交互。

AI 总结组件是一个垂直组件 Module。Host 读取关联数据快照；组件内部依次完成字段白名单选择、固定请求组装、SSE 协议适配和生成会话管理；View 只消费按组件 id 隔离的 AI 总结快照。数据网关 Interface 仍只负责 DQE 取数和维度候选值，不包含 AI、Prompt、SSE 或总结方法。

摘要的创作期默认是 `text`：后端已生成或已确认的结论随页面文档返回。只有需求明确声明运行时 SSE 动态生成时，才在页面文档中声明 `aiSummary`。

`text` 正文默认按纯文本渲染；需要分色时显式声明 `bodyFormat: "semanticHtml"`。它与 `rankingDetailCard` 的语义 HTML 明细共用 `widgets` 内的受控语义 HTML Module：Interface 只接收原始字符串，Implementation 统一负责标签/语义类白名单、安全解析、失败关闭、节点渲染与颜色映射，调用方不接触解析树，也不使用原始 HTML 注入。

只有当生成能力出现多个组件消费者，或出现下载、通知等非组件消费者时，才从垂直组件中提取公共 Module。

## 13. 错误模型

| 错误类型 | 边界 |
|---|---|
| `SCHEMA_ERROR` | 页面 JSON 结构、引用或组件能力 |
| `FIELD_CONTRACT_ERROR` | 页面数据行与结果字段契约 |
| `QUERY_MAPPING_ERROR` | DQE 输出与页面字段映射 |
| `FILTER_BINDING_ERROR` | 页面筛选器与 DQE 目标绑定 |
| `DQE_PROTOCOL_ERROR` | DQE 请求或响应协议 |
| `DQE_EXECUTION_ERROR` | DQE 查询项执行 |
| `DATA_CONTEXT_ERROR` | 页面创作所需数据上下文 |

运行时错误通过数据快照进入 Runtime UI。页面校验错误阻止页面进入渲染和保存边界。

## 14. 应用与部署

| 应用 | 职责 |
|---|---|
| 页面试验场 | 开发态仓库页面浏览、JSON 即时预览 |
| Platform | 页面目录、页面搭建、草稿历史与状态发布 |
| DQE Sim | 本地 DQE 协议仿真 |

页面试验场只读取仓库页面，按需启动与构建，不作为产品交付物。数据网关通过共享运行配置模块读取注入配置。

`packages/embed` 是渲染引擎的 JS 挂载入口，不是应用：普通 HTML 或异构集成应用通过 JS 地址加载后调用 `mount`，Svelte/页面搭建类集成应用使用 npm 入口。IOC 的独立微前端子应用与 platform 自行承担应用集成，引擎不实现微前端协议；不向集成应用开放字体、主题或其他视觉配置。页面文档由集成应用加载，数据网关与身份恢复由集成应用提供（[ADR-0066](adr/0066-self-contained-rendering-engine-host-boundary.md)）。

跨页导航使用页面声明的 `href + query`：URL 与显式动态绑定由内容提供方负责，默认普通浏览器跳转，集成应用可选接管；6.0 协议、普通查询值与显式迁移见 [ADR-0068](adr/0068-plain-url-navigation-protocol.md)。页面资产身份保留，集成应用继续拥有路由栈、返回与面包屑。

## 15. 系统不变式

1. 页面是统一运行时的唯一页面输入。
2. 页面协议版本以 `packages/page/src/version.ts` 的 `versionPolicy.current` 为唯一真源(当前为 `5.3`)。
3. 页面数据源完整声明结果字段契约。
4. 页面字段和 DQE 字段只通过显式映射对应。
5. 筛选状态只通过显式筛选绑定影响查询。
6. Schema 元数据只参与页面创作。
7. 页面业务数据只通过页面数据源进入统一运行时；动态查询结果经数据网关进入，内嵌初始行和 `inline` 数据随页面文档进入；AI 生成文本只通过 AI 总结组件的私有 SSE Adapter 进入。
8. 纯渲染 View 不发请求、不执行查询、不访问页面全局状态；AI 总结请求只存在于其垂直组件 Module。
9. 创作基线在本轮内固定；更新携带修订基线，冲突或未知结果不自动重发。
10. 发布要求人工确认并消费已验证回执；AI 保存结果只由一个提交者写入。

架构决策记录位于 [`docs/adr/`](./adr/)。
