# 分支与工作树清理标准

每次交付收口清理本任务已合入 main 的分支和工作树。用户要求全仓盘点时，将范围扩展到全部本地分支、GitHub 分支和工作树。标准由 [范围交付 Skill](../../.agents/skills/scoped-main-delivery/SKILL.md) 执行。

## 核对合并状态

1. `git fetch origin --prune`，以最新 `origin/main` 为基线，记录完整 SHA。原工作区有未提交修改时保持原状，不能以本地 main 落后为由整体覆盖或自动暂存。
2. 读取 `git worktree list --porcelain`、本地与远端分支引用，以及 GitHub 开放 PR、默认分支和保护状态。记录每个候选引用的完整 SHA 和所属工作树。
3. 按下表判断；ahead/behind 数量、上游分支已删除、分支名称和旧交付说明均不能单独证明已合并。

| 证据 | 处理 |
|---|---|
| `git merge-base --is-ancestor <候选SHA> origin/main` 成功 | 提交历史已包含在 main，可继续检查清理条件 |
| 非祖先，但 `git cherry -v origin/main <候选SHA>` 的全部非合并提交均为 `-`，且候选独有范围内无合并提交 | 补丁等价，可继续检查清理条件；记录等价依据 |
| 存在 `+`、独有合并提交，或仅凭 squash 后功能相似判断 | 保留；核对实际内容后再决定，不在清理中自动合并或丢弃 |

## 检查可删除条件

- 保留主工作区、默认分支、受保护分支，以及仍有开放 PR、活动任务或明确保留用途的项。远端分支和同名本地分支分别判断，它们可能指向不同提交。
- 对每个工作树读取完整 `git status --short --untracked-files=all`，另查忽略文件。未提交、未跟踪或 detached HEAD 的独有内容均须保留；若需归档后移除，先生成可恢复快照并核对保存结果。
- 忽略的验收日志、手工产物和必要构建产物先另存并核对；依赖、缓存及可重建构建目录可随工作树移除。Git 快照不包含忽略文件，不能用它代替产物保存。
- 核对引用该目录的开发服务和进程 cwd。在本任务清理范围内，先停止对应进程再移除目录；仍被其他活动任务使用的工作树保留并说明。避免遗留引用已删目录的 Vite 或 DQE 仿真服务。

## 执行与复核

1. 保存清理清单和引用 SHA；历史批量清理或删除补丁等价分支前，另存并验证 Git bundle 等可恢复备份。
2. 删除前重读候选引用、远端 main、开放 PR 和工作树状态。候选 SHA 或工作状态变化时重新判断。交付默认先完成远端提交与 CI 验证，再清理；用户选择的其他完成点照原约定执行。
3. 删除符合条件的 GitHub 分支，保留 main 和未确认合并项；不 force push。普通工作树使用 `git worktree remove`；本任务附着的 Codex 托管工作树优先使用 `archive_worktree`。清理其他任务所属目录时遵守其所有权限制，无法移除的项保留并报告。
4. 工作树移除后再删除本地分支。祖先分支用普通删除；补丁等价分支在保存证据和备份后，用带预期旧 SHA 的引用删除防止误删新提交。失败时复核原因，不能直接强制移除有修改的目录。
5. 再次读取 GitHub 分支、本地引用和工作树清单，确认删除结果及原工作区未受影响。最终报告 main 基线、清理数量、保留项与原因、备份位置；未确认差异应区分实现、文档、原型和备份，不能全部称为未上线功能。
