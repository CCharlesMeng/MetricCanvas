# 新功能验收要求

所有新功能在同一实施批次完成以下三项，作为实施完成条件。纯执行或协议能力也通过页面场景体现其可观察结果，并补充对应边界测试。

1. **页面场景**：在 `pages/` 新增或扩展可直接加载的完整页面；文件名与页面 id 一致，使用当前合法协议。注册到 `apps/playground/page-catalog.json`，在 `pages/README.md` 写明入口、数据环境、操作、预期结果和证据边界。覆盖该功能的正常行为与关键异常；无法由页面构造的取消、迟到响应等边界由行为测试补充。自动验收读取该页面，保留页面中的交互配置，不在测试里临时拼出功能。
2. **页面元数据文档**：修改 `PAGE-METADATA.md` 及 `docs/page-metadata/` 中实际拥有该语义的模块和示例路由；涉及参数时同步 `PAGE-PARAMETERS.md`，涉及字段或版本时同步产品 Schema、校验和契约向量。文档明确声明、运行行为、限制与对应验收场景。
3. **本地创作 Skill**：按 [维护流程](local-authoring-skill-maintenance.md) 从产品真源生成 `metriccanvas-local-authoring` 的协议知识、示例、独立校验器和版本/哈希清单；工作流有变化时更新作者维护的说明。复制安装目录到仓库外验证链接闭合及页面校验，保持独立使用能力。

上述要求由本页维护；仓库入口和 Skill 维护文档只指向本页。派生文件通过导出器更新，避免在文档或 Skill 中手写第二份协议规则。

验收记录列出功能到页面、文档模块、Skill 产物的对应关系，以及实际执行的命令和结果。静态校验、单元/集成、浏览器、Sim、真实 DQE/Relay 与真实模型分层报告；演示或仿真页面显式标识数据性质。环境阻碍须记录证据及可执行步骤，继续完成其余项，保留未验收结论。
