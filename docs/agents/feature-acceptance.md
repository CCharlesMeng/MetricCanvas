# 功能与协议能力验收要求

适用于所有新功能，以及页面协议能力的新增、行为调整、缺陷修复、校验收紧和废弃。每次更新均在同一实施批次完成以下三项，作为实施完成条件。纯执行、校验或版本边界更新也通过页面场景展示可观察的输出、状态或诊断，并补充对应边界测试。

开始修改页面元数据前，按[页面元数据定义与修改流程](page-metadata-changes.md)核对完整 JSON、同层字段命名和演进方式。字段名、基数、引用方式与默认行为属于同一份契约；实现和测试全部沿用同一个错误拼写，也不代表契约正确。

1. **Playground 场景与浏览器验收**：在 `pages/` 新增或扩展完整页面；文件名与页面 id 一致，使用当前合法协议。页面通过 `pages/` 实际文件夹自动被 Playground 目录发现，并通过 `/pages/<id>` 直接访问。应用不维护逐页目录元数据；组件与数据来源等筛选信息从页面文档读取。在页面所在目录的 README.md 写明入口、所需 URL 参数、数据环境及启动方式、操作、可观察的预期结果和证据边界，根 `pages/README.md` 提供主题入口；跨页能力同时给出来源与目标入口。按这些步骤在真实浏览器中验证效果，验收记录保留入口、操作与结果，按需附截图或机器报告。覆盖正常行为与关键异常；非法输入给出可复现的夹具或输入步骤，取消、迟到响应等边界由行为测试补充。自动验收直接读取对应页面并保留其中的交互配置，使页面日常演示与测试使用同一份功能声明。
2. **页面元数据文档**：修改 `PAGE-METADATA.md` 及 `docs/page-metadata/` 中实际拥有该语义的模块和示例路由；涉及参数时同步 `PAGE-PARAMETERS.md`，涉及字段或版本时同步产品 Schema、校验和契约向量。文档明确声明、运行行为、限制与对应验收场景。
3. **本地创作 Skill**：按 [维护流程](local-authoring-skill-maintenance.md) 从产品真源生成 `metriccanvas-local-authoring` 的协议知识、示例、独立校验器和版本/哈希清单；工作流有变化时更新作者维护的说明。复制安装目录到仓库外验证链接闭合及页面校验，保持独立使用能力。

Skill 验证范围按 [仓库约定](../../AGENTS.md#skill-验收范围) 仅验收 local-authoring；其他 Skill 和真实模型按用户明确要求追加，产品验收范围保持上述要求。

上述要求由本页维护；仓库入口和 Skill 维护文档只指向本页。派生文件通过导出器更新，避免在文档或 Skill 中手写第二份协议规则。

验收记录列出功能到页面、文档模块、Skill 产物的对应关系，以及实际执行的命令和结果。静态校验、单元/集成、浏览器、Sim、真实 DQE/Relay 与真实模型分层报告；演示或仿真页面显式标识数据性质。

Playground 浏览器验证属于每次协议能力更新的完成判据；仅有 Schema、单元测试或文档更新时，继续标记该场景为未验收。环境阻碍时记录具体原因与恢复步骤，完成其余工作，并保留未完成的 Playground 验收状态。
