# Playground 示例维护

页面试验场的完整页面同时承载产品能力演示、验收和创作参考。页面继续按产品能力、业务场景及布局形态组织；作者在现有页面和目录说明中提供可复用意图，工具从同一真源提取知识。

本约定适用于新增、本次修改或被选为推荐参考的示例。未触及的历史页面按实际复用需要逐批补齐，不在普通版本更新时全库重写。对应的索引、CLI 与 Skill 实施见 [唯一主计划](../plan/2026-11-09-local-authoring-knowledge-consumption.md)；首批 find/show 与示例局部读取已实现，目标页面上下文及增量影响分析的未完成项以主计划标识为准。

## 真源与归属

| 内容 | 作者维护位置 | 原则 |
|---|---|---|
| 可运行的完整页面 | `pages/` 对应能力或业务目录中的 JSON | 页面文件名与 id 一致且全树唯一，浏览器与测试消费同一声明 |
| 任务用途、操作与预期、移植边界 | 同目录 README 的对应场景章节 | 沿用已有说明，不另写一份完整配置 |
| 推荐场景的发现入口 | `apps/playground/scenarios/catalog.ts` 及现有能力映射 | 只为推荐学习场景登记；普通文件发现仍自动完成 |
| Schema、字段语义和执行规则 | 产品协议及正式页面元数据文档 | 页面仅作为特定使用方式的见证，不把示例取值升级为通用约束 |
| Skill 示例目录、对象和依赖索引、投影片段 | 从上述真源生成或在查询时计算 | 不手改安装副本，不另建与真源同步维护的页面副本 |

新增页面显式使用 `layout:"dashboard"`，Report 场景仍按仓库已有判据处理。已有页面的 id、稳定组件身份和访问地址保持连续；不为 Skill 批量改目录、重命名对象或向页面 Schema 添加检索字段。

## 目录说明的最小内容

在既有场景章节中补齐以下四项，已有文字能表达时直接沿用，不要求每页使用重复表格。章节包含精确的 `/pages/<page-id>` 入口；当前页面试验场按该入口定位并展示说明，不从自然语言生成运行配置。

1. **复用用途**：用户要完成的任务、采用该例能得到的效果，以及必要的适用条件。
2. **参考对象**：关联页面及关键组件 id；需要时补字段 id、Tab id、筛选 id，说明应关注的配置。JSON Pointer 是当前文件中的位置，不能替代稳定身份。
3. **移植边界**：目标页需要映射哪些字段或输入、哪些配套关系必须保留、哪些内容只是合成示例。不要把示例查询、业务编码或数据行默认带入目标页。
4. **可观察预期与环境**：启动方式及参数、操作、预期变化和数据性质；结构、浏览器、导出、Sim、真实服务分别描述，不用一个“已验证”覆盖全部层级。

维护样板见 [商务类型前端枚举](../../pages/capabilities/table/README.md#商务类型前端枚举680) 和 [时间格式](../../pages/capabilities/table/README.md#时间格式与固定-utc8)。跨页能力列出来源和目标，筛选联动说明实际影响哪些查询；未知业务口径或服务能力保留缺口。

需要进入任务指南索引的场景，在原章节标题下加一行关联标记，例如 `<!-- example-guide: task=time-format; page=table-time-format; components=times -->`。`task` 为该页内稳定的任务 id，`page` 为真实页面 id，`components` 为逗号分隔的焦点组件 id。四项说明沿用上述自然段标签（`复用用途：`、`参考对象：`、`移植边界：`、`可观察预期与环境：`），可保留多段；不要把整章改成另一份配置。每个标题到下一标题为一个指南章节；同一章节可写多个关联标记来服务多页，同页多个任务使用不同任务 id，重复关联会阻断生成。

可选声明为 `lifecycle=candidate|recommended|historical` 之一，以及 `verified=structure,browser,export,sim,real-service` 中实际已有依据的层级列表；省略时分别保留 `candidate` 和空列表。`verified` 只记录作者声明，工具仍标为本轮 `not-assessed`，不从“校验通过”或操作预期推断浏览器、导出、Sim 或真实服务。推荐必须具备四项说明、焦点组件和至少一个声明层级；缺项、未知声明、悬空页面或组件、重复关联均使生成失败。未补齐的候选保留 `not-provided`，历史未标记章节不要求批量重写。

生成器只复制对应章节与角色段落，稳定指南身份为页面 id 加任务 id；README 其他章节变化不改变该指南摘要及内容哈希。分发副本把原相对链接和本地入口保留为文字来源，由页面身份及查询入口继续定位，不生成指向仓外安装路径的链接；完整 README 留在仓库本地。

## 页面结构与大文件

完整 JSON 保持单一运行真源。100—200 KB 的示例可以由 CLI 在本地完整解析；默认模型阅读只投影任务需要的对象，既有单文件 1,000,000 字节上限仍适用。

- 保持组件、分区、Tab 和字段的既有稳定身份；新增对象按产品协议命名。对象目录、路径、字段类型、引用关系、行数和大小由工具计算，作者不维护第二套结构目录。
- 页面可组合多个相关能力；每个参考任务指向自己的焦点对象。共享数据、条件或交互集中声明，不复制页面来制造“更小的例子”。确有独立教学目的时才新增独立场景。
- 合成数据只保留展示和验收所需的代表值；大量行确为性能、分页或完整性验收所需时，沿用可复现的夹具或生成机制，并标明场景用途。
- 后续读取默认返回页面目录、选中对象和依赖入口，数据行、查询体和长文本单独按需读取。对象片段不是独立页面；依赖尚未齐全时明确标识，不宣称可以直接运行。

## 推荐与验证范围

新页面首先作为候选参考；具备用途、参考对象、移植边界，并通过所声明层级的检查后，才在对应层级推荐。布局范式、可运行功能例子和历史兼容例子分别标明用途，避免用组件树摘要冒充功能配方。

验证结果与实际来源内容关联。页面或夹具变化后，检查受影响预期；不能把旧截图或旧服务回执自动沿用到新内容。原页面的历史缺陷和未验服务边界不能在进入 Skill 后变成“成功实现”的保证。

提取片段时既核对结构和依赖，也核对该例声明的行为。删除筛选、排序或补列后仍能通过 Schema，只证明结构合法，不能证明保留了原示例的效果。

## 按变更维护

| 变更 | 作者动作 | 验证原则 |
|---|---|---|
| 文案或演示数据更新 | 按实际变化维护原说明和真源，不重填无关字段 | 核对引用、代表值及受影响预期 |
| 单个示例能力调整 | 更新对应参考对象、操作和移植边界 | 结构检查及该行为的定向回归 |
| 共享组件或协议变化 | 从产品引用关系找受影响示例，补新增能力的推荐入口 | 执行仓库规定的功能与协议验收；影响不明确时扩大范围 |
| 索引、提取或 CLI 变化 | 在维护源修正通用实现，重建派生物 | 通用边界、关联示例、生成一致性及独立安装检查 |
| Skill 消费流程变化 | 调整查询和组装指引 | 使用独立原始输入复测代表性任务，比较正确率、读取量与修复轮次 |

完整生成一致性、链接闭合、哈希和独立分发要求继续适用。影响分析优先节省昂贵的模型、浏览器和外部服务复测，不作为跳过现有必选检查的依据。机器报告、截图、日志和版本验收回执保留在本地忽略目录，正式说明只维护长期语义、操作及边界。
